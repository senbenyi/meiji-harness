# 全步骤修改与重新生成：页面复查和修复方案

> 状态：用户已确认执行，修复已实施；实机验收记录见 `2026-10-07-studio-edit-regenerate-verification.md`。
> 基线：2026-10-06，当前工作区与已安装的 3081 工作台，验收项目 `20261006223852287`。
> 范围：七个页面的二次修改、重新生成入口，以及操作后的任务、版本和失效状态。

## 1. 结论

目前没有做到“每一步都可修改和重新生成”。页面问题和后端返工缺口同时存在：

1. 正式内容被投影为只读卡片，缺少修改和重新生成入口。
2. 旧视频卡的“重做”只是填入宿主聊天草稿，不直接提交任务；独立页面没有宿主接收时也没有可见反馈。
3. 上游修改没有完整地使视频、时间线和交付失效，旧成片仍可能显示就绪。这是补入口前必须处理的最大问题。
4. 已完成任务的恢复不会重新执行；已合成镜头也不能直接创建新生成尝试，需要明确的返工命令。

上一轮页面优化验收覆盖布局、阅读、状态刷新和播放，不能视为二次修改与重新生成能力已经验收。

## 3. 根因和直接证据

### 页面与执行入口

- `studio/app.js::nodeCard()` 在 `if (node.domainProjection) return card` 处直接返回，后面的编辑和重做按钮只属于旧画布节点。保护领域数据所有权是正确的，但缺少对应的领域操作入口。
- `nodeCard()` 的“重做”调用 `askAi()`；`lib/client.js` 的 `ask-ai` 监听只调用 `inputActions.setDraft(data.text)`，没有提交任务。
- 已有 `POST /projects/:id/commands` 可执行领域命令；现有 `/generate/image`、`/generate/video` 直接调用生成。尚无供全部阶段统一使用的、带影响范围与版本信息的返工入口。

### 下游失效

在真实记录的内存副本上调用当前命令，未写回存储：

| 操作 | 实测结果 |
| --- | --- |
| 修改一个正式镜头的 prompt | 镜头仍为 `assembled`，3 个视频仍为 `approved`，交付仍为 `ready`；进度已识别分镜与视频仅完成 2/3，但交付仍显示完成 1/1 |
| 修改角色描述 | 3 个正式镜头变为 `invalidated`，但3 个视频仍为 `approved`、交付仍为 `ready`；进度中分镜和视频为 0/3，交付仍完成 1/1 |
| 对已完成生产运行调用 `resumeProductionRun` | 恢复任务数为 0 |
| 对已合成镜头直接调用 `createGenerationAttempt` | 拒绝：`shot is not ready for generation: assembled` |

对应代码断点：

- `lib/domain/commands/index.js::upsertShot()` 更新镜头但不执行内容变化后的下游失效；`upsertEpisode()` 也是通用写入，不能直接作为完整返工操作。
- `completeGenerationAttempt()` 的资产依赖目前来自可选 `payload.sourceIds`。本项目视频的 `dependsOn` 为空，无法从镜头修改追踪到视频。
- 本项目正式交付的 `dependsOn` 也为空，进一步截断了失效传播。
- `lib/domain/invalidation.js` 依赖 `dependsOn` 遍历，无法传播未记录的关系。
- `lib/domain/production.js::resumeProductionRun()` 只恢复失败、阻塞或租约中断任务，不处理已完成任务。这是恢复与重生成不同的语义，不能直接复用按钮冒充重生成。
- `lib/production/drama.js::dramaProductionTasks()` 会复用签名仍有效的设定图与分镜，没有明确的“即使已完成也重新生成指定步骤”范围。
- `applyDevelopmentProposal()` 对已交付分集的规划替换有限制，说明返工需要明确版本与状态转换，不能简单放开状态校验。

## 4. 操作契约

所有入口遵循同一条链路：读取当前版本 → 编辑内容或选择重生成范围 → 展示受影响步骤 → 提交领域命令 → 返回持久任务或保存结果 → 刷新状态与产物。

- **修改**：打开预填当前真实数据的表单；保存领域数据，不把投影节点当成数据源。取消不产生写入。
- **重新生成**：不依赖聊天框草稿；同一操作的重复点击返回同一任务，新的主动重生成建立新任务与新产物版本。
- **替换原文**：导入新源文版本，保留旧源文；不覆写当前不可变源文记录。
- **文本阶段**：复用内容开发 Proposal 和现有源文引用校验；修改正式剧本必须校验镜头和情节覆盖，不能只改展示文字。
- **图片和视频阶段**：编辑对象、镜头说明或生成设置；替换图片必须写入正式资产并更新绑定。
- **只修改标题等展示字段**：不重跑媒体；真正影响内容或生成输入的字段变化才使关联产物失效。
- **受影响产物**：保留为历史版本，标记“内容已更新，需重新生成/合成”；旧交付不能继续占据当前正式成片位置。
- **重新合成**：复用当前有效镜头视频，不默认重新渲染所有视频；若缺少有效镜头，显示具体缺口并跳转对应阶段。
- **并发与失败**：提交包含项目版本和稳定操作 ID；版本冲突要求重新读取，不能覆盖别人刚保存的内容；提交中禁用重复操作，失败可重试且保留输入。
- **状态同步**：重新进入页面或重启服务后可恢复任务显示；项目、阶段、镜头和成片状态保持一致。

不能只删掉 `domainProjection` 的提前返回、把所有按钮接到 `/canvas/node`：这会修改显示副本而不是正式业务数据。也不能把生成门禁放宽为允许任意终态直接执行。

## 5. 文件、改动与验收计划

| 文件 | 计划改动 | 验证方式 |
| --- | --- | --- |
| `studio/app.js`、`studio/app.css` | 按对象显示修改、重生成与替换入口；预填编辑表单、影响范围、任务状态和错误反馈；保持卡片紧凑 | 七页逐个点击；检查对象 ID、保存、取消、失败重试、窄屏和播放行为 |
| `lib/domain/read-models.js` | 提供真实操作目标、可执行动作、禁止原因、当前与历史版本；交付进度依赖当前有效产物 | 旧项目及新项目的状态、动作与产物版本一致；不得显示无效成功状态 |
| `lib/domain/commands/index.js`、`lib/domain/invalidation.js`、必要的 `lib/domain/state-machines.js` | 明确返工命令；内容变化触发正确失效；生成资产、时间线、交付记录完整依赖；已交付项目可进入合法返工状态 | 修改角色、镜头、剧本后，正确影响对应下游；其他分集不误失效；历史产物保留 |
| `lib/production/drama.js`、`lib/domain/production.js` | 区分失败恢复与主动重生成；支持指定实体、镜头、分集及合成范围；生成持久任务并保持幂等 | 已完成任务可主动产生新版本；重复提交不重复排队；只合成不重新生成镜头 |
| `lib/index.js` | 接通页面到保存、文本开发、媒体生成与合成的实际执行路径；返回任务 ID、版本与失败信息 | 浏览器请求实际到达目标项目和对象，独立工作台无需宿主聊天也能操作 |
| `lib/script/novel-production.js`、`lib/script/tools.js` | 复用并补齐分析、规划与本集剧本返工入口，保持源文引用、结构化数据和 Proposal 校验 | 指定文本步骤重做不意外覆盖其他集；缺参或不完整剧本保存失败且不改变原记录 |
| `tests/domain/production-stages.test.js` 及受影响的领域/插件测试 | 覆盖失效、历史数据、终态返工、幂等、版本冲突与依赖传播 | 先复现本报告中的失效断点，再验证修复；运行完整回归与 smoke |

历史数据缺少依赖时，通过已有镜头资产绑定、时间线资产列表与交付时间线关系恢复可验证的关系，不按标题猜测，也不无条件批量标记所有项目失效。

## 6. 实施和验收顺序

1. 先修内容变更与下游失效，确保旧成片不会被误认为当前结果。
2. 接通保存和分阶段返工服务，验证已完成内容也能建立新任务。
3. 给七页添加对应入口，逐个验证表单、范围、请求与反馈。
4. 用隔离测试项目走“修改设定 → 重生成关联图和镜头 → 重新合成 → 页面检查”的真实闭环；所有步骤的动作另有接口和浏览器测试覆盖。
5. 安装并再次逐页检查；静态或模拟测试不能替代真实生成结果。未实跑的远程步骤单独注明，不称为全部已验收。
