# 提示词编排

本文是 meiji 三份开发契约之一，只描述怎样把 `in_puts/*.yaml` 变成模型请求。项目字段见 [项目数据结构](项目数据结构.md)。任务在哪一步发请求见 [任务步骤](任务步骤.md)。

各业务的生成、重新生成和审核平铺在 `meiji/dev_docs/in_puts/`。文件名是「业务-generate.yaml」「业务-regenerate.yaml」「业务-review.yaml」。不另设通用模板，也不另存输出契约。

## 文件形状

文件只保留外层 `mark` 和 `input`。`mark` 解释用途，不进入请求。`input` 中的文字和资料直接转为自然语言，程序不再附加或改写指令。

- `input.system` 定义角色、执行规则、语言要求和输出格式。规则只规定执行方式和内容边界，不重复声明当前任务，不保留「任务范围」字段。
- `input.user.任务` 固定定义当前文件负责的生成、审核或重新生成，不由业务传入。
- `input.user.背景信息` 承载实际资料。适用时直接列修改意见和待审核内容。
- 人物、服装等资料使用实际名称作字段。背景资料较多时按剧情、角色、素材和前镜衔接分类。

生成、审核、重新生成各自使用独立文件，不保留不适用字段。需要 AI 审核的节点使用统一审核返回结构。生成和重新生成使用本节点同一返回结构。

图片、视频的参考文件和接口参数单独传输，不写进提示词正文。尾帧和合片由程序执行，没有 AI 提示词文件。

## 占位符

业务内容使用 `{{中文占位符}}`，例如 `{{输出语言}}`、`{{人物资料}}`、`{{修改意见}}`。替换后直接变成自然语言。占位符缺失则这次渲染失败。注入后的资料不再二次展开，资料里的 `{{ }}` 保持原样。

`{{输出语言}}` 来自项目配置。对白、旁白和心声台词保留来源原文，其余自然语言字段值使用该语言。JSON 字段名、固定枚举值和编号保持协议规定。

每个 YAML 占位符必须由对应业务的提示词资料构建器提供。模板新增、删除或改名占位符时，同步修改 `promptValues`（或媒体请求对应的资料构建器），并用真实资料走一次 `renderTemplate` 集成测试；不能只用测试资料模拟所有占位符。条件资料也必须提供键：无资料时给空字符串，由渲染器省略该字段。模板在每次请求时从磁盘读取，资料构建器则随 Harness 进程加载；YAML 与构建器必须作为一组更新，并重启 Harness 后验证，避免运行进程读到新模板却仍持有旧资料构建器。

没有适用规则时，`{{补充规则}}`、`{{指导素材}}` 为空，渲染时省略该段。有参考素材时 `{{指导素材规则}}` 填固定使用说明。规则怎样从项目 `规则[]` 分进这两个占位符，见 [项目数据结构](项目数据结构.md)。

长文本使用 YAML 的 `|`。无末尾换行时使用 `|-`。规则正文和输出要求中的多条要求按 `1.、2.、3.` 连续编号，不另设分类标题。

## 输出格式

唯一位置是 `input.system.输出格式`，始终为对象。

| 字段 | 用途 |
|---|---|
| `类型` | `JSON`、文本、图片或视频 |
| `结构` | 仅 JSON 返回需要。直接定义模型返回对象的字段和形状 |
| `要求` | 面向模型的返回约束。只保留返回形式，以及结构示例没有写明的枚举、空值、单位、范围和字段含义 |

JSON 生成示例：

```json
"输出格式": {
  "类型": "JSON",
  "结构": { "正文": "摘要正文" },
  "要求": "只返回上述结构的JSON对象，不输出解释或Markdown围栏。正文按本次资料填写。"
}
```

审核示例：

```json
"输出格式": {
  "类型": "JSON",
  "结构": { "通过": true, "原因": "" },
  "要求": "只返回通过和原因。通过时原因为空，不通过时说明具体问题。"
}
```

媒体返回不虚构 JSON 结构：

```json
"输出格式": {
  "类型": "图片",
  "要求": "只输出一张图片，不输出JSON、解释或审核文字。"
}
```

组装时按层级转成标题和正文。不向模型解释文件存储、程序执行或字段读取。内部 id、状态、原因和程序版本不由 AI 输出。AI 用编号引用角色、服装和镜头，程序核对后再换成 id。

文本返回先按 JSON 解析，再按 `结构` 严格校验键和类型，然后核对时长、覆盖和编号引用。镜头表生成与重新生成只要求模型返回 `标题`、`编号`、`参考时长`、`正文`；按故事大纲小段顺序细分镜头，每镜参考时长为1至15秒正整数，拆分规则只用于提示适合的切点。人物资料直接来自项目 `角色库`，不通过逐集筛选的资产清单。程序按数组顺序补 `序号`，并把 `参考时长` 写入项目字段 `时长秒`。整集时长仍按本集参考时长 ±30 秒（下限至少 1 秒）校验；故事大纲小段时长之和须精确等于本集参考时长。结构不合法的结果不覆盖节点。

## 图片参考图

每次图片请求最多一张参考图。`参考图片说明` 由媒体请求处理器根据当前生成/重新生成场景组装，并注入模板占位符；图片文件本身通过接口参数单独传递。角色图片生成是例外：有用户参考图时填固定说明，没有时为空并省略。

| 业务 | 模板 | 参考图 | 来源 |
|---|---|---|---|
| 角色图片生成 | `character-image-generate` | 用户参考图，只用于确定面相与体型。没有则不传 | `角色.参考图.地址` |
| 角色图片重新生成 | `character-image-regenerate` | 当前角色定妆图，作为修改底图 | `角色.图片.地址` |
| 服装图片生成 | `costume-image-generate` | 该角色定妆图，只用于确定身份、面相和体型 | `角色.图片.地址` |
| 服装图片重新生成 | `costume-image-regenerate` | 当前服装图，作为修改底图 | `服装.图片.地址` |

重新生成模板只用于「节点已有图片，且任务带修改意见」。不带意见或没有原图时，重新生成也使用生成模板。服装图片生成要求角色定妆图已生成，由前置检查保证。图片请求不附带角色声线。

## 视频参考图

视频参考图最多 9 张，主体参考与开场衔接的使用方式沿用现有接口，不在提示词正文里塞文件。

- 每个出镜角色：指定了服装就用该服装图，否则用角色定妆图。
- 不是首镜时，上一镜尾帧作为开场画面，上一镜每秒分镜作为衔接资料。
- 远端任务 id 在提交后记到步骤 `result`，不写进提示词。

视频重新生成带修改意见时使用 `video-regenerate`，否则使用 `video-generate`。重新生成不把原视频当作底片传回。
