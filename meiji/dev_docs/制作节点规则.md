# 制作节点规则

节点顺序以 [制作工作流](制作工作流.md) 为准。每个节点的前置条件、生成规则和审核规则都在本文定义，生成规则和审核规则逐条换行。

来源：

- `minimax-h3/h3-prompt-writing`：文生视频、首帧、尾帧、首尾帧、全参考的提示词结构。
- `minimax-h3/3d-animation-short-generator` 及其 `references/shot-table-spec.md`、`storyboard-guidelines.md`、`qc-checklist.md`：故事大纲、角色卡、六列镜头表、每秒指令、文本分镜、单镜视频、拼接和终检。

3D 动画短片 skill 的默认画风是风格化 3D。荷兰角、弹性表演和皮克斯式前缀只在采用该画风时执行，条目前标「3D 动画风格」。画布节点、用户选项卡和 Seedance 回退不写入。其余 7 个风格 skill 各锁一种视觉语言，不改变这里的节点。

单镜时长和 H3 单段成片时长都是 4–15 秒。镜头总时长在本集参考时长 ±30 秒内。

## 项目摘要（`project-summary`）

H3 的项目简报是开拍前的制作说明，不是剧情摘要。本节点仍只根据剧本写简短摘要，不挡住后续流程。

**前置条件：**

1. 项目剧本正文非空。

**生成规则：**

1. 根据完整剧本写项目级简短摘要，不依赖角色提取或分集结果。
2. 只保留剧本已经写出的人物、事件和结局。
3. 剧本没有写明的动机、后传、画幅和总时长不编造。

**审核规则：**

1. 摘要中的人物和事件都能在剧本中找到依据。
2. 摘要没有新增或改变剧情。
3. 表述比剧本短，且没有把后文制作步骤写进摘要。

模板：[`project-summary-generate.yaml`](in_puts/project-summary-generate.yaml)、[`project-summary-review.yaml`](in_puts/project-summary-review.yaml)。

## 剧本重要角色（`project-characters`）

对应 3D 动画短片 skill 的角色卡文字资料。图片由后面的定妆照节点按服装生成。

**前置条件：**

1. 项目剧本正文非空。

**生成规则：**

1. 按重要程度提取角色：主角、形成对比或施压的角色、剧情必需的配角。
2. 每个角色锁定身份：名字、定位、年龄段、身材、发型、服饰颜色、签名道具、不可改特征。
3. 服装和签名道具写在该角色资料里，供定妆照和后续镜头绑定。
4. 沿用项目角色库中已有角色；同一人不得拆成两个身份。
5. 只返回本次新增或变更，不重写已经固定的资料。

**审核规则：**

1. 每个角色的身份和资料都能在剧本中找到依据。
2. 没有把同一角色重复提取成两人。
3. 不可改特征、签名道具和服装没有超出剧本依据。
4. 只审核本次变更，不要求重写未改动的固定资料。

模板：[`project-characters-generate.yaml`](in_puts/project-characters-generate.yaml)、[`project-characters-review.yaml`](in_puts/project-characters-review.yaml)。

## 定妆照

一套服装加上该角色的人物资料，生成一张定妆照。同一角色有多套服装时，每套各一张。镜头没有指定服装时，使用默认服装的定妆照。

**前置条件：**

1. 目标角色存在，且这一套服装已经写在该角色资料中。
2. 人物资料足以确定身份、面相和体型。
3. 用户参考图可选；有则作为面相和体型的依据。

**生成规则：**

1. 根据这一套服装和该角色的人物资料生成一张图，身份和服装在同一张图里。
2. 有条件时使用 16:9。
3. 画面包含主 3/4 视角，以及正面、侧面、背面三视图。
4. 画面包含表情，以及这套服装的颜色、材质和签名道具。
5. 图上标注角色名、角色定位和这套服装的名称，并重复身份锁：年龄段、身材、发型、服饰色、签名道具、不可改特征。
6. 有用户参考图时，用它确定面相和体型，同时穿上资料中的这套服装。
7. 同一角色的各套定妆照保持同一张脸、同一体型和同一不可改特征。
8. 3D 动画风格：风格化 3D，比例和材质在该角色的各套定妆照之间一致。

**审核规则：**

1. 角色名、服装名、定位和身份锁可以读清，且与人物资料和这套服装一致。
2. 三视图、主 3/4 视角和表情都在画面中。
3. 面相、体型、发型和不可改特征与人物资料一致；有用户参考图时与参考图一致。
4. 服装颜色、材质和道具属于资料中的这一套服装。
5. 没有换成另一名角色或另一套服装。
6. 程序确认图片可读取、可解码后才算成功，不另开模型自审。

## 展示摘要（`episode-summary`）

已下载的 skill 没有单独的剧集摘要。本节点只供剧集列表展示，不参与后续生成前置。

**前置条件：**

1. 本集剧情非空。

**生成规则：**

1. 只依据本集剧情提取简短展示摘要。
2. 不补充本集剧情没有写出的情节。
3. 不规划后续镜头或角色。

**审核规则：**

1. 摘要中的事件都能在本集剧情中找到依据。
2. 摘要没有新增、修改或规划剧情。
3. 表述比本集剧情短。

模板：[`episode-summary-generate.yaml`](in_puts/episode-summary-generate.yaml)、[`episode-summary-review.yaml`](in_puts/episode-summary-review.yaml)。

## 故事大纲（`outline`）

对应 3D 动画短片 skill 的故事大纲。各段时长合计等于本集参考时长。

**前置条件：**

1. 剧本模式要求本集剧情非空。
2. 自由创作模式要求项目创作方向非空。

**生成规则：**

1. 写出主角想要什么、需要什么、缺陷是什么。
2. 写出本集生效的核心世界规则。
3. 按因果关系写成有序故事小段，后段由前段的行动或缺陷引出。
4. 标出需要在后面回收的情绪锚点。
5. 用户明确要求台词时，才写入台词节拍；否则不锁定语言。
6. 各段时长合计等于本集参考时长。

**审核规则：**

1. 主角在推动事件，不是只被情节带走。
2. 危机由主角缺陷放大，巧合没有直接解决问题。
3. 结局回收了前面写出的情绪锚点。
4. 施压来自具体关系或处境，不是一个没有行为的反派标签。
5. 台词在改变关系，不是解释主题。
6. 事实、因果和覆盖范围与本集剧情或创作方向一致，只报告有明确依据的遗漏或矛盾。
7. 各段时长合计等于本集参考时长，且每段都能按该时长呈现。

模板：[`outline-generate.yaml`](in_puts/outline-generate.yaml)、[`outline-review.yaml`](in_puts/outline-review.yaml)。

## 镜头表（`shots`）

对应 H3 六列镜头表中除逐秒展开以外的部分。逐秒五要素写在每秒分镜，不在本节点重复每一秒。衔接、锚点、钩子和音频写在正文里。

**前置条件：**

1. 本集故事大纲已有效生成。

**生成规则：**

1. 每个故事小段先作为剧情锚点，再拆成镜头。
2. 模型只返回标题、编号、参考时长、正文。
3. 每镜 4–15 秒，更长就拆开；短于 4 秒的节拍并入相邻镜头。
4. 镜头总时长在本集参考时长 ±30 秒内。
5. 每镜写连续性衔接：如何承接上一镜的结束画面、道具位置、眼神、姿态、声桥或情绪，以及如何为下一镜开场做准备。
6. 每镜写参考锚点：场景中的固定地标及其画面位置、每个出镜角色的画面位置、朝向和初始姿态、上一镜有而本镜没有的角色及其离场原因、光位基线，以及精确角色名。
7. 每镜用中文写一个钩子，只从这八个里选：视觉笑点（靠画面好笑）、反转（结果和预期相反）、悬念（危险或疑问先悬着）、温情（柔和的情感停顿）、追逐（追、逃或赶时间）、揭示（揭开之前没看见的信息）、回扣（呼应前面的画面、台词或道具）、表情拍（重点是表情变化）。
8. 单镜有动作或对白的重要角色不超过 3 人。
9. 同一场景的相邻镜头，固定地标和光位要么保持一致，要么写明如何变化。
10. 景别在特写、大特写和其他景别之间交替，避免连续重复同一种景别。
11. 用户没有明确要求语言时，不锁定对白语言；离屏旁白默认闭嘴，出镜对白默认张嘴。
12. 已经离场的角色至少再记录一镜；连续两镜明确不在场后再从退场记录中去掉。
13. 翻转眼神、人物位置、道具状态或光位时，写明这是硬切或时间跳跃，不能写成自然衔接。
14. 3D 动画风格：追逐、失衡、惊吓或闹剧节拍安排荷兰角。
15. 人物资料直接读取项目角色库，名字与定妆照上的角色名、服装名一致。

**审核规则：**

1. 每镜都有钩子；每连续 3 镜至少 1 镜是揭示、反转或回扣。
2. 开场镜和收尾镜的钩子是视觉笑点、反转、揭示、悬念、温情之一。
3. 没有镜头短于 4 秒或超过 15 秒。
4. 没有镜头超过 3 个有动作或对白的重要角色。
5. 同场景相邻镜头的地标和光位要么继承，要么有明确变化说明。
6. 按连续性衔接逐镜阅读，没有一镜从与上一镜结尾矛盾的状态开始。
7. 人物引用与项目角色库一致，顺序覆盖各个故事小段。
8. 程序已经校验过的编号结构和时长问题，不由审核重复判定。
9. 任一项不通过时列出失败镜头，修订后重新审核；通过前不进入每秒分镜。

模板：[`shots-generate.yaml`](in_puts/shots-generate.yaml)、[`shots-review.yaml`](in_puts/shots-review.yaml)。

## 每秒分镜（`seconds`）

对应镜头表里的每秒指令，以及文本分镜的四象限内容。文本是权威结果；铅笔分镜图只供人眼预览，不能覆盖文本。

**前置条件：**

1. 目标镜头属于本集，且本集镜头表已有效生成。

**生成规则：**

1. 只为当前镜头写逐秒指令，从 0 秒覆盖到该镜最后一帧，中间不留空隙。
2. 普通秒用 `0–1s`、`1–2s`；只有该秒本身是这一镜的钩子时，才追加 `2.0–2.5s` 这类亚秒节拍。
3. 每一秒都写动作、姿态和表情，包括身体、剪影、手持道具、眼神和表情变化。
4. 每一秒都写镜头运动：推、拉、摇、倾、横移、升降、环绕、跟拍、固定或手持晃动；需要时写幅度和速度。
5. 每一秒都写空间位置：人物在画面哪里、拿着什么、哪个地标在画面哪里。
6. 每一秒都写音频线索：旁白、对白、音效、呼吸、沉默；有意无声时写 `silent`。
7. 每一秒都写交给下一秒或下一镜的状态。
8. 旁白所在的秒标记说话人嘴唇闭合；出镜对白所在的秒标记张嘴，并写眼神和身体动作。
9. 面板数量与秒数一致：3 秒 3 格，4 秒 4 格，依此类推。
10. 角色名、服装和地标与镜头表中的锚点使用同一名称。
11. 禁止只写「继续移动」而不写身体、镜头或道具。
12. 3D 动画风格：适用的节拍写明挤压拉伸、预备、过冲、跟随和弧线。

**审核规则：**

1. 从 0 秒到镜尾每一秒都有指令，没有时间空隙。
2. 每一秒都含动作或姿态或表情、镜头、空间、音频、交接这五项。
3. 内容与镜头表的事实、时长、锚点和连续性衔接一致。
4. 动作能在该秒内做完，道具和人物位置能交到下一秒。
5. 说话的秒写明嘴部开合，离屏旁白为闭，出镜对白为开。
6. 不新增镜头表没有的人物、地标和事件。

模板：[`seconds-generate.yaml`](in_puts/seconds-generate.yaml)、[`seconds-review.yaml`](in_puts/seconds-review.yaml)。

## 文本提示词（`storyboard`）

对应 `h3-prompt-writing`。先按每秒分镜写成一条可执行的视听提示，再按当前视频模式套结构。不改时间线、事件和素材引用。

**前置条件：**

1. 目标镜头属于本集。
2. 本集镜头表和该镜头每秒分镜均已有效生成。

**生成规则：**

1. 无参考图时用文生视频。只有首帧、只有尾帧、同时有首尾帧时，分别用首帧、尾帧、首尾帧模式。需要引用人物、服装或其他素材时用全参考模式。
2. 文生视频、首帧、尾帧、首尾帧都使用三个字段，顺序固定：`integrated_multimodal_description`、`overall_soundscape`、`non_diegetic_music`。
3. 文生视频不用图像对齐句，直接从三个字段开始。
4. 首帧模式的第一行声明参考图对齐成片 0.00 秒，然后按「首帧状态、动作开始、连续发展、结果或反应」往下写。
5. 首尾帧模式的第一行声明第一张图对齐 0.00 秒、第二张图对齐成片结束时间；正文按「首帧状态、可见的中间变化、差异逐渐收束、尾帧状态」写。默认保持一个镜头，只有上游明确要求切镜时才写多个镜头。
6. 仅尾帧模式的第一行声明参考图对齐成片结束时间；正文从合理的前一状态收到这张尾帧上。
7. 全参考模式使用六段，顺序固定：`subject_definitions`、`summary`、`retention_analysis`、`detailed_description`、`overall_soundscape`、`non_diegetic_music`。
8. 参考标签一经定义就保持同一含义。人物、服装、场景、道具、风格和动作用 `<Subject N>`。只有这张图本身充当首帧、尾帧或构图锚点时才单独使用 `<Picture N>`。整段视频的剪辑、续写或时间结构用 `<Video N>`。要复制或参照的声音用 `<Audio N>`。
9. 定妆照用来定义 `<Subject N>`。只有这张定妆照本身充当首帧、尾帧或构图锚点时，才再占一个 `<Picture N>`。
10. `summary` 用任务类型开头，只使用已经定义的标签。`retention_analysis` 为每个标签写保留、部分保留、属性转移或弱参考；音频则写全量复制、部分复制、参照或弱参考。
11. 描述总时长等于该镜时长。切镜时间严格递增，并落在该时长之内。第一镜不加时间戳，后一镜写成 `At 00:03.500` 这种切点。
12. 运镜写成完整英文动作，包含运动类型；幅度和速度只在需要时写出。只改变距离或小角度时优先写镜头运动，不无故切镜。
13. 说话人使用跨镜稳定的 `(S1)`、`(S2)`。对白和歌词放在 `<d>` 内并保留原文，不翻译、不改写。旁白使用 `says in an off-screen voiceover`，并紧接写明对应角色嘴唇闭合。
14. 画面上真实可见的文字保留原文，放在英文双引号中。
15. `overall_soundscape` 用 1–4 句概括环境声、动作声和非语言人声，不重复对白。`non_diegetic_music` 用 1–3 句写观众听得见、角色听不见的配乐，只写乐器、速度、节奏和强弱变化。用户要求整段无声时，声景写 `N/A`。
16. 改写正文使用英文。对白、歌词和画面文字保留原语言。
17. 用具体的构图、主体、环境、动作、镜头和声音，不用 `cinematic`、`beautiful` 这类空词，也不把内容写成剧情摘要。
18. 去掉 `[char:…]`、`[scene:…]`、`[shot:…]`、`[dur:…]`、`[hook:…]` 后再交给视频生成。

**审核规则：**

1. 字段名、段序和标签与所选模式一致。
2. 描述总时长等于该镜时长，切点没有超出或倒退。
3. 每个参考标签都有定义，并且前后含义不变。
4. 定妆照没有被错误写成首帧或尾帧，除非该模式确实把它当作帧锚点。
5. 对白、歌词和画面文字没有被翻译或改写。
6. 首帧、尾帧、首尾帧的起止状态与对应参考图对齐。
7. 时间线、事件和素材引用与每秒分镜一致。
8. 提示里没有遗留分镜双绑定标签。

模板：[`storyboard-generate.yaml`](in_puts/storyboard-generate.yaml)、[`storyboard-review.yaml`](in_puts/storyboard-review.yaml)。

## 视频（`video`）

对应单镜头视频片段。文本提示词是这一镜的权威说明。指定了服装就用那套服装的定妆照，没指定就用默认服装的定妆照。

**前置条件：**

1. 目标镜头属于本集。
2. 镜头表和该镜头文本提示词已有效生成。
3. 该镜引用的定妆照已有效生成。
4. 不是首镜时，上一镜尾帧已有效生成。

**生成规则：**

1. 按已审核的文本提示词生成这一镜，保留事件、顺序、结果和素材编号。
2. 角色外观、脸、发型、体型、服装和签名道具以该镜引用的定妆照为准。
3. 不是首镜时，用上一镜尾帧作为与本镜衔接的画面依据。
4. 成片只保留干净画面：不带分镜线稿、手绘草图、面板边框、箭头、时间标记、标签、水印；用户没有要求时不加字幕。
5. 保持项目已确认的画幅。H3 本地权重默认短边 768 像素、24 帧、立体声，单段 4–15 秒。
6. 画面中的地标、人物进出方向和光位与镜头表锚点一致；发生漂移时用锚点原文重试，不用另一条旧片段悄悄替换。
7. 3D 动画风格：渲染为风格化 3D 全彩动画，可在提示前缀中写明设计语言、干净运动和角色设计一致性。

**审核规则：**

1. 程序确认视频可读取、可解码，并且媒体任务成功。
2. 角色身份、服装和签名道具与引用的定妆照一致。
3. 地标落在镜头表写明的画面位置，光位和人物进出方向没有无说明地翻转。
4. 对白能听清，音效落在每秒分镜写明的时间。
5. 成片中没有分镜痕迹和双绑定标签。
6. 成片时长落在该镜计划时长内，并且在 4–15 秒内。

生成提示词：[`video-generate.yaml`](in_puts/video-generate.yaml)。带意见重新生成：[`video-regenerate.yaml`](in_puts/video-regenerate.yaml)。本节点不另开模型自审。

## 跨节点

来自 3D 动画短片 skill 的重生成纪律，适用于上面所有节点。

1. 某套定妆照更新后，引用这套服装的镜头表、每秒分镜、文本提示词和视频改用新图，并按原来的角色名和服装名绑定。
2. 镜头表修订后，重新审核镜头表，再重做受影响镜头的每秒分镜和更下游产物。
3. 每秒分镜或文本提示词修订后，对应视频改用新文本。
4. 同时存在多个版本时，先标明当前采用的版本，再继续下游。
