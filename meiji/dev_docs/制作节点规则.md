# 制作节点规则

节点顺序见 [制作工作流](制作工作流.md)。本文写 AI 节点和程序编排节点。标题标明 `AI` 或 `程序`。文本节点另有审核规则，审核返回 `通过` 和 `原因`：通过时原因为空，不通过时写明问题。定妆照和视频不进行模型审核。

节点生成、审核或后置处理成功后，先数据保存同步，再做下游节点 hash 检查。未通过或失败时不写入新结果，也不检查下游。保存写入项目 Model 的指定字段，并同步到本地项目 JSON，同时记下本节点当时依赖资料的 `依赖hash`。视频节点包含生成后的尾帧截取与校验；视频文件和尾帧都成功后再一起保存。hash 检查在保存完成之后进行。受影响的每个下游节点，按它自己的依赖资料读取那些节点字段，算出 hash，与它已有的 `依赖hash` 比较。不一致，或尚未记录，则把已生成的该节点标为已过期，内容保留，并继续检查它的下游。一致则不标过期，也不从该节点继续向下传递。未生成、未通过、失败、已取消的节点保持原状态。

拆分剧集、故事大纲、镜头表分步交给模型。后一步只能看见前一步写下的内容，所以每一步都要留下上一步里的剧情、动作、场景、情绪和形容词，不能漏掉，也不能改成别的意思。

## 拆分剧集（`script-split`，AI）

拆分剧集不是节点。它把完整剧本切成各集剧情，供后面的故事大纲使用。

**生成规则：**

1. 剧本中的剧情、动作、场景、情绪和形容词都要进入某一集剧情。
2. 不漏段，不跳段，不把这些描述改成概述或另一种说法。
3. 程序按段落原文拼接各集剧情，不改字。

**核对：**

程序对照完整剧本核对。上述描述都还在某一集剧情里，没有被删掉或改写。拆分剧集不另做模型审核。

**依赖资料：**

- `项目.剧本.正文`。剧本不是节点。

**步骤：**

1. 前置条件检查（程序）。
2. 生成（AI）：只决定各集起止段落。
3. 程序按段落原文拼接各集剧情。
4. 数据保存同步。
5. 下游节点 hash 检查。

**数据保存同步：**

把拼接后的剧本原文写入 `剧集[].剧情`，并同步到本地项目 JSON。

**下游节点 hash 检查：**

影响各集展示摘要、故事大纲。展示摘要读取 `剧集[].剧情`。故事大纲在剧本模式读取 `剧集[].剧情`。新剧集还没有已生成的下游时，不标过期。

## 项目摘要（`project-summary`，AI）

**前置条件：**

1. 项目剧本正文非空。

**生成规则：**

1. 根据完整剧本写项目级简短摘要。
2. 只保留剧本已经写出的人物、事件和结局。
3. 剧本没有写明的动机、后传、画幅和总时长不写入摘要。

**返回结构：**

一段项目摘要。里面只写剧本已经写出的人物、事件和结局。

**审核规则：**

1. 摘要中的人物和事件都能在剧本中找到依据。
2. 摘要没有新增或改变剧情。
3. 表述比剧本短。

**依赖资料：**

- `项目.剧本.正文`。剧本不是节点。

**步骤：**

1. 前置条件检查（程序）。
2. 生成（AI）。
3. 审核（AI）。未通过时，带审核意见和原内容重新生成（AI），再审核（AI）。
4. 数据保存同步。
5. 下游节点 hash 检查。

**数据保存同步：**

审核通过后，把摘要写入 `项目摘要.正文`，并同步到本地项目 JSON。

**下游节点 hash 检查：**

没有下游。保存后不标过期。

## 剧本重要角色（`project-characters`，AI）

**前置条件：**

1. 项目剧本正文非空。

**生成规则：**

1. 按重要程度提取角色：主角、形成对比或施压的角色、剧情必需的配角。
2. 每个角色写明名字、定位、年龄段、身材、发型、服饰颜色、签名道具、不可改特征。
3. 每套服装写明名称、颜色、材质和随服装出现的道具。
4. 沿用项目角色库中已有角色；同一人只保留一个身份。
5. 只返回本次新增或变更。

**返回结构：**

```json
{
  "角色": [
    {
      "名字": "",
      "定位": "",
      "年龄段": "",
      "身材": "",
      "发型": "",
      "服饰颜色": "",
      "签名道具": "",
      "不可改特征": "",
      "服装": [
        { "名称": "", "颜色": "", "材质": "", "道具": "" }
      ]
    }
  ]
}
```

只列本次新增或变更的角色。没有变更时，`角色` 为空数组。同一人只出现一次，用名字对应角色库里已有的人。

**审核规则：**

1. 每个角色的身份和资料都能在剧本中找到依据。
2. 同一角色没有被拆成两人。
3. 不可改特征、签名道具和服装没有超出剧本依据。
4. 只审核本次变更。

**依赖资料：**

- `项目.剧本.正文`。剧本不是节点。

**步骤：**

1. 前置条件检查（程序）。
2. 生成（AI）。
3. 审核（AI）。未通过时，带审核意见和原内容重新生成（AI），再审核（AI）。
4. 数据保存同步。
5. 下游节点 hash 检查。

**数据保存同步：**

审核通过后，把本次新增或变更写入 `角色库.角色[]`。角色字段为 `名字`、`定位`、`年龄段`、`身材`、`发型`、`服饰颜色`、`签名道具`、`不可改特征`。服装字段为 `服装[].名称`、`颜色`、`材质`、`道具`。程序保留已有 id 和编号。并同步到本地项目 JSON。

**下游节点 hash 检查：**

人物资料变化时，影响该角色的全部定妆照。只有某套服装资料变化时，只影响该套定妆照。定妆照按自己的依赖资料读取这些角色字段或服装字段。定妆照被标为已过期后，再检查它的下游。

## 定妆照（AI）

**前置条件：**

1. 目标角色存在，且这一套服装已经写在该角色资料中。
2. 人物资料足以确定身份、面相和体型。
3. 用户参考图可选。

**生成规则：**

1. 按这一套服装和该角色的人物资料生成一张定妆照。
2. 同一角色有多套服装时，每套各生成一张。
3. 主画面是该角色穿着这套服装的单一 3/4 视角，脸、体型和服装同时可见。
4. 表情、服装颜色、材质和签名道具与资料一致。
5. 有用户参考图时，用它确定面相和体型；服装以资料中的这套服装为准。
6. 同一角色的各套定妆照保持同一张脸、同一体型和同一不可改特征。
7. 画面不印角色名、服装名、说明文字和分镜标记。

**返回结构：**

这一套服装的一张定妆照。单一 3/4 视角，脸、体型和这套服装同时可见。不返回 JSON，画面上不写角色名、服装名或说明。不进行模型审核。

**依赖资料：**

- 角色图片：`角色库.角色` 的 `名字`、`定位`、`年龄段`、`身材`、`发型`、`服饰颜色`、`签名道具`、`不可改特征`。
- 服装图片：该套 `服装` 的 `名称`、`颜色`、`材质`、`道具`，以及同一角色的 `名字`、`身材`、`发型`、`不可改特征`。

**步骤：**

1. 前置条件检查（程序）。
2. 生成（AI）。
3. 数据保存同步。
4. 下游节点 hash 检查。

**数据保存同步：**

生成完成后，角色图片写入 `角色库.角色[].图片.地址`，服装图片写入 `角色库.角色[].服装[].图片.地址`，并同步到本地项目 JSON。

**下游节点 hash 检查：**

影响使用这张图的多模态提示词。多模态提示词按自己的依赖资料读取对应的 `图片.地址` 和 `图片.依赖hash`。文生视频提示词不依赖定妆照，不检查。多模态提示词被标为已过期后，再检查它的下游。

## 展示摘要（`episode-summary`，AI）

**前置条件：**

1. 本集剧情非空。

**生成规则：**

1. 只依据本集剧情提取简短展示摘要。
2. 不补充本集剧情没有写出的情节。
3. 不写入后续镜头或角色安排。

**返回结构：**

一段展示摘要。只写本集剧情里已经发生的事件。

**审核规则：**

1. 摘要中的事件都能在本集剧情中找到依据。
2. 摘要没有新增或修改剧情。
3. 表述比本集剧情短。

**依赖资料：**

- `剧集[].剧情`。剧情不是节点。

**步骤：**

1. 前置条件检查（程序）。
2. 生成（AI）。
3. 审核（AI）。未通过时，带审核意见和原内容重新生成（AI），再审核（AI）。
4. 数据保存同步。
5. 下游节点 hash 检查。

**数据保存同步：**

审核通过后，把摘要写入 `剧集[].摘要.正文`，并同步到本地项目 JSON。

**下游节点 hash 检查：**

没有下游。保存后不标过期。

## 故事大纲（`outline`，AI）

**前置条件：**

1. 剧本模式要求本集剧情非空。
2. 自由创作模式要求项目创作方向非空。

**生成规则：**

1. 剧本模式按本集剧情写成有序故事小段，覆盖其中的事件和因果。
2. 剧本模式不漏掉、也不改写本集剧情里的剧情、动作、场景、情绪和形容词。可以调整叙述顺序的写法，不能用笼统概述换掉这些具体描述。
3. 剧本模式不补充剧情没有写出的动机、缺陷、世界规则和台词。
4. 自由创作写明主角想要什么、需要什么、缺陷是什么，以及本集生效的世界规则。
5. 自由创作按因果关系排列故事小段，并标出需要在后面回收的情绪锚点。
6. 自由创作只在用户明确要求台词时写入台词节拍。
7. 各段时长合计等于本集参考时长。

**返回结构：**

剧本模式：

```json
{
  "小段": [
    { "序号": 1, "时长秒": 0, "事件": "", "因果": "" }
  ]
}
```

自由创作：

```json
{
  "想要": "",
  "需要": "",
  "缺陷": "",
  "世界规则": "",
  "小段": [
    { "序号": 1, "时长秒": 0, "因果": "", "情绪锚点": "", "台词节拍": "" }
  ]
}
```

两种模式的 `时长秒` 都是正数，合计等于本集参考时长。自由创作里，用户没有要求台词时不写 `台词节拍`。

**审核规则：**

1. 剧本模式的事实、因果和覆盖范围与本集剧情一致。本集剧情里的剧情、动作、场景、情绪和形容词都还在对应小段里，没有被漏掉或改成别的意思。
2. 自由创作中，危机来自主角缺陷，巧合没有直接解决问题。
3. 自由创作的结局回收了前面写出的情绪锚点。
4. 自由创作的台词在改变关系。
5. 各段时长合计等于本集参考时长，且每段都能按该时长呈现。

**依赖资料：**

- 剧本模式：`剧集[].剧情`。剧情不是节点。
- 自由创作：`项目.创作方向`。创作方向不是节点。

**步骤：**

1. 前置条件检查（程序）。
2. 生成（AI）。
3. 审核（AI）。未通过时，带审核意见和原内容重新生成（AI），再审核（AI）。
4. 数据保存同步。
5. 下游节点 hash 检查。

**数据保存同步：**

审核通过后写入 `剧集[].故事大纲`。剧本模式保存 `小段[].序号`、`时长秒`、`事件`、`因果`。自由创作另保存 `想要`、`需要`、`缺陷`、`世界规则`，小段另保存 `情绪锚点`；用户要求台词时再保存 `台词节拍`。并同步到本地项目 JSON。

**下游节点 hash 检查：**

影响该集镜头表。镜头表按自己的依赖资料读取故事大纲的上述字段，以及 `故事大纲.依赖hash`。

## 镜头表（`shots`，AI）

一次生成本集全部镜头。这里只规划每一镜的内容、时间和跨镜关系，不写逐秒指令。逐秒动作留给后面的每秒分镜，每次只做一镜。

**前置条件：**

1. 本集故事大纲已有效生成。

**生成规则：**

1. 每个故事小段先作为剧情锚点，再拆成镜头。
2. 每镜 4–15 秒。更长就拆开。短于 4 秒的节拍并入相邻镜头。
3. 镜头总时长在本集参考时长 ±30 秒内。
4. `正文` 写本镜事件：谁在画面里、做了什么、结果是什么。不写每一秒的运镜和站位。故事小段里已经写出的剧情、动作、场景、情绪和形容词必须留在对应镜头里，不能漏掉，也不能改成概述或另一种意思。可以拆进多镜，不能跨小段丢掉。
5. 每镜写连续性衔接：如何承接上一镜的结束画面、道具位置、眼神、姿态、声桥或情绪，以及如何为下一镜开场做准备。
6. 每镜写参考锚点：固定地标及其画面位置，每个出镜角色的画面位置、朝向、初始姿态和服装，上一镜有而本镜没有的角色及其离场原因，以及光位基线。
7. 每镜用中文写一个钩子，只从这八个里选：视觉笑点（靠画面好笑）、反转（结果和预期相反）、悬念（危险或疑问先悬着）、温情（柔和的情感停顿）、追逐（追、逃或赶时间）、揭示（揭开之前没看见的信息）、回扣（呼应前面的画面、台词或道具）、表情拍（重点是表情变化）。
8. 每镜定一个景别。景别在特写、大特写和其他景别之间交替。
9. 每镜写音频安排：有没有旁白、对白和关键音效，谁在说话。不写到某一秒。用户没有明确要求语言时，不锁定对白语言。
10. 单镜有动作或对白的重要角色不超过 3 人。
11. 同一场景的相邻镜头，固定地标和光位要么保持一致，要么写明如何变化。
12. 已经离场的角色至少再记录一镜。连续两镜明确不在场后，不再记录。
13. 眼神、人物位置、道具状态或光位发生翻转时，在连续性衔接里写明这是硬切或时间跳跃。
14. 出镜角色和服装使用角色库中的名字。

**返回结构：**

```json
{
  "镜头": [
    {
      "标题": "",
      "编号": "S01",
      "参考时长": 12,
      "景别": "",
      "钩子": "视觉笑点",
      "正文": "",
      "连续性衔接": "",
      "参考锚点": {
        "固定地标": "",
        "人物位置": "",
        "离场角色": "",
        "光位": ""
      },
      "音频安排": {
        "旁白": "",
        "对白": "",
        "音效": ""
      }
    }
  ]
}
```

`参考时长` 是 4–15 的整数秒。`钩子` 只用规定的八个词之一。没有旁白、对白或音效时，对应项为空字符串。

**审核规则：**

1. 每镜都有钩子。每连续 3 镜至少 1 镜是揭示、反转或回扣。
2. 开场镜和收尾镜的钩子是视觉笑点、反转、揭示、悬念、温情之一。
3. 没有镜头短于 4 秒或超过 15 秒。
4. 镜头总时长在本集参考时长 ±30 秒内。
5. 没有镜头超过 3 个有动作或对白的重要角色。
6. 同场景相邻镜头的地标和光位要么继承，要么有明确变化说明。
7. 按连续性衔接逐镜阅读，没有一镜从与上一镜结尾矛盾的状态开始。
8. 景别在特写、大特写和其他景别之间交替。
9. 人物和服装与角色库一致，镜头顺序覆盖各个故事小段。每个小段里的剧情、动作、场景、情绪和形容词都能在对应镜头中找到，意思没有被修改。
10. 正文、衔接、锚点和音频安排停留在整镜层面，没有拆成逐秒动作。
11. 编号结构和时长由程序校验。审核不重复判定这两项。
12. 未通过的镜头表不能作为每秒分镜的输入。

**依赖资料：**

- `剧集[].故事大纲` 的 `小段[].序号`、`时长秒`、`事件`、`因果`。自由创作再读 `想要`、`需要`、`缺陷`、`世界规则`、`小段[].情绪锚点`、`台词节拍`。
- `故事大纲.依赖hash`。

**步骤：**

1. 前置条件检查（程序）。
2. 生成（AI）。
3. 审核（AI）。未通过时，带审核意见和原内容重新生成（AI），再审核（AI）。
4. 数据保存同步。
5. 下游节点 hash 检查。

**数据保存同步：**

审核通过后写入 `剧集[].镜头表.镜头[]` 的 `标题`、`编号`、`时长秒`、`景别`、`钩子`、`正文`、`连续性衔接`、`参考锚点`、`音频安排`。模型返回的 `参考时长` 写入 `时长秒`。程序保留已有镜头 id，并补 `序号`。并同步到本地项目 JSON。

**下游节点 hash 检查：**

影响该集每个镜头的每秒分镜。每秒分镜按自己的依赖资料读取该镜的 `标题`、`编号`、`时长秒`、`景别`、`钩子`、`正文`、`连续性衔接`、`参考锚点`、`音频安排`，以及 `镜头表.依赖hash`。

## 每秒分镜（`seconds`，AI）

一次只生成当前这一镜。镜头的时长、事件、景别、钩子、衔接、锚点和音频安排以镜头表为准，这里只把它们落到每一秒。

**前置条件：**

1. 目标镜头属于本集。
2. 本集镜头表已有效生成，且这一镜的时长、正文、景别、钩子、连续性衔接、参考锚点和音频安排都已写明。

**生成规则：**

1. 只为当前镜头写逐秒指令，从 0 秒覆盖到该镜最后一帧，中间不留空隙。
2. 不改这一镜的时长、边界、事件、景别、钩子、出镜人物、服装、地标和光位。
3. 第一秒从本镜连续性衔接写明的开场状态开始。最后一秒的交接，落到镜头表为下一镜准备的开场；已经是最后一镜时，落到本镜结尾。
4. 普通秒用 `0–1s`、`1–2s`。只有该秒本身是这一镜的钩子时，才追加 `2.0–2.5s` 这类亚秒节拍。
5. 每一秒都写动作、姿态和表情，包括身体、手持道具、眼神和表情变化。
6. 每一秒都写镜头运动：推、拉、摇、倾、横移、升降、环绕、跟拍、固定或手持晃动。运动留在镜头表已定的景别里。需要时写幅度和速度。
7. 每一秒都写空间位置，并落在参考锚点已写的地标和人物位置上。不新增地标，不把人物改到锚点以外的位置。
8. 每一秒都写音频线索。只把本镜音频安排里的旁白、对白和音效落到具体秒，不新增镜头表没有的台词。没有声音时写明无声。
9. 旁白所在的秒写明说话人嘴唇闭合。出镜对白所在的秒写明张嘴，并写眼神和身体动作。
10. 每一秒都写交给下一秒的状态。
11. 每一秒一格。只有钩子所在秒追加了亚秒节拍时，才可以多一格。
12. 角色名、服装和地标与镜头表使用同一名称。
13. 每一秒都写明身体、镜头或道具的具体变化。

**返回结构：**

```json
{
  "分镜": [
    {
      "时段": "0–1s",
      "动作": "",
      "镜头": "",
      "空间": "",
      "音频": "",
      "交接": ""
    }
  ]
}
```

从 `0–1s` 起逐秒覆盖到镜尾，中间不留空隙。每一秒一格。只有这一镜的钩子所在秒，才可以再加一格，时段写成 `2.0–2.5s` 这样。

`动作` 写身体、手持道具、姿态、眼神和表情。`镜头` 写推、拉、摇、倾、横移、升降、环绕、跟拍、固定或手持晃动，需要时写幅度和速度。`空间` 写人物位置、手持物和地标位置。`音频` 写这一秒的旁白、对白、音效、呼吸或无声，并写嘴部开合。`交接` 写交给下一秒的状态。

**审核规则：**

1. 从 0 秒到镜尾每一秒都有指令，没有时间空隙。覆盖时长等于镜头表的参考时长。
2. 每一秒都含动作或姿态或表情、镜头、空间、音频、交接这五项。
3. 事件、人物、服装、景别、钩子、地标、光位和台词与镜头表一致。没有改时长，没有拆镜或并镜。
4. 第一秒接得上本镜连续性衔接。人物和地标落在参考锚点写明的位置。
5. 动作能在该秒内做完，道具和人物位置能交到下一秒。
6. 说话的秒写明嘴部开合。离屏旁白为闭，出镜对白为开。
7. 没有新增镜头表中不存在的人物、服装、地标、事件和台词。

**依赖资料：**

- 该镜 `镜头` 的 `标题`、`编号`、`时长秒`、`景别`、`钩子`、`正文`、`连续性衔接`、`参考锚点`、`音频安排`。
- `镜头表.依赖hash`。

**步骤：**

1. 前置条件检查（程序）。
2. 生成（AI）。
3. 审核（AI）。未通过时，带审核意见和原内容重新生成（AI），再审核（AI）。
4. 数据保存同步。
5. 下游节点 hash 检查。

**数据保存同步：**

审核通过后，把逐秒内容写入 `剧集[].镜头表.镜头[].每秒分镜.分镜[]` 的 `时段`、`动作`、`镜头`、`空间`、`音频`、`交接`，并同步到本地项目 JSON。

**下游节点 hash 检查：**

影响该镜文生视频提示词。文生视频提示词按自己的依赖资料读取 `每秒分镜.分镜[]` 的上述字段，以及 `每秒分镜.依赖hash`。

## 文生视频提示词（`storyboard`，AI）

模型只生成这一份。首尾帧和多模态不在这一步生成。

**前置条件：**

1. 目标镜头属于本集。
2. 本集镜头表和该镜头每秒分镜均已有效生成。

**生成规则：**

1. 只转写该镜每秒分镜。不改时间线、事件、角色、服装和时长。
2. 不引用定妆照，也不引用上一镜尾帧。
3. 描述总时长等于该镜时长。每秒分镜没有写切镜时，提示里不增加切点。有切镜时，切点严格递增并落在该时长之内，第一段不加时间戳。
4. 运镜写成完整英文动作，包含运动类型。幅度和速度只在每秒分镜写了的时候才写。
5. 说话人使用跨镜稳定的 `(S1)`、`(S2)`。对白和歌词放在 `<d>` 内并保留原文。旁白写明对应角色嘴唇闭合。
6. 画面上真实可见的文字保留原文。
7. `overall_soundscape` 用 1–4 句概括环境声、动作声和非语言人声，不重复对白。`non_diegetic_music` 用 1–3 句写角色听不见的配乐，只写乐器、速度、节奏和强弱变化。整段无声时，声景写 `N/A`。
8. 画面描述使用英文。对白、歌词和画面文字保留原语言。
9. 用具体的构图、主体、环境、动作、镜头和声音写提示。
10. 提示中的画面描述不包含角色名贴片、时间码、钩子名称和分镜标记。

**返回结构：**

只返回文生视频这三段：

```text
integrated_multimodal_description:
overall_soundscape:
non_diegetic_music:
```

画面描述用英文。对白、歌词和画面文字保留原文，对白放在 `<d>` 里，说话人用跨镜稳定的 `(S1)`、`(S2)`。没有切镜时不写切点。`overall_soundscape` 用 1–4 句写环境声、动作声和非语言人声，不重复对白；整段无声时写 `N/A`。`non_diegetic_music` 用 1–3 句写乐器、速度、节奏和强弱。

**审核规则：**

1. 只有上述三段，没有定妆照标签，也没有尾帧对齐。
2. 描述总时长等于该镜时长，切点没有超出或倒退。
3. 对白、歌词和画面文字没有被翻译或改写。
4. 时间线、事件、角色、服装和素材与每秒分镜一致。
5. 提示中的画面描述没有角色名贴片、时间码、钩子名称和分镜标记。

**依赖资料：**

- `剧集[].镜头表.镜头[].每秒分镜.分镜[]` 的 `时段`、`动作`、`镜头`、`空间`、`音频`、`交接`。
- `每秒分镜.依赖hash`。

**步骤：**

1. 前置条件检查（程序）。
2. 生成（AI）。
3. 审核（AI）。未通过时，带审核意见和原内容重新生成（AI），再审核（AI）。
4. 数据保存同步。
5. 下游节点 hash 检查。

**数据保存同步：**

审核通过后，把三段写入 `剧集[].镜头表.镜头[].文生视频提示词` 的 `integrated_multimodal_description`、`overall_soundscape`、`non_diegetic_music`，并同步到本地项目 JSON。

**下游节点 hash 检查：**

影响该镜首尾帧提示词、多模态提示词和视频。首尾帧提示词按自己的依赖资料读取文生视频三段和 `文生视频提示词.依赖hash`，以及上一镜 `尾帧.地址`、`尾帧.依赖hash`。多模态提示词读取文生视频三段和 `文生视频提示词.依赖hash`，以及绑定的 `图片.地址`、`图片.依赖hash`。视频读取它这次实际使用的那一份提示词字段。某一项字段的 hash 仍一致时，不标该节点过期，也不从它继续向下传递。

## 首尾帧与多模态提示词（程序）

这两份由程序编排，不调用模型，也不另做模型审核。`prompt` 使用已通过的文生视频三段，原文不改。一次视频请求只使用一种结构。首尾帧的 `input_reference`、`last_frame` 不能和 `reference_images`、`reference_videos`、`reference_audios` 出现在同一次请求里。本项目用 JSON 提交，不用 multipart。

**前置条件：**

1. 该镜头文生视频提示词已有效生成。
2. 首尾帧另要求不是首镜，且上一镜尾帧已有效生成。首镜不编排首尾帧。
3. 多模态另要求镜头写了出镜角色，且对应服装的定妆照已有效生成。没有指定服装时，使用默认服装的定妆照。没有出镜角色时不编排多模态。

**编排规则：**

1. `model` 固定为 `elysium-video`。`seconds` 等于该镜计划时长，为 4–15 的整数。`size` 由项目画幅换算：`1344x768` 为 `1024x576`，`768x1344` 为 `576x1024`。
2. 图片只使用 PNG、JPEG、WebP。地址必须是 data URL；首尾帧图片也允许裸 Base64。不使用 HTTP 地址。
3. 首尾帧的 `prompt` 在文生视频三段前加一行，声明上一镜尾帧对齐本镜 0.00 秒，然后空一行，再照抄三段原文。`input_reference` 填上一镜尾帧。本镜尾帧要等这条视频生成后再截取，编排时不填 `last_frame`，提交时省略该字段。
4. 多模态的 `prompt` 就是文生视频三段，不加帧对齐。`reference_images` 按出镜顺序填定妆照的 data URL，同一张图只出现一次，最多 9 张。定妆照表示人物身份和服装，不是首帧。本项目不使用参考视频和参考音频，`reference_videos`、`reference_audios` 留空，提交时省略。
5. 两份分开保存。多模态请求不带 `input_reference` 和 `last_frame`。首尾帧请求不带三个参考数组。

**编排结果：**

首尾帧：

```json
{
  "model": "elysium-video",
  "prompt": "<Picture 1> aligns with 0.00 seconds. It is the previous shot's last frame.\n\nintegrated_multimodal_description:\noverall_soundscape:\nnon_diegetic_music:",
  "seconds": 12,
  "size": "1024x576",
  "input_reference": "上一镜尾帧"
}
```

多模态：

```json
{
  "model": "elysium-video",
  "prompt": "integrated_multimodal_description:\noverall_soundscape:\nnon_diegetic_music:",
  "seconds": 12,
  "size": "1024x576",
  "reference_images": ["定妆照 data URL"]
}
```

`prompt` 里的三段换成该镜已通过的文生视频原文。`seconds` 换成该镜时长。`size` 换成该项目画幅对应的尺寸。`reference_images` 换成本镜实际绑定的定妆照，一张图一个元素。

**依赖资料：**

首尾帧提示词：

- `剧集[].镜头表.镜头[].文生视频提示词` 的 `integrated_multimodal_description`、`overall_soundscape`、`non_diegetic_music`，以及 `文生视频提示词.依赖hash`。
- 上一镜 `尾帧.地址`、`尾帧.依赖hash`。

多模态提示词：

- 同上文生视频三段，以及 `文生视频提示词.依赖hash`。
- 出镜角色对应的 `角色库.角色[].图片.地址` 或 `角色库.角色[].服装[].图片.地址`，以及该图片的 `依赖hash`。

**步骤：**

1. 前置条件检查（程序）。
2. 按文生视频原文编排首尾帧请求、多模态请求（程序）。
3. 数据保存同步。
4. 下游节点 hash 检查。

**数据保存同步：**

编排完成后写入该镜。首尾帧写入 `剧集[].镜头表.镜头[].首尾帧提示词` 的 `model`、`prompt`、`seconds`、`size`、`input_reference`。多模态写入 `剧集[].镜头表.镜头[].多模态提示词` 的 `model`、`prompt`、`seconds`、`size`、`reference_images`。首镜不写首尾帧。没有出镜角色时不写多模态。并同步到本地项目 JSON。

**下游节点 hash 检查：**

影响该镜视频。视频按自己的依赖资料读取这次实际使用的那一份提示词字段，以及它绑定的 `图片.地址`、`图片.依赖hash` 或上一镜 `尾帧.地址`、`尾帧.依赖hash`。

## 视频（`video`，AI 生成并由程序完成尾帧后处理）

**前置条件：**

1. 目标镜头属于本集。
2. 该镜头文生视频提示词已有效生成。
3. 本镜使用多模态时，多模态编排已完成，且绑定的定妆照已有效生成。
4. 本镜使用首尾帧时，首尾帧编排已完成，且上一镜尾帧已有效生成。

**生成规则：**

1. 按本镜这次调用对应的一份请求生成这一镜，保留事件、顺序、结果和素材编号。有出镜角色时调用多模态请求；不是首镜且没有出镜角色时调用首尾帧请求；首镜且没有出镜角色时只发送 `model`、`prompt`、`seconds`、`size`，`prompt` 为文生视频三段。两份编排都存在时不合并，也不把首尾帧字段和多模态字段放进同一次请求。
2. 有出镜角色时，脸、体型、服装和签名道具以多模态编排绑定的定妆照为准。
3. 不是首镜时，0.00 秒的画面以上一镜尾帧为准。
4. 成片不带分镜线稿、说明文字、角色名贴片、时间码、钩子名称、字幕和水印。用户明确要求字幕时除外。
5. 画幅使用项目已确认的画幅。时长等于该镜计划时长，并在 4–15 秒内。
6. 地标、人物进出方向和光位与镜头表锚点一致。

**返回结构：**

模型返回这一镜的一条视频。时长等于该镜计划时长，并在 4–15 秒内。不返回 JSON 或说明文字。不进行模型审核。视频任务随后由程序截取并校验该视频尾帧。

**依赖资料：**

- 有出镜角色：`镜头[].多模态提示词` 的 `model`、`prompt`、`seconds`、`size`、`reference_images`，以及 `多模态提示词.依赖hash`。另读所绑定的 `图片.地址`、`图片.依赖hash`。
- 不是首镜且没有出镜角色：`镜头[].首尾帧提示词` 的 `model`、`prompt`、`seconds`、`size`、`input_reference`，以及 `首尾帧提示词.依赖hash`。另读上一镜 `尾帧.地址`、`尾帧.依赖hash`。
- 首镜且没有出镜角色：`镜头[].文生视频提示词` 的三段，以及 `文生视频提示词.依赖hash`。

**步骤：**

1. 前置条件检查（程序）。
2. 生成视频（AI）。
3. 校验视频文件可读取（程序）。
4. 从视频截取最后一帧，并确认图片可读取（程序）。
5. 同一任务中一起保存视频地址与尾帧地址，并同步到本地项目 JSON。
6. 下游节点 hash 检查。

**数据保存同步：**

视频和尾帧都成功并可读取后，把视频地址写入 `剧集[].镜头表.镜头[].视频.地址`，把尾帧地址写入 `剧集[].镜头表.镜头[].尾帧.地址`，并同步到本地项目 JSON。生成或截帧任一步失败时，视频任务失败，不提交本轮新视频或尾帧，也不进行下游 hash 检查。

**下游节点 hash 检查：**

影响本集合片和下一镜视频。合片按自己的依赖资料读取本集各镜 `视频.地址`、`视频.依赖hash`。下一镜在使用首尾帧时，读取本镜 `尾帧.地址`、`尾帧.依赖hash`；因此本镜视频任务完成后，比较并更新该下游视频的依赖状态。下一镜文生视频提示词和多模态提示词不依赖尾帧，不检查。已经是最后一镜时，没有下一镜可检查。

## 合片（`assembly`，程序）

**前置条件：**

**执行规则：**

1. 按镜头序号拼接。
2. 确认合片文件可读取。

**返回结构：**

本集的一条合片。

**依赖资料：**

- 本集各镜按 `序号` 排列的 `视频.地址`、`视频.依赖hash`。

**步骤：**

1. 前置条件检查（程序）。
2. 按镜头顺序拼接（程序）。
3. 数据保存同步。
4. 下游节点 hash 检查。

**数据保存同步：**

把地址写入 `剧集[].合片.地址`，并同步到本地项目 JSON。

**下游节点 hash 检查：**

没有下游。保存后不标过期。
