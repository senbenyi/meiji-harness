# 镜头-视频（`video`，生成并完成尾帧后处理）

- 误差时长：±5秒。
- 重试轮次：2（首次后最多修订两次）。
- 接口：[视频接口与成片编排设计](../../../docs/implement/1016-视频接口与成片编排设计.md)。

## 前置条件

目标镜头属于本集；镜头表及文生提示词有效，`video_generation_type`与当前出镜绑定确定的类型一致。首尾帧要求对应编排和前镜尾帧有效；多模态要求对应编排和本镜人物/服装定妆照有效。文生不要求图片。

## 执行

1. 发送到现有`textBaseUrl`的`/videos/generations`，模型MiniMax-H3。文生使用已审核三段；素材模式使用已保存编排正文和素材地址。每轮只发一种模式，不重写已审核台词、人物或时间线。
2. HTTP共用字段`model/mode/prompt/duration/resolution/ratio`。duration为本镜4–15整数秒，resolution固定768P；文生和多模态用项目比例，首尾帧ratio固定adaptive。
3. 首尾帧只读前镜尾帧发送first_frame，不传不存在的目标last_frame。多模态按编排顺序读取图片发送images，按正文映射保持人物身份与服装；不混前镜尾帧。程序发送前校验并转image data URL，不把Base64写进项目。
4. 服务端提交并查询MiniMax，成功返回task_id/status/url；Harness检查status=succeeded，再立即下载视频。无需旧网关的提交ID查询和content接口。HTTP详情保留生成及下载两个阶段。
5. 下载后检查文件、按项目像素归一化、实测时长，截取并校验视频最后一帧。apply步骤完成这些后处理，全部成功后才能成对提交视频与尾帧。
6. 程序审核检查实测处于4–15秒且相对参考时长差不超过±5秒。未通过时按原有额度修订，正文从已保存编排加本轮意见开始；额度用尽保留本轮有效文件配对为rejected，保留原成功hash，不更新下游。

服务端错误、网络或下载失败、不可读文件、截帧失败和取消均不覆盖旧媒体配对，不自动重新提交付费生成。HTTP状态和原因真实显示，包括402余额不足及503未配置密钥。取消通过断开本地请求停止服务端等待，但当前上游客户端没有调用MiniMax远端撤销接口，已受理生成不保证撤销费用。

视频规则仍遵守已审核分镜：参考图只约束对应人物身份与服装，不增角色，不改变事件/动作顺序，不新增角色名贴片、时间码、水印或字幕（用户明确要求字幕除外）。

## 保存与下游

成功后写`video.address`、镜头`actual_duration_seconds`和`last_frame.address`，视频与尾帧generated并写指纹；集实际时长为各镜实测总和，不用预算代替。镜像同步到项目JSON。

影响本集合片，及下一镜确实使用首尾帧时的编排和视频。下一镜文生和多模态不读取前尾帧。独立tail不接受新任务，历史仍可查看；尾帧是视频任务产物。

人工导入不调用AI、不要求文本已生成，仍在同任务做文件校验、实测和截尾帧，成对保存。
