# 项目-剧本重要角色（`project-characters`，AI）

**固定属性：**

- 误差时长：无
- 重试轮次：2

**步骤：**

1. 前置条件检查（程序）。
2. 生成（AI）。
3. 程序审核。本节点不适用，跳过。
4. AI 审核。未通过且未达重试轮次时，把原因作为修改意见，带原内容重新生成，再做 AI 审核。达到重试轮次仍未通过则保留本轮内容，节点进入未通过，不更新下游。
5. 数据保存同步。
6. 下游节点 hash 检查。

**前置条件：**

1. 项目剧本正文非空。
2. [项目-剧本](项目-剧本审核.md) 节点已生成（审核通过或人工放行）且剧本未变化。

**生成规则：**

1. 只在剧本明确给出姓名的人物中，按重要程度提取实际出镜或发声并承担独立剧情作用的主角、形成对比或施压的角色、剧情必需的配角。仅被提及、名单展示、背景介绍，或只被借用其方法、发明、言论的人不建卡。修改意见与这条冲突时以这条为准，不得把这类人补进名单。无姓名人物一律排除，不设重要性例外；职业、身份、序号、站位及动作称谓不算姓名，例如“第三位旅行勇士”。不为凑齐人数建卡，不自行起名；卡外人物的剧情、动作和对白仍由分镜保留。
2. 性别、年代、年龄段、身材、发型、面部特征、身高、声线必须为字符串。原文有则原样保留，不把性格或习惯句改写成年龄。原文没有时按故事年代和身份补可拍摄的结果，句末标「背景补」；年龄只写粗段，身高写观感、不写厘米。国籍只在故事世界已经能确定时补，否则为空。定位只写剧本里的身份。签名道具和伤疤、残疾只保留原文，没有则数组为空。性格不写入不可改特征。
3. 原文服装的名称、颜色、材质和配件原样保留。没有服装时补一套默认着装；已有名称但颜色或材质为空时只补空项。补写项句末标「背景补」。
4. 只依据剧本提取身份；同一人只保留一个身份。提示词不提交已有角色库。外观补写不得改身份，也不得与原文冲突。
5. 年代按全剧或该人物已经明确的时间背景填写；跨时代关系按原文保留，不以年龄段代替年代。确实无法判断时才填「未明确」。
6. 返回剧本中应保留的全部重要角色。首次生成和重新生成使用同一提示词。

**生成返回结构：**

```json
{
  "characters": [
    {
      "name": "",
      "gender": "男（背景补）",
      "era": "19世纪",
      "position": "",
      "age_range": "中年（背景补）",
      "body_type": "中等（背景补）",
      "hairstyle": "短发（背景补）",
      "facial_features": "方脸（背景补）",
      "height": "中等身高（背景补）",
      "nationality": "",
      "voice": "低沉（背景补）",
      "signature_props": [],
      "immutable_traits": [],
      "costumes": [
        { "name": "常服（背景补）", "color": "深色（背景补）", "material": "布（背景补）", "props": [] }
      ]
    }
  ]
}
```

`signature_props`、`immutable_traits`、`costumes[].props` 必须为字符串数组，每项一条，无资料返回 `[]`，不接受字符串、对象或 null。其他人物和服装资料字段为字符串。

首次生成和重新生成使用同一提示词，只提交完整剧本，不提交已有角色库。返回剧本中应保留的全部重要角色，不要用空数组表示沿用旧资料。程序按姓名合并，未返回的旧角色不删除。

**程序审核：**

不适用。

**AI审核：**

1. 每个角色的身份和资料都能在剧本中找到依据。
2. 同一角色没有被拆成两人。
3. 性别、年代、年龄段、身材、发型、面部、身高观感、声线必填。原文有则必须保留原句。原文没有时必须是句末含「背景补」的补写。国籍可空。签名道具和伤疤残疾没有原文时必须为空；性格写入不可改特征判不通过。
4. 实际出镜或发声的角色至少一套服装，名称、颜色、材质非空。背景补与原文冲突时判不通过。不得因为补写本身判超出剧本，也不得要求删除与原文不冲突的背景补。
5. 按剧本审核实际出镜或发声并承担独立剧情作用的具名角色是否完整，不对照角色库。仅被提及、名单展示、背景介绍，或只被借用其方法、发明、言论的人，不得因未列入判不通过，也不得因修改意见要求补入而判遗漏。待审内容已经列出某人时不得再写遗漏该人。多建了仅被提及的人时判不通过并要求删除该卡。不得因遗漏无姓名人物或未列足群体人数判不通过，也不得要求补建“第三位旅行勇士”等称谓角色卡。

**审核返回结构：**

```json
{
  "是否通过": true,
  "原因": ""
}
```

`是否通过` 为 `true` 或 `false`。为 `true` 时原因为空，为 `false` 时写明问题。

**依赖资料：**

- `script.body`。剧本不是节点。

**数据保存同步：**

AI 审核通过后，把本次新增或变更写入 `character_library.characters[]`。角色资料保存 `name`、`gender`、`era`、`position`、`age_range`、`body_type`、`hairstyle`、`facial_features`、`height`、`nationality`、`voice`、`signature_props`、`immutable_traits`。服装颜色只保存在每套服装的 `costumes[].color`，不另存角色级服饰颜色。服装字段为 `costumes[].name`、`color`、`material`、`props`；没有原文服装时保存一套句末标「背景补」的默认着装。图片只保存在 `costume_images`。程序首次保存时分配角色/服装唯一 ID，按姓名和服装名合并时保留已有 ID；不再分配 number。提取通过后，本次返回角色的定妆照地址清空，只留下空图片槽位；未返回角色的定妆照保留。为新服装准备空定妆照条目；无服装准备一条 `costume_id` 为空的条目。提取不调用图片模型，用户在人物卡单独点击“生成定妆照”后按服装顺序生成；首套作为默认角色图。重试轮次用尽后 AI 审核仍未通过时，仍保存本轮角色变更，节点进入未通过，原因写入 `character_library.node_state.reason`，不更新下游 hash。

**下游节点 hash 检查：**

人物资料变化时，影响该角色全部定妆照。首套服装或图片变化使后续定妆照及实际引用视频过期；其他套服装变化只影响该套图片及实际引用的视频。
