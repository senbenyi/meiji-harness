# 项目-剧本重要角色（`project-characters`，AI）

**前置条件：**

1. 项目剧本正文非空。

**生成规则：**

1. 按重要程度提取角色：主角、形成对比或施压的角色、剧情必需的配角。
2. 每个角色写明名字、定位、年龄段、身材、发型、服饰颜色、签名道具、不可改特征。
3. 每套服装写明名称、颜色、材质和随服装出现的道具。
4. 沿用项目角色库中已有角色；同一人只保留一个身份。
5. 只返回本次新增或变更。

**生成返回结构：**

```json
{
  "角色": [
    {
      "名字": "",
      "定位": "",
      "年龄段": "",
      "身材": "",
      "发型": "",
      "服饰颜色": "",
      "签名道具": "",
      "不可改特征": "",
      "服装": [
        { "名称": "", "颜色": "", "材质": "", "道具": "" }
      ]
    }
  ]
}
```

只列本次新增或变更的角色。没有变更时，`角色` 为空数组。同一人只出现一次，用名字对应角色库里已有的人。

**审核规则：**

1. 每个角色的身份和资料都能在剧本中找到依据。
2. 同一角色没有被拆成两人。
3. 不可改特征、签名道具和服装没有超出剧本依据。
4. 只审核本次变更。

**审核返回结构：**

```json
{
  "是否通过": true,
  "原因": ""
}
```

`是否通过` 为 `true` 或 `false`。为 `true` 时原因为空，为 `false` 时写明问题。

**依赖资料：**

- `项目.剧本.正文`。剧本不是节点。

**步骤：**

1. 前置条件检查（程序）。
2. 生成（AI）。
3. 审核（AI）。未通过时，带审核意见和原内容重新生成（AI），再审核（AI）。
4. 数据保存同步。
5. 下游节点 hash 检查。

**数据保存同步：**

审核通过后，把本次新增或变更写入 `角色库.角色[]`。角色字段为 `名字`、`定位`、`年龄段`、`身材`、`发型`、`服饰颜色`、`签名道具`、`不可改特征`。服装字段为 `服装[].名称`、`颜色`、`材质`、`道具`。图片分两个字段：`角色图` 每个角色一条；`定妆照` 是数组，条数与 `服装[]` 相同，每条带对应 `服装id`。程序保留已有 id 和编号，并为新角色补上空的 `角色图` 和 `定妆照`。并同步到本地项目 JSON。

**下游节点 hash 检查：**

人物资料变化时，影响该角色的角色图和全部定妆照。只有某套服装资料变化时，只影响 `定妆照` 数组里对应这一套服装的那一条。角色图变化时，影响该角色全部定妆照。这些图片按自己的依赖资料读取对应字段。被标为已过期后，再检查它的下游。
