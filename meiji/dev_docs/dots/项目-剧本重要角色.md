# 项目-剧本重要角色（`project-characters`，AI）

**固定属性：**

- 误差时长：无
- 重试轮次：2

**步骤：**

1. 前置条件检查（程序）。
2. 生成（AI）。
3. 程序审核。本节点不适用，跳过。
4. AI 审核。未通过且未达重试轮次时，把原因作为修改意见，带原内容重新生成，再做 AI 审核。达到重试轮次仍未通过则保留本轮内容，节点进入未通过，不更新下游。
5. 数据保存同步。
6. 下游节点 hash 检查。

**前置条件：**

1. 项目剧本正文非空。

**生成规则：**

1. 按重要程度提取角色：主角、形成对比或施压的角色、剧情必需的配角。
2. 每个角色写明名字、定位、年龄段、身材、发型、签名道具、不可改特征。年龄段保留剧本明确描述；不把概括年龄推算成精确数值。
3. 只记录剧本明确描述的服装；每套服装写明名称、颜色、材质和随服装出现的道具。剧本没有描述服装时，不推断或补写服装资料，`服装` 返回空数组。
4. 沿用项目角色库中已有角色；同一人只保留一个身份。
5. 只返回本次新增或变更。

**生成返回结构：**

```json
{
  "角色": [
    {
      "名字": "",
      "定位": "",
      "年龄段": "",
      "身材": "",
      "发型": "",
      "签名道具": "",
      "不可改特征": "",
      "服装": [
        { "名称": "", "颜色": "", "材质": "", "道具": "" }
      ]
    }
  ]
}
```

只列本次新增或变更的角色。没有变更时，`角色` 为空数组。同一人只出现一次，用名字对应角色库里已有的人。

**程序审核：**

不适用。

**AI审核：**

1. 每个角色的身份和资料都能在剧本中找到依据。
2. 同一角色没有被拆成两人。
3. 年龄段、不可改特征、签名道具和服装没有超出剧本依据；没有服装依据时接受空数组，不得凭空添加服装或颜色。
4. 只审核本次变更。

**审核返回结构：**

```json
{
  "是否通过": true,
  "原因": ""
}
```

`是否通过` 为 `true` 或 `false`。为 `true` 时原因为空，为 `false` 时写明问题。

**依赖资料：**

- `script.body`。剧本不是节点。

**数据保存同步：**

AI 审核通过后，把本次新增或变更写入 `character_library.characters[]`。角色资料含 `名字`、`定位`、`年龄段`、`身材`、`发型`、`签名道具`、`不可改特征`；`年龄段` 保存为 `age_range`。服装颜色只保存在每套服装的 `costumes[].color`，不另存角色级服饰颜色。服装字段为 `costumes[].name`、`color`、`material`、`props`；无剧本明确服装时 `costumes` 为空数组。图片分两个字段：`角色图` 每个角色一条；`定妆照` 至少一条。`costumes` 非空时每套服装对应一张定妆照并带对应 `服装id`；`costumes` 为空时仍生成一张依据角色其他资料的定妆照，其 `costume_id` 为空，不创建或回填服装资料。程序保留已有 id 和编号，并为新角色补上空的 `角色图` 和定妆照条目，再同步到本地项目 JSON。

**下游节点 hash 检查：**

人物资料变化时，影响该角色的角色图和全部定妆照。只有某套服装资料变化时，只影响 `定妆照` 数组里对应这一套服装的那一条。角色图变化时，影响该角色全部定妆照。这些图片按自己的依赖资料读取对应字段。被标为已过期后，再检查它的下游。
