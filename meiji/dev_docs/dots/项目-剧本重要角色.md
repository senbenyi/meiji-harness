# 项目-剧本重要角色（`project-characters`，AI）

**固定属性：**

- 误差时长：无
- 重试轮次：2

**步骤：**

1. 前置条件检查（程序）。
2. 生成（AI）。
3. 程序审核。本节点不适用，跳过。
4. AI 审核。未通过且未达重试轮次时，把原因作为修改意见，带原内容重新生成，再做 AI 审核。达到重试轮次仍未通过则保留本轮内容，节点进入未通过，不更新下游。
5. 数据保存同步。
6. 下游节点 hash 检查。

**前置条件：**

1. 项目剧本正文非空。
2. [项目-剧本](项目-剧本审核.md) 节点已生成（审核通过或人工放行）且剧本未变化。

**生成规则：**

1. 按重要程度提取角色：主角、形成对比或施压的角色、剧情必需的配角。
2. 性别 `gender` 必须为非空字符串；依据剧本明确描述或身份称谓填写，无依据时填写“未明确”（按输出语言表达），不得依据姓名或外貌猜测。缺失、空白或类型错误作为结构错误拒绝。每个角色写明名字、性别、年代、定位、年龄段、身材、发型、签名道具、不可改特征。年龄段保留剧本明确描述；不把概括年龄推算成精确数值。
3. 只记录剧本明确描述的服装；每套服装写明名称、颜色、材质和随服装出现的道具。剧本没有描述服装时，不推断或补写服装资料，`服装` 返回空数组。
4. 只依据剧本提取；同一人只保留一个身份。提示词不提交已有角色库。
5. 年代 `era` 必须为非空字符串，按剧本时间背景及人物所属年代填写；跨时代关系按原文保留，不以年龄段代替年代。无明确依据时填写“未明确”，不猜测具体年代。
6. 返回剧本中应保留的全部重要角色。首次生成和重新生成使用同一提示词。

**生成返回结构：**

```json
{
  "characters": [
    {
      "name": "",
      "gender": "未明确",
      "era": "未明确",
      "position": "",
      "age_range": "",
      "body_type": "",
      "hairstyle": "",
      "signature_props": [],
      "immutable_traits": [],
      "costumes": [
        { "name": "", "color": "", "material": "", "props": [] }
      ]
    }
  ]
}
```

`signature_props`、`immutable_traits`、`costumes[].props` 必须为字符串数组，每项一条，无资料返回 `[]`，不接受字符串、对象或 null。其他人物和服装资料字段为字符串。

首次生成和重新生成使用同一提示词，只提交完整剧本，不提交已有角色库。返回剧本中应保留的全部重要角色，不要用空数组表示沿用旧资料。程序按姓名合并，未返回的旧角色不删除。

**程序审核：**

不适用。

**AI审核：**

1. 每个角色的身份和资料都能在剧本中找到依据。
2. 同一角色没有被拆成两人。
3. 性别必填并符合剧本依据；确无依据时接受“未明确”。年龄段、不可改特征、签名道具和服装没有超出剧本依据；没有服装依据时接受空数组，不得凭空添加服装或颜色。
4. 年代必填并符合剧本时间背景及人物所属年代，无依据时接受“未明确”。
5. 按剧本审核待审名单是否完整，不对照角色库。

**审核返回结构：**

```json
{
  "是否通过": true,
  "原因": ""
}
```

`是否通过` 为 `true` 或 `false`。为 `true` 时原因为空，为 `false` 时写明问题。

**依赖资料：**

- `script.body`。剧本不是节点。

**数据保存同步：**

AI 审核通过后，把本次新增或变更写入 `character_library.characters[]`。角色资料保存 `name`、`gender`、`era`、`position`、`age_range`、`body_type`、`hairstyle`、`signature_props`、`immutable_traits`。服装颜色只保存在每套服装的 `costumes[].color`，不另存角色级服饰颜色。服装字段为 `costumes[].name`、`color`、`material`、`props`；无剧本明确服装时 `costumes` 为空数组。图片只保存在 `costume_images`。程序保留已有 ID 和编号。提取通过后，本次返回角色的定妆照地址清空，只留下空图片槽位；未返回角色的定妆照保留。为新服装准备空定妆照条目；无服装准备一条 `costume_id` 为空的条目。提取不调用图片模型，用户在人物卡单独点击“生成定妆照”后按服装顺序生成；首套作为默认角色图。重试轮次用尽后 AI 审核仍未通过时，仍保存本轮角色变更，节点进入未通过，原因写入 `character_library.node_state.reason`，不更新下游 hash。

**下游节点 hash 检查：**

人物资料变化时，影响该角色全部定妆照。首套服装或图片变化使后续定妆照及实际引用视频过期；其他套服装变化只影响该套图片及实际引用的视频。
