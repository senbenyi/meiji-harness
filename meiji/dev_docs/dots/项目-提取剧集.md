# 项目-提取剧集（`script-split`，AI）

**固定属性：**

- 误差时长：无
- 重试轮次：2

只选择完整剧本段落的集间边界，不生成或改写剧本正文。程序审核后增加独立 AI 容量审核。

**步骤：**

1. 前置条件检查（程序）。
2. 为剧本段落编号（程序）。
3. 生成各集起止段落（AI）。
4. 程序审核：校验切分并按段落原文拼接各集剧情。未通过且仍有修订次数时，把原因作为修改意见，重新生成各集起止段落，再做程序审核。修订次数用尽仍未通过时，任务以未通过结束，保留最后一轮候选于任务历史并记录原因；不替换项目中的现有剧集，也不检查下游。
5. AI 容量审核：按对白、剧情、完整动作及并行/串行关系评估能否自然呈现；拒绝原因带具体集数、P编号和切点/真实估时修正方向，按相同修订预算重新生成并重走两类审核。两类审核共用2次修订，不各自增加额度。
6. 数据保存同步。
7. 下游节点 hash 检查。

**前置条件：**

1. 项目剧本正文非空。
2. `reference_episode_duration_seconds` 已设置。
3. 已有剧集上没有未结束任务。
4. [项目-剧本](项目-剧本审核.md) 节点已生成（审核通过或人工放行）且剧本未变化；在上述条件通过后检查。

**生成规则：**

1. 程序把完整剧本按完整句、完整发言及换行编成候选段落（`P001`、`P002`…），不判断、不删除任何内容。空行并入相邻段落。剧本里是否有与剧情无关的内容，程序不知道。
2. AI 只返回每集的起止段落、预估时长，以及与剧情无关的排除段落，不返回剧情正文。
3. 按参考单集时长切分。依据每段的对白、动作和场面估算呈现时长，使每集预估时长尽量接近参考值。单集可在参考值上下浮动约两成，最后一集可以更短。先估完整发言、动作及反应后累计装入；将超上限时提前切集并增加集数，长戏允许跨集。不得统一伪填参考秒数。
4. 切点优先落在场次、地点或时间转换处，其次落在一个完整事件或对话结束处。不在单次完整发言或不可中断动作内部切开；多轮对白可在完整发言或问答结束处切集。
5. 实际剧情按顺序完整分配，各集起止范围互不重叠、不倒序。与剧情无关的段落由模型列入排除段落，可以位于两集之间，也可以位于某一集的起止范围之内；范围内被排除的段落不写入该集。没有无关内容时，第一集从第一段开始，最后一集到最后一段结束。
6. 集数由内容和参考时长决定，不预设集数。不为制造悬念移动切点，也不因内容精彩程度调整单集长度。
7. 与剧情无关的段落由模型判断，通常包括剧名、人物介绍、分场间隔符号、场次的预计时长、时间和地点，以及计时标记。这些段落列入排除段落，不进入剧情。场次标题属于剧情。不能因为时长或重要性再筛选实际剧情。
8. 程序审核只核对每个段落要么落在恰好一集的起止范围内、要么列入排除段落，且各集剧情是范围内未被排除段落的原文拼接。程序不识别段落内容，也不自动补切点。多单位单集声明估时不得超过参考时长1.2倍向下取整（150秒时180秒）；超限要求提前切集。单个不可拆单位保留真实超长估时。该检查不证明真实表演时间。
9. 本次执行意见随这次拆分写入修改意见，只调整切点。没有意见时提示里不出现修改意见。

**生成返回结构：**

```json
{
  "剧集": [
    { "序号": 1, "起始段落": "P001", "结束段落": "P012", "预估时长秒": 150 }
  ],
  "排除段落": []
}
```

`序号` 从 1 连续递增。`起始段落`、`结束段落` 使用编号剧本中的段落编号，同一集内起始段落不晚于结束段落。`预估时长秒` 为正整数。`排除段落` 是不写入剧情的段落编号，可以位于两集之间或某一集起止范围之内；没有无关内容时为空数组。不返回剧情正文。

**程序审核：**

AI 生成分集切点和排除段落，程序按归入的段落原文拼接各集。审核条件为每个段落要么归入恰好一集、要么列入排除段落，且无重叠。未通过则把原因作为修改意见，按修订次数进入修订；用尽后任务进入未通过。最后一轮切分候选保留在任务历史，不写入 `episodes[]`，也不检查下游。本任务是项目级 AI 任务，但不对应持久化项目节点，因此没有项目 `node_state`。

**AI审核：**

按完整发言的表达与语气、剧情推进、动作过程、停顿反应和场景承接评估；只允许真正同时发生的内容并行计时，不能压缩先后发言或动作。禁止字符数、字数、句数与固定每秒字数换算。容量合理且估时可信就通过，不为精确凑参考秒数或个人节奏偏好重切。拒绝时一次列明具体剧集、P编号、原文对白/动作、容量冲突及最小切点或估时修正方向，不能只说太长。

**审核返回结构：**

`{"是否通过": true, "原因": ""}`。拒绝时原因必须非空。

**依赖资料：**

- `script.body`。剧本不是节点。
- `reference_episode_duration_seconds`。

**数据保存同步：**

程序与AI审核均通过后整体写入剧集。每集保存 `sequence`、`duration_seconds`、`plot`。返回的预估时长写入 `duration_seconds`。`plot` 为对应段落的原文拼接。并同步到本地项目 JSON。

**下游节点 hash 检查：**

影响各集剧集摘要和故事大纲。二者按自己的依赖资料读取 `episodes[].plot`。新集还没有已生成的下游时，不标过期。

程序审核一次报告所有段落覆盖问题：遗漏范围、重叠/倒序、未覆盖结尾，以及对应期望和实际编号。修订应处理全部反馈并返回完整剧集数组和排除段落（含未修改条目）。哪些段落与剧情无关由模型判断；程序不自动补切点，保存时各集剧情与所归段落逐字一致。
