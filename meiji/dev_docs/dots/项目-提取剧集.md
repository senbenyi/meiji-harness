# 项目-提取剧集（`script-split`，AI）

只选择完整剧本段落的集间边界，不生成或改写剧本正文。不进行模型审核。

**前置条件：**

1. 项目剧本正文非空。
2. `项目.参考单集时长秒` 已设置。
3. 已有剧集上没有未结束任务。

**生成规则：**

1. 程序先把完整剧本按换行切成编号段落（`P001`、`P002`…）。空行并入相邻段落，保证段落按顺序拼接后与原文一致。
2. AI 只返回每集的起止段落和预估时长，不返回剧情正文。
3. 按参考单集时长切分。依据每段的对白、动作和场面估算呈现时长，使每集预估时长尽量接近参考值。单集可在参考值上下浮动约两成，最后一集可以更短。不为凑整而拆开一场戏。
4. 切点优先落在场次、地点或时间转换处，其次落在一个完整事件或对话结束处。不在一句对白、一组连续对白或一个动作过程中间切开。
5. 全部段落按顺序完整分配：第一集从第一段开始，最后一集到最后一段结束。每集的起始段落紧接上一集的结束段落，不遗漏、不重叠、不跳段、不倒序。
6. 集数由内容和参考时长决定，不预设集数。不为制造悬念移动切点，也不因内容精彩程度调整单集长度。
7. 不能因为时长、场次或重要性筛选剧情、动作、场景、情绪和修饰描述。每段原文都必须归入且只归入一集。
8. 程序校验连续覆盖、无漏段、无重叠，且拼接结果与原剧本一致后，按段落原文写入各集剧情。不重写、不删减、不概括。

**生成返回结构：**

```json
{
  "剧集": [
    { "序号": 1, "起始段落": "P001", "结束段落": "P012", "预估时长秒": 150 }
  ]
}
```

`序号` 从 1 连续递增。`起始段落`、`结束段落` 使用编号剧本中的段落编号，同一集内起始段落不晚于结束段落。`预估时长秒` 为正整数。不返回剧情正文。

**审核返回结构：**

不适用。本节点不进行模型审核；分集覆盖与原文完整性由程序校验。

**依赖资料：**

- `项目.剧本.正文`。剧本不是节点。
- `项目.参考单集时长秒`。

**步骤：**

1. 前置条件检查（程序）。
2. 为剧本段落编号（程序）。
3. 生成各集起止段落（AI）。
4. 校验切分并按段落原文拼接各集剧情（程序）。校验失败则不保存，也不检查下游。
5. 数据保存同步。
6. 下游节点 hash 检查。

**数据保存同步：**

校验通过后整体写入剧集。每集保存 `序号`、`时长秒`、`剧情`。`预估时长秒` 写入 `时长秒`。`剧情` 为对应段落的原文拼接。并同步到本地项目 JSON。

**下游节点 hash 检查：**

影响各集剧集摘要和故事大纲。二者按自己的依赖资料读取 `剧集[].剧情`。新集还没有已生成的下游时，不标过期。
