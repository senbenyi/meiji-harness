# 镜头-角色与服装识别（`shot-characters`，AI）

选择本镜可见的已有角色和服装，不创建角色卡或定妆照。首次生成后最多两次修订，程序审核与 AI 审核共用次数。

## 前置与输入

目标镜头属于本集，本集镜头表与项目角色库均有效。不要求图片。输入为语言、补充要求、本镜镜头表资料、文字人物/服装目录，以及可选的上一镜有效穿着绑定；不传整集正文、图片状态或上一镜尾帧。

## 输出与保存

路由三动作共用输出契约，审核返回统一审核结果。生成和修订返回：

```json
{"on_screen_characters":[{"character_number":"C1","costume_number":"C1F1"}]}
```

无出镜人物返回空数组。角色没有服装目录时服装编号为空；有服装目录必须选择所属服装。未知编号、跨角色服装和重复人物由协议校验拒绝，不能覆盖正式绑定。

程序把编号映射到项目内部 ID，保存为 `shot.character_binding.{node_state,has_result,on_screen_characters}`，数组项为 `character_id/costume_id`。`has_result=false` 表示未识别；`has_result=true` 且空数组、状态 generated 表示已确认无人。人工编辑使用同一编号契约。

## 流程与依赖

前置检查→生成→程序审核→AI审核→保存→下游 hash 检查。审核未通过可带候选和意见修订；次数耗尽保留候选为 rejected，不更新成功 hash 或下游。取消、失败、继续使用统一任务机制。

绑定影响本镜每秒分镜和后续文本/视频，也影响下一镜识别所参考的穿着。语言、规则、补充要求、文字角色资料、本镜镜头表和有效前镜绑定纳入依赖；图片不参与文本依赖。输入与 hash 共用 `shared/shot-text-inputs.js`。
