# 镜头-首尾帧与多模态提示词（程序）

本步骤由程序编排，不调用模型，也不另做模型审核。它先在前置检查中确定本镜的 `生成视频类型`：`文生`、`多模态` 或 `首尾帧`。类型为 `文生` 时，本步骤跳过，不生成首尾帧或多模态提示词；类型为 `多模态` 或 `首尾帧` 时，只编排对应的一种提示词。`prompt` 使用已通过的文生视频三段，原文不改。一次视频请求只使用一种结构。首尾帧的 `input_reference`、`last_frame` 不能和 `reference_images`、`reference_videos`、`reference_audios` 出现在同一次请求里。本项目用 JSON 提交，不用 multipart。

**前置条件：**

1. 该镜头文生视频提示词已有效生成。
2. 前置检查必须先确定并写入 `shots[].video_generation_type`，只能是 `文生`、`多模态`、`首尾帧` 之一：镜头有出镜角色时设为 `多模态`；没有出镜角色且不是首镜时设为 `首尾帧`；首镜没有出镜角色时设为 `文生`。
3. 类型为 `文生` 时，本步骤以“跳过”结束，不要求尾帧或人物图片，不编排、不写入首尾帧和多模态提示词；直接由后续视频任务读取文生视频提示词。
4. 类型为 `首尾帧` 时，必须不是首镜，且上一镜尾帧已有效生成；否则前置检查失败，不得编排。首镜不能使用首尾帧。
5. 类型为 `多模态` 时，必须有出镜角色，且这些角色的角色图及本镜所穿服装对应的定妆照已有效生成。没有指定服装时，使用默认服装对应的定妆照；任一参考素材缺失或无效时，前置检查失败，不得编排。

**编排规则：**

1. `model` 固定为 `elysium-video`。`seconds` 等于该镜计划时长，为 4–15 的整数。`size` 由项目画幅换算：`1344x768` 为 `1024x576`，`768x1344` 为 `576x1024`。
2. 图片只使用 PNG、JPEG、WebP。地址必须是 data URL；首尾帧图片也允许裸 Base64。不使用 HTTP 地址。
3. 首尾帧的 `prompt` 在文生视频三段前加一行，声明上一镜尾帧对齐本镜 0.00 秒，然后空一行，再照抄三段原文。`input_reference` 填上一镜尾帧。本镜尾帧要等这条视频生成后再截取，编排时不填 `last_frame`，提交时省略该字段。
4. 多模态的 `prompt` 就是文生视频三段，不加帧对齐。`reference_images` 按出镜顺序填该角色 `角色图` 和本镜服装对应 `定妆照` 的 data URL，同一张图只出现一次，最多 9 张。角色图表示体型，定妆照表示本镜身份和服装，都不是首帧。本项目不使用参考视频和参考音频，`reference_videos`、`reference_audios` 留空，提交时省略。
5. 只编排并保存 `生成视频类型` 对应的提示词。多模态请求不带 `input_reference` 和 `last_frame`；首尾帧请求不带三个参考数组；`文生` 类型跳过本步骤，不生成首尾帧或多模态请求。

**生成返回结构：**

首尾帧：

```json
{
  "model": "elysium-video",
  "prompt": "<Picture 1> aligns with 0.00 seconds. It is the previous shot's last frame.\n\nintegrated_multimodal_description:\noverall_soundscape:\nnon_diegetic_music:",
  "seconds": 12,
  "size": "1024x576",
  "input_reference": "上一镜last_frame"
}
```

多模态：

```json
{
  "model": "elysium-video",
  "prompt": "integrated_multimodal_description:\noverall_soundscape:\nnon_diegetic_music:",
  "seconds": 12,
  "size": "1024x576",
  "reference_images": ["角色图 data URL", "本镜定妆照 data URL"]
}
```

`prompt` 里的三段换成该镜已通过的文生视频原文。`seconds` 换成该镜时长。`size` 换成该项目画幅对应的尺寸。`reference_images` 换成本镜实际绑定的角色图和定妆照，一张图一个元素。`生成视频类型` 为 `文生` 时，视频请求只有 `model`、`prompt`、`seconds`、`size`，`prompt` 为文生视频三段。

**审核返回结构：**

不适用。本步骤由程序编排，不进行模型审核。

**依赖资料：**

首尾帧提示词：

- `episodes[].shot_list.shots[].text_to_video_prompt` 的 `integrated_multimodal_description`、`overall_soundscape`、`non_diegetic_music`，以及 `text_to_video_prompt.node_state.dependency_hash`。
- 上一镜 `last_frame.address`、`last_frame.node_state.dependency_hash`。

多模态提示词：

- 同上文生视频三段，以及 `text_to_video_prompt.node_state.dependency_hash`。
- 出镜角色的 `character_library.characters[].character_image.address`、`character_image.node_state.dependency_hash`，以及本镜服装对应的 `character_library.characters[].costume_images[]` 中该条的 `地址`、`node_state.dependency_hash`。

**步骤：**

1. 前置条件检查（程序）：确定并写入 `生成视频类型`。
2. 类型为 `文生` 时跳过本步骤，后续视频任务使用文生视频提示词；类型为 `首尾帧` 或 `多模态` 时，仅按该类型编排对应请求（程序）。
3. 保存本步骤实际编排的提示词并同步数据；跳过时不生成提示词。
4. 完成类型写入及适用的提示词保存后，执行下游节点 hash 检查；即使提示词编排跳过，也要检查依赖 `生成视频类型` 的视频节点。

**数据保存同步：**

前置检查先写入 `shots[].video_generation_type`。类型为 `文生` 时跳过提示词编排，不写首尾帧或多模态提示词；类型为 `首尾帧` 时仅写 `首尾帧提示词` 的 `model`、`prompt`、`seconds`、`size`、`input_reference`；类型为 `多模态` 时仅写 `多模态提示词` 的 `model`、`prompt`、`seconds`、`size`、`reference_images`。文生视频提示词已在上一步保存。将类型及实际编排的字段同步到本地项目 JSON，并检查视频节点的依赖 hash。

**下游节点 hash 检查：**

影响该镜视频。视频按自己的依赖资料读取 `生成视频类型`，以及该类型对应的提示词字段。`多模态` 另读绑定的 `character_image.address`、`character_image.node_state.dependency_hash` 和对应 `costume_images.address`、`costume_images.node_state.dependency_hash`。`首尾帧` 另读上一镜 `last_frame.address`、`last_frame.node_state.dependency_hash`。
