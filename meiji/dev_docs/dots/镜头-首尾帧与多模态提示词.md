# 镜头-首尾帧与多模态提示词（程序）

- 节点：`first-last-frame`、`multimodal`。
- 重试轮次：0。无AI生成或AI审核；由程序复用已审核三段并编排素材。
- 接口设计与完整请求示例：[视频接口与成片编排设计](../../../docs/implement/1016-视频接口与成片编排设计.md)。

## 顺序和前置条件

成片先完成每秒分镜和文生视频提示词，执行视频前按镜头出镜绑定确定类型，插入必要的编排任务，再生成视频。文生跳过编排。有卡内角色使用多模态；无卡内角色且有上一镜使用首尾帧；否则文生。缺图停止，不改类型。

两节点均要求本集镜头表、本镜文生提示词有效；首尾帧还要求上一镜有效尾帧；多模态要求本镜绑定人物与服装对应定妆照有效且可读取，最多9张。群演无角色卡时不要求其定妆照。

## 首尾帧

上一镜`last_frame.address`作为本镜`first_frame`，`ratio=adaptive`。正文增加0秒开场约束，后面原样放本镜已审核三段。当前成片没有目标尾帧来源，不发送`last_frame`；视频完成后截出的尾帧是输出，不能反用作输入。不混多模态参考素材。

## 多模态

按`on_screen_characters`顺序取本镜对应服装的定妆照，无服装资料使用空costume_id的定妆照。正文明确“第N张参考图—人物姓名—全项目稳定speaker_tag—服装”，图片顺序与`images`一致。不把图片序号误作人物编号，不混前镜尾帧，不让画外声音人物因参考图而出镜。随后原样放已审核三段。

当前业务只提供参考图。服务端支持参考视频/音频，但本节点没有相应素材来源，不构造空文件或虚假引用。

## 保存与校验

保存到`first_last_frame_prompt`或`multimodal_prompt`的既有Model：`model/prompt/seconds/size`，以及`input_reference`或`reference_images[].address`。只存本地地址，不存Base64。`seconds/size`是内部兼容快照，新HTTP实际发送`duration/resolution/ratio`；不发送旧网关字段。

编排和最终发送共用本机视频接口参数校验：MiniMax-H3，4–15整数秒，完整提示词最多7000字符，素材互斥、数量及地址合法。视频实际采用已保存`prompt`与素材地址，当前时长和画幅按镜头/项目核对。错误不发送付费请求，不通过截断台词或改时长绕过。

依赖包含视频类型、本镜三段及hash、时长、画幅；首尾帧另依赖前镜尾帧地址和hash，多模态另依赖绑定人物/服装的定妆照地址和hash。依赖变化使编排和视频过期，不自动覆盖旧内容；旧内容重新编排后采用新映射。

步骤为precheck→generate（程序执行编排）→数据保存→视频依赖检查；没有额外文本AI请求。原结果修改或上游变更按现有状态与hash规则处理。
