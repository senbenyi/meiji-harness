# 剧集-故事大纲（`outline`，AI）

**固定属性：**

- 误差时长：±30秒
- 重试轮次：2

**步骤：**

1. 前置条件检查（程序）。
2. 生成故事大纲（AI）：把本集剧情完整拆成故事小段。
3. 程序审核。未通过且未达重试轮次时，把原因作为修改意见，带原内容重新生成，再从程序审核做起。达到重试轮次仍未通过则保留本轮内容，节点进入未通过，不更新下游。
4. AI 审核。未通过时按同一重试轮次、同一方式修订。
5. 数据保存同步。
6. 下游节点 hash 检查。

**前置条件：**

1. 本集剧情非空。

**生成规则：**

1. 两种创作模式均只按 `episodes[].plot` 的完整本集剧情拆成连续、有序故事小段。优先保留原文句子，按场景/时间变化及完整行动起止分段；在一次生成内先规划段数、逐段时长和对应原文范围，锁定后再填写各段完整剧情。创作方向、摘要、参考素材及旧稿不能代替或改写原剧情。
2. 每段 `正文` 写下这一段的完整剧情，不是一句事件概述。保留本集剧情中的人物与关系、动作过程及对象、场景环境、事件因果、情绪及强弱变化、对白与声音、物件和状态、结果、结尾，以及具体形容词和限定描述（如程度、色彩、质感、语气）。允许重组句子。不得省略、弱化、泛化或改变含义，不得用笼统概述替换这些内容。
3. `causal` 只写这一段和前后段如何衔接。段内已经发生的因果留在 `body`。
4. 不补写原文没有的人物、动机、动作、台词、转场或结尾。不遗漏、不重复、不颠倒原有叙事顺序。所有 `body` 连起来应覆盖原文全部剧情信息，原台词逐字保留；逐项从原文找到对应小段，再反查小段没有无依据新增。
5. 本集参考时长是本轮总预算，先依据完整动作、正常语速对白及反应需要分配各段时长，允许小数秒，合计必须等于总预算。不预设固定段数；规划阶段可在同一总预算内调整段数、边界和分配，确认能承载全部剧情后锁定。
6. 填写 body/causal 时，以本段已锁定的 duration_seconds 为时间约束，以对应原文范围为事实依据，使动作、完整对白与反应在本段时长内正常呈现。整集参考时长仅用于规划分配和总和校验，不用于填充阶段重新设计或估算本段时长，也不按正文长度反向加时；不追加段数或时长。发现分配不合理时返回内部规划，在同一总预算内重新分配后再填写；不能为了凑时长删剧情、缩写台词、异常加速、添加空等或重复剧情。规划和填写在一次请求内完成，只输出完整 segments，不输出规划草稿或额外字段。
7. 原结果修订或自动修订先核对预算，再修正内容；只改时长且原文范围无需变化时，仅重分配 duration_seconds，保留正文。分段必须调整时先重新规划，补齐遗漏不能增加总时长。
8. 输出前核对逐段时长和总和，再逐项检查原文内容完整归属、无新增及段间状态连续。

**生成返回结构：**

```json
{
  "segments": [
    { "sequence": 1, "duration_seconds": 12.5, "body": "", "causal": "" }
  ]
}
```

`body` 按生成规则 2 写。`causal` 按生成规则 3 写。`duration_seconds` 是有限正数，允许小数，按锁定预算填写，合计等于本集参考时长。

**程序审核：**

所有故事小段的时长秒数合计与 `episodes[].duration_seconds` 的差值绝对值不超过 30 秒即通过，边界包含在内，不要求完全相等。超出则把原因作为修改意见，按重试轮次进入修订；用尽后保留本轮小段，节点进入未通过，不更新下游。生成提示词以总和等于参考时长为目标；程序审核仍保留±30秒容差，不改为严格相等，也不增加程序预分配步骤。

**AI审核：**

1. 按生成规则 2 核对每段 `body`。遗漏、弱化、泛化、改变含义，或把明确内容改成笼统概述，均判不通过。
2. `causal` 只写前后段衔接，没有把 `body` 里的对白、动作或描写移走。
3. 审核每段剧情能否按分配时长正常呈现，只报告有明确原文依据的冲突。修正要求在同一总预算内重分配或调整分段，不要求额外增加总时长、删改剧情或异常加速；数值合计由程序审核。

**审核返回结构：**

```json
{
  "是否通过": true,
  "原因": ""
}
```

`是否通过` 为 `true` 或 `false`。为 `true` 时原因为空，为 `false` 时写明问题。

**依赖资料：**

- `episodes[].plot`。剧情不是节点。
- `episodes[].duration_seconds`。本集参考时长改变时重新检查依赖。

**数据保存同步：**

程序审核和 AI 审核都通过后写入 `episodes[].story_outline`，节点标为已生成、原因清空，更新本节点保存的依赖 hash。正式内容保存 `segments[].sequence`、`duration_seconds`、`body`、`causal`。

两种审核共用最多 2 次修订。程序审核或 AI 审核耗尽后仍未通过，仍将最后一轮小段保存到同一正式节点；状态为 `rejected`，原因写入 `story_outline.node_state.reason` 和任务结束原因，保留原成功 hash，不主动更改下游状态、hash 或媒体。重新提交带上该原因。新任务以执行时的正式资料做前置校验，不回退历史正文；公共状态规则见 [step_model.md](../step_model.md)。

**下游节点 hash 检查：**

影响该集镜头表。镜头表按自己的依赖资料读取故事大纲的四个小段字段、本集参考时长，以及已保存的 `story_outline.node_state.dependency_hash`。必需上游已过期时继续向后传播，不能因保留的正文和 hash 尚未改变而让下游维持有效。

故事大纲成功保存（含人工编辑、通过程序审核的人工放行）后，以所有小段 duration_seconds 的合计回写本集 duration_seconds，保留小数秒，再记录依赖 hash。候选和未通过结果不回写；本轮大纲审核仍使用回写前参考。镜头表生成及程序审核统一读取回写后的本集参考时长，镜头总时长仍允许 ±30 秒误差。
