# 剧集-故事大纲（`outline`，AI）

**固定属性：**

- 误差时长：±30秒
- 重试轮次：2

**步骤：**

1. 前置条件检查（程序）。
2. 生成故事大纲（AI）：完整保留本集剧情，原剧情不足以自然撑满参考时长时补充设计合理情节，再编成故事小段。
3. 程序审核。未通过且未达重试轮次时，把原因作为修改意见，带原内容重新生成，再从程序审核做起。达到重试轮次仍未通过则保留本轮内容，节点进入未通过，不更新下游。
4. AI 审核。未通过时按同一重试轮次、同一方式修订。
5. 数据保存同步。
6. 下游节点 hash 检查。

**前置条件：**

1. 本集剧情非空。

**生成规则：**

1. 两种创作模式均以 `episodes[].plot` 为必须保留的主线和事实约束。先依据正常动作、对白和反应判断原剧情能否自然撑满本集参考时长；明显不足时允许 AI 根据已有剧情自行补充设计合理情节，内容足够时不强行扩写。创作方向、摘要及旧稿不能代替原剧情。
2. 每段 `body` 写完整可呈现的剧情，包含原剧情与必要补充，不是摘要。完整保留原人物关系、动作及对象、过程与结果、环境、情绪变化、声音、物件状态和具体限定；原台词逐字保留，说话人和声源不变。不遗漏、不弱化、不泛化、不重复、不颠倒原事件顺序。
3. 补充可包括服务现有主线的行动过程、对话、互动、合理阻碍、反应及场景承接，须符合已有设定、人物动机与关系、时间线及状态。不得改变原事件结果、核心事实或结局，不另起无关主线、不引入改变主线的关键人物、不替原文悬念编造答案、不越过本集结尾续写。保留原开头及结尾落点，可在原事件之间及展开过程中补充。不靠空等、无意义慢动作或重复凑时长，不加入机位、景别或制作秒数。
4. `causal` 仅说明段间因果、时间或场景承接，可说明合理补充与原事件的联系。全部动作、对白和描写必须留在 `body`，不以 `causal` 代替正文。
5. 本集参考时长为本轮总预算；在一次生成中先判断内容量，再规划原剧情及必要补充、段数、边界和逐段时长，确认能自然呈现后锁定。时长为有限正数，允许小数，合计以本集参考为目标，在上下30秒内选择能正常呈现的总量后锁定。不预设固定段数，不按固定秒数机械截断。
6. 按各段已锁定的 `duration_seconds` 填写正文，不按正文长度反向加时；分配不合理或内容不足时返回内部规划，在同一总预算内调整后重新锁定。不得删原剧情、缩写原台词、异常加速或突破允许时长范围。仅输出最终 segments，不输出规划草稿或新增字段。
7. 修订同步遵守上述规则，保留合规补充，不因没有逐句原文依据而删除。只改时长且内容已足够、分段范围无需变化时只重分配时长；明显内容不足时必须补充有推进作用的剧情，不能仅拉长数字。原剧情事实不被旧稿或修改意见覆盖。
8. 输出前核对预算、原剧情覆盖、补充合理性与段间状态连续，确保逐段内容量自然匹配时长。

**生成返回结构：**

```json
{
  "segments": [
    { "sequence": 1, "duration_seconds": 12.5, "body": "", "causal": "" }
  ]
}
```

`body` 按生成规则 2 写。`causal` 按生成规则 3 写。`duration_seconds` 是有限正数，允许小数，按锁定预算填写，合计处于本集参考上下30秒内，与锁定的规划总和一致。

**程序审核：**

所有故事小段的时长秒数合计与 `episodes[].duration_seconds` 的差值绝对值不超过 30 秒即通过，边界包含在内，不要求完全相等。超出则把原因作为修改意见，按重试轮次进入修订；用尽后保留本轮小段，节点进入未通过，不更新下游。生成、修订与审核共用程序派生的目标及30秒容差；合规且自然可执行就通过，不为精确凑秒反复改稿。尽量不生成不足4秒的独立段，短事件并入相邻关联段。

**AI审核：**

1. 核对原剧情及原台词完整保留、顺序和事实无误，发现遗漏、弱化、泛化或改变含义时指出原文依据。
2. 同步判断必要补充是否符合生成规则 3；合理补充不需要逐句来自原文，不得仅因原文没有而拒绝。检查人物、物件及行动状态连续，`causal` 不代替正文。
3. 审核内容与时长能否自然匹配，数值合计与结构仍由程序审核。明显内容不足、空等或重复凑时长时要求在同一总预算内补充推进剧情的情节；内容过多时先在允许范围内重分配；整个范围都无法承载原剧情时明确指出上游切集容量冲突，不反复要求下游压缩。不要求突破允许总量、删原剧情、缩写原台词或异常加速。不按字数或固定段长机械判定。
4. 未通过原因给出原文事实或补充规则/时长的具体冲突、对应小段编号、具体问题及最小修正方向。合规补充不能因没有逐句原文依据被删除。

**审核返回结构：**

```json
{
  "是否通过": true,
  "原因": ""
}
```

`是否通过` 为 `true` 或 `false`。为 `true` 时原因为空，为 `false` 时写明问题。

**依赖资料：**

- `episodes[].plot`。剧情不是节点。
- `episodes[].duration_seconds`。本集参考时长改变时重新检查依赖。

**数据保存同步：**

程序审核和 AI 审核都通过后写入 `episodes[].story_outline`，节点标为已生成、原因清空，更新本节点保存的依赖 hash。正式内容保存 `segments[].sequence`、`duration_seconds`、`body`、`causal`。

两种审核共用最多 2 次修订。程序审核或 AI 审核耗尽后仍未通过，仍将最后一轮小段保存到同一正式节点；状态为 `rejected`，原因写入 `story_outline.node_state.reason` 和任务结束原因，保留原成功 hash，不主动更改下游状态、hash 或媒体。重新提交带上该原因。新任务以执行时的正式资料做前置校验，不回退历史正文；公共状态规则见 [step_model.md](../step_model.md)。

**下游节点 hash 检查：**

影响该集镜头表。镜头表按自己的依赖资料读取故事大纲的四个小段字段、本集参考时长，以及已保存的 `story_outline.node_state.dependency_hash`。必需上游已过期时继续向后传播，不能因保留的正文和 hash 尚未改变而让下游维持有效。

本集 duration_seconds 是由切集或人工编辑确定的固定参考，大纲保存、修订和人工放行不自动回写。大纲合计与镜头表合计均须在同一本集参考±30秒内；镜头表还须接近大纲累计取整目标，两项容差取交集，不逐层叠加。确需改预算时，先人工编辑本集参考时长。
