# 剧集-故事大纲（`outline`，AI）

**前置条件：**

1. 本集剧情非空。

**生成规则：**

1. 按本集剧情切成有序故事小段。
2. 每段 `正文` 写下这一段的完整剧情，不是一句事件概述。保留本集剧情中的人物与关系、动作过程及对象、场景环境、事件因果、情绪及强弱变化、对白与声音、物件和状态、结果、结尾，以及具体形容词和限定描述（如程度、色彩、质感、语气）。允许重组句子。不得省略、弱化、泛化或改变含义，不得用笼统概述替换这些内容。
3. `因果` 只写这一段和前后段如何衔接。段内已经发生的因果留在 `正文`。
4. 不补充剧情没有写出的动机、缺陷、世界规则和台词。
5. 各段时长合计等于本集参考时长。

**生成返回结构：**

```json
{
  "小段": [
    { "序号": 1, "时长秒": 0, "正文": "", "因果": "" }
  ]
}
```

`正文` 按生成规则 2 写。`因果` 按生成规则 3 写。`时长秒` 是正数，合计等于本集参考时长。

**审核规则：**

1. 按生成规则 2 核对每段 `正文`。遗漏、弱化、泛化、改变含义，或把明确内容改成笼统概述，均判不通过。
2. `因果` 只写前后段衔接，没有把 `正文` 里的对白、动作或描写移走。
3. 各段时长合计等于本集参考时长，且每段都能按该时长呈现。

**审核返回结构：**

```json
{
  "是否通过": true,
  "原因": ""
}
```

`是否通过` 为 `true` 或 `false`。为 `true` 时原因为空，为 `false` 时写明问题。

**依赖资料：**

- `episodes[].plot`。剧情不是节点。

**步骤：**

1. 前置条件检查（程序）。
2. 生成（AI）。
3. 审核（AI）。未通过时，带审核意见和原内容重新生成（AI），再审核（AI）。
4. 数据保存同步。
5. 下游节点 hash 检查。

**数据保存同步：**

审核通过后写入 `episodes[].story_outline`。保存 `segments[].sequence`、`时长秒`、`正文`、`因果`。并同步到本地项目 JSON。

**下游节点 hash 检查：**

影响该集镜头表。镜头表按自己的依赖资料读取故事大纲的上述字段，以及 `story_outline.node_state.dependency_hash`。
