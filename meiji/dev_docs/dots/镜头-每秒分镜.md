# 镜头-每秒分镜（`seconds`，AI）

**固定属性：**

- 误差时长：±5秒
- 重试轮次：2

一次只生成当前这一镜。镜头的时长、事件、景别、钩子、衔接、锚点和音频安排以镜头表为准，这里只把它们落到每一秒。H3 视频提示词不单独保存每秒 JSON；写 `integrated_multimodal_description` 需要每一秒的动作、镜头、空间、音频和交接。镜头运动的幅度和速度写在 `camera` 里，不另设字段。整段环境声和配乐写在文生视频提示词的 `overall_soundscape`、`non_diegetic_music`，不放进每秒分镜。有对白的秒另记 `dialogue`，用来绑定角色卡。

**步骤：**

1. 前置条件检查（程序）。
2. 生成（AI）。
3. 程序审核。未通过且未达重试轮次时，把原因作为修改意见，带原内容重新生成，再从程序审核做起。达到重试轮次仍未通过则保留本轮内容，节点进入未通过，不更新下游。
4. AI 审核。未通过时按同一重试轮次、同一方式修订。
5. 数据保存同步。
6. 下游节点 hash 检查。

**前置条件：**

1. 目标镜头属于本集。
2. 本集镜头表已有效生成，且这一镜的 `duration_seconds`、`body`、`shot_scale`、`hook`、`continuity_transition`、`reference_anchor` 和 `audio_arrangement` 都已写明。

**生成规则：**

1. 只为当前镜头写逐秒指令，覆盖镜头表参考时长，从 0 秒连续覆盖，中间不留空隙。
2. 不改这一镜的时长、边界、事件、景别、钩子、出镜人物、服装、地标和光位。
3. 第一秒从本镜连续性衔接写明的开场状态开始。最后一秒的交接，落到镜头表为下一镜准备的开场；已经是最后一镜时，落到本镜结尾。
4. 普通秒用 `0–1s`、`1–2s`。只有该秒本身是这一镜的钩子时，才追加 `2.0–2.5s` 这类亚秒节拍。
5. 每一秒都写动作、姿态和表情，包括身体、手持道具、眼神和表情变化。
6. 每一秒都写镜头运动：推、拉、摇、倾、横移、升降、环绕、跟拍、固定或手持晃动。运动留在镜头表已定的景别里。需要时写幅度和速度。
7. 每一秒都写空间位置，并落在参考锚点已写的地标和人物位置上。不新增地标，不把人物改到锚点以外的位置。
8. 每一秒都写音频线索。只把本镜音频安排里的旁白、对白和音效落到具体秒，不新增镜头表没有的台词。没有声音时写明无声。
9. 旁白所在的秒写明说话人嘴唇闭合。出镜对白所在的秒写明张嘴，并写眼神和身体动作。
10. 每一秒都写交给下一秒的状态。
11. 每一秒一格。只有钩子所在秒追加了亚秒节拍时，才可以多一格。
12. 角色名、服装和地标与镜头表使用同一名称。
13. 每一秒都写明身体、镜头或道具的具体变化。

**生成返回结构：**

```json
{
  "storyboard": [
    {
      "time_range": "0–1s",
      "action": "",
      "camera": "",
      "space": "",
      "audio": "",
      "handoff": "",
      "dialogue": [
        {
          "speaker_id": "",
          "speaker_name": "",
          "mode": "画内",
          "dialogue_text": ""
        }
      ]
    }
  ]
}
```

从 `0–1s` 起逐秒覆盖到镜尾，中间不留空隙。每一秒一格。只有这一镜的钩子所在秒，才可以再加一格，`time_range` 写成 `2.0–2.5s` 这样。

`action` 写身体、手持道具、姿态、眼神和表情。`camera` 写推、拉、摇、倾、横移、升降、环绕、跟拍、固定或手持晃动，需要时写幅度和速度。`space` 写人物位置、手持物和地标位置。`audio` 写这一秒的旁白、对白、音效、呼吸或无声，并写嘴部开合。`handoff` 写交给下一秒的状态。这一秒没有对白时 `dialogue` 为 `[]`。有对白时每句一条：`speaker_id` 用角色 id，未建卡人物和独立旁白留空；`speaker_name` 保留原称谓；`mode` 为画内、画外或心声；`dialogue_text` 为原台词。

**程序审核：**

逐秒分镜覆盖总时长与该镜镜头表参考时长的差值不得超过误差时长。超出则把原因作为修改意见，按重试轮次进入修订；用尽后保留本轮分镜，节点进入未通过，不更新下游。

**AI审核：**

1. 从 0 秒起连续覆盖，没有时间空隙，并覆盖镜头表事件、对白和结尾状态。
2. 每一秒都含动作或姿态或表情、镜头、空间、音频、交接这五项。
3. 事件、人物、服装、景别、钩子、地标、光位和台词与镜头表一致。没有改时长，没有拆镜或并镜。
4. 第一秒接得上本镜连续性衔接。人物和地标落在参考锚点写明的位置。
5. 动作能在该秒内做完，道具和人物位置能交到下一秒。
6. 说话的秒写明嘴部开合。离屏旁白为闭，出镜对白为开。
7. 没有新增镜头表中不存在的人物、服装、地标、事件和台词。

**审核返回结构：**

```json
{
  "是否通过": true,
  "原因": ""
}
```

`是否通过` 为 `true` 或 `false`。为 `true` 时原因为空，为 `false` 时写明问题。

**依赖资料：**

- 该镜的 `title`、`number`、`duration_seconds`、`shot_scale`、`hook`、`body`、`continuity_transition`、`reference_anchor`、`audio_arrangement`。
- `shot_list.node_state.dependency_hash`。

**数据保存同步：**

程序审核和 AI 审核都通过后，把逐秒内容写入 `episodes[].shot_list.shots[].seconds_storyboard.storyboard[]` 的 `time_range`、`action`、`camera`、`space`、`audio`、`handoff`、`dialogue`，节点标为已生成、原因清空，并同步到本地项目 JSON。重试轮次用尽后程序审核仍未通过时，仍保存本轮分镜内容，节点进入未通过，原因写入 `seconds_storyboard.node_state.reason`，不更新下游 hash。

**下游节点 hash 检查：**

影响该镜文生视频提示词。文生视频提示词按自己的依赖资料读取 `seconds_storyboard.storyboard[]` 的上述字段，以及 `seconds_storyboard.node_state.dependency_hash`。
