# 镜头-每秒分镜（`seconds`，AI）

**固定属性：**

- 误差时长：无（末段结束时间必须等于镜头表参考时长）
- 重试轮次：2

一次只生成当前这一镜。镜头的时长、事件、景别、钩子、衔接、锚点和音频安排以镜头表为准，这里按节拍把它们落到时间线。节点名沿用“每秒分镜”，内容按节拍切格：一个节拍是一个主要动作或一段持续状态，长度不固定。H3 视频提示词不单独保存节拍 JSON；写 `integrated_multimodal_description` 需要每个节拍的动作、镜头、空间、音频和交接。镜头运动的幅度和速度写在 `camera` 里，不另设字段。整段环境声和配乐写在文生视频提示词的 `overall_soundscape`、`non_diegetic_music`，不放进每秒分镜。有对白的节拍另记 `dialogue`，用来绑定角色卡。

**步骤：**

1. 前置条件检查（程序）。
2. 生成（AI）。
3. 程序审核。未通过且未达重试轮次时，把原因作为修改意见，带原内容重新生成，再从程序审核做起。达到重试轮次仍未通过则保留本轮内容，节点进入未通过，不更新下游。
4. AI 审核。未通过时按同一重试轮次、同一方式修订。
5. 数据保存同步。
6. 下游节点 hash 检查。

**前置条件：**

1. 目标镜头属于本集。
2. 本集镜头表已有效生成，且这一镜的 `duration_seconds`、`body`、`shot_scale`、`hook`、`continuity_transition`、`reference_anchor` 和 `audio_arrangement` 都已写明。

3. 项目角色库与该镜角色/服装识别已有效生成；不要求定妆照。
4. 非首镜要求上一镜每秒分镜有效且交接资料完整；未生成、未通过或过期时阻断。明确换场仍读取前镜资料，由本镜剧情决定需要继承的部分。

**生成规则：**

整镜背景与开场设定由镜头表提供：读取 `body` 中的场景及整镜摄影安排、景别、参考锚点、连续性与音频安排，与前镜实际末态核对后继承。每个节拍只细化接触、施力、动作进度、位置及光声变化，不重新设计背景、机位、风格或可见范围，不逐拍重复无变化的设定。简洁且能执行的描述合法，不以固定字数判断；持续节拍要写明保持的状态、细微的连续变化及运镜幅度和速度，不能只写“继续/缓慢”。旧表未给摄影细节不自动拒绝，必要执行缺口应指出需补镜头表。本节点输出结构不变，不保存第二份整镜设定。

面板每秒分镜卡片在节拍时间线前只读展示“整镜设定（来自镜头表）”，直接读取当前本镜的 `body`、`shot_scale`、`continuity_transition`、`reference_anchor`、`audio_arrangement`。源镜头表变更后刷新显示新值，不修改已保存的每秒结果，也不替代其有效性状态。

1. 只为当前镜头写节拍指令，从 0 秒连续覆盖到镜头表参考时长，中间不留空隙，末段结束时间等于参考时长。
2. 不改这一镜的时长、边界、事件、景别、钩子、出镜人物、服装、地标和光位。
3. 第一秒从本镜连续性衔接写明的开场状态开始。镜末记录实际结束状态和待续事项，不提前编写下一镜剧情。首段读取有效前镜交接资料，不重演已完成动作；明确换场或时间省略时按本镜剧情选择继承。
4. 按节拍切格，`time_range` 写节拍起止，如 `0–2s`、`2–5s`。以下位置必须开新节拍：剪辑切镜、对白开始或换说话人、钩子、关键状态改变（持物转移、开合、入画出画、到达位置）。每个节拍只有一个主要动作或一段持续状态，次要动作写在拍内。拍长按内容决定，一般为 1–4 秒；有剧情依据的情绪反应、凝视、氛围或缓慢运镜可以是一个较长的持续节拍。只有钩子所在时刻可以拆成 `2.0–2.5s`、`2.5–3.0s` 这类连续亚秒节拍。补充需求明确要求逐秒控制时，每个节拍固定 1 秒。
5. 每个节拍都写动作、姿态和表情：事件节拍写起点到终点的过程，持续节拍写保持的状态和细微的连续变化，包括身体、手持道具、眼神和表情。节拍内的关键时点写明，如“约 3.5s 杯子落地”。
6. 每个节拍都写镜头运动：推、拉、摇、倾、横移、升降、环绕、跟拍、固定或手持晃动。运动留在镜头表已定的景别里。写明贯穿本拍的幅度和速度。
7. 每个节拍都写空间位置（起止位置，有移动时写路径），并落在参考锚点已写的地标和人物位置上。不新增地标，不把人物改到锚点以外的位置。
8. 每个节拍都写音频线索。只把本镜音频安排里的旁白、对白和音效落到具体节拍及拍内时点，不新增镜头表没有的台词。没有声音时写明无声。
9. 旁白所在的节拍写明说话人嘴唇闭合。出镜对白所在的节拍写明张嘴，并写眼神和身体动作。
10. 非末段 handoff 写本镜内部交给下一节拍的状态；末段 handoff 留空，跨镜以顶层四字段为准。
11. 节拍之间连续、不重叠。不用一个覆盖整镜的节拍省略其中的事件，也不为凑格数把一个连续动作拆成重复节拍。
12. 角色名、服装和地标与镜头表使用同一名称。
13. 不为显示变化而编造镜头表没有的离散小动作；有剧情依据的停留不压缩成一瞬，再用新增动作补足时长。

**生成返回结构：**

```json
{
  "end_state": "最后一刻的已知状态",
  "pending_actions": "",
  "pending_dialogue": "",
  "continuing_audio": "",
  "storyboard": [
    {
      "time_range": "0–2s",
      "action": "",
      "camera": "",
      "space": "",
      "audio": "",
      "handoff": "",
      "dialogue": [
        {
          "speaker_id": "",
          "speaker_name": "",
          "mode": "画内",
          "dialogue_text": ""
        }
      ]
    }
  ]
}
```

从 0 秒起按节拍覆盖到镜尾，中间不留空隙，末段结束时间等于参考时长。`time_range` 写节拍起止，如 `0–2s`、`2–5s`；只有钩子所在时刻可以用连续亚秒格，如 `2.0–2.5s`、`2.5–3.0s`。

`action` 写身体、手持道具、姿态、眼神和表情。`camera` 写推、拉、摇、倾、横移、升降、环绕、跟拍、固定或手持晃动，需要时写幅度和速度。`space` 写人物位置、手持物和地标位置。`audio` 写这一节拍的旁白、对白、音效、呼吸或无声，并写嘴部开合。`handoff` 写本镜内交给下一节拍的状态，末段留空。这一节拍没有对白时 `dialogue` 为 `[]`。有对白时每句一条：`speaker_id` 用角色 id，未建卡人物和独立旁白留空；`speaker_name` 保留原称谓；`mode` 为画内、画外或心声；`dialogue_text` 为原台词。

**程序审核：**

时间段从 0 连续覆盖，每段结束必须大于开始，禁止空隙和重叠。末段结束时间必须等于该镜镜头表参考时长。不相等则把原因作为修改意见，按重试轮次进入修订；用尽后保留本轮分镜，节点进入未通过，不更新下游。

**AI审核：**

1. 从 0 秒起连续覆盖，没有时间空隙，并覆盖镜头表事件、对白和结尾状态。
2. 每个节拍都含动作或姿态或表情、镜头、空间、音频；非末段 handoff 说明镜内交接，末段交接由顶层四字段记录。
3. 事件、人物、服装、景别、钩子、地标、光位和台词与镜头表一致。没有改时长，没有拆镜或并镜。
4. 第一秒接得上本镜连续性衔接。人物和地标落在参考锚点写明的位置。
5. 动作能在该节拍内做完，道具和人物位置能交到下一秒。
6. 说话的秒写明嘴部开合。离屏旁白为闭，出镜对白为开。
7. 没有新增镜头表中不存在的人物、服装、地标、事件和台词。
8. 节拍切分合理：必须开新节拍的位置都已切开；一拍一个主要动作或一段持续状态；允许一个动作或停留跨多秒。停留被压缩后用新增动作补时、为显示变化编造拍内小动作、用一个节拍覆盖整镜省略事件，均判不通过。

**审核返回结构：**

```json
{
  "是否通过": true,
  "原因": ""
}
```

`是否通过` 为 `true` 或 `false`。为 `true` 时原因为空，为 `false` 时写明问题。

**依赖资料：**

- 该镜的 `title`、`number`、`duration_seconds`、`shot_scale`、`hook`、`body`、`continuity_transition`、`reference_anchor`、`audio_arrangement`。
- 项目文字人物目录、已确认本镜绑定（编号）、语言和补充要求；输入与 hash 共用共享投影，不含图片。
- `character_binding.node_state.dependency_hash`。

**数据保存同步：**

程序审核和 AI 审核都通过后，把节拍内容写入 `episodes[].shot_list.shots[].seconds_storyboard.storyboard[]` 的 `time_range`、`action`、`camera`、`space`、`audio`、`handoff`、`dialogue`，节点标为已生成、原因清空，并保存到 SQLite 项目 Model。重试轮次用尽后程序审核仍未通过时，仍保存本轮分镜内容，节点进入未通过，原因写入 `seconds_storyboard.node_state.reason`，不更新下游 hash。

**下游节点 hash 检查：**

影响该镜文生视频提示词及下一镜每秒分镜；下一镜失效时按依赖继续传播。前镜非末尾内容改变而交接资料及末尾片段不变时，不单独使下一镜过期。文生视频提示词按自己的依赖资料读取 `seconds_storyboard.storyboard[]` 的上述字段，以及 `seconds_storyboard.node_state.dependency_hash`。

## 镜末交接与前镜输入

四个顶层字符串字段与时间轴一同生成、审核、修订并保存到 seconds_storyboard：end_state 为非空结束状态，涵盖已知人物位置/朝向/姿态/服装/持物、物件及环境；pending_actions、pending_dialogue、continuing_audio 分别记录未完成动作、未结束对白及持续声音，无则为空字符串，不虚构下一镜行动。AI审核核对这些字段与末段一致，且首段符合前镜及本镜转场意图。

previous 输入首镜为 null，后镜为前镜编号、上述四字段及 last_beats；last_beats 直接读取与末尾3秒相交的完整节拍，不截断或让模型另写摘要，内部 speaker_id 清空。前镜资料放 user；多轮修订的 assistant 只放本镜旧结果。依赖指纹与提示词读取同一份 previous。下游文生提示词也接收四字段，视频沿用已审核三段提示词。

v13迁移保留旧正文与历史，新增交接字段为空，已有产出的生成态每秒节点及相关下游标为过期；排队快照同步过期，按镜头顺序重生成，不用旧逐段 handoff 猜测镜末资料。

目录内对白说话人的 `speaker_id` 原样引用角色唯一ID，`speaker_name` 为显示名称；目录外人物及独立旁白允许空ID。出镜绑定直接使用 `character_id`、`costume_id`，不转换编号。

出镜与着装唯一依据为本镜镜头表 on_screen_characters，群演依据 background_characters 及正文。每秒阶段不重新选择服装或人物；群演的抬手、点头等动作不构成缺绑定，不要求群演衣物目录。

明确按秒报时或倒计时时，相邻连续秒数按真实一秒间隔推进，不按参考镜长机械均摊成每数多秒；保留原数词，不擅自补报省略的数。原剧情已有等待预定时刻、屏息待令时可自然持续，保持动作与发声真实，不因禁止无意义空等而删去有依据的等待。生成、修订、审核采用同一计时口径，口令与下一镜响应衔接一致。

原台词的省略号、破折号等标点在dialogue_text中原样保留；可在表演中说明停顿或拖音，但不能用表演替代后删去原标点，也不朗读标点为新增词语。

明确原对白增加程序完整性检查，按时间线拼接dialogue_text，保留原标点、发声顺序；完整来源可确定时拒绝漏句、重复及倒序。不明确的叙述/旁白不猜测。上游矛盾使用公共结构化问题定位，不继续耗费本节点修订；重复确定性程序错误可提前停止，详见制作工作流。
