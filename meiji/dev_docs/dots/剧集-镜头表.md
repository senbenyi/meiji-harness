# 剧集-镜头表（`shots`，AI）

**固定属性：**

- 误差时长：±30秒
- 重试轮次：2

一次生成本集全部镜头。这里只规划每一镜的内容、时间和跨镜关系，不写逐秒指令。逐秒动作留给后面的每秒分镜，每次只做一镜。

**步骤：**

1. 前置条件检查（程序）。
2. 生成（AI）。
3. 程序审核。未通过且未达重试轮次时，把原因作为修改意见，带原内容重新生成，再从程序审核做起。达到重试轮次仍未通过则保留本轮内容，节点进入未通过，不更新下游。
4. AI 审核。未通过时按同一重试轮次、同一方式修订。
5. 数据保存同步。
6. 下游节点 hash 检查。

**前置条件：**

1. 本集故事大纲已生成，结构有效，保存的依赖 hash 与当前资料一致。
2. 角色和服装文字作为上下文读取，不要求角色库节点为 `generated`。

**生成规则：**

1. 一次生成内部先规划、后填充：按小段确定整数预算、镜头数量、顺序、剧情范围和每镜时长；骨架锁定后再填写全部镜头字段。不增加生成阶段或模型调用，只输出最终完整镜头表。
2. 每镜为4–15整数秒。按剧情边界在本段固定预算内拆分，短节拍并入同段相邻镜头，状态停留也计入预算。先调整镜头数量及分配，保证末镜剩余时长同样满足范围，再锁定；不能靠删对白、快进动作或新增剧情凑时长。长对白按自然语义拆镜，拼接后保留完整原话和说话人。
3. 先按sequence顺序累计小段原始时长：第i段整数预算为round(前i段累计)−round(前i−1段累计)，首段前累计为0，0.5向上取整。整数小段预算保持不变；避免各段独立取整积累误差。每段镜头合计必须等于该段整数预算，整集目标为原始小段总和四舍五入，舍入误差不超过0.5秒；不得因本集参考时长不同伸缩小段预算。填充字段时不改锁定的数量、顺序及各镜时长。返回前逐段及整集核对；若需修正，回到该段固定预算内调整骨架，再同步填写字段。上述计算只作为AI指导，不增加程序预算分配。
4. `正文` 写本镜事件：谁在画面里、做了什么、结果是什么。不写每一秒的运镜和站位。每个小段 `正文` 里明确写出的剧情事实和描写都要落入该小段对应的连续镜头：人物与关系、动作过程及对象、场景环境、事件因果、情绪及强弱变化、对白与声音、物件和状态、结果、结尾，以及具体形容词和限定描述（如程度、色彩、质感、语气）。可以重组句子或拆进多镜，但不能漏掉、弱化、泛化或改变含义；不能跨小段丢掉。
5. 每镜写连续性衔接：如何承接上一镜的结束画面、道具位置、眼神、姿态、声桥或情绪，以及如何为下一镜开场做准备。
6. 每镜写参考锚点：固定地标及其画面位置，每个出镜角色的画面位置、朝向、初始姿态和服装，实际离场角色及已知原因（未入镜不等于离场，仍在场时如实说明），以及光位基线。
7. 每镜用中文写一个钩子，只从这八个里选：视觉笑点（靠画面好笑）、反转（结果和预期相反）、悬念（危险或疑问先悬着）、温情（柔和的情感停顿）、追逐（追、逃或赶时间）、揭示（揭开之前没看见的信息）、回扣（呼应前面的画面、台词或道具）、表情拍（重点是表情变化）。
8. 每镜定一个景别。景别在特写、大特写和其他景别之间交替。
9. 每镜写音频安排：有没有旁白、对白和关键音效，谁在说话。不写到某一秒。用户没有明确要求语言时，不锁定对白语言。
10. 单镜有动作或对白的重要角色不超过 3 人。
11. 同一场景的相邻镜头，固定地标和光位要么保持一致，要么写明如何变化。
12. 已经离场的角色至少再记录一镜。连续两镜明确不在场后，不再记录。
13. 眼神、人物位置、道具状态或光位变化时，说明原有动作或拍摄参照变化；不能用硬切掩盖状态矛盾，时间跳跃须有故事小段依据。
14. 姓名和服装名称目录仅用于明确同一身份人物/同一服装的名称对齐，不能改变原文时代、身份阶段或服装事实。原文未收录人物/服装保留原称谓或描述；现代林峥不能因目录武松而变成古装武松。不得据目录补造剧情、换装或细节，素材关联交给后续角色与服装识别。

镜头规划服务于已有剧情，不得为景别、钩子或时长要求新编事件、台词、出入场或结尾。正文完整承载本镜剧情，音频字段与正文声音对应；同一句台词不得重复播放。首镜承接原开场，末镜停在原结尾。修订先核对旧表是否满足当前小段整数预算；预算错误需先修正对应小段骨架，再落实意见，保留其余内容和编号。不能因为补充字段增加时长；旧表不能作为新增剧情或预算的依据。

**生成返回结构：**

```json
{
  "shots": [
    {
      "title": "",
      "number": "S01",
      "duration_seconds": 12,
      "shot_scale": "",
      "hook": "视觉笑点",
      "body": "",
      "continuity_transition": "",
      "reference_anchor": {
        "fixed_landmark": "",
        "character_positions": "",
        "departed_characters": "",
        "lighting": ""
      },
      "audio_arrangement": {
        "narration": "",
        "dialogue": "",
        "sound_effects": ""
      }
    }
  ]
}
```

`duration_seconds` 是整数秒，由程序审核判定 4–15 秒范围。`hook` 只用规定的八个词之一。没有旁白、对白或音效时，对应项为空字符串。不设置最少镜头数。shots 是非空数组；所有规定字段齐全，除 duration_seconds 外的叶字段均为字符串，不能返回 null 或字符串数组。已有同一镜头沿用编号，新镜在已占用最大编号后递增，首次从 S01 开始；播放顺序由数组决定，不输出内部 ID、sequence 或小段映射。

**程序审核：**

可解析JSON缺少必填字段（例如 audio_arrangement）属于程序审核未通过，缺字段原因及本轮原始候选进入同任务修订，共用既有两次修订。修订耗尽仍缺字段时，任务及节点进入未通过，原始候选只留历史，保留原正式镜头表及hash，不保存不完整对象。网络、接口、超时或JSON不可解析仍记失败，异常原因不自动上传提示词。

每镜参考时长为 4–15 整数秒，包含边界。全剧集镜头参考时长总和与 `episodes[].duration_seconds` 的差值绝对值不得超过 30 秒，不要求完全相等。超出则把原因作为修改意见，按重试轮次进入修订；用尽后保留本轮镜头表，节点进入未通过，不更新下游。未通过的镜头表不能作为每秒分镜的输入。生成提示以小段总和统一舍入后的预算为严格目标；±30秒仍为原有程序审核接受范围，不是生成时可自由使用的增减预算。此次仅修改AI指导，未新增逐段程序校验或小段映射字段。

**AI审核：**

1. 每个故事小段 `正文` 中的明确事实和描写都能在其连续镜头序列中找到；逐项核对人物、动作、场景、情绪、声音、结果及形容和限定细节，没有漏项、泛化或改义。每镜都有钩子。每连续 3 镜至少 1 镜是揭示、反转或回扣。
2. 开场镜和收尾镜的钩子是视觉笑点、反转、揭示、悬念、温情之一。
3. 没有镜头超过 3 个有动作或对白的重要角色。
4. 同场景相邻镜头的地标和光位要么继承，要么有明确变化说明。
5. 按连续性衔接逐镜阅读，没有一镜从与上一镜结尾矛盾的状态开始。
6. 景别在特写、大特写和其他景别之间交替。
7. 人物身份、时代与服装符合故事小段事实，名称目录仅辅助同身份对齐，未收录不构成拒绝理由。镜头顺序覆盖各个故事小段。每个小段 `正文` 里的剧情、动作、场景、情绪和形容词都能在对应镜头中找到，意思没有被修改。
8. 正文、衔接、锚点和音频安排停留在整镜层面，没有拆成逐秒动作。
9. 审核正文是否能按分配时长正常呈现和完整覆盖剧情；必要修复在对应小段固定整数预算内调整切分，不能建议跨段借时或扩时。统一舍入带来的小数差异不算剧情问题。单镜时长范围、编号结构及总时长仍由程序审核判定，不重复报告数值问题。

**审核返回结构：**

```json
{
  "是否通过": true,
  "原因": ""
}
```

`是否通过` 为 `true` 或 `false`。为 `true` 时原因为空，为 `false` 时写明问题。

**依赖资料：**

- `episodes[].story_outline` 的 `segments[].sequence`、`duration_seconds`、`body`、`causal`。
- 已保存的 `story_outline.node_state.dependency_hash`，不以递归重算出的值替代。
- `episodes[].duration_seconds`。
- 任务输入和保守依赖仍保留的角色文字：`character_library.characters[]` 的 `number`、`name`、`position`、`age_range`、`body_type`、`hairstyle`、`signature_props`、`immutable_traits`。
- 上述角色的 `costumes[]` 中 `number`、`name`、`color`、`material`、`props`。

任务输入和依赖计算共用完整文字投影；提示词compose再精简为角色name与costumes[].name，生成、修订、审核一致，不发送编号、年龄、定位、外貌、道具等额外目录字段。本次保持依赖指纹算法不变，不迁移已有项目；因此完整角色文字变化仍可能触发镜头表过期，属于保守依赖。不读取图片地址、图片状态、声线或默认服装配置作为本节点依赖。角色库仅状态改变但这些文字未变，不因此使镜头表过期。

**数据保存同步：**

程序审核和 AI 审核都通过后，节点标为已生成、原因清空并更新本节点依赖 hash；写入 `episodes[].shot_list.shots[]` 的 `title`、`number`、`duration_seconds`、`shot_scale`、`hook`、`body`、`continuity_transition`、`reference_anchor`、`audio_arrangement`。同编号保留已有镜头 ID 和下游内容，新编号生成 ID，程序按返回顺序补 `sequence`。有未结束任务或节点规则引用的镜头不可直接移除；旧终态任务和步骤不重建。

两种审核共用最多 2 次修订。程序审核或 AI 审核耗尽后仍未通过，仍将最后一轮镜头表保存到同一正式节点；状态为 `rejected`，原因写入 `shot_list.node_state.reason` 和任务结束原因，保留原成功 hash，不主动更改下游状态、hash 或媒体。重新提交带上该原因。新任务以执行时的正式资料做前置校验，不回退历史正文；公共状态规则见 [step_model.md](../step_model.md)。

**下游节点 hash 检查：**

影响该集每个镜头的每秒分镜。每秒分镜按自己的依赖资料读取该镜的 `title`、`number`、`duration_seconds`、`shot_scale`、`hook`、`body`、`continuity_transition`、`reference_anchor`、`audio_arrangement`，以及已保存的 `shot_list.node_state.dependency_hash`。必需上游失效时继续向后传播。

镜头删除或重排还要直接检查合片的有序视频依赖，以及保留镜头的前镜尾帧引用关系，不能只等每秒分镜内容变化后才检查。保留媒体文件及旧 hash，仅将失效节点标为过期。镜头集合变化后重新累计本集实际时长。

故事大纲成功保存（含人工编辑、通过程序审核的人工放行）后，以所有小段 duration_seconds 的合计回写本集 duration_seconds，保留小数秒，再记录依赖 hash。候选和未通过结果不回写；本轮大纲审核仍使用回写前参考。镜头表生成及程序审核统一读取回写后的本集参考时长，镜头总时长仍允许 ±30 秒误差。
