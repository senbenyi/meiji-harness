# 剧集-镜头表（`shots`，AI）

**固定属性：**

- 误差时长：±30秒
- 重试轮次：2

一次生成本集全部镜头。这里只规划每一镜的内容、时间和跨镜关系，不写逐秒指令。逐秒动作留给后面的每秒分镜，每次只做一镜。

**步骤：**

1. 前置条件检查（程序）。
2. 生成（AI）。
3. 程序审核。未通过且未达重试轮次时，把原因作为修改意见，带原内容重新生成，再从程序审核做起。达到重试轮次仍未通过则保留本轮内容，节点进入未通过，不更新下游。
4. AI 审核。未通过时按同一重试轮次、同一方式修订。
5. 数据保存同步。
6. 下游节点 hash 检查。

**前置条件：**

1. 本集故事大纲已有效生成。

**生成规则：**

1. 每个故事小段先作为剧情锚点，再拆成镜头。
2. 每镜 4–15 秒。更长就拆开。短于 4 秒的节拍并入相邻镜头。
3. 镜头总时长尽量接近本集参考时长，不为凑时长删改剧情。
4. `正文` 写本镜事件：谁在画面里、做了什么、结果是什么。不写每一秒的运镜和站位。每个小段 `正文` 里明确写出的剧情事实和描写都要落入该小段对应的连续镜头：人物与关系、动作过程及对象、场景环境、事件因果、情绪及强弱变化、对白与声音、物件和状态、结果、结尾，以及具体形容词和限定描述（如程度、色彩、质感、语气）。可以重组句子或拆进多镜，但不能漏掉、弱化、泛化或改变含义；不能跨小段丢掉。
5. 每镜写连续性衔接：如何承接上一镜的结束画面、道具位置、眼神、姿态、声桥或情绪，以及如何为下一镜开场做准备。
6. 每镜写参考锚点：固定地标及其画面位置，每个出镜角色的画面位置、朝向、初始姿态和服装，上一镜有而本镜没有的角色及其离场原因，以及光位基线。
7. 每镜用中文写一个钩子，只从这八个里选：视觉笑点（靠画面好笑）、反转（结果和预期相反）、悬念（危险或疑问先悬着）、温情（柔和的情感停顿）、追逐（追、逃或赶时间）、揭示（揭开之前没看见的信息）、回扣（呼应前面的画面、台词或道具）、表情拍（重点是表情变化）。
8. 每镜定一个景别。景别在特写、大特写和其他景别之间交替。
9. 每镜写音频安排：有没有旁白、对白和关键音效，谁在说话。不写到某一秒。用户没有明确要求语言时，不锁定对白语言。
10. 单镜有动作或对白的重要角色不超过 3 人。
11. 同一场景的相邻镜头，固定地标和光位要么保持一致，要么写明如何变化。
12. 已经离场的角色至少再记录一镜。连续两镜明确不在场后，不再记录。
13. 眼神、人物位置、道具状态或光位发生翻转时，在连续性衔接里写明这是硬切或时间跳跃。
14. 出镜角色和服装使用角色库中的名字。

**生成返回结构：**

```json
{
  "镜头": [
    {
      "标题": "",
      "编号": "S01",
      "参考时长": 12,
      "景别": "",
      "钩子": "视觉笑点",
      "正文": "",
      "连续性衔接": "",
      "参考锚点": {
        "固定地标": "",
        "人物位置": "",
        "离场角色": "",
        "光位": ""
      },
      "音频安排": {
        "旁白": "",
        "对白": "",
        "音效": ""
      }
    }
  ]
}
```

`参考时长` 是 4–15 的整数秒。`钩子` 只用规定的八个词之一。没有旁白、对白或音效时，对应项为空字符串。

**程序审核：**

每镜参考时长为 4–15 秒。全剧集镜头参考时长总和与本集参考时长的差值不得超过误差时长。超出则把原因作为修改意见，按重试轮次进入修订；用尽后保留本轮镜头表，节点进入未通过，不更新下游。未通过的镜头表不能作为每秒分镜的输入。

**AI审核：**

1. 每个故事小段 `正文` 中的明确事实和描写都能在其连续镜头序列中找到；逐项核对人物、动作、场景、情绪、声音、结果及形容和限定细节，没有漏项、泛化或改义。每镜都有钩子。每连续 3 镜至少 1 镜是揭示、反转或回扣。
2. 开场镜和收尾镜的钩子是视觉笑点、反转、揭示、悬念、温情之一。
3. 没有镜头超过 3 个有动作或对白的重要角色。
4. 同场景相邻镜头的地标和光位要么继承，要么有明确变化说明。
5. 按连续性衔接逐镜阅读，没有一镜从与上一镜结尾矛盾的状态开始。
6. 景别在特写、大特写和其他景别之间交替。
7. 人物和服装与角色库一致，镜头顺序覆盖各个故事小段。每个小段 `正文` 里的剧情、动作、场景、情绪和形容词都能在对应镜头中找到，意思没有被修改。
8. 正文、衔接、锚点和音频安排停留在整镜层面，没有拆成逐秒动作。
9. 只判断各小段时长预算是否明显失衡、正文是否能按分配时长正常呈现。单镜时长范围、编号结构及总时长由程序审核判定。

**审核返回结构：**

```json
{
  "是否通过": true,
  "原因": ""
}
```

`是否通过` 为 `true` 或 `false`。为 `true` 时原因为空，为 `false` 时写明问题。

**依赖资料：**

- `episodes[].story_outline` 的 `segments[].sequence`、`时长秒`、`正文`、`因果`。
- `story_outline.node_state.dependency_hash`。

**数据保存同步：**

程序审核和 AI 审核都通过后，节点标为已生成、原因清空；写入 `episodes[].shot_list.shots[]` 的 `标题`、`编号`、`时长秒`、`景别`、`钩子`、`正文`、`连续性衔接`、`参考锚点`、`音频安排`。模型返回的 `参考时长` 写入 `时长秒`。程序保留已有镜头 id，并补 `序号`，同步到本地项目 JSON。重试轮次用尽后程序审核仍未通过时，仍保存本轮镜头表，节点进入未通过，原因写入 `shot_list.node_state.reason`，不更新下游 hash。

**下游节点 hash 检查：**

影响该集每个镜头的每秒分镜。每秒分镜按自己的依赖资料读取该镜的 `标题`、`编号`、`时长秒`、`景别`、`钩子`、`正文`、`连续性衔接`、`参考锚点`、`音频安排`，以及 `shot_list.node_state.dependency_hash`。
