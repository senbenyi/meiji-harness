# 剧集-镜头表（`shots`，AI）

**固定属性：**

- 误差时长：镜头合计严格等于故事小段原始时长之和四舍五入
- 重试轮次：2

一次生成本集全部镜头。这里只规划每一镜的内容、时间和跨镜关系，不写逐秒指令。逐秒动作留给后面的每秒分镜，每次只做一镜。

整镜设定也在本节点确定，复用现有字段：`body` 完整保留事件并交代场景背景与整镜摄影安排（固定机位或整体运镜意图、观察方向、必要对焦目标）；`shot_scale` 定景别；`reference_anchor.fixed_landmark` 写固定参照、初始构图和物件相对位置，`character_positions` 写人物初始姿态、位置与可见范围，`lighting` 写光源方向和明暗基准；衔接与音频字段交代开场状态和整镜声音。只拍手和袖口时明确可见范围，不强加全身或表情。上游未指定时可设计不改变剧情事实的摄影和构图，不杜撰地点、时代、服装、关键物件或新事件，不写逐秒时间点。生成、修订与审核同口径，接受合规的拍摄设计，必要方向不能留成“某一侧/自行决定”。

**步骤：**

1. 前置条件检查（程序）。
2. 生成（AI）。
3. 程序审核。未通过且未达重试轮次时，把原因作为修改意见，带原内容重新生成，再从程序审核做起。达到重试轮次仍未通过则保留本轮内容，节点进入未通过，不更新下游。
4. AI 审核。未通过时按同一重试轮次、同一方式修订。
5. 数据保存同步。
6. 下游节点 hash 检查。

**前置条件：**

1. 本集故事大纲已生成，结构有效，保存的依赖 hash 与当前资料一致。
2. 项目角色库节点有效，角色及服装的ID与完整文字资料作为输入，不要求定妆照。

**生成规则：**

1. 一次生成内部先规划、后填充：按小段确定整数预算、镜头数量、顺序、剧情范围和每镜时长；骨架锁定后再填写全部镜头字段。不增加生成阶段或模型调用，只输出最终完整镜头表。
2. 每镜为4–15整数秒。按剧情边界在本段固定预算内拆分，短节拍并入同段相邻镜头，状态停留也计入预算。先调整镜头数量及分配，保证末镜剩余时长同样满足范围，再锁定；不能靠删对白、快进动作或新增剧情凑时长。长对白按自然语义拆镜，拼接后保留完整原话和说话人。
3. 先按sequence顺序累计小段原始时长：第i段整数预算为round(前i段累计)−round(前i−1段累计)，首段前累计为0，0.5向上取整。整数小段预算保持不变；避免各段独立取整积累误差。每段镜头合计尽量贴近该段整数预算。整集镜头合计与原始小段总和四舍五入相差不超过±30秒，不要求精确相等；不得因本集参考时长不同伸缩小段预算。填充字段时不改锁定的数量、顺序及各镜时长。返回前逐段及整集核对；若需修正，回到该段固定预算内调整骨架，再同步填写字段。上述计算只作为AI指导，不增加程序预算分配。
4. `正文` 写本镜事件：谁在画面里、做了什么、结果是什么。不写每一秒的运镜和站位。每个小段 `正文` 里明确写出的剧情事实和描写都要落入该小段对应的连续镜头：人物与关系、动作过程及对象、场景环境、事件因果、情绪及强弱变化、对白与声音、物件和状态、结果、结尾，以及具体形容词和限定描述（如程度、色彩、质感、语气）。可以重组句子或拆进多镜，但不能漏掉、弱化、泛化或改变含义；不能跨小段丢掉。
5. 每镜写连续性衔接：如何承接上一镜的结束画面、道具位置、眼神、姿态、声桥或情绪，以及如何为下一镜开场做准备。
6. 每镜写参考锚点：固定地标及其画面位置，每个出镜角色的画面位置、朝向、初始姿态和服装，实际离场角色及已知原因（未入镜不等于离场，仍在场时如实说明），以及光位基线。
7. 每镜用中文写一个钩子，只从这八个里选：视觉笑点（靠画面好笑）、反转（结果和预期相反）、悬念（危险或疑问先悬着）、温情（柔和的情感停顿）、追逐（追、逃或赶时间）、揭示（揭开之前没看见的信息）、回扣（呼应前面的画面、台词或道具）、表情拍（重点是表情变化）。
8. 每镜定一个景别。景别按事件、空间关系、动作和对白选择，允许连续相同景别，不机械交替。
9. 每镜写音频安排：有没有旁白、对白和关键音效，谁在说话。不写到某一秒。用户没有明确要求语言时，不锁定对白语言。
10. 单镜有动作或对白的重要角色不超过 3 人。
11. 同一场景的相邻镜头，固定地标和光位要么保持一致，要么写明如何变化。
12. 已经离场的角色至少再记录一镜。连续两镜明确不在场后，不再记录。
13. 眼神、人物位置、道具状态或光位变化时，说明原有动作或拍摄参照变化；不能用硬切掩盖状态矛盾，时间跳跃须有故事小段依据。
14. 姓名和服装名称目录仅用于明确同一身份人物/同一服装的名称对齐，不能改变原文时代、身份阶段或服装事实。原文未收录人物/服装保留原称谓或描述；现代林峥不能因目录武松而变成古装武松。不得据目录补造剧情、换装或细节，本节点直接选择该人物所属服装ID；不具名群演单独描述，不强制绑定。

镜头规划服务于已有剧情，不得为景别、钩子或时长要求新编事件、台词、出入场或结尾。正文完整承载本镜剧情，音频字段与正文声音对应；同一句台词不得重复播放。首镜承接原开场，末镜停在原结尾。修订先核对旧表是否满足当前小段整数预算；预算错误需先修正对应小段骨架，再落实意见，保留其余内容和镜头内部ID。不能因为补充字段改变目标预算；旧表总时长不是上限，偏短须补足、偏长须收回到目标。各段预算B的镜数范围为ceil(B/15)至floor(B/4)，按正常语速、动作及反应确定镜数；旧镜数不能作为上限。允许必要的增镜、拆并镜及对应正文重分配，新增镜头只承载已有剧情，不以空等或重复填时。旧表不能作为新增剧情或预算的依据。

**生成返回结构：**

生成与修订按输出结构返回合法JSON，reference_anchor包含四个规定字符串子字段，audio_arrangement与其同级，均在当前镜头对象内；lighting不得放到镜头根层。字段顺序不限。序列化要求只在输出契约中渲染一次，检查括号、逗号和转义，不接受注释、尾逗号或对象外内容；不由解析器猜测或静默修补。

```json
{
  "shots": [
    {
      "title": "",
      "id": "",
      "duration_seconds": 12,
      "shot_scale": "",
      "hook": "视觉笑点",
      "body": "",
      "on_screen_characters": [{"character_id":"c_UUID","costume_id":"co_UUID"}],
      "background_characters": "",
      "continuity_transition": "",
      "reference_anchor": {
        "fixed_landmark": "",
        "character_positions": "",
        "departed_characters": "",
        "lighting": ""
      },
      "audio_arrangement": {
        "narration": "",
        "dialogue": "",
        "sound_effects": ""
      }
    }
  ]
}
```

`duration_seconds` 是整数秒，由程序审核判定 4–15 秒范围。`hook` 只用规定的八个词之一。没有旁白、对白或音效时，对应项为空字符串。不设置最少镜头数。shots 是非空数组；所有规定字段齐全，除 duration_seconds 外的叶字段均为字符串，不能返回 null 或字符串数组。已有同一镜头原样返回内部 id，新增镜头 id 为空字符串；非空 id 不能重复或引用他集镜头。播放顺序由数组决定，程序按顺序生成 S01、S02…及 sequence，禁止输出 number 或小段映射。

**程序审核：**

可解析JSON的字段、人物/服装绑定、镜头身份及内容组装契约错误统一进入程序审核未通过，携带本轮原始候选与原因，共用已有两轮修订。修订耗尽保留旧正式内容和hash，不保存无效候选。JSON不可解析和审核协议错误记为未通过；HTTP、网络及超时等执行异常记为失败。

每镜参考时长为4–15整数秒。全集镜头合计与大纲所有小段原始时长合计四舍五入相差不超过±30秒，不要求精确相等。小段整数预算由既有累计舍入规则解释给AI，直接读取上游时长，不增加独立预算数据。逐段剧情归属与覆盖由AI审核；未新增小段映射字段。修订意见逐行去重。时长等可保存的内容审核未通过时保留最后候选与原成功hash；结构或身份无效时保留原正式内容。

**AI审核：**

1. 每个故事小段 `正文` 中的明确事实和描写都能在其连续镜头序列中找到；逐项核对人物、动作、场景、情绪、声音、结果及形容和限定细节，没有漏项、泛化或改义。每镜都有钩子。钩子按已有内容选择，不设密度配额。
2. 首尾镜沿用全部八种钩子枚举，不额外限制类别。
3. 没有镜头超过 3 个有动作或对白的重要角色。
4. 同场景相邻镜头的地标和光位要么继承，要么有明确变化说明。
5. 按连续性衔接逐镜阅读，没有一镜从与上一镜结尾矛盾的状态开始。
6. 景别按事件、空间关系、动作和对白选择，允许连续相同景别，不机械交替。
7. 人物身份、时代与服装符合故事小段事实，名称目录仅辅助同身份对齐，未收录不构成拒绝理由。镜头顺序覆盖各个故事小段。每个小段 `正文` 里的剧情、动作、场景、情绪和形容词都能在对应镜头中找到，意思没有被修改。
8. 正文、衔接、锚点和音频安排停留在整镜层面，没有拆成逐秒动作。
9. 审核正文是否能按分配时长正常呈现和完整覆盖剧情；必要修复在对应小段固定整数预算内调整切分，不能建议跨段借时或扩时。统一舍入带来的小数差异不算剧情问题。单镜时长范围、编号结构及总时长仍由程序审核判定，不重复报告数值问题。

**审核返回结构：**

```json
{
  "是否通过": true,
  "原因": ""
}
```

`是否通过` 为 `true` 或 `false`。为 `true` 时原因为空，为 `false` 时写明问题。

**依赖资料：**

- `episodes[].story_outline` 的 `segments[].sequence`、`duration_seconds`、`body`、`causal`。
- 已保存的 `story_outline.node_state.dependency_hash`，不以递归重算出的值替代。
- `episodes[].duration_seconds`。
- 完整角色文字目录：角色 id、name、gender、era、position、age_range、body_type、hairstyle、signature_props、immutable_traits。
- 各角色所属 costumes[] 的 id、name、description、color、material、props。

输入和依赖使用同一完整文字投影，生成、修订、审核均传入角色与服装目录。不读取图片地址、图片状态、声线或默认服装作为本节点依赖。

**数据保存同步：**

程序审核和 AI 审核都通过后，节点标为已生成、原因清空并更新本节点依赖 hash；写入 `episodes[].shot_list.shots[]` 的 `title`、`number`、`duration_seconds`、`shot_scale`、`hook`、`body`、`continuity_transition`、`reference_anchor`、`audio_arrangement`。按已有镜头 id 保留该镜头身份和下游内容；新增空 id 由程序创建身份，全部镜头按返回顺序生成 `number` 和 `sequence`。重排不会将资源按位置分配到另一镜头；旧数据和历史任务不迁移、不改写，展示编号在下次保存镜头表时统一生成。有未结束任务或节点规则引用的镜头不可直接移除；旧终态任务和步骤不重建。

两种审核共用最多 2 次修订。程序审核或 AI 审核耗尽后仍未通过，仍将最后一轮镜头表保存到同一正式节点；状态为 `rejected`，原因写入 `shot_list.node_state.reason` 和任务结束原因，保留原成功 hash，不主动更改下游状态、hash 或媒体。重新提交带上该原因。新任务以执行时的正式资料做前置校验，不回退历史正文；公共状态规则见 [step_model.md](../step_model.md)。

**下游节点 hash 检查：**

影响该集每个镜头的每秒分镜。每秒分镜按自己的依赖资料读取该镜的 `title`、`number`、`duration_seconds`、`shot_scale`、`hook`、`body`、`continuity_transition`、`reference_anchor`、`audio_arrangement`，以及已保存的 `shot_list.node_state.dependency_hash`。必需上游失效时继续向后传播。

镜头删除或重排还要直接检查合片的有序视频依赖，以及保留镜头的前镜尾帧引用关系，不能只等每秒分镜内容变化后才检查。保留媒体文件及旧 hash，仅将失效节点标为过期。镜头集合变化后重新累计本集实际时长。

故事大纲成功保存（含人工编辑、通过程序审核的人工放行）后，以所有小段 duration_seconds 的合计回写本集 duration_seconds，保留小数秒，再记录依赖 hash。候选和未通过结果不回写；本轮大纲审核仍使用回写前参考。镜头表生成及程序审核统一读取回写后的本集参考时长，镜头总时长仍允许 ±30 秒误差。

## 出镜人物和服装

镜头表直接确定本镜卡内人物与服装，on_screen_characters 只保存目录中实际可见人物的ID及其所属服装ID；同人不重复，人物有服装目录必须选择相符服装，无目录允许空服装ID。正文写明人物表演及已知着装，参考锚点与绑定一致；角色和服装资料不作为新剧情依据，不默认第一套服装。

background_characters 记录上游已有的不具名社员、工人等群演及其可见行为，无则空字符串。群演可以有自然动作及上游原对白，不要求角色卡、服装ID或参考图，不占三名重要人物上限。审核不能仅因群演可见或有动作而要求绑定。每秒分镜和视频直接继承这些镜头字段，不另设识别节点。

## 字段层级错误与界面分组

body、on_screen_characters、background_characters、continuity_transition、reference_anchor、audio_arrangement同属镜头根层；reference_anchor只能包含四个规定锚点字符串，禁止额外放入或重复body。可解析JSON中镜头对象及其嵌套对象出现未知字段时，保留原始候选和完整错误路径，按原有两次修订预算进入程序审核/模型修订；耗尽仍不合法时不覆盖旧正式内容和hash。根响应未知字段、非法JSON、网络和审核协议错误仍为失败，不静默搬字段。

界面的“出镜人物与服装”是父容器，每个人物为子分组，所选服装名称及描述再归属于该人物；群演为父容器内的独立分组。镜头表和成片共用此DOM，存储ID不变。

### 叙事语义与审核证据

叙事正文允许不改变事件、时间状态、程度、语气及因果的同义转写、语序调整和古今异体字规范化；原对白及明确保留的画面文字仍逐字核对。不能仅因叙事措辞不同判为遗漏。报告前须重查本镜和同段相邻镜头，引用来源与候选的实际原文，确认动作、对象、限定或结果确有缺失或改变；已保留的内容不重复要求补回。真实动作遗漏及连续性矛盾仍须修订。

修订先核实最新候选，已解决的历史意见不重复修改。已经匹配预算且正文合规的段落保持不变；只有仍有时长或内容冲突时才在对应小段内重新规划，避免每轮因旧时长原因重写全文而引入新遗漏。

审核发现镜头表明确承认时序、空间或人物状态缺口，且没有可执行转场依据时，必须未通过；不能只声明缺口后交由下游继续。明确的回叙、换场或时间省略可按已确定依据执行。

同一连续出场场景的着装须结合相邻小段理解：具体人物的明确着装优先于群体概称，不因分段边界推断另一套服装或新增换装；明确不同服装及实际换装依据仍按变化处理。
