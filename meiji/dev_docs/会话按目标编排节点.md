# 会话按目标编排节点

- 状态：未实施
- 类型：会话编排
- 档位：分阶段。先改会话能看见的状态和唤醒，再加目标与沿主路径提交；上游修补和重新确认放在后面
- 目标：用户在会话中给出成品目标时，会话模型按现有主路径一次提交一个前置已满足的节点；任务终态回到该会话后再决定下一步。上游问题只改标明的那一处，依赖指纹决定过期，再回到原目标
- 非目标：不替换节点内部的前置检查、生成、程序审核、AI 审核和修订。不让会话模型改写 `project.json`。不把整份项目放进节点生成提示词。不让模型代替依赖指纹判断谁过期。不在导入时预排每一镜。不自动生成项目摘要、剧集摘要和定妆照

## 主 agent 与子任务

会话模型是主 agent。它看不见制作源码，每轮只有 `meiji-workflow` 技能、用户原话和工具摘要。用户给出成品目标后，它提交一个节点任务并结束本轮；任务终态送回后，再决定下一项。剧集 id、镜头 id 来自上一步结果，导入时不排死每一镜。

每个节点任务是子任务，不是另一个会聊天的 agent。切集、大纲、某一集的成片组仍由 `TaskService` 跑完前置检查、生成、程序审核、AI 审核和修订。输入仍由 `taskNodeInput` 裁剪。主 agent 不看中间稿，不代写该节点提示词，也不编排这些内部步骤。项目写入串行，子任务一个完成后再开下一个。

送回主 agent 的终态摘要只有：完成、未通过或失败；新产生的剧集 id 或镜头 id；未通过原因；上游问题的来源、位置、依据和建议；这次写入后实际过期的节点。不含生成全文、历史提示词和图片。

## 未通过归因

三类都由主 agent 判断。子任务只交证据：程序审核原文，AI 审核的是否通过和 `问题`，以及修订前后候选有没有变化。程序核对上游依据是否真的出现在所声明的资料里。生成模型和审核模型不判断「是能力不够」或「是规则冲突」。

- 上游问题：`修复范围` 是上游，且依据能在该来源里对上。停掉本节点自动修订，只改那一处，再按过期名单回来。
- 模型结果不正确：程序审核已通过，AI 仍拒绝，但依据在候选里已经存在，或位置超出实际条目数；或修订后候选几乎没变、同一条意见又出现。先换修订方式，例如局部修订对不上就改整表替换。仍然如此就停止，不再空转。
- 程序规则冲突或缺陷：模型已按契约返回，程序仍拒绝，且换修订方式后还是同一条程序错误。主 agent 留下这条程序原因并停止该目标，不把它当成内容问题再改一轮，也不修改规则本身。

## 行为

- 面板按钮和会话都创建同一种目标，例如「做完成片」。目标记录原始节点、意见、参考单集时长和当前停住的上游问题。目标不代替任务组。
- 会话每次只提交依赖已经满足的下一个节点或现成任务组。剧集数等切集结果，镜头数等镜头表。
- 「按剧本生成视频，每集大概 3 分钟」把 `reference_episode_duration_seconds` 写成 180。各集正式时长仍以切集结果为准。顺序是：写入剧本并等待自动剧本审核 → 提取剧集 → 提取人物 → 按集做故事大纲、选择性提取场景、镜头表 → 按集提交 `episode-film` 成片组 → 视频齐备后由现有规则追加合片 → 下一集从大纲继续。
- 审核给出上游问题时，本轮候选仍不写入正式内容，该节点任务仍为未通过。目标收下 `问题` 的来源、位置、依据和建议，只对那一处提交局部修改。`expireDownstream` 标过期。
- 过期节点先走重新确认：正文仍符合新上游时，只重写依赖指纹并回到已生成，不调用生成模型。对不上的才提交现有生成或修订。然后回到原目标。连续上游修补有次数上限，超过则停住并说明。
- 面板增加一行目标状态。节点卡片仍显示该节点自己的任务组状态。

## 会话每轮输入输出

技能保持主路径、时长字段和「一次一个节点」。查询返回绑定、节点状态、当前任务状态和上游问题，不返回历史提示词、图片和整份步骤。

示例：

1. 用户给出剧本和成片目标。模型调用查询，得到未绑定。
2. 模型调用创建项目，带上剧本和 180 秒。返回项目 id 和剧本审核已排队。模型告知用户后结束本轮。
3. 审核终态作为下一轮输入送回会话。通过则提交 `script-split`。
4. 之后每收到一个终态摘要，再提交主路径上的下一项。全部完成时只回复结果，不再发任务。

当前缺口：`meiji-context-query` 返回整份快照；技能禁止自动提交下一步；任务完成只出提示卡，不唤醒会话。

## 阶段

1. 会话查询改为状态摘要。`meiji-context-query` 不再返回 `repository.read()` 全量快照。
2. 增加目标记录。面板和会话的明确成品请求都写入目标，尚不自动串联。
3. 目标进行中的任务进入终态时，把终态摘要送回该会话，唤醒主 agent。摘要含任务 id、状态、原因、上游问题和本次过期节点。
4. 按主路径懒提交下一节点。更新 `skills/session/panel.md`：明确的成片目标可以提交前置已满足的下一步；前置不足仍报告原因，不发明节点内部步骤。
5. `upstreamFailure` 把结构化问题挂到目标上。剧本、剧情、大纲补局部修改。新增重新确认。编排器只遍历本次过期名单，并限制上游跳转次数。
6. 面板显示目标行。

## 验收

- 会话查询的结果不含步骤提示词和图片，且能看出节点是否已生成、未通过或已过期。
- 导入剧本并要求按约 3 分钟一集生成视频后，未绑定会话会创建项目、写入 180 秒，并在审核通过后自行提交切集；摘要和定妆照不会被提交。
- 任务终态会进入原会话的下一轮，而不是只留在面板提示卡。摘要足以让主 agent 区分上游问题、模型结果不正确、程序规则障碍，且不含节点生成全文。
- 镜头审核标明上游某一句时，只修改该句；指纹未变的节点保持已生成；过期但正文仍符合的节点经重新确认恢复，不重新生成。
- 节点生成提示词的输入范围与改动前一致。
