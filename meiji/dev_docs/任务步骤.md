# 任务步骤

本文是 meiji 三份开发契约之一，只描述任务、步骤和组合。项目节点和过期见 [项目数据结构](项目数据结构.md)。提示词见 [提示词编排](提示词编排.md)。

结构样例是同目录 `step_model.json`。任务、步骤和组合存在任务存储，按 `task_id`、`group_id` 绑定，不放进项目 Model。

## 任务、步骤、组合

任务是针对一个目标的一次执行记录。一个任务只针对一个节点，或针对一次不是节点的操作（剧本、拆分剧集、删除资料），用 `business_type` + `target_id` 定位。

节点业务、目标类型、项目 JSON 字段、产物类别和审核策略统一定义在 `shared/node-definitions.js`。项目 JSON 保留项目→剧集→镜头等层级；任务只引用一个节点，不复制节点内容。`task_groups` 保持独立，用来编排多个单节点任务；组合类型、顺序及续作语义不属于节点定义。

任务停止即终态，没有暂停。重新生成、继续、人工编辑保存、人工放行和删除都创建新任务，不恢复旧任务，不重写旧步骤。

步骤只属于一个任务。每一步实际发出的提示词和输出都记在步骤上。

文本步骤执行时按业务、步骤种类选择 `in_puts/` 中的 YAML 模板，再由文本处理器按当前项目、任务、步骤和草稿构建所有占位符资料。模板字段与资料构建器是同一提示词契约的一部分；改动后须验证真实任务路径并重启 Harness，使已加载代码和磁盘模板版本一致。

组合任务不是另一种任务，而是一批按顺序执行的普通任务。每次操作都创建组：

- 独立操作创建 `single`，默认一个任务。
- 剧本生成、角色提取创建 `workflow`。派生的项目摘要或图片任务按 `group_seq` 追加到同一组。父任务完成后，子任务失败不改写父任务。
- 成片和历史中的每秒分镜使用 `episode-film`、`episode-seconds`。

持久化的任务必须有 `group_id` 和从 1 开始的 `group_seq`。已有历史缺 `name` 时只读补显，不改写旧记录。

组、任务、步骤在创建时各保存 `name`。之后角色、剧集或镜头改名，不修改历史名称。`group_type`、`business_type`、`kind` 仍负责执行语义。

## 节点状态与任务状态

| 任务状态 | 节点状态 |
|---|---|
| `queued` | 排队中 |
| `running` | 生成中 |
| `completed` | 已生成 |
| `rejected` | 未通过 |
| `failed` | 失败 |
| `cancelled`，且任务已经开始 | 已取消 |
| `cancelled`，且任务尚未开始 | 恢复 `previous_node_state` |
| `superseded`，且任务尚未开始 | 恢复 `previous_node_state` |
| `superseded`，且重启时任务已经开始 | 已取消，正文与媒体保留 |

入队前把节点状态和原因写入 `previous_node_state`。剧本、拆分剧集和删除任务不是节点任务，该字段为 null。同一节点已有排队或运行任务时不重复建任务，返回已有任务。

## 任务状态

| 值 | 名称 | 含义 |
|---|---|---|
| `queued` | 排队中 | 已创建，等待执行 |
| `running` | 生成中 | 正在执行。同一项目同时只有一个 |
| `completed` | 已通过 | 全部步骤完成并通过 |
| `rejected` | 未通过 | 有结构有效的产出，自审最终未通过 |
| `failed` | 失败 | 执行出错，没有可用的新产出 |
| `cancelled` | 已取消 | 用户取消 |
| `superseded` | 已作废 | 组合前序失败、未通过或取消后尚未执行的任务；服务重启时所有尚未完成的排队与进行中任务 |

失败和未通过分开。失败通常重新生成。未通过可以人工编辑、人工放行或重新生成。终态任务及其已结束步骤不重新执行。

## 步骤状态与种类

| 步骤状态 | 名称 |
|---|---|
| `ready` | 等待中 |
| `running` | 执行中 |
| `done` | 完成 |
| `failed` | 失败。自审判定不通过不算失败，审核步骤仍为完成，结论记在 `result` |
| `skipped` | 已跳过 |
| `cancelled` | 已取消 |
| `superseded` | 已作废。任务结束后剩余未执行步骤，或重启时尚未完成的步骤 |

| kind | 名称 |
|---|---|
| `precheck` | 前置检查 |
| `generate` | 生成 |
| `review` | 自审 |
| `revise` | 自审修订，用 `round` 记轮次 |
| `manual_edit` | 人工编辑保存 |
| `override` | 人工放行 |
| `impact` | 计算删除影响，不改项目 |
| `apply` | 删除资料并写过期 |

步骤组成：

- 文本类：前置检查 → 生成 → 自审。自审未通过则修订后再自审，最多两轮。初审 `round=0`，其后修订和自审为 `round=1`、`2`。镜头表生成或修订若仅因单镜超过 15 秒或整集镜头总时长超出本集参考时长 ±30 秒范围而未通过程序校验，保存该失败步骤和草稿、作废本轮待审步骤，并在原任务追加修订和自审，最多两轮；修订提示包含校验错误、当前镜头数与总时长、目标范围及上一版四字段镜头表。其他程序校验错误、模型错误和接口错误仍使任务失败。
- 拆分剧集：只有前置检查 → 生成。程序校验切分结果，没有 AI 自审。
- 图片、视频、尾帧、合片：前置检查 → 生成。尾帧是截帧，合片是拼接，都不调用 AI。
- 人工编辑、人工放行：前置检查 → 对应步骤，不调用 AI。
- 删除：前置检查 → impact → apply。

文本类包括项目摘要、剧本重要角色、剧本、展示摘要、故事大纲、镜头表、每秒分镜、文本提示词。拆分剧集也走文本处理，但去掉自审。

## 发起方式

按钮保持可点。适用条件由前置检查判断，不作为按钮灰置规则。节点处于排队中或生成中时不能重复执行，程序返回已有任务。

| action | 行为 |
|---|---|
| `generate` | 节点原状态必须是未生成 |
| `regenerate` | 节点已有内容。新内容直接替换旧内容，不弹删除确认 |
| `continue` | 只出现在组合的新任务上 |
| `manual_edit` | 保存编辑内容，通过后为已生成，并触发下游过期 |
| `override` | 只用于带 AI 自审、且原状态为未通过的文本。保留失败稿，通过后为已生成 |
| `delete` | 只用于 `character-delete`、`costume-delete` |

面板对同一节点再次生成时，若该节点最新相关任务是失败、未通过、已取消或已作废，提交的 `generate` 按 `regenerate` 创建，以便通过「已有内容」的前置检查。已有排队中的同一任务则复用。没有其他未结束任务时直接启动；有其他等待或运行任务时整次拒绝。

节点卡片的生成操作按实际产物显示：没有有效内容时只显示「AI生成」；已有内容且状态为 `generated` 时只显示「重新生成」；已有内容且状态为 `rejected` 时显示「重新生成」和「按意见修改」。重新生成不带修改意见并直接提交；按意见修改必须填写非空意见，再以 `regenerate` 提交。失败或过期节点按当前仍保留的内容选择「AI生成」或「重新生成」。

## 任务业务

剧本和拆分剧集不是节点。删除也不是节点。其余业务值就是节点类型。

| 值 | 目标 | AI 自审 |
|---|---|---|
| `project-summary` | 项目 id | 有 |
| `project-characters` | 项目 id | 有 |
| `character-image` | 角色 id | 无 |
| `costume-image` | 服装 id | 无 |
| `script` | 项目 id | 有。只有审核通过才写回剧本 |
| `script-split` | 项目 id | 无 |
| `episode-summary` | 剧集 id | 有 |
| `outline` | 剧集 id | 有 |
| `shots` | 剧集 id | 有 |
| `seconds` | 镜头 id | 有 |
| `storyboard` | 镜头 id | 有 |
| `video` | 镜头 id | 无 |
| `tail` | 镜头 id | 无 |
| `assembly` | 剧集 id | 无 |
| `character-delete` | 角色 id | 无 |
| `costume-delete` | 服装 id | 无 |

`episode_id` 只用于按集查询。剧集层和镜头任务必须填写，且与目标所属剧集一致。项目、角色、服装任务留空。

角色提取通过后，只为本次新增且图片仍为空的角色和服装创建图片任务。剧本审核通过后，按项目摘要当前是否为空，向同一 workflow 组追加生成或重新生成项目摘要。

## 任务字段

| 字段 | 说明 |
|---|---|
| `id`、`project_id`、`episode_id` | 标识与归属 |
| `name` | 创建时的展示名 |
| `business_type`、`target_id` | 唯一定位目标 |
| `action` | 上表六种发起方式 |
| `group_id`、`group_seq` | 所属组和组内顺序。保存后的任务两者都必填 |
| `task_status` | 任务状态 |
| `source` | `panel` 或 `session` |
| `opinion` | 修改意见。首次生成不接受非空意见 |
| `previous_node_state` | `{ 状态, 原因 }`。非节点任务为 null |
| `queue_order` | 从 1 开始的项目内排队顺序 |
| `end_reason` | 排队中、生成中、已通过必须为空；其余终态必须非空 |
| `created_at`、`started_at`、`ended_at` | 时间 |

## 组合

| group_type | 组成 |
|---|---|
| `single` | 一次独立操作。可以没有 `episode_id`，`shot_ids` 为空 |
| `workflow` | 剧本、角色提取，以及追加的派生任务 |
| `episode-seconds` | 每镜一个 `seconds`。保留历史契约，面板不再提供独立入口 |
| `episode-film` | 按镜头顺序，每镜 `seconds` → `storyboard` → `video` → `tail`。可用 `shot_id` 限定本集的一个镜头 |

单镜视频的生成和重新生成都提交单镜 `episode-film`。`opinion` 保存到组和组内任务。

组字段：`id`、`project_id`、`episode_id`、`name`、`group_type`、`action`、`continued_from_group_id`、`source`、`opinion`、`shot_ids`、`created_at`。`status` 和 `reason` 不存储。`episode-seconds` 和 `episode-film` 的 `shot_ids` 必须非空。

组状态只看本组任务，后来的新组、人工编辑和放行不改旧组：

1. 按 `group_seq` 找到首个 `rejected`、`failed` 或 `cancelled`，状态和原因取该任务。
2. 否则有 `running` 则为生成中。
3. 否则有 `queued` 则为排队中。
4. 否则本组非空且全部 `completed` 则为已通过。
5. 否则有 `superseded` 则显示已作废。

继续时创建新组，`continued_from_group_id` 指向旧组，`group_seq` 从 1 重新开始。新组只为当前不是「已生成且产出有效」的节点建任务。原范围都已有效时不创建空组。`single` 和 `workflow` 的继续跳过已通过任务；人工编辑、放行和删除不从组继续，回到原入口。`episode-film` 继续时，跳过的有效节点仍要计算上游重生成会造成的下游过期。

创建或继续时，幂等请求返回原组。其他请求先检查拟创建节点是否已有排队或运行任务。有重叠则整组拒绝，不创建部分任务。

## 步骤字段

| 字段 | 说明 |
|---|---|
| `id`、`task_id`、`name` | 步骤单独存储，不内嵌在任务里 |
| `seq` | 从 1 开始 |
| `kind`、`round` | `round` 为 0 到 2 |
| `step_status`、`error_reason` | 失败步骤的原因必须非空 |
| `prompt` | 本步实际请求 |
| `result` | 本步输出。审核结论也在这里 |
| `started_at`、`ended_at` | 时间 |

## 前置检查

每个任务的第一步是 `precheck`，不调用 AI。不通过时该步和任务为 `failed`，节点变为失败，原内容不变，余下步骤作废，组合停止并作废后续任务。不隐式补做上游。

检查：

1. 目标存在，归属与 `business_type` 一致。发起方式适用于 `previous_node_state` 里的原状态，不把本任务写入的 `running` 当作原状态。
2. 必需输入的内容和状态都是 `generated`，并且通过产出校验。
3. 单镜任务检查镜头、时长和本次使用的前镜尾帧。图片和视频检查素材可读、参数有效。尾帧检查本镜视频。合片检查参与镜头的视频都有效。
4. 人工放行检查原状态为 `rejected`，且失败稿结构有效。
5. 人工编辑的 `precheck` 直接通过。待保存内容的结构在随后的 `manual_edit` 步校验。结构不合法时失败的是 `manual_edit` 步，任务为 `failed`，旧稿保留。

业务条件：

- 剧本任务只允许自由创作。项目摘要和角色提取要求完整剧本非空。
- 拆分剧集要求剧本非空、参考单集时长为正整数，且剧集上没有其他未结束任务。
- 故事大纲：自由创作要求创作方向非空；剧本模式要求本集剧情非空。不要求项目摘要。
- 展示摘要要求本集剧情非空。
- 镜头表要求故事大纲已生成；人物资料直接取项目角色库。
- 每秒分镜要求镜头表已生成。文本提示词要求本镜每秒分镜已生成。
- 视频要求本镜文本提示词已生成。出镜指定了服装则要求该服装图已生成，否则要求角色图已生成。不是首镜时要求上一镜尾帧已生成。
- 服装图要求该角色定妆图已生成。

## 删除

`precheck` 不满足则任务失败，不删除。

- 角色：被镜头出镜角色、对白 `说话人id`、节点规则或素材库引用时不能删除。
- 服装：是默认服装、被节点规则引用，或素材库仍有引用时不能删除。
- `impact` 记录受影响的镜头视频 id，不改项目。
- `apply` 删除资料。服装删除时，把出镜里的该 `服装id` 换成角色 `默认服装id`，这些镜头视频若为已生成则标为已过期，原因写「引用服装已删除」，再按视频的下游继续传递。

## 运行规则

整个项目同时只执行一个任务。当前任务通过后自动开始下一项。失败、未通过或取消会停下队列，排队任务不自动开始，由面板开始或移除。

面板提交拆分剧集时，若没有其他未结束任务，直接清除暂停并执行；已有排队中的同一拆分则复用。有其他未结束任务时拒绝，不带起其他任务。会话提交和其他普通提交在队列暂停时继续等待。

服务重启把所有排队和进行中的任务结算为 `superseded`，未完成步骤同样作废，已完成步骤和历史终态保留。排队节点恢复快照，已经开始的节点结算为已取消并保留内容。重启清除队列暂停。旧任务不重放，晚到结果不得覆盖已作废任务。视频任务若重启时正在运行，作废原因要说明远端视频可能仍在运行。用户取消视频时同样只停止本地等待。

任务失败或未通过后，剩余步骤作废。重新生成创建新任务。文本结构不合法、接口报错、审核协议错误为 `failed`，不替换旧内容。镜头表若最终修订后仍仅因整集总时长超出允许范围而失败，最后一次结构有效的生成结果写入正式 `镜头[]`，节点同时保存 `failed` 状态和校验原因；面板展示这份正式内容。自审最终未通过为 `rejected`，节点保存有效失败稿。剧本不是节点，审核未通过不写回剧本。媒体文件必须实际可读且通过解码后才算通过。远端提交成功不等于视频已生成，远端任务 id 保存在步骤结果。
