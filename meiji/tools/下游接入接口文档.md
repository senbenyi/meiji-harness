## 1. 接入约定

### 1.1 地址与鉴权

公网接入地址：`http://43.154.247.11`。

所有 `/v1/*` 请求必须携带：

```http
Authorization: Bearer YOUR_GATEWAY_API_KEY
```

使用服务方分配的**网关 API 密钥**。除 `/health` 外，不支持匿名访问。密钥不放在 URL 或 JSON 请求体中。

curl 示例统一先设置：

```bash
export GATEWAY_URL='http://43.154.247.11'
export GATEWAY_API_KEY='YOUR_GATEWAY_API_KEY'
```

`GATEWAY_URL` 不包含 `/v1`，末尾不加 `/`。使用 OpenAI 风格客户端的 `base_url` 时，一般填写 `http://43.154.247.11/v1`，是否自动追加 `/v1` 以客户端实现为准。

### 1.2 编码与返回值

| 项目 | 约定 |
|---|---|
| JSON 请求 | `Content-Type: application/json`，UTF-8 |
| 文件上传 | `multipart/form-data`；curl 用 `-F` 自动生成 Content-Type 和 boundary |
| 普通结果 | JSON；时间戳为 Unix 秒 |
| 流式文本 | SSE：`Content-Type: text/event-stream` |
| 文件/视频下载 | 二进制响应，不是 JSON |
| 标识符 | 文件 `file_...`，视频任务 `video_...`；原样保存并传回 |
| 资源归属 | 文件和视频任务按 API 密钥隔离；同一公司的不同密钥也不能默认互读 |
| 示例内容 | 示例 ID、文本、时间戳和用量为说明值，不能当作真实资源使用 |

### 1.3 当前模型与能力

| 模型 ID | 主要用途 | 接口 |
|---|---|---|
| `elysium-chat` | 文本对话、流式回复、函数调用 | `/v1/chat/completions`、`/v1/responses` |
| `elysium-image` | 文生图、单参考图生成 | `/v1/images/generations` |
| `elysium-video` | 文生视频、首尾帧、多参考图、视频/音频参考 | `/v1/videos` |

模型是否存在以 `GET /v1/models` 返回为准。模型列表不包含能力描述，不表示任意模型都能调用所有生成接口。后续新增模型可能有不同参数限制，本文媒体限制对应上述当前模型。

## 2. 接口总表

| 方法 | 路径 | 用途 | 成功响应 |
|---|---|---|---|
| GET | `/health` | 网关存活检查，无需鉴权 | 200 JSON |
| GET | `/v1/models` | 查询模型 ID | 200 JSON |
| POST | `/v1/chat/completions` | 文本聊天 | JSON 或 SSE |
| POST | `/v1/responses` | Responses 文本/函数调用 | JSON 或 SSE |
| POST | `/v1/images/generations` | 同步图片生成 | 200 JSON，包含 Base64 |
| POST | `/v1/files` | 上传一个文件 | 200 JSON，包含 URL |
| GET | `/v1/files/{id}/content` | 下载上传的原始文件 | 200 二进制；Range 可返回 206 |
| DELETE | `/v1/files/{id}` | 删除上传文件 | 200 JSON |
| POST | `/v1/videos` | 提交一个异步视频任务 | 200 JSON，包含任务 ID |
| GET | `/v1/videos/{id}` | 查询视频任务状态 | 200 JSON |
| GET | `/v1/videos/{id}/content` | 下载已完成的视频 | 二进制；Range 支持依赖产物服务 |

目前没有批量上传、文件列表、文件元数据查询、视频列表、视频取消或删除接口。

## 5. 聊天 Chat Completions

**POST `/v1/chat/completions`**。

### 5.1 请求参数

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `model` | string | 是 | `elysium-chat` |
| `messages` | array | 是 | 对话消息；基础用法为 `role` 和字符串 `content` |
| `stream` | boolean | 否 | 建议明确传 `false` 或 `true` |
| `stream_options` | object | 否 | 流式用量可传 `{"include_usage":true}` |
| `temperature`、`top_p` | number | 否 | 转交模型服务；范围和支持情况由模型服务决定 |
| `max_tokens` | integer | 否 | 输出长度参数，转交模型服务，不由网关设定统一上限 |
| `tools`、`tool_choice` | array / string 或 object | 否 | 函数工具声明和选择，转交模型服务；由调用方执行工具 |

其他聊天参数按上游支持情况处理，不保证所有 OpenAI 字段均可用。基础文本消息使用 `system`、`user`、`assistant`；工具结果使用 `tool` 角色及相应 `tool_call_id`。不要把上传文件 URL 当作已支持的聊天附件；该读取能力目前只接通到视频素材字段。

测试期聊天上下文窗口为 **262,144 token（输入与输出合计，包含模板/工具等开销）**。服务默认不额外限制输出 token；显式 `max_tokens`（Responses 使用 `max_output_tokens`）仍按请求生效。超过总窗口会报错，应给输出预留空间。

聊天与 Responses 已取消网关原先 10 分钟的总响应时限，代理等待预算为 24 小时；长输入预填充可能长时间没有正文。下游 SDK、调用方代理和下面示例的 `--max-time` 都有各自时限，长请求须相应提高；流式不会扩大模型上下文。

### 5.2 非流式示例

```bash
curl -sS --fail-with-body --max-time 600 "$GATEWAY_URL/v1/chat/completions" \
  -H "Authorization: Bearer $GATEWAY_API_KEY" \
  -H 'Content-Type: application/json' \
  --data-raw '{
    "model":"elysium-chat",
    "messages":[
      {"role":"system","content":"请简洁地用中文回答。"},
      {"role":"user","content":"介绍一下海边日落。"}
    ],
    "stream":false
  }'
```

典型响应结构如下；额外字段随模型服务变化：

```json
{
  "id":"chatcmpl_example",
  "object":"chat.completion",
  "model":"elysium-chat",
  "choices":[
    {"index":0,"message":{"role":"assistant","content":"夕阳映红海面，浪花轻拍沙滩。"},"finish_reason":"stop"}
  ],
  "usage":{"prompt_tokens":30,"completion_tokens":20,"total_tokens":50}
}
```

文本读取 `choices[0].message.content`。函数调用时检查 `choices[].message.tool_calls`，不要假设每次都有文本。

### 5.3 流式示例

```bash
curl -N -sS --fail-with-body --max-time 600 "$GATEWAY_URL/v1/chat/completions" \
  -H "Authorization: Bearer $GATEWAY_API_KEY" \
  -H 'Content-Type: application/json' \
  --data-raw '{"model":"elysium-chat","messages":[{"role":"user","content":"介绍一下海边日落。"}],"stream":true,"stream_options":{"include_usage":true}}'
```

SSE 典型片段：

```text
data: {"model":"elysium-chat","choices":[{"index":0,"delta":{"content":"夕阳"}}]}

data: {"model":"elysium-chat","choices":[{"index":0,"delta":{"content":"映红海面。"}}]}

data: [DONE]
```

按 SSE 事件解析，拼接 `choices[].delta.content`；工具调用增量需按对应字段组装。不要按 TCP 数据包切割 JSON。明确请求 `include_usage` 时，可能收到 `choices: []` 的用量事件；客户端应能处理。未请求用量时，网关隐藏自己为计量额外请求的纯用量事件。

## 6. Responses

**POST `/v1/responses`**。适合使用 Responses 协议的调用方。

### 6.1 请求参数

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `model` | string | 是 | `elysium-chat` |
| `input` | string / array | 是 | 输入文本，或历史消息、函数调用和函数结果列表 |
| `instructions` | string | 否 | 本轮指令 |
| `stream` | boolean | 否 | 明确设置是否使用 SSE |
| `store` | boolean | 建议 | 固定传 `false`；本接入方式不依赖服务端保存历史 |
| `tools` | array | 否 | 函数声明，见下例 |
| `tool_choice`、`max_output_tokens` 等 | 按模型服务约定 | 否 | 透传参数，不保证全部字段受支持 |

当前无 Responses 保存、按 ID 查询、删除、后台任务或服务端会话管理。不要依赖 `previous_response_id` 接续历史；调用方自行携带历史。没有 OpenAI 托管的搜索、文件检索等内置工具。

### 6.2 普通调用与返回

```bash
curl -sS --fail-with-body --max-time 600 "$GATEWAY_URL/v1/responses" \
  -H "Authorization: Bearer $GATEWAY_API_KEY" \
  -H 'Content-Type: application/json' \
  --data-raw '{"model":"elysium-chat","instructions":"使用中文回答。","input":"介绍一下海边日落。","stream":false,"store":false}'
```

典型结果：

```json
{
  "id":"resp_example",
  "object":"response",
  "model":"elysium-chat",
  "status":"completed",
  "output":[
    {"type":"message","role":"assistant","content":[{"type":"output_text","text":"夕阳映红海面。"}]}
  ],
  "usage":{"input_tokens":20,"output_tokens":10,"total_tokens":30}
}
```

遍历 `output` 中 `type: message` 的项目，再读取 `content` 内 `type: output_text` 的 `text`；原始 JSON 不保证有顶层 `output_text`。

### 6.3 流式与函数调用

流式请求将 `stream` 改为 `true`，curl 增加 `-N`。保留上游 SSE `event:` 和 `data:`；事件可能包含 `response.output_text.delta`、`response.output_item.done`、`response.completed`。按事件类型处理，不要按 Chat Completions 的 `choices` 结构解析 Responses。

函数调用请求示例：

```bash
curl -sS --fail-with-body "$GATEWAY_URL/v1/responses" \
  -H "Authorization: Bearer $GATEWAY_API_KEY" \
  -H 'Content-Type: application/json' \
  --data-raw '{
    "model":"elysium-chat",
    "input":[{"role":"user","content":"查询北京天气"}],
    "store":false,
    "stream":false,
    "tools":[{
      "type":"function",
      "name":"weather",
      "description":"查询城市天气",
      "parameters":{"type":"object","properties":{"city":{"type":"string"}},"required":["city"]}
    }]
  }'
```

模型可能返回以下 `output` 项；`arguments` 是需要再次解析的 JSON 字符串：

```json
{"type":"function_call","id":"fc_example","call_id":"call_example","name":"weather","arguments":"{\"city\":\"北京\"}","status":"completed"}
```

调用方执行函数后，下一轮 `input` 携带原历史、实际返回的函数调用项以及匹配 `call_id` 的结果，例如：

```json
{
  "model":"elysium-chat",
  "store":false,
  "stream":false,
  "input":[
    {"role":"user","content":"查询北京天气"},
    {"type":"function_call","id":"fc_example","call_id":"call_example","name":"weather","arguments":"{\"city\":\"北京\"}","status":"completed"},
    {"type":"function_call_output","call_id":"call_example","output":"北京，晴，25℃"}
  ]
}
```

示例调用 ID 必须替换为本轮真实返回的值。若继续允许模型调用函数，应在后续请求中同时提供所需的 `tools`。

## 7. 图片生成

**POST `/v1/images/generations`**。同步接口，收到结果前连接可能持续较长时间。

### 7.1 请求参数

| 字段 | 类型 | 必填 | 默认/限制 |
|---|---|---|---|
| `model` | string | 是 | `elysium-image` |
| `prompt` | string | 是 | 非空描述 |
| `n` | integer | 否 | 只支持生成一张；建议固定 `1`，不支持批量出图 |
| `size` | string | 否 | `宽x高`，如 `1024x1024`；宽高为正数、8 的倍数，各不超过 2048；省略或 `auto` 使用质量档默认值 |
| `quality` | string | 否 | `fast`、`regular`、`high`，默认 `regular` |
| `seed` | integer | 否 | 0–4294967295，默认 666；参考图编辑内部噪声由图片内容和此值共同确定 |
| `image` | string | 否 | 单张参考图，data URL 或裸 Base64；**当前不支持上传返回的文件 URL** |

质量别名：`low → fast`，`medium/standard → regular`，`hd → high`，`auto → regular`。

| quality | 未指定 size 时的尺寸 |
|---|---|
| fast | 640×960 |
| regular | 832×1216 |
| high | 1024×1536 |

仅上述字段构成当前支持的图片参数契约。不要使用 `reference_images`、`response_format: "url"` 或 `stream` 期待切换行为；当前图片接口不提供多参考图、URL 输出或图片流式返回。

当前图片模型为 Qwen-Image-2.1 UC INT8，支持直接输入中文。参考图编辑使用确定性内容派生 seed，避免与原图生成噪声重复；相同图片字节和请求 seed 可复现，data URL 与裸 Base64 等价。更换参考图会改变内部噪声，显式 seed 不等于 ComfyUI 编辑节点的原始 seed。

### 7.2 curl 与结果

```bash
curl -sS --fail-with-body --max-time 600 "$GATEWAY_URL/v1/images/generations" \
  -H "Authorization: Bearer $GATEWAY_API_KEY" \
  -H 'Content-Type: application/json' \
  --data-raw '{"model":"elysium-image","prompt":"A lighthouse on a rocky coast at sunset","n":1,"size":"1024x1024","quality":"regular","seed":42}' \
  -o image-response.json
```

```json
{
  "created":1800000000,
  "data":[{"b64_json":"BASE64_IMAGE_BYTES"}]
}
```

`data[0].b64_json` 是纯 Base64，不包含 `data:image/...;base64,` 前缀。解码得到图片；例如：

```bash
python3 - <<'PY'
import base64, json
from pathlib import Path
result = json.loads(Path('image-response.json').read_text())
Path('image.png').write_bytes(base64.b64decode(result['data'][0]['b64_json']))
PY
```

参考图生成时增加 `image`，例如 `"image":"data:image/png;base64,..."`，其中省略号必须换成真实编码内容。若希望下游完全不处理 Base64，当前已经满足视频素材上传路径，但尚未满足图片生成输入/输出的这一要求。

## 8. 文件上传、下载、删除

文件存储与模型能力分开：允许保存通用文件，不表示任何生成模型都支持该格式。

### 8.1 上传一个文件

**POST `/v1/files`**，`multipart/form-data`。

| 表单字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `file` | binary file | 是 | 恰好一个文件，带非空文件名；内容不能为空 |

当前不接受 `files[]`、重复 `file` 或额外 `purpose` 字段。上传多个文件需逐个调用，可以在客户端控制并发。此接口不是 OpenAI Files API 的全字段实现。

```bash
curl -sS --fail-with-body --max-time 600 "$GATEWAY_URL/v1/files" \
  -H "Authorization: Bearer $GATEWAY_API_KEY" \
  -F 'file=@/绝对路径/reference.jpg' \
  -o upload-response.json
```

成功 **HTTP 200**：

```json
{
  "id":"file_0123456789abcdef0123456789abcdef",
  "object":"file",
  "url":"http://43.154.247.11/v1/files/file_0123456789abcdef0123456789abcdef/content",
  "filename":"reference.jpg",
  "bytes":12345,
  "content_type":"image/jpeg",
  "created_at":1800000000
}
```

| 返回字段 | 含义 |
|---|---|
| `id` | 网关文件 ID，删除时使用 |
| `object` | 固定 `file` |
| `url` | 完整引用地址，提交生成时原样使用 |
| `filename` | 文件名，不包含客户端目录 |
| `bytes` | 实际文件字节数 |
| `content_type` | 网关根据文件内容嗅探的 MIME，未知格式可能为 `application/octet-stream` |
| `created_at` | 上传记录创建时间，Unix 秒 |

文件持久化保存，重启后仍可使用；当前没有自动过期时间。删除前可多次引用。不要自行修改返回 URL 的主机、路径、查询参数或追加密钥；当前只接受网关自身返回的规范 URL，不能传任意公网/内网 URL 或本地文件路径。

上传成功仅代表文件已保存；具体媒体类型、完整性、时长和生成组合在生成接口进一步校验。`content_type` 为 `application/octet-stream` 时不一定是无效素材，例如没有 ID3 标签的 MP3；参考音频接口会继续检查实际媒体内容。

### 8.2 下载原始文件

**GET `/v1/files/{id}/content`**，使用上传时的同一密钥。

```bash
FILE_ID='替换为上传返回的id'
curl -sS --fail-with-body "$GATEWAY_URL/v1/files/$FILE_ID/content" \
  -H "Authorization: Bearer $GATEWAY_API_KEY" \
  -o original-file
```

返回原始二进制内容，包含 `Content-Type`、附件形式的 `Content-Disposition`、`X-Content-Type-Options: nosniff`、`Cache-Control: private, no-store`。

支持 `Range: bytes=0-1023`，有效范围返回 206，无效范围可能返回 416。文件不存在、已删除或不属于当前密钥均返回 404。URL 无匿名访问权限，不能直接作为无需请求头的公开图片链接。

### 8.3 删除文件

**DELETE `/v1/files/{id}`**。

```bash
curl -sS --fail-with-body -X DELETE "$GATEWAY_URL/v1/files/$FILE_ID" \
  -H "Authorization: Bearer $GATEWAY_API_KEY"
```

```json
{"id":"file_0123456789abcdef0123456789abcdef","object":"file","deleted":true}
```

删除后新请求不能再下载或引用；重复删除返回 404。已提交到上游的生成任务不会因此取消，已打开的读取也可能继续完成。建议等相关提交请求完成后再删除其素材。

## 9. 视频生成与多文件输入

**POST `/v1/videos`**，JSON 请求，返回一个异步任务。

### 9.1 完整字段表

| 字段 | 类型 | 必填 | 默认/用途 |
|---|---|---|---|
| `model` | string | 是 | `elysium-video` |
| `prompt` | string | 是 | 非空生成描述 |
| `seconds` | string / number | 否 | 1–15，默认 5；建议使用字符串，如 `"4"`；支持范围内的小数 |
| `quality` | string | 否 | `fast/regular/high`，默认 `regular`；别名同图片接口 |
| `seed` | integer | 否 | 非负 uint64，最大 18446744073709551615；不传时随机；JS 调用方优先使用不超过 9007199254740991 的整数，避免精度损失 |
| `input_reference` | string | 否 | 首帧图片：上传 URL、图片 data URL 或裸 Base64 |
| `last_frame` | string | 否 | 尾帧图片：上传 URL、图片 data URL 或裸 Base64；可单独使用 |
| `reference_images` | string[] | 否 | 最多 9 张图片；每项为上传 URL 或图片 data URL |
| `reference_videos` | string[] | 否 | 最多 3 段 MP4；每项为上传 URL 或 `data:video/mp4;base64,...` |
| `reference_audios` | string[] | 否 | 最多 3 段独立 WAV/MP3；每项为上传 URL 或对应音频 data URL |

当前视频模型拒绝未知字段。不要添加 `size`、`fps`、`n`、`stream`、`image`、`files` 等未列字段；每次创建一个视频任务。

### 9.2 输入模式和组合限制

| 模式 | 填写字段 |
|---|---|
| 文生视频 | 不填任何素材字段 |
| 首帧图生视频 | `input_reference` |
| 尾帧约束 | `last_frame` |
| 首尾帧 | `input_reference` + `last_frame` |
| 多图参考 | `reference_images` |
| 视频参考 | `reference_videos` |
| 音频参考 | `reference_audios` |
| 混合参考 | 三个 `reference_*` 列表中的任意组合 |

- 首帧/尾帧模式与三个参考列表**不能混用**。
- 三个参考列表可混合：图片≤9、视频≤3、独立音频≤3，合计≤12 个文件。
- 视频自带音轨不额外占“12 个文件”名额，但会参与声音参考。
- 各字段可混合使用上传 URL 和 data URL；参考列表不接受裸 Base64。
- 一次上传一个文件，不限制一次生成只用一个文件。

### 9.3 格式、时长与分辨率

| 素材 | 支持与限制 |
|---|---|
| 图片 | PNG、JPEG、WebP；检查真实内容；当前单张像素数不超过 16777216 |
| 参考视频 | MP4；每段 2–15 秒，参考视频总时长≤15 秒；每段不能长于实际生成帧时长 |
| 独立音频 | WAV、MP3；每段 2–15 秒，独立音频总时长≤15 秒 |
| data URL MIME | 图片 `image/png`、`image/jpeg`、`image/webp`；视频 `video/mp4`；音频建议 `audio/wav`、`audio/mpeg` |

| quality | 输出宽×高 | 帧率 |
|---|---|---|
| fast | 384×512 | 24 fps |
| regular | 576×768 | 24 fps |
| high | 864×1184 | 24 fps |

`seconds` 是请求时长，不保证成品恰好等长。生成帧数按模型的 `17k+5` 帧规则向上对齐；例如请求 4 秒得到 107 帧，约 4.458 秒。响应中的 `seconds` 记录请求/计量时长，不是下载文件的实测时长。

参考视频会先转换为 24 fps，再向下对齐有效帧数，最多舍弃约 0.67 秒尾部；音轨同步处理。请预留这一变化，不能依赖参考片段最后一帧必然保留。

### 9.4 多素材提示词

按对应数组顺序使用 `<Picture 1>`、`<Picture 2>`、`<Video 1>`、`<Audio 1>` 等引用，编号从 1 开始，包含尖括号。

Audio 编号先包含有声参考视频的音轨，再包含独立音频。例如一段有声参考视频和一段独立音频，独立音频对应 `<Audio 2>`。参考声音会影响生成，不表示原音轨直接复制或承诺精准复刻。

## 10. 视频查询与下载

### 10.1 查询任务

**GET `/v1/videos/{id}`**。

```bash
TASK_ID='替换为返回的视频任务id'
curl -sS --fail-with-body "$GATEWAY_URL/v1/videos/$TASK_ID" \
  -H "Authorization: Bearer $GATEWAY_API_KEY"
```

返回结构与提交结果一致：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 网关视频任务 ID |
| `object` | string | 固定 `video` |
| `model` | string | 对外模型 ID |
| `status` | string | 见下表 |
| `created_at` | integer | Unix 秒 |
| `size` | string | 输出 `宽x高`；提交结果待恢复时可能为空字符串 |
| `seconds` | string | 请求/计量时长；提交结果待恢复时可能暂为 `"0"` |
| `error` | object | 有错误时出现，包含 `message` |

| status | 调用方处理 |
|---|---|
| queued | 已排队或提交回执待恢复，继续查询 |
| in_progress | 尚未完成，继续查询；不提供精确完成百分比 |
| completed | 可以调用内容下载接口 |
| failed | 终止查询，读取 `error.message` |

失败任务查询仍返回 **HTTP 200**，需检查 JSON `status`：

```json
{
  "id":"video_0123456789abcdef0123456789abcdef",
  "object":"video",
  "model":"elysium-video",
  "status":"failed",
  "created_at":1800000000,
  "size":"384x512",
  "seconds":"4",
  "error":{"message":"remote task failed"}
}
```

任务不存在或属于其他密钥返回 404。建议每 3–5 秒查询一次，按业务设置等待期限。停止轮询或断开客户端不等于取消已提交的任务。

### 10.2 下载视频

**GET `/v1/videos/{id}/content`**，仅在 `status=completed` 后调用。

```bash
curl -sS --fail-with-body --max-time 600 "$GATEWAY_URL/v1/videos/$TASK_ID/content" \
  -H "Authorization: Bearer $GATEWAY_API_KEY" \
  -o result.mp4
```

返回视频二进制。未完成时返回 **409**，不是视频文件。`Range` 会转发给产物服务：上游返回 206 时透传分段内容；上游拒绝范围并返回 416 时，保留 416 及上游提供的 `Content-Range`，调用方应修正范围或移除 Range 后完整下载。上游未采用 Range 时也可能返回完整内容 200。下载重试无需重新提交生成。

## 11. 完整示例：上传多图并生成视频

此 Bash 示例依赖 curl 与 Python 3，仅用 Python 读取/编码 JSON，不对素材做 Base64。先将两个路径改为真实图片路径。

```bash
set -euo pipefail
export GATEWAY_URL='http://43.154.247.11'
export GATEWAY_API_KEY='YOUR_GATEWAY_API_KEY'

curl -sS --fail-with-body --max-time 600 "$GATEWAY_URL/v1/files" \
  -H "Authorization: Bearer $GATEWAY_API_KEY" \
  -F 'file=@/绝对路径/person.jpg' -o person-upload.json

curl -sS --fail-with-body --max-time 600 "$GATEWAY_URL/v1/files" \
  -H "Authorization: Bearer $GATEWAY_API_KEY" \
  -F 'file=@/绝对路径/scene.jpg' -o scene-upload.json

python3 - <<'PY' > video-request.json
import json
from pathlib import Path
urls = [json.loads(Path(name).read_text())['url']
        for name in ('person-upload.json', 'scene-upload.json')]
print(json.dumps({
    'model': 'elysium-video',
    'prompt': '保持 <Picture 1> 的人物外观，人物在 <Picture 2> 的场景中自然行走',
    'seconds': '5',
    'quality': 'fast',
    'reference_images': urls
}, ensure_ascii=False))
PY

# 只提交一次；超时且未收到 ID 时，不要盲目重跑此 POST。
curl -sS --fail-with-body --max-time 600 "$GATEWAY_URL/v1/videos" \
  -H "Authorization: Bearer $GATEWAY_API_KEY" \
  -H 'Content-Type: application/json' \
  --data-binary @video-request.json -o video-task.json

TASK_ID="$(python3 -c 'import json; print(json.load(open("video-task.json"))["id"])')"
printf '任务 ID：%s\n' "$TASK_ID"

# 最长轮询约 30 分钟；HTTP 请求耗时另计。已有 ID 可仅重复此查询部分。
STATUS='queued'
for ((i=0; i<360; i++)); do
  curl -sS --fail-with-body --max-time 30 "$GATEWAY_URL/v1/videos/$TASK_ID" \
    -H "Authorization: Bearer $GATEWAY_API_KEY" -o video-status.json
  STATUS="$(python3 -c 'import json; print(json.load(open("video-status.json"))["status"])')"
  if [[ "$STATUS" == completed ]]; then
    break
  elif [[ "$STATUS" == failed ]]; then
    cat video-status.json
    exit 1
  fi
  sleep 5
done

if [[ "$STATUS" != completed ]]; then
  printf '等待超时，保留任务 ID 继续查询：%s\n' "$TASK_ID" >&2
  exit 1
fi

curl -sS --fail-with-body --max-time 600 "$GATEWAY_URL/v1/videos/$TASK_ID/content" \
  -H "Authorization: Bearer $GATEWAY_API_KEY" -o result.mp4
```

保存 `person-upload.json`、`scene-upload.json` 和 `video-task.json`，以便后续复用、删除和继续查询。删除素材使用第 8.3 节接口，不会删除视频产物。

## 12. 错误、限额与重试

### 12.1 错误格式

网关处理的错误通常为：

```json
{
  "error":{
    "message":"invalid API key",
    "type":"invalid_request_error"
  }
}
```

| HTTP 状态 | 常见原因 | 处理 |
|---|---|---|
| 400 | JSON/参数非法、缺少字段、素材不匹配、未知视频字段、非法组合、上传表单不符合约定 | 修改输入后重试 |
| 401 | 密钥缺失、无效或已停用 | 检查 Bearer 密钥 |
| 404 | 模型或资源不存在、跨密钥访问、未提供路由 | 检查 ID、模型和密钥 |
| 405 | HTTP 方法不匹配 | 核对方法 |
| 409 | 视频未完成就下载 | 等待 completed |
| 413 | 请求体、上传、处理后单文件或累计素材超限 | 减小内容，核对限额；参考视频转换后也可能变大 |
| 416 | 下载 Range 无效 | 修正范围或完整下载 |
| 502 | 上游连接、生成服务或其他内部转发错误 | 查询已有任务状态，必要时联系服务方 |
| 503 | 视频素材处理依赖或预算未配置等服务不可用 | 联系服务方 |
| 504 | 代理等链路等待超时 | 不等于任务已取消，先核对提交结果 |

网关错误 `type`：小于 500 为 `invalid_request_error`，其他为 `upstream_error`。未匹配路由、下载范围错误或 nginx 拒绝可能返回纯文本/HTML，客户端需先检查 HTTP 状态和 Content-Type，不能始终假设错误体为 JSON。

流式响应开始后发生错误，可能体现为连接中断而非新的 JSON 错误。应结合终止事件、响应状态和连接错误判断是否完整。

### 12.2 当前配置限额

| 项目 | 当前值 |
|---|---|
| JSON 请求体 | 64 MiB，包含所有 Base64 和 JSON 开销 |
| 文件上传请求 | 64 MiB，包含 multipart 开销，因此文件本身应略小于 64 MiB |
| 单次视频原始素材合计 | 256 MiB，URL 文件和内联解码数据累计 |
| 单次视频处理后素材合计 | 256 MiB |
| 单个处理后素材上传 | 100 MiB；上游 ComfyUI 限制，原始文件较小也可能在视频转换后超过此值并返回 413 |
| 文件自动到期 | 未提供；持久保存，按需删除 |
| 视频提交处理预算 | 当前配置 8 分钟；不等于完整生成耗时上限 |
| 同步/流式上游传输时限 | 当前配置 10 分钟；客户端也需设置相应超时 |
| 异常提交恢复等待 | 当前恢复阈值约 9 分钟，实际状态更新还受后台查询影响 |

限额可能由服务方调整。上传 URL 可避免 Base64 约三分之一的编码膨胀，但不会绕过文件大小、素材数量、媒体时长或模型能力限制。

原始上传的 64 MiB、处理后单文件的 100 MiB 和原始/处理后各自累计的 256 MiB 分别校验，同时生效；不能将累计预算当作单文件限额。

### 12.3 重试约定

- 没有公开的 `Idempotency-Key` 去重契约。重新 POST 生成请求可能创建新任务或产生新用量。
- 已有视频 ID：只查询、下载该任务，不要为等待超时重新生成。
- 提交超时且没有拿到 ID：结果可能未知，先由服务方核对记录；当前没有按自定义请求 ID 检索任务的公开接口。
- 网关对当前视频渠道的内部提交回执丢失有恢复机制，不代表重复的客户端 POST 会自动合并。
- GET 查询/下载失败可重试；失败文件需结合 HTTP 状态处理，避免把错误 JSON 当成媒体。
- 每次成功上传创建独立文件；不保证相同内容自动去重。重复上传后按需删除多余文件。

## 13. 兼容范围与未提供接口

| 能力 | 当前边界 |
|---|---|
| 文件统一上传 | 图片、视频、音频及其他文件可保存；每次一个文件 |
| 一次生成多个参考文件 | 视频支持，遵守 9 图/3 视频/3 音频/总计 12 的限制 |
| 文件 URL 用于视频 | 支持首帧、尾帧和三类参考列表；须同一网关、同一上传密钥 |
| 文件 URL 用于图片生成 | 尚未接入；`image` 仍使用 Base64/data URL |
| 图片输出 URL | 尚未提供；返回 `b64_json` |
| 图片一次生成多张/多参考图 | 当前不支持；不要套用视频多图字段 |
| 聊天视觉、音频或文档附件 | 未作为本版已验证能力提供；上传文件不自动变成可用聊天附件 |
| 单独语音识别/语音合成 | 没有 `/v1/audio/transcriptions`、`/v1/audio/speech` 等接口；音频目前可作视频参考 |
| 任意外部 URL 下载 | 不支持，只解析本网关返回的文件 URL |
| 公开无鉴权文件链接 | 不支持，暂无签名下载 URL |
| 上传多个文件的一次批量请求 | 不支持，逐个上传获得多个 URL |
| 文件列表/元数据查询、视频取消/删除、生成完成 Webhook | 未提供 |
| Embeddings、向量库、微调、Batch、图片编辑专用路由 | 未提供 |
| Responses 服务端历史与 OpenAI 托管内置工具 | 未提供，使用 `store:false` 并自行携带历史 |
| 浏览器跨域直连 | 未提供统一 CORS 处理；建议业务后端调用 |

本文说明的是接口和当前模型约束，不承诺参考素材必然被精确复制；生成画面、音色和内容效果应在实际模型联调中验收。
