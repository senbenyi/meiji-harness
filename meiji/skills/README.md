# 技能与约束

每个功能只维护一份基础生产规则，统一放在 `task/`，按功能命名 Markdown，不设分类子目录。大纲、人物提取、场景提取分别对应独立文件。不存在独立的通用、审核、修订、共享或指导 skill。

`catalog.js` 登记功能与约束文件；`protocols.js` 保存程序解析需要的输出协议。`load.js` 读取和校验基础正文。基础只读，空正文有效，缺失或未登记文件报错。

每个需要大模型参与的步骤由独立 Model 编排：生成使用生产规则与任务资料；审核使用同一规则验收最新结果；修订增加基稿与本次意见，只修改受影响内容。角色、语言、审核协议、修订边界及输出协议由代码负责。图片、视频步骤保留现有调用能力，不为统一方法增加额外 API 请求。

当前集当前节点的补充 skill 是独立输入，与基础规则一同组装，支持增删改，不跨集继承。任务开始时冻结规则与补充，预览复用真实编排，步骤历史保存实际请求。旧的基础覆盖、本剧审核/修订覆盖不再参与新请求；运行数据不删除。

动作、台词、表情、声音等仍有用的生产要求已归入对应功能基础正文，不再独立注册。参考素材是资料，不是额外基础 skill。

只有 `session/panel.md` 注册给 Harness，供会话 agent 使用，不参与生产提示词组装。

基础约束文件统一以 `-skill.md` 结尾；正文不包含展示用 Markdown 标题、skill 用途或程序实现介绍，只保留可直接编入提示词的执行要求。条件规则使用明确条件句，不能省略适用对象。


约束文件统一使用小写 kebab-case「动作-对象-skill.md」：生成用 `generate-`，提取用 `extract-`。例如 `generate-shot-table-skill.md`、`extract-story-characters-skill.md`。文件名描述主要职责，生成、审核和按意见修订仍由同一 Model 编排并共用基础正文；改名只更新 catalog 和引用，不改变运行时 skill ID。

不创建独立 revise/review 约束文件。单镜修订复用 `generate-shot-table-skill.md`；指定镜头、基稿、意见、编号时长与修改范围由 ShotRevisionModel 编排，审核对照同一生产规则。

图片提示词改写没有独立基础 skill：保留原主体、限定外观修改、禁止编造素材等由 ImagePromptModel 编排。生成、审核、修订不是新增基础文件的理由；仅真实生产功能维护约束正文。

目录职责：`task/` 放具体任务的基础 skill，`session/` 放处理会话的 skill。三个 JS 文件保留：`catalog.js` 管理功能登记及文件映射，`load.js` 管理读取、校验和会话注册数据，`protocols.js` 管理输出协议；它们是代码，不是额外的 skill 正文。

基础正文只描述生产约束；根据哪些资料做什么，由 Model 的本次任务描述。上下文、修改意见和输出结构由 Model 分区组装，不能在基础规则中重复模式编排或接口说明。
