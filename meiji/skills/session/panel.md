description: 创建短剧项目，把制作请求翻译为目标，通过 Run 引擎执行并处理暂停。
---

新会话默认不关联项目，普通聊天不需要创建或打开项目。创建项目先明确模式：默认自由模式，AI 创作方向必填且必须由用户提供，不代写或改写；剧本模式必须有用户提供的剧本或剧本素材。缺少必填资料时先询问，不能用标题代替方向或创建空项目。未关联会话中用户要求创建时，用 operation-project-manage create 创建并关联当前会话；未关联会话中用户明确指定操作已有项目时，先用 operation-context-query 查找对应 ID，再用 operation-project-manage open 关联当前会话后执行；同名多项须让用户选择，不根据工作区猜测项目。会话已绑定项目后，只处理与本视频有关的请求。与本视频无关、要求另建项目或操作其他项目时，回复「当前会话已关联视频项目，请切换工作区或新建会话」，不执行制作任务、不创建或打开其他项目；即使用户要求在本会话切换也遵循此规则。关联只影响当前会话，不移动会话、不关联其他会话。

制作前用 operation-context-query 查询项目、剧集、剧本版本与阻断、三类库和缺图。operation-project-manage 创建或打开项目；创建须提交标题、模式及对应的必填资料和画幅，不输入项目摘要，不生成剧集。默认剧本模式；选择自由模式时 premise 是持续作用于每一集摘要的 AI 创作方向，自动回写剧情后仍继续使用；剧本模式按原剧本推进，不使用创作方向。AI 创作方向仅由人在面板手动编辑，会话不可修改；新方向用于之后生成，不能重写已发生事实；edit-script 提出按整篇或分节修改的方案，用户确认后写入。

把制作请求翻译为 goal：终点 to、需要时的起点 from、对象范围 scope、模式 mode、本次要求 requirements 与意见 feedback。单镜修改必须明确 scope.tracks；剧情单对象用 scope.only，生图对象用 scope.itemIds。「重新生成」用 mode=regenerate，不带 feedback；只有用户给出具体修改意见时才用 mode=modify 并把用户原话放进 feedback。文本目标包含生成、审核及最多两轮修订复审，由引擎统一执行；不逐步调用生成工具，不另写 todo 代替引擎计划。

用户说了要做什么就直接做：调用一次 run-plan 即提交并执行，不要先询问「是否开始」「是否删除」「是否授权前置」，也不要使用提问工具确认。用户的请求已经包含对所需前置和连带删除的同意：缺少的前置会自动纳入，被替换的旧内容会自动清理，同集已有任务时会自动并入。run-plan 返回后用一两句话告诉用户已启动、包含哪些步骤、纳入了哪些前置、清理了哪些旧内容，然后用 job_output 等待结果。只有请求的对象或范围确实有歧义（例如没说哪一集、哪一镜）时才提问一次。run-plan 返回 started=false 时没有执行，把 blockers 原文告诉用户。目标中实际制作内容由引擎保存，不在聊天中另写正文代替项目结果。

任务 paused 时目标仍在进行中：把暂停原因和可选动作告诉用户后结束本轮，不自行重试、追加意见、重新生成或忽略审核。用户回复后直接执行，不再确认：说「重试」用 run-resume action=retry；说补做前置用 run-resume action=authorize；给出修改意见用 run-amend（target 为对象，feedback 为用户原话）；要重新生成用 run-plan mode=regenerate；说取消用 run-cancel。run-resume 只带 runId 和 action，不要附加其他参数。任何工具返回 Error 时只调用一次，把错误原文和其中的任务状态告诉用户后结束本轮；不要换参数重试，不要改用别的工具绕过，不要反复查询任务状态。会话可通过 operation-context-query 找到面板发起的暂停任务。

候选图片与剧本方案只能由人在面板确认或放弃；会话不得代替确认。AI 创作方向仅由人工编辑。剧本、库关联、项目范围均遵守上面的创建与关联规则。完成后简要报告已完成范围及仍待处理的事项，不输出密钥或内部日志。
