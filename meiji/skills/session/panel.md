# 短剧制作工作流

普通聊天无需关联项目。先用 meiji-context-query 查询当前会话；仅在用户明确要求创建或操作项目时调用 meiji-project-command。自由创作方向须由用户提供，剧本模式必须提供完整剧本。已绑定会话不切换其他项目，提示使用新会话。

把用户的明确制作请求转换为 meiji-task-command：单节点使用 submit，业务与 target_id 明确；首次生成 action=generate，重新生成 action=regenerate，用户提供修改意见时带 opinion；节点未通过原因由服务端带入新任务。不使用首次生成要求、隐式补上游、并入、暂停或恢复。前置不足会生成 failed 任务，向用户报告实际原因，不自主创建修复或前置任务。

剧本本身是节点（business_type=script-review，target_id 为项目 id，状态在 script.node_state）。剧本创作方式创建项目后自动提交一次审核，评估剧情连续性与拍摄适配；未通过时原因是给剧本的修改意见。action=revise（需带意见）按意见改写剧本后再审核，最多两轮；regenerate 重新审核；override 人工放行；不支持 manual-edit。拆分剧集与提取人物（project-characters）要求剧本节点已生成且未过期，否则前置检查失败并说明原因。剧本创作方式下剧集由拆分得到：对项目提交 business_type=script-split（target_id 为项目 id；无剧集用 generate，已有剧集用 regenerate），按项目的参考单集时长把剧本原文按段落切分到各集「剧情」，不改写内容；参考单集时长在面板设置。剧本创作方式不能用 add-episode，自由创作才逐集新增。剧集「故事大纲」是 outline 节点，「剧情」是本集剧本原文，展示摘要根据剧情生成。

文本任务由服务完成前置检查和生成，再按该节点做程序审核和 AI 审核；没有的那一步跳过。两种审核共用该节点的修订次数，用尽后才进入未通过，最后候选和原因保存在正式节点。时长误差只由程序审核判定，不在生成提示词增加容差规则。图片不调用审核；当前视频、尾帧分别执行，视频时长审核与类型分支留待镜头级对齐。

成片组 episode-film 当前按镜头顺序执行每秒分镜、分镜提示词、视频、尾帧。submit-group 的 action=generate 补齐无效节点，action=regenerate 重跑所选镜头；带意见修改时用 regenerate 并传 opinion。生成单镜成片时同时传 episode_id 和 shot_id，整集不传 shot_id。单镜组不代生成其他镜头；同集成片队列结束且本集全部视频有效时，最后完成组追加唯一合片。合片只做前置检查和生成，不调用 AI 审核。视频完成后记录每镜实测时长，剧集实际时长为当前镜头实测值之和，参考时长不改。每秒分镜已并入成片，无独立标签；episode-seconds 仅保留单项及历史契约。继续使用 continue-group 从原组停点创建新组，已完成任务不重做；仅合片失败时继续只创建合片。旧任务终态不可复活。队列失败、未通过或取消后停止，用户通过面板开始或移除排队项。

用 query 读取任务及步骤结果，区分 completed、rejected、failed 和 cancelled。产物由服务保存，不在聊天中另写正文替代项目结果。人工编辑、人工放行、删除角色/服装以及排队控制只在面板执行。

面板操作和任务结果只在会话中显示提示卡，不进入对话、不唤醒你；面板已展示节点状态，你不需要为这些提示回复。用户询问时用 query 读取实际结果再回答。不得编造 meiji 不存在的项目状态或操作（如「标记完成」）。只有用户在会话中请求的操作被阻断、必须由用户选择才能继续时（例如删除被引用的角色，需要选择改删服装或重新生成图片），才使用提问工具；其余情况不主动提问，不提议后续操作，不自主创建修复、重试或继续任务。会话关闭不取消业务任务；只有 cancel 命令才取消。业务已受理而通知失败时，仍使用返回的 task/group id 查询，不重复提交。

项目人物提取只写人物及服装资料，不自动生成图片。生成人物全部服装定妆照使用 type=submit-costumes、target_id=人物 c_ id、action=generate 或 regenerate；单独建立任务组，按服装顺序逐套生成，无服装生成一张未绑定图片。第一套作为默认人物角色图，可选用户参考；后续以第一套为唯一参考。独立 character-image 生成已移除。单套 costume-image 使用服装 co_ id，无服装使用人物 c_ id；空服装不补写资料。已有未绑定历史图及任务记录保留；新增服装后历史图只读。
