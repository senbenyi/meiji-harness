# 文本提示词编排与独立节点

## 调用路径

业务阶段 → 提示词编排 → 流程调度 → 单次请求 worker → 模型网关。

- `server/prompts/story-prompts.js`：集中编排剧集摘要、剧情整包（大纲/人物/场景）与单类卡片任务。
- `server/prompts/shot-prompts.js`：集中编排镜头表、单镜修改、单镜与整集每秒指令；文本分镜也使用同一请求结构。
- `server/prompts/text-prompts.js`：共用的生成、审核和修订构建函数，负责 Skill、语言、输出协议、自定义要求及修改意见。审核请求重新包含任务依据、适用生成规范和当前待审正文，不依赖生成请求的会话。
- `server/prompts/continuity-review.js`：构建跨镜连续性审核资料。
- `server/generate/text-workflow.js`：`runGenerationNode` 和 `runReviewNode` 可独立调用。`runTextWorkflow` 负责节点顺序、最多一次自动修订及结果保存。
- `server/generate/text-request.js`：`runTextRequest` 每次只发送一个已经编排完整的请求，处理日志、取消信号和 API 异常；不加载 Skill、不追加提示词、不触发审核。
- `server/generate/chat.js`、`gateway.js`：模型请求及网关传输。

旧的 `askSkill`、`runTextGeneration` 接口及对应旧 worker、旧拼接文件已移除；调用方统一使用新接口。

## 请求结构

编排函数返回 `{ skill, system, user, json }`，worker 接收该对象与请求选项。测试注入的 `request` 同样接收一个包含完整提示词的对象。

最终 API 请求恰含两条消息：

```json
{
  "messages": [
    { "role": "system", "content": "Skill 正文、项目语言和本阶段输出协议" },
    { "role": "user", "content": "本次目标、输入、上下文、补充要求及本阶段材料" }
  ]
}
```

生成和修订剧情资料采用 JSON 输出；镜头表、每秒指令采用自由文本；审核采用 PASS/FAIL。输出格式不改变请求的两条消息结构。密钥、运行锁和日志不进入提示词。

## 节点与保存

生成节点请求一次 API，校验并保存生成稿后结束。独立审核节点再请求一次 API，保存该稿的审核结论。明确内容 FAIL 时，流程层以最新失败稿、失败原因和原人工意见调度一次修订，再独立复审。第二次失败保存并停止；接口异常、空结果、格式错误和无效审核协议不触发自动内容修订。

剧情整包、人物卡、场景卡、镜头表与单镜每秒指令都在自审前保存生成稿。整集每秒指令先保存完整结果，再逐镜审核和定向修订。自审或修订 API 异常保留最新已保存稿；生成 API 尚未产生有效稿时保留原结果。未完成审核不标记通过。

保存沿用 `revisionStore` 的依赖检查，防止正在审核的旧版本覆盖已变更资料。节点运行期间保留操作归属和新输入的人工意见，最终结论对应当前保存版本。

人工编辑仅调用审核节点。图片、铅笔分镜和视频生成不进入该文本自动修订流程。

## 验证

`tests/prompt-nodes.test.js` 覆盖五类任务的两条消息、完整审核依据、基稿隔离、独立节点执行和审核 API 失败后的保存。现有测试覆盖修订上限、语言、自定义 Skill、整集每秒指令、连续性、日志及取消。

运行 `npm test`。测试使用模拟 API；部分旧测试依赖默认模型配置中存在非空测试密钥，验证时可在临时副本中配置假密钥，不使用真实密钥或付费生成。

### 剧情输入范围

剧情重新生成只接收项目总背景、剧本、本集时长/集数/风格/画幅和前后集衔接约束，不接收本集旧摘要、旧剧情或历史意见。人工修订接收本集摘要、完整剧情基稿与修改意见。审核仅接收本次任务上下文与最新待审稿；自动修订以最新失败稿为基准。时长协议由阶段技能负责，通用语言技能不规定大纲秒数；保存、审核请求及重试次数由流程层负责。
