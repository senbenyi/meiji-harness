# 生成链路契约验收

## 根因与范围
模型的 markdown 字符串只经过局部语法解析，角色/场景引用、镜头覆盖、目标镜头范围没有统一验收；模型输入丢失场次信息，单镜重写仍收到全集；流水线对失败盲目重复，直到逐镜生产时才检查场景。此前以项目数据修补代替链路验证，未解决这些断点。

## 实施
- documents.js：统一 validateScript 校验角色、场景、说话人、覆盖、提示词与镜头时长。
- planning.js：保留场次边界；单镜只传目标行；把失败输出和具体错误传回模型纠正一次，通过后保存。
- service.js：保存与生产共用校验；总览修改不能破坏已有剧本引用；整集、项目生产预检；修改镜头清除受影响的旧任务关联并增加 take，保留无变化镜头及媒体。
- database/managers/projects.js：在保存队列内检查文档版本与更新关联状态，避免陈旧保存覆盖新文档；无变化状态不重写。
- pipeline.js：生产前补齐文档，先校验所有文档再创建定妆/视频任务；内容纠正耗尽后明确暂停，不无条件重抽同样输入。
- episode.js、projects.js：不完整分镜回到生成入口，暂停任务显示继续生产。
- script.md、storyboard.md：明确实体名称、场次范围、目标镜头及 correction 的输入约定；同步运行 Skill。

## 验证
- 全量 211/211 通过；最后流水线改动后专项 3/3 通过。
- 覆盖错误场景、纠正成功、两次失败不保存、重复场景名称的场界、单镜起始行错误、空首帧、上游引用删除、旧任务失效与未修改镜头保留。
- 构建打包重启通过，差异检查通过。
- 户外爬山 2 集 27 镜通过只读生产预检；本轮没有改写真实项目剧情或重新抽样视频。

## 边界
模型仍可能输出不合格内容；本次保证它在进入生产前得到具体纠正或明确失败，不保证画面质量与完整成片成功。文档和 state 各自原子写入，不构成跨文件崩溃事务。
