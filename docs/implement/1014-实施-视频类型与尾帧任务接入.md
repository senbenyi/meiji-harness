## 改了什么

- `shared/video-inputs.js`：按有效绑定选择类型，有角色多模态、无人后镜首尾帧、无人首镜文生。缺图不降级。
- `shared/node-definitions.js`、`server/handlers/video-prompt-handler.js`、runtime 注册器：新增 first-last-frame/multimodal 程序节点，复用已有 Model 和 HTTP 编排函数，不调用文本模型。项目保存编排参数和素材本地地址，发送时读取为 Base64。
- `server/flow/tasks/task-service.js`：视频轮到执行时才物化适用编排，事务内插到本组视频之前，组内序号和排队顺序同时调整；同镜视频/编排冲突检查。继续时不复制旧类型分支。补齐启动前取消守卫，不复活已取消排队任务。
- `server/data/sqlite-store.js`：动态插入编排时先腾开移动任务的组内序号，避免逐行 upsert 撞唯一约束；没有为本视频阶段新增 schema 或迁移。
- `precheck.js`、`shared/node-dependencies.js`：按类型验证和传播。首尾帧才依赖前尾帧，多模态才依赖绑定图片；计划时长、画幅、三段正文、实际素材及编排纳入 hash。
- `shared/task-plan.js`、`task-labels.js`、`server/handlers/media-handler.js`、`extract-video-tail.js`：视频 generate/revise 后执行可见 apply 步骤，校验文件、实测、截帧并校验图片；截帧支持取消。人工导入走同样后处理，无需文本节点、不调用模型。
- `node-state.js`、`handler-registry.js`、`content.js`：视频实测必须4–15秒且与计划相差不超过±5秒，最多两次修订，只带对应审核意见。视频和尾帧一起提交；审核耗尽保存最后配对为 rejected、保留原成功hash；文件失败或取消保留旧配对及实测值，不自动再次付费生成。
- `task_contract.js`：独立tail不再接受新命令，保留产物字段和历史只读定位。
- client 任务面板、镜头详情、历史：显示适用程序编排、视频类型；按钮使用执行/重新编排；尾帧放入视频卡内只读，保留查看历史，不再独立生成或导入。
- 同步制作工作流、step_model、视频与程序编排节点文档、README、开发指引和总计划进度。
