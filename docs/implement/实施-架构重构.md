## 阶段 6+7：任务队列、重启取消、ffmpeg 检查

### 已修改文件
- `meiji/server/flow/queue.js` — 新增全局队列：按 text / image / video 限制并发（默认 4 / 2 / 2），空出名额直接交给最早排队的任务，排队中可取消
- `meiji/config/models.json` — 新增 `concurrency`（可在 `models.local.json` 覆盖；面板保存设置不会裁剪它，因为从部署配置读取）
- `meiji/server/flow/tasks.js` — 任务经队列执行，排队时 `queued: true` 并写会话日志；服务关闭以「取消」中止（复用用户停止路径，已提交的远端任务会收到取消请求）
- `meiji/server/flow/interrupt.js` — 启动时遗留任务一律取消：节点标记失败并写明「服务重启，任务已取消，请重新发起」，视频内容标为终态；对已提交的远端视频尽力发送取消请求，失败如实写入节点
- `meiji/index.js` — 启动时传入远端取消函数；检查 ffmpeg，缺失时记录警告
- `meiji/server/generate/ffmpeg.js` — 新增 ffmpeg 可用性检查
- `meiji/server/data/task-records.js` — 重启遗留任务与中止任务一律记为 `cancelled`
- `meiji/server/flow/operations/films.js` — 删除续查分支（`queueOrResumeFilm` → `submitFilm`），重试一律重新提交
- `meiji/server/generate/gateway.js`、`server/data/self-checks.js`、`operations/finish.js` — 删除「暂停」（`TASK_PAUSED`）分支：已无任何代码产生该原因；已有数据中的「暂停」状态仍可正常显示
- `meiji/tools/session-task-control-tool.js` — 工具说明改为「服务重启会取消进行中任务（cancelled）」
- 测试：新增 `queue.test.js`（6 项）；改写 4 项旧的暂停语义测试；`tasks.test.js` 提交后立即取消的断言改为「以已取消结束，若已执行则收到中止信号」

### 过程中发现并修复
- 排队任务在读取并发上限期间被取消会永久挂起（中止事件已错过）：读取后先检查，排队时若已中止立即拒绝。
- 新测试中模拟的等待函数不响应中止，导致后续测试被连带取消；此后每次验证同时检查「cancelled」计数。

### 与计划的偏差
- 队列不持久化：重启一律取消（用户决定），无需恢复。
- 未在面板状态栏提示缺少 ffmpeg：启动时记录警告，使用时各处已报「本机未安装 FFmpeg」。

### 验证
- `npm test` 315 通过 / 0 失败 / 0 取消（连续 3 次）；`index.js` 可正常加载。→ AC-6 通过
