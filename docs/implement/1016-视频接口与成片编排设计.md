# 视频接口与成片编排设计

本设计以 `meiji-server/src/server.js` 和 `src/minimax-video.js` 的当前实现为准；调用参数原始依据为 [服务端接口文档](../../../meiji-server/docs/调用接口文档.md#14-minimax-h3-视频生成)。Harness 的视频编排是程序处理，不新增一次文本模型生成或审核。

## 请求与职责

`成片组 → 每秒分镜 → 文生视频提示词 → 确定视频类型 → 必要的素材编排 → 视频请求 → 下载 → 画幅归一化 → 实测时长/截尾帧 → 程序审核 → 保存视频和尾帧`。

Harness 发送 `POST http://127.0.0.1:11435/v1/videos/generations`。地址来自现有 `textBaseUrl`，模型固定 `MiniMax-H3`，本机占位鉴权为 `Bearer ollama`。MiniMax 密钥只在服务端配置，不发送给面板或保存在项目中。

服务端提交 MiniMax 并轮询，完成才返回 `task_id/status/url`。Harness 不再对服务端调用旧的 `/videos/{id}` 和 `/content`；拿到成功结果后立即下载 URL，再走本地视频实测与尾帧处理。HTTP 详情分别记录生成和下载阶段。

## 三种方式的输入

| 项目 | 文生 | 首尾帧 | 多模态 |
|---|---|---|---|
| `mode` | `文生` | `首尾帧` | `多模态` |
| `prompt` | 已审核三段正文 | 开场首帧约束＋已审核三段 | 人物/场景图片对应关系＋已审核三段 |
| `duration` | 本镜整数参考时长，4–15秒 | 同左 | 同左 |
| `resolution` | `768P` | `768P` | `768P` |
| `ratio` | 项目比例，`16:9`或`9:16` | `adaptive`，由首帧确定 | 项目比例 |
| 首帧 | 无 | 上一镜有效尾帧→`first_frame` | 无 |
| 目标尾帧 | 无 | 当前成片流程不提供；不发送`last_frame` | 无 |
| 参考图 | 无 | 无 | 本镜人物定妆照及绑定场景参考图→`images`，合计1–9张 |
| 参考视频、音频 | 无 | 无 | 服务端支持，当前Harness没有业务素材来源，本轮不构造 |
| 程序编排节点 | 跳过 | `first-last-frame` | `multimodal` |

项目横版`1344x768`映射请求`16:9`，竖版`768x1344`映射`9:16`。`resolution`和`ratio`是生成参数；下载后仍按项目像素归一化成片，实测时长独立保存。

沿用当前选型：有卡内出镜角色则多模态；无人且明确连续接拍、同场景同状态时才用前镜尾帧；其余绑定场景用多模态，未绑定普通地点用文生。缺图时明确阻断，不悄悄改成别的模式。不具名群演不要求角色卡或定妆照。类型在视频执行前确定，先插入对应程序编排任务，再执行视频。

## 首尾帧编排

1. 本镜文生视频三段必须有效，上一镜尾帧必须有效且文件可读取。
2. 程序读取上一镜 `last_frame.address`，校验图片，发送前转成 image data URL，作为本镜 `first_frame`。
3. 正文前只增加“首帧为上一镜尾帧，用作本镜0秒开场，随后按已审核分镜执行”的约束，不重写台词、时间线和声音。
4. **输入的目标尾帧 `last_frame` 与视频完成后截取的输出尾帧是两个概念。** 当前没有独立生成本镜结束画面的节点，不能把上一镜尾帧再同时当作本镜目标尾帧，也不能把尚未生成的视频尾帧当输入。
5. 服务端及Harness节点直接接口支持显式可选目标尾帧，但成片面板当前没有该素材来源；实际成片请求只带首帧。

示例，素材内容仅作占位：

```json
{
  "model": "MiniMax-H3",
  "mode": "首尾帧",
  "prompt": "首帧为上一镜的尾帧，用作本镜0秒的开场画面。后续按已审核分镜执行。\n\nintegrated_multimodal_description:\n本镜已审核画面正文\n\noverall_soundscape:\n本镜已审核声景\n\nnon_diegetic_music:\nN/A",
  "duration": 8,
  "resolution": "768P",
  "ratio": "adaptive",
  "first_frame": "data:image/png;base64,..."
}
```

首帧模式不带`images/videos/audios`。未指定目标尾帧时整个`last_frame`字段省略，不传空字符串。

## 多模态编排

1. 按本镜 `on_screen_characters` 数组顺序取图；有`costume_id`时使用该套服装定妆照；人物无服装资料时使用空`costume_id`的定妆照。
2. 每张图对应一个人物及本镜服装。直接复用文生提示词的全项目稳定 `speaker_tag`，例如 `(S2)`；图片编号从1开始，不能把“第1张图”误当成“(S1)”人物。
3. 正文前明确对应关系，例如：

```text
参考图对应关系（按images数组顺序，从1开始）：
第1张参考图："乙"，说话人标记(S2)，服装："蓝色短外套"。
第2张参考图："甲"，说话人标记(S1)，服装："灰色长衫"。
只用对应图片保持各人物身份、面相、体型和本镜服装，不交换身份，不增加出镜人物；参考图不是本镜首帧或尾帧。

integrated_multimodal_description:
……(S2)说<d>别走。我还有话说。</d>……
overall_soundscape:
……
non_diegetic_music:
N/A
```

一句台词完整放在一个`<d>`中。相同人物连续说多句可整体放一个标签，或在完整句之间分开。映射说明不改变已审核三段原文，也不增加旁白或画外人物出镜。

4. 请求使用`images`数组，顺序与上面的图编号相同，不发送`first_frame/last_frame`。人物图片是身份与服装参考；绑定场景另外附一张空间参考图并定义独立Subject，保留固定布局和本镜状态。不把定妆照背景带入场景，不把参考图强制当开场画面。
5. 不凭提示词里一句“声音跟随参考音频”就发送不存在的音频。服务端的参考音视频能力需在Harness有明确素材和绑定后再接入。

```json
{
  "model": "MiniMax-H3",
  "mode": "多模态",
  "prompt": "参考图对应关系……\n\nintegrated_multimodal_description:\n……\n\noverall_soundscape:\n……\n\nnon_diegetic_music:\nN/A",
  "duration": 8,
  "resolution": "768P",
  "ratio": "9:16",
  "images": ["data:image/png;base64,...", "data:image/png;base64,..."]
}
```

## 保存与实际发送

保留现有项目Model和字段，避免迁移已生成项目：

| 项目内部字段 | 含义/最终HTTP字段 |
|---|---|
| `model` | 固定`MiniMax-H3` |
| `prompt` | 已保存编排正文，视频实际发送采用它；先逐段核对与当前已审核正文一致，再发送，不再重新拼一份忽略编排 |
| `seconds` | 兼容的本镜时长快照；HTTP发送`duration`，始终核对当前镜头参考时长 |
| `size` | 旧内部画幅快照；不能作为新HTTP字段。新HTTP使用`resolution=768P`与项目`ratio` |
| `input_reference` | 上一镜尾帧的本地媒体地址；读文件后发送`first_frame` |
| `reference_images[].address` | 按序保存的定妆照本地地址；读文件后发送`images` |

项目JSON不保存Base64。编排和发送均调用同一`videoPayload`校验：完整提示词最多7000字符（含映射、三段和修订意见）；不截断、提速、改秒数规避上限。手工编辑或上游变更照既有hash规则使编排/视频过期。旧编排内容不自动重写，重新编排时生成新映射。

程序编排零文本模型调用，前置核验/编排失败不发送付费视频。视频修订使用已保存编排正文，在末尾追加本轮意见；共用原有最多两次修订额度。网络失败、服务错误和下载失败不自动重新提交生成。

## 返回、错误和取消

成功必须同时有`status=succeeded`、非空`task_id`和`url`。先下载，确认非空且文件可解码，再归一化、实测、截取并检查尾帧。视频和尾帧成对保存。失败或取消保留旧正式配对。

服务端400参数错误、402余额不足、503缺配置原样保留HTTP状态和原因；非成功状态不下载。生成HTTP详情保留服务响应，下载阶段记录地址的origin/path（不另记录签名查询串）、状态、字节数及错误；下载不携带本机鉴权。

本机服务视频队列独立且并发1。Harness取消通过AbortSignal断开活动请求；服务端停止自身排队、轮询或请求。MiniMax已经受理的任务没有在当前实现中调用远端取消接口，停止本地等待不保证撤销远端生成或费用。当前不添加自动重提交。

## 本次验证与运行条件

- 真实两个项目的运行代码隔离联调：Harness任务→真实meiji-server解析器→MiniMax协议客户端→本地模拟上游→视频下载/归一化/实测/截帧，三种模式完成；模拟上游只替代外部MiniMax，不替代Harness和服务端HTTP代码。
- 本机11435的三种合法请求均到达视频处理器，返回503“未配置MINIMAX_API_KEY”。这是当前真实出片阻碍，不能把模拟联调称为真实MiniMax出片成功。
- 配置位置：`meiji-server/.env`中的`MINIMAX_API_KEY`，配置后重启meiji-server；再做一镜真实生成验收。

场景采用选择性建档，不重要的一次性地点不需要配图；场景图按需生成或人工导入，不自动批量派生。详见[提取场景](../../meiji/dev_docs/dots/剧集-提取场景.md)。
