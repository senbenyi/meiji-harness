# 盒子按需读取执行循环

计划：[1027-计划-盒子按需读取执行循环.md](../plans/1027-计划-盒子按需读取执行循环.md)。

## 结果与修改范围

- 公共`http-client`增加`modelClient.turn`，透传tools/tool_choice、返回经验证的assistant正文/tool_calls。`complete`继续返回文本，媒体接口不变。
- drama新增`node_runtime/box_skills.js`与`box_model_runner.js`。每阶段首轮提供阶段、目标、语言、skill/资料/历史索引和工具；正文按需读取。支持read_skill/read_material/read_contract/read_execution和按阶段限定的submit_candidate或submit_review。
- 剧本优化、故事大纲、场景、团队、人物、分镜六盒子及项目原稿摘要接入。每轮一Step、一份prompt和一次llm-http；阶段内用box_phase_id续接assistant/tool消息。审核新建阶段上下文，不自动继承作者消息。
- 修改必须读最新完整基稿和旧问题；审核必须读完整候选、当前上游依据及上一轮有效问题。大纲原有全篇审核/整轮修订范围skill亦为必读，动态段数和ID由工具按当前候选替换，原始消息测试覆盖。旧问题供重新核实，不能作为新增锁定要求；生成/修改校验后保存并继续独立审核，状态机、重复问题检测及最多3轮内容修订保留。
- 定制base和有效补充规则从Task规则快照作为必读主题提供，优先于默认skill。默认base与原初始化JSON一致时使用拆分主题，不重复注入整份默认规则。没有迁移或覆盖已保存项目。
- 同阶段最多32轮模型请求；候选/审核输出最多2次额外修复，反馈不成为有效审核意见。摘要保留无效提交立即警告、不进行内容审核的语义。网络、存储、取消和保存错误不作为内容修复吞掉。
- 新增工具读取Step不含业务output/review，各Executor只挑选真正已提交的候选，业务报告和用户continue仍沿原任务关联。
- 更新7盒子skill索引、2个动态参数说明、开发入口与开发方向。图片盒子继续实际图片协议；尚无执行器的视频提示词不增加生产入口。
