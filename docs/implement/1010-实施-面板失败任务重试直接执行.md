# 面板失败任务重试直接执行实施记录

## 已修改文件
- `meiji/server/flow/tasks/task-service.js` — 只在同 target 最新任务为失败/未通过/取消/作废（或旧版排队重试且前次失败）时识别面板重试；若没有其他未完成任务，在事务内清除队列暂停并启动；把新重试的 `generate` 按 `regenerate` 处理，复用旧版 queued 重试并纠正其动作。其他未完成任务存在时冲突。
- `meiji/tests/stage04-task-queue.test.js` — 覆盖解析失败后立即新建/执行 regenerate、保留旧失败；旧版 queued 重试复用；其他排队任务冲突；会话提交仍保持暂停。
- `.agents/meiji-dev.md` — 记录面板同节点重试行为与冲突边界。

## 验收标准核对
| AC | 状态 | 验证方式与证据 |
|---|---|---|
| AC-1 | 通过 | TaskService 测试验证 `failed` 旧任务保持终态，新任务改走 `regenerate` 并完成；旧 queued 重试也复用执行 |
| AC-2 | 通过 | 其他目标有 queued 任务时面板重试返回 TASK_CONFLICT，暂停与任务数不变 |
| AC-3 | 通过 | 会话提交保留 queued 与 `queue_stopped=true`；普通提交暂停、拆分专用恢复回归通过 |
