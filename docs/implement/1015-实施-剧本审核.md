# 剧本审核实施记录

## 第二轮调整
用户确认剧本本身是节点，不设独立审核节点：`NODE_DEFINITIONS['script-review'].field = "script"`，状态在 `script.node_state`，结论在 `script.review`；概要页不再另放审核卡，数据状态标签放在剧本标题旁，公共节点 UI 与结论放在剧本信息下方。本机数据库已按第一版升级到 v16（含独立 `script_review`），新增 v17 将其并入剧本并保留状态、原因、依赖指纹与结论。

## 第三轮调整
- 剧本卡片不展示状态标签、版本和审核说明；剧本有无即其数据状态。
- 审核与修改都是剧本节点的任务：审核任务只有 precheck→AI 审核（`{是否通过, 原因}`），未通过不自动修改；未通过原因下方新增「修改」，提交 `revise`：AI 按原因改写剧本→AI 审核，未通过再修改一次（retryRounds 1，共两轮）。写入新剧本时版本递增、记修改历史，项目摘要与角色按 hash 过期。
- 审核结论字段 `script.review` 移除，新增 v18 迁移；本机库（v17，剧本未通过）副本试迁移后保留未通过状态与原因。
- `shared/models/script_review_model.js` 已不再被引用，因连接文件夹不允许删除而保留，需手动删除。

## 验收标准核对
| AC | 状态 | 验证方式与证据 |
|---|---|---|
| AC1 自动提交 | 通过 | stage21「导入剧本自动审核」：创建返回 `script_review_task_id`，任务完成；自由创作不提交 |
| AC2 步骤与结构 | 通过 | 同上，步骤为前置检查 / AI审核剧本连续性与拍摄适配 / 程序审核：判定剧本审核结论 |
| AC3 不适合 → 未通过 | 通过 | stage21：任务 rejected、原因与节点 reason 均为修改意见，模型只调用一次 |
| AC4 缺修改意见 | 通过 | stage21：任务 failed，节点仍为空 |
| AC5 拦截 | 通过 | stage21：未通过时提取剧集/人物任务失败且不调用模型；过期提示重新审核 |
| AC6 人工放行与按钮 | 通过 | stage21：放行后 generated、拦截解除；manual-edit/revise 命令被拒；卡片按钮为 重新审核/人工放行/任务历史 |
| AC7 界面位置 | 通过 | stage21：只有剧本卡片带 `data-business=script-review`，不展示数据状态标签与剧本版本（第三轮：剧本有无即数据状态），节点 UI 在剧本文件名之后；stage07-panel 剧本卡按钮为 重新审核/任务历史 |
| AC8 迁移 | 通过 | stage21：v15 库升级到 v17，旧项目补空节点；早期独立 `script_review` 并入剧本，未通过状态、原因、指纹与修改意见保留；迁移记录 16、17 各一次 |
