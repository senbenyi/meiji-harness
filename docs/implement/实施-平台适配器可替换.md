## 验收标准核对

| AC | 状态 | 验证方式与证据 |
| --- | --- | --- |
| AC-1：业务统一分派 | 通过 | 独立测试适配器记录调用及进程 ID，确认 connect/createClient/buildGraph 在实际 worker 子进程中调用；检查、LLM 配置及工作流来源均命中适配器。原子工具、批次与媒体实际访问本地 HTTP 模拟服务。 |
| AC-2：完整 Runpod 参考实现 | 通过（仓库已有服务流程范围） | 同一端到端场景使用正式 Runpod 模块执行；契约测试验证所有方法；生命周期测试模拟 check/start/重复 start/restart/stop，拒绝外来 PID 和相似但不同端口。 |
| AC-3：独立扩展与缺失隔离 | 通过 | 临时副本仅新增测试 AutoDL 入口，不改核心/前端；实际 HTTP 登记、检查、选择通过。正式未实现 AutoDL 登记返回 409；前端测试验证动态选项及不可用记录。 |
| AC-4：旧任务与批次归属 | 通过 | A 上任务实际失败，默认切 B 后在 A 查询原 prompt 并恢复，无重复提交；新任务实际提交 B；A 批次切 B 后继续在 A 完成第二镜头和参考帧；重复执行完成批次不再提交。相同排队 ID 的取消只影响指定 A。 |
| AC-5：物理删除 Runpod | 通过（本地协议模拟） | 每次复制源码后物理删除 Runpod，构建 lib 并再次断言 Runpod 不存在；导入实际插件入口并注册 HTTP 路由；完成项目创建/读取、服务器检查/切换、真实 worker、恢复、批次、参考帧、媒体代理、LLM 配置及工作流来源。原 Runpod 快照恢复返回 PROVIDER_UNAVAILABLE，其他项目仍可读取。 |
| AC-6：预留与真实环境边界 | 通过 | 测试适配器仅在临时副本生成，不引用或复制 Runpod；真实其他平台保留占位；所有服务器调用使用 loopback HTTP 模拟服务。未改真实存储/服务器配置/凭据，未操作云实例或冻结制作案例。 |

LLM 设置实际应用、重装保留配置与凭据，由 Harness 测试覆盖；删除场景覆盖动态适配器提供 LLM 配置。测试使用模拟模型节点和回执，不将其表述为 GPU 生成、画质或真实平台接入验收。

## 人工待办

本次代码补全无待办。后续接入 AutoDL 等平台时，需实现独立契约、准备实际模型服务，并在真实环境验收连接、生成质量及各自运维行为。

删除 Runpod 不会迁移原 Runpod 上的任务或媒体。切换到已实现且检查通过的其他平台后，新业务可以独立运行；访问仍属于 Runpod 的历史远端资源，需要保留或恢复原适配器。
