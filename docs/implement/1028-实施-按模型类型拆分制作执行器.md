# 按模型类型拆分制作执行器实施记录

## 已修改文件

- `projects/drama/src/production/text_executor.js` — 文本节点的单元准备、生成/独立审核/修订步骤，以及章摘要层级归并、故事相邻段复核。实际文本工具循环仍为model_loop.js。
- `image_executor.js` — 素材需求单元、参考图组合、图片模型调用、立即入库、人工选用条件。
- `video_executor.js` — 分片单元、提示词/对白/声线预检、视频模型调用/下载/技术校验、候选复用与人工选用条件。
- `program_executor.js` — 参考绑定、分片、实际剪辑及分集导出；不调用生成模型。
- `unit_executor.js`、`execution_support.js` — 只共用Task/单元清单、完成单元跳过、文件引用、步骤描述和终态设施；各类型自己决定具体单元、执行步骤和确认条件。错误节点类型/内部步骤在执行前拒绝。
- `executor_registry.js` — 将11个制作节点注册到四类执行器；替代原单个ProductionExecutor总分支文件。
- `service.js`、`project_workspace_service.js` — Service按节点选执行器，公共Task注册的plan/execute使用同一类型分派；项目创建/导入/人工编辑仍走ProjectDocumentExecutor。
- `rules.js`、`model_loop.js`、`text_pipeline.js`、`program_pipeline.js` — 规则读取和执行通用工具独立；从程序管线移出图片/视频模型调用，避免图片执行器依赖文本模型循环。
- `tests/production-executors.test.js` — 错误类型/内部步骤保护、人工保存、各类型模型隔离、图片与视频失败续接、程序后期零模型请求。
- `projects/drama/AGENTS.md`、`docs/开发方向.md`、`docs/项目数据契约.md` — 同步执行器职责。未改变项目Schema、UI、接口、规则内容、Task/Step格式。
