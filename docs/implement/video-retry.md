# 视频任务重试与展示

网络恢复由 `video-execution.js` 在同一个任务内处理：最多退避重试 5 次，间隔为 2、4、8、16、30 秒。准备、提交和查询进度共用预算。中途只更新任务状态，不向模型返回每次网络错误。参数错误、模型执行失败及无法确认的提交结果不会盲目重试；耗尽预算后返回一次失败并要求等待用户恢复。

提交始终经过原有提交日志：有 prompt_id 时查询原任务，提交响应丢失时按 elysium_job_id 核对队列和历史，无法确认时停止，禁止再次 POST。显式恢复一个已确认执行失败的任务可以产生新的远端执行，但保留同一 job_id 和卡片。

生成入口默认关联当前 session 最近的未完成视频，即使模型改变提示词也不会新建。只有用户明确要求另一个视频时才使用 `new_video: true`；该字段不进入工作流参数。会话级启动锁串行化并发生成调用。同一轮恢复调用最多启动一次，后续调用只返回原任务状态。

展示按 job_id 合并同轮结果，并通过 Harness 的前序事件上下文识别跨轮恢复，保留原轮卡片。失败卡片每 30 秒只读查询原任务，以感知后来手动恢复；成功后停止轮询。历史原始工具消息不删除，既有不同 job_id 的视频也不强行合并。后台重试不会增加工具消息。

验证：`pnpm --dir dsh-elysium-tools test`。`video-retry.test.js` 覆盖准备断网、提交响应丢失、查询断网、重试耗尽、取消和并发重复调用；`media-card.test.js` 覆盖同轮/跨轮去重、历史回放以及原卡片恢复。测试不提交真实 GPU 任务。
