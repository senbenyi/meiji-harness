# 节点数据与任务状态分离

对应计划：`docs/plans/1015-计划-节点数据与任务状态分离.md`。

## 实现

- `shared/node-state.js`、`project_contract.js`、`task_contract.js`：当前项目节点只允许 empty/generated/rejected/expired；任务历史的旧执行前快照保持可读。fail_message 保留为空，执行失败原因归任务 end_reason。
- `server/flow/tasks/task-manager.js`：排队、开始、失败、取消不写数据状态，不恢复旧快照覆盖当前数据；仅完成、审核未通过更新数据状态。
- `client/node-task-status.js`、`task-panel.js`、`project-ui.js`：第一排数据状态和按钮，第二排最新任务状态及失败原因，第三排意见输入，第四排非空未通过原因。优先当前关联任务，否则从完整持久化任务数组取 queue_order 最大记录；无记录隐藏第二排。视频内尾帧缺失时允许重新提取。
- `server/data/node-data-state-migration.js`、`sqlite-store.js`、`schema.sql`：schema v15 显式迁移旧 running/failed/cancelled 数据状态。优先保留可恢复的审核/过期原因，其余有内容节点按依赖 hash 判定 generated/expired，无内容为 empty。保留正文、任务历史及终态；更新未结束任务的执行前快照与项目 revision。启动时通过既有镜像路径同步本地 JSON。
- 同步工作流、步骤协议和开发说明，并更新旧状态耦合测试；上轮角色目录精简对应的两个旧断言改为确认不带年龄。
