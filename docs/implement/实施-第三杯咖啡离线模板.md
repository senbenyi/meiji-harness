## 媒体字段与访问约束

职责划分：`assets/local-media.js` 负责本地媒体 schema、登记和文件边界；`assets/catalog.js` 负责可用性摘要；`http/media-routes.js` 负责认证和HTTP流；项目 store 负责引用集合；客户端负责同源展示。

任务结果约定：

```json
{
  "media_kind": "video",
  "local_media_path": "media/third-cup/shots/001.mp4"
}
```

`media_kind` 支持 image、video、file（SRT）。只允许 `media/<集合>/...` 下的受支持扩展名；同一集合的 `manifest.json.files` 必须同时匹配 path、job_id、size_bytes。图片格式支持 PNG/JPEG/WebP，视频 MP4，字幕 SRT。任务状态文件本身不会授权读取未在 manifest 登记的文件。

所有读取仍经 `/plugins/dsh-elysium/media/{status,image,video,download}`，使用页面凭据和 job_id。客户端没有本地路径参数，不返回 file URL。绝对路径、父目录段、编码路径、反斜线和符号链接越界被拒绝；文件必须是普通文件。GET/HEAD、单段 Range、206/416、长度、范围、类型、ETag/If-Range 与附件名均有测试。

本地字段存在时优先使用本地文件；缺失或登记无效时明确报错，不回退失效外网或自动无限重试。只有没有本地字段的旧任务继续使用 HTTP(S) 代理。SHA-256 在安装和验收阶段校验，HTTP读取阶段核对登记、边界、类型和大小，不对每次 Range 重新计算整片哈希。

项目封面支持 `cover_job_id`，锚点通过 source.job_id 请求图片；远端 image_url 旧数据保持兼容。成片及字幕复用原成品组件已有的 job_id 播放和下载逻辑。

## 安装与启动

先安装 Git LFS，并在克隆后执行 `git lfs pull`；MP4通过LFS保存，SRT和JSON普通入库。不存在的锚点图没有配置LFS或伪造占位图片。空目录使用 `.gitkeep`。

```sh
node harness/scripts/install.mjs
node harness/scripts/start.mjs
```

安装在任何复制或依赖安装前验证模板媒体：LFS pointer、缺失实体或哈希不匹配均失败。已知的原始素材缺口会明确提示；现有122份媒体必须全部通过校验。

`storage-template.mjs` 只初始化缺失存储单元：项目、任务、生产记录、媒体集合整目录存在时保留原样；directors.json只在不存在时初始化。不会将仓库测试项目 `1f7712c5` 的删除传播到用户目录。缺失的标准项目可补入已有安装，已有项目内部缺少某个文件也不会擅自补写。用户若要更新已经初始化的标准项目，应先自行备份并明确选择更新范围。

`DSH_HOME` 必须是独立绝对目录，不能是系统根或用户主目录。默认仍为 `~/.dsh`。其他Harness托管配置继续按原方式更新。首次安装依赖获取可能需要网络；安装后的项目浏览无需模型API密钥或外网。

启动不复制存储，不终止其他Harness进程；默认端口由Harness配置决定，脚本读取本次进程的真实监听端口。可通过 `DSH_PORT` 覆盖（0表示系统分配），通过 `DSH_SKIP_TUNNEL=1` 跳过模型隧道，`DSH_NO_OPEN=1` 禁止自动打开浏览器。默认保留Harness自身打开带登录凭据页面的行为；日志由Harness管理，不应公开。
