# Skill 编写规范

- 适用范围：流程 Skill `drama` 与所有导演 Skill `director-*`。
- 标准样例：`drama` 的现行文件（流程 Skill 的完整写法），以及 `director-cad24a59`（甜宠虐恋 · 氛围情感剧，导演 Skill 的写法）。新写或修改 Skill 前先对照样例。
- 位置：运行时 `~/.dsh/storages/elysium/pools/skills/`，仓库模板 `harness/.dsh/storages/elysium/pools/skills/`，两处保持一致。
- 编辑入口：工作台“流程”面板（`drama`）和“导演”面板（`director-*`），全文 Markdown 编辑，失焦或 ⌘S 保存。

## 1. 原则

1. **问题修在 Skill 里，不修在项目里。** 同类问题出现两次，就改 Skill，不要逐个项目手改。
2. **两个包各管一件事。**
   - `drama` 管“写什么、按什么格式写”，所有项目共用。
   - 导演管“什么味道、多大规模”，每种风格一个包。
3. **按步骤同名对齐。** 生成某一步时，系统提示只由下面四部分拼接，没有其他来源：

   ```text
   drama/SKILL.md + drama/steps/<步骤>.md + director/SKILL.md + director/references/<步骤>.md
   ```

   步骤共四个：`project`（立项）、`series`（总览）、`script`（剧本）、`storyboard`（分镜）。
4. **写规则，不写建议。** 用“固定 2 集”，不用“通常 2 集”。一个数值只在一个文件里出现一次。
5. **优先级：人工编辑 > 导演 > `drama`。** 因此 `drama` 不写导演该决定的数值和风格。

## 2. 文件职责

| 文件 | 只写 | 不得写 |
|---|---|---|
| `drama/SKILL.md` | 总则：人工内容优先、名称规则、输出纯 Markdown、代码负责的部分 | 任何步骤的具体格式、风格、数值 |
| `drama/steps/<步骤>.md` | 本步的输入、输出格式（逐字模板）、结构规则；`storyboard.md` 另含视频模型语法 | 集数、时长这类导演决定的数值；风格偏好 |
| 导演 `SKILL.md` | 风格与题材、人物塑造、声音与对白、禁忌、代表作参考；每一步都会读取 | 输出格式、模型语法、集数 |
| 导演 `references/project.md` | 题材范围、立项要求（主角与冲突的写法） | 分集内容 |
| 导演 `references/series.md` | **规模（唯一的集数规则）**、分集结构、角色设定（服装色系、标志物、定妆画风）、场景设定 | 剧本写法、镜头语言 |
| 导演 `references/script.md` | 单集结构、节奏、对白风格、物件与伏笔 | 集数、镜头语言 |
| 导演 `references/storyboard.md` | 镜头语言、单镜时长、光线与色调、视频描述的风格要求 | 模型语法（如时间标记格式、首帧语言），这些写在 `drama/steps/storyboard.md` |

## 3. 各文件标准结构

新建导演时，系统会按下面的结构自动生成 5 个文件；删掉括号里的说明，填入内容即可。

### 导演 `SKILL.md`

```text
---
name: director-xxxxxxxx          （系统生成，勿改）
description: "一句话风格描述"
metadata:
  kind: director
  display_name: "显示名"
  order: 0                        （系统维护）
---

# 显示名
## 风格与题材        （可选题材、核心情绪体验、世界观质感、整体基调）
## 人物塑造          （主角、对手、配角各自的性格与表现方式）
## 声音与对白        （对白长短、音色、环境音；对白写法示例）
## 禁忌              （内容安全与价值观底线）
## 代表作参考（风格参照，不复制情节）
```

### 导演 `references/project.md`

```text
# 导演立项
## 题材范围          （允许的题材列表；立项题材必须落在这里）
## 立项要求          （梗概写什么：主角处境、核心冲突、情绪卖点；不写分集）
```

### 导演 `references/series.md`

```text
# 导演总览
## 规模
- 集数：固定 N 集。            （全项目唯一的集数规则）
- 单集时长：X–Y 秒。
## 分集结构          （每集承担的剧情功能，例如第 1 集完成什么、最后一集落在哪里）
## 角色设定          （服装色系与标志物跨集不变；定妆画风要点）
## 场景设定          （场景数量与复用原则）
```

### 导演 `references/script.md`

```text
# 导演剧本
## 单集结构          （开头 / 中段 / 结尾各做什么）
## 节奏              （信息密度、情绪起伏、甜虐或压抑爆发的交替方式）
## 对白风格          （句长、口语化程度、关键台词写法）
## 物件与伏笔        （承载情绪或反转的物件、跨集复现方式）
```

### 导演 `references/storyboard.md`

```text
# 导演分镜
## 镜头语言          （常用景别、构图、正反打、特写的使用场合）
## 单镜时长          （信息镜头与情绪镜头的时长范围）
## 光线与色调        （不同情绪段的光线与色温）
## 视频描述要求      （视频描述必须写清的风格要素，例如人物距离、情绪细节的时间点）
```

### `drama/steps/<步骤>.md`

```text
# 步骤名
## 目标              （这一步产出什么、好结果的样子）
## 输入              （系统传入的 JSON 字段及用法）
## 输出格式          （逐字模板；解析器依赖它，改之前先确认 documents.js 的解析规则）
## 写作方法          （按顺序的写法与数量、长度建议）
## 质量自查          （输出前逐条检查的清单）
## 不得              （明确禁止的内容）
## 示例              （一份完整可解析的样例，四步示例前后衔接）
```

`drama/SKILL.md` 另含：四步流程表（每步读取什么、产出什么、下一步怎么用）、总则、代码负责的部分、内容底线。

四个步骤的“示例”必须能被解析器通过，并且前后衔接：剧本示例使用总览示例中的角色和场景，分镜示例按剧本示例的行号切分。测试 `flow skill examples always pass the document parsers` 会检查这一点，改示例后运行 `npm test`。

每一步的输入由 `planning.js` 的 `assemble` 决定：

| 步骤 | 输入字段 |
|---|---|
| project | `director`（导演显示名）、`requirements` |
| series | `project`（名称、题材、梗概）、`requirements` |
| script | `series`、`episode`、`previous_last_scene`（上一集最后一场）、`requirements` |
| storyboard | `series`、`episode`、`numbered_lines`（带临时序号的本集剧本行）、`requirements` |

## 4. 自查清单

改完 Skill 后逐条检查：

- [ ] 集数只出现在导演 `references/series.md`，写的是“固定 N 集”，全文没有其他集数暗示（如“前 10 集”“每 5 集”）。
- [ ] 导演文件里没有输出格式和模型语法；`drama` 文件里没有风格偏好和集数、时长数值。
- [ ] 同一条规则只写在一个文件里，两处写法互不矛盾。
- [ ] `drama/steps/*` 的输出模板与解析器一致：总览的字段名、剧本的“场 / 动作 / 音效 / 角色（语气）”、分镜的“从第 N 行｜景别｜运镜｜N 秒｜人物”。
- [ ] 分镜模板写明“人物”，主体放第一位：首帧按第一位角色的定妆图生成，写错就会换人。
- [ ] 改完用一个测试项目重新生成对应步骤，确认结果。
