# 创作工作台体验优化设计

日期：2026-09-12　状态：已据此实施首版；实测结果及验收边界见实施记录。

依据：[问题调查](../research/调研-Harness展示布局与操作效率.md)。执行顺序见[实施计划](../plans/计划-创作工作台体验优化.md)。

## 1. 目标与范围

让用户快速找到素材、定位镜头、检查画面、修改内容、审看成片。以《第三杯咖啡》4 锚点、6 幕、120 镜作为主验收样本。

设计原则：内容优先；浏览时保持简洁；编辑时信息完整；每次操作都有可见结果；只加载当前需要的内容。

保留素材 → 项目 → 交付的现有业务结构和项目数据。此次不新增生成模式、自动剪辑、多人协作、时间线编辑器或新插件，不调整部署拓扑、登录和模型服务。媒体继续使用服务器 URL，下载仍由用户点击浏览器链接触发。

## 2. 页面结构：全屏工作台与聊天切换

将“素材与项目面板”入口改为“创作工作台”。打开后使用插件拥有的全屏工作区，默认进入上次所在位置；首次进入项目列表。固定顶栏提供“项目”“素材”和“返回聊天”。返回聊天保留工作台位置，重新进入可继续。

工作台打开期间暂停其余插件媒体播放。宿主聊天无需卸载；插件不通过修改宿主私有 DOM、隐藏其内部节点或全局 body 右边距实现布局。全屏层管理焦点，关闭后返回触发入口。优先复用宿主公开挂载能力；若没有合适能力，使用现有插件自有挂载根作为独立全屏层。

首版只提供一种工作台布局，不同时维护旧窄面板和新工作台两套制作界面。

### 尺寸与适配

按工作台可用宽度判断布局，不按设备名称判断。

| 可用宽度 | 布局 |
| --- | --- |
| ≥1280px | 幕导航 176px；中间至少 480px、自适应；详情 360px |
| 960–1279px | 幕导航缩为工具栏下拉；镜头列表 + 320px 详情 |
| <960px | 单列列表；点镜头进入详情页，明确“返回镜头列表”；保留原滚动位置 |

素材网格用 `minmax(180px, 1fr)`，窄屏最小卡宽降为 150px。390px 宽保持可操作，无水平页面滚动。首版不做拖拽调整列宽，减少布局和状态复杂度。

## 3. 视觉规则

- 沿用 Harness 明暗主题变量；工作台内部设统一样式变量并限定作用域。
- 正文字号 14px、辅助文字 12px、项目标题 20px；正文行高 1.5。字体继承系统中文字体。
- 间距使用 4/8/12/16/24px；控件高 36px，触屏主要点击区域至少 44px。
- 中性色背景、一级卡片底色、细分隔线；只用一个强调色表达选中与主要动作。避免多层描边、彩色装饰和重复卡片嵌套。
- 完成/运行/失败同时使用文字与图标，不能只靠颜色区分。选中行有底色和清楚焦点框。
- 一块区域最多一个主要按钮；删除、解除关联等放入“更多操作”。图标按钮必须有名称与提示。
- 动效仅用于开关或反馈，时长约 120–160ms；尊重减少动态效果设置。不做持续闪烁或自动播放。

## 4. 各页面设计

### 4.1 项目列表

顶部为“项目”、搜索、主按钮“新建项目”；点击新建后才打开标题与档次表单。

项目卡显示：已有锚点图作为封面、项目名、档次、完成数/镜数、更新时间、“继续制作”。没有可用图时显示项目首字与中性背景，不自动生成封面。删除放入更多菜单并保留确认。

继续制作优先恢复上次子页/镜头；没有历史时，有镜头进入分镜，只有锚点进入锚点，空项目展示“添加锚点”入口。项目摘要接口可增加从现有数据推导的封面字段，避免为每张项目卡获取完整项目。

### 4.2 素材库

固定工具栏：关键词搜索、类型、档次、结果数、清空筛选；按时间倒序。每页 30 条，固定分页；更改条件回到第一页。搜索覆盖服务端全部可匹配素材，不能只搜索当前加载页。

卡片包含预览图、标题（两行内）、媒体类型、时长或尺寸、时间。规格不再承担标题职责。标题优先使用已有标题，其次提示词摘要，缺失时显示“视频/图片 · 任务短 ID”；完整提示词只在详情展示。服务端只返回需要的展示字段，不返回整份调试输入。

点击卡片打开单素材预览；详情中提供“下载”和“用作项目锚点”。不使用含义模糊的“→项目”，也不自动推断素材属于某个项目。

缩略图有统一视觉容器，图片按比例居中；竖屏卡可用 3:4，横屏用 4:3，外部卡片总高保持一致。完整预览保留原始比例、不裁切。视频无服务器封面时展示媒体图标、时长与标题；点击才创建播放器。不得用 30 个 video 获取首帧，也不把角色参考图冒充视频实际画面。

### 4.3 锚点

以图片卡片展示角色/场景名称和一行描述。点选后打开详情：大图、名称、描述；角色 ID 和服务器 URL 放入“技术详情”。技术详情有明确标签，仍保留现有可编辑能力。

主操作“选择参考素材”合并原来重复的两个按钮。选择器固定在视口中，标题为“为「林」选择参考素材”，内部复用素材筛选与分页。默认图片类型；如现有业务允许视频锚点，保留类型切换并标明将引用的视频素材，不擅自移除能力。

选中只高亮，点击“使用此素材”才写入；提交中禁用重复提交。失败保留选择和上下文；成功关闭并更新原卡片。取消不改项目。弹层固定标题/底部按钮，内部列表独立滚动。

### 4.4 分镜

默认紧凑列表，每行约 56px。列为：镜号、小图或占位、角色、动作摘要、状态。幕导航显示完成数/镜数；“全部”按原镜头顺序显示，每页 30 镜。

搜索支持镜号、动作、字幕；筛选支持角色与状态。输入 `120` 可定位第 120 镜；若不在当前幕/筛选结果，提供“在全部镜头中定位”，避免误报不存在。

选中行后右侧显示当前镜头播放器、动作、字幕、角色、备注。角色完整描述按需展开，不在每行重复。只读详情是默认态；“编辑”进入带标签的表单，底部固定“取消/保存”。保存成功退出编辑，失败保留草稿及重试入口。

“上一镜/下一镜”沿当前筛选结果移动并同步分页；到边界禁用。键盘上下移动选中项、Enter 打开详情；输入框内不拦截这些按键。

操作命名：

| 可见操作 | 实际行为 |
| --- | --- |
| 标记待重拍 | 保留旧产物，记录待重拍状态；不声称已开始生成 |
| 解除素材关联 | 确认后清空关联任务并回到待生成；准确替代原“替换”文案 |
| 上移/下移 | 当前幕内调整顺序；有筛选时禁用并解释需清空筛选 |
| 移除镜头 | 明确显示目标并确认后移除 |

首版保留现有生成与关联逻辑，不新增“点击立即生成”或尚无服务端支持的镜头替换流程。添加镜头、添加幕、修改幕标题和删除幕均保留，移到对应幕菜单或明确入口。

### 4.5 交付

选择成片后展示一个大播放器；旁边显示名称、时长、分辨率（有数据才显示）、文件大小和下载按钮。字幕列在附属文件区域。已有交付顺序保持可识别；无明确关联字段时不猜测哪份字幕属于哪个版本。

字幕使用 B/KB/MB 自适应单位。首版提供字幕下载和信息，不承诺浏览器直接加载 SRT 字幕轨道；格式转换属于后续独立工作。

零交付显示“尚无交付物”和当前项目镜头完成情况，不新增无后端支持的合成按钮。

## 5. 交互与状态规则

### 状态保存

工作台顶层持有选中项目、子页、镜头、筛选、页码及列表滚动位置。持久化仅存必要的导航 ID、布局偏好；筛选文本、未保存草稿和媒体凭据不写 localStorage。当前会话内保留筛选和位置，刷新后恢复有效导航 ID。

关闭工作台可卸载列表/播放器以释放资源，界面状态仍保留。不能通过将全部页面永久挂载来“保留位置”。

现有镜头模型没有保证稳定的独立 ID：首版使用项目 ID + 幕/镜位置维护选择；本客户端排序后同步更新位置，删除后选相邻镜。刷新后校验位置和已知任务关联，不一致就回列表，避免编辑错镜。不得把可能变化的位置当作永久业务标识。

### 编辑与反馈

一次编辑一个对象，显式保存，允许取消。切换镜头、子页或退出工作台时如有草稿，显示“保存并继续 / 放弃修改 / 继续编辑”；保存失败不导航。提交时串行处理项目写入，成功后使用服务端返回项目刷新视图。

当前项目 API 未承诺多客户端版本冲突保护；本次不宣传实时协作。验收写操作用项目副本，避免多人同时改同一项目。

列表首次加载显示固定尺寸骨架；刷新保留原内容并显示更新提示。区分“无素材”“无匹配结果”“读取失败”。预览区分加载中、未关联、无产物、失败，失败可重试；不能将加载中显示成无产物。

操作错误显示在当前区域；成功使用短提示或对象内状态，不弹阻断对话框。弹层支持 Escape、Tab 焦点约束、关闭后恢复焦点；有未保存草稿时遵循草稿规则。

## 6. 性能与数据策略

### 首版选型

采用分页和局部渲染，复用现有 React 与模块加载器，不引入 UI 框架、全局状态库或虚拟列表依赖。120 镜数据可以一次取回，但仅渲染当页 30 行；只有一套详情表单。

插件工作台内完整播放器最多 1 个；打开素材选择预览时卸载背后的播放器，关闭后按需恢复。切换路由、关闭工作台、页面隐藏时暂停播放；列表图片懒加载并预留尺寸，避免布局跳动。

仅选中镜头查询产物状态；不因渲染列表发起逐镜查询。缓存相同 job 的展示结果并合并在途请求；用户刷新、关联变化或失败重试时失效。当前可见运行任务可低频查询，页面隐藏时暂停；已完成任务不持续轮询。

素材查询输入防抖 250ms，切换筛选取消旧请求，并以请求序号防止旧结果覆盖新结果。缓存键包括查询、档次、类型、页码；设条目数量上限，更新素材后失效。

### 已知接口限制与最小扩展

当前 `/media/list` 已返回 total、profile、media_kind 和媒体存在标志，但没有用于卡片的标题/提示词摘要/封面字段；当前实现每次扫描任务状态文件。

必需扩展：服务端支持有长度限制的 `q`，在分页前过滤；白名单输出可用标题/提示词摘要。先核对真实任务元数据来源，旧数据缺失用短 ID 回退，不回填或伪造历史提示词。

暂不增加视频封面生成服务或持久化索引。若实测文件扫描成为瓶颈，再评估有界内存摘要缓存及明确失效方式；不能只加 TTL 而让新生成素材长期不可见。没有瓶颈证据不增加缓存层。

### 验收预算

以下是目标，不是已达到的测试结果。浏览器以 100% 缩放、1440×900 和同一网络做前后对照。

| 项目 | 首版目标 |
| --- | --- |
| 分镜行 DOM | 每页最多 30 行；默认编辑表单 0 套，编辑时 1 套 |
| 播放器 | 工作台最多 1 个；素材网格 0 个 |
| 120 镜首次进入 | 1 次项目详情查询；未选中镜头不请求逐镜状态 |
| 素材查询 | 每次确定条件只保留 1 个有效列表请求 |
| 已缓存界面切换 | 浏览器交互延迟 p95 ≤100ms；媒体加载不计入该指标 |
| 连续滚动 | 录制 10 秒，不出现可归因于列表渲染的 >100ms 主线程任务 |
| 内存释放 | 反复进入/退出 10 次，播放器、监听器和未结束请求不累积 |
| 网络首屏 | 记录冷/热加载各 5 次的中位数与 p95，分开报告 API、图片和视频；不可用一次观感代替测量 |

若未达标，阶段记录中写明实测值、原因与修复项，不直接降低指标宣布通过。

## 7. 验收场景

1. 打开《第三杯咖啡》，桌面同时看到至少 10 镜；导航、状态与当前镜头清晰。
2. 搜索 120 并选中，两个操作内进入目标镜头；切换素材再回来仍在该位置。
3. 为“林”选择参考素材：弹层立即可见，筛选与预览后明确提交，取消不写数据。
4. 编辑一个镜头后保存、模拟失败重试、取消；检查刷新后的内容与提示一致。
5. 筛选无结果、读取失败、媒体不可用均显示不同反馈，错误不导致整页空白。
6. 交付页审看六分钟成片并点击下载，字幕大小正确；真实下载由人工完成。
7. 1440×900、1366×768、390×844，以及键盘、200% 缩放检查；小屏不依赖悬停操作。

调查发现的聊天卡片“预览加载失败”另行复核。工作台验收不能代替聊天媒体链路验收；不在尚未确定根因时扩大本次设计范围。
