# 多服务器平台扩展设计（修订）

日期：2026-09-15。职责：定义可替换的平台模块与公共业务边界。替代原先“所有 provider 仅预留”的错误范围。

依据：[调研与 AC](../research/调研-平台适配器可替换.md)。用户要求直接执行调研、计划、实施；其他平台暂只保留目录。

## 依赖方向

```text
项目 / 聊天工具 / worker / 批次 / 媒体 / 设置 / 启动脚本
                         ↓
                 servers/runtime.js
                         ↓ 按快照 provider 动态加载
                 providers/<id>/index.js
                         ↓
       通用 HTTP、SSH、ComfyUI、H3 工作流、Qwen 协议
```

公共业务和公共协议都不能导入 Runpod 模块。适配器之间不能相互依赖。平台实现可以复用公共协议和模型能力，无须复制项目与生产编排。

## 模块与统一契约

`servers/provider-loader.js` 扫描 provider 目录，只有存在 `index.js` 且通过契约校验的模块可调用。不使用包含所有平台的静态 import 表。只有占位目录可见为未接入；内部依赖损坏不能被当作成功或悄悄使用 manual。

每个适配器导出 `default` 对象：

| 成员 | 职责 |
| --- | --- |
| `apiVersion: 1`、`id`、`label`、`services` | 契约版本、身份及支持的服务 |
| `validate(backend)` | 校验本平台支持的服务、部署约定及连接配置 |
| `connect(backend)` | 建立/校验连接；可复用公共 SSH 所有权检查 |
| `check(backend)` | 检查目标服务与模型；不提交生成 |
| `createClient(backend, options)` | 返回 ComfyUI 协议客户端，承接提交、查询、等待、取消、产物 URL |
| `buildGraph(backend, plan, jobId)` | 返回已有执行器所需的图、输出节点与规格 |
| `llmSettings(backend)` | 返回启动时应用的模型协议配置，不自行改写宿主 settings |
| `workflowSource(backend)` | 返回工作流同步的服务 URL；编译器保留在公共层 |
| `manage(action, options)` | 显式的服务端进程管理入口；不由安装、检查或聊天自动触发 |

公共 `servers/standard-adapter.js` 提供现有 ComfyUI/H3 与 Qwen 实现作为复用组件。`manual` 是明确选择的兼容适配器，保留旧配置；不能作为缺失具体平台的兜底。

`servers/runtime.js` 是业务唯一调度入口：加载、版本/能力验证后调用上述方法。任务快照保存 provider、接口版本、连接与实例身份；恢复以原快照为准。新任务在分配 ID 前验证适配器存在；移除旧适配器后保留任务记录，调用时报告 `PROVIDER_UNAVAILABLE`。

## Runpod 完整参考实现

```text
providers/runpod/
  index.js              # 完整契约组合与公共协议入口
  config.js             # Runpod 服务能力与现有镜像默认路径/端口
  service.mjs           # 当前镜像内 ComfyUI check/start/stop/restart
  server.example.json   # 不含真实地址/凭据的登记示例
  README.md             # 从配置、检查、执行、恢复到运维的使用与扩展说明
```

已有 `runpod/scripts/comfyui.mjs` 改为兼容入口；服务管理实现归入模块。通用 `scripts/server-service.mjs <provider> <action>` 在模型服务器显式执行，不启动 Harness。通过统一 `manage` 调用，其他平台可参照实现自己的目录和进程管理。

工作流同步默认从当前选中适配器取 URL，删除脚本中固定的 Runpod 实例 URL；仍支持显式 `--url` 同步已有 H3 工作流。五种 H3 模板保留公共目录，因为相同模型在 AutoDL 上也可使用。冻结案例脚本不作为通用依赖，不改动。

其他目录保留 `.gitkeep`；正式 AutoDL 未实现前不承诺能执行。替换验收用临时副本中的 AutoDL 测试实现，明确区别于平台实际接入。

## 设置、配置和兼容

- `servers.json` 继续为本机清单，revision 和原子写入保留。结构校验只处理身份、URL、端口和凭据引用；平台/模型能力交给适配器。
- 前端平台选项来自后端发现的有效模块，不能写死 Runpod 或其他平台；已有缺失模块的记录仍显示，但禁用检查/使用并说明原因。
- 默认由 `active.comfyui` / `active.llm` 指向记录决定；打包 Runpod 不意味着业务必须加载它。
- 旧无清单配置和旧快照继续走明确的 manual 兼容路径；不猜测旧 URL 属于哪个平台。新的 provider 快照记录契约版本，版本不兼容时拒绝调用。
- 已完成媒体保留原 URL。其平台适配器缺失时不影响项目浏览和其他平台；调用原平台媒体连接会明确不可用。
- LLM 仍按下次启动应用；适配器返回现有 Qwen 兼容配置，宿主安全启动规则保留。

## 验收与边界

用同一套契约测试检查 Runpod 和测试替代平台；在临时副本中真实删除 Runpod，构建并执行本地 worker 成功生成、恢复、查询/取消、批次、参考帧及媒体/项目接口。测试代码不得从 Runpod 导入或复制实现来伪装替代。

删除 Runpod 的代码不等于迁移其运行中任务或媒体。平台被删除时原任务只报告该平台不可用；新平台业务继续运行。公共云 API、实例租赁与环境安装不是仓库已有能力，本轮不虚构。HTTP 实例身份仍依赖手工登记和地址稳定性，云端生成质量与真实跨平台性能仍需后续实测。
