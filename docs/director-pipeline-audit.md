# 导演流水线：当前边界与修复状态

更新：2026-09-09。按用户最新确认：**全部素材开拍前准备好并放在服务器；产物留在服务器；Harness 展示服务器 URL。**

## 固定流程

1. 导演先确定剧本、分镜和素材清单。角色单人参考、场景首帧、所需音频和复用镜头全部准备好，放在服务器目录。
2. 分镜 JSON 逐镜绑定素材。Harness 只提交 `plan_path`，不重抄长 JSON。
3. 插件读取 JSON 并检查素材。缺项、文件不存在、格式无效就停止；不边拍边补图，不裁切三视图。
4. 已有素材在服务器提供给 ComfyUI input。仅原样复制必要文件，不加工图片；已在 input 内则直接引用。
5. ComfyUI 排队、工作流及模型执行，完成解码、时间映射和封装。
6. 插件通过 SSH 在服务器运行 FFprobe／FFmpeg 校验最终成片及镜头，读取 SHA256、规格和服务器路径。
7. 插件返回元数据和服务器播放 URL。Harness 直接播放；刷新重新读取原任务，不能重新生成。
8. 内容审片通过后才继续下一集。文件校验通过不代表角色、剧情、对白或口型合格。

## 已修复

| 环节 | 当前实现 |
| --- | --- |
| 分镜读取 | SSH 分镜只复制 JSON；媒体保留服务器地址，不下载到本机再上传 |
| 素材检查 | 多镜头独立场景必须有预先准备的图片；绑定的图片、音频和视频均检查后才创建任务；远端部署拒绝多镜头使用本机素材 |
| 三视图边界 | 只作角色档案；声明 `character-sheet` 会拒绝推理；删除 `image_crop` 参数、自动裁切实现及对应测试 |
| 产物交付 | 删除插件下载、断点续传、下载缓存及本地成片校验；在服务器检查最终文件和各镜头后返回 URL |
| 界面 | 优先直接使用服务器 URL；播放失败提示重试，不绕回本机视频副本；旧本地产物端点仅保留历史兼容 |
| 恢复 | 先启动原任务，再绑定新工具调用，防止首读旧失败状态后冻结；保留原 prompt_id，查询异常不自动重提 |
| 停止 | 停止会话等待不取消远端；worker 停止记录本地失败；进程失活能被查询识别，不伪报远端取消 |
| 校验与状态 | 远端成功独立记录；规格／解码检查在服务器执行；内容验收保持 `not_run`，不以技术成功冒充审片 |

主要实现位于插件的 `workflows/video-plan-file.js`、`video-plan.js`、`video-execution.js`、`video-artifacts.js`、`media-artifacts.js`、`media/server-media.js` 和 `server-media.py`，以及卡片和任务状态路径。图片生成、三视图工具的产物引用也兼容服务器路径，避免新结果无法继续作为素材。

配置：`serverHost`、`serverPython`、`serverOutputRoot`、`serverInputRoot`；`comfyUrl` 供工具访问，`publicUrl` 必须能被浏览器访问。服务器脚本随插件携带，通过 SSH 执行，不需要新增 HTTP 服务。Harness 与 ComfyUI 同机时可省略 `serverHost`，仍直接校验 ComfyUI 输出目录。
