# 制作结果分批合并调研

## 结论与规格
目标：千问输出设为 32768；Segment、分镜、H3 输入按完整 JSON 分批返回，本地暂存、校验、合并和恢复。
- AC-1：仓库及本机 maxTokens=32768。已有他处 contextWindow/maxBytes 改动保留。
- AC-2：每批最多 4 项；完整批次校验通过后才持久化；全部完成前不覆盖正式结果。
- AC-3：跨批人物/尾帧衔接、顺序、ID、各 Scene 和全片时长校验保持；错误批次可重试，重复批次不重复写入。
- AC-4：重启或模型中断后，从保存的下一批恢复；进度可见，阶段未完成时工具指示继续同阶段。
- AC-5：测试、构建、发布及通用模型验证通过，保留现有项目数据，不续跑用户项目。
非目标：不从截断字符拼 JSON；不自动提交视频；剧情文本仍整体生成。

## 证据与调用链
页面 generateProduction → production-request → project_production_read → context → AI → project_production_complete → complete → 原子生产快照。
- production.js 当前 complete 要求全量数据；已有版本/身份/时长校验和原子快照可复用。
- tools/project/production.js 固定提示保存后停止，会阻断同阶段多批，需修正。
- database/managers/production.js 将 request 保存于 state.json，可在 request.batch 保存临时结果并随快照恢复。
- Harness dsh-llm 的 assembled() 在 finish.kind=max-tokens 时剔除 tool-call，残缺参数不会到插件，因此必须每批独立完整工具调用。
- 当前他处已把 maxTokens 改为 65536，按本次明确值调整为 32768；contextWindow=262144 与已知运行端上下文 65536 不同，保留他处设置并记录该限制。
