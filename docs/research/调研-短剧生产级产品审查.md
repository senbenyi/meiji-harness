# 短剧生产级产品审查调研

## 结论

从运营视角走完「创建项目 → 锚点 → 分镜 → 成品」：**链路已能跑通，但产出只是“单角色、同一首帧、5 秒一镜、提示词一句话的拼接样片”，达不到可上架的 AI 短剧**。

根因不是缺某个按钮，而是**剧情规划被写死在代码里**：分镜提示词、幕数与镜头数上限、镜头提示词格式都硬编码在 `storyboard.js` / `service.js`；运营无法调整剧情规划的方法，也无法逐步审核。按 2026-09-21 用户决策，改为 **Skill + 提示词驱动 qwen3.8 分步规划，每一步运营审核/修改/重生成，满意后再执行一集**。

- AC-1 — 已确认可用 — 建项、锚点、分镜、批量提交、合成均有代码路径；专项测试 22/22；运行项目 `20260919145813973` 已产出 35.1 秒成片。
- AC-2 — 已确认不满足 — 剧情规划写死在代码，无梗概/剧本输入，导演风格正文与代表作未传给模型，不能分步审核，已有分镜不能重新生成。
- AC-3 — 已确认不满足 — 每镜只能绑 1 个角色，i2va 直接用锚点原图做首帧；真实项目 7 镜首帧是同一张图，男主镜头从女主肖像起帧。
- AC-4 — 已确认不满足 — 镜头提示词仅一句动作（约 30 字），远低于参考提示词 `docs/design/propment.md` 的细节级（单镜约 3,000 字，含分秒阶段、光线、运镜、声音、字幕）。
- AC-5 — 部分满足 — H3 为音画联合生成（工作流含 `VAEDecodeAudio`），成片已带 AAC 音轨；但对白、音色没有写进提示词，配音不可控。
- AC-6 — 已确认存在缺陷 — 任务回写、状态、编辑入口、合成共 9 项 Bug。
- AC-7 — 未验收 — 页面端到端操作未人工验收。

## 规格

- 目标：让运营通过「Skill 驱动、逐步审核」的方式，用 qwen3.8 从导演与题材规划出多集剧情，逐集生成细节级镜头提示词，满意后执行生成并在本地合成带对白音频的成片。
- 非目标：
  1. 本次调研不修改代码、Skill、运行数据或远端服务。
  2. 不新增项目级分辨率/画幅设置（沿用设置页创作质量）。
  3. 不接入 H3 以外的 TTS 或口型模型。
  4. 不评估模型画质上限。
- 验收标准：
  - AC-1：运营不用聊天、不填技术字段，可在工作台完成「建项 → 成片下载」。
  - AC-2：剧情规划的每一步由 Skill/提示词文件定义；改文件即可改变规划方式，无需改代码；每步输出可审核、手改、改提示词重新生成。
  - AC-3：同一角色跨镜头外观一致；多角色可同镜。
  - AC-4：镜头提示词达到参考提示词的细节级（场景、主体、分秒阶段、运镜、光线、声音/对白、字幕）。
  - AC-5：成片含 H3 生成的对白与环境音；角色音色可保持一致。
  - AC-6：重拍、删除、并发操作不会让镜头指向错误视频；镜头视频在本地可用。
  - AC-7：页面全流程经人工验收。

## 调用链（现状）

```text
项目列表 → 新建（名称/导演/封面）→ POST /project/create
→ 锚点页：名称 + 描述 + 从素材库选已有图片
→ 继续到分镜 → POST /project/generate-storyboard
   ├─ 已有分镜 → 直接跳转（不能重新生成）
   └─ 空分镜 → completeStructured(写死的 system/user 提示词) ⚠ 代码写死
        输入仅 title + director 名称 + anchors；max_tokens 4096、120 秒超时
        输出 1–3 幕 × 2–6 镜，每镜 role/action/subtitle/notes
→ 生成全部待处理 → POST /project/produce
   → {mode, prompt=action 一句话, first_frame=锚点原图, quality=设置} → H3 5 秒（带音频）
   → sink 回写 job_id/status（不核对当前任务）⚠
→ 继续到成品 → POST /project/compose（同步请求）
   → 从远端 ComfyUI /view 拉流 → ffmpeg concat -c copy → 本地 media/<id>.mp4
→ 成品页播放/下载
```

## 调用链（目标：Skill 驱动分步规划）

```text
导演 Skill 根目录（Agent 与工作台共用，一处定义）
  <director-id>/SKILL.md            ← 每个导演一个标准 Skill
    frontmatter: name(kebab-case) / description / metadata.display_name …
    正文: 风格、题材、叙事节奏、人物塑造、镜头语言、声音与对白、禁忌
  <director-id>/references/
    works.md                        代表作与 TOP 参考（文字/链接）
    shot-prompt-example.md          细节级镜头提示词范例（如 propment.md）
    steps/*.md                      （可选）覆盖通用流程中的某一步

通用流程 Skill（已决定分层）
  drama-planning/SKILL.md           立项→大纲→剧本→人物/场景→分镜→镜头提示词 的步骤、输出结构、质检清单

工作台每一步：
  读取 通用步骤 + 所选导演 SKILL.md（及 references）+ 上一步定稿 + 运营补充要求
  → qwen3.8 生成草稿 → 结构校验（代码）+ 清单自检（模型）
  → 运营审核
     ├─ 通过 → 定稿，进入下一步
     ├─ 手改 → 保存为新版本
     └─ 改提示词/补充要求 → 重新生成（保留历史版本）
  → 分镜与镜头提示词全部定稿 → 「生成本集」
  → H3 逐镜生成（对白与音色在提示词内）→ 镜头视频落本地
  → 本地合成本集成片 → 下一集
```

| P0 | **H3 配音** | 提示词不含对白（E3、E9） | 对白与音色写入提示词；需要同一角色音色时，用该角色已有镜头的音频作为 `reference` 的 `audio_path` |

| P1 | 镜头连贯 | 独立生成 | 同场景使用 H3 `continue` 与固定 seed（E8） |
| P1 | 字幕 | 仅文本 | 按对白生成 SRT，可选烧录 |
| P1 | 镜头多版本 | 手填任务 ID | 每镜保留多个 take，可对比选定 |

## 导演 Skill 化方案

**可行性：已确认可行。** Harness 已启用标准 Skill 加载（E22、E23），只需把导演 Skill 根目录加入 `customSkillDirs`，Agent 即可按名称加载；工作台插件经 `src/database/files.js` 读取同一份文件作为提示词。一份文件两边共用，修改后 Agent 下次加载即生效（E22：正文每次重新读取）。

| 项 | 现状（E24、E25） | Skill 化后 |
|----|------------------|-----------|
| 存储 | `pools/directors.json` 一个数组 | `pools/directors/<director-id>/SKILL.md` + `references/`；目录即导演库 |
| 身份 | 显示名即主键，改名需改写所有项目 | `director-id`（kebab-case，稳定）为主键；显示名放 `metadata.display_name`，改名不再触及项目 |
| 内容 | `style` ≤1000 字 + `works` 文本 | 不限结构的 Markdown：风格、题材、节奏、人物、镜头语言、声音对白、禁忌；代表作与细节级提示词范例放 `references/` |
| 项目引用 | `project.director = 名称` | `project.director = director-id`；旧项目按名称一次性迁移 |
| 导演页 | 名称/风格/代表作三栏表单 | 列表 + SKILL.md 全文编辑（新建给模板）；保存时校验 frontmatter |
| 聊天工具 | `call_tools_director_list` 返回 JSON | Agent 直接从 Skill 目录看到导演，按需加载；列表工具可保留为项目选导演用 |
| 规划调用 | 只传导演名（E1） | 每步拼接：通用步骤 + 导演 SKILL.md 正文 + 需要的 references |

需要同步处理：
1. **迁移**：现有导演逐个生成 SKILL.md（`style` → 正文“风格”，`works` → `references/works.md`），生成 ID，项目 `director` 字段按名称映射为 ID；旧 JSON 归档不删除。
2. **排序**：Skill 目录无顺序，排序改存 `metadata.order` 或单独排序文件。
3. **Agent 目录体积**：每个导演 Skill 的 `description` 会进入 Agent 的 Skill 目录；导演多时需控制描述长度，或对不需要 Agent 自动选用的导演设 `disable-model-invocation`。
4. **预设规则**：导演预设“直接执行、不做方案确认”（E12）需改为按 Skill 步骤逐步产出、等待审核。

## 删除导演预设的影响

原则：预设只选 Agent 基础配置（工具、模型），不含创作业务规则；业务行为全部在 Skill（导演 Skill + 通用流程 Skill）中。

| 影响点 | 现状 | 删除后要处理的 |
|--------|------|----------------|
| 项目工具可见性 | 只在导演预设可见（E26） | 改为 `call_tools_load` 的 `project` 组（见「模式决策」） |
| 自由模式内部工作区 | `elysium-free` 强制把任务存进不可见项目（E26） | 保留 `elysium-free` 预设仍可用；若它也要“什么都不管”，内部工作区规则需改为由是否指定项目决定 |
| 预设 persona/rules | 两个预设都写了创作规则（E27） | 删除导演预设目录；`elysium-free` 的 persona/rules 清空或只留最小说明，规则迁入 Skill |
| 插件注入的创作提示词 | 写死“自由/导演模式”（E28） | 删除模式分支；只保留与模型调用相关的技术约束（质量不传参、失败恢复规则等） |
| 测试与规范 | 6 处引用（E29） | 同步删改测试与 `.claude/standards.md` 预设结构章节 |
| 本机已安装预设 | `~/.dsh/.agent-presets/elysium-director/` 存在 | 部署脚本只增不删（standards §3），需要手动删除或新增清理步骤；已有使用该预设的会话需确认去向 |

## 模式决策：不再区分自由模式与导演模式

**决定**：只保留一个 Elysium 预设，不再按预设 ID 分“自由/导演”两种行为。

理由：
1. 两个预设 persona 完全相同，rules 只差项目一段（E27）；区别本质是“这次创作是否属于某个项目”，这是任务属性，不是 Agent 身份。
2. 用户已决定预设不管业务；按预设 ID 分流（E26）正是预设在管业务。
3. 现有 `call_tools_load` 按需加载工具组机制（`src/tools/load.js`、`config/tools.json`）可直接复用：把项目与导演工具设为一个可加载组，默认隐藏，需要时加载。无需新机制。

行为规则：

| 场景 | 行为 |
|------|------|
| 用户只要一张图或一个视频 | 项目工具不可见；不传 `project_id`，任务存入内部工作区（现有自由模式行为） |
| 用户要做短剧/项目，或 Agent 加载了 `drama-planning` / 导演 Skill | Skill 指示先 `call_tools_load` 加载 `project` 组，再创建或读取项目；生成时传 `project_id` |
| 工作台操作 | 不经过预设，直接调用项目接口，不受影响 |

需要的改动（计划阶段细化）：
1. `config/tools.json` 新增 `project` 组（`call_tools_project_*`、`call_tools_director_*`）；删除 `projection.js` 中按预设判断项目工具的分支。
2. `src/tools/project/context.js`：由“自由预设一律进内部工作区”改为“未传 `project_id` 才进内部工作区”。
3. `src/session/presets.js`：`ELYSIUM_AGENT_PRESETS` 只剩一个；删除 `isElysiumFreeAgent`、`isElysiumProjectAgent`。
4. `src/session/prompts.js`：删除自由/导演模式段落，只保留模型调用技术约束。
5. 保留预设 ID `elysium-free`，避免迁移默认设置与历史会话；显示名改为“极乐世界”。persona/rules 清空到最小说明。
6. 删除 `elysium-director` 预设目录、本机已安装副本及相关测试断言；更新 `.claude/standards.md` 预设章节。

风险：模型可能在用户只要单个视频时也加载项目组。缓解：`project` 组描述写明“仅做项目/短剧时加载”，并由 `drama-planning` Skill 承担项目流程说明。

### 阶段 0 实测（2026-09-21）

- qwen3.8 运行接口报告 `n_ctx=65536`、训练上下文 `n_ctx_train=262144`；前者是当前服务配置，并非已实测可用的最大输入。两次真实请求分别输入 7,191 / 6,091 字符，服务均返回 200、`finish_reason=stop`，输入提示词分别消耗 5,585 / 4,943 tokens。
- 要求一次输出约 3,000 汉字且设置 `max_tokens=8192`：第一次输出 348 个汉字、356 tokens；第二次明确要求 12 节、每节至少 220 汉字，输出 1,226 个汉字、1,006 tokens。两次都主动结束，未达到细节级单镜目标。`shot-prompt` 应按场景/时间段拆成多次生成并合并，再做长度与结构校验；不能只提高 `max_tokens`。
- AutoDL ComfyUI 实际端口 `6016` 可达，H3 节点齐全。用 `fast` 档提交 3 秒单镜中文对白提示词，远端任务 `8cb8ea5e-d188-474c-a437-d223dadfc3de` 成功，产物为 384×512、30 fps、3.000 秒的 H.264/AAC MP4，含非静音音轨（平均 -13.9 dB）。抽取 0.5、1.5、2.5 秒画面可见人物嘴形变化及字幕，但没有可用的音频听辨或语音识别能力；对白是否清晰、是否完整、口型是否准确同步仍未确认。单镜测试也不能证明跨镜音色一致。
