## 根因与对应修复

主要问题在业务流程与执行契约：分析中的候选名称曾充当生产资产，镜头意图文本曾兼作图片/视频提示词，实际生成与正式剧本、资产状态、提示词版本之间缺少强制绑定。多 Agent 仅增加分工，无法自动补上这些依赖。

1. 资产来源与剧本脱节：正式剧本批准后才逐集提取生产资产，保存逐字引用与剧本指纹；分析候选不能直接进入生产。
2. 创作成果与实际生成脱节：角色、场景、道具、衍生图、分镜图和视频分别保存完整提示词；所有媒体生成入口检查当前版本，实际请求另存不可变快照。
3. 状态与依赖脱节：基础图先于衍生图，分镜先于视频；修改上游使受影响下游失效，旧图片不再抵消缺失提示词，旧产物不计为当前完成量。
4. 子任务过大且恢复脆弱：真实模型出现 JSON 类型错误、截断、只返回说明、引用类型错误；任务拆到单项，主协调验证、有限重试并保存成功检查点。曾重复使用同一检查点命令编号的问题已修复。
5. 状态参考互相冲突：同镜保留本体依赖，但实际引用选择当前衍生图，避免两种服装、昼夜或干湿状态同时作为可见参考。

参考项目依据见批准计划第 2 节：Toonflow 的正式剧本资产提取、资产提示词保存与衍生流程，以及 ArcReel 的独立图片/视频视觉层与按 ID 校验合并。没有将模型输出文件路径当作真实产物。
