# 流程状态与重新执行调研

## 规格与结论
- AC-1：七张制作卡片各自显示状态及进度。已确认目前只有全局请求提示和计数，无统一状态。
- AC-2：各状态下均提供重新执行入口；前置数据缺失时明确反馈。已确认前端 locked 和后端 editable 会阻止重新执行。
- AC-3：重新执行替换旧请求，迟到回写失效，已有产物和分批结果在新结果完成前保留；媒体生成保留版本。已确认请求身份和制作快照可复用，但 Segment 规划目前禁止已有视频项目重新执行。
- AC-4：测试、构建后重启 Harness 并检查实际界面。
- AC-5（用户补充）：生成中断后，启动显示“已中断”，等待人工点击；去掉“待更新”。

## 调用链与证据
production-workflow.js → project-generation.js → production.js → segment-queue.js / composition.js。
production-ui.js:Step 只渲染下一步按钮；production.js:editable 锁定所有活动请求和队列；plannedSegments 禁止已有视频。
database/managers/production.js 每次保存创建独立快照，可保留重新规划前的数据。

## 人工介入
无。保留其他任务现有修改；验收用独立普通剧情，不触发用户视频生成。

## 补充取证
src/index.js 启动后每 4 秒自动刷新队列和合片。需要在首次刷新前标记遗留任务中断，阻止自动提交；AI 请求保留批次，并在显式继续时重新激活。
