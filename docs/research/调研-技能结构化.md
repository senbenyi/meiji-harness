# 技能结构化调研

## 结论
- AC-1 — 已确认 — 技能正文被整体读取、整体拼入请求，代码不区分生成、审核、修订用的内容（`skills/load.js:69-88`、`server/prompts/text-prompts.js:19-29`）。
- AC-2 — 已确认 — 审核请求在 user 中整份附带生成技能（含官方参考），文本分镜每镜一次审核约 6.7 万字符。
- AC-3 — 已确认 — 通用审核技能 `skill-gongyong-content-review` 混有各阶段专属规则，所有阶段的审核请求都整份带上。
- AC-4 — 已确认 — 同一段落在多个技能中重复：意见修订边界 10 处（9 处逐字相同）、服务端自动修订边界 5 处（`skill-juese-image-review` 另有 1 处同义）、当前成片尾帧协议 3 处、修订范围审核 2 处。
- AC-5 — 已确认 — 文本分镜同时注入文生视频与多模态两种官方参考（约 4.7 万字符），而本次模式在请求前已确定。
- AC-7 — 已确认 — 发给图片接口的提示词带有面向文本模型的说明（身份与职责、只输出产物、意见修订边界），铅笔分镜还带入官方工作流原文。
- AC-8 — 已确认 — Harness 注册只把名称与描述放进会话 agent 的技能目录，agent 可按需加载全文；生成流程不经 Harness 读取技能。`skill-gongyong-panel-generate` 是唯一给会话 agent 用的技能，`skill-chengpian-video-generate` 正文没有任何代码发给模型。

## 规格
- 目标：技能按「通用、生成、审核、修订」结构化存储，由代码直接按字段读取；新增动作、武术、台词、表情、声音五个指导技能；面板可查看与修改基础技能（替换内置）并为本剧增补；生成、审核、修订请求按统一规则合并各层内容，去掉重复与无关文字，规则不丢失。
- 非目标：
  1. 不改变请求次数、顺序、输出协议（JSON / 自由文本 / PASS-FAIL）与解析方式。
  2. 不改写规则本身的含义；只做归类、去重和按需组装。
  3. 不改变项目「自定义 skill」与「指导素材」的功能（仍按阶段追加）。
- 验收标准：见计划文档（AC-6「规则不丢失」、AC-9「文档与兼容」为实施验收项，无现状问题）。

## 设计

### 1. 技能分类
| 类别 | 技能 | 字段 |
|---|---|---|
| 阶段技能 | 摘要、剧情整包、镜头表、单镜修订、每秒指令、文本分镜；人物 / 场景 / 部件 / 铅笔分镜图片；图片提示词改写 | 通用、生成、审核、修订，另有只读的协议 |
| 指导技能（新增） | 动作指导、武术指导、台词指导、表情指导、声音指导 | 通用、审核，以及各阶段的落点与生成要求 |
| 共享模块 | 审核通用协议、镜头类审核（可见面、朝向、空间与摄影证据）、修订边界、尾帧协议、语言 | 单段正文，被技能引用 |
| 会话说明 | `skill-gongyong-panel-generate` | 仍注册给 Harness，不参与提示词组装 |

- 通用：身份、输入说明、领域规则。生成：写法与步骤。审核：验收标准（生成时作为自检清单，独立审核时作为验收依据）。修订：意见修订与自动修订的边界。
- 协议：程序解析依赖的格式（JSON 字段结构、`## S01 / 5s`、`[seconds-complete]`、`[opening-reference: …]`、审核 PASS/FAIL），由代码持有，面板只读，保证怎么改规则都不会让解析失败。
- 流程说明类文字（「服务端自动修订边界」「生成、审核和修订由程序分别发起请求」）不再发给模型。

### 2. 指导技能
每个指导技能说明一种专业能力的做法和验收标准，在不同阶段落到不同位置：

| 指导 | 剧情整包 | 镜头表 | 每秒指令 | 文本分镜 | 默认 |
|---|---|---|---|---|---|
| 动作指导 | 人物行为与事件推进 | 动作起止与切点 | 动作与空间调度时间线 | 画面描述（detailed_description / integrated_multimodal_description） | 启用 |
| 武术指导 | 打斗事件与胜负因果 | 攻防回合与切点 | 招式、节奏、受力与位置时间线 | 画面描述 | 本剧开启 |
| 台词指导 | 对白创作 | 对白归属与切段 | 说话人、时点与语气 | `<d>` 台词与说话人表演 | 启用 |
| 表情指导 | 情绪与反应 | 镜头情绪 | 表情变化时间线（受可见面约束） | 画面表演 | 启用 |
| 声音指导 | 环境与声音氛围 | 镜头声场 | 声源、时点与强弱 | overall_soundscape / non_diegetic_music | 启用 |

- 摘要与图片阶段不使用指导技能。
- 现有同类规则散落在阶段技能与通用审核中（每秒指令「剧情、声音与视觉细节」、文本分镜「对白、环境声与配乐」、通用审核「说话人」「声音」「感官保真」等），移入对应指导技能，只维护一份。武术指导目前没有现成规则，需要新写。
- 指导素材（片库）是参考例子，指导技能是规则。素材分类增加「武术」；表情、动作、武术、对白、声音与配乐分别挂在对应指导技能下选择。原有的阶段落点说明（`shared/guidance.js` 的 `guidanceModule`）并入指导技能的阶段落点。

### 3. 三层与合并
| 层 | 存放 | 修改入口 | 生效范围 |
|---|---|---|---|
| 内置 | 插件源码 `meiji/skills/`（入 git，只读） | 开发 | 默认 |
| 基础 | `$DSH_HOME/storages/meiji/skills/<id>.json` | 技能详情页「编辑基础」，保存即替换内置 | 所有剧 |
| 本剧 | 项目索引的 `skills` 字段 | 技能详情页「本剧补充」 | 本剧所有集 |

- 每个字段：基础 = 面板修改的内容，没有修改时用内置；最终 = 基础 + 本剧补充（追加在该字段后，带【本剧补充】标题）。
- 指导技能同样三层，另有本剧的启用开关。
- 优先级（写入提示词）：输出协议 > 上游事实与本次任务 > 本剧补充 > 阶段技能 > 指导技能 > 指导素材（参考）。指导技能不能新增上游没有的事件，比如武术指导不能凭空加一场打斗。
- 现有「补充 skill」按集保存在剧集里，迁移为本剧补充：各集内容合并并标注来源集。指导素材的选择同样迁到本剧（见待用户决定 1）。

### 4. 页面
- 各阶段原「添加 / 编辑补充 skill」按钮改为「查看 skill」，旁边显示状态：基础已修改、本剧有补充、已启用的指导。
- 技能详情页（每个阶段一页）：
  1. **基础 skill**：页签 通用 / 生成 / 审核 / 修订 / 协议（只读）。默认只读展示；点「编辑」后保存即替换内置，保存前确认「对所有剧生效」。可恢复内置、撤回上一版；内置版本更新时提示并可对比。
  2. **本剧补充**：同样的页签，填写只对本剧生效的追加内容（最常用的是生成和审核）。
  3. **指导**：列出本阶段适用的指导技能，可按本剧启用或停用；点击进入指导技能详情（同样有基础编辑与本剧补充）；指导素材选择在各指导下。
  4. **预览**：用当前剧集的实际上下文拼出生成、审核、修订三种请求，按来源着色（协议、阶段技能、指导、本剧补充、素材、上下文），显示字数，不调用模型。
- 设置页新增「技能库」：列出全部阶段技能、指导技能与共享模块及其修改状态。

### 5. 组装：最终提示词
每一段带来源标题（如【阶段技能·生成】【指导·武术】【本剧补充】），模型能分辨优先级，预览也按此着色。

| 请求 | system（按顺序） | user |
|---|---|---|
| 生成 | 阶段通用 → 阶段生成 → 启用的指导（通用 + 本阶段要求）→ 本剧补充 → 自检标准（阶段审核 + 指导审核 + 本剧审核补充）→ 语言 → 优先级声明与输出协议；当前模式的官方参考（仅文本分镜等） | 任务与上下文 → 指导素材（按指导分组）→ 本次修改意见 |
| 人工意见修改 | 生成的 system，在协议前加修订边界 | 同生成，另附基稿 |
| 审核 | 审核通用协议 → 语言 → PASS/FAIL 协议 | 任务与上下文 → 验收标准（阶段审核 + 指导审核 + 本剧审核补充）→ 连续性资料 → 待审内容（不再附整份生成技能与官方参考） |
| 自动修订 | 生成的 system，自检标准换成修订边界 | 任务与上下文 → 失败稿 → 失败原因 → 原人工意见 |
| 图片 | —（图片接口只有一段 prompt） | 阶段生成（画面要求）→ 本剧补充 → 语言 → 视觉风格 → 本次画面要求 |

预计：摘要生成 system 约减 40%；文本分镜每镜生成由约 5.9 万字符降到约 3 万（只带一种模式的官方参考），审核由约 6.7 万降到约 1 万。指导技能会增加一些长度，只在适用阶段加入，预览会显示字数。

### 6. 版本与追溯
- 每个字段有内容哈希。任务出队时固定所用技能组合（阶段 + 指导 + 本剧）的版本，同一任务内的生成、审核、修订一致；进行中的任务不受中途修改影响。
- 任务记录写入 `skills: [{ id, layers, hash }]`，任务历史显示所用技能及是否为修改版或含本剧补充。

### 8. 接口（只接受面板同源请求，会话 agent 无对应能力）

### 9. 存储格式
- A（采用）：每个技能一个目录，`skill.json` 加各字段 Markdown；代码按文件名直接读取，正文便于在仓库编辑与对比。面板修改层与本剧层用 JSON，由接口读写。加载后三层是同一个结构。
- B：每个技能一个 JSON 文件；C：单个 Markdown 按标题分段。均不采用（B 编辑与对比困难，C 需要解析）。
