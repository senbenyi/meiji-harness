# 短剧生成契约统一调研

## 结论

- AC-1 — 已确认：四步生成目前共用仅含 `markdown: string` 的模型返回 schema；Skill 的细分格式没有进入生成约束。
- AC-2 — 已确认：输入字段、Skill 说明、解析和保存校验由不同文件维护，已有字段遗漏与校验范围差异。
- AC-3 — 已确认：第 1 集失败不是单个坏项目；本次真实生成多次漏掉第二场 `first_line=7`，两次重试后仍可能暂停。
- AC-4 — 未验收：统一契约实施后，四步的真实生成、保存与原有 Markdown 编辑均需验收。
- AC-5 — 未验收：运行时 Skill 与仓库模板的同步需要可重复核对，不能以安装覆盖本地文件代替。

## 规格

- 目标：让四步创作的 Skill 写法、模型输入输出、代码校验与保存结果遵循同一套可验证契约，消除因模型漏写硬性结构而反复失败。
- 非目标：改动导演风格与创意内容；自动恢复暂停的生产或提交媒体任务；重写现有项目文档。
- AC-1：每一步的生成结果具有对应的结构化 schema；代码负责渲染 Markdown，手工编辑仍走现有 Markdown 保存入口。
- AC-2：必填字段、名称引用、场与集的边界、导演规定的数值均在保存前校验；Skill、输入字段和测试保持一致。
- AC-3：分镜结果按场组织，每场必有首镜；服务端用剧本计算出的 `first_line` 填入镜头起点，模型不能漏写或改写这个边界。
- AC-4：模型结果无效时反馈具体字段和期望值；失败不改写原文档或镜头状态，人工可见失败位置。
- AC-5：运行时和模板中的共用 Skill 可核对差异；同步以本地为准且不覆盖本地特有导演文件。
- AC-6：用多场且第二场首行为音效的真实剧本验证完整生成、解析、保存；只生成分镜，不自动恢复生产。

## 调用链

```text
Skill 文件 + 导演文件 → planning.assemble 输入 JSON + 通用 {markdown} schema
→ 模型输出 Markdown → planning.generate 最多纠错一次
→ documents 解析 / 插镜 → planning.save 校验 → 项目 Markdown
                               ↘ 两次失败 → pipeline 暂停
```
