# 清理项目隧道实现调研

## 结论

- AC-1 — 已确认：服务器清单仍接受 SSH 服务，并由 `catalog/transport.js` 建立本地端口转发。
- AC-2 — 已确认：私有模型设置页原有聊天隧道按钮，以及图片、视频的连接和重新连接按钮。
- AC-3 — 已确认：当前运行设置的聊天和 ComfyUI 后端已使用 HTTP 地址，但聊天配置仍含旧 `chat.tunnel` 字段。
- AC-4 — 未验收：安装后的 Harness 和真实外网模型服务尚未验证。

## 规格

- 目标：移除项目内模型隧道与私有聊天模型连接实现，使用已登记的 HTTP(S) 地址。
- 非目标：不修改运维 SSH 登录和远端服务配置。
- 验收标准：AC-1 清单不再接受 SSH 服务且无本机转发代码；AC-2 私有模型设置不再提供连接按钮，图片和视频选择直接保存；AC-3 旧 HTTP 设置的隧道字段在启动时移除并写回；AC-4 构建和相关测试通过。

## 调用链

设置页 → 设置路由 → 模型目录/服务器清单 → 适配器 → 任务执行与媒体访问。

## 证据表

| 来源 | 支持的结论 |
|------|------------|
| `src/worker/models/catalog/registry-schema.js`、`transport.js` | 接受 SSH 服务并建立本机转发 |
| `src/server/routes/settings.js`、`src/client/workbench/settings.js` | 聊天隧道操作仍暴露给页面 |
| `~/.dsh/storages/elysium/config/settings.json` 的字段类型检查 | 当前服务使用 HTTP，聊天保留旧字段；未输出地址或凭据 |
