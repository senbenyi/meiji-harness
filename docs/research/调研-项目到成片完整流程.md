# 项目到成片完整流程调研

## 结论

- AC-1 — 已确认（代码与专项测试）— 创建项目要求已有导演和可用图片封面，成功后保存项目并进入锚点页；未做本次浏览器人工验收。
- AC-2 — 已确认（代码与专项测试）— 添加锚点后可生成并原子保存可提交的分镜，镜头经用户审核后可批量提交；本次未重新调用模型。
- AC-3 — 已确认（代码与运行数据）— 镜头任务结果回写到分镜。运行项目 `20260919145813973` 的 7 镜及对应任务均为 `succeeded`，7 个远端视频均可读取。
- AC-4 — 已确认失败 — 全部镜头成功后，项目仍无成品：按钮只切换页面，成品页只读取空交付列表，项目摘要仍是待处理；项目列表还会默认打开空成品页。
- AC-5 — 未确认 — 成品应是按顺序合并的一部影片，还是可独立播放和下载的镜头集合；两种实现范围不同。

## 规格

- 目标：定位“创建项目 → 锚点 → 分镜 → 镜头生成 → 成片”真实路径的断点，并界定最小修复范围。
- 非目标：
  1. 不重提或覆盖已成功的镜头任务。
  2. 本次调研不修改业务代码、运行项目或远端媒体。
  3. 不把独立镜头误称为已合并影片。
- 验收标准：
  - AC-1：给定已有导演和可用图片封面 → 创建项目成功持久化，并进入锚点页。
  - AC-2：给定至少一个锚点 → 继续后获得已持久化、可提交的分镜；提交后产生关联镜头任务。
  - AC-3：给定镜头任务成功 → 项目分镜显示成功状态和可访问的媒体任务 ID。
  - AC-4：给定全部镜头成功且媒体可用 → 成品页有可播放结果，项目可进入已完成状态，不重提已有镜头。
  - AC-5：成品展示必须符合用户确认的交付语义；若为完整影片，须是按分镜顺序合并、可播放和下载的单个交付物。

## 调用链

```text
项目页新建 → POST /project/create → 校验导演、封面 → project.json 等文件
→ 锚点页添加锚点 → POST /project/update-anchor
→ 继续到分镜 → POST /project/generate-storyboard → 模型生成 → 原子保存 storyboard.json
→ 用户审核并提交 → POST /project/produce → Worker 镜头任务 → shot sink 回写 job_id/status
→ 分镜页“继续到成品” → go('deliverables')：只有页面切换
→ DeliveryView 只读 deliverables.json
  ├─ 有交付物 → 播放/下载入口
  └─ 为空 → “尚无交付物”
→ projectSummary：交付物为空时 status 仍为 todo
```
