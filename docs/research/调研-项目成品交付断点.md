# 项目成品交付断点调研

## 结论

- AC-1 — 已确认 — 当前项目 7 个镜头任务均成功且都有可播放视频，但 `deliverables.json` 仍为空。
- AC-2 — 已确认 — “继续到成品”只切换客户端标签，不创建、合成或登记交付物。
- AC-3 — 未确认 — “成品”应展示 7 个独立镜头，还是自动拼接成一部完整影片，需要产品决策。

## 规格

- 目标：完成全部镜头后，进入“成品”步骤不能停在“尚无交付物”的断裂状态。
- 非目标：
  1. 未确认前不新增视频合成任务。
  2. 不改写或重新提交已经成功的 7 个镜头任务。
- 验收标准：
  - AC-1：给定全部镜头均成功且含视频结果的项目，进入成品步骤应能看到对应结果，而不是只有“尚无交付物”。
  - AC-2：任何自动登记或合成都不得重新生成已有镜头。
  - AC-3：若选择完整成片方案，应按分镜顺序生成并持久化一个可播放、可下载的交付物；若选择镜头集合方案，应明确标注为镜头成片而非合并影片。

## 调用链

```text
分镜页“继续到成品”
→ projects.js: go('deliverables')
→ DeliveryView 仅读取 project.deliverables
├─ deliverables 非空 → 展示登记的成片/字幕
└─ deliverables 为空 → 显示“尚无交付物 · 7 镜已完成”

镜头任务完成
→ shot sink 只回写 shot.job_id/status
→ 没有 delivery sink、合成任务或交付登记
→ 7 个成功视频与 deliverables 永远保持分离
```
