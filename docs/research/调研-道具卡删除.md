# 道具卡删除调研

## 结论
- AC-1 — 已确认：道具通过 `stillCards` 渲染，当前没有卡片删除按钮。
- AC-2 — 已确认：剧情操作注册在 `story.js` 和 `registry.js`；按剧集使用 `scopeProjects` 保存，支持只更新 props。
- AC-3 — 已确认：操作定义支持 `agent: false`；任务执行者需在 task-store 人工操作集合登记。
- AC-4 — 未验收：需要回归验证按钮、当前集删除、空道具列表及任务记录。

## 规格
- 目标：用户手动删除当前剧集的道具卡。
- 非目标：按用户明确要求暂不处理下游；不删除全局素材文件，不调用大模型。
- AC-1：每张道具卡标题旁有删除按钮，忙碌时禁用；提交失败显示错误并可重试。
- AC-2：点击后保存删除指定道具卡，其他道具、人物、场景及其他剧集保持不变；最后一张也可删除。
- AC-3：删除是人工操作，会话工具拒绝；任务历史记录一个人工保存步骤。
- AC-4：不存在的道具返回 404，不误删角色或场景。

## 调用链
道具卡按钮 → actions.perform → 任务执行 → executeOperation 的剧集作用域 → story 操作处理 → projectStore.save。

## 证据
| 来源 | 结论 |
|---|---|
| client/stages.js、asset-cards.js | 道具卡公用图片卡渲染，标题行可增加按钮 |
| flow/operations/registry.js | 操作范围、人工专属标记及保存步骤统一登记 |
| data/episodes.js：scopeProjects | 只保存指定剧集 |
| data/task-store.js：humanActions | 保存任务的人工执行者 |

道具卡缺少删除入口和对应保存操作。
