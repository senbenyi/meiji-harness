# 工具结果契约统一调研

## 结论

- AC-1 — 已确认 — 视频任务生成成功，但成功结果不含 `project_id`，被 `projectJob` 输出 schema 拒绝。
- AC-2 — 已确认 — `call_tools_job_result` 的严格 `completed` schema 不接受真实图片和视频结果中的 `path` 及视频元数据。
- AC-3 — 已确认 — 作品卡不使用 `project_id`，自由模式不应投影内部项目 ID。

## 规格

- 目标：统一媒体任务工具的 Harness 输出契约，消除已成功任务被报为 `INVALID_TOOL_OUTPUT` 的情况。
- 非目标：不修改任务驱动、Provider、媒体存储、模型参数或项目归属。
- AC-1：图片、视频的生成和恢复工具均接受包含 `job_id` 与 `status` 的终态结果。
- AC-2：任务状态和成功结果查询使用同一最小契约，真实 Provider 扩展字段不导致输出失败。
- AC-3：作品卡默认输出不暴露内部 `project_id`。

## 调用链

`execute → waitJob → completedResult/原始 Job → Harness output.schema 校验 → renderWorkcard → tool/result`

Harness 在 `renderWorkcard` 之前校验原始 value，因此展示层无法修复上游 schema 与 value 不一致。
