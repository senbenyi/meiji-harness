# 文本镜头与多模态引用分步调研

## 结论与规格
旧书留言 S01 的 referenceSnapshot 可读取小宁图片并转换 Base64，但已通过正文为 text 三段结构，没有多模态六段及主体绑定。当前 generateShotStoryboard 一次请求同时转写剧情与引用图片，缺少结构校验。

- AC-1：每秒指令 → 已审核文本镜头 → 已审核最终引用提示词，两个独立 Model/基础规则，任务与提示词历史区分两阶段。
- AC-2：保存文本镜头，允许只重新编排引用；引用失败保留文字与失败稿，不能提交视频。
- AC-3：代码匹配确认素材并冻结编号顺序；有图片使用 reference，无图片使用 text。Base64 只在视频提交时读取并转换。
- AC-4：界面展示两份正文和引用重编入口；输出结构/图片/主体引用校验参与修订并在提交前再次校验。

## 调用链与证据
`shot-storyboard/storyboard/produce → generateShotStoryboard → buildStoryboardPrompts → TextStoryboardModel → runTextSteps`。`shot-text.js` 一次返回最终 prompt；`filmSubmit` 对 format:text 跳过 bindReferencePrompt。图片转换已有 `pictures.referenceImageData`，不需要更改网关协议。任务计划与所有分镜入口须同步。

## 待用户决定
无。保持 schemaVersion，新增内容与步骤字段为可选产物，不修改旧文件布局。旧分镜仍可展示；没有独立文本镜头时须先生成，不能把旧最终提示词假作新文本镜头。
