## 结论与勘误

页面确实存在严重问题。首要根因在 `studio/app.css`：`.canvas` 使用纵向 Flex 布局，子项默认允许收缩；`.node` 同时设置 `overflow: hidden`，大量卡片因此被挤进一屏并裁切。总览的 21 张卡片被压成细线；资产描述、图片、剧本及视频控件也被遮住。

此前的流程验收只确认阶段数据和 DOM 元素存在，没有充分验证最终可见布局。不能据此声称页面体验已验收通过。这是此前验收的遗漏。

本次仅在 `studio/app.css` 增加 `.canvas > * { flex-shrink: 0; }`，使卡片与折叠分区保持内容高度，溢出由画布滚动承接。布局修复不代表以下信息组织与交互问题已经解决。

附加实测：

- 在分镜图页点画布左侧空白，页签立即变为“制作总览”。`app.js` 的空白点击调用 `locateLatest()`，后者强制切回总览。
- `pollFollow()` 只在出现新节点 ID 时更新，且会改写当前阶段；同 ID 的状态变化不触发更新。这是代码确认，未在本次制造后台状态变更。
- 点击“资产库”显示“资产库还是空的”，而项目资产页有三张设定图。`/assets` 读跨会话资产库，画布读项目资产，是不同来源；本次没有证据表明项目图片丢失。现有入口没有清楚解释这个区别。
- 状态值 `ready/approved/assembled/delivered`、短 ID 和生成参数直接展示；图文投影与旧画布卡片的操作能力也不一致。
