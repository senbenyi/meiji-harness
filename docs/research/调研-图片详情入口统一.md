# 图片详情入口统一调研

## 结论
- AC-1 已确认：人物列表直接生成，场景列表复用可生成的 stillCards，需要移除列表生图操作。
- AC-2 已确认：详情页已有文字编辑、生成及候选确认控件，可保留统一使用。
- AC-3 已确认：session 会在详情之外显示独立图片确认页，应将人物、场景候选导向详情，铅笔分镜保留原流程。
- AC-4 已确认：详情没有生图任务和基础 skill 入口，可复用历史及技能详情组件。

## 规格
目标：人物和场景图片统一在详情编辑页生成及确认，入口旁支持查看任务及 skill。
非目标：改变图片接口、生成协议、铅笔分镜流程。
验收：列表只有查看详情；详情能生成及确认；已有候选回到对应详情；任务记录与生图 skill 可查看。

## 调用链及证据
character.js characterCard → beginImage：人物列表直接生成。
stages.js renderScenes → stillCards：场景列表带生图、素材导入控件。
session.js renderSession → renderImageReview：非详情出现独立图片确认页。
asset-cards.js：详情复用现有生成、编辑、素材、确认操作。
execution-history.js / skill-entry.js：可复用入口。
