# 产品闭环完整性调研

## 结论

- AC-1 — **已确认** — 部署→启动→访问→创作→出片 主链路完整，无断点
- AC-2 — **已确认** — 失败→自动重试→手动恢复→出片 容错链路完整
- AC-3 — **已确认** — 四个预设各有人格、规则和工具配置，切换即生效
- AC-4 — **待实施** — 成片无导出出口 → 方案：卡片加下载按钮 + 服务端代理下载端点
- AC-5 — **待实施** — 创作历史无回溯入口 → 方案：右侧可收起/拖拽资产面板
- AC-6 — **待实施** — 导演模式缺少分镜管理闭环 → 方案：本地 JSON 分镜 + 面板内分镜标签页
- AC-7 — **已确认** — 三档指令菜单→参数映射→工具调用→卡片展示 全自动，无需手动传参

## 规格

- 目标：从产品使用角度审核所有流程是否形成闭环，假设代码质量 OK，只关注体验完整性。
- 非目标：
  1. 不评估代码质量、性能或安全性
  2. 不评估部署脚本的健壮性
  3. 不提出架构重构建议
- 验收标准：逐条列出产品闭环的完整/断裂状态及依据。

## 闭环评估矩阵

以下按用户旅程逐段评估：

### 1. 发现与上手 — 完整 ✅

```
安装部署 → 启动 → 浏览器访问 → 预设选择 → 首次对话
```

- 部署脚本一键化，输出明确的访问 URL
- 默认教学预设，AI 主动引导
- 预设切换在顶栏，无需配置

### 2. 创作触发 — 完整 ✅

```
输入 / → 三档菜单 → 点击 → 填写内容 → 发送
```

- 菜单中文，置顶显示
- 点击后自动注入档位标记
- AI 自动映射到工具参数

### 3. 生成与等待 — 完整 ✅

```
工具调用 → worker 执行 → GPU 采样 → MP4 生成
```

- 媒体卡片实时显示进度
- 预览 ~3 秒、常规 ~30 秒、高清数分钟
- 超时和网络错误有自动重试

### 4. 成片交付 — 完整 ✅

```
卡片更新 → 视频可播放 → 放大查看 → 详情面板
```

- 302 重定向到服务器 /view
- 支持内联和全屏两种播放
- 详情展示任务 ID、耗时、规格

### 5. 失败恢复 — 完整 ✅

```
失败 → 卡片显示错误 → 用户请求恢复 → resume 工具 → 成功
```

- 自动重试 5 次
- 手动恢复复用原配置
- 禁止自动改词重建，保护用户意图

### 6. 成片消费 — 断裂 ❌

```
观看 → 下载? → 分享? → 归档?
```

- 视频只能在 Harness 内播放
- 无下载按钮（铁律禁止下载方法）
- 无分享机制（链接含 token，外部无法访问）
- 无作品归档或收藏

### 7. 创作迭代 — 部分闭合 ⚠️

```
不满意 → 修改提示词 → 重新生成 → 对比
```

- 可以在同一会话中重新生成
- 但无法并排对比多个版本
- 旧视频在聊天流中被冲走

### 8. 连续剧/长视频 — 部分闭合 ⚠️

```
剧本 → 分镜 → 逐镜生成 → 审片 → 调整 → 成片
```

- 导演 persona 有完整流程描述
- 导演设置可保存和读取
- 但分镜表是纯文本，无结构化管理
- 镜头审核需逐条翻看聊天记录
- 无镜头替换/重排/拼接能力

## 人工决策

- AC-4：铁律不变（禁止 AI 自动下载），用户点击下载按钮触发下载。
- AC-5：右侧可收起/拖拽资产面板。
- AC-6：本地 JSON 分镜管理，类似资产面板 UI。
- 删除 `dsh-elysium-ui` 插件，项目合并为单插件。

## 设计方案（v2）

> v1 设计（AC-4 下载 + 扁平资产面板 + 孤立分镜表）已被 Codex 实施。经真实制作验证（《第三杯咖啡》120 镜短剧），v1 缺少项目概念、锚点管理和公共/项目素材分层。以下为 v2 设计，替代 v1 的 AC-5/AC-6 部分。

### 术语

| 术语 | 含义 |
|------|------|
| **素材** | 公共资产池，所有非项目内的生成物 |
| **项目** | 导演模式下的结构化制作单元 |
| **锚点** | 角色/场景的定型参考图，镜头自动引用 |
| **幕** | 分镜表的章节分组 |
| **镜** | 分镜表最小单位，一次生成 = 一镜 |
| **交付** | 成片及附属产出 |

### 信息架构

```
面板
├── 素材        ← 公共池，教学/自由/标准模式生成物自动归入
│   ├── 筛选：时间 / 档次 / 类型
│   └── 操作：预览、下载、引入项目
│
├── 项目        ← 导演模式，结构化制作
│   ├── 第三杯咖啡
│   │   ├── 锚点    ← 角色/场景参考图（从素材引入或项目内生成）
│   │   ├── 分镜    ← 按幕折叠，每镜绑定锚点和产物
│   │   └── 交付    ← 成片、字幕
│   └── + 新建
```

### 归属规则

| 预设模式 | 生成产物去向 |
|---------|------------|
| 教学 / 自由 / 标准 | 素材（公共池） |
| 导演（项目外） | 素材（公共池） |
| 导演（项目内） | 项目素材 |

素材可**引入**项目（引用，不复制）。删除被引用的素材时提示用户。

### AC-5：素材（v2 重新设计）

v1 实现了扁平的 job 列表。v2 需要：

1. **素材概念**：不再叫"资产"，统一称"素材"。素材是公共池中所有已完成的生成物。
2. **归属标记**：每条素材记录生成时的预设模式（preview/regular/hd）和来源上下文。
3. **引入项目**：素材可被选入导演项目，作为锚点或参考。引入后在项目中显示，原素材保留。

#### 服务端变更

- 新增 `PUT /media/tag` — 为素材添加标签（收藏、引入项目引用）

#### 客户端变更

面板顶层标签页从 `[资产] [分镜]` 改为 `[素材] [项目]`。

- 筛选器：档次（预览/常规/高清/全部）、类型（视频/图片/全部）
- `[→项目]` 按钮：弹出项目选择，将素材引入为项目锚点或参考

### 用户操作流程

```
1. 教学/自由模式下试拍 → 产物自动进入素材池
```
