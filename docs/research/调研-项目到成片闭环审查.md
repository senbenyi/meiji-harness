# 项目到成片闭环审查

- 日期：2026-09-21
- 范围：工作台「项目 → 剧本 → 锚点 → 分镜 → 成片」全流程，自有模型（AutoDL ComfyUI）为主路径。
- 原则：不兼容旧数据与旧路径，全部按新规范执行；不符合新规范的本机数据由用户手动清理。

## 结论

自有模型路径未闭环：有两处必然失败（参考图引用、镜头不落本地），人工点击量约 180+ 次（3 集 × 10 镜），首帧、锚点、种子、字幕、音量五处直接压低成片质量。

## 断点与问题

### P0 闭环断点
1. **ComfyUI 产物不落本地**：`src/server/projects/film.js:composeEpisodeFilm` 只接受 `local_media_path`；`src/worker/models/protocols/comfyui/artifacts.js` 仅返回 `comfyui_view_url`；只有百炼/BytePlus 调用 `saveMedia`。受 `.claude/standards.md` §5 铁律阻塞，用户已批准修订。
2. **`job:` 参考图在 ComfyUI 路径无法解析**：`src/server/projects/service.js:productionPlan` 以 `job:<锚点任务>` 作 i2va 首帧；`job:` 只由 `worker/runner/context.js:imageReference` 转换，仅百炼/BytePlus 调用；AutoDL 计划校验经 `protocols/comfyui/media-reference.js:mediaReference` 只接受本 ComfyUI 的 view URL → 提交即 422。
3. **新建项目强制封面**：`src/client/workbench/projects.js:150`、`src/database/managers/projects.js:339`；素材库为空时无法建项目。

### P1 人工干预
4. 逐镜提示词逐个「选镜 → 生成 → 定稿」（`planning.js:165`），无批量。
5. 逐镜「采用此镜」（`storyboard.js:98`）。
6. 时间线逐集定稿、分镜逐集生成与定稿、锚点图逐个生成。

### P1 质量
7. **首帧 = 角色定妆照**：同角色所有镜头首帧相同，景别、运镜、场景失效；场景锚点图从未使用；多人镜头仅取第一个角色。
8. **锚点出图**：中文「名称。外观；音色；性格」直接送 RealVisXL（SDXL CLIP 不理解中文，音色/性格为噪声），未用已有的正面站姿工作流 `workflow_character_front`。
9. **固定种子**：视频 `director.js` 与图片 `image/plan.js` 默认 `seed 666`，项目提交不传种子 →「重新生成此镜」得到几乎相同画面，重拍无效。
10. **无字幕、无响度统一**：对白已存但合成不烧录、不导出 SRT；各镜音量不一。
11. **对白与时长无约束**：分镜校验不检查台词量是否放得进镜头时长，易出现念不完或语速过快。

### P2 简洁性
12. 分镜两套编辑入口：规划版本表单 + `StoryboardView`（改动作/字幕、增删幕和镜），后者不回写规划版本；按集分镜固定一幕。
13. 旧「不分集」路径残留：根级 `storyboard.json`/`deliverables.json`、`episode === undefined` 分支、`composeFilm`（`-c copy`）、`productionPlan` 的 `planned=false`、锚点 `image_url`、镜头 `mode`/单 `role`。
14. 「继续」放行条件比依赖更严。
15. 媒体播放在有预览地址时走服务器；AutoDL 按时计费常被关机，关机后工作台无法播放已完成镜头。

## 目标

完整 AI 短剧生产流程：立项 → 剧情总览 → 角色锚点（场景仅文字）→ 分集时间线 → 分镜 → 逐镜提示词 → 每镜首帧 → 视频 → 按集合成（字幕、响度）→ 交付（MP4 + SRT）→ 重拍单镜 → 重新合成；人工节点只保留：
1. 剧情总览定稿；
2. 锚点图确认（一次点击，可替换任意图）；
3. 成片审看，需要时重拍单镜，系统自动重新合成。

## 非目标与已知限制

- 聊天 Agent 闭环工具不做；本轮仅按新数据结构调整其参数以保持可用。
- 不新增 r2va、fl2va 续接、BGM、片头片尾、转场。
- 画幅与分辨率由创作质量档位决定（3:4 竖屏：快速 384×512、常规 576×768、高清 864×1184），不做 9:16 平台规格转换。
- 角色一致性依赖首帧的单张 IP-Adapter FACE 参考：多人镜头只保证主角（`roles[0]`）；场景一致性依赖文字描述，场景锚点只保留文字、不出图（参考工作流为人脸预设，场景图无法作为参考，出图只会误导审核）。
- 全部 ComfyUI 产物（含聊天创作）落本地，占用本机磁盘；清理由用户负责。
- 角色音色依赖 H3 音画联合生成与提示词中的音色描述，无音色参考，跨镜音色可能漂移。
- 生产期间切换创作质量会造成本集分辨率不一，合成按首镜缩放；运营不应在生产中切换。
- 替换锚点图不会自动重拍已完成镜头，需人工重拍。

## 验收标准

- AC-1：ComfyUI 图片与视频任务成功后产物保存到所属项目 `media/` 并登记；工作台播放与下载一律读本地文件，不依赖模型服务器在线；本集合成只读本地镜头。
- AC-2：ComfyUI 路径支持 `job:<任务ID>` 图片引用：同服务器产物直接引用原 view 地址，否则上传本地文件到 ComfyUI input（上传分支视计划「待确认 1」，不放开则明确报错）；引用未成功或非图片任务时报错；恢复任务沿用首次解析结果。
- AC-3：不选封面可创建项目；项目卡片无封面时用首个角色锚点图。
- AC-4：剧情总览为每个角色输出英文 `image_prompt`；角色锚点用正面站姿工作流出图，提示词只用 `image_prompt`；场景锚点只保留文字。
- AC-5：每镜先以 `keyframe_prompt` + 主角（`roles[0]`）锚点图（无角色则纯文生图）生成与视频档位同比例的首帧，再以该首帧 i2va；首帧与视频任务同泳道按序执行；首帧失败即镜头失败。
- AC-6：每次提交镜头（含重拍）为首帧与视频生成新随机种子并写入任务计划；恢复原任务沿用原种子。
- AC-7：分镜校验每镜台词字数 ≤ 时长 × 5；逐镜提示词须包含全部定稿对白与说话角色的音色描述。
- AC-8：本集成片烧录中文对白字幕（镜内多句按字数比例分配时间）、音频响度统一到 -16 LUFS，并登记 SRT 交付物。
- AC-9：流水线是唯一生产路径。总览定稿后自动为缺图或描述变化的角色锚点出图，新增或变化角色使「锚点已确认」复位。「一键生产」可选范围（全部 / 到第 N 集），自动完成各集时间线、分镜、逐镜提示词的生成与定稿；镜头提交前等待运营「确认锚点」且所需锚点图就绪；随后自动提交镜头，本集全部成功后自动合成。镜头失败自动换种子重拍一次，仍失败则暂停并显示原因与位置（可跳转），处理后「继续」；可随时暂停；流水线生成期间运营已定稿的步骤不被覆盖；上游重新定稿首次引发已有镜头的集需复核时暂停并显示影响范围，确认后本轮级联；逐镜提示词变更使已生成镜头回到待生成；成片审看后重拍任一镜，自动重新合成新版本。流水线不阻塞任务驱动，重启后续跑且不重复提交。
- AC-10：删除全部旧不分集路径与字段，并删除「采用」概念及手动批量生成、手动合成、批量时间线入口；按集分镜页单镜只保留预览、重拍、恢复；「继续」按钮按真实依赖放行。
