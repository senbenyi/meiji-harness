# 设置统一存储调研

## 结论

- AC-1 — 已确认 — 工作台“设置”页的数据目前分散在包内默认配置、`servers.json`、`selection.json`、`providers/*.json` 和 provider 定义中，尚未统一写入运行目录的 `config/settings.json`。
- AC-2 — 已确认 — 目标文件 `~/.dsh/storages/elysium/config/settings.json` 已存在且权限为 `0600`，但当前为 0 字节，不能作为有效配置读取。
- AC-3 — 已确认 — 连接清单与模型选择各自使用 revision、文件锁、临时文件加 rename；合并后必须由同一 Store 统一锁定整份文件，并保留分区 revision，避免不同设置互相覆盖。
- AC-4 — 已确认 — 百炼与 BytePlus 文件包含 API 密钥；统一文件必须保持 `0600`，HTTP 模型列表仍不得返回密钥、SSH 地址或端口。
- AC-5 — 未验收 — 现有设置无损迁入单文件、旧文件停止成为写入源，需要实施后用临时目录迁移测试和本机字段级对比验证。

## 规格

- 目标：工作台“设置”页涉及的聊天模型与隧道、私有模型目录与连接、服务器清单、三方渠道配置以及当前模型选择，统一保存到 `~/.dsh/storages/elysium/config/settings.json`。
- 非目标：
  1. 不迁移项目、任务、素材、导演或运行日志。
  2. 不改变工作台设置页现有布局和操作方式。
  3. 不把 API 密钥、SSH 地址或端口返回浏览器。
  4. 不改变新任务优先私有模型、三方模型回退和历史任务固定后端的业务规则。
- 验收标准：
  - AC-1：首次加载时，空目标文件或无目标文件可从现有 `servers.json`、`selection.json`、`providers/*.json` 及包内默认值生成完整的 version 1 设置。
  - AC-2：设置页读取、私有模型切换、三方模型切换及服务器登记/启停后，只更新 `config/settings.json`，不再写旧设置文件。
  - AC-3：统一文件使用 `0600`、独占锁、临时文件加 rename；连接与选择的 revision 冲突语义保持不变，并发修改不会丢失其他分区。
  - AC-4：运行时从统一文件解析聊天模型、隧道、私有模型、服务器连接、三方渠道和选择；任务路由行为与迁移前一致。
  - AC-5：模型列表和错误响应不暴露 API 密钥、SSH 地址、端口或其他连接私密信息。
  - AC-6：迁移前后旧配置的非敏感字段和值逐项一致；旧文件归档到 `runtime/migrations/<timestamp>/settings-sources/`，可恢复且不再参与读取。
  - AC-7：设置相关测试、完整插件测试、构建、registry 打包及 `git diff --check` 通过。

## 调用链

```text
工作台“设置”页 ServerList
└─ serverRequest → /server/models、model-connect、third-party-select、tunnel-connect
   ├─ 私有模型目录 → 包内 config/settings.json
   ├─ 当前选择 → config/selection.json
   ├─ 服务器连接 → config/servers.json
   ├─ 三方渠道参数与凭据 → config/providers/bailian.json、byteplus.json
   └─ 聊天模型与隧道 → provider definition.json

目标：上述运行设置 → config/settings.json
                       ├─ shared Store：整文件锁、原子写、0600
                       ├─ connections：服务器清单与独立 revision
                       ├─ selection：私有/三方选择与独立 revision
                       ├─ models/chat：目录、聊天模型与隧道
                       └─ providers：百炼/BytePlus 参数与凭据
```
