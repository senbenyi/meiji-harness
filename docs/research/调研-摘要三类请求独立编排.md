# 摘要三类请求独立编排调研

## 结论
- AC-1 — 已确认 — model.toGenerationSegments 混用 kind，审核 toSegments 仍注入编剧身份。
- AC-2 — 已确认 — episode.review 使用通用审片协议和语言模板，重复输出规则并含其他阶段字段。
- AC-3 — 已确认 — contextText 不带修改基稿；textSteps 复审只传结果，无法核对最新失败稿的修订范围。
- AC-4 — 已确认 — preview 复用 buildEpisodePrompts；任务快照仍由 generationParts/reviewParts 登记。

## 规格
- 目标：同一 model 独立生成、按意见修订、审核三类请求，共用故事上下文。
- 非目标：图片流程、网关协议、持久化、任务步骤数量与重试策略。
- AC-1：提供 toGenerateMessages、toReviseMessages、toReviewMessages 及对应 segments；实际接口使用三类入口。
- AC-2：生成和修订为编剧、JSON 协议；审核为独立摘要审核员、仅一个 PASS/FAIL 输出协议，验收标准在 system，去除其他阶段通用模板。
- AC-3：生成/重做不带旧稿及历史意见；人工修改带基稿/意见；自动修订使用最新失败稿及本轮失败原因并保留人工要求；初审/复审分别收到对应基稿。
- AC-4：固定约束作为审核依据不丢失；基础覆盖、本剧补充、语言及预览继续生效；其他阶段不改变提示词。

## 调用链
buildEpisodePrompts → buildTextPrompts → interfaces/episode → EpisodeSummaryModel → gateway。
textSteps：生成 → 审核 → 自动修订 → 复审；复审须传递最新失败稿与本轮原因。
