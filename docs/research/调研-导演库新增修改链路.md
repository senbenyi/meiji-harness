# 导演库新增修改链路调研

## 结论

- AC-1 — **已确认** — 导演页已有新增按钮、`create` HTTP 端点和串行原子写入；服务端测试已覆盖新增、重复名称及落盘结果。
- AC-2 — **未满足** — 修改虽然已接通 `update` 端点，但入口绑定在整张可拖拽的 `article` 卡片点击上，没有显式修改按钮、键盘入口，并与拖动排序复用同一交互区域。
- AC-3 — **已确认** — 新增/修改成功后均以服务端返回对象更新当前列表；修改失败时表单不会关闭或清空。
- AC-4 — **已确认** — 最终数据由 Store 串行读取最新数组后，通过 `0600` 临时文件加 `rename` 原子替换 `$ELYSIUM_STATE_ROOT/directors.json`；当前本机实际文件是 `/Users/mac/.elysium/directors.json`，不是迁移前的 `.dsh/storages/elysium/directors.json`。
- AC-5 — **部分确认** — 项目下拉框和 `director_list` 工具每次读取 Store，不使用长期内存快照；但导演页新增/修改入口没有客户端交互测试，真实浏览器操作尚未验收。
- AC-6 — **已确认** — 运行中 `/director/list` 与 `/Users/mac/.elysium/directors.json` 逐项一致，与旧 `.dsh` 文件不一致；所谓“界面和文件不一致”是同时保留了迁移前后两份数据，删除接口只更新当前数据源。

## 规格

- 目标：确认导演库的新增入口、修改入口、最终保存文件和更新读取链路，修复已证实的入口问题并补齐回归验证。
- 非目标：
  1. 不允许修改导演名称；当前名称同时是项目引用和更新定位键。
  2. 不改变删除、排序和项目数据结构。
  3. 不改变“作品”允许为空或少于五项的既有业务行为。
  4. 未确认当前数据源选择前，不直接改写或删除任一 `directors.json`。
- 验收标准：
  - AC-1：导演页提供明确的“添加导演”入口；提交后只发送一次 `create`，成功后显示服务端最终返回值。
  - AC-2：每位导演提供独立、可聚焦的“编辑导演 {名称}”入口；拖动卡片不会依赖或触发整卡点击编辑。
  - AC-3：编辑入口回填名称、风格和作品；提交后只发送一次 `update`，成功后原位更新，失败时保留草稿和原列表。
  - AC-4：新增和修改最终写入 `$ELYSIUM_STATE_ROOT/directors.json`，写入保持串行、原子替换及 `0600` 权限，重新创建 Store 后能读到相同数据。
  - AC-5：修改后的导演列表能被导演页、重新进入的项目导演下拉框和 `director_list` 读取，无需重启；源代码经构建、打包后进入本机 Harness 链接的 `registry`。
  - AC-6：本机只把一个明确路径作为当前导演库；旧迁移副本不再被误认为运行数据，删除后接口与当前文件保持一致。

## 调用链

```text
工作台“导演”标签
  → DirectorList 首次挂载
  → GET /plugins/dsh-elysium/director/list
  → DirectorStore.list → enqueue(load)
  → $ELYSIUM_STATE_ROOT/directors.json
  → 当前默认解析为 /Users/mac/.elysium/directors.json

新增
  → 顶部 plus 图标
  → 表单 submit → createDirector
  → POST /director/create
  → DirectorStore.create
  → 读取最新数组 → 校验重名 → write([...items, director])
  → 0600 临时文件 → rename directors.json
  → 返回最终 director → 当前列表追加

修改
  → 当前：点击整个 draggable article（问题发生点）
  → 回填 draft → updateDirector
  → POST /director/update
  → DirectorStore.update
  → 按稳定 name 定位 → 替换单项 → 原子写入
  → 返回最终 director → 当前列表原位替换

下游读取
  ├─ 项目表单重新挂载 → fetchDirectors → 最新文件
  └─ director_list 工具 → 共享 DirectorStore.list → 最新文件
```

## 人工介入

- 需要用户确认唯一数据源：推荐继续使用当前 `/Users/mac/.elysium/directors.json`，将旧 `.dsh/storages/elysium/directors.json` 做可恢复归档；不建议把整个状态根切回旧目录，因为项目、任务、上传和模型选择也会随之切换。
- 实施完成并重启本机 Harness 后，需要在浏览器确认按钮布局、拖动排序与编辑按钮不会互相触发。
- 若希望支持“修改导演名称”，需另行设计项目引用的级联更新；本计划保持名称为稳定键。
