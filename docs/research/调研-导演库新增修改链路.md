# 导演库与 Elysium 数据根目录调研

## 结论

- AC-1 — **已确认** — 导演新增入口、`create` HTTP 端点和原子写入已存在。
- AC-2 — **未满足** — 修改入口绑定在整张可拖拽卡片点击上，没有独立、可聚焦的编辑按钮，并与拖动排序复用交互区域。
- AC-3 — **部分确认** — 新增/修改成功后使用服务端返回对象更新列表，失败时保留表单；客户端没有专项回归测试。
- AC-4 — **未满足** — 代码默认把 Elysium Home 解析到 `~/.elysium`，不符合所有数据必须位于 `$DSH_HOME/storages/elysium` 的要求。
- AC-5 — **已确认** — 本机 `$DSH_HOME/storages/elysium` 已有 956 个文件、约 81 MB，含 6 个项目、任务、上传和运行记录；迁移必须保留这些数据。
- AC-6 — **未满足** — 当前运行进程仍按旧配置读取 `~/.elysium`；该目录已被用户移走后，下一次导演列表读取会重新创建默认文件。
- AC-7 — **未满足** — 连接、模型选择和平台配置的默认路径及迁移脚本仍围绕独立 `~/.elysium` 设计，无法保证全部 Elysium 数据收敛到指定根目录。

## 规格

- 目标：将 Elysium 的导演、项目、任务、上传、运行状态、服务器连接、模型选择和平台配置统一到 `$DSH_HOME/storages/elysium`，同时修复导演新增/修改入口和更新链路问题。
- 非目标：
  1. 不改变项目、任务、素材及导演的数据结构。
  2. 不修改导演名称；名称继续作为项目引用和更新定位键。
  3. 不删除或镜像覆盖现有 81 MB 项目数据。
  4. 不输出或改写平台凭据内容。
- 验收标准：
  - AC-1：导演页提供明确的添加入口；成功后显示服务端最终返回值。
  - AC-2：每位导演提供独立的“编辑导演 {名称}”按钮，拖动不触发编辑。
  - AC-3：编辑回填并只发送一次 update；失败保留草稿和原列表。
  - AC-4：未显式覆盖时，所有运行路径均以 `$DSH_HOME/storages/elysium` 为根，不创建或读取 `~/.elysium`。
  - AC-5：本机现有 projects、runtime、uploads 全量保留，文件数量和内容校验迁移前后相符。
  - AC-6：最新导演数据合并到 `$DSH_HOME/storages/elysium/directors.json`；重启后接口、界面与该文件一致。
  - AC-7：`servers.json`、`config.json`、`providers/` 均位于同一根目录，凭据文件权限保持 `0600`。
  - AC-8：源码完成 build、registry 打包和 Harness 重启，运行进程实际使用新根目录。

## 调用链

```text
DSH_HOME=/Users/mac/.dsh
  → resolveConfig
  → ELYSIUM_HOME=/Users/mac/.dsh/storages/elysium
  ├─ directors.json
  ├─ projects/{project_id}/
  │  ├─ project/anchors/storyboard/deliverables/materials
  │  ├─ jobs/
  │  ├─ media/
  │  └─ production/
  ├─ uploads/
  ├─ runtime/
  ├─ servers.json
  ├─ config.json
  └─ providers/{provider}.json

导演界面
  → /director/{list|create|update|delete}
  → 共享 DirectorStore
  → $ELYSIUM_STATE_ROOT/directors.json
```
