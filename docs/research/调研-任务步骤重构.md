# 任务步骤重构调研

本文是任务步骤重构的设计文档：记录现状证据、概念模型、规则与已定决策。实施步骤见 `docs/plans/计划-任务步骤重构.md`。

## 结论
- AC-1 — 已确认 — 任务状态现由 3 处分别赋值，规则不一致，需改为只从步骤推导。
- AC-2 — 已确认 — 任务记录已有 `nodes` 数组，但按执行顺序临时追加，事先没有计划，也没有「未执行」「已跳过」状态。
- AC-3 — 已确认 — `runTextWorkflow` 在 9 处调用中各自编排「生成→自审→修订→复审」，与任务层构成两个调度者；步骤之间靠 `checkContext` 上的可变标志传递状态。
- AC-4 — 已确认 — 人工编辑文本分镜、场景、大纲已自动触发自审；没有「人工放行」。
- AC-5 — 已确认 — 图片只能由人在面板确认，模型工具无法批准。
- AC-6 — 已确认 — 若干文件名与内容不符或按历史事件命名。

## 规格

- 目标：以「操作 → 任务 → 步骤 → 内容节点」为唯一执行模型：操作生成步骤清单，执行器按顺序调用现有 worker，任务状态只从步骤推导；增加人工忽略自审；面板提供「当前任务」与「任务历史」两个页面查看步骤；结构上预留整集一键与人工关卡。
- 非目标：
  1. 本次不实现「整集一键」「人工关卡」「图片自动确认」，只在结构上预留。
  2. 不改变 worker 的请求内容、提示词与 skill。
  3. 不改变制作门禁顺序。
  4. 不支持并行步骤（当前所有流程都是顺序执行）。
- 验收标准：见计划文档。

## 设计

### 1. 四个概念

```text
操作（定义，写在代码里）──每点一次生成──▶ 任务（实例，存成数据）─ 步骤[1..n] ──写入──▶ 内容节点
```

| 概念 | 是什么 | 状态 | 状态由谁决定 | 存储 |
|---|---|---|---|---|
| 操作 | 按钮或工具对应的定义：生成哪些步骤、作用范围、队列类别、能否由 agent 调用 | 无 | — | 代码：`server/flow/operations/` |
| 任务 | 一次操作的执行实例 | 排队中 / 执行中 / 等待人工（预留）/ 完成 / 审核未通过 / 失败 / 已取消 | 只从步骤推导 | `projects/<id>/history/tasks/<taskId>.json` |
| 步骤 | 任务里的一次具体工作，由 worker 执行 | 未执行 / 执行中 / 完成 / 失败 / 已取消 / 已跳过 / 等待人工（预留） | 执行器 | 任务文件内 `steps` |
| 内容节点 | 项目里的一块内容（大纲、镜头表、S01 每秒指令、S01 视频……） | 未生成 / 生成中 / 通过 / 失败 / 已过期 | 步骤完成时写入、人工编辑、上游变化 | 项目剧集文件 |

- 任务与内容节点是多对多：一次一键成片写入所有镜头；一个节点历史上被多次任务写入。
- 「生成中」由「有正在执行的步骤指向该节点」推导，节点不再单独记录执行状态。
- 节点的通过/失败描述当前内容是否有效，与某次任务的成败无关；人工编辑、上游变化都会改变它。
- 任务记录中的 `nodes` 改名为 `steps`，「节点」只指内容节点。

### 2. 操作定义

在 `operations/registry.js` 中每个操作一条定义：

| 字段 | 含义 | 现状 |
|---|---|---|
| `label` | 显示名称 | 已有 |
| `scope` | `project` / `episode` / `shot`：决定与哪些任务冲突 | 部分已有（`episodeScoped`） |
| `queue` | `text` / `image` / `video` | 已有（`queue.js` 按名称判断），移入定义 |
| `plan(project, operation)` | 生成步骤清单，可分阶段展开 | 新增 |
| `agent` | agent 能否通过会话工具调用 | 新增；人工忽略、图片确认、人工关卡为 `false` |

操作不单独存成数据：每点一次就是一个任务，任务的 `action` 字段记录来源。

### 3. 步骤

```js
{ id, kind, target, status, verdict, when, inputs, outputs, attempts, error, actor, startedAt, endedAt }
```

- `kind`：`generate` / `review` / `revise` / `re_review` / `save` / `check`（保存时内容校验不通过）/ `video_submit` / `video_generate` / `image_generate` / `assemble` / `tail_frame` / `confirm`（处理候选图片）/ `execute`（其他操作整体）/ `override`（人工忽略）/ `checkpoint`（人工关卡，预留）。
- `target`：写入的内容节点，如 `seconds:S01`、`storyboard:S03`、`film:S03`。
- `status` 与 `verdict` 分开：自审返回 FAIL 是「完成 + 不通过」，不是执行失败。
- `when`：执行条件；不满足时标为「已跳过」。
- `attempts`：同一步骤内的多次请求（每秒指令续传最多 3 次）记为尝试，不拆成独立步骤。
- `actor`：`model` / `human`。

- 出队时第一个计划步骤记为「准备中」的执行中（`preparing`），使任务状态由「排队中」变为「执行中」；执行器真正开始的步骤若不是它，它恢复为未执行。

### 4. 任务状态推导

按顺序执行，同一时刻最多一个步骤在执行：

| 步骤情况（按优先级） | 任务状态 |
|---|---|
| 全部未执行 | 排队中 |
| 有步骤执行中 | 执行中 |
| 有步骤等待人工（预留） | 等待人工 |
| 有步骤已取消 | 已取消 |
| 有步骤失败 | 失败（其后步骤保持未执行） |
| 全部完成或跳过，且有审核不通过 | 审核未通过 |
| 全部完成或跳过 | 完成 |

任务状态由一个函数 `deriveTaskStatus(steps)` 计算，写入任务文件只是缓存；任何代码都不直接给任务状态赋值。队列中的 `queued` 标记由「全部未执行」推导。

### 5. 执行器与 worker

- 只有一个调度者：操作生成步骤清单，执行器按顺序逐个执行；步骤状态只能通过执行器的「开始步骤 / 结束步骤」修改。
- worker 保持不变，按 `kind` 分派：

| kind | worker |
|---|---|
| generate / revise | `runGenerationNode`（含续传与格式校验） |
| review / re_review | `runReviewNode` |
| video_submit | `submitFilm` |
| video_generate | `retrieveFilm` + 保存成片与尾帧 |
| assemble | `concatFilms` |
| save（人工编辑保存） | 各领域保存函数 |

- 步骤输出交给后续步骤并写入任务记录（沿用现有产物快照 `artifacts`）。

### 6. 文本步骤（替代 runTextWorkflow）

`text-workflow.js` 中的编排循环删除，改为声明式的步骤清单：

```js
textSteps({ target, prompts, validate, complete, persist, canRevise })
// → [generate, review, revise(when: 自审不通过且可修订), re_review(when: 已修订)]
```

- 规则与现在相同：自审必须是 PASS 或「FAIL 原因」，否则为执行失败；只在 FAIL 且可修订时修订一次；格式校验在审核前失败则任务失败。
- 9 处调用改为各自声明 `textSteps(...)`。
- `checkContext` 移到 `server/data/operation-context.js`（数据层：`review-checks.js` 与 generate 层都要用，放在 flow 会形成反向依赖）；其上的可变标志改为从步骤推导：`textDraftSaved` = 存在已完成的 generate/revise 步骤；`reviewHistory` = review/re_review 步骤的 verdict；接口失败回退改为「失败且没有已保存草稿的步骤时回退」。

### 7. 组合：单镜、一键成片、整集一键

| 操作 | 步骤清单 |
|---|---|
| 单镜成片 | `shotSteps(S03)`：分镜 textSteps → video_submit → video_generate |
| 一键成片 | `shotSteps(S01)` … `shotSteps(Sn)`，已通过的镜头在展开时跳过 |
| 整集一键（预留） | 剧情 → 镜头表 → 每秒指令 → 各镜头（镜头表通过后展开）→ 合成 |

- 同一份 `shotSteps` 被单镜与一键复用，行为一致。
- 分阶段展开：镜头数未知的部分先占一个阶段，前序通过后再展开；未展开部分视为未执行。
- 「一键」= 把本集推进到能推进的最远处：遇到自审不通过或图片待人工确认即停止；处理后再点一次，已通过的内容跳过。
- 失败即停：后一镜依赖前一镜尾帧，不跳过失败继续。
- 不引入子任务：每镜进度按 `target` 分组推导。

### 8. 人工忽略自审

| 规则 | 说明 |
|---|---|
| 作用于内容节点，不改原任务 | 原任务保持「审核未通过」；忽略是一个新任务，只含一个 `override` 步骤，`actor: human` |
| 保留 AI 理由并记录放行人与时间 | 节点 `check` 增加 `override: { at, reasons }`；面板显示「人工放行」，与 AI 通过区分 |
| 只能在面板操作 | 操作定义 `agent: false`；会话工具不开放 |
| 只忽略语义审核 | 格式错误（解析失败）不可忽略 |
| 只对当前版本有效 | 与 `check.revision` 绑定；内容再次生成或编辑后失效并重新自审 |

人工编辑后仍默认自审，不通过时可忽略（用户决定）。

### 9. 预留：人工关卡与图片自动确认（本次不实现）

- 步骤状态与任务状态预留「等待人工」。
- 等待人工时释放队列名额与剧集写入锁，允许「修改后继续」。
- 继续时按最新内容重新计算依赖（关卡是 `revisionStore` 依赖快照的分界点）。
- 只有人能通过关卡；图片自动确认必须是人事先在项目设置中开启的规则，而不是模型自行判断。
- 重启时等待中的任务同样取消；再次执行会跳过已通过的内容。

### 10. 并发、冲突与重启

- 队列类别与冲突范围来自操作定义；整集任务运行时拒绝同集的单镜操作（沿用现有冲突检查）。
- 重启一律取消（已定）：执行中的步骤标为已取消，任务推导为已取消；已提交的远端视频尽力取消。
- 重试一律新建任务；以后若需把多次执行关联为同一次整集生成，给任务增加 `continues`（接续自哪个任务）字段即可。

### 11. 当前任务与任务历史页面

两个页面共用同一个「步骤清单」组件，数据都来自任务文件的 `steps`：

| | 当前任务 | 任务历史 |
|---|---|---|
| 入口 | 状态栏「查看当前任务」；有任务运行或排队时显示 | 各阶段与剧集的「查看任务历史」（已有） |
| 内容 | 本集进行中与排队中的任务：操作名、任务状态、排队位置；步骤清单按 `target`（如各镜头）分组，已完成 / 当前 / 未执行一目了然 | 已结束的任务，按状态筛选（已有），步骤清单同左 |
| 当前步骤 | 高亮，显示已用时间、同一步骤内的尝试次数（如续传 2/3）、视频的远端任务编号 | — |
| 每个步骤 | 类型、目标、状态、审核结论与理由、错误、执行者（模型 / 人工）、起止时间 | 同左，外加内容快照（已有） |
| 刷新 | 通过已有的 `/plugins/meiji/events` 推送：步骤状态变化即通知面板，不新增轮询 | 手动刷新（已有） |
| 操作 | 停止任务 | — |

- 前提：所有操作都写任务记录（去掉 `tracked` 白名单），并在任务开始时写入完整步骤计划（未执行状态）。
- 逐镜成片的子操作（`shot-storyboard`、`film`）经 `deps.runOperation` 执行但复用同一任务上下文（嵌套作用域：不另建记录、不另加锁、不单独结束），所有镜头的步骤都在同一个任务里，修复 E13。
- 接口：`GET /plugins/meiji/tasks/current?projectId&episodeId` 返回进行中与排队中的任务及其步骤；历史接口沿用 `/history`，返回 `steps`。

## 风险
- 接口失败回退（`finish.js`）依赖 E6 的标志，改为从步骤推导时最易出错；以 `api-failure-state`、`reviewed-generation`、`self-checks`（改名后 `review-checks`）、`all-seconds` 测试为护栏。
- 历史任务文件使用 `nodes` 字段与旧状态值，需要迁移脚本（`nodes`→`steps`，`succeeded`→`completed`，`interrupted`→`cancelled`），不写运行时兼容。
- 一键成片从 worker 改为步骤清单后，跳过已完成镜头与尾帧衔接的判断必须保持一致。

## 已定决策
1. 采用「操作 → 任务 → 步骤 → 内容节点」模型；操作只存在于代码。
2. `runTextWorkflow` 的编排删除，单步 worker 保留。
3. 人工编辑后默认自审，不通过可由人忽略；忽略只能在面板操作。
4. 图片需人工确认时停下由人决定；整集一键、人工关卡、图片自动确认只做结构预留。
5. 重启一律取消；重试新建任务。
