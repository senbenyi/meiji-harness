# 剧集摘要提示词与请求顺序调研

## 结论
- AC-1 — 已确认当前不满足：`opEpisodeGenerate` 在调用 `generateEpisode` 前执行 `loadModels`，缺密钥会阻止提示词组装。
- AC-2 — 已确认具备复用基础：摘要生成和技能预览都调用 `buildEpisodePrompts`，组装本身不需要模型配置。
- AC-3 — 已确认结构差异：人物图修改有独立 model 与固定约束 MD；摘要仍将动态上下文、规则句子分散在 `story-prompts.js` 和 episode 技能中。
- AC-4 — 未验收：请求层已有失败标记和内容恢复机制，但缺密钥提前失败不经过 `runTextRequest`；改动后需实测原摘要及下游恢复。
- AC-5 — 未验收：模式隔离、时长、前后集衔接已有测试，需用于重构回归。

## 规格
- 目标：重新生成指定剧集摘要时先完成提示词组装，只在准备发送模型 API 请求时检查密钥；参考人物图 model 和约束 MD 的职责拆分。
- 非目标：本轮不实施；不重构人物图或其他生成阶段，不改变摘要返回协议，不新增模型调用，不改上游 Harness。
- 验收标准：
  - AC-1：无密钥也能完成摘要 model 和提示词组装；到请求步骤报缺密钥，网络调用次数为零。
  - AC-2：相同输入、模式和技能快照下，预览与真实请求的 system/user 一致。
  - AC-3：摘要有独立数据模型与明确的约束 MD 来源，旧组装和被替代规则无重复、无回退。
  - AC-4：密钥或 API 失败不破坏尚未成功替换的原摘要及下游；任务正确结束并保留错误原因。
  - AC-5：重新生成排除目标集旧摘要和历史意见；人工修改、自动修订各使用对应基稿；保留原时长与前后集边界。

## 调用链
`client/stages.js` 的重新生成按钮 → `actions.perform(episode-generate)` → HTTP 操作入口 → 任务执行器 → `opEpisodeGenerate` → `loadModels` → `normalizeModels`（当前提前检查密钥）→ `generateEpisode` → `buildEpisodePrompts` → `interfaces/episode.js` → `runTextSteps` → `runTextRequest` → `askModel` → `completeChat`。

技能预览：`previewPrompts` → `buildEpisodePrompts` → 同一 episode 接口，不调用模型。

人物图参考：`characterImageModificationModel` 从技能快照读取固定约束并赋值 → `CharacterImageModel.toSegments()/toPrompt()`。注意人物图普通生成仍使用片段组装，且 `startImage` 也在组装前调用 `loadModels`；不能将它误认为“延迟校验密钥”的现成实现。

## 范围修订：全部 API 与新增剧集 AI 草稿
本节按后续用户要求扩展规格，前文“只处理摘要请求、不改其他生成阶段”的非目标已被取代。最新验收标准以计划 AC-1…AC-6 为准。

- `client/overview.js:242` 的 episodeDialog 当前摘要在前、时长在后；摘要 required，只有保存回调，没有 AI 生成回调。
- `client/app.js:327` 保存时分派 episode-add/episode-edit；`data/episodes.js` 的 blankEpisode 必须有非空摘要，因此先创建空集不是现有合法路径。
- `data/episodes.js:addEpisode` 将新集放数组头部；历史上下文必须转换成剧情顺序，新增取全部既有集，编辑只取目标之前。
- `shared/project-rules.js:durationOf` 接受 1–86400 秒；`generate/story.js:normalizeEpisodeDraft` 却要求模型给出 1–180 秒，generateEpisode 还将审核选项的 durationSeconds 写死为 180。新需求要求由用户时长驱动，需一起替换。
- `flow/operations/services.js:loadModels` 影响 project/story/images/films 中全部使用者，不再局限摘要。`chat.js`、`film.js` 及图片操作存在额外前置密钥检查。
- `generate/image.js:submitPencilBoard/generateStillFile/submitAssetImage` 根据 backend.apiKey 判断是否走网关，否则走旧 ComfyUI；延迟校验必须删除这一隐式回退，而非仅修改 loadModels。
- `generate/gateway.js:requestGatewayRaw` 是网关 fetch 汇合点；文本、图片生成、视频提交/查询/下载需要不同校验字段。downloadImageBytes 的同源/跨源鉴权差异必须保留。
- `flow/tasks/runner.js:snapshot` 将 task.result 返回客户端，执行后合并 trace.result，可用于草稿回填；跨进程持久化读取草稿仍需在实施时核对，不应仅依赖内存结果。
- 本轮未修改业务代码；未运行新增场景。约束 MD 正文、model 结构与生命周期已列入更新后的计划。


## 最新规格修订：参考时长与 AI 实际时长
用户明确要求保留 AI 决定时长，输入值是参考值，剧情容量与实际时长必须在参考值 ±20 秒内。此前“只返回 summary”“用户时长固定不变”的方案已作废，以最新计划为准。

按用户最新要求，摘要非空且不超过 300 个非空白 Unicode 字符（含标点），不设置额外最低字数目标，适用于通常 2–3 分钟剧情；字数限制不是字数与片长的换算公式。机器检查数值和字数，自审检查实际剧情容量。

代码影响补充：`opEpisodeGenerate` 当前持久化优先取 existing.durationSeconds，会覆盖 AI 新时长；`normalizeEpisodeDraft` 当前固定 180 秒上限，也不适用于参考 180 秒允许最多 200 秒的新规格。这两处须同步修改。
