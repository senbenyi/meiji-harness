# 人物图修改接口调研

## 结论
- AC-1 已确认：新版下游文档第 6.2 节要求 multipart 的 model/prompt/size/image[]，图片 1–10 张，无 role 字段；可在 prompt 内固定任务职责。
- AC-2 已确认：已有 model 缺少模式、图片用途与意见；需要赋值后由 model 生成最终提示词，意见独立于规则。
- AC-3 已确认：现有 startImage 先改写文字；网关分支 revise-image 不带原图。人物修改应直接用原图和意见编辑，跳过文字生成/审核步骤，场景仍沿用原流程。
- AC-4 已确认：prepareChecks 在修改待确认图时将 matchingCandidate 保存到 originalCandidate；可读取 draft 的图片，优先于已确认素材；需要校验所属剧集。
- AC-5 已确认：新版文档返回 URL，但用户明确覆盖该要求：原图 Base64 字符串，返回仍使用 b64_json，先不展开接口协议。保留现有 multipart 容器，人物修改的 image[] 使用 Base64 data URL 文本；尺寸按文档 8 倍数与 2048 长边归一化。真实服务接收该字符串的行为未验收。
- AC-6 已确认：人物固定规则、场景 generate.md 已移动。场景新旧正文完全一致。需最小修改加载路径才能恢复整个技能加载；不改正文或场景功能。
- AC-7 已确认：预览与步骤计划须反映人物修改实际请求；返回图片保持待确认流程。

## 规格
- 目标：先完成基于原图与人工意见的人物图修改，支持新版图片接口。
- 非目标：更改场景修改行为、视频/文本接口、角色卡存储、自动确认或上传外部数据；实际收费模型验证。
- AC-1：请求字段严格符合第 6.2 节，无 role 字段。
- AC-2：model 定义 mode/character/generationRules/canvas/images/modification，支持内部 toPrompt()；意见具名单独分节；图片用途明确。
- AC-3：人物 modify 只调用图片生成步骤，原图和意见提交，不改写人物卡。
- AC-4：待确认原图优先，已确认图次之；缺失原图/意见不降级生成。
- AC-5：原图 Base64 字符串单独提交，结果继续解码 b64_json；prompt 与归一化尺寸一致。
- AC-6：移动后的规则纳入原有快照；空规则无默认回退。
- AC-7：预览复用 model，步骤计划符合真实执行，生成结果仍待人工确认。
