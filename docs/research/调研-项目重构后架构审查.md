## 调用链

### 视频生成主链路

```
startVideoJob(args, exec)
  └─ withVideoSessionLock           # 会话级串行化
      └─ startVideoJobLocked
          ├─ validateVideoPlan       # 参数校验（mode/prompt/media_url）
          ├─ findVideoCall (复用)    # 同项目未完成任务自动复用
          ├─ createJob              # 写入 input/request.json
          ├─ bindVideoCall          # 绑定 callId → jobId
          └─ launch(jobId)
              └─ withLaunchLock     # 目录级锁（防并发启动）
                  └─ launchLocked
                      ├─ open(worker.lock, 'wx')  # 独占创建
                      │   └─ EEXIST → workerAlive() → alive: 返回状态 / dead: unlink + 重建
                      ├─ writeFile(resume-request.json)  # 仅 retryFailed
                      ├─ saveJson(status.json, queued)
                      └─ spawn(worker.js, detached)
                          └─ worker 进程
                              ├─ executeComfyVideo
                              │   ├─ prepareComfyWorkflow（构建/缓存图）
                              │   ├─ runComfyWorkflow（提交 + 轮询）
                              │   ├─ collectVideoArtifacts
                              │   └─ 失败 → 最多 5 次指数退避重试
                              ├─ saveJson(status.json, succeeded/failed)
                              └─ finally: unlink(worker.lock)
```

### 恢复流程

```
resumeVideoJob(jobId, exec)
  └─ withVideoSessionLock
      └─ resumeVideoJobLocked
          ├─ getJob(jobId)
          ├─ 检查同 turn 是否已有 resume 调用 → 有则绑定返回（防重复）
          ├─ succeeded → 直接返回
          └─ failed + comfyui → launch(jobId, retryFailed=true)
```

## 问题

| # | 预期 | 实际 | 状态 | 根因 | 证据 |

| P-1 | .pyc 不入版本控制 | 10 个 .pyc 在暂存区 | 待修复 | .gitignore 缺少 Python 缓存规则 | E-8, E-9 |

| P-3 | validProjectId 统一定义 | schema.js 和 paths.js 各定义一次 | 可接受 | 有意隔离：schema 做严格类型检查，paths 宽松处理 null | 两个模块独立维护 |

**说明**：以下初始标记为"严重"的问题经代码核实为误判，不列入问题表：

- **projects/store.js writeJson 的 finally 块** — `rm(temporary)` 中的 `temporary` 是 UUID 临时文件路径，不可能删除目标文件 `path`
- **operations 队列"吞掉错误"** — `.catch(() => {})` 只作用于内部链变量 `operations`，调用者通过 `return operation` 正常接收异常
- **launch.lock 与 worker.lock 竞态** — worker.lock 的回收在 launch.lock 保护内，同一时刻只有一个进程操作
- **workerAlive 60 秒宽限期** — 针对 lock 文件已创建但 PID 尚未写入的启动窗口，合理
- **AsyncLocalStorage 嵌套** — resolveConfig 中的 withConfig 仅做校验，不影响运行时
