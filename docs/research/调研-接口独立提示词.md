# 接口独立提示词调研

## 结论
- AC-1 — 已确认现状不满足：所有文本阶段均由 `generationSystem/reviewSystem` 统一排列，`text-prompts.js` 统一决定 JSON 输出。
- AC-2 — 已确认现状不满足：四类图片共用 `imageSegments` 的固定结构；成片补充位于同一通用模块，衔接规则另外散落在流程层。
- AC-3 — 已确认：网络、鉴权在 `gateway.js`，无需改变；任务的技能快照、基础覆盖、本剧补充由 `skill-store.js` 与 `task-store.js` 提供。
- AC-4 — 未验收：预览与真实调用改为调用同一个接口模块，需要回归测试。

## 规格
- 目标：用户已明确取消统一提示词包装，各生成接口独立定义 system/user 或 prompt，继续共用网络请求与鉴权。
- 非目标：改变模型配置、技能正文、生成门禁、审核流程、输出解析协议；本次不实现技能文件热更新。
- AC-1：七个文本阶段各自拥有生成、审核、修订的角色内容与顺序，以及 JSON 输出选择；公共分发器不再注入固定段落。
- AC-2：人物图、场景图、附属图、铅笔图和视频各有独立组装模块；可单独修改结构，不影响其他接口。
- AC-3：仍支持基础覆盖、本剧补充、指导技能、任务快照、取消、网络与鉴权；已存在的输出解析所需协议继续显式使用。
- AC-4：请求预览和真实请求经过相同的组装函数；无自定义结构变动时保持当前提示词内容，避免迁移时误删规则。
