# 人物图固定约束调研

## 规格与结论
- 目标：固定约束集中在 skills/constraints/，先迁移人物图；删除其 generate.md；空文件表示不添加约束。
- AC-1 — 现状不满足：人物图基础要求位于 generate.md，另有 JS 的 clothedConstraint。目标为单一 Markdown 来源，JS 不保存约束正文。
- AC-2 — 现状不满足：loadStage 强制 generate 字段；需要显式 fixedConstraints 标记，允许人物图 fields 为空、固定文件为空。
- AC-3 — 现状不满足：基础覆盖和本剧补充会影响人物图；目标为 API 禁止编辑固定约束、停用旧字段，UI 只读展示。
- AC-4 — 待验收：约束参与任务固定快照与哈希，实际生成和预览共用；其他阶段不变。

## 证据
- `skills/load.js:35`：字段结构与目录 Markdown 对照，目录级缓存。
- `server/data/skill-store.js:41`：读取基础覆盖；buildSkillSet 固定任务组合。
- `server/prompts/interfaces/character-image.js`：年龄判断、JS 约束和可编辑 generate 分支。
- `server/http/skill-routes.js:22`、`client/skill-detail.js:27`：当前只支持可编辑字段和只读协议。

## 范围
只迁移人物图。成年/未成年/年龄不明仍分支；条件规则正文放同一 Markdown 的分节。空文件不注入任何约束，缺文件仍报配置错误。其他步骤以后显式接入。固定是应用内不可编辑，源码可修改。存储格式不变，旧覆盖文件保留但退休字段不再用于生成。
