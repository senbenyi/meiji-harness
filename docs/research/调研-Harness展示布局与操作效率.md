# Harness 展示、布局与操作效率问题调查

日期：2026-09-12  
状态：浏览器调查完成；本报告不包含界面实施。

## 1. 调查结论

当前界面能够承载项目数据，但主要仍是“聊天窗口旁边的一长列表单”。对《第三杯咖啡》这样有 120 镜的完整项目，用户必须反复滚动、辨认重复信息、重新进入项目，难以快速完成检查和修改。

主要问题集中在四点：

1. 制作主任务被放进侧栏，宽度增加后也没有变成高效的工作区。
2. 全部镜头同时展开为编辑表单，浏览密度很低，导航无法跟随。
3. 素材缺少可辨识的业务信息，选择器出现在视口外，增加寻找和操作成本。
4. 页面切换丢失工作位置，保存与加载反馈不清楚，操作名称和实际动作存在差异。

优先调整信息结构和交互路径，再统一视觉样式。仅放大面板、调字体或改变颜色，无法解决 120 镜项目的使用效率问题。

## 2. 调查范围与证据边界

- 入口：[服务器 Harness](https://36we4j3zo503js-8888.proxy.runpod.net/)。使用 Chrome 实际访问、点击标签、筛选、打开选择器和滚动页面。
- 样本：项目《第三杯咖啡》，4 个锚点、6 幕、120 镜，列表统计 120 镜完成；交付页有六分钟视频和中文字幕 SRT。
- 测量时视口约 2104 × 1359 CSS 像素；右侧面板约 793 像素宽。这是当前浏览器保存的布局，不代表首次打开默认值。
- 检查素材、项目列表、锚点、分镜、交付，以及素材与项目之间的切换。
- 未编辑项目字段，未执行导入、删除、重拍或替换；未重新生成内容。本次也未重新测试真实文件下载。
- 浏览器证据来自现场截图观察、可访问性结构和 DOM 尺寸/数量；没有随报告保存截图文件。代码核对来自本地工作区，未在本次逐文件比对远端部署哈希。
- 未做网络瀑布、CPU、内存、滚动帧率或接口耗时基准。以下“资源压力”属于结构性风险，不作为服务器慢或实际卡顿的测量结论。手机和常规笔记本视口尚未实测。

## 4. 问题清单

优先级：P1 为显著妨碍完整项目操作的问题；P2 为持续增加理解、点击或检查成本的问题。

### P1-01：制作工作区空间分配不合理

**现象：** 左侧是会话列表，中部保留聊天和大幅媒体卡片，项目制作集中在右侧固定面板。即使面板已拉到约 793 像素，内容仍采用单列；素材、项目列表和交付页大量留空，分镜页却极长。

**原因：** 面板宽度变化没有带来内容组织变化。固定侧栏承载了素材库、项目管理、角色编辑、镜头编辑和交付验收等不同任务。

**建议：** 提供明确的项目工作区入口；制作时以项目内容为主体，聊天可收起或作为辅助区。项目内采用幕导航、镜头列表/网格和当前镜头详情的分区布局，避免全部任务共享同一条滚动长列。

### P1-02：120 镜默认展开，缺少快速定位与比较

**复现：** 项目 → 第三杯咖啡 → 分镜。6 幕全部展开，每镜同时展示角色图、长描述、动作、字幕、模式、播放器、任务 ID、状态、备注和操作按钮。

**影响：** 单镜约 580 像素；浏览完整作品需要跨越很长的页面。无法直接按镜号、角色或状态查找，也没有紧凑总览。相邻镜头难以同时比较。

**建议：** 默认展示紧凑镜头列表或缩略图网格，只展开选中镜头的编辑器；提供幕目录、镜号定位和状态筛选。角色长描述应进入详情，列表保留角色名和缩略图即可。

### P1-03：滚动后丢失项目与幕导航

**复现：** 分镜页向下滚动。外层“素材/项目”仍在，但项目标题、返回按钮、锚点/分镜/交付标签及幕标题均滚出视口。

**影响：** 既不知道当前属于哪一幕，也无法就近切换交付或返回项目。镜头越多，回程成本越大。

**建议：** 固定项目标题和子导航；幕目录保持可见，并标出当前幕。镜头详情提供上一镜/下一镜，避免每次回长列表寻找。

### P1-04：选择器出现在列表底部，点击后看不到下一步

**复现 A：** 首个锚点点击“从素材选择”，选择器被插在所有锚点之后，首次出现就在视口下方。

**复现 B：** 素材列表第一个条目点击“→项目”，项目选择器位于 50 个素材之后，top 约 11,621。

**原因：** 两个选择器虽然设置了 `role="dialog"`，但仍作为普通文档流内容插入列表末端；没有相应弹层定位和焦点转移处理。

**建议：** 使用始终位于当前视口内的对话框或抽屉，显示操作对象、选择目标与取消按钮；正确处理打开焦点、关闭和返回原入口。无需先滚到列表底部。

### P1-05：素材能筛选类型，但不能高效识别内容

**现象：** 视频名称主要是“原工作流”或相同的分辨率/秒数/步数说明；图片名称统一为“已完成素材”。只有档次和类型两个筛选项，没有内容搜索、项目/角色线索或结果数量提示。

**影响：** 用户寻找“林的参考图”或某镜头时，需要反复辨认画面。相同规格和相近时间无法充当作品名称。

**建议：** 首先显示已有数据能支持的标题/提示词摘要、媒体类型和来源上下文，再放规格与时间；增加内容搜索和结果数量。项目、角色关联需先核对数据来源，不应凭空生成标签。缩略图采用多列布局，点击后单独预览。

### P1-06：列表同时挂载大量媒体，存在前端资源压力

**证据：** 默认素材首批 50 个播放器；分镜页 120 个播放器和 120 个角色图片。代码中每个 `ShotPreview` 挂载后分别查询状态，再创建对应媒体元素。

**影响边界：** 结构上增加请求、媒体元数据读取和 DOM 工作量；本次没有测出实际带宽、内存或帧率，不能据此断言下载了 120 个完整视频。

**建议：** 列表使用缩略图；按可见区域加载，只有选中镜头挂载完整播放器；状态查询去重或批量处理。实施前后分别记录首屏、请求数、媒体元素数和滚动表现。

### P2-01：浏览与编辑混在一起，技术字段抢占主要位置

**现象：** 锚点角色 ID、服务器 URL、英文描述和名称均直接呈现为输入框；每镜展示生成模式、任务 ID 等字段。已有值时 placeholder 消失，缺少持续可见的字段标题。

**说明：** 字段存在 `aria-label`，不能据此说完全没有无障碍名称；问题在于视觉用户难以分辨相邻内容的用途。

**建议：** 默认只读展示作品信息，点选后进入有可见标签的编辑区；任务 ID、原始 URL、模式代码放到技术详情。保留必要操作能力，但不让技术字段占据浏览首屏。

### P2-02：竖屏媒体被放进扁宽盒子，画面过小

**现象：** 素材预览统一宽度 100%、最大高度 160，并使用 contain。面板变宽只增加两侧黑边，没有增加竖屏画面尺寸。角色参考图也难以检查细节。

**建议：** 按横竖比例设计缩略图卡片；完整播放采用独立预览区域，支持放大参考图。列表不应让每个素材都占一整行宽播放器。

### P2-03：切换页面会丢失当前工作位置

**复现：** 从项目交付页切到素材，再切回项目，回到项目列表；重新打开《第三杯咖啡》进入锚点，而非原交付页。

**代码补充：** 选中项目、项目子标签、幕折叠均保存在会被卸载的组件局部状态中。当前持久化只涵盖面板宽度、收起状态和顶层标签。

**建议：** 保留当前项目、子页面、选中镜头、幕折叠、筛选和滚动位置；从素材选择返回后仍能继续原镜头。范围应限定为界面状态，不混入项目业务数据。

### P2-04：按钮含义不够准确，视觉层级不足

**现象与代码：** 锚点“替换”和“从素材选择”进入同一选择器；分镜“重拍”实际标记待重拍，并不会立即生成；分镜“替换”实际清空任务关联并设为待生成。重拍有 title 提示，但默认可见文案未表达完整动作。常规、编辑和删除按钮样式相近。

**建议：** 按实际行为命名，例如“标记待重拍”；替换应形成清楚的选择流程，或明确说明“解除素材关联”。合并同义入口，区分主要操作和危险操作。

**边界：** 本次未点击这些写入按钮；项目与幕删除已有确认框，不应描述为“所有删除都无确认”。

### P2-05：保存与加载反馈缺少状态区分

**证据：** 字段采用失焦保存，界面没有明确“保存中/已保存”提示。分镜加载期间曾先显示“暂无可播放产物”，随后视频正常出现；代码将状态未返回与确无产物合并显示。

**影响：** 用户难判断编辑是否完成保存，也容易把加载过程误判为产物丢失。

**建议：** 显示明确的保存状态；区分加载中、未关联、无产物和加载失败。保存交互需要实施时专门验收，本次未修改字段验证。

### P2-06：项目总览与交付页信息不足

**现象：** 项目列表只有标题、统计和删除按钮，缺少封面与明确的继续制作入口。交付页只有文字规格及下载链接，无法直接审看六分钟成片。字幕大小显示 0MB，是两位小数的 MB 格式舍入，不能推断文件为空。

**建议：** 项目卡提供封面、完成进度和“继续制作”；交付页以成片预览为核心，将视频与对应字幕组合展示。小文件使用 KB/B 等适当单位。

## 5. 独立异常：聊天媒体卡片加载失败

调查会话中，聊天文字显示“视频已生成完成”，可见媒体卡片却出现“预览加载失败 / 重试播放”；素材面板中另有视频能显示画面。

这是现场异常，不能简单归入布局问题。尚未逐项比对聊天卡片和素材列表是否为相同任务，也未确认失败来自地址、鉴权、格式还是播放器。后续应针对失败卡片核对任务与请求结果，不能用布局改版掩盖它。本报告不认定生成任务本身失败。

## 6. 优化顺序建议

1. **先恢复操作连续性：** 选择器可见、项目导航固定、切换保留位置，修正误导性动作与加载文案。
2. **再重组制作工作区：** 项目主区、幕导航、紧凑镜头总览、单镜头详情与单播放器，解决 120 镜浏览问题。
3. **再提升素材识别：** 缩略图网格、可辨识标题、搜索、筛选结果计数与已有业务关联。
4. **补齐审看体验：** 项目封面、成片预览、字幕配套展示；统一字体、间距、状态和按钮层级。
5. **用真实项目验证性能：** 在同一设备、同一网络、相同 120 镜数据下对照测量。

## 7. 建议验收标准（待后续实施确认）

| 验收任务 | 目标 |
| --- | --- |
| 浏览 120 镜 | 默认无需展开 120 套表单；1440 × 900 下紧凑列表至少同时看到 10 镜 |
| 定位第 120 镜 | 通过幕/镜号导航，最多两次导航操作到达，不依赖长距离滚动 |
| 查看当前镜头 | 始终可见项目、当前幕/镜号与返回或切换入口 |
