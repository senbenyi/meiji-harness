# 聊天模型隧道连接调研

## 结论

- AC-1 — **未满足** — 私有模型面板当前只渲染图片和视频模型，没有“聊天模型：qwen3.8”。
- AC-2 — **未满足** — 面板没有聊天模型连接按钮；现有 `model-connect` 只从图片/视频清单解析并切换新任务选择。
- AC-3 — **已确认（能力已有）** — 提供者声明中已有 qwen 隧道参数，`legacyTunnelBackend → checkBackend → ensureConnection` 可建立或复用 SSH 控制连接，并校验 `/v1/models` 包含目标模型。
- AC-4 — **已确认（启动边界）** — `harness/scripts/start.mjs` 只管理 Harness 进程，不启动模型隧道；对应测试也明确禁止启动脚本引用 tunnel/模型配置。

## 规格

- 目标：Harness 启动时不建立 Qwen 隧道；用户在“私有模型”中对“聊天模型 qwen3.8”点击“连接”时才建立隧道，成功后可再次点击“重新连接”。
- 非目标：
  1. 不恢复 Harness 启动时自动建隧道。
  2. 不让 Elysium 接管 Harness 的聊天模型选择或改写 `settings.yaml`。
  3. 不新建第二套 SSH 隧道实现，不终止非本功能拥有的端口进程。
  4. 不改动图片、视频和三方模型的选择语义。
- 验收标准：
  - AC-1：打开模型面板 → “私有模型”下显示“聊天模型：qwen3.8”及“连接”按钮。
  - AC-2：隧道未建立时点击“连接” → 仅此用户操作触发 `veo-qwen38` 的本机 SSH 端口转发，并在返回成功前核对目标 Qwen 模型。
  - AC-3：连接成功 → 按钮文案变为“重新连接”；再次点击会重新执行连接与模型检查，可用隧道由现有 SSH 控制连接安全复用。
  - AC-4：启动 Harness → 启动脚本仍不读取模型配置、不建立隧道。
  - AC-5：连接失败 → 面板显示脱敏错误，按钮恢复可点击，不改动图片/视频选择。

## 调用链

```text
Harness 启动 → harness/scripts/start.mjs → 只启动 dsh web

私有模型面板 → ServerList
├─ 图片/视频下拉框 → model-connect → check/switchServer（保持现状）
└─ 聊天模型 qwen3.8 → 连接/重新连接（待增加）
   → 已认证的 server route
   → legacyTunnelBackend(qwen)
   → checkBackend
   ├─ ensureConnection → 复用已有控制连接 / 新建 SSH 隧道
   └─ GET 127.0.0.1:18000/v1/models → 确认 qwen3.8-27b-elysium
```
