# 导演页面审查调研

## 结论
- AC-1 — 未满足：作品用 `<ol>` 展示，浏览器会显示序号。
- AC-2 — 未满足：编辑名称输入被禁用，更新接口又用新名称定位原记录。
- AC-3 — 未满足：项目以导演名称作引用；直接改名会留下旧引用。
- AC-4 — 未满足：作品输入会按顿号和部分数字序号拆分，可能改写作品名称。

## 规格
- 目标：审查导演页面，并让作品不显示序号、导演名称可修改且保存后引用一致。
- 非目标：不改变导演排序和作品的既有排列顺序；不修改历史任务文本。
- 验收标准：
  - AC-1：打开导演卡片，作品按原顺序展示且不显示数字序号。
  - AC-2：编辑导演名称，保存和重载后显示新名称；重名、空名报明确错误。
  - AC-3：已有项目引用被改名的导演时，改名后项目详情和导演选择仍指向有效导演。
  - AC-4：输入含顿号、数字的作品名称，保存和重载后文本不被错误拆分或剥除。

## 调用链
`DirectorList` → `director-api.update` → `/director/update` → `createDirectorStore.update` → `pools/directors.json`；项目表单读取导演库，但项目元数据 `project.json` 单独保存导演名称。删除路径通过 `projects.usesDirector` 检查这些引用。

## 人工介入
改名时建议同步已有项目的导演引用。跨 `directors.json` 和各项目 `project.json` 的写入不能天然原子提交，实施前需明确失败恢复方式。
