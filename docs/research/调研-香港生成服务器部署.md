# 香港生成服务器部署调研

## 结论
- AC-1 — 已确认（现状）— 香港机可通过 `veo-hk` 登录，`127.0.0.1:26016/system_stats` 和 `127.0.0.1:28000/v1/models` 均返回 200；尚无 Node、pnpm、dsh、`~/.dsh`。
- AC-2 — 未实施 — 仓库 Harness 模板和 Elysium 默认聊天地址仍指向香港公网网关；本机已存储的聊天与 ComfyUI 地址也指向公网网关。
- AC-3 — 未实施 — `harness/scripts/install.mjs` 可复制默认 Skill、构建插件并安装 Registry 包，但仅面向脚本运行所在主机；尚无香港一键部署入口。
- AC-4 — 未验收 — 香港 Harness、插件、默认 Skill 和真实生成均尚未安装与验证。

## 规格
- 目标：本机执行一个 `harness/scripts` 部署入口，在香港服务器安装并启动 Harness 与 Elysium 插件，安装仓库默认 Skill，香港进程使用香港回环模型端口，本机现有配置继续使用公网网关。
- 非目标：本次不迁移或删除本机项目、历史任务和用户自定义 Skill；不改两台 GPU 的模型服务与反向端口；不把 Harness Web 直接发布到公网。
- 验收标准：
  - AC-1：部署前检查 SSH、香港本地模型端口和运行依赖；缺项给出明确错误或由脚本安装。
  - AC-2：香港 Harness 聊天与 Elysium 聊天、图片、视频地址均为香港本机 `127.0.0.1:28000/v1`、`127.0.0.1:26016`；本机配置与已存储地址不变。
  - AC-3：本机一条命令同步所需文件，安装 Harness、插件和仓库默认 Skill，且不会改写远端已有项目与用户自定义 Skill。
  - AC-4：香港 Harness 仅监听回环接口，插件可发现、Skill 可读取，Qwen 与 ComfyUI 检查通过，至少一次真实生成成功。

## 调用链
```text
本机部署入口 → SSH/rsync → 香港依赖准备 → 香港 install.mjs → 香港 start.mjs
                                      ├─ Harness settings.yaml → Qwen 127.0.0.1:28000/v1
                                      └─ Elysium settings.json → ComfyUI 127.0.0.1:26016
                                                               → Qwen 127.0.0.1:28000/v1
浏览器 → SSH 本地端口转发 → 香港 Harness 回环监听
```
