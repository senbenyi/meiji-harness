# 按剧情划分场景与镜头调研

## 规格与结论

目标：Scene、Segment 和分镜都按实际剧情规划，避免把技术时长限制、动作节点误当场景变化或切镜理由。

- AC-1：同一时空连续发生的 30 秒书店重逢可保留一个 Scene；真实地点/时间变化仍可拆 Scene。
- AC-2：一个 Scene 可对应多个 4～15 秒 Segment；按动作节奏选择生成边界，不能为了视频时长创造换景、动作重启或多余片段。
- AC-3：段内动作、表情或景别渐变不自动变成新镜头；连续动作适合一镜到底时，每个 Segment 用一条完整连续镜头记录，叙事要求正反打/交叉剪辑时保留必要切镜。
- AC-4：最终 H3 Prompt 继承前述编排，不自行新增切镜；真实千问工具调用及测试、构建通过。

已确认：`src/database/schemas/production.js` 中 sceneValues 不限制单个 Scene 到 15 秒，segmentValues 可重复归属同一 scene_id，shotValues 允许 1～20 条。数据模型无需新增字段。`src/server/projects/production.js` 的 context.instructions 目前分别强调场景时间串联、Segment 时长、分镜字段及总时长，但未充分定义叙事单位，也未约束最终 Prompt 擅加剪辑。

调用链：项目按钮 → 关联会话 → project_production_read → 各阶段 instructions → 千问编排 → project_production_complete → 后续阶段。

非目标：不更换文本/视频模型，不硬编码所有 30 秒视频为单场景，不重新生成用户现有视频，不修改另一个任务正在清理的 UI。

人工介入：无。下一步仅修改四阶段指令，以真实生成检查行为。
