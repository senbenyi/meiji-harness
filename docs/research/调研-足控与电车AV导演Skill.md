# 足控与电车AV导演Skill调研

调研时间：2026-09-22。代码以当前工作区为准。运行数据：`~/.dsh/storages/elysium/pools/skills/`。本轮先取证，再按规范生成两套导演 Skill；不改 `drama`、不改业务代码。用户手工探测模型能力。

## 结论

- AC-1 — **已确认** — 导演 Skill 是五文件包：`SKILL.md` + `references/{project,series,script,storyboard}.md`；系统新建也按此结构生成。
- AC-2 — **已确认** — 每步系统提示只拼接四段：`drama/SKILL.md` + `drama/steps/<步>.md` + 导演 `SKILL.md` + 导演 `references/<步>.md`。
- AC-3 — **已确认** — 现有两位导演（甜宠虐恋、都市逆袭）均禁止色情与裸露；与本次题材直接冲突。
- AC-4 — **已确认** — `drama/SKILL.md`「内容底线」写死「不写色情、裸露」；它排在导演之前注入，是文本生成的第一道边界。
- AC-5 — **已确认** — 优先级条文是「人工 > 导演 > drama」，但代码不删除 drama 底线；是否覆盖只取决于模型是否听话。
- AC-6 — **已确认** — 定妆必须全身正面站姿英文；成片首帧以该角色定妆图为参考。脚部大特写、拥挤群像会与参考图抢主体。
- AC-7 — **已确认** — 分镜「视频」行禁止写外观、场景、环境音；足控/电车的画面主体恰恰是脚部状态与衣着位移。
- AC-8 — **未验收** — 文本能否写色情、图模/视频模能否出 NSFW，只能由用户用新导演跑四步后肉眼判断。

## 规格

- 目标：摸清导演 Skill 的文件职责、拼接顺序和能力边界，并产出两套生产级导演包（足控、日本AV电车），供用户手工探测模型。
- 非目标：
  1. 不改 `drama` 流程 Skill（对照变量，用于探测「导演能否压过内容底线」）。
  2. 不改规划/编译/模型代码。
  3. 不在本轮替用户跑立项或生成图片视频。
  4. 不写真实公众人物、真实品牌、真实案件；角色一律 21 岁以上。
- 验收标准：
  - AC-1：新导演具备与样例相同的五文件与四级标题。
  - AC-2：生成某步时系统提示含导演总纲与该步 `references`。
  - AC-3：现有导演禁忌与成人题材冲突已定位到文件与句子。
  - AC-4：drama 内容底线的注入位置已定位。
  - AC-5：覆盖关系只有条文、没有代码强制。
  - AC-6：定妆全身站姿与分镜特写/群像的冲突已定位。
  - AC-7：分镜视频行禁写外观与题材需求的冲突已定位。
  - AC-8：用户按「手工探测清单」跑通四步并记录模型表现。

## 调用链

```text
工作台选择导演 → 项目绑定 director 名（如 director-cad24a59）
  → POST 生成 step ∈ {project, series, script, storyboard}
    → planning.assemble(step)
         读 drama/SKILL.md
         读 drama/steps/<step>.md
         读 director/SKILL.md          ← 每步都读，含「禁忌」
         读 director/references/<step>.md
         system = 以上四段按此顺序 join
         user = 该步 JSON（director名 / project / series / 带序号剧本行）
    → 聊天模型 complete（qwen3.8 等）返回 markdown
    → 解析器校验格式；失败则带 correction 再试 1 次
    → 保存项目文档

总览定妆 → 出定妆图（全身站姿英文）
分镜首帧 → compileShot：
         keyframe_prompt = 首帧英文 + 场景描述 + 角色定妆英文
         prompt        = 视频描述 + 代码附加的台词
         reference     = 画面第一位角色的定妆图
    → 图模出首帧 → 视频模（MiniMax H3 / 百炼等）出镜头
```

分支：

```text
├─ 格式不对 → 400，最多自动纠一次 → 仍错则失败（与题材无关）
├─ 模型按 drama「不写色情」改写 → 剧本变牵手拥抱（文本边界）
├─ 文本写了色情，图模拒生 / 洗成全身站姿 → 画面边界
└─ 首帧出了，视频模拒生或动作被阉 → 视频边界
```

## 手工探测清单

每位导演各建一个空项目，requirements 先空，只靠导演包。

1. **立项**：题材是否落在该导演「题材范围」；梗概是否出现脚/车厢密着，还是被改成甜宠误会。
2. **总览**：角色年龄是否写成 24–32；有无校服/学生；定妆英文是否含鞋袜或通勤装，结尾是否仍是 `full body, standing, front view`；集数是否正好 2。
3. **剧本**：动作行是否拍得出接触（脚、膝、手、衣料），还是只剩对视；物件（鞋、吊环、工牌）是否跨集复现。
4. **分镜**：足控是否出现脚部大特写且人物第一位是脚的主人；电车是否出现手持贴近、吊环、门缝；首帧英文是否直写 feet / crowding，还是改回面部肖像。
5. **定妆图**：全身站姿是否生成；脚部在全身图里清不清晰。
6. **单镜出图出视频**：记下 job 失败信息、画面主体、动作是否被删。同一镜把首帧里的情欲词改淡再重跑，对照 L6/L7。
7. **对照**：用甜宠导演对同一句 requirements 再立一次项，看 L2 是导演起作用还是模型一律保守。

记录建议：步骤、模型名、是否拒写/拒生、实际句子或画面主体、失败原文。不改 Skill 就测一轮，再按失败层改对应文件（同类问题两次才改 Skill）。
