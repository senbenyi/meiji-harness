# 千问输出上限调研

## 结论
- AC-1 — 已确认 — Harness `maxTokens: 4096` 限制千问单次补全，Segment JSON 会在写完前被截断。
- AC-2 — 已确认 — 运行中 llama.cpp `n_ctx=65536`，`n_ctx_train=262144`；客户端 `contextWindow` 也是 65536。
- AC-3 — 已确认 — 创作预设 `agent-instructions.maxBytes: 65536` 会按 64KB 截指令/资料，大 Segment JSON 不够用。

## 规格
- 目标：提高千问单次输出和相关容量上限，避免 Segment 完整 JSON 被截断。
- 非目标：
  1. 不改 Segment 生成提示词或拆段策略。
  2. 不改 ComfyUI / H3 工作流里的 min_tokens。
- 验收标准：
  - AC-1：`settings.yaml` 中 qwen3.8 `maxTokens` 大于 4096，且不小于 65536。
  - AC-2：`contextWindow` 对齐模型可训练上下文，不再卡在 65536。
  - AC-3：创作预设 `maxBytes` 大于 65536，足以容纳完整 Segment JSON。
  - AC-4：本机 `~/.dsh/settings.yaml` 同步新上限，Harness 重启后生效。

## 调用链
