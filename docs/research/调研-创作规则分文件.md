# 创作规则分文件调研

## 结论
- AC-1 — 已确认：五类创作职责集中在 `production.js:context` 的四段内联提示词，尚未独立成文件。
- AC-2 — 已确认：`context` 已按请求阶段返回 instructions，可直接接入显式文件加载，无需增加 AI 调用。
- AC-3 — 已确认：Registry 和 npm files 目前不包含根目录 resources，必须补齐运行资源发布。
- AC-4 — 已确认：四个创作预设仍引用旧 project_generation 工具，需统一到 production 工具。

## 规格
- 目标：分离剧情、场景、Segment、分镜、H3 Prompt 的创作规则，让维护文件实际参与生成。
- 非目标：不新增模型调用、不改界面、不重写已有项目、不改变模式和硬校验。
- AC-1：五份 Markdown 各自说明职责、输入、输出、判断规则和正反例。
- AC-2：story 加载 story/scenes；segments、shots、inputs 分别加载对应文件，当前时长进入提示词；规则缺失时明确失败。
- AC-3：源码、独立 Registry 和 npm 包都能加载完整规则，不依赖仓库外部路径。
- AC-4：四个预设使用当前 production 工具；测试构建通过，运行环境加载新规则并重启。

## 调用链
页面请求 → project_production_read → workflow.context → 阶段规则 → 文本 AI → project_production_complete → 原有结构/时长/身份校验 → 项目快照。
文件缺失或阶段无效应报错，不静默退回旧提示词。
