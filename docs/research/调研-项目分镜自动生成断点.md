# 项目分镜自动生成断点调研

## 结论

- AC-1 — **未实现** — 锚点页的“继续到分镜”只切换客户端标签，没有生成或保存分镜内容。
- AC-2 — **未实现** — 新项目只创建空 `storyboard.json`；空镜头也没有动作描述，服务端会拒绝提交。
- AC-3 — **已确认可行** — 当前 qwen3.8 OpenAI 兼容接口实测支持严格 JSON Schema，可用于返回结构化幕与镜头。
- AC-4 — **未实现** — 当前没有“生成失败不覆盖原分镜”和“已有分镜不自动重生成”的专用服务端边界。

## 规格

- 目标：修复项目向导在锚点与分镜之间的断点，根据项目名称、导演和锚点自动生成可编辑、可提交的分镜文本。
- 非目标：
  1. 不在生成分镜文本后自动提交视频任务。
  2. 不覆盖或重写已有分镜。
  3. 不新增聊天模型配置或第二套项目存储。
  4. 不改动媒体任务驱动、模型路由或成品交付流程。
- 验收标准：
  - AC-1：给定标题、导演、至少一个锚点且分镜为空的项目 → 点击“继续到分镜”后生成并持久化至少一幕、一个镜头，然后进入分镜页。
  - AC-2：给定自动生成的分镜 → 每个镜头有非空动作描述、有效角色引用或空角色、合法生成模式、`pending` 状态与空 `job_id`，“生成全部待处理镜头”可成功受理。
  - AC-3：给定聊天模型连接或输出失败 → 项目不写入部分分镜，页面停留在锚点步骤并显示可重试错误。
  - AC-4：给定已有任意幕或镜头的项目 → 点击继续只进入分镜页，不请求聊天模型，不覆盖原内容。

## 调用链

```text
ProjectDetail 锚点页“继续到分镜”
├─ 当前：go('acts')
│  └─ 分镜为空 → 页面只显示无镜头 → 无可提交任务
└─ 目标：POST /project/generate-storyboard
   ├─ 读取项目，已有分镜 → 原样返回
   ├─ 空分镜 → 连接已配置 LLM → JSON Schema 生成
   ├─ 验证与规范化 → 原子初始化 storyboard.json
   └─ 返回项目 → 客户端进入分镜页 → 用户审核后提交视频任务
```
