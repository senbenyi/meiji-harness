# 图片、视频与合片主链路验收

## 发布顺序

1. 在 `llm-ai-model` 执行 `bash app/deploy_workflows.sh`，同步可视化工作流与 `elysium_media.py` 节点。
2. 队列空闲后，通过既有 `app/start_comfyui_minimax.sh --restart` 入口重启远端 ComfyUI；确认 `/object_info/ElysiumSelectFrames` 返回节点定义。
3. 再按既有入口发布工具插件及 UI 插件。新的 Harness 启动脚本会传入 `HARNESS_PYTHON`；本地运行可使用 `PYTHON_BIN`，否则使用 `python3`。

这些操作包含发布与重启，需要按当次授权执行。先发布插件、后安装节点会使新任务在提交前校验失败。

## 恢复与回传

- 停止等待不等于取消远端任务。先查原 `job_id`，再使用原恢复工具。
- 启动过程使用操作系统文件锁；进程退出会释放锁。不要删除 `launch.lock` 文件，它可以一直存在。
- 恢复时核对 worker PID 与命令。确认已退出或 PID 属于其他进程后才接管；不会终止该进程。
- 保留原提交记录。远端任务仍在运行或已完成时继续查询、下载与验收；提交结果不明时不自动重提。
- 任务连续不在队列和历史中时返回明确错误，不伪装成取消成功，也不自动创建替代任务。
- 工具结果保留真实 `path` 与预览 URL，后续参考图、复用和合片直接使用原路径；任务卡无需展示路径。

## 产物与性能

- H3 原生时间基准保持 24 fps；交付规格仍从可视化工作流读取。
- `ElysiumSelectFrames` 按原时间映射一次批量取帧，返回最后一帧供续拍；源帧不足立即失败，不重复末帧补足。
- 成片与每个可复用镜头均检查实际尺寸、帧率、视频及音轨时长、编码和完整解码。镜头损坏时任务失败，恢复只重新下载和校验已有成功 prompt。
- 批量取帧减少节点与中间复制，但最终合片仍使用完整帧批次；这不是流式处理，长视频峰值内存仍需真实任务测量。
- 本地 HTTP fixture 测试与 CPU 张量测试不替代新节点部署后的真实 GPU 推理和人工审片。
