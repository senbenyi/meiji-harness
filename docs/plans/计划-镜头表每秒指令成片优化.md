# 镜头表、每秒指令与成片优化

类型：提示词与节点流程重构。
目标：每个目标一个纯约束文档、独立 Model，并落实 `.agents/meiji-dev.md` 的节点开发要求。
调研：`docs/research/调研-镜头表每秒指令成片优化.md`。
本轮仅输出计划，不修改业务代码。三个方案问题均已确认；本计划可用于后续实施。

## 已确认与待确认

| 问题 | 推荐方案 | 另一方案的影响 |
|---|---|---|

| 每秒指令粒度（已确认） | 一次生成整集；单镜意见明确标记范围，保留未涉及镜头 | 不改成逐镜生成 |

## 1. 约束与 Model

| 目标 | Model（拟新增） | 唯一节点约束文档（拟新增） | 主要输入 |
|---|---|---|---|
| 镜头表及单镜修订 | `shot-table-model.js` | `constraints/shots/generate-shot-table.md` | 本集摘要、已通过大纲、人物/场景、目标时长；修订时加基稿与范围 |
| 每秒指令 | `shot-seconds-model.js` | `constraints/seconds/generate-shot-seconds.md` | 已通过镜头表、编号/时长、状态衔接；修订时加本轮基稿和意见 |
| 文本分镜 | `text-storyboard-model.js` | `constraints/storyboard/generate-text-storyboard.md` | 当前镜头及每秒指令、角色/场景、视频模式、固定顺序素材与前镜尾帧 |
| 视频提交 | `film-model.js` | `constraints/video/generate-film.md` | 已通过文本分镜、当前镜头、时长/画幅、真实参考素材及开场衔接 |

Model 放在 `meiji/server/prompts/models/`，负责组装，不调用 API 或保存数据，不引入业务基类。

约束文档只保留创作与质量要求，必要时同文件分“创作约束”“验收约束”。角色职责、已解析语言、任务模式、修改范围和输出协议由代码组装；审核使用验收部分，不执行创作指令。编号、时长、完成标记、Subject/Picture 等协议保持兼容，解析器与 Model 一起校验。

`skill.json` 保留必要登记信息，单镜修订复用镜头表约束；真正跨节点共用的指导保留共享来源。本轮只删除目标节点被替代的 Markdown，不顺带改摘要、剧情或官方归档。

## 3. 节点与修改规则

- 镜头表使用 `shots`；单镜修订使用 `shot:S01`；每秒指令使用 `seconds`／`seconds:S01`；文本分镜使用 `storyboard:S01`；成片使用 `film:S01`。
- 按实际操作范围选择补充：整集任务明确标注各单镜要求的作用域；单镜任务只使用该目标需要的内容，不混入其他镜头或其他集的意见。
- 人工意见与补充 skill 分开保存。成功消费已提交且版本一致的意见，失败保留，运行期间新输入不被清除。
- 更新镜头表或每秒指令时，只按必要依赖重置下游，保持未涉及素材及历史；旧视频版本不覆盖。
- 成片生成不能把“已提交视频”当成功：下载保存完成后才消费对应意见。尾帧失败独立展示，不把已保存的视频抹掉。
- 视频提交只组装已通过文本，不凭空增加一次文本 API 或视频审片；若意见影响剧情/动作，先修订审核对应文本分镜，再提交新视频。
- 保留文本、首帧、多模态参考的现有规则；参考图在请求边界转 Base64，Model 不承担下载或文件读取。历史展示完整提示词、图片用途和顺序，不把大段 Base64 放进正文。

## 4. 数据与文档迁移

旧 shots、shot-revise、seconds、storyboard、video 项目补充只迁入已有剧集对应节点；新剧集不继承。整集/单镜之间的要求作用域明确记录，不无条件复制成全局约束。已有基础修改层完整备份；适用的创作/验收要求迁入当前已有节点补充并标明来源，协议与流程说明归入代码，记录差集，不静默丢弃用户自定义内容。若实际内容有无法等价迁移的冲突，列出具体条款再确认。

所有运行数据先完整备份、迁移、读回核对；保持操作/素材 ID 和历史快照可读。提示词改造前后生成同批场景差集，每条删除规则标明合并、移动或删除理由。

实施时同步 `development.md` 当前多文件技能规范与新单文档方案，更新 `architecture.md` 和 `meiji-dev.md`；只保留仍实际引用的代码与文档。

## 5. 验收与相关测试

1. 中文/英文配置由代码确定；生成、人工修订、自动修订、审核四类请求资料与职责正确；预览等于实际组装。
2. 镜头编号连续、1–15 秒范围及总时长容差保留；每秒输出覆盖既定镜头编号和时长，缺镜或截断不能覆盖有效结果。
3. 修改单镜不改无关镜头；跨镜动作、对白、位置及持物衔接正确；后项失败不抹掉已通过结果。
4. 文本分镜与视频素材顺序一致，Picture 引用、模式、尺寸及前镜尾帧有效；提交/下载/保存/尾帧失败与取消如实记录。
5. 补充 skill 增删改、跨集/跨镜隔离、任务冻结、历史版本、意见清理与新意见保护。
6. 各操作处历史入口、步骤当前状态、完整提示词；按钮组合及面板内弹窗可用，会话不被遮挡。
7. 只运行相关测试：`shot-text`、`shot-timing`、`all-seconds`、`produce-shots`、`video-prompt-text`、相关 gateway/skill/node/task/UI 测试及架构检查；新增四个 Model 测试和必要迁移测试。记录基线与通过/失败/取消数，不跑全套。
8. 重启最新服务后，在已有摘要/剧情的验收项目测试镜头表→每秒→文本分镜→单镜成片；真实视频优先验证单镜，批量与失败路径用模拟接口，避免无必要地生成整集视频。
9. `git diff --check`、实施记录、目录同步；代码与验证完成后集中更新一次 GitNexus 索引。
