# 执行步骤独立展示
- 类型：完整流程，展示职责调整及任务元数据扩展。
- 目标：标题节点状态和操作按钮不随步骤切换；所有阶段在当前步骤区展示，审核未通过返修用红字，执行按钮固定文案且置灰禁用。
- 非目标：新增执行步骤、扩充公共NodeState状态或修改审核决策。

## 验收标准
| AC | 状态 → 结果 | 证据/缺口 |
|---|---|---|
| AC-1 | 执行前/执行中/刷新 → 标题保持执行前节点状态；结束展示最终状态 | 将初始node_state快照加入Task.metadata并投影到script_execution |
| AC-2 | 准备/排队/生成/审核/修订 → 当前步骤区域跟随，审核未通过原因在同一区域红色 | 现有Step和review_issues足够，不新增伪造Task步骤 |
| AC-3 | 执行中 → 按钮固定按意见修改，灰色且不可点击，结束恢复 | 当前busy按钮文案被phase替换，需要移除，增加点击守卫 |
| AC-6 | 标题右侧箭头 → 查看剧本文字按钮，仍进入优化稿详情，原稿入口保留 | 用户追加要求，复用原稿查看按钮样式 |
| AC-5 | 有优化稿 → 复制原文紧邻查看规则，复制完整正文，底部无重复按钮 | 用户追加要求；保留原复制成功/失败交互 |
| AC-4 | 已有稿主动修改/旧拒绝新任务 → 显示生成步骤；本任务审核失败返修 → 红色修订与原因 | 保留本任务issues识别策略 |
