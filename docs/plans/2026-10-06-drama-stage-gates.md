> 基线：2026-10-06，`09cb1ad0`，插件 1.8.2。

## 0. 已确认结论

**制作阶段目前主要是页面对节点的分类，不是执行过程必须满足的业务前置条件。领域层允许上游产物全为空时创建视频生成 Attempt。**

用户指出的“内容分析、资产设定、分镜剧本、分镜图为空，仍生成视频”在当前新项目得到确认。它包含两个同时存在的断点：

1. 内容分析和剧本文本存在领域 JSON 中，却没有被投影到画布阶段。
2. 角色参考和分镜图确实没有生成；视频入口也没有检查它们。

上一轮调查找到的子 Agent 失败及通用镜头补缺，属于上游错误被放行的具体实例。此次进一步证实：即使全部前置文本也为空，领域层仍能放行；流程缺少完整的服务端执行契约。

## 1. 页面为空的实际证据

对真实 `canvasReadModel()` 与 `canvasStageCounts()` 运行当前项目记录：

| 项目 | 内容分析节点 | 资产设定节点 | 剧本节点 | 分镜节点 | 单镜视频节点 | 审核交付节点 |
| --- | --- | --- | --- | --- | --- | --- |
| `20261006210821751` | 0 | 0 | 0 | 0 | 10 | 4 |

该项目领域记录有 1 个内容分析 Proposal、1 个分集规划 Proposal、3 个剧本 Proposal、3 份 script 和 10 个 Shot；其中第 3 集 script 是失败后用大纲替代的，并非有效正式剧本。

同项目 `step-02-development`、`step-04-scripts`、`step-05-assets`、`step-06-storyboards` 没有文件。全部 10 个领域资产为视频，图片为 0；镜头 references 全空。

**不能用领域中“有一个文本字段”宣称阶段已合格，也不能将 UI 空白一概解释为没有任何领域数据。**

实际展示链：

```text
领域 Project
  → canvasReadModel 有 legacyCanvas 时直接返回兼容画布
  → 内容分析、角色、Episode.script 不参与投影
  → stages.js 仅按节点标题、group、kind 的正则分类
  → 只有视频节点的项目，前四个页签必然为空
```

证据：`lib/domain/read-models.js:16–18`、`studio/stages.js`、`studio/app.js:889`。

旧项目虽然存在一些阶段节点，部分是父 Agent 写的“角色卡清单”“分镜静帧清单”文本。节点数或文字清单不能证明已经生成对应图片资产。

## 2. 空上游仍能执行的实际证据

本次调用真实 `createProjectAggregate()`、`upsertEpisode()`、`upsertShot()`、`createGenerationAttempt()`，只在内存中建立测试项目，没有写项目记录、没有远程请求：

```json
{
  "storyBible": null,
  "proposals": 0,
  "characters": 0,
  "assets": 0,
  "script": null,
  "shotBefore": "planned",
  "shotAfter": "generating",
  "attemptCreated": true
}
```

已定位的实际断点：

- `lib/domain/commands/index.js:244` 的 `createGenerationAttempt` 没有制作前置条件校验，还自动把 planned 转为 ready。
- `lib/index.js:598` 的 `ensureLegacyShot` 可补一个兼容集及 ready 镜头；不能让这条路径绕开正式短剧阶段。
- `lib/index.js:4238` 的 batch 把 draft/planned 镜头视为可生成，只按状态筛选。
- `studio_novel_orchestrate` 保存文本后直接创建视频 batch，根本没有角色参考与分镜图任务。
- `canvasStageCounts()` 只统计节点，不参与生成准入；名称相似的节点也能被归类，不能作为验收依据。

## 3. 目标执行契约

短剧制作统一依赖以下顺序：

```text
源文
  → 内容分析与剧情覆盖
  → 角色／场景／道具设定及所需参考素材
  → 分集剧本与完整镜头表
  → 逐镜分镜图及对应绑定
  → 视频／声音
  → 拼接
  → 自动检查与正式交付
```

角色与场景身份设定必须在剧本及分镜间保持一致。创建集或镜头的草稿记录不代表对应阶段完成。

每阶段需要明确、可定位且与当前版本一致的产物。文本要有真实结构化结果，图像要有实际可读取资产和有效绑定；空字段、通用模板、清单文字、单纯节点计数都不能代替产物。

任一必需前置条件缺失，生成任务应返回阻塞原因及缺失对象，不能提交 ComfyUI；文本任务失败应保留失败状态，不能补通用镜头当作成功。

快速模式可以减少质量成本与人工等待，仍要执行必要阶段和自动验收。页面从同一领域事实展示产物与阻塞原因，不能另用标题正则推断完成。

本计划针对完整短剧生产。现有明确的单独图像／视频创作需求需要保持其独立语义；不把临时单镜创作误标为完成短剧，也不默认为短剧设置绕过开关。

## 4. 文件、改动与验证范围

| 文件 / 模块 | 职责与拟改动 | 验证 |
| --- | --- | --- |
| `lib/domain/policies.js` | 定义短剧阶段前置条件，校验真实产物、对应版本与镜头绑定 | 缺分析、设定、剧本或分镜图分别返回明确阻塞；产物齐全可进入生成 |
| `lib/domain/commands/index.js` | 在创建视频 Attempt 的业务边界执行准入，取消用 planned→ready 自动代替阶段验收 | 当前空上游复现改为失败，未增加 Attempt，镜头状态不改变 |
| `lib/domain/production.js` | 创建／领取制作任务时保留阶段依赖及失败状态，供后台恢复使用 | 上游失败不领取下游视频任务；恢复只重做缺失／失败任务 |
| `lib/index.js` 的 novel / batch / render 链 | 文本成功后建立设定素材、分镜图、视频的依赖图；逐项核对结果；取消模板补缺；让兼容路径遵守正式短剧门禁 | 子 Agent 无输出或 Schema 失败时不能生成视频；同一镜头前置产物可追溯 |
| `lib/script/contracts.js` | 校验正式剧本、镜头与剧情覆盖的关联，不将非空大纲视为合格剧本 | 通用镜头不能覆盖实际集内容的失败样本被拒 |
| `lib/domain/read-models.js` | 从领域记录投影内容分析、资产设定、剧本、分镜及媒体；合并必要兼容画布节点，避免提前返回遮蔽数据 | 当前新项目能展示真实文本；缺图片显示缺失，不能伪造完成 |
| `studio/stages.js`、必要时 `studio/app.js` | 按明确阶段归属展示投影，不把正则节点数当业务状态 | 标题不含阶段关键词也能准确展示；清单文字不冒充图像资产 |
| `tests/domain/`、`tests/studio/canvas-stages.test.js` 及相关生产测试 | 添加跨入口阻塞、子任务失败、兼容投影及恢复验证 | 工具、HTTP、后台 Worker 到最终领域边界的行为一致 |

时长、独立对白字段及交付实体闭环已在根因报告中定位。实施时与视频交接、最终完成验收一并核对，不用“产物齐全”掩盖这些已知缺陷。

## 5. 现有项目处理与完成标准

- 从领域数据展示已有分析和剧本；第 3 集模板剧本标为缺失／需重做，不据此通过验收。
- 保留已经生成的视频，标记缺少前置产物与未验收状态，不自动删除或重新生成。
- 两个项目均不得仅因 Run completed 被视为合格短剧。
- 实施验证先用内存与 Mock 证明阻塞、失败传播和恢复，再执行仓库相关测试、完整 smoke 与差异检查。
- 真实媒体验收须检查角色参考、每镜分镜、剧情覆盖、计划／实际时长、对白与正式交付记录；未进行真实媒体验证时明确记录。
