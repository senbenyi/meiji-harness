# 任务历史按ID读取

- 状态：已完成实现与自动验收（2026-10-17）；未提交/推送，未重启生产服务。

- 类型：重构（性能与数据边界）
- 档位：完整流程（存储、仓库、任务管理器、接口、项目 Model、客户端、测试）
- 目标：内存只保留排队中与运行中的任务（及其组和步骤）；已结束的任务、步骤、提示词与 HTTP 只在数据库，展示时按 ID 查询。项目 JSON 记录各节点最近任务 ID 与需展示的最近任务组 ID。
- 非目标：不改任务执行流程、审核与修订规则；不改幂等记录与通知 outbox 的存放方式（另立任务）。
- 用户决定：内存保留排队中和运行中；页面状态用批量接口按 ID 查；一次做完。

## 设计
1. 内存快照：任务组只要还有排队中或运行中的任务就整组留在内存（满足组内序号连续校验）；整组结束后提交完成时移出。启动只加载未结束的组。
2. 步骤记录：内存步骤不含 `prompt`、`http`。运行中写记录直接更新 `task_steps` 对应行，任务管理器内存保留该步最新记录，并发出 `record` 事件（不改版本号）。
3. 项目 JSON：顶层 `latest_tasks`（`业务类型:目标ID` → 任务ID）与 `latest_groups`（`episode-film:剧集ID`、`shot-film:镜头ID`、`costume-image` → 任务组ID）。放在顶层，不进入任何节点对象，不影响依赖指纹。创建任务时写入。
4. 查询（全部走数据库，运行中步骤记录以任务管理器内存为准）：
   - `/api/meiji/records?group_ids=&task_ids=`：批量返回任务组摘要（组、任务、步骤状态，不含记录）。
   - `/api/meiji/group?group_id=`：任务组详情，含步骤提示词与 HTTP。
   - `/api/meiji/history?status=&business=&episode=&offset=&limit=`：任务历史分页（只读组与任务表）。
   - 会话 `query` 命令按任务/组 ID 查库。
5. 服务端依赖历史处改为查库：继续任务组、取消已结束任务、再次生成判断、提取剧集上次候选与原因、队列序号。
6. 客户端：面板快照只含项目与未结束任务；节点卡、组卡、继续按钮按 `latest_tasks`/`latest_groups` 取 ID，未结束的从快照读，已结束的经批量接口读取并缓存（已结束记录不再变化）；推送中整组结束的视图转入缓存。
