# 任务历史展示重构

- 类型：UI 重构
- 目标：将任务历史列表和详情页改为以查看为主的清晰卡片展示，减少嵌套边框与流程操作入口。
- 非目标：不改变任务筛选、任务加载、提示词/响应/快照读取接口，不改变任务执行状态。

## 验收标准与调研结论

| AC | 输入/状态 → 可观测结果 | 状态 | 依据或缺口 |
|---|---|---|---|
| AC-1 | 打开任务历史列表 → 每个任务只有一个卡片容器，点击卡片任意区域进入详情 | 已确认 | `run-list.js` 当前卡片内嵌任务按钮，只有按钮区域触发进入详情 |
| AC-2 | 打开任务详情 → 每个步骤卡直接显示步骤状态、执行者和时间 | 已确认 | `run-detail.js` 当前步骤主体在 `details` 内，需展开才完整查看 |
| AC-3 | 步骤不通过/有错误 → 详情默认直接显示失败原因与审核问题 | 已确认 | 当前错误与 issues 也在可展开步骤内部 |
| AC-4 | 步骤有提示词/原始返回 → 外层直接显示查看按钮，并可复制提示词 | 已确认 | 当前按钮在步骤展开内容中；`task-prompt.js` 已提供记录读取与复制能力 |
| AC-5 | 任务详情 → 不显示暂停、取消、重试、放行、编辑、提交意见、重新生成等流程操作 | 已确认 | 当前由 run controls、pause reason actions、optional goals 和 feedback actions 渲染 |
| AC-6 | 任务暂停原因/错误信息 → 只读展示，并可复制错误/原因文本 | 已确认 | 当前原因区包含可执行按钮和意见输入 |

## 调用链与影响范围

任务历史入口 → `panel-app.js` → `renderRunList`；任务卡点击 → `openRun` → `renderRunDetail`。详情中的提示词和原始返回继续通过 `loadRecords` 调用既有任务记录接口，删除所有写操作按钮不会改变后端流程。

## 改动

### 阶段 1：任务列表卡片

1. `meiji/client/run-list.js` — 任务标题改为卡片正文，整卡支持点击和键盘进入详情，移除卡片内嵌按钮结构 → AC-1。

### 阶段 2：任务详情只读展示

1. `meiji/client/run-detail.js` — 移除流程控制、意见提交和可选后续操作；步骤改为直接展示状态、失败原因、审核问题、技能、提示词/原始返回查看与复制入口；保留只读快照和事件查看 → AC-2 至 AC-6。
2. `meiji/client/panel-styles.css` — 减少任务卡和步骤卡嵌套边框，建立单层卡片、状态标签和只读原因布局 → AC-1、AC-2。

### 阶段 3：回归测试

1. `meiji/tests/run-view.test.js` — 更新列表/详情断言，覆盖整卡点击、失败默认可见、外层提示词按钮和流程按钮缺失 → AC-1 至 AC-6。

验证：`node --test tests/run-view.test.js`、`git diff --check`。
