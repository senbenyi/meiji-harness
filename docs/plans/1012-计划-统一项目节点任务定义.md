# 统一项目节点任务定义

- 类型：重构
- 目标：按制作工作流建立统一的节点定义，让项目内容、节点状态、单节点任务与任务组职责一致，并保留现有项目 JSON 层级和任务组。
- 非目标：不把项目节点迁入独立 SQLite 表；不删除或扁平化任务组；不改变节点内容字段、任务数据库列和任务组续作语义；不改写提示词正文及制作流程。

## 调用链与证据

项目 JSON 由 `project-contract.js` 校验；任务命令由 `task-contract.js` 验证，再进入 `TaskService.command → #add → stepKinds` 创建任务和步骤。`business_type + target_id` 在 `locateTarget/nodeOf` 中分别解析目标与节点字段；`precheck` 检查节点上游和原始输入；`node-state` 保存节点状态并校验产出；`node-dependencies` 传播过期。任务组独立保存多节点组合，TaskService 串行排队、续作并追加派生任务。客户端和历史标签分别读取节点与任务组。

## 改动

### 阶段 1：统一领域定义

1. `meiji/shared/node-definitions.js`（新增）— 定义 12 个节点的目标类型、项目字段、名称、执行类别及审核策略，并单独列出非节点操作 → AC-1。
2. `meiji/shared/task-contract.js` — 从节点/操作目录派生可用业务类型、节点类型、目标定位和节点字段；保持现有任务命令及数据库记录 → AC-2。
3. `meiji/shared/task-plan.js`、`meiji/shared/node-state.js`、`meiji/shared/task-labels.js` — 从同一目录派生审核步骤、文本节点识别与任务名称，删除被替代的重复映射 → AC-3。

验证：节点目录与 project_detail/step_model 全量对照；合同、产出、任务步骤及历史标签回归通过。

### 阶段 2：保留编排并对齐契约

1. `meiji/server/flow/tasks/precheck.js` — 由节点目录中的前置检查规则键分派到动态规则；保持运行时检查内容和报错行为不变 → AC-2、AC-4。
2. `meiji/dev_docs/项目数据结构.md`、`任务步骤.md`、`step_model.json` — 说明节点目录为静态定义，项目 JSON 保存节点内容/状态，task 指向一个节点，group 编排多个 task → AC-4、AC-5。
3. `meiji/tests/` — 覆盖全部节点定位/处理类别、非节点业务隔离和既有 group 类型/续作 → AC-6。

验证：相关 stage 测试；完整 `npm test` 与 `git diff --check`。无需 SQLite 迁移，因为项目字段和 tasks/task_groups 数据列不变。
