# 修复按钮直接提交与位置调整

- 类型：UI交互修正（完整流程，涉及公共组件及多处测试）。
- 目标：未通过节点的按意见修改改为修复，位于原因说明下方独立一排，直接携带审核原因提交，不弹框。
- 非目标：不改服务端任务协议，不把网络失败原因上传，不改变普通原结果修订弹框。

## 验收标准与证据
| AC | 输入/状态 → 可观测结果 | 已确认依据 |
|---|---|---|
| AC-1 | 未通过且可修改 → 原因下方独立修复行，顶部操作栏不再出现按意见修改 | task-panel.js目前将该按钮加入顶部buttons |
| AC-2 | 点击修复 → 不创建dialog，直接携带未通过原因及公共执行意见提交；有正式内容revise，无内容generate | 现generate已统一携带意见，可直接复用 |
| AC-3 | 网络失败或排队/运行/只读 → 不提供该修复入口、不注入网络原因 | 保持上一轮分类和冻结规则 |
| AC-4 | 正常已有结果 → 原结果修订原交互不变 | 普通editor仅针对非rejectedText保留 |
