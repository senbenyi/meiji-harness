# 镜头表统一出镜与服装

- 类型：完整流程，节点和数据契约重构。
- 目标：镜头表一次确定出镜角色和服装，成片直接开始每秒分镜。
- 非目标：不删除历史任务、媒体或用户角色，不让群演创建角色卡。

## 验收标准
- AC-1：shots输出包含on_screen_characters（character_id/costume_id）及background_characters字符串，正文明确出镜表演和已知着装；有服装目录必须选择所属服装。
- AC-2：镜头表生成/修订/审核读取完整ID和服装资料；卡外群演可表演但不要求建卡、绑定或编造衣服。
- AC-3：成片编排仅seconds→storyboard→适用参数编排→video，无独立识别节点、按钮、路由及运行时旧绑定状态。
- AC-4：所有视频判型、参考图、删除引用、依赖和编辑直接读取镜头表绑定。
- AC-5：v20迁移旧绑定至镜头字段并移除character_binding；旧镜头表及下游生成态标过期，正文/绑定/媒体/历史保留，明确重生成。

## 调用链与影响
当前shots→shot-characters→seconds→storyboard→video。图谱replaceShots/videoType影响CRITICAL；任务静态目录变更影响MEDIUM，涉及任务编排、前置、节点状态、数据存储与UI。

## 改动
- shared模型/contract/collection、shots路由/提示词：镜头字段和校验。
- node-definitions/task-manager/precheck/node-state/node-dependencies：移除识别执行链，保留退役业务元数据用于历史。
- shared/shot-text-inputs、video-inputs、server/handlers及client：改为镜头直接绑定和展示。
- 删除独立识别路由、PromptModel和绑定Model；历史不适配为新任务。
- sqlite/schema/v20迁移及全部受影响测试和业务文档同步。

## 验证
记录全量基线；输出与归属、群演提示词、组编排、逐镜文本/视频、迁移与界面测试；无新增失败。正式数据库备份及副本演练后在无活动任务时重启验证。

## 验证结果
AC-1至AC-5通过。基线482项470通过12失败0取消；修改后481项470通过11失败0取消，无新增失败。核心定向27项通过。数据库备份、副本演练与正式v20迁移成功，29镜头正文/绑定/媒体及所有任务历史保留，完整性、外键和JSON镜像通过。旧镜头表需重生成确认新规则；真实模型生成效果未确认。详见实施记录。
