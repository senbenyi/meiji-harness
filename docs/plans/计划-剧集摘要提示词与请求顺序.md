# 剧集摘要 AI 草稿与全部 API 请求校验重构

- 类型：完整流程；已按用户“开始执行”完成实施。
- 目标：新增剧集先设参考时长，再由 AI 生成摘要草稿并决定实际时长；所有模型/网关 API 在实际请求前校验所需配置。
- 调研：`docs/research/调研-剧集摘要提示词与请求顺序.md`。
- 本文替换前版仅处理摘要密钥顺序的方案。

## 产品行为
1. 新增/编辑剧集弹框顺序：参考时长（秒）→ 本集剧情摘要与「AI 生成」按钮 → 摘要输入框 → 取消/保存。
2. 新增剧集只需先填写有效参考时长即可点 AI 生成，不要求预填摘要，不先创建占位剧集。AI 按钮使用 `type="button"`，不触发摘要 required 的保存校验。
3. AI 结果回填弹框，用户可修改；只有点保存才调用 episode-add/episode-edit 正式落盘。手工填写和保存仍可用。
4. 点击 AI 生成表示基于上游资料重新生成，不将输入框原文偷偷当成基稿。人工定向修改继续使用明确的“修改”模式和意见。
5. 请求期间禁用重复生成及保存；允许取消。取消或关闭时取消关联本地任务，迟到结果不得写回已关闭或重新打开的弹框。输入时长改变则不能应用基于旧时长的结果。
6. 失败保留用户原输入、时长和已保存内容；自审失败保留候选摘要与失败原因，不伪装成已通过。
7. 历史上下文默认取当前集之前的全部剧集，按剧情顺序排列。新增第 N 集取 1…N−1 集；编辑第 K 集取 1…K−1 集，后续集单列为衔接约束。这里不新增“历史剧集多选”控件。
8. 数据层当前按新集在前存储，组装时显式转换为剧情顺序；不得把整个数组反复混用为上下文。历史过长时明确报容量问题，不静默丢弃较早剧集。

## 当前 model 与目标 model
改造前不存在 EpisodeSummaryModel。`episodePrompt` 拼上下文，`buildEpisodePrompts` 读取模式和意见，`interfaces/episode.js` 组合技能。人物图修改的 model/约束分工可参考，但其提前验密钥顺序不能照搬。

新增 `meiji/server/prompts/models/episode-summary-model.js`，数据结构：

```js
{
  mode: 'generate', // generate | regenerate | modify
  role: '短剧分集编剧',
  project: {
    title: '',
    summary: '', // 视频/整部短剧总摘要，主要故事依据
    script: '',  // 可选的已有剧本，不凭空补出
    style: '',
    aspectRatio: '',
    outputLanguage: 'zh-CN'
  },
  target: {
    episodeId: null, // 新增尚未保存时为空
    episodeNumber: 1,
    referenceDurationSeconds: 150, // 用户提供的参考时长
    minDurationSeconds: 130, // max(1, referenceDurationSeconds - 20)
    maxDurationSeconds: 170 // min(86400, referenceDurationSeconds + 20)
  },
  previousEpisodes: [
    // { episodeId, episodeNumber, durationSeconds, summary }
  ],
  followingEpisodes: [], // 仅编辑中间集时使用，不是已经发生的历史
  summaryLength: { min: 1, max: 300 }, // 非空白 Unicode 字符，含标点
  generationRules: '',   // 当前技能快照的固定约束 MD 正文
  modification: null    // modify 时为 { baseSummary, durationSeconds, instruction }
}
```

- model 只保留必要事实、规则与本次操作输入；不含密钥、网关地址、模型凭据、旧任务错误、镜头和图片信息。
- `toSegments()` 生成有来源标识的 system/user 片段，`toMessages()` 输出完整文本请求；不复用图片式单一 prompt，也不访问文件或网络。
- `episode-prompts.js` 负责取值、读取技能快照、赋值 model；model 内部不读取全局 operation context。
- 人工修改的基稿仅在 modify 中存在。自动修订显式传本轮最新候选和本轮审核意见，不能回退到最初旧稿。
- 生成、审核、修订和预览共用 model 及快照；审核/修订需要的新内容由各自接口显式传入。

## 约束 MD 草案
位置：`meiji/skills/constraints/episode.md`。由 episode skill 启用 `fixedConstraints: true`，使用加载器已有默认路径。以下是生成语义正文草案；JSON 协议单独存放。

```markdown
## 创作依据
以视频总摘要为整体故事方向，围绕用户参考时长规划本集容量，由 AI 给出实际时长。
已有剧本是明确事实依据。此前各集摘要按剧情顺序作为已经发生的故事。
无历史剧集时，根据总摘要展开第一集，不虚构“上一集已经发生”的事实。

## 本集范围
只生成指定这一集的故事摘要，不续写为下一集，不一次写多集。
承接此前全部剧集的事件、人物身份、关系、位置、伤势、持物和未解决矛盾。
不得重复已经完成的事件，不无故重置人物状态，不提前演完整部故事。
后续剧集资料仅用于约束衔接，不当成本集之前已经发生的事实。

## 摘要内容
写清本集目标、冲突、行动过程、因果转折、角色决策与结尾状态。
合理续写须符合总摘要、已有剧本和历史事实；保留明确要求的关键事件。
只写故事摘要，不输出镜头表、运镜、机位、角色卡、素材地址或逐秒制作说明。

## 时长
根据事件、对白、行动和转场估计实际时长，结果必须在参考时长上下 20 秒内（含边界）。
生成、审核和修订始终使用本次原始参考值，不能以 AI 上轮时长重新计算浮动区间。
不以摘要字数直接推断时长，不为了机械凑时长删除关键因果；故事容量与返回时长均须匹配。

## 摘要长度
针对通常 2–3 分钟的剧情，摘要必须非空且不超过 300 字符，不要求凑足字数。
字数按去除空白后的 Unicode 字符数计算，标点计入。
保留主要事件、因果转折和结尾状态，不用空泛重复凑字，不展开成逐句对白脚本。

## 重新生成与修改
重新生成只使用总摘要、剧本、本集配置、历史事实和后集衔接约束。
不使用本集旧摘要或历史审核意见。
只有明确的修改模式才使用本次基稿和意见，保留未涉及的事件与顺序。
```

- 原 generate.md 的有效规则与 JS 内固定语义迁入此文件；删除原 generate 字段及重复规则，不留旧路径回退。
- common/review/revise/protocol 保留各自职责；审核标准按上述依据、范围、因果、时长验收，不要求摘要具备镜头细节。
- 空约束文件表示该约束为空；缺文件报错；预览和实际请求读取同一技能快照。
- 若运行数据存在旧 episode.generate 覆盖，实施时提供一次性备份迁移，将有意义的用户补充转移至仍支持的补充字段，删除废弃键；不静默丢弃用户文本，不增加运行时兼容分支。

## 输出协议、时长和字数
- 保留模型响应 `{"summary":"本集完整摘要","durationSeconds":150}`；durationSeconds 必须是整数，由 AI 按剧情容量决定，不接受字符串数字。
- 用户输入字段为 referenceDurationSeconds，默认建议 150 秒；“一般 2–3 分钟”作为典型使用场景，不额外把参考输入锁死为 120–180 秒。
- 后端从参考值计算闭区间 `[max(1, referenceDurationSeconds - 20), referenceDurationSeconds + 20]`，再与领域可保存时长 1–86400 秒取交集。例如参考 120 秒允许 100–140 秒，参考 150 秒允许 130–170 秒，参考 180 秒允许 160–200 秒。
- 删除摘要路径原先固定 180 秒的上限和 `project.durationSeconds = 180` 审核替身；不能误拒绝参考 180 秒、AI 返回 190 秒的合法结果。
- 输入 model 保存参考值与边界，生成结果保存实际时长；审核时同时提供原始参考范围和当前候选实际时长，修订不能让范围漂移。
- 程序校验 summary 非空且不超过 300 个非空白 Unicode 字符（含标点）；采用同一计数函数供后端与 UI 字数提示使用，避免 JS UTF-16 长度与显示值不一致。这是本方案的产品限制，不是字数能证明片长的公式。
- 机器校验实际时长和字数上下界；AI 自审另外检查内容是否能在所报时长内展开。不能仅凭 durationSeconds 合法就判剧情容量通过。
- 超出时长范围或字数范围视为明确可修订问题，进入已有有限次数的修订/复审，不直接截断摘要、不强行夹紧时长、不无限重试；最终仍不合格则保留失败候选用于查看，但不得当作合法结果保存。
- 返回弹框草稿 `{ summary, referenceDurationSeconds, durationSeconds, check, taskId }`，实际时长单独展示，不覆盖参考输入。保存采用校验后的实际时长。
- 手动新增没有 AI 候选时，实际时长采用用户参考值；手动编辑摘要同样检查字数。参考值变化后原 AI 候选失效，不能保存旧候选的时长和审核结论。
- 既有剧集的重新生成可用已保存实际时长作为本次参考值，并在任务快照中固定；成功保存新的 AI 实际时长，删除“existing.durationSeconds 优先覆盖 AI 返回时长”的旧逻辑。
- 不批量改写历史摘要；最多 300 字符的限制作用于新生成和本次提交，历史记录可读取。修改后的候选需重新校验，不继承已失效的审核结论。

## 全部 API 的校验位置
适用 meiji 外部生成与网关请求；浏览器访问本地业务 API 的会话鉴权、输入验证和生产门禁保持在原位置。

统一顺序：读取配置数据 → 准备业务输入/参考素材 → 构建提示词与请求内容 → 进入对应请求步骤 → 校验该次请求所需配置 → 构造认证头并发送 → 处理响应。

| 请求 | 请求前校验 | 不应要求 |
|---|---|---|
| 文本生成、自审、修订、复审及文字编辑审核 | 当前文本用途的地址、密钥、模型 | 图片/视频模型已配置 |
| 人物、场景、部件、铅笔分镜生成或修改 | 图片地址、密钥、模型及该接口参数 | 文本/视频模型已配置 |
| 视频提交 | 视频地址、密钥、模型及视频输入 | 文本/图片模型已配置 |
| 视频状态轮询与网关视频下载 | 本次网关地址、密钥、任务标识 | 无关模型名 |
| 网关同源图片下载 | 地址及该网关认证 | 无关模型配置 |
| 第三方图片下载 URL | URL 安全校验；不发送网关凭据 | 第三方要求网关密钥 |

- `loadModels` 改为仅读取并展开各用途路由，不再调用带密钥必填的 normalizeModels。
- 在 `generate/gateway.js` 实际 fetch 前统一执行请求配置校验与凭据归一化；生成接口声明所用用途/必要字段，下载和查询不能套用生成接口的模型要求。
- 去掉 chat.js、film.js、图片操作入口等提前阻断逻辑，缺配置在正确请求步骤失败，由已有 API 失败机制处理。
- 移除图片流程以 apiKey 有无选择网关/ComfyUI 的隐式回退。清查调用图后删除仅为此回退存在的执行器、环境变量读取、轮询、工作流模板、参数和测试；仍被其他明确功能使用的代码不盲删。
- 不记录空密钥请求为“已发送”；错误归入 API 请求步骤，fetch 为零。正常鉴权头与日志脱敏统一处理。
- 模型设置保存仍校验用户提交配置；这是保存行为，不应在只读取配置、预览提示词时触发。

## 草稿生成与保存逻辑
1. 前端传 projectId、referenceDurationSeconds、可选 episodeId、operationId；服务端读取最新项目并固定上下文快照，不信任前端上传的历史摘要。
2. 新增 `episode-summary-draft` 项目级操作，设置 `agent: false`，经既有任务队列、步骤、鉴权和取消机制执行。不能直接从弹框调用外部 API。
3. 不调用 addEpisode/editEpisode，也不调用会清空已保存节点的 prepareChecks；生成、自审、必要修订使用同一个 generateEpisode 内核，在任务内保存候选结果。
4. 用任务结果返回草稿、审核信息、输入时长和输入版本标识；补齐任务记录中的结果读取，保证查询任务能取到草稿。不得额外创建平行任务框架或新一套状态推导。
5. 弹框只接受仍匹配本次请求和输入时长的结果。生成失败不覆盖原文本；审核未通过的草稿可展示和修改，不冒充通过状态。
6. 点击保存才调用现有 episode-add/episode-edit。仍走现有保存和门禁语义，不因为 AI 填过内容就自动视为审核通过。
7. 已保存剧集的“重新生成”复用同一个 model 和生成内核，继续按现有步骤持久化；新草稿尚未保存时 API 失败恢复旧内容，已保存新草稿后审核失败保留新稿。
8. 人工修改摘要后不得沿用修改前 AI 审核结论。取消本地任务不宣称取消已发出的远端请求；不自动恢复旧轮询任务。

## 验收标准
- AC-1：所有生成/网关 API 只在请求边界检查凭据，前置数据与提示词组装不依赖密钥。
- AC-2：只检查本次请求所需配置，缺密钥不回退其他执行器，不对第三方下载泄露密钥。
- AC-3：摘要 model 和 MD 分工清晰，单一组装路径，预览与请求一致，旧实现删除。
- AC-4：总摘要 + 参考时长 + 全部前集摘要生成目标集；AI 实际时长在参考值 ±20 秒内，摘要非空且最多 300 个非空白字符，重新生成不混入旧稿。
- AC-5：新增剧集可从空摘要直接 AI 生成，保存前无正式剧集写入。
- AC-6：保存、取消、输入变化、请求失败和审核失败均保持正确数据与状态。

## 边界测试补充
- 参考 150 秒：130、170 通过；129、171 不通过；小数或字符串时长不通过。
- 参考 180 秒：190、200 通过，201 不通过，不能沿用旧 180 秒硬上限。
- 摘要 299、300 字符通过；301 字符、空字符串或纯空白不通过；空白不计数，标点和 Unicode 字符口径一致。
- 生成与修订均使用原始参考范围；返回实际时长被保存，未被参考值或既有时长覆盖。
