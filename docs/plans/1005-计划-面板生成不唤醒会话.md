# 面板单次操作接入 Harness goal 并在完成后结束

- 类型：Bug 修复，完整流程。
- 目标：面板生成以当前操作为唯一目标，登记真实 Harness goal 和会话 job；目标结算后模型只汇报本次结果并 end。
- 非目标：不取消 job 登记，不扩展为整部短剧制作，不覆盖用户其他目标，不改变用户明确授权的会话多步骤流程，不重做全功能页面测试。

面板 → POST turn → startPanelOperation → resolveAgent → panelGoals.begin → goals.create/disarm → jobs.start → manager.start → manager.whenEnded → goals.complete/block → job settled → tool-jobs 通知 → job_output → 汇报后 end。

| 来源 | 结论 |

| Harness packages/goal/goal/src/index.ts 的 create/disarm/complete/block/clear | 公开目标生命周期；每会话唯一目标，变更校验 id/revision |

## 决策
用户明确选择「必须接入 /goal，将当前操作设为目标并在完成后关闭」。使用真实 goal 服务，业务仍由现有引擎执行；目标 active 时立即 disarm，避免 round-driver 再次发起生成。成功 complete；失败、审核未通过、取消均 blocked/disarmed，不能假称目标达成。
其他未完成目标返回 409，不覆盖。关联业务已结束的自有目标可恢复结算；本适配器结算的失败/取消目标在再次点击时清理后建立新目标。人工编辑或暂停导致 ref 改变时不自动覆盖。
摘要草稿与手动 script-sync 也统一经过面板 goal/job 入口；业务内部自动回写仍由原流程执行，不重复建立目标。直接保存、删除等非生成操作不经过模型。
