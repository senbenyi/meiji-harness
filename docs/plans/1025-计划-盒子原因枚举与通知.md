# 盒子原因枚举与通知

- 类型：完整流程，公共任务模型、失败持久化、报告与界面/通知。
- 目标：原因使用单一枚举，网络连接失败正确显示且不唤醒主Agent。
- 非目标：不改HTTP连接和响应超时、重试次数，不删除用户数据，不改内容审核协议。

## 验收标准与取证
| AC | 状态 → 可观测结果 | 证据 |
|---|---|---|
| AC-1 | 网络失败 → reason_type/stop_code均network_connection_failed，界面显示网络连接失败 | 当前failure-decision将failed固定映射执行错误；异常code未持久化 |
| AC-2 | 项目创建网络失败 → 展示结果但不agent.followup，重启也不补发 | report_dispatcher仅排除requires_user_decision，project不在该列表 |
| AC-3 | 所有终态 → 使用同一枚举验证、分类、展示；未知枚举拒绝 | 现有9类stop_code散落于模型/投影/界面 |
| AC-4 | 已存网络失败记录 → 显式一次性迁移为结构化错误码，不运行时解析文案 | 旧步骤只存error_reason，采用SQLite迁移，不删除记录 |

## 调用链与影响
HTTP NETWORK_CONNECTION_FAILED → TaskManager catch → failed Step → boxReport/projectExecutions → displayContext/失败卡片与ReportDispatcher → 主Agent。
根因一：错误码在TaskManager只存message后丢失；根因二：UI将failed当原因；根因三：project失败仍notify_main。
图谱有效；ReportDispatcher、TaskManager、NodeStateModel均CRITICAL，已提前告知。未解析符号用源码调用方检索补查。
