# 任务生成按钮按内容状态互斥

- 类型：Bug 修复
- 目标：让每个任务节点根据现有内容和审核状态显示明确、互斥的生成操作。
- 非目标：不改任务协议、前置检查、节点状态流转、审核规则和历史记录。

## 验收标准与调研结论

| AC | 输入/状态 → 可观测结果 | 状态 | 依据或缺口 |
|---|---|---|---|
| AC-1 | 无有效内容 → 只显示“AI生成”，点击提交 `generate` | 已确认 | 新增 UI 测试验证按钮互斥及实际请求动作 |
| AC-2 | 有内容且状态 `generated` → 只显示“重新生成”，点击直接提交 `regenerate` 且不带意见 | 已确认 | 新增 UI 测试验证无弹窗直接提交 |
| AC-3 | 有内容且状态 `rejected` → 显示“重新生成”和“按意见修改”；意见操作拒绝空白输入，提交 `regenerate` 与修订意见 | 已确认 | 新增 UI 测试验证空意见校验与非空载荷 |
| AC-4 | 有内容的过期节点显示“重新生成”，无内容的失败节点显示“AI生成”；各业务节点使用同一映射 | 已确认 | 新增 UI 测试验证两个边界状态；共享 `nodeCard` 用于各类节点 |

## 调研与计划

`renderTaskPanel` 的 `nodeCard` 对所有节点始终渲染 AI生成和重新生成；重新生成又通过一个可选意见弹窗混合了两种意图。节点契约用 `empty`、`generated`、`rejected` 等状态标记产物与审核结论，任务规则明确区分接口失败与审核未通过。故修复范围在共享节点卡片：用实际产物判断生成/重生成，用 `rejected` 附加必填意见操作。

GitNexus 对 `renderTaskPanel` 的 upstream 影响为 CRITICAL：116 个符号、42 条流程、10 个模块，包含 107 个直接调用方；首轮默认 100 项被截断，提升到 200 后完整返回。实际修改仅涉及通用节点卡片的本地按钮渲染和面板测试；手工核对动态节点入口覆盖项目摘要、故事大纲、本集资产、镜头表、每秒分镜、文本提示词、视频、尾帧、合片及角色/服装图片。

### 问题

| AC | 预期 | 实际 | 根因 |
|---|---|---|---|
| AC-1–3 | 主生成按钮随节点内容/审核结论互斥 | 所有节点卡片一律出现 AI生成与重新生成，意见没有独立必填入口 | `nodeCard` 未读取节点产物，两个语义被一个可选意见编辑器混用 |

### 改动

1. `meiji/client/task-panel.js` `nodeCard` — 删除同时显示两个生成按钮及可选意见混用；根据是否有有效节点产物显示一个生成操作，并仅在 `rejected` 时增加必填意见操作 → AC-1–4。
2. `meiji/tests/stage07-task-actions.test.js` — 验证空/已通过/未通过/失败/过期节点的互斥按钮和实际命令/意见载荷 → AC-1–4。
3. `meiji/tests/stage07-film.test.js` — 已有视频内容的测试改点“重新生成”按钮，保持单镜完整组请求验证 → AC-2。
4. `meiji/dev_docs/任务步骤.md` — 记录节点操作按钮与状态对应规则 → AC-1–4。

基线：`node --test tests/stage07-panel.test.js tests/stage07-film.test.js tests/stage07-button-regressions.test.js`（10 项通过）。实施后验证定向 UI 测试、`npm test`、`git diff --check` 和 GitNexus detect-changes。
