# AI任务记录与刷新恢复

- 类型：完整流程，跨 meiji-harness 与 meiji-server。
- 目标：AI 请求在服务端独立执行并记录，App 刷新或重启后取回原请求状态与结果，不重复调用 AI。
- 非目标：同步整个业务数据库；自动恢复已终结的旧任务；恢复 meiji-server 自身重启前的推理；绕过审核直接发布原始结果。
- 用户确认：按推荐仅记录每次 AI 请求及结果。复用现有 step.id、step.http、任务状态与服务端记录，不改变项目/任务/步骤 JSON 字段定义。

## 验收标准与调研结论
| AC | 输入/状态 → 可观测结果 | 调研 |
|---|---|---|
| AC-1 | 带异步标志提交文本/图片/视频 → 立即收到请求标识，断连后继续执行并存结果 | server.js 当前依赖 HTTP 连接，需修改 |
| AC-2 | 同一步骤重复提交/刷新 → 查询同一记录，AI 只执行一次 | 服务端已有幂等键；App 文本尚未关联步骤 |
| AC-3 | 页面刷新 → 保留运行中业务并读当前状态 | workbench 当前首次加载取消所有任务 |
| AC-4 | App 后端重启，步骤已有可恢复 HTTP 记录 → 查询原请求，续跑审核/下载/保存 | TaskService.recover 当前全部取消 |
| AC-5 | 失败/取消/interrupted/记录缺失/结果过期 → 原因可见，无自动重生成 | 需显式区分查询故障与终态 |
| AC-6 | 用户取消 → 停止服务端请求；App 服务关闭 → 仅停止本地等待 | 当前两者都通过断连取消 |
| AC-7 | 已取消旧任务或没有恢复标识的运行任务 → 不复活/不猜测执行 | 保留旧任务终态及安全结算 |
| AC-8 | 取回结果 → 沿原契约、审核、修订与事务提交；结果与成功状态一致落库 | 当前 finishTask 先改状态再存结果，需事务保护 |

## 调用链与证据
App TaskService.#run → text/media handler → createAiRoutes → llmServerClient → meiji-server ledger → SQLite；恢复反向按步骤 ID 查询，再走原处理器和提交链。

- `meiji-server/src/jobs/routes.js` 已提供状态/结果查询；tasks.js 保存结果并将服务重启遗留记录记 interrupted。
- `meiji/server/http/llm-server/params.js` 图片/视频传业务任务 ID，文本未传；新方案统一按每个 AI 步骤 ID。
- 现有 step.http 支持请求头及请求地址，发送前 await recordTransfer 已落库，可用于识别新协议和原服务地址。
- TaskService 每个步骤结束及业务提交同事务；恢复必须重建最近成功候选与校验失败原因，不能只把 running 改 ready。
- GitNexus：meiji-harness 图谱仅计划文档变化，源码有效；TaskService CRITICAL（20 直接引用），createAiRoutes HIGH；sendChat LOW，媒体调用 MEDIUM，mount MEDIUM。chatParameters UNKNOWN 已用源码确认动态调用。meiji-server 未启用图谱。

## 改动
1. meiji-server：异步受理与断连独立执行、幂等重放、明确停止鉴权、事务保存结果与成功状态；补 HTTP 回归测试。
2. App HTTP：新建共用服务端任务提交/查询适配器；步骤 ID 作为任务号和幂等键，发送前落 HTTP 记录；恢复只查询，不能重新 POST；明确取消发送 stop，服务关闭不发送 stop。
3. App 编排：移除页面首次刷新取消；恢复仅接回可识别请求的业务，重建已完成步骤候选，继续未完成步骤；兼容旧运行任务安全取消。
4. 同步制作工作流、接口说明、测试及实施记录。

## 验证
两仓库全量测试基线与改后结果；覆盖 queued/running/succeeded/failed/cancelled/interrupted/404/结果过期、重复请求、断连、显式停止、原步骤审核续跑、旧记录不重放。使用本地 mock，不调用付费 AI。
