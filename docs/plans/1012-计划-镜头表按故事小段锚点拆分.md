# 镜头表按故事小段锚点拆分

- 类型：提示词规则优化
- 目标：先把每个故事小段作为独立镜头锚点，再仅在该小段内部按动作、对白和反应拆成 1–15 秒镜头。
- 非目标：不改项目数据结构、不新增镜头来源字段、不改变故事小段时长之和及整集镜头表 ±30 秒校验、不要求各小段镜头时长精确等于小段时长。

## 调研与证据
调用链：TaskService 文本步骤 → `createTextHandler` → `promptValues` 注入本集故事大纲小段及参考时长 → `yaml-prompts` 渲染 `shots-{generate,regenerate,review}.yaml` → chat 接口 → JSON/镜头时长程序校验。GitNexus 对 `createTextHandler` 的 upstream impact 为 HIGH，13 个受影响符号、2 个流程、3 个模块；本计划不改共享执行器，只改 3 份镜头专属 YAML 和对应渲染测试。

## 本轮补充规格：取消镜头数下限并落实时长预算

- 用户明确要求删除“镜头表目标最少镜头数 20”限制；镜头数量仅由故事事件和 1–15 秒单镜时长自然决定，不再传入或校验最低数量。
- 时长控制采用“每个故事小段的时长作为段内初始预算 → 按真实事件拆镜并逐镜累计段内小计 → 小段间只做有限调配 → 整集目标以参考时长为中心并满足现有 ±30 秒硬范围”。不以镜头数凑时长，不虚构停顿/事件，不要求段内精确等于预算。
- regenerate 的直接重生成须提供当前镜头表作连续性/编号参考；修订仍提供实际待修订草稿和意见。
