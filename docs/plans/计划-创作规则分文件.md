## 执行步骤

### 阶段 1：规则与工作流
1. `dsh-elysium/resources/production-rules/{story,scenes,segments,shots,h3-prompt}.md` — 新增：内联规则 → 按职责编排的输入输出、判断标准、正反例 → AC-1。
2. `dsh-elysium/src/server/projects/production-rules.js` — 新增：固定阶段映射、按请求读取文件、替换目标时长 → AC-2。
3. `dsh-elysium/src/server/projects/production.js:context` — 修改：内联提示词 → await 加载规则，其他业务不变 → AC-2。
4. `dsh-elysium/tests/production-rules.test.js` — 新增：四阶段上下文路由、时长、未知阶段、独立发布包及缺文件错误 → AC-2/3。

验证：针对性 Node 测试和 build；现有时长/衔接/审核校验继续通过。

### 阶段 2：发布与运行
1. `dsh-elysium/package.json:files`、`scripts/registry.mjs:files` — 修改：发布范围增加 production-rules 子目录 → AC-3。
2. `harness/.dsh/.agent-presets/elysium-{creation,director,free,teaching}/rules.md` — 修改：旧流程工具 → 当前 production 流程，同步对应本机文件 → AC-4。
3. `dsh-elysium/README.md` — 修改：说明五份规则及加载/部署方式 → AC-1/3。
4. `.claude/progress.md` 和本任务调研/计划/实施记录 — 新增或局部更新：验证证据 → AC-1～4。

验证：全量插件与 Harness 测试、build、package:registry、隔离 Registry/npm 资源加载、空闲状态检查后重启与页面检查。

## 验收标准
- AC-1：五份规则各有职责、输入、输出、判断规则和正反例。
- AC-2：四阶段显式加载正确文件和实时目标时长，文件缺失报错。
- AC-3：源码、独立 Registry 和 npm 包均含可加载规则。
- AC-4：预设使用当前工具，测试构建通过，本机重启并加载新规则。

## 验证结果
AC-1～4 均通过：15 项针对性测试、227 项插件测试、10 项 Harness 测试、构建、Registry 与实际 npm 包隔离加载、本机工具只读回验及重启页面检查。详见 `docs/implement/实施-创作规则分文件.md`。
