# App 刷新取消进行中任务

- 类型：Bug 修复，完整流程。
- 目标：App 重新加载后，取消当前项目遗留运行任务，Model 保存取消状态后再渲染。
- 非目标：服务端任务缓存与恢复、队列启动入口、清理既有排队任务、其他项目任务。
- 用户已明确采用当前粗暴取消策略，覆盖旧的刷新后继续后台执行行为；不等待二次审批。

## 验收标准与调研结论
| AC | 输入/状态 → 可观测结果 | 状态 | 依据 |
|---|---|---|---|
| AC-1 | 重新加载时当前项目有 running 任务 → 任务、对应节点取消，旧正文保留，再渲染 | 已确认实现路径，未验收 | workbench.mount/refresh → sendCommand(cancel) → TaskService.command/#finish → ProjectModel.update |
| AC-2 | 初始化并发刷新 → 只取消一次；之后普通刷新、事件刷新、恢复可见 → 不取消新任务 | 未验收 | mount 当前 follow 与显式 refresh 会并发调用，需共享初始化 Promise |
| AC-3 | 旧请求晚到 → 不覆盖已取消状态和旧正文 | 已有测试，待回归 | TaskService 的 abort 和 running 终态检查；stage04-task-queue S4-07 |
| AC-4 | 取消失败 → 报错，不伪造 Model/UI 已取消；再次刷新可重试 | 未验收 | 所有状态仍取服务端快照 |
| AC-5 | 无运行任务 → 保留排队任务和历史终态 | 未验收 | 只选择首次快照中的 running 任务 |

## 调用链与证据
- client/panel.js 动态加载 workbench.mount；mount 首次 refresh 读取 context，旧实现直接 paint。
- server/http/task-routes.js context 原样返回 ProjectModel.read；不在 GET 中修改状态。
- TaskService.command(cancel) 在事务中结算任务/步骤/节点，保留内容，暂停队列，同组后序按现有规则作废；提交后 abort。
- TaskService.#loop 在异步结果返回后检查 signal 与任务终态，禁止晚到写入。
- GitNexus status 索引覆盖 318 文件且有效；query/context 结合源码确认调用链。impact(mount) 返回 CRITICAL（152 影响项、105 直接项、33 流程），已向用户说明。实际入口以 panel.js 和 mount 测试补查，限制变更到初始化。
