# 提示词编排简化

- 类型：重构
- 目标：减少文本提示词的编排层次、重复代码与无效内容，统一请求结构，降低单镜请求体量。
- 调研：docs/research/调研-提示词编排简化.md

## 待用户决定
无。用户（2026-10-02）确认 1–5 阶段全部执行：阶段 4 精简上下文执行；审核标准随阶段 3 移到 system；阶段 5 剧情/摘要并入统一组装器。

## 改动
### 阶段 1：删除无效内容（行为不变）
1. `meiji/server/prompts/skill-prompts.js:generationParts/reviewParts` — 删除恒空字段 `common`、`commonShared`、`guidance`、`selfCheck`、`shared` → 各 Model 去掉对应展开 → AC-3
2. `meiji/server/prompts/interfaces/{shots,seconds,shot-revise,image-prompt,storyboard}.js` — 转发文件删除，`interfaces/registry.js` 直接映射到 Model → AC-1
3. `meiji/server/http/skill-routes.js:56–57`、`interfaces/outline.js:sections` — 删除按旧小节裁剪 skill 的遗留逻辑 → AC-3

验证：改前改后各执行 `node tests/fixtures/prompt-scenarios.js` 生成场景，再用 `scripts/prompt-diff.js` 对比 — 除删除的空标题外无差异；`npm test` 不新增失败。

### 阶段 2：步骤 Model 合并为一套组装器
1. 新建 `meiji/server/prompts/models/text-step-model.js` — 一个 `TextStepModel`，按配置生成三类请求；配置项：`stage`、`role`、`reviewRole`、`json`、`outputProtocol`、`scope`（单镜范围说明，可选）→ AC-2
2. `models/{shot-table,episode-seconds,shot-seconds,shot-revision,image-prompt}-model.js` — 各改为 5–10 行配置导出，或合并到一个配置表 → AC-2
3. 去掉 `requestTask()` 改写 skillSet 的做法：生产规则与审核标准作为显式参数传入组装器 → AC-2

验证：同阶段 1 的场景差集应为零差异；`step-prompt-model`、`prompt-nodes`、`skill` 测试通过。

### 阶段 3：结构化入参与统一请求结构
1. `meiji/server/prompts/shot-prompts.js`、`story-prompts.js`、`episode-prompts.js` — 由拼接字符串改为传入对象：`{ task, facts: [{ title, text }], requirements, opinion, baseContent }` → AC-4
2. `skill-prompts.js:requestContext`、`interfaces/text-context.js:withRequirements` — 删除；`reviewInstructions` 改为只含审核目标与上游事实，不再复制生成指令 → AC-4
3. 组装器固定顺序：system＝角色 → 规则（生成/修订用生产规则，审核用审核标准）→ 本节点补充 → 语言 → 协议；user＝任务 → 上游事实 → 基稿/意见 → 待审内容 → AC-6（若用户决定暂缓，审核标准保留在 user，只统一其余顺序）

验证：场景差集只出现预期的位置移动与生成指令移除；`npm test` 不新增失败；真实项目各步骤跑一遍，自审结论与改前抽样对比。

### 阶段 4：精简单镜上下文（待用户确认）
1. `shot-prompts.js:shotContext` — 相邻镜头的每秒指令只保留前镜最后一段末态与后镜第一段起始状态，不放全文 → AC-5
2. `shotContext` — 人物/场景卡只放本镜关联的卡片；大纲只放与本镜相关的「因果剧情」节拍和结尾状态，其他小节不放 → AC-5
3. 镜头表输出协议中的两镜完整示例改为一镜，审核请求不带生成侧输出协议与示例 → AC-5

验证：真实项目同一集改前改后各跑一次，统计每类请求平均字数（目标下降 30% 以上）与自审首轮通过率（不下降）。

### 阶段 5：剧情/摘要 Model 并入统一组装器（可选）
1. `models/story-{outline,character,scene,props}-model.js`、`episode-summary-model.js`、`interfaces/outline.js`、`interfaces/episode.js` — 保留各自的上下文构造，三类请求的组装交给 `TextStepModel` → AC-1、AC-2

验证：同阶段 2。

## 验收标准
- AC-1：一个文本步骤从操作到消息不超过 4 层，转发文件删除。
- AC-2：步骤 Model 共用一套组装器，各自只声明差异配置。
- AC-3：不再返回恒空字段；渲染结果除删除空段外逐字不变。
- AC-4：结构化入参，不解析「【本次任务】」，审核不收到生成指令。
- AC-5：单镜相关请求平均字数下降 30% 以上，自审通过率不下降。
- AC-6：生成、修订、审核统一 system 放规则与协议、user 放任务与资料。

## 验证结果
执行于 2026-10-02。

- 阶段 1＋2：删除 6 个恒空字段、5 个转发接口和 5 个复制的步骤 Model，新增 `models/text-step-model.js`。场景差集（30 场景、137 个 system/user 字段）与改前逐字相同，0 处变化。
- 阶段 3＋5：新增 `request.js` 统一请求结构；剧情四类合并为 `models/story-model.js`；摘要 Model 改用同一组装；`shot-prompts.js` 改为 `{ task, review, facts }`；删除 `requestContext`、`withRequirements`、`interfaces/text-context.js` 与 `reviewInstructions`。审核标准移到 system，审核只收到审核目标。差集报告见 `meiji/reports/2026-10-02-prompt-simplify/差集.md`：全局删除的 25 句均已核对（审核 JSON 说明由统一审核协议承担、镜头表示例第二镜、相邻镜头整段每秒指令、改由标题承担的「镜头原文/本集摘要/大纲」前缀），无生产规则丢失。
- 阶段 4：单镜上下文只带本镜及前后镜关联卡片、前镜末段与后镜开场；大纲存在时不重复摘要；镜头表协议示例改为单镜。接近真实体量的项目测量（8 镜、5 人物、4 场景）：单镜每秒指令生成 16421→11007（-33%）、审核 14443→9029（-37%）；单镜修订生成 14529→9115（-37%）、审核 13577→8163（-40%）；镜头表生成 11973→11303（-6%）。整集步骤需要全部资料，变化小。
- 层次：文本步骤为 操作 → generate → shot/story/episode-prompts → text-prompts 分发 → Model（request.js 组装）。`server/prompts` 代码 1848→1570 行（含同期他人改动）。
- `npm test`：439 通过、27 失败，与改动前基线失败集完全相同（均为既有失败，多数为缺少 jsdom 的 UI 测试）；新增 3 项测试覆盖审核不带生成指令、system/user 分工、单镜上下文裁剪。`git diff --check` 通过。
