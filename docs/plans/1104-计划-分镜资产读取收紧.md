# 分镜资料首轮完整提供

- 类型：完整流程（分镜输入行为及新增模块、测试）
- 目标：按用户最新澄清，文字分镜首轮一次提供当前故事段完整正文、衔接、改编指导和已有资产定义；审核/修订同时提供当前候选，不再让模型逐项读取。
- 非目标：不做资产精简索引，不改资产权威字段、图片库、审核门槛，不承诺模型固定调用次数，不修改历史任务资料。

## 验收标准与调研结论

| AC | 输入/状态 → 可观测结果 | 依据 |
|---|---|---|
| AC-1 | 开始分镜单元 → 完整正文、衔接、改编指导、资产定义均在首轮 unit.material | 当前项目每段完整资料约 1.5 万字符，可一次提供 |
| AC-2 | 审核/修订 → 首轮 candidate 提供完整当前候选，读取校验认可本轮真实传入事实 | 保持审核证据与结构/来源验证，不用空内容冒充已读 |
| AC-3 | 多段连续执行 → 后段看到前段新增资产，同单元后续沿用冻结资料 | text_executor.executeUnit 的 prepareUnit hook 在每单元快照写入前调用 |
| AC-4 | 正常完整输入 → 不暴露重复读取同份资料的工具；超大资料/候选 → 明确未内联并保留分页回退 | 内部 complete 模式首轮资料+候选上限 64000 字符；其他盒子保持原有 16000 行为 |
| AC-5 | 图片引用和历史 → 完整保留原有定义/ID/选图，旧 Task/Step 不修改 | 只投影当次冻结输入，不读取图片二进制、不迁移或重放任务 |

## 调用链与影响

prepareText 仅提前列出单元，不能在这里冻结全部资料，否则后段看不到前段资产。完整资料按每段实际开始时的 project 构造。
