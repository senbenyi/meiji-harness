# 项目原稿摘要自动提取

- 类型：新功能，完整流程。
- 目标：项目盒子创建时有原稿则提取摘要，无原稿跳过；导入/替换原稿后自动重新提取。优化稿继续随正文返回摘要，不增加调用。
- 非目标：不新建摘要盒子/主Agent工具，不改优化器，不改meiji或外部Harness，不补算历史项目摘要，不新增时长字段或摘要编辑/审核UI。

## 验收标准与依据

| AC | 输入/状态 → 结果 | 依据 |
|---|---|---|
| AC-1 | 创建有原稿 → 创建程序步骤后执行AI摘要步骤，保存原稿摘要；无原稿 → 只创建、不调用模型 | 当前只有创建程序步骤；根插件可注入所选文本模型 |
| AC-2 | 面板或工具导入/替换原稿 → 原稿先持久化，再在同盒子提取新摘要，清除旧摘要避免错配 | 当前editProject.import_script只改正文 |
| AC-3 | 摘要调用 → 有任务/步骤/提示词/llm-http记录，归project盒子；优化仍仅generate/review原流程 | 公共TaskManager支持nextSteps；原优化output已含summary |
| AC-4 | 模型异常/无效JSON/中途换稿/取消 → 不覆盖新内容；保留已创建项目或已导入原稿，准确返回摘要失败 | ProjectManager队列/CAS、任务不可变终态可复用 |
| AC-5 | 并发重复/已完成请求重试 → 不重复创建/同一请求不重复提取，后续编辑保留摘要字段 | 现有幂等创建索引；导入提供稳定request_id |

## 字段与职责

新增basic_info.original_script_summary（string，初始空，程序写入AI摘要），与原始剧本对应；不作为创建/人工编辑可写字段。basic_info原人工字段校验保留这个只读字段。优化稿继续使用script_revision.output.summary，二者不混用。
摘要功能在项目盒子summary_extractor.js中实现，程序编排一次有界llm-http并验证{summary:string}，不继承会话历史、不用工具、不进入生成审核循环。业务Service显式配置摘要依赖；根插件生产入口启用，独立纯存储单元不隐式访问模型。

## 调用链与影响

创建：Service→program create→AI extract_summary（仅有原稿）→CAS保存→终态。
导入：Service提交project.import_script任务→program import→AI extract_summary→CAS保存→终态；修复上游的import_script也追加相同步骤。
摘要失败不阻断主操作，任务完成但结果明确包含summary_error，API/Tool返回warning，不触发主Agent规划；取消仍按取消终态处理。原稿先保存，失败后不撤回业务数据、不假称摘要完成。
GitNexus索引有效，已检查ProjectService/createProject/editProject/boxReport的impact，均按共享项目/任务链路风险核对。动态根组装及路由/客户端由源码补查。
