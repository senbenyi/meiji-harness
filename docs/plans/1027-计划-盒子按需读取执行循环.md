# 盒子按需读取执行循环

- 类型：完整流程，模型接口与关键业务流程改造。
- 目标：已实现的文本盒子每个阶段首轮仅发送阶段、目标、skill/资料索引及工具定义；模型后续选择读取并提交结果，保留审核和修改状态机。
- 范围：剧本优化、大纲、场景、团队、人物、分镜及项目原稿摘要；公共客户端扩展工具响应接口。图片生成仍使用真实图片接口，不伪装为聊天工具协议；尚无Executor的视频提示词不新增生产入口。
- 非目标：不实现局部JSON编辑、长期记忆、自动跨盒子执行或无限重试；不覆盖现有项目规则，不修改外部meiji-server。

## 验收标准与取证

| AC | 输入/状态 → 可观测结果 | 依据/验证 |
|---|---|---|
| AC-1 | 每个新阶段 → 首个llm-http请求只有目标、语言、索引与执行约定，没有规则/资料正文 | 抓取真实模拟请求，使用独有正文标记断言 |
| AC-2 | 模型请求读取 → 只返回本盒子skill、当前资料或本Task记录；支持多轮和批量读取 | 原生tool_calls及JSON Pointer测试 |
| AC-3 | 修改/审核 → 必须读取最新候选及全部旧问题，审核独立上下文、仅能提交审核结果；修订后再审核 | 集成生成→审核→修订→审核，证据与旧问题回归 |
| AC-4 | 无效候选或审核证据 → 工具返回具体校验反馈，原阶段继续；不得保存/通过 | 现有结构/引用/证据校验复用，输出修复预算2次 |
| AC-5 | 多次模型请求 → 每次一个Step、一份prompt与llm-http记录；同阶段追加消息连续，切阶段独立 | TaskManager禁止同一步多prompt，按nextSteps续接 |
| AC-6 | 私有规则/补充规则 → 快照作为可读权威资料，必须读取且不被默认skill覆盖 | 定制base与补充规则测试；默认相同时使用拆分skill |
| AC-7 | 取消、连接失败、上游/规则冲突、重复候选问题、内容修订上限 → 沿用原语义 | drama及公共包回归，工具循环另设有限调用预算 |
| AC-8 | 原complete文本接口/媒体调用 → 返回与协议保持兼容，新turn接口保留工具消息 | 公共http-client测试，全工作区、verify:copy/install |

## 调用链与影响

Service提交Task/input_snapshot → Executor组装本阶段资料 → 新box_model_runner单轮请求 → modelClient.turn → 已有模型服务原生tool_calls → 本地只读工具/提交校验 → nextSteps续接同阶段或沿原Executor进入审核/修订。

TaskManager每Step仅允许一份prompt，因此不在单Step里隐藏多次模型调用。记录通过原Task上下文写入，不直写任务数据库。
独立审核只继承候选、依据及可读历史事实，不自动继承作者会话。程序保留状态机和保存职责，模型不能跳阶段或写项目文件。

GitNexus前置status仅旧实施文档过期，已analyze刷新。query/context核对文本盒子；执行器类impact为CRITICAL（约156–158符号，163流程），已向用户说明。公共sendChat/chatParameters查询UNKNOWN，源码已核对complete→chatParameters/sendChat及公共测试；不将UNKNOWN视为无影响。StorySegmentsExecutor沿用前一任务CRITICAL分析，编辑前补查。所有既有待提交skill文件及文档保留。

## 改动

1. 公共客户端：chatParameters可透传tools/tool_choice；sendChat可返回校验后的assistant消息；modelClient.turn新增，不改变complete。
2. drama节点运行层新增skill目录读取与单轮工具执行器：索引不含正文，资料按名称/Pointer读取，提交校验和调用预算，阶段消息与读记录随Step持久化。
3. 六个文本Executor及项目摘要接入，过滤中间读取Step，记录终轮trace，保留原保存/内容审核状态机；删除大纲执行器的重复内嵌规则，改为按需读取本地skill。
4. 迁移模型模拟器以执行原生工具交互，保留既有业务断言；新增原始请求、阶段隔离、非法调用、校验反馈、取消/失败等测试。
5. 同步开发入口/业务文档及skill待接入说明；不改私有项目数据。
