# 人工放行移至修复行

- 类型：小改动
- 目标：节点公共 UI 中「人工放行」从顶部操作按钮行移出，与「修复 / 修改」放在同一排，位于未通过原因下方。
- 非目标：不改人工放行的显示条件与提交命令；不改提取剧集卡（project-ui.js）自有布局。

## 验收标准
| AC | 输入/状态 → 可观测结果 |
|---|---|
| AC-1 | 节点未通过且有原因、可修复 → `.node-ui-repair-row` 依次为「修复（再给 N 轮）」「人工放行」，位于原因下方；顶部 `.workflow-generation-row` 不再有人工放行 |
| AC-2 | 只有人工放行（如合片/编排已有产出、无修复按钮）→ 原因下方一排只有「人工放行」 |
| AC-3 | 剧本节点未通过 → 原因下方为「修改（再给 1 轮）」「人工放行」 |
| AC-4 | 显示条件不变：进行中、只读、摘要节点、非未通过时不出现人工放行；点击仍提交 `override` |

## 改动
1. `meiji/client/task-panel.js` nodeCard — 人工放行不再 push 到 buttons，单独作为 `override` 传入 nodeUi → AC-1/2/4
2. `meiji/client/task-panel.js` nodeUi — 新增 `override` 参数，修复行由 `[repair, override]` 中存在者组成 → AC-1/2/3
3. 测试 `stage07-panel`、`stage21-script-review` 断言按新位置更新；`dev_docs/制作工作流.md` 同步布局描述
