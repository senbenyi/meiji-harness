# 提示词资料与大纲结构统一

- 类型：完整流程，涉及输出、存储、提示词和页面。
- 目标：单段参考资料直接使用正文；本次要求统一自然语言表达；大纲生成和保存为七个中文字段的 JSON，展示时才添加【标题】。
- 非目标：不改其他生成结果协议、任务调度、审核次数或素材关联。

## 验收标准与调研结论

| AC | 输入 → 结果 | 当前依据 |
|---|---|---|
| AC-1 | 摘要、剧本等单段资料 → 一个具名标签加原文，不重复套 JSON | StoryModel、EpisodeSummaryModel 目前包装 summary/script |
| AC-2 | 生成、修订、审核 → user 中唯一【本次要求】，明确语言、适用时长和风格 | prompt-request.js 当前语言在 system、参数在 facts |
| AC-3 | 大纲响应 → 七个固定中文字段的对象，无 outline 长字符串或内部小节标签 | output-protocols.js、episode-story.js 当前提取 outline 字符串 |
| AC-4 | 修订、审核、角色/场景/道具提取及镜头规划 → 使用同一个大纲对象，不再包 outline 字段 | story-model.js、shot-text-prompts.js |
| AC-5 | 查看、编辑、保存大纲 → 展示【字段名】，保存仍为对象，换行和原文保留 | generation-stage-views.js、storyDialog 当前单文本框 |
| AC-6 | 旧字符串大纲 → 先备份再迁移，失败可恢复；历史请求不改 | assertDrama、project-files.js；需增加专用迁移 |
| AC-7 | 相关功能测试、请求差异、分层检查 → 无新增失败，预览等于提交 | 验证前后相关测试；不跑全套 |

## 实施

1. shared/story-outline.js 定义七字段、校验和展示；生成及手动保存使用对象，门禁与 Model 校验同步。
2. output-protocols.js 与 StoryModel 更新协议；prompt-text.js、prompt-request.js 共用正文取值与要求表达，统一相关 Model 的资料标签。
3. 页面只在展示时加【标题】，人工编辑按字段保存；历史对象快照使用同样展示。
4. scripts/migrate-story-outline.js 转换旧大纲；备份索引与剧集、读回校验、失败还原，不改历史请求。
5. 同步开发文档和 fixtures，覆盖生成/修订/审核/编辑/下游提取/错误响应/迁移；检查请求前后差异，重启 Harness、更新 GitNexus。
