- 地位：唯一的开发计划，包含已定规则、阶段顺序、删除清单、测试用例与验收标准；与 `meiji/dev_docs/` 冲突时先修正 dev_docs 再继续。

## 一、已定规则

### 1. 项目 Model 与存储

- 每个项目只有一个项目 Model，是节点内容、状态与原因的唯一事实源。
- 所有修改都经 Model 写入：任务结果、人工编辑、人工放行、资料删除、过期标记；不绕过 Model 改文件或界面状态。
- Model 写入后保存为本地项目 JSON（结构即 `project_detail.json`），启动时从 JSON 恢复。
- 面板与 Model 响应式同步：节点状态、原因、内容直接读 Model。
- 任务、步骤、组合任务另存于任务存储，按 `task_id`、`group_id` 绑定；任务历史与步骤从任务存储读取，不进项目 Model。
- 旧项目与旧会话不支持，不迁移、不兼容读取；遇旧格式拒绝加载并提示可删除。

### 2. ID 与编号

- 所有 id 为创建时一次性生成的「前缀_uuid」：项目 `p_`、剧集 `e_`、角色 `c_`、服装 `co_`、镜头 `s_`、规则 `r_`、任务 `t_`、组合任务 `tg_`、步骤 `st_`。前缀只给人看，程序不拼接、不截取、不按前缀判断类型。
- `序号` 为数字顺序，`编号` 为给人和 AI 看的文本（C01、C01-01、S01）。引用一律存 id；发给 AI 的资料用编号，AI 返回的编号由程序换回 id 再保存。
- 节点由 `business_type + target_id` 唯一定位；`episode_id` 只用于按集查询。
- 角色库、镜头表重生成时，同一对象保留 ID，新对象创建新 ID；不能通过整表替换无声删除已引用对象。对象匹配、实际移除与资源及排队任务处理在阶段 1 冻结，按此边界实现。

### 3. 节点与状态

- 节点是可以独立发起生成任务的最小内容单元，共 13 种：项目摘要、剧本重要角色、角色图片、服装图片、展示摘要、剧情、本集资产、镜头表，以及每镜的每秒分镜、文本提示词、视频、尾帧，每集的合片。剧本不是节点，没有状态。
- 节点状态 8 种：`empty`、`queued`、`running`、`generated`、`rejected`、`failed`、`cancelled`、`expired`；状态与原因同步存储在 Model 中。
- `empty`、`queued`、`running`、`generated` 原因为空；`rejected`、`failed`、`cancelled` 写任务的 `end_reason`；`expired` 写过期原因。
- 入队时把节点原状态与原因存入 `task.previous_node_state`；未开始就取消或作废时恢复该快照；排队期间上游变化，快照中的 `generated` 同步改为 `expired`。
- 只有 `generated` 能作为下游输入。

### 4. 过期规则

- 上游节点转为 `generated` 后，下游 `generated` 节点不删除，标为 `expired`，并逐级向下传递；按 `项目数据结构.md` 的过期表执行。
- 自由创作的剧本更新只使项目摘要过期，不使剧情过期；创作方式为剧本时不提供剧本修改任务。
- 角色、服装图片变化只使用它作参考图的镜头视频过期。
- 暂定：输出语言、画幅、规则、角色声音及默认服装的修改不影响已生成资源，不改已有内容、不标为过期、不清空，只影响后续步骤。不能仅因这些配置与旧产物快照不同，就把已有资源判为失效；资料删除和其他上游内容变化仍按原过期规则执行。

### 5. 任务、步骤与组合任务

- 任务是对一个节点的一次操作；结束即终态（`completed`、`rejected`、`failed`、`cancelled`、`superseded`），没有暂停。重新生成、继续、人工编辑、人工放行、删除都创建新任务。
- 任务只带修改意见 `opinion`，不再有首次生成要求 `requirements`；任务与组合任务都删除该字段，界面上的生成要求输入一并删除。剧集的 `本集要求` 属于项目资料，保留。
- 任务发起方式 `action`：`generate`、`regenerate`、`continue`、`manual_edit`、`override`、`delete`。
- 每个任务第一步是程序 `precheck`：检查目标归属、原状态是否适用、必需输入存在且为 `generated`；失败则任务 `failed`，不调用 AI。按钮常亮，条件由 precheck 判断，不隐式补上游。
- 文本任务：precheck → generate → review，未通过则 revise 后再 review；自动修订最多两轮（round 0、1、2），用尽仍不通过为 `rejected`，保存有效失败稿；结构无效、接口报错、审核协议错误为 `failed`，不替换旧内容。
- 图片、视频任务：precheck → generate，无 AI 自审；媒体文件可读取且有效才通过；视频远端任务 id 记在步骤结果。尾帧、合片由程序执行，不调用 AI。
- 人工编辑、人工放行：`precheck → manual_edit/override` 两步任务，分别保存检查结果与执行结果；不调用 AI 自审，放行只绕过 AI 审核，不绕过结构校验。
- 项目串行：同一项目同时只执行一个任务，不按剧集并行；同节点未结束任务去重。前一任务通过后自动开始下一排队任务；失败、未通过或取消后队列停止，由用户在面板开始或移除排队项。
- 任务运行期间面板生成与编辑冻结，只能查看和取消。
- 组合任务不是任务，是按顺序执行的任务数组；成片 `episode-film` 按镜头表顺序逐镜创建 seconds（生成/审核/修订）→storyboard→video→tail，可用shot_id限定单镜，视频实测时长写入镜头。每秒分镜并入成片，`episode-seconds`仅保留单项及历史契约。状态与原因只按本组任务计算；任一任务失败、未通过或取消，后序作废并恢复快照。「继续」新建组并按当前有效产物与预期过期跳过节点，旧历史不变。
- 组合创建与继续：请求幂等命中时返回原组；否则先检查本次拟创建任务对应节点是否已有 queued/running 任务。存在重叠即拒绝整组受理并返回冲突任务列表，不创建 group 或部分任务、不改节点状态、不挪用旧任务。检查与建组一致执行，避免并发竞争；用户处理冲突后重新提交。
- 派生任务：剧本重要角色、本集资产通过后为新增角色和服装创建图片任务；自由创作剧本更新后创建项目摘要任务。由程序在前一任务通过后创建，`source` 沿用原任务，加入队尾，独立结束，不改原任务结果。

### 6. 资料删除

- 只考虑从项目中删除角色、服装，作为任务执行（`character-delete`、`costume-delete`）：precheck → impact（算出受影响的镜头视频，不改项目）→ apply（在 Model 中删除并把受影响视频标为 `expired`，一次提交）。
- 角色被项目内容（本集资产、镜头出镜角色、对白说话人）或素材库引用时不能删除，只能删除其服装或重新生成图片。
- 服装被素材库引用或是角色默认服装时不能删除；删除时把镜头出镜角色中的该服装id 换成角色默认服装id，相关镜头视频标为过期。

### 7. 提示词

- `in_puts/` 中的 YAML 是唯一的提示词与基础规则来源；文件只有 `mark` 和 `input`，`mark` 不进入提示词。生成、重新生成、审核各用独立文件；输出格式只在 `input.system.输出格式` 定义。
- 占位符统一 `{{中文名}}`。`{{输出语言}}` 取项目 `输出语言`；`{{补充规则}}` 取项目 `规则[]` 中 `约束` 为必须的条目（节点级排在项目级之后）；`{{指导素材}}` 取 `约束` 为参考的条目并按类别分组。没有内容时整段省略。
- 冲突优先级：本次修改意见 ＞ 节点规则 ＞ 项目规则 ＞ 基础规则；参考素材只作参考。审核时规则只作验收依据，修改意见核对是否落实。
- AI 自审统一返回 `{ 通过, 原因 }`。
- 图片每次最多一张参考图：角色图片生成用用户参考图（有则传）；服装图片生成用角色定妆图；重新生成模板只在节点已有图片且带修改意见时使用，参考图为原图，否则用生成模板。
- 视频参考图沿用现有接口，最多 9 张；重新生成只能带修改意见，不能带原视频。
- 旧 skill 文件、加载器与界面全部删除，只保留并改写 `skills/session/panel.md`。

### 8. 会话与面板联动

- 会话工具与面板 HTTP 调用同一个任务命令服务，读取同一份 Model 与任务存储。
- 面板操作（发起、取消、人工编辑、放行、删除）及任务终态，由 meiji 在绑定会话中显示一张提示卡（Harness `command/run` + `command/done` 事件）：只供用户查看，不进入模型上下文，不唤醒 AI。AI 不因通知回复或提问；只有用户在会话中请求的操作被阻断、需要用户选择才能继续时，才使用提问工具。不使用 Harness jobs/goals，不提供 `/meiji-run`。
- 会话断开或面板关闭不取消任务；取消只通过任务命令。task 已受理但通知投递失败时，返回「已受理 + task/group id + 通知错误」，不得诱发重复提交。
- 切换会话或项目时，晚到的响应和事件按会话、项目、版本校验，不覆盖当前显示；任务日志固定归属发起会话。

## 二、目标调用链

```
会话工具 / 面板 HTTP
  → 项目绑定校验
  → 任务命令服务（提交、取消、继续、编辑、放行、删除、开始/移除排队项）
  → 任务存储（task / step / group）+ 节点入队（Model 写 queued 与快照）
  → 项目串行调度
  → precheck → 业务步骤（YAML 渲染、模型/媒体调用、解析、自审修订）
  → 项目 Model 一次提交（内容、状态、原因、过期传播）→ 保存本地 JSON
  → 事件 → 面板响应式更新；通知 → 绑定会话
```

## 四、各阶段工作

### 阶段 1：契约定死

工作项：
1. 把 `step_model.json` 的枚举、节点类型、任务业务、id 前缀、状态转换规则写成共享常量与校验函数；`project_detail.json` 写成项目结构校验。
2. 带前缀 id 生成器；编号与 id 双向映射（资料→编号、返回编号→id，未知、重复、歧义编号拒绝）。
3. YAML 加载与渲染器：读取 `in_puts/` 文件、校验占位符、替换并渲染为 system/user 两段自然语言消息（图片、视频为正文）；规则列表到 `{{补充规则}}`、`{{指导素材}}` 的组装函数。
4. 任务命令协议：提交、查询、取消、继续、编辑、放行、删除、开始/移除排队项的入参、返回、错误、幂等键；事件与通知的触发事件、去重与文案；工具与 HTTP 端点名称。移除 amend/resume/pause 语义。
5. 底层回归基线：网关请求与响应（图片编辑、视频提交与轮询）、图片解码、尾帧截取、模型 JSON 输出解析。

测试：`stage01-contracts.test.js`（S1-01～S1-06，见第六节）。

退出条件：协议文档与常量冻结；没有未定的命名与触发规则。

### 阶段 2：项目 Model 与任务存储

工作项：
1. 项目 Model：内存单例（每项目一个）、统一写入接口、写入后保存本地 JSON、启动从 JSON 恢复、变化事件。
2. 任务存储：task、step、group 独立存储，按 id 关联；group 的 status/reason 只计算不存储。
3. 一致提交：节点内容、状态、原因与任务结果一次提交；写入中断可恢复，不出现半个终态。
4. 项目加载时校验版本，旧格式拒绝。
5. 删除旧数据模型与旧存储（R1、R2），删除场景、道具全部实现（R13）。

测试：`stage02-storage.test.js`、`stage02-commit-recovery.test.js`（S2-01～S2-07）。

退出条件：重载一致、失败注入后可恢复、同项目并发无覆盖丢失。

### 阶段 3：状态、precheck 与过期传播

工作项：
1. 唯一的状态与原因转换函数；入队快照、未开始取消或作废时恢复、排队期间上游变化改快照。
2. 过期表与逐级传播；角色、服装图片只影响引用它的视频；尾帧→下一镜视频；视频→尾帧、合片。
3. 服务端 precheck 框架与各业务的必需输入表；开始执行时重新读取输入。
4. 删除旧状态派生、下游清空与按钮门禁（R3）。

测试：`stage03-node-state.test.js`、`stage03-expiration.test.js`（S3-01～S3-06）。

退出条件：过期表每一行参数化覆盖，含排队快照与跨镜传播。

### 阶段 4：任务内核

工作项：
1. 任务命令服务：项目串行调度、`queue_order`、同节点去重、请求幂等；通过后自动开始下一项，失败、未通过、取消后停住。
2. 组合任务：建组时全部入队、顺序执行、停止时作废后续并恢复快照；「继续」建新组。
3. 派生任务：角色提取通过后建图片任务；自由创作剧本更新后建项目摘要任务。
4. 资料删除任务：`character-delete`、`costume-delete` 的 precheck、impact、apply（含服装id 替换为默认服装）。
5. 在隔离测试中用同一服务驱动会话适配器和最小面板视图，业务执行器先用可控替身。
6. 删除旧规划器、旧引擎与旧服务（R4）。

测试：`stage04-task-queue.test.js`、`stage04-task-groups.test.js`（S4-01～S4-10）。

退出条件：用可控 Promise 与调用记录验证真实时序；联动用例 L-01、L-02、L-03、L-05、L-08 通过。

### 阶段 5：文本业务与 YAML

工作项：
1. 文本任务执行器只实现 generate、review、revise 单步；轮次控制统一在任务内核。
2. 按 YAML 构造请求，按 `输出格式` 解析与结构校验，编号换回 id，审核统一 `{ 通过, 原因 }`。
3. 先以项目摘要走通完整闭环，再接其余文本业务：剧本（自由创作的更新）、剧本重要角色、展示摘要、剧情、本集资产、镜头表、每秒分镜、文本提示词。
4. 删除旧执行器、旧审核与准备逻辑、旧文本工作流、旧提示词 Model 与 interfaces、旧 skill 体系（R5、R6、R7、R12）。

测试：`stage05-prompt-rendering.test.js`、`stage05-text-tasks.test.js`（S5-01～S5-06）。

退出条件：所有文本业务的成功、未通过、失败三种结果都经真实执行器验证。

### 阶段 6：媒体与人工任务

工作项：
1. 图片：四个模板的选择规则、每次最多一张参考图、文件有效性验收。
2. 视频：参考图（最多 9 张）与开场衔接、修改意见、远端任务 id、轮询与下载、有效性验收；尾帧截取、合片拼接。
3. 人工编辑、人工放行改为 precheck 加对应操作的两步任务；普通项目管理（创建、打开、删除项目等）走独立命令。
4. 删除即时保存服务与旧编辑、放行写入路径（R8）。

测试：`stage06-media-tasks.test.js`、`stage06-manual-tasks.test.js`（S6-01～S6-07）。

退出条件：真实临时媒体文件验证通过；取消后的晚到下载不写节点、不启动下一项。

### 阶段 7：会话与面板切换

工作项：

2. 新实现从新契约和新测试出发，禁止导入上表旧编排/执行模块；禁止通过兼容 flag、legacy 分支或 catch fallback 调回旧写入路径。隔离开发期间旧服务仍可工作，但同一项目只能选择一个完整版本。
3. 每组重写先接通其调用方，再在对应候选阶段删除旧文件/导出/注册/文档入口；当前阶段模块和测试保持可执行；阶段 1–6 允许完整主系统暂不可用，阶段 7 恢复双端入口。阶段 2–6 的暂存旧模块最晚阶段 7 双端切换时全部退出生产加载路径。
4. 删除不仅检查静态 import：扫描动态 import、工具/步骤注册表、HTTP 路由、配置、启动脚本和会话 skill。图谱 impact、源码检索和真实入口运行共同验证；UNKNOWN 继续补查，不作无影响判断。
5. 不保留旧数据迁移或历史只读解析；旧格式在启动和打开项目时直接拒绝。
6. 新建 `tests/stage08-cleanup.test.js`，检查运行时可达模块、注册/路由清单、唯一执行与提交入口、旧文件删除和允许名单边界；阶段 4–7 同时用真实服务行为验证旧控制命令不可复活终态。检查不能只依赖源码关键词是否出现。
7. 交付删除清单的实际 diff 和新测试结果；每个清单项必须为“已删除”或“保留及明确依据”。无依据的保留 wrapper、重复 handler、过渡适配器、未使用导出不算完成。`git diff --check` 与入口导入/启动检查通过后才能验收 AC-11。

## 八、验收标准

| AC | 输入/状态 → 可观测结果 |
|---|---|
| AC-1 | 两入口提交同一节点 → 同一未结束任务；不同节点 → 项目内串行排队 |
| AC-2 | 节点变化 → 内容、状态、原因与任务结果经 Model 一次保存；下游保留内容并过期 |
| AC-3 | 任务失败、未通过、取消 → 终态不再改；继续创建新组与新任务 |
| AC-4 | 会话提交 → 面板看到相同任务与步骤；面板操作与任务终态 → 绑定会话显示提示卡，不唤醒 AI |
| AC-5 | 切换会话或项目、事件乱序 → 不展示旧结果、不转移日志、不影响后台任务 |

| AC-7 | 关闭面板、会话断开、通知失败 → 已受理任务不被取消，结果可查询 |
| AC-8 | 人工编辑、放行 → 新的 precheck 加对应操作的两步任务，检查与执行结果分别记录，无 AI 自审，旧历史保留 |
| AC-9 | 打开旧格式项目 → 明确拒绝并提示可删除 |
| AC-10 | 每阶段新测试通过；联动与真实制作链有运行证据 |
| AC-11 | 删除清单中的旧模块、函数、注册、调用方与兼容分支退出运行时 |
| AC-12 | 任务运行期间面板生成与编辑冻结，只能查看与取消 |
| AC-13 | 删除被引用角色 → precheck 失败；删除服装 → 引用替换为默认服装、相关视频过期，一次提交 |
| AC-14 | 面板节点状态与 Model、项目 JSON 始终一致；重启后从 JSON 恢复相同状态 |
| AC-15 | 面板保留现有页面、标签页与布局结构；节点状态、按钮与任务记录按新结构显示，废弃入口已删除 |
| AC-16 | 集合重生成 → 同一对象保留 ID，新对象生成 ID，不无声删除已引用对象，不产生悬空引用 |
| AC-17 | 新组合或继续组存在任务重叠 → 整组拒绝并列出冲突，无部分入队；幂等重试返回原组 |

## 九、实施中冻结的契约（阶段 1）

### 命令与入口

- 统一命令校验：`meiji/shared/task-contract.js`；面板 `POST /api/meiji/task-command`、会话工具 `meiji-task-command` 使用同一命令，查询也经该入口。项目创建/打开/删除走独立项目管理入口，不包装成生成任务。
- 所有命令含 `type`、`project_id`；写命令必须含非空 `request_id`（最多 128 字符），由绑定入口填充 source/session，不接受客户端指定发起方或执行步骤。同项目同幂等键同输入返回原结果；同键不同输入为 409，不创建第二项。

| type | 业务入参 | 结果 |
|---|---|---|
| submit | business_type、target_id、action（generate/regenerate）、可选 opinion；generate 不允许非空意见 | accepted、task_id、revision |
| submit-group | group_type（episode-seconds/episode-film）、episode_id；episode-film可选shot_id/opinion | accepted、group_id、task_ids、revision |
| query | 可选 task_id 或 group_id（不能同时指定） | task/steps 或 group/tasks；不指定则项目任务列表 |
| cancel、start-queued、remove-queued | task_id | accepted、task_id、revision |
| continue-group | group_id | accepted、新 group_id/task_ids、revision |
| manual-edit | business_type、target_id、content | accepted、新 task_id、revision |
| override | business_type、target_id | accepted、新 task_id、revision |
| delete | business_type（character-delete/costume-delete）、target_id | accepted、新 task_id、revision |

返回错误统一 `{code,message,path?,conflicts?}`；结构错误 422、绑定/权限错误 403、目标不存在 404、占用或幂等键冲突 409、旧数据/损坏数据拒绝 422。通知失败附加 `notification_error`，业务已受理仍 `accepted:true`，不能返回拒绝或抛出诱发重提的模糊错误。重复请求不重复创建任务、步骤、组及通知。

### 对象身份与集合合并

- 匹配只依据当前项目目录中的唯一编号，不依据名字、内容相似度、数组位置或 ID 前缀猜测身份。已有编号保留 ID，新编号创建新 ID；重复、类型错误、跨角色服装、来源不明的引用一律拒绝。
- 角色库提取为合并：未返回的已有角色/服装保留；集合重生成不能承担删除。真正移除只通过 character-delete/costume-delete，执行既定引用阻断、默认服装替换与过期规则。旧素材文件与历史任务保留，资源回收阶段 8 单独处理。
- 镜头表为整表结果：返回既有编号即保留 ID 与旧产物；内容变化按过期表处理。缺失旧镜头时，若有 queued/running 任务或节点规则引用即拒绝整表提交；否则允许移除，历史任务/素材仍保留，下一镜视频与合片按依赖变化过期。历史终态任务可指向已移除镜头，不再当成悬空的运行目标。
- 镜头生成和重生成 YAML 增加已有编号目录及编号规则；只传身份目录，不把旧稿偷偷当成本次生成输入。角色/服装/镜头的编号重排只改展示编号，ID 与引用不变。

### 会话通知

- 经 Harness 公开 `sessionController.resolveAgent(sessionId)` 取得会话，用 `agent.session.append` 写入 `command/run` + `command/done` 提示卡（commandId 为通知 ID，失败、未通过显示为错误卡）；不调用 `Agent.send`，不进入模型上下文、不唤醒 AI，不接入 jobs/goals。适配器为 `server/host/task-notices.js`。
- 触发：面板写命令已受理（submitted/cancel-requested/manual-edit/override/delete/start-queued/remove-queued）；所有来源任务终态（completed/rejected/failed/cancelled/superseded）。组继续用 submitted，消息附新组 ID。会话提交的受理结果直接由工具返回，不重复发受理通知。
- 通知 ID 在事务中生成并保存，不因重试变更；每个任务终态只能创建一条通知。通知跟随项目绑定时的接收会话，后续切换不更改旧通知归属；没有接收会话时保留待投递状态，由面板展示原因。
- 提交后投递，失败保留 outbox；重启按同 ID 重新投递，极端情况下可能重复显示一张提示卡，不影响业务。通知本身不是用户授权。

### 阶段 2 一致提交实现约束

- 新存储目录每项目一份 Model；每代目录独立保存 project.json、tasks.json、steps.json、groups.json、runtime.json。runtime 维护 revision、幂等请求、队列运行标志与待投递通知，不进项目 Model。
- 不逐个覆盖线上文件：先写完整新代并校验，再原子替换 CURRENT 指针。只有指针发布后才更新内存和发变化事件；重启仅加载 CURRENT 指向的完整代。失败注入涵盖各文件写入、指针前后、重载；指针后异常必须报告已提交，不得重复执行业务。
- 同项目提交串行，不同项目独立；读取返回副本；终态 task/step/group 历史不可复活或改写。模型及任务关联在发布前一次验证；损坏或旧格式显式拒绝。

## 十、追加需求：剧本拆分剧集

规格已同步到 `meiji/dev_docs/`（`project_detail.json`、`step_model.json`、`项目数据结构.md`「拆分剧集」一节、`in_puts/script-split-*.yaml`、`in_puts/episode-summary-*.yaml`），代码已实施，见下方「实施结果」。

### 已定规则

- 剧集原先一集一集手动添加；创作方式为剧本时，改为「拆分剧集」：弹窗填写参考单集时长（秒），由任务把剧本按单集时长切分到各剧集。自由创作仍按集添加。
- 剧集原 `剧情` 节点（故事小段）改名为 `故事大纲`，业务仍为 `outline`。
- 剧集新增 `剧情` 字段：本集剧本原文，不是节点。剧本创作方式由拆分写入，只按段落物理切分、不改写内容；自由创作由剧本更新写入本集对应文本。剧本 `分节` 字段删除，以各集 `剧情` 为准。
- 展示摘要改为根据本集 `剧情` 生成的简短总结；剧本创作方式下故事大纲以本集 `剧情` 为剧情依据。
- 过期：本集 `剧情` 被拆分写入或人工编辑后，展示摘要与故事大纲过期；故事大纲 → 本集资产、镜头表。

### 拆分任务 `script-split`

- 目标为项目，不是节点任务；步骤 precheck → generate，无 AI 自审，生成步骤结束即写入项目。
- precheck（程序检查，不用 YAML）：剧本正文非空、参考单集时长已设置，剧集上没有未结束任务。
- generate：程序把剧本按换行编号为 P001、P002…；AI 只返回每集起止段落与预估时长。
- generate 内程序校验段落连续覆盖、无遗漏、无重叠、顺序递增，按段落原文拼接写入各集 `剧情`，拼接结果与原剧本逐字一致才提交；按序号整体替换剧集，`时长秒` 取预估时长。
- 重新拆分带修改意见时使用 `script-split-regenerate.yaml`，提供上一版切分。
