# 项目到成片最小闭环

- 类型：Bug 修复
- 目标：全部镜头成功后，由用户点击“继续到成品”生成一部按分镜顺序合并的影片，登记并提供播放、下载。
- 调研来源：`docs/research/调研-项目到成片完整流程.md`

## 人工决策

用户已要求执行项目代码修复，不代替用户合成现有项目。成片按完整影片语义实施。

2. `dsh-elysium/src/worker/store/media.js:saveMedia/localMediaInput/saveFilmJob`、`src/worker/index.js` — 修改：经现有媒体存储边界保存影片、校验本地输入、登记可供媒体路由读取的影片任务 → AC-4、AC-5。
3. `dsh-elysium/src/database/managers/projects.js:addFilm/projectSummary` — 新增/修改：在项目变更队列内校验镜头快照并原子登记交付物；未交付项目仍从分镜页进入合成 → AC-4、AC-5。
4. `dsh-elysium/src/server/projects/service.js:createProjectStore` — 修改：组合合成和交付登记 → AC-4、AC-5。
5. `dsh-elysium/src/server/routes/projects.js:createProjectHandler` — 修改：新增认证的 `POST /compose` → AC-4、AC-5。
6. `dsh-elysium/tests/project.test.js` — 修改：覆盖未完成拒绝、成功合成、幂等、失败不登记及下载媒体 → AC-3、AC-4、AC-5。
7. `dsh-elysium/tests/media-http.test.js` — 修改：路由清单包括合成接口 → AC-4。

验证：`node --test tests/project.test.js tests/media-http.test.js`，临时测试项目合成后读取交付物和媒体 → AC-3、AC-4、AC-5。

2. `dsh-elysium/tests/connection.test.js` — 覆盖控制连接存活但转发失效的回归路径。

验证：连接专项测试、构建打包、重启已安装 Harness，并经认证媒体接口读取真实镜头字节 → AC-3。

## 验收标准

- AC-1：给定已有导演和可用图片封面 → 创建项目成功持久化，并进入锚点页。
- AC-2：给定至少一个锚点 → 继续后获得已持久化、可提交的分镜；提交后产生关联镜头任务。
- AC-3：给定镜头任务成功 → 项目分镜显示成功状态和可访问的媒体任务 ID。
- AC-4：给定全部镜头成功且媒体可用 → 成品页有可播放结果，项目可进入已完成状态，不重提已有镜头。
- AC-5：成品是按分镜顺序合并、可播放和下载的单个交付物。

## 验证结果

自动测试、构建与打包通过，只作为代码回归验证。2026-09-21 真实运行只读核对时，已有 7 镜项目由外部操作生成 1 个成片交付物；认证接口返回 `completed`，成片可完整下载并解码，哈希与存储文件一致。本轮未发送合成请求。发现旧 SSH 隧道控制检查存活但 HTTP 转发超时；阶段 4 修复并重启后，7 个镜头的认证媒体接口均返回 206 和实际字节。页面创建、分镜提交、成片播放交互和 7 镜画面顺序仍未验收；详见 `docs/implement/实施-项目到成片最小闭环.md`。
