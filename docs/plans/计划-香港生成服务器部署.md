# 香港生成服务器部署

- 类型：新功能
- 目标：从本机一条命令部署香港 Harness、Elysium 插件和默认 Skill，使香港生成调用使用本地模型端口。
- 调研来源：`docs/research/调研-香港生成服务器部署.md`

## 人工决策
- 本计划按香港全新运行数据实施，不迁移本机项目或历史任务；若要迁移，需要另定迁移与回退方案。
- 当前工作树的两处 drama Skill 未提交修改会随部署同步，需在实施前确认是否采用。

## 执行步骤

### 阶段 1：环境配置
1. `harness/.dsh/settings.hk.yaml:llm-pi-ai.providers.qwen38-local.baseURL` — 新增香港模板：公网 `/qwen/v1` → `http://127.0.0.1:28000/v1`，其余 Harness 配置与本机模板一致 → AC-2。
2. `harness/scripts/install.mjs:配置复制` — 修改：本机默认复制 `settings.yaml`；香港环境明确选择 `settings.hk.yaml` 安装为远端 `settings.yaml`；香港安装前检查默认 Skill 同名目录，已有内容不一致时停止并报告，避免覆盖用户 Skill → AC-2、AC-3。
3. `harness/scripts/start.mjs:dsh web 参数` — 修改：香港部署显式传 `--host 127.0.0.1`，本机启动行为保持现状 → AC-4。

验证：本机 Harness 配置专项测试；在隔离 `DSH_HOME` 下检查两套 settings 地址、Skill 文件与 Harness 启动参数 → AC-2、AC-3、AC-4。

### 阶段 2：一键部署入口
1. `harness/scripts/deploy-hk.mjs:main` — 新增：只连接 `veo-hk`，检查端口和依赖，同步当前工作树中的 Harness、插件必需文件，在香港准备 Node 与 pnpm，调用远端安装脚本；初始化香港 Elysium 配置中的聊天与 ComfyUI 为回环地址；启动 Harness 并输出 SSH 浏览器转发命令 → AC-1、AC-2、AC-3、AC-4。
2. `harness/tests/harness-scripts.test.mjs:部署脚本契约` — 修改：覆盖香港环境选择、回环模型 URL、Skill 安装与 Web 回环监听约束 → AC-2、AC-3、AC-4。
3. `harness/README.md:香港部署` — 修改：写明一条命令、模型端口、浏览器 SSH 转发和全新数据范围 → AC-1、AC-3、AC-4。

验证：脚本语法、Harness 专项测试、插件构建与 Registry 打包；香港安装前 dry-run 清单核对；实际部署后核对远端 `settings.yaml`、Elysium 地址字段、默认 Skill、插件包和监听地址 → AC-1、AC-2、AC-3、AC-4。

### 阶段 3：运行验收
1. 香港 `dsh web`、Elysium 运行接口 — 运行验证：回环访问 Harness，查询插件、模型与 Skill；执行一次真实生成并检查任务结果与媒体 → AC-4。

验证：记录远端 HTTP/进程/文件回读与真实任务证据；本机原配置差异、`git diff --check` → AC-2、AC-4。

## 验收标准
- AC-1：部署前检查 SSH、香港本地模型端口和运行依赖；缺项给出明确错误或由脚本安装。
- AC-2：香港 Harness 聊天与 Elysium 聊天、图片、视频地址均为香港本机 `127.0.0.1:28000/v1`、`127.0.0.1:26016`；本机配置与已存储地址不变。
- AC-3：本机一条命令同步所需文件，安装 Harness、插件和仓库默认 Skill，且不会改写远端已有项目与用户自定义 Skill。
- AC-4：香港 Harness 仅监听回环接口，插件可发现、Skill 可读取，Qwen 与 ComfyUI 检查通过，至少一次真实生成成功。
