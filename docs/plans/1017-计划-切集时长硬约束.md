# 切集时长硬约束

- 类型：Bug 修复，完整流程。
- 目标：每集按对白、剧情、动作估时，必须在项目参考时长 ±30 秒内，同一情景允许跨集。
- 非目标：不按字数计时，不重切现有项目，不改写原剧本，不生成媒体。

## 调用链与证据
面板/会话提交 → TaskService → handler-registry 程序审核 → buildSplit；通过后 commitContent → buildSplit → emptyEpisode。人工放行从 rejectedSplitCandidate 取原候选，registry 与提交都需携带项目参考时长。HTTP compose 经 splitBudget 将同一预算注入生成、修订、审核。

GitNexus status：up-to-date，2026-10-17 07:26 UTC；仓库 meiji-harness。query/context/impact 已执行。buildSplit、splitBudget、commitContent、createHandlerRegistry、generateRules、output0 均报告 CRITICAL（上游约131直接关联，部分结果类型/关联过宽），已向用户警示。实际源码核对 buildSplit 只有 registry 程序审核、registry 放行、content 放行、content 正常提交四个生产调用；splitBudget 由 buildSplit 与路由 compose 使用。动态动作注册用源码补查；不把图谱宽泛结果当作实际调用证据。

## 问题
下限未校验；±20%不等于固定±30秒；末集、单个不可拆单位和人工放行例外违背硬条件。修订只解释超上限，缺少不足时向前后平衡的策略。
