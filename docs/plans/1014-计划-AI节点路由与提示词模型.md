# AI 节点路由与提示词模型

- 类型：完整流程 / 重构，涉及 HTTP、节点契约、提示词与任务调用链。
- 目标：一套节点路由显式声明输入和输出；节点 PromptModel 保存角色与各动作要求；按当前 model 编排并调用两个独立 HTTP 单例。
- 非目标：新增项目大纲节点、镜头级工作流对齐、改变任务状态机、改动独立 llm-server 的默认采样参数、迁移历史数据。

## 调用链与证据
现有：TaskService → text/media Handler → YAML 渲染 → gateway → 项目事务。
目标：TaskService 提取节点业务参数 / HTTP 节点路由 → 统一节点执行函数 → PromptModel + 节点编排 + 路由输出契约 → 按 model 选择来源 → HTTP 单例。任务正式写入和结算仍由 TaskService 承担。

GitNexus 已执行 status 和 analyze --index-only。MCP 缓存仍提示旧 commit，结合当前源码核对动态 gateway 注入与 Handler 注册。
影响：createTextHandler、promptValues、renderTemplate 为 HIGH；modelRoute 为 CRITICAL；createAppRuntime 为 MEDIUM；completeChat、createMediaHandler、createTaskHttpHandler 为 LOW。主要调用方为 app-runtime、任务/媒体测试及宿主入口。文本路由选择可利用当前 modelRoute 的返回值，无需改动宿主聊天配置格式。

## 改动
1. server/http/nodes/：每个节点定义输入、各动作输出和 PromptModel/编排器绑定；server/http/ai-routes.js 统一校验与执行。
2. server/prompts/models/ 与 composers/：迁移全部 10 个现行 AI 节点、27 个动作的角色及要求；移除输出定义；公共渲染不依赖 YAML。
3. server/http/elysium/、llm-server/：两个单例与独立协议参数组装；共享文本传输重试/取消/留痕代码。
4. text-handler.js、media-handler.js、handler-registry.js、app-runtime.js、task-routes.js：接入统一节点执行路径，历史保存输入、模型、实际提示和传输记录。
5. 删除被替代 YAML、加载函数、completeChat；更新测试与开发文档。

验证：先项目摘要两来源协议/节点输入输出，再全节点生成/审核/修订及媒体回归；新增真实本地 HTTP 路由测试和并发/取消/重试测试；最终 npm test、git diff --check、GitNexus detect-changes 与索引更新。
