# 角色团队重新生成

- 类型：完整流程；新增两个面板操作与请求参数。
- 目标：团队设定、人物提取已有数据时同时显示重新生成和按意见修改，行为参照场景。
- 用户已用团队卡片截图确认：有内容显示两个按钮；修改带意见，重新生成不带输入框意见，保留草稿。
- 非目标：生图、自动重启、自动重生成当前项目、抽取公共提交框架。

## 验收标准
| AC | 输入/状态 → 结果 |
|---|---|
| AC-1 | 团队/人物已有结果 → 两个按钮；无结果 → 原生成按钮 |
| AC-2 | 重新生成 → generate首步；按意见修改 → revise首步；请求ID区分模式，重新生成不传输入框意见 |
| AC-3 | 正在提交/执行或前置未满足 → 禁用操作，连点及交叉点击不重复提交 |
| AC-4 | 新生成失败/无效候选 → 原数据保留，已存在生成有效候选仍按原即时保存流程 |
| AC-5 | 缺大纲/团队前置、会话归属、互斥、历史重试语义保持 |

## 证据及影响
角色panel分别调用groups.generate和characters.generate，经project-overview传递到workbench，再POST groups/characters路由。Service当前根据是否已有数据自动选revise，需可选regenerate:boolean。沿用场景已有实现与幂等方式，不把retry_action的失败任务重新派发当普通重新生成。
GitNexus已status、刷新索引、query、context和各目标impact；多个动态符号UNKNOWN，实际回调、路由与服务已源码补查，不能理解为无影响。基线test:drama 255通过、0失败、0取消。

## 改动
1. group_setting与character_extraction的ui/panel/index.js：共享各自提交处理，新增重新生成按钮、模式感知请求ID、原有状态及前置门禁。
2. 两个Service：可选布尔regenerate校验/记录/幂等对比，显式generate动作；不与retry_of/retryAction混用。
3. client/workbench.js与harness_server/project_routes.js：可选第三参数传递，仅对应两个接口。
4. characters.test.js：真实面板接口步骤/幂等/无效候选保留，以及两个卡片操作去重与互斥。
5. 开发方向和实施记录同步，diff/detect-changes与最终索引。
