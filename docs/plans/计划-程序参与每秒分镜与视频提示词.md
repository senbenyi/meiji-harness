# 程序参与每秒分镜与视频提示词计划

- 类型：生成流程重构；本次仅输出计划。
- 目标：模型负责创作内容，程序负责镜头覆盖、时间计算、引用编号、对白序列化和最终格式。
- 调研：docs/research/调研-程序参与每秒分镜与视频提示词.md
- 待用户决定：无；以下为建议实施方案，不在本次执行。

## 阶段 1：固定整集输入，一次返回全部镜头（AC-1）
文件：server/generate/shot-text.js、server/prompts/shot-prompts.js、models/episode-seconds-model.js、shot-seconds-model.js、操作步骤计划。
- 请求开始冻结镜头 ID、时长、事件、卡片 ID、既定对白及切镜约束。
- 保留一次生成请求返回全部镜头，不拆成逐镜请求。模型根据完整镜头清单统筹跨镜动作、对白和首末状态。
- 一次返回 shots[{shotId, beats:[{duration, action, camera, space, sound, endState}]}]；shotId 只能引用给定清单。程序检查缺失、重复、额外镜头，再按上游顺序组装。实体使用稳定 ID，对白使用独立事件与引用。内部结构化传输，界面仍显示可读文本，大纲保持纯文本。
- 程序累加每镜节拍 duration 生成时间码和标题。模型决定节拍长短；程序不机械平均分秒、不缩放动作或截断对白。各镜时长之和必须等于对应上游时长。
- 镜头齐全并满足审核条件后原子发布整集；失败留任务草稿，不覆盖原内容。删除被替代的自由文本续传与完成标记机制。
- 按整集规模评估输出预算，压缩重复指令，配置接口支持的输出额度。截断或结构损坏不发布，不静默切换为逐镜生成。
- 可解析的漏镜或内容问题进入自审，限定范围补全并合并后复核整集；不可解析响应要求重新返回完整结构。沿用最多一次自动修订预算。局部补全只属于失败后的修订，不改变初次整集生成策略。
- 验证初次生成只有一个整集请求；覆盖 1/2/N 镜、缺镜、重复/额外镜头及截断。记录实际 token、请求数和耗时，不预先承诺节省比例。

## 阶段 2：程序编排视频提示词（AC-2/3）
文件：server/generate/shot-text.js、film.js、server/prompts/models/text-storyboard-model.js；新增 server/prompts/video-prompt-renderer.js、shared/seconds-content.js（名称实施时按职责确认）。
- 结构化每秒内容作为唯一时间线输入；固定字段顺序、标题、时间码和切镜编号由 renderer 生成。
- 程序根据实际出镜人物/场景与 referenceSnapshot 分配 Picture/Subject；实体 ID 到标签映射固定，正文按 ID 引用，不做自由文本姓名正则替换。
- 同一主体可对应多张参考图；尾帧是连续性参考，不因增加一张图就新建一个人物 Subject。保留所有素材的实际用途校验。
- 程序生成 subject_definitions、引用标签及固定用途说明；模型仅补充不能从结构直接渲染的必要语义，不再重写整段已审核内容。
- 每条对白作为唯一事件存储，完整原文只渲染在对应时段，声音汇总只写事件引用及声源；允许剧情明确安排的重复台词，不按文本相同一刀切删除。
- 视频接口继续由提交层按同一 referenceSnapshot 顺序读取本地图并转 Base64，放 reference_images；不塞进 prompt、不把 Base64 写入历史快照。

## 阶段 3：收紧审核职责与局部修订（AC-4）
文件：server/generate/text-steps.js、相关 Model、skills/task/generate-seconds-instructions-skill.md、generate-text-storyboard-skill.md、skills/protocols.js。
- 程序审核：结构完整、全部镜头、时长之和、时间连续、合法实体 ID、引用定义与使用、对白事件引用次数、字段和图片映射。
- 模型审核：人物行为及道具状态、空间/机位可行性、情绪与表演、上游事件及台词保真；不得反复审核程序已确定的序列化格式。
- 审核问题必须给出当前片段和上游证据、规则、最小修订范围。上游冲突单独定位，不能要求下游擅自改变剧情；已明确切镜不机械要求连续运镜路线。
- 程序内容检查与模型否决仍合并为自审不通过；接口错误和非法审核协议仍执行失败。不新增用户开关。
- 修订只更新有问题的镜头/节拍，重新计算结构，复核受影响的相邻交接；程序不能凭空补缺失剧情。更改前镜末态时，下游依赖必须失效并重审，不能盲用缓存。
- 合并重复约束，保留每条有效规则的去向；运行提示词差集报告，不用删除质量约束来获得通过率。

## 阶段 4：数据迁移与验证
文件：shared/drama-model.js、项目内容读写与编辑路径、scripts/migrate-*.js、相关 tests、.agents 文档。
- 采用结构化每秒内容后同步所有读取、编辑、预览、历史和依赖版本；提供备份后离线迁移。旧文本只能可靠解析的字段才迁移，无法解析的保留备份并明确标记待重新生成，不伪造通过、不保留运行时新旧双轨。
- 先固化最近失败任务为脱敏 fixture，不携带 API key、Base64 或用户素材。覆盖缺 S02、未定义 Subject、未使用 Subject、尾帧用途、对白重复、持续声、额外叙事评论。
- 覆盖 1/2/N 镜、不同总时长、亚秒动作、无图/多图、多人共图、多图同人、场景图、尾帧、局部修订与跨镜依赖、取消/接口失败及旧内容保护。
- 验收：程序渲染的数量/编号/标题/标签结构错误为零；语义错误被真实检出；不能把漏内容通过补空字段伪装合格。
- npm test 对照执行前基线无新增失败、无新增取消；模型效果单独以相同样本/配置比较首审通过率、最终通过率、完整性、请求数、token 和时长。固定样本通过不宣称生产零失败。
- 更新架构/开发说明与实施记录、git diff --check、GitNexus 影响复查和索引同步；只在正式实施完成后重启。
