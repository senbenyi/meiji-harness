# 项目模型统一英文结构

- 类型：数据结构重构
- 目标：以 `meiji/dev_docs/project_detail.json` 与 `step_model.md` 为开发契约，在运行时代码中固定定义英文 `snake_case` 的项目、任务组、任务、步骤对象，并使持久化、服务端、面板和测试统一使用该结构。
- 非目标：改变业务流程、任务状态含义、AI 接口协议和 SQLite 关系表字段；提示词的自然语言/外部返回字段仍按节点文档定义，只在输入输出边界映射到项目模型。

## 改动
### 阶段 1：模型与契约
1. `meiji/shared/models/` — 项目、剧集、角色、镜头及所有嵌套对象分别定义为 `*_model.js`，通过 `index_model.js` 汇总导出；每个模型文件首行注释说明其对象职责；`shared/project_contract.js` 使用这些模型工厂严格校验英文结构 → AC-1/2。
2. `meiji/shared/models/task_group_model.js`、`task_model.js`、`step_model.js` — 新增独立、固定字段的 group/task/step 模型对象；`shared/task_contract.js` 保留通用协议校验 → AC-3。
3. `meiji/server/model/project_model.js`（由 `project-model.js` 重命名）— 保留 Repository 持有的唯一事务包装 → AC-1/2。

### 阶段 2：调用链
4. `meiji/shared/`、`meiji/server/`、`meiji/client/` 及相关测试 — 中文项目字段访问 → 对应英文结构；保留界面中文文案及提示词协议，在边界映射外部字段 → AC-5。任务、组、步骤由各自 model factory 创建。

### 阶段 3：存储升级与验证
5. `meiji/server/data/sqlite-store.js`、`meiji/server/data/schema.sql`、`meiji/tests/stage02-sqlite.test.js` — schema v3 → v4，在单个 SQLite 事务内将现存项目数据转为英文键，任务历史保持不变 → AC-4。
6. `meiji/tests/` — 补充新对象形状、旧 v3 数据迁移及端到端创建/读取/生成验证 → AC-1 至 AC-6。

验证：先执行针对契约、面板、生成和 SQLite 的阶段测试，再执行 `cd meiji && npm test`；执行 `git diff --check` 与 `gitnexus detect-changes --scope all`。全部成功为预期。
