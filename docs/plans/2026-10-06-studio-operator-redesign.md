# 短剧工作台：面向运营使用者的页面优化

> 状态：待确认；本轮只形成设计，尚未修改产品代码。
> 基线：2026-10-06，当前仓库工作区干净；Chrome 实查 3081 验收项目的全部七个页签。
> 范围：信息组织、页面命名、文字、状态、布局与阅读交互；沿用现有项目和生成流程。

## 1. 设计结论

把页面组织成运营人员能直接使用的短剧工作台：先看进度，再逐集检查内容，最后预览和下载成片。所有页面采用同一套标题、间距、操作位置和状态语言；每个页面根据内容采用适合的布局。

首页展示项目概况和六个阶段摘要。角色设定将图文放在一起；剧本按集阅读；分镜和视频按镜头排序；交付突出正式成片。技术信息统一放入默认收起的“技术详情”，错误原因和缺失内容直接可见。

## 2. 已确认的问题与执行路径

- `studio/index.html` 顶栏以“短视频画布”为标题，长期展示上传图片、资产库和刷新；缺少项目身份与页面任务的层级。
- `studio/app.js` 的 `renderStageTabs()` 在导航下重复显示完成状态和数字，字号偏小。`nodeCard()` 对不同类型都展示原始状态、短 ID、参数，描述与图片分别成卡。
- `render()` 把总览当作全部节点列表；`locateLatest()`、自动跟随和空白点击会改变阅读位置或页签。本次打开总览的截图位于列表末尾。
- `studio/app.css` 的正文跨越大部分屏幕；Markdown 容器 `white-space: pre-wrap` 与块级段落共同形成大空隙，且正文有 360px 内部滚动。导航说明 10px、节点 ID 10px，信息密集又难读。
- `lib/domain/read-models.js` 的 `canvasReadModel()` 将业务数据投影为通用节点；实体、分集、镜头、图片和交付之间的关联未完整提供给前端，无法可靠组织图文与分集。
- 当前浏览器项目：21 张卡片；资产页 6 张卡片对应 3 份设定与 3 张图；交付页 2 张视频卡。顶栏直接出现 `native`、`fast`；状态出现 `ready`、`approved`、`delivered`、`assembled`。

浏览器证据：`/tmp/drama-redesign-before-0.png` 至 `-6.png`。临时截图可能被系统清理。当前证据来自独立工作台，宿主嵌入态尚待实施后的验收。

## 3. 页面与名称

| 页面名称 | 第一眼看到什么 | 内容布局与操作 |
| --- | --- | --- |
| 项目总览 | 项目名称、集数、镜头数、制作进度、当前待处理事项 | 六个阶段摘要，按制作顺序排列；每项显示名称、带单位的进度和“查看”；成片存在时提供“查看成片”。不展开全部产物。异常放在阶段摘要旁，成功时不显示空的异常面板 |
| 故事分析 | 故事概述 | 原始素材显示名称、字数；分析正文作为主要阅读区；分集规划按集排列。原文内容有真实可读入口时才显示“查看原文”，无入口时准确标为“原始素材信息” |
| 角色与场景 | 角色、场景的名称和设定图 | 同一实体的图片与描述配对；宽屏图文并排、窄屏上下排列；先角色后场景。缺图时在原位置显示“设定图待生成”。上传和素材库入口放在本页工具栏 |
| 分集剧本 | 集数选择、当前集名称 | 当前集正式剧本为主；镜头列表放在其后，每镜显示序号、画面、对白和声音。长文使用“展开全文 / 收起”，展开后随页面滚动 |
| 分镜预览 | 当前集、分镜完成数量 | 按镜头顺序展示图片与对应画面说明；宽屏两列，窄屏一列；图片完整显示，可打开大图。缺图镜头保留位置和明确状态 |
| 镜头视频 | 当前集、视频完成数量 | 按镜头顺序展示播放器与简短画面说明；显示实测时长，只有计划时长时明确标为“计划”。生成参数收起；已有重新生成等操作收进“更多” |
| 成片交付 | 正式成片预览、集名、实际时长、审核状态 | 正式交付为主区域，提供已有媒体的预览和下载；分集合成及历史版本置于折叠区。没有正式成片时显示真实制作阶段和对应入口 |

命名只改变界面文字，现有阶段 key 保持兼容。“资产库”改为“公共素材库”，弹窗明确说明这是可跨项目使用的素材，不代表当前项目的角色与场景为空。

## 4. 统一版式与文字

页面结构：

```text
项目名称                                     刷新
项目总览  故事分析  角色与场景  分集剧本  分镜预览  镜头视频  成片交付

当前页面标题                         本页必要操作
第 1 集 · 集名                       已生成 3 / 3 个镜头

主要内容
次要内容或折叠详情
```

- 延续当前浅色、深色主题，使用中性背景、清晰正文和一个强调色；选中项用强调色，失败用红色，待处理用琥珀色。状态同时带文字，不依赖颜色表达。
- 项目标题约 20px，页面或分区标题 16–18px，正文 14px、行高约 1.7，辅助文字至少 12px；删除纯装饰小字和重复说明。
- 内容区居中，宽屏最大宽度约 1120px；长文阅读宽度约 800px；采用 8/16/24px 间距，卡片内边距 16–20px。窄屏自然换行，不挤成多层小字。
- 卡片头部采用紧凑单行：业务序号（必要时）、标题、中文状态同行对齐，不让每个字段各占一行。例如当前“ 两杯相碰·亡夫之痛 / review / ep-002-s ”三行改为“ 两杯相碰·亡夫之痛　待审核 ”一行；内部编号 `ep-002-s` 放入技术详情。`review` 的具体中文含义实施时按实际对象状态核对。
- 镜头序号与名称可作为不同文字元素，但仍在同一行，例如“镜头 01　走进安静的车站　已生成”。去掉标题的 `width: 100%` 等强制独占行规则；仅在长标题或窄屏确实放不下时自然换行，不用省略号遮掉关键名称。
- 导航只保留短名称、选中态及必要异常提示；完整进度放在总览或当前页标题旁，避免每处重复。
- 图片采用完整适配，不裁切主体；播放器完整显示控制条。长标题允许换行，按钮不盖住内容。
- 保留正文、对白和原始生成内容的准确性，只整理外层标题与排版；不通过删正文或正则清洗伪造“干净”。
- 卡片主界面移出模型、seed、哈希、路径、内部 ID 和原始枚举；折叠技术详情仍可查看。
- 低频操作收入明确标注的“更多”；查看、播放、下载保持直接可用。只展示当前数据和现有能力支持的操作。

## 5. 状态与阅读交互

- 状态按对象解释：素材生成完成显示“已生成”；剧本存在显示“剧本已就绪”；分集合成完成显示“已合成”。不能把 Episode 的 `delivered` 原样挂在剧本文字上。
- 制作状态与审核状态分别表达。“制作完成”不能表示“审核通过”；无审核证据显示“待审核”，只在相关审核位置呈现。
- `approved` 需核对其业务含义和审核来源；系统流程确认不得包装为人工质量审核。
- 未知状态在技术详情保留原值，界面显示“状态待确认”，不默认为成功。
- 失败或前置内容缺失直接显示原因和查看入口；数量带单位，例如“已生成 3 / 3 个镜头”，不把卡片数当作业务完成数。
- 首次打开从总览顶部开始；切换页签保留各页阅读位置；刷新、切回浏览器和后台新增产物不强制切页或滚动。
- 同 ID 的状态变化也应更新。刷新时保留正在播放的视频、已展开内容和当前分集；必要时提示“内容已更新”让用户主动加载，避免播放器被重建。
- 空白点击不导航；顶部/底部定位按钮使用中文名称，并明确其目的。
- 空状态只显示“缺什么 + 可执行下一步”；加载失败与无内容使用不同提示。

## 6. 数据边界与文件改动计划

当前链路为领域项目 → `canvasReadModel()` → `/api/canvas` → 阶段筛选 → 卡片渲染。关联在读取模型中补齐，页面消费明确关联，不靠标题相似程度配对。

| 文件 | 职责与拟改动 | 验证方式 |
| --- | --- | --- |
| `studio/index.html` | 工作台外壳：项目标题、简洁顶栏、页面区域与资源版本引用 | 首屏、窄屏、主题切换和宿主嵌入检查 |
| `studio/stages.js` | 页面名称与现有阶段映射；保持阶段 key 和旧节点兼容 | 现有阶段归类测试，核对旧画布节点仍可找到 |
| `studio/app.js` | 总览摘要、按集浏览、图文配对、中文状态、折叠详情、上下文操作及稳定刷新 | 七页逐项操作；同 ID 更新、新节点、空白点击、切回窗口与视频播放期间刷新 |
| `studio/app.css` | 字体层级、阅读宽度、间距、图文布局、媒体适配与焦点样式 | 1440、820、390 三种宽度，浅深主题截图与人工审视 |
| `lib/domain/read-models.js` | 提供项目名称、分集顺序、镜头关联、实体关联和交付层级等呈现所需信息 | 读取模型测试核对内容对应关系与计数；不修改项目记录 |
| `tests/studio/canvas-stages.test.js`、`tests/domain/production-stages.test.js` | 仅补充受影响的归类、关联、计数和交付层级回归用例 | 相关测试及仓库要求的检查；视觉效果由真实浏览器验收 |

实施时核对资产 provenance、镜头引用和交付记录的真实关联来源。无法确认关系的历史数据放入“未关联素材”，保留可访问性，不依据名称擅自拼接或删除。

采用现有原生 JavaScript 和 CSS，不引入 UI 框架或依赖。所有改动限于这次呈现与交互目标；不修改小说、剧本内容、生成模型或制作门禁，不重跑付费生成任务。

## 7. 实施顺序与验收

1. 统一页面外壳、文字层级、中文状态和技术详情收纳。
2. 补齐呈现关联，完成七个页面的专用布局与分集组织。
3. 修正抢焦点、自动跳页和状态刷新行为。
4. 安装至运行环境，浏览器逐页操作，记录截图和验证结果。

验收必须包含：

- 真实验收项目的七个页面全部检查；另外以可控多集、缺失产物、失败和历史无关联数据覆盖边界。这些样例只证明展示行为，不称为真实生成验收。
- 三种宽度无页面横向溢出、卡片裁切、控件遮挡；正文无固定高度的内部滚动，长表格可单独横向滚动。
- 浅深主题均可阅读；关键辅助文字至少 12px；键盘焦点清楚，Tab 能到达展开、选择、播放与下载入口。
- 使用“两杯相碰·亡夫之痛 / review / ep-002-s”这一用户反馈样例验证卡片头：常规宽度标题和中文状态只占一行，无单独编号行、空元信息行或多余头部留白；窄屏只在必要时换行。
- 项目与阶段名称统一；首屏不直接出现内部 ID、哈希、模型参数或原始英文状态。
- 设定图对应正确实体；分镜与视频对应正确集数和镜头；缺图缺视频不会因布局美化而消失。
- 正式交付与分集合成有明确层级，审核状态不被制作完成覆盖。
- 切页、后台更新、刷新与点击空白保持阅读位置和选择；实际视频播放正常。
- 3080 宿主嵌入态在可用登录环境中复验；如受登录限制，明确记录未验收范围。
- 运行相关测试、仓库必需检查和 `git diff --check`；记录部署版本与浏览器结果。不能只凭 DOM 元素存在或截图尺寸判定体验通过。
