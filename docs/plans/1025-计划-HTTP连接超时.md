# HTTP连接超时

- 类型：完整流程（共享传输及两个项目的测试，共3个代码文件）
- 目标：公共HTTP客户端建立连接最多等待5秒，成功连接后的等待时限不变。
- 改动：`packages/http-client/src/request.js` 使用带5000ms连接超时的EnvHttpProxyAgent，沿用Harness发布的代理环境变量；保留响应头、响应体及总请求60分钟时限。`packages/http-client/tests/http.test.js` 验证连接超时与慢响应。
- AC-1：TLS连接无法完成 → 约5秒以连接超时失败。
- AC-2：连接已建立、响应头或响应体超过5秒才返回 → 请求成功。
- AC-3：代理仍按环境变量选择；响应头/体等待配置保持原值。
- 影响：GitNexus已刷新；impact未找到createDispatcher（UNKNOWN）。源码检索只有默认requestDispatcher及测试调用createDispatcher；公共模型、异步任务及下载共用该实例。
- 基线：HTTP客户端53通过、0失败、0取消。
- 验证：公共包测试、drama测试、git diff --check、图谱变更检查并更新索引。

## 验证结果
- AC-1通过：本机TCP接受连接但不完成TLS，实际请求约5秒返回UND_ERR_CONNECT_TIMEOUT。
- AC-2通过：本机HTTP已连接后延迟响应头、延迟响应体各5.5秒，均成功。
- AC-3通过：环境代理传输调用保留headersTimeout/bodyTimeout及总请求3600000ms，网关回归通过。
- npm test：1092通过、0失败、0取消；git diff --check通过。
- detect-changes：3个代码文件、风险low、未截断；索引已更新成功。

## 调用链与补充改动
drama配置客户端 → 公共llm-server客户端 → requestData/requestRemoteTask → requestDispatcher → EnvHttpProxyAgent → TCP/TLS连接。
