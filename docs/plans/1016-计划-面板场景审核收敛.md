# 面板场景审核收敛

- 类型：Bug修复，完整流程（3个文件）。
- 目标：修复第三集面板实测中场景审核合并/拆分来回矛盾，完成一集的面板自测。
- 非目标：额外测试其他集、生成视频或定妆照、放宽原修订次数。

## 验收标准与证据

| AC | 预期 | 已确认问题 |
|---|---|---|
| AC-1 | 同一连续室外场地可在一份总体布局中描述多个区域，不因栅门/观众区位置不同来回拆并 | 真实面板任务queue_order=192：审核3要求合并、审核5要求拆分、审核7又要求删除观众区，三轮耗尽 |
| AC-2 | 场景再审核能看到本任务前轮意见，修复后无新事实不能反向要求还原 | taskNodeInput只给revise传前轮原因，scene review模板也不展示opinion |
| AC-3 | 历史反馈不跨任务泄漏，仍按当前候选和上游事实独立审核 | 仅episode-scenes的review增加本任务历史，拒绝原因仍允许被事实纠正 |
| AC-4 | 第三集场景、图、镜头表及全部逐镜文本通过；不生成视频/定妆照 | 已验收：28镜/300秒，28份节拍与28份最终文本均有效，无禁止媒体任务 |

| AC-9 | 程序校验已通过的UUID/结构/数值不再被AI依据历史意见重复误判；AI只核对意见的结果，不执行意见中的修订输出指令 | 第200任务ID正确却被照旧意见误报；第202任务程序通过，AI审核却按修改意见输出patch而非审核结构 |
| AC-10 | 上次其他动作的协议诊断不覆盖当前输出契约；协议错误/空表之后仍能恢复完整修订基稿 | 第203任务把上次审核错误“本层仅允许是否通过、原因”当成修订契约，反复返回审核结构或空shots，基稿丢失 |
| AC-11 | 普通停步交谈衔接不被过度判成上游矛盾；speaker_tag始终在<d>外，程序仍拒绝标签污染原话与拆句 | 第218任务用空节拍报告可在本镜细化的走近/停步；第221任务把(S4)/(S3)写入<d>，均自动一轮修好，提示口径可减少这两类重试 |
| AC-12 | 关键绝对时刻在事件镜头明确下传；报秒、号令与该时刻一致，时间省略后不会把已结束作业的连接硬带入后续事件 | 第254任务S25先等5秒，再报35–40秒并立即放射，未带入S01的22:40:46预定时刻；末态仍断言铁索连接弹丸，妨碍下一镜发射 |
| AC-13 | 原结果修订弹窗明确填写修改意见、提交AI修订，而非误导为直接替换正文；其他人工编辑保持默认行为 | 第255任务实际面板弹窗标题为原结果修订，字段却为正文、按钮为保存，语义不符 |

## 改动

1. meiji/server/prompts/models/episode-scenes.js：统一收录与空间粒度；室外场地总体布局允许多个分区，拆分需具体不可共用的空间事实；review展示同任务此前意见并禁止无依据反向修改。
2. meiji/server/handlers/node-inputs.js:taskNodeInput：仅场景审核按顺序加入此前本任务审核原因，不混入其他任务；不改变其他节点原协议。
3. meiji/tests/stage29-scenes.test.js：覆盖实际合并/拆分历史传入、跨任务隔离与规则约束。
4. scene-inputs/scene-image路由及PromptModel/media-handler/node-dependencies：加入引用该场景剧集的原始剧情，禁止用常见装置造型代替专用结构、补造地理；输入与依赖共用投影，补原始上下文真实渲染测试。只修订本集这一张图。
5. shots路由引用校验：聚合具体镜号/数组位置、错误值与人物服装目录，并在有完整预算输入时同时反馈时长问题，不自动猜测替换；新增回归，保留原有拒绝与修订预算。没有引用错误时仍使用原独立程序时长审核。
6. shots修订规则、输出契约和resolveShotPatch反馈：已有非空唯一ID用id定位；空ID候选支持candidate_index（从0开始）+原title双重匹配，仅能修改同一完整基稿的无ID镜头，禁止混用字段、越界、标题不符或重复目标。两者都不是新增正式身份；合并后原id仍为空，正式ID由既有保存流程创建。增删拆并重排仍要求完整replace。图谱确认resolveShotPatch只有shots.normalizeResult直接调用，LOW；补候选局部修订与错误定位拒绝回归。
7. taskNodeInput只对action=revise且正式镜头表为rejected、无本任务draft的入口，读取最近同目标rejected任务最后done候选；非法patch则读取其完整输入基稿。没有失败候选时仍读正式表。新生成、其他节点、其他目标及已通过表的原结果修订不混入失败候选。CRITICAL影响已说明，补候选与历史隔离回归。
8. shots的AI审核规则明确程序与AI分工：UUID精确性、归属、重复、字段和数值由程序检查；AI仍核对实际人物/服装语义及完整剧情。历史意见只能对照最新内容，已修复项不能照抄为拒绝原因。修改意见中的patch/replace等动作和输出指令只作为核对背景，审核不执行它们，只输出审核结构。
   第204任务再审核把第1/2镜共同承载第1小段误判为跨段；实际第3/4镜才是第2小段。补充镜号不等于段号、合法一段多镜的明确例子，跨段拒绝须指出同镜混入的两个小段事实或实际段序错误。
9. 生成/修订规则明确错误消息中的其他动作字段不是本次输出要求，当前shots契约优先。taskNodeInput对shots只从非空完整数组候选或该步prompt.input.content恢复基稿，协议响应/空表不覆盖可用基稿；跨任务修复按本节点最近任务中的步骤倒序寻找可用基稿。
10. seconds共享整镜规则明确可在本镜预算内细化的普通短距离衔接；storyboard共享对白规则明确说话人名称/speaker_tag在<d>外、原话在内。不放宽现有完整性校验和修订上限。GitNexus文件影响分别LOW/MEDIUM，均为各自节点入口动态引用；当前真实任务已自动修好，澄清后继续本集余下节点验证。
11. shots共享整镜设定规则要求把原文的关键绝对时刻带入事件镜头，区分剧情时钟和镜长；seconds共享规则允许有明确时间省略及后续事实依据时省略普通作业收尾，不以“没拍到”硬保留接触/连接。面板只修订S25：12秒对应22:40:34至46，35–40按真实一秒报出，其后按预定时刻屏息待令，不新增41–46的报词；镜头开场前吊运已完成并脱离吊具。前24镜保持有效，重测S25及尚未生成的后镜。
12. content-forms.editor增加可选textField/submitLabel，默认body/保存不变；仅原结果修订入口选择opinion/提交修订，标为修改意见并保持多行输入。既有面板提交回归同步核对标签和请求语义。共享editor及renderTaskPanel为CRITICAL，检查默认人工编辑与既有完整回归；最终在面板打开并取消弹窗验证，不额外调用AI。

GitNexus：taskNodeInput为CRITICAL（17直接调用者）；仅增加场景审核分支，检查既有节点回归。PromptModel文件LOW，测试文件UNKNOWN，源码确认由npm test的tests/*.test.js加载。
