# 面板场景审核收敛

- 类型：Bug修复，完整流程（3个文件）。
- 目标：修复第三集面板实测中场景审核合并/拆分来回矛盾，完成一集的面板自测。
- 非目标：额外测试其他集、生成视频或定妆照、放宽原修订次数。

## 改动

1. meiji/server/prompts/models/episode-scenes.js：统一收录与空间粒度；室外场地总体布局允许多个分区，拆分需具体不可共用的空间事实；review展示同任务此前意见并禁止无依据反向修改。
2. meiji/server/handlers/node-inputs.js:taskNodeInput：仅场景审核按顺序加入此前本任务审核原因，不混入其他任务；不改变其他节点原协议。
3. meiji/tests/stage29-scenes.test.js：覆盖实际合并/拆分历史传入、跨任务隔离与规则约束。
4. scene-inputs/scene-image路由及PromptModel/media-handler/node-dependencies：加入引用该场景剧集的原始剧情，禁止用常见装置造型代替专用结构、补造地理；输入与依赖共用投影，补原始上下文真实渲染测试。只修订本集这一张图。
5. shots路由引用校验：聚合具体镜号/数组位置、错误值与人物服装目录，并在有完整预算输入时同时反馈时长问题，不自动猜测替换；新增回归，保留原有拒绝与修订预算。没有引用错误时仍使用原独立程序时长审核。
6. shots修订规则、输出契约和resolveShotPatch反馈：按ID的patch仅可定位已有非空唯一ID的镜头；目标镜头ID为空时必须完整replace，不能自行编造ID或用数组位置猜测绑定。图谱确认resolveShotPatch只有shots.normalizeResult直接调用，LOW；补空ID候选的替换修复回归。
7. taskNodeInput只对action=revise且正式镜头表为rejected、无本任务draft的入口，读取最近同目标rejected任务最后done候选；非法patch则读取其完整输入基稿。没有失败候选时仍读正式表。新生成、其他节点、其他目标及已通过表的原结果修订不混入失败候选。CRITICAL影响已说明，补候选与历史隔离回归。

GitNexus：taskNodeInput为CRITICAL（17直接调用者）；仅增加场景审核分支，检查既有节点回归。PromptModel文件LOW，测试文件UNKNOWN，源码确认由npm test的tests/*.test.js加载。
