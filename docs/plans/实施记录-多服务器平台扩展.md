## 使用方式

1. 更新插件后，在右侧工作台打开“服务器”，登记已经运行的服务。平台选项只是归属标记，不会登录平台或租赁实例。
2. HTTP 登记不接受 URL 中的凭据、查询参数；SSH 登记使用本机已有别名与独立本地端口。实例与部署身份必须填写，登记后连接信息不可原地修改。
3. 点击“检查”查看检查结果；点击“使用”会再次检查并原子保存默认目标。ComfyUI 检查包含预览、常规和五种完整工作流的节点、模型信息，不提交生成请求。
4. ComfyUI 切换影响新任务；旧任务、恢复和已开始批次保留原服务器。旧记录可以停用但不能删除；当前默认目标需要先切走才可停用。历史任务仍可使用已停用目标。
5. LLM 当前只支持兼容的 `qwen3.8-27b-elysium` OpenAI Completions 服务。选中后显示“下次启动”，停止当前 Harness 后通过 `node harness/scripts/start.mjs` 应用。

首次登记清单后，需要检查并选择 ComfyUI 默认服务器才能创建新视频；此时不会继续隐式使用旧环境变量。独立插件实例/测试可用 `serversFile` 配置或 `ELYSIUM_SERVERS_FILE` 指定清单位置。

服务器设置端点位于 `/plugins/dsh-elysium/server/{list,register,check,switch,set-enabled}`。浏览器只收到服务器名称、ID、平台、服务类型及选择状态，不收到 SSH 解析细节、环境变量引用或凭据内容。新增平台包仍只在设计文档登记名称，没有创建 providers 目录或新增平台依赖。

## LLM 宿主核验

本机已安装 `@deepseek-ai/dsh` 版本为 `0.1.2-rc.1`。核验了安装包中的：

- `@deepseek-ai/dsh-settings-file/lib/index.js`：文件变更会通过 watcher 发布，不能把改写 settings 当作“下次启动才生效”。
- `@deepseek-ai/dsh-llm-pi-ai/lib/index.js`：provider 配置按请求重新解析，新请求会使用变更后的地址；未确认有可供本功能调用的全局会话空闲与原子应用接口。

因此设置页只写服务器清单。启动脚本在检测到仍有 Harness 进程时拒绝改写 LLM settings；无运行进程时，使用 Harness 自带 YAML 解析器，只修改现有 `qwen38-local` 的地址、凭据环境变量引用及默认模型，保留其他配置。自定义 headers 的既有路由拒绝自动切换，避免继承未知认证信息。未新增网关、热切换或供应商自动接入。

## 明确边界

- HTTP 地址背后的真实云实例身份依赖手工登记及地址稳定性；未接入平台 API，不能验证平台是否把同一公网地址重新分配。实例更换时应登记新身份和新地址；SSH 目标使用新本地端口。
- SSH 指纹来自 `ssh -G` 的主机、用户、端口、跳板和密钥路径，不是云厂商实例认证。别名解析变化会拒绝旧任务连接。
- 没有服务器快照的旧批次拒绝直接恢复，需要先核对原回执进行迁移；不会自动绑定当前默认服务器。原冻结案例 `runpod/scripts/third-cup-preview.mjs` 未改动。
- 空模型列表无法证明模型存在；切换检查会拒绝将其标为已验证。检查通过仍不代表生成质量或全部远端运行能力已经实测。
- 未实现媒体搬运、自动租机或平台 API。真实跨平台验收留待对应平台正式接入。
- 清单写锁异常退出后可能遗留；需核对写入进程已停止后处理，不自动抢占未知锁。
