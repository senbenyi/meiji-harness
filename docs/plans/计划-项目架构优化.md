# 项目架构优化

- 类型：重构
- 目标：消除项目中的配置重复、统一目录命名、清理冗余文件
- 调研来源：架构审查（2026-09-12）

## 人工决策

1. 预设共享方式选择符号链接（symlink）。若部署环境不支持 symlink，改为复制脚本。
2. 构建脚本统一为 `scripts/`，仓库内引用同步更新；仓库外引用无法由本次扫描确认。

3. `harness/.dsh/.agent-presets/elysium-teaching/agent.cordis.yml` — 修改：删除文件，创建 symlink → `../_base/agent.cordis.yml`
4. `harness/.dsh/.agent-presets/elysium-free/agent.cordis.yml` — 修改：同上
5. `harness/.dsh/.agent-presets/elysium-director/agent.cordis.yml` — 修改：同上

验证：

### 阶段 3：统一构建脚本目录

两个插件的构建脚本统一为 `scripts/`；tools 已有工作流同步脚本，迁移时合并目录，不覆盖已有文件。

2. `dsh-elysium/package.json` — 修改：`scripts.build` 路径更新为 `scripts/build.mjs`；`scripts.package:registry` 路径同步更新
3. `dsh-elysium/.gitignore`（如有引用）— 修改：更新路径

验证：
- `cd dsh-elysium && pnpm build` 成功
- `cd dsh-elysium && pnpm package:registry` 成功
- tools 原构建脚本目录不存在

两个插件的 `package-registry.mjs` 实现风格不一致（文件列表、错误消息语言、执行顺序）。以 tools 版本为基准统一。

1. `dsh-elysium-ui/scripts/package-registry.mjs` — 修改：
   - 添加 `dirname`/`join` 导入
   - 先校验全部文件再复制（当前 UI 版本先校验后删除重建，tools 版本先删除再校验）

验证：

- `ls dsh-elysium-ui/registry/` 包含所有声明文件
