# 会话步骤级制作

- 类型：新功能（完整流程）
- 目标：会话文本制作按本次目标选择单个生成、审核、修订步骤，并按实际结果组织 todo；面板保留完整流程。
- 非目标：不改媒体生成协议与人工确认、不拆解剧本回写/方案事务（提供显式回写工具替代会话自动回写）、不改 Harness 源码和持久化结构版本。

## 验收标准与调研结论
| AC | 输入/状态 → 可观测结果 | 状态 | 依据或缺口 |
|---|---|---|---|
| AC-1 | 会话生成/重新生成/修改摘要、大纲、人物、场景、道具、镜头表、单镜每秒指令或项目摘要 → 仅一个生成或修订节点，不自动审核 | 通过 | session-steps、session-tools 集成测试验证生成/修订均仅一个节点 |
| AC-2 | 会话仅审核已有内容 → 仅审核节点，更新结论，不改正文、不清理下游、不自动修订 | 通过 | 独立审核正文、版本和下游保留；接口失败不覆盖已有内容 |
| AC-3 | 只审核且不通过 → 业务状态保留 review_failed，但 job 表明审核已执行，目标可以完成 | 通过 | review_failed 保留业务结论，审核 job 完成；真实 Harness 单项目标可完成 |
| AC-4 | 面板原操作 → 保留生成、自审与有限修订；会话不能隐式前置额外任务 | 通过 | 面板回归保持自动流程；会话不隐式补摘要或回写 |
| AC-5 | 会话目标一项或多项 → 先明确完成标准，建立 Harness goal 和步骤 todo，按授权结果推进与结束 | 通过 | 真实 Harness 配合可控规划桩验证一项、两项和失败阻塞三种场景 |

## 调用链与证据
session operationTools → operation registry → task registry/runner → task-executor → runTextNodes → generateStep/reviewStep。
review-checks 在调用生成前清理目标及下游；独立审核必须走审核执行路径，不能进入生成准备。
GitNexus 已刷新，query/context/impact：runTextNodes 上游 23 符号，7 流程；源码补查覆盖动态注册、审核持久化和 job 结算。

## 问题
生成、审核虽有独立函数，但任务计划和执行会隐式串联；仅改提示词不能提供单步能力。未审核产物还需保留待审核状态，不能被保存层误判通过。

## 待用户决定
无。沿用既有工具名，mode 明确 generate/regenerate/modify/review；会话 story 必须 only、seconds 必须 track，避免打包多个内容对象。

## 改动
用户补充：按具体业务步骤一一对应文件（生成大纲、审核大纲、修订大纲、提取人物/场景/道具、生成镜头表等），不是只拆三个通用动作。业务步骤独立执行，不触发后续；公共机制放 steps/shared，组合流程归任务层。所有调用方与架构检查同步。
1. `server/flow/steps/`（迁移原 runtime/text-generation.js）与独立生成、审核、修订步骤模块：拆出共享生成/审核执行函数，会话生成和修订不自动审核。→ AC-1、AC-4
2. `server/flow/tasks/`、`server/flow/shared/task-executor.js`、`runtime/review-checks.js`：单节点计划、独立审核现有内容、准确保存待审核状态。→ AC-1、AC-2
3. 新增显式 `operation-sync-script` 工具，并同步工具图谱；`tools/session-operation-tools.js`、`server/flow/operations/`：参数与前置条件验证，精确选中内容对象，阻止隐式额外任务。→ AC-1、AC-4
4. `server/host/harness-jobs.js`：区分执行完成和审核通过，返回步骤结果。→ AC-3
5. `skills/session/panel.md`、工具图谱、预设与开发指引：目标、步骤 todo、授权、停止规则同步。→ AC-5
6. 测试覆盖请求次数/种类、内容与下游保留、未审核状态、失败审核 job、面板回归和 Harness 预设。→ 全部 AC

验证：针对性集成测试与全量 npm test；git diff --check；GitNexus detect-changes 和最终索引更新。

## 验证结果
基线：827 passed / 0 failed / 0 cancelled / 0 skipped（/tmp/meiji-steps-baseline.log）。


最终结构：`flow/tasks/text-step-registry.js` 映射业务步骤；`flow/tasks/text-workflow.js` 负责固定组合及单步选择；生成大纲、提取人物/场景/道具、摘要、镜头表、每秒指令分别有生成、审核、修订 step 文件。图片、分镜和视频的已有步骤入口也归入 steps；视频提交、生成保存与尾帧分为独立文件，顺序仍由 task-video 组织。通用请求、记录和校验机制放 steps/shared，不新增旧路径兼容导出。

最终全量：839 passed / 0 failed / 0 cancelled / 0 skipped（/tmp/meiji-steps-final.log）。新增 12 项测试，相比基线无新增失败。真实 Harness 使用可控规划适配器与业务响应桩，验证公开 goal/todo/job 工具的实际调用、目标终态与不续跑；没有把该测试当作真实大模型自然语言规划评测。未恢复此前停止的全页面功能走查。

GitNexus detect-changes：87 个已跟踪文件、233 个符号、154 个关联流程，风险 critical；较多文件是移动后的 import 同步。新增 step 文件由动态注册、依赖架构检查与集成测试核对。git diff --check 通过。
