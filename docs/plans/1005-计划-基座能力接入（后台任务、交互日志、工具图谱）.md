# 基座能力接入：后台任务、交互日志、工具图谱

> **已合并**：本计划已与另一份计划合并为 `1005-计划-合并实施（基座能力接入、项目剧本与角色库）.md`，**实施以合并计划为准**。本文只保留为设计讨论记录，其中与合并计划冲突的条目（尤其是创建页草稿相关内容）一律作废。

- 类型：新功能（完整流程）
- 目标：
  - 面板与会话发起的生成都登记为会话的 Harness 后台任务（jobs）：完成时通知会话；同一视频项目同一时间只执行一个生成操作。
  - meiji 网关的每次请求都有可追溯的原始返回，会话工具调用能对应到 meiji 的操作、任务和步骤。
  - 提供 meiji 专用会话预设并设为默认；meiji 的会话工具和会话说明只在该预设内注册。按操作生成会话工具，用工具图谱校验工具、操作、任务、skill 和会话说明是否一致。
  - 创建页的剧本导入与项目摘要草稿（已在「1005-计划-创建页剧本摘要预生成」中实现）按本计划的统一规则处理：占用、job、停止、原始返回、导出与工具图谱。
- 非目标：
  - 不改操作 → 任务 → 步骤三层模型，不改提示词 Model、生产/审核 skill 和网关请求参数。
  - 不改 deepseek-harness 源码。
  - 不做按图谱动态增减工具。
  - 不迁移 meiji 现有的已废弃 Harness 同步读接口（见第 8 节风险 R5）。
  - 不兼容旧会话：使用 standard 等其他预设创建的会话不再提供 meiji 工具，旧会话直接删除，不做迁移。
- 基线：
  - llm-dsh-plugins HEAD `e320f88`（已包含「剧本素材导入与摘要提取」）。工作区里另有进行中的「1005-计划-创建页剧本摘要预生成」。
  - deepseek-harness `0.1.7-rc.2`（`21638c5`）。
- 状态：设计已由用户分五轮决定（附录 A）。2026-10-05 第二次复核后整份修订；同日第四轮决定把「创建页剧本与项目摘要草稿」纳入范围，并确定不兼容旧会话、以后都使用新预设。待用户决定的事项已全部确认（第 5 节）。

## 2. 验收标准

可行性一列：「已确认」表示接口和代码点已核对（附证据编号）；「未确认」表示实施时需要先验证。所有 AC 当前的验收状态都是「未验收」。

| AC-1 | **生成按项目互斥**：同一项目已有生成操作（任一集或项目级，含排队中）时，面板或会话再发起任何生成 → 返回 409，`code: 'OPERATION_BUSY'`；`busy` 含 `operationId/label/initiator/kind/episodeId`；文案为「本项目正在生成：{label}（面板\|会话发起），同一项目同一时间只能执行一个生成操作」。不同项目之间互不影响 | 已确认 M7、M8 | `tests/project-occupancy.test.js` |

### 3.1 现状

- 会话生成：模型调用 `meiji_content_generate.execute`（`tools/session-content-generate-tool.js:12`）→ `tasks.start`（`operation-manager.js:75`）→ `occupy`（`:77`）→ 返回 operationId → 模型反复调用 `meiji_task_control` 的 wait（`session-task-control-tool.js:17`）→ `manager.wait` → `waitFor`（与 25 秒超时竞速，`:68-73`），循环直到结束。

### 3.2 目标

- 会话生成：模型调用 `meiji_generate_<op>.execute`（`tools/session-operation-tools.js`）→ `jobs.startOperation({ sessionId: exec.agent.session.id, initiator:'session', op })`。在 `ctx.jobs.start({ kind:'meiji', owner, run })` 的 `run` 里调用 `tasks.start`；占用冲突时 run 抛出 409，job 不会登记，改为登记等待 job。→ 返回 jobId，本轮结束。→ 操作结束，`hooks.done` 结算 → tool-jobs 注入通知或唤醒会话 → 模型用 `job_output` 读结果。
- 面板生成：`POST /turn` 的 generate 分支 → `ensureLiveSession(sessionId)` → `jobs.startOperation({ initiator:'panel' })`（登记失败时退回直接 `tasks.start`）→ 返回 202 和 `{operationId, jobId}`。
- 停止：
  - 面板：`manager.cancel` → `task.done` → job 以 killed 结束 → 会话收到通知。
  - 模型：`job_kill` → meiji 守卫（面板 job 直接拒绝）→ `registry.kill` → `hooks.cancel(reason)` → `manager.cancel`。如果 reason 是 teardown，只脱离、不停止操作。
- 网关：`requestGatewayRaw` → 原有的 `writeApiLog`，加上新增的 `recordNodeResponse` → `history/responses`（草稿写入 `project-drafts/history/responses`，发布时复制到项目历史）。
- 创建页草稿：保持「创建弹窗 → `/turn`（draft）→ 草稿操作 → 回填摘要 → 确认创建时发布」，不占用项目、不登记 job（6.1）。
- 会话工具与会话说明：由 meiji 预设内的子插件 `@meiji/harness-plugin/session` 注册（J6），主机层只提供 `ctx.meiji` 服务与 `job_kill` 守卫。

## 6. 设计约定（跨阶段共用）

### 6.1 job 规格

| kind | 何时登记 | label | 结束条件 | 结果 `result`（JSON 字符串） |
|---|---|---|---|---|
| `meiji` | 一个生成操作（会话或面板发起） | `{operationLabel}（会话发起\|面板发起）` | 操作结束 | `{operationId, projectId, episodeId, action, status, reviewPassed, failures, error?, pendingConfirm?}` |
| `meiji-wait` | 会话发起时项目被占用 | `等待：{占用者 label}（面板\|会话发起）` | 占用操作结束 | `{occupantOperationId, occupantStatus, message:'占用已结束，可以重新发起'}` |
| `meiji-images` | ① 图片操作结束时有待确认的候选图（目标为本次生成的卡片）；② 会话调用 `meiji_wait_images`（目标为传入的 itemIds，省略时为调用当时本集全部缺图卡片） | `等待图片就绪：{n} 张卡片` | 目标卡片都有图（`pictureOf(item).localPath` 非空且不 stale），且本集 `pendingImages` 中没有这些卡片的候选 | `{items:[{itemId, name, ready}]}` |

- 状态映射（kind 为 `meiji`）：操作 completed → `completed`；cancelled → `killed`（detail「已停止」）；failed → `failed`（detail 为错误信息）；review_failed → `failed`（detail「审核未通过」）。模型以 result 里的 `status/reviewPassed/failures` 为准。
- 进度：每次收到 `notifyProject` 时，用 `handle.updateProgress('{已结束任务数}/{任务总数} {当前任务 label}[ 排队中]')` 更新进度；每个任务结束时 `handle.append('{任务 label}：{状态}\n')`，每个任务只追加一次。
- `outputLimitBytes: 16384`。
- 取消 `hooks.cancel(reason)`：
  - reason 是 `'owner disposed'` 或 `'jobs service disposed'` → 只脱离：`done` 立即以 `killed`（detail「会话已关闭，操作仍在执行，可在面板查看」）结束，**不停止操作**（AC-9）。
  - 其他原因 → `tasks.cancel(operationId, projectId)`；操作已结束时忽略 404。
- **创建页的项目摘要草稿**（`project-summary` 且 `draft: true`、没有 projectId）**不登记 job**：项目还没创建，弹窗自己显示进度与结果并负责取消；唤醒会话只会多一轮无用的模型请求，模型也无法对草稿做任何操作。会话创建项目时仍是「创建后提取」，这个提取操作登记 job。
- 已完成短路：`task.ready` 返回 `alreadyCompleted` 时，工具先调用 `registry.wait(jobId, 5000, sessionId)` 再 `registry.remove(jobId)`。被 wait 收走的结算不会再触发通知（H7）。

### 6.2 互斥规则

`conflict(holder, wanted) = 同一项目 && ((holder.kind === 'generate' && wanted.kind === 'generate') || 剧集重叠)`，其中剧集重叠 `= !holder.episodeId || !wanted.episodeId || holder.episodeId === wanted.episodeId`。

| 已占用 ＼ 新发起 | 生成·第 N 集 | 生成·第 M 集 | 生成·项目级 | 编辑·第 N 集 | 编辑·第 M 集 | 编辑·项目级 |
|---|---|---|---|---|---|---|
| 生成·第 N 集 | 拒 | 拒 | 拒 | 拒 | 允许 | 拒 |
| 生成·项目级 | 拒 | 拒 | 拒 | 拒 | 拒 | 拒 |
| 编辑·第 N 集 | 拒 | 允许 | 拒 | 拒 | 允许 | 拒 |

没有 projectId 的操作（创建项目、创建页的项目摘要草稿）不占用。草稿按会话归属，由创建弹窗在切换剧本或关闭时取消旧草稿（D2）。

### 6.3 停止权限

| 谁 | 能停止什么 | 方式 |
|---|---|---|
| 面板「停止」按钮 | 项目内任何操作（面板或会话发起） | `operation-cancel` → 操作取消 → job 随之以 killed 结束，会话收到通知 |
| 会话模型 | 只能停止本会话发起的 meiji job，以及本会话的等待类 job | `job_kill`；对面板发起的 meiji job，守卫直接拒绝 |
| 其他会话 | 不能停止 | job 按会话 owner 隔离（H1） |

### 6.4 会话工具清单

公共参数只定义一次（`tools/session-operation-tools.js`）：
- `episodeNumber`：integer，≥1。
- `mode`：枚举 generate / regenerate / modify，各工具可以收窄。
- `requirements`：string。

## 附录 B：会话说明 `skills/session/panel.md` 目标文本

```markdown
---
name: skill-gongyong-panel-generate
description: 短剧视频制作：在会话中创建或打开短剧项目，按集生成摘要、剧情、角色/场景/道具图片、镜头表、每秒指令和成片视频，并跟踪后台任务结果。
---

会话负责理解用户意图、规划业务步骤和调用 meiji 工具；内容由工具背后的生成流程产出并保存，不在聊天里代写或另存一份。

一、先查询：调用 meiji_context_query 了解当前项目、剧集和各阶段状态。创建或打开项目用 meiji_project_manage；导入剧本会自动提取项目摘要（返回 jobId）。

二、阶段顺序：摘要 → 剧情 → 镜头表 → 每秒指令 → 图片 → 成片。镜头表和每秒指令不依赖图片，先做完；图片在成片前处理（见第五条）。各阶段工具：
- meiji_generate_project_summary：按剧本重新提取项目摘要
- meiji_generate_summary：本集摘要（新集只能是最后一集的下一集）
- meiji_generate_story：剧情（大纲、角色、场景、道具），only 只生成其中一项
- meiji_generate_images：图片，省略 itemIds 时为本集全部缺图卡片
- meiji_generate_shot_table：镜头表
- meiji_generate_seconds：每秒指令，track 指定镜头
- meiji_wait_images：登记等待，用户在面板处理完图片时通知你
- meiji_generate_film：成片，parts 可选 storyboard / video / tail，track 指定镜头
按查询结果跳过已通过且未过期的阶段。多步骤请求先用 todo_write 列出业务步骤，每次只调用一个工具，按顺序执行，不要合并。

三、模式：generate 首次生成；regenerate 用户明确要求重做，新要求放 requirements；modify 基于当前内容局部修改，意见放 review。本次要求只作用于本次任务，不保存为永久配置。

四、后台任务：生成工具返回 jobId 后本轮可以结束，任务结束时你会收到通知；需要进度时用 job_output（可带 wait）。结果中 status=completed 且 reviewPassed=true 才算完成，可以继续依赖步骤；review_failed、failed、cancelled 时停止依赖步骤，报告 failures 中的原因，不自行重试。返回 busy 表示本项目正在执行其他生成（可能由面板发起）：告诉用户正在执行什么；工具已登记等待任务，结束时会通知你，届时再重新发起本步骤。

五、图片：AI 生成的图片不稳定，用户也可能想用自己的图片。每秒指令完成后、成片之前，用 meiji_context_query 查看本集缺图卡片（images.missing）。有缺图且用户事先没说明处理方式时，用 ask_user 询问：自己在面板导入或从素材库选；AI 生成全部缺图；AI 只生成指定卡片；不要图片直接成片。
- 选自己处理：调用 meiji_wait_images，告诉用户去面板处理，收到就绪通知后再做成片；用户在会话里说「继续」时，用 job_kill 停止等待后继续。
- 选 AI 生成：调用 meiji_generate_images。结果含 pendingConfirm 时请用户到面板确认或放弃，收到通知后再做成片；有被放弃的卡片如实报告，按用户要求处理。
- 用户没有选「不要图片」时，不在缺图状态下发起成片。多集一起做时，先完成各集文字阶段，再一次列出所有集的缺图。

六、停止：只能用 job_kill 停止本会话发起的任务；面板发起的任务只能在面板停止。被面板停止的任务记为 cancelled：停止依赖步骤并报告，不自行重做。

七、面板发起的任务结束时你也会收到通知：只用一两句话告知结果，不主动发起新的生成，除非它属于用户已要求的计划。

八、用户已要求的多个步骤连续执行，不在步骤之间重复请求确认。最后简要说明已完成的项目、集数和阶段，或未完成的原因；不复述参数、密钥和内部日志。任务与步骤详情在面板查看。
```
