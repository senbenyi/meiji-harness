# 图片生成状态与剧情状态分离

- 类型：Bug 修复（完整流程：涉及状态写入路径与多个文件）
- 目标：生成/重绘/部件图/铅笔分镜图片的失败、停止、开始与确认，只改对应图片节点状态，不改剧集/项目级剧情状态（activityError）。
- 非目标：不改图片生成期间的 `activity` 互斥锁（生成中仍禁止并发操作）；不改大纲、角色、场景、道具节点逻辑；不改导入图片、参考图等手动图片操作。

## 调用链与证据
图片生成：`runOperation` → `image-operations.js opImage/startImage` → `projects.save({activity:'image:Cxx', activityError:null})`（清除剧情错误）→ 后台 `submitAssetImage` → 失败/停止 `.catch` → `projects.save({activity:null, activityError: msg})` → `review-checks.js` wrapped.save：以 `changes.activityError` 为信号把图片节点置 FAILED，但 `activityError` 同时写入剧集，并经 `episode-rules.js foldEpisode` 写入项目根。
前端读取：`project-session-view.js:161` 剧集页顶部 notice、`generation-stage-views.js:207`/`character-views.js:51` 详情提示、`chat-bridge.js:74` 会话状态均显示 activityError；`image-review.js` 图片门以 `episode.activityError` 作为图片错误来源。

| 来源（文件:行） | 结论 |
|---|---|
| `server/flow/operations/image-operations.js:123,199,215,240,247,412` | 图片生成各阶段读写剧集级 activityError |
| `server/runtime/review-checks.js:138-149` | 图片节点失败依赖 changes.activityError 信号 |
| `shared/episode-rules.js:19` | 剧集 activityError 同步到项目根 |
| 探针（失败/停止各一次） | 前：activityError=null；后：剧集与根 activityError=图片错误，图片节点 failed，剧情各节点不变 |

1. `meiji/server/runtime/review-checks.js` wrapped.save — 图片生成类操作（image、revise-image、part-image、pencil）保存时，`next.activityError` 保持保存前的值；仍用 changes.activityError 作为图片节点失败信号 → AC-1/2/3
1b. `meiji/server/runtime/review-checks.js` prepareChecks 开始保存 — 实施中发现任务开始时统一清空 activityError；图片生成类操作跳过 → AC-3
1c. `meiji/server/flow/tasks/cancel-interrupted-tasks.js` interruptRunning — 实施中发现服务重启取消中断任务时清空 activityError；中断的是图片生成（image:/pencil:/confirm-image）时保留 → AC-2
2. `meiji/server/flow/operations/image-operations.js` opConfirmImage — 确认图片时不再写 `activityError: null` → AC-3
3. `meiji/client/image-review.js` — 图片门错误改读对应图片节点 error，不再读剧集 activityError → AC-5
4. `meiji/tests/api-failure-state.test.js` — 新增失败/停止/开始保留剧情错误与图片节点失败断言 → AC-1/2/3/4
5. `meiji/tests/model-ui.test.js` — 新增图片门读取节点错误、忽略剧情错误断言 → AC-5
