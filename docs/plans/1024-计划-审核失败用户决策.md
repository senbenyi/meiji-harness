# 审核失败用户决策

- 类型：完整流程，终态通知与用户触发重试。
- 目标：内容审核修订耗尽后明确等待用户操作，不唤醒主Agent自动派发；用户可继续最后候选、停止或从当前正式稿重新生成。
- 非目标：改变默认三轮上限、自动修复上游/规则、其他制作节点。
- 用户追加：独立失败决策卡片；审核遍历全部故事段并汇总问题；有效生成结果自动保存，审核未通过也不撤销保存。此新设计替代原仅审核通过保存的设计。

## 追加范围（用户本轮指示）
- 独立 client/ui/failure-decision.js，自己的深浅主题样式、保存事实、失败原因及操作区；由task-operation挂载并登记静态资源。
- 两盒子每次generate/revise有效输出即保存；每一步用上一有效输出指纹做并发校验；通过审核才清空用户意见，未通过标记rejected。报告/历史/按钮从真实saved步骤投影，不把保存等同审核通过。
- 故事大纲实际历史：每轮完整输入3段，审核问题数依次2/1/2/1，程序无逐段遇错退出；存在候选反复留下炮底/入舱顺序矛盾及审核把相同引文判改动。为审核加入完整遍历、跨段状态核对、全部问题一次汇总约束，为修订加入逐项关闭+全文回归约束；不覆盖用户持久化业务规则。
- AC-6：有效候选即使审核失败/审核网络失败也已保存，结构无效与外部并发修改不覆盖；状态与真实结果相符。
- AC-7：审核输入完整大纲，明确要求全部段完整审核；多个问题完整进入同一轮修订，未截断首个问题。
