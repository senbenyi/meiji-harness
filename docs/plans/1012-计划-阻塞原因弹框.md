# 面板操作阻塞原因弹框

- 类型：UI 交互修复
- 目标：面板操作因运行状态被冻结或服务端拒绝时，以弹框明确显示阻塞原因。
- 非目标：不改变任务受理、队列、前置校验和取消规则；不改 Harness 上游。

## 验收标准与调研结论
| AC | 输入/状态 → 可观测结果 | 状态 | 依据 |
|---|---|---|---|
| AC-1 | 存在 `running` 任务 → 面板操作按钮保留 `aria-disabled=true` 语义且点击可达；显示占用任务名称和等待说明，不提交请求 | 已确认 | `task-panel.js` 公共 `button()` 将 busy 写成原生 disabled，浏览器不派发 click |
| AC-2 | `act()` 的服务端提交返回错误 → 显示含服务端具体错误的弹框 | 已确认 | `act()` 目前只写底部状态并重新抛错，按钮 catch 空吞异常 |
| AC-3 | 未阻塞的生成、提交成功及任务取消 → 行为保持原样 | 已确认 | 生成由 `button()` → `act()`；取消路径显式不使用 busy 冻结 |
| AC-4 | 请求失败、运行中阻塞和正常提交的 DOM 测试 → 验证三个结果 | 已确认 | 定向 DOM/UI 测试 14 项通过，全量测试 226 项通过 |

## 调研与证据
实际可见窗口停留在任务历史页，该页本身没有镜头表“AI生成”按钮；最近的镜头表任务结束于失败，之后没有新任务受理。面板节点按钮在运行任务期间还会写成原生 `disabled`，确有点击不可响应、无法告知原因的实现路径。服务端提交拒绝则目前仅更新面板底部状态。

调用链：节点按钮 → `button()` 冻结 / `act()` → `sendCommand()` → `/api/meiji/task-command` → 服务端校验。GitNexus `renderTaskPanel` upstream impact 为 CRITICAL（35 个节点、20 条流程）；实现限定在该组件的按钮与错误反馈，并用局部渲染测试检查回归。

## 改动
1. `meiji/client/task-panel.js` — 运行中操作按钮保留禁用语义但接受点击以说明当前运行任务；请求失败时弹框显示服务端原因 → AC-1/2/3。
2. `meiji/tests/stage07-blocked-action-dialog.test.js`、`meiji/tests/stage09-script-split.test.js` — 覆盖忙碌点击、服务端拒绝、正常提交及既有表单错误反馈 → AC-4。
