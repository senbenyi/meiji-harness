# 镜头表剧情时间与每秒镜头设计

- 类型：完整流程，提示词职责调整。
- 目标：镜头表先规划剧情与时间，超过 15 秒的小剧情按同名加序号拆段；每秒指令负责具体镜头与空间调度。
- 非目标：不改变逐镜调用方式、保存格式、时长校验、UI 或运行数据，不调用付费生成接口。

## 验收标准与调研结论

## 调用链与证据

操作 registry → shot-operations.js 的 generateShots/generateShotSeconds → shot-text-prompts.js → text-prompts.js → TextStepModel → task/review skill 与 output-protocols.js。镜头表正文自由文本；仅 `## Snn / Ns` 解析为编号和时长。每秒指令仍返回当前镜头 shots JSON，程序检查 durationMs。

GitNexus 原索引过期，已在改动前刷新至当前 HEAD 2680c07。查询 buildSecondsPrompts/TextStepModel 的 context 与上游 impact：直接影响逐镜生成、预览及 all-seconds、step-prompt-model、prompt-nodes、seconds-feedback 等测试；动态 registry 分派以源码补核。改动不涉及队列、网络或数据迁移。

## 改动

1. `meiji/skills/task/generate-shot-table-skill.md`、对应两份 review skill：时间优先、同剧情分段命名，删除摄影细节要求，保留剧情交接 → AC-1/2/3。
2. `meiji/skills/task/generate-seconds-instructions-skill.md`、对应 review skill：承接具体调度、人数/景别/切镜规则，解除必须继承上游摄影安排 → AC-4。
3. `meiji/skills/output-protocols.js`：镜头表改为剧情条目及同名分段示例；每秒 transition 允许本阶段有依据的 cut，JSON 字段不变 → AC-2/3/4。
4. `meiji/server/prompts/models/text-step-model.js`、`shot-text-prompts.js`：三类编排保持剧情事实，单镜每秒补充当前关联人物/场景/道具资料 → AC-3/4。
5. 相关测试与 `.agents/meiji-dev.md`：覆盖分段标题实际保存/显示、生成审核修订编排分工、当前镜头资料筛选；写明新的职责 → AC-5。

验证：仅运行上述功能及提示词相关测试；生成 28 场景提示词快照并对比，记录删句的迁移去向；detect_changes 核对范围，确认无执行任务后重启 Harness，最终统一更新图谱。

## 验证结果

实施前相关测试：71 通过，0 失败，0 取消。实施后加入卡片 UI 与新场景测试，共 124 通过，0 失败，0 取消；仅运行镜头表、每秒指令、提示词及相关卡片 UI 测试，未运行全套测试。

AC-1/2/3：三类提示词均使用时间优先与同名分段规则；保存读回及镜头表/每秒指令/成片卡片测试保留 12 秒、8 秒同名分段标题，S03 使用独立事件标题。单镜修订保留分段尾数。

AC-4/5：本镜关联场景的地标/光位及人物/道具资料进入生成、审核和修订，不带其他场景布局或图片地址；没有上游摄影安排时，新设计的 cut 能通过程序校验并保存；现有逐镜调用、前镜承接、失败保存、毫秒校验测试通过。

28 个场景提示词快照已比较，181 条旧措辞逐项记录去向，见 [提示词差集](../reports/镜头表剧情时间-提示词差集.md)。GitNexus detect-changes：风险 low，业务变更集中在两条每秒边界常量、buildSecondsPrompts 和输出协议；检测还匹配到 UI 测试辅助符号，没有新增业务调用链。

真实大模型生成质量未验证，本轮未调用付费接口。
