# 短剧生产级

- 类型：新功能（含 Bug 修复与调研验证）
- 目标：运营在工作台按「导演 Skill + 剧情规划 Skill」让 qwen3.8 分步规划剧集，每步审核、手改或补充要求后重新生成，定稿后按集生成细节级镜头（H3 对白音频），镜头落本地并合成本集成片。
- 调研来源：`docs/research/调研-短剧生产级产品审查.md`

## 人工决策

已定（2026-09-21）：
- 创作质量沿用设置页，不新增项目级规格。
- 每个导演是一个标准 Skill；通用 `drama-planning` Skill 与导演 Skill 分层；导演页直接编辑 SKILL.md 全文。
- 删除导演预设，不再区分自由/导演模式；项目工具改为 `call_tools_load` 的 `project` 组。
- 集数、单集时长由 Skill 约束模型判断；配音使用 H3 音画联合生成；镜头视频落本地。

实施前需授权：
1. **铁律修订**：`.claude/standards.md` §5“插件不允许上传、下载、保存文件方法 / 媒体一律使用服务器 URL”改为“模型产物由 Worker 经 `saveMedia` 保存到所属项目目录；页面仍经认证 URL 访问”。阶段 7 开始前确认。
2. **删除本机预设**：阶段 2 需删除 `~/.dsh/.agent-presets/elysium-director/`（安装脚本只增不删）。执行前再次确认。
3. **旧数据迁移**：现有项目的 `storyboard.json` 迁为第 1 集分镜；`pools/directors.json` 迁为导演 Skill 后归档到 `runtime/migrations/`，不删除。
4. **阶段 0 实测**会占用 qwen3.8 与 H3 GPU 各约数分钟。

## 设计要点

### Skill 根与格式

- 唯一 Skill 根：`$ELYSIUM_HOME/pools/skills/`，由 `src/database/paths.js` 新增 `skillsRoot()` 构造。
- 目录：
  - `drama-planning/SKILL.md` — `metadata.kind: planning`；正文为总流程；`references/steps/{series,outline,script,cast,storyboard,shot-prompt}.md` 为每步提示词；`references/checklist.md` 为质检清单；`references/shot-prompt-example.md` 为细节级范例（取自 `docs/design/propment.md`）。
  - `director-<id>/SKILL.md` — `metadata.kind: director`、`metadata.display_name`、`metadata.order`；正文为风格、题材、节奏、镜头语言、声音对白、禁忌；`references/works.md` 为代表作与 TOP 参考；可选 `references/steps/<step>.md` 覆盖通用步骤。
- 模型参数由 Skill 控制：`drama-planning` 的 `metadata.llm` 可写 `max_tokens`、`timeout_ms`、`temperature`，代码只做上限钳制（max_tokens ≤ 32768、timeout ≤ 600000），不写死取值。
- Agent 侧：`_base/agent.cordis.yml` 的 `skill-filesystem.customSkillDirs` 指向同一根，聊天与工作台共用一份文件。
- 默认 Skill 随插件发布于 `dsh-elysium/skills/drama-planning/`；插件启动时仅在目标不存在时写入，已存在绝不覆盖（运营修改不会被重装冲掉）。

### 规划步骤与版本

| 步骤 | 范围 | 输入 | 输出（代码校验结构与上限） |
|------|------|------|---------------------------|
| `series` 立项 | 项目 | 导演 Skill、题材/梗概（运营填写） | 一句话梗概、题材、集数、单集秒数、世界观、角色表（id、名称、外观、音色、性格）、场景表 |
| `outline` 大纲 | 项目 | 立项定稿 | 每集标题、剧情、结尾钩子 |
| `script` 剧本 | 单集 | 立项 + 大纲 + 本集 | 分场；每场地点、时间、情节、对白（说话人、台词、情绪） |
| `storyboard` 分镜 | 单集 | 剧本定稿 + 角色/场景 | 镜头：角色列表、场景、景别、运镜、时长（1–15 秒）、动作、对白、字幕、备注 |
| `shot-prompt` 镜头提示词 | 单镜 | 分镜该镜 + 角色/场景卡 + 范例 | 细节级提示词全文（逐镜调用，避免输出截断） |

- 每一步保存为 `{ step, episode?, shot_id?, versions: [{ id, content, source: generated|edited, request, created_at }], final }`。
- 生成：`通用步骤文件（导演 references/steps 同名文件优先）+ 导演 SKILL.md 正文 + 前序定稿 + 运营补充要求` → `completeStructured`。
- 重新生成、手改都追加版本，不覆盖；定稿只指向某个版本。上游定稿变化时，下游标记“需复核”，不自动删除。
- 安全上限（代码）：集数 ≤ 100、每集镜头 ≤ 200、单镜提示词 ≤ 20000 字；数量本身由 Skill 决定。

### 项目数据结构

```text
projects/<id>/
  project.json        + genre, synopsis（运营输入），director = director-<id>
  planning.json       立项、大纲的版本与定稿
  anchors.json        + kind: role|scene，role 对应角色表 id
  episodes/<n>/
    episode.json      标题、状态、交付物
    script.json       剧本版本与定稿
    storyboard.json   分镜（幕/镜），镜头新增 roles[]、scene、shot_size、camera、duration、dialogue[]、prompt、prompt_versions
  media/              镜头与成片（本地）
```

## 验收标准

- AC-1：运营不用聊天、不填技术字段，可在工作台完成「建项 → 成片下载」。
- AC-2：剧情规划的每一步由 Skill/提示词文件定义；改文件即可改变规划方式，无需改代码；每步输出可审核、手改、改提示词重新生成。
- AC-3：同一角色跨镜头外观一致；多角色可同镜。
- AC-4：镜头提示词达到参考提示词的细节级（场景、主体、分秒阶段、运镜、光线、声音/对白、字幕）。
- AC-5：成片含 H3 生成的对白与环境音；角色音色可保持一致。
- AC-6：重拍、删除、并发操作不会让镜头指向错误视频；镜头视频在本地可用。
- AC-7：页面全流程经人工验收。
