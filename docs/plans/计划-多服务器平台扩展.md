# 多服务器平台扩展实施计划

日期：2026-09-14

状态：已按用户确认实施步骤 1→2→3→4→5（2026-09-15）。文件与验证结果见[实施记录](实施记录-多服务器平台扩展.md)。

职责：将[设计](../design/设计-多服务器平台扩展.md)拆分为可验证步骤，并限定未接入平台的预留范围。

## 1. 范围

先建设现有 `dsh-elysium` 插件内部的通用服务器配置、任务绑定和切换能力；不新建 Harness 插件。

以下包名仅登记在文档，不创建目录、代码、依赖或空实现：

```text
dsh-elysium/src/servers/providers/featurize/
dsh-elysium/src/servers/providers/vast/
dsh-elysium/src/servers/providers/runpod/
dsh-elysium/src/servers/providers/autodl/
```

平台接入方式暂为手工登记已运行服务。原 `runpod/` 运维脚本保持原用途，不整体改名或复制为四个平台的脚本。

## 2. 步骤 1：确认边界并建立统一配置

**涉及文件**：拟新增 `dsh-elysium/src/servers/schema.js`、`store.js`、`resolve.js`；修改 `src/config.js`；必要时增加 `harness/.dsh/servers.example.json` 并调整 `harness/scripts/install.mjs` 的示例排除规则。

**改动**：

- 实现服务器身份、平台标记、服务类型、HTTP/SSH 连接描述及按服务选择的默认目标。
- 实际清单位于 `${DSH_HOME}/servers.json`；配置变更使用版本检查和临时文件加 rename，避免两个设置窗口相互覆盖。
- 无清单时保留 `COMFYUI_URL` 和原 Qwen 配置；有清单时使用清单中的默认选择，不混合覆盖来源。
- 清单只存凭据引用；接口返回脱敏信息。
- 安装不覆盖正式清单，不检查远端服务或端口。
- 核验 LLM 的宿主空闲与配置应用接口，形成已验证/未支持结论。此步不实现运行中无感切换。

**验证**：新增 `dsh-elysium/tests/servers-config.test.js`，覆盖服务类型、未知目标、URL与端口、重复身份、配置版本冲突、缺失清单回退；在 `harness/tests/` 验证重装不覆盖服务器清单和凭据。

## 3. 步骤 2：让任务固定服务器归属

**涉及文件**：`dsh-elysium/src/jobs/create.js`、`src/video/service.js`、`launcher.js`、`worker.js`、`execution.js`；`src/comfyui/client.js`、`execution.js`、`submission.js`、`media-reference.js`；`src/tools/comfyui-tasks.js`。

**改动**：

- 在新任务创建时解析一次目标，保存独立后端快照；视频计划校验也使用同一目标，不能先按A验证素材再在B创建任务。
- worker、恢复操作从任务快照恢复运行上下文，不取当前默认值替换旧任务目标。
- 保留已有 `server_url` 不一致拒绝逻辑。
- 原子工具使用明确的登记服务器身份；`minimax-h3` 旧参数只作为明确配置的兼容映射，不能在切换后悄悄改指向。
- 按旧任务留下的服务器证据进行兼容解析；证据缺失或冲突时拒绝自动恢复。

**验证**：新增后端归属测试；A创建任务后默认切到B，恢复、查询及取消仍只请求A；两个服务器出现相同 `prompt_id` 也不能串用。检查工作流保存前失败的任务仍有后端记录，旧任务归属无法确定时不发远端请求。

## 4. 步骤 3：批量生产与素材兼容

**涉及文件**：`dsh-elysium/src/video-production/runner.js`、`state.js`、`reference-frame.js`；`scripts/production-runner.mjs`、`preview-shot.mjs`；必要时 `src/video/artifacts.js`、`src/assets/catalog.js`、`src/http/media-routes.js`。

**改动**：

- 一轮批量生产固定服务器，生成、历史查询、参考帧提取和恢复全部复用该目标。
- 项目状态与媒体展示保留历史任务的原服务器归属，不使用当前默认服务器重建旧 URL。
- 跨服务器参考素材给出明确不兼容提示，保留当前 `/view` 归属校验，不添加媒体搬运。
- 冻结案例入口 `runpod/scripts/third-cup-preview.mjs` 保持原用途，记录它不属于动态切换入口，避免顺手改动历史制作流程。

**验证**：生产中切换默认值后，后续镜头仍使用本轮原服务器；A素材不能作为B的同名文件使用；历史媒体访问不因默认切换改域名；复用原生产回执时检查服务器身份。

## 5. 步骤 4：通用连接与显式切换

**涉及文件**：`harness/scripts/tunnel.mjs`、`start.mjs`；`dsh-elysium/src/servers/resolve.js` 及必要的运行检查模块。是否修改 `harness/.dsh/settings.yaml` 取决于步骤1的 LLM 核验结论。

**改动**：

- SSH 隧道参数由登记信息提供；保留原 `qwen` 调用兼容入口。
- 只管理自己创建的隧道和控制句柄；端口被其他进程占用时报告冲突，不终止无关进程。
- 不同 ComfyUI 目标使用独立本地端口，保留旧任务需要的原隧道。
- 切换前显式检查目标服务及所需工作流节点、模型信息，检查失败保留原默认配置。检查成功不等于已经验证画质或完整生成能力。
- 默认切换与任务快照读取具有明确原子边界，不存在半次配置生效。
- LLM 只有在宿主空闲与应用机制已验证时才提供即时应用，否则只保存下次启动生效的选择。不新增代理网关作为未经审核的替代方案。

**验证**：在本机模拟两个 HTTP 服务和 SSH 子进程，验证端口冲突、断线、身份变化、切换失败、旧隧道保留；确认安装脚本仍无远端检查。测试只用临时端口与测试配置，不修改用户 `~/.ssh/config`。

## 6. 步骤 5：服务器设置与切换回执

**涉及文件**：拟新增 `dsh-elysium/src/http/server-routes.js`、`src/client/workbench/servers.js` 与必要 API 模块；修改 `src/index.js`、`src/client/workbench/index.js`、`projects.js`、`scripts/client-source.mjs`；必要时修改 `harness/.dsh/profiles/web/cordis.patch.yml`。

**改动**：

- 服务器设置展示手工登记目标、服务类型、当前选择、检查结果与待生效状态。
- 使用现有注入 token 和 URL 构建能力；不在浏览器暴露平台凭据。
- 切换回执说明新任务使用新目标、旧任务继续原目标；任务详情能看到所属服务器。
- 未接入适配包不显示登录或自动租机操作；有任务引用的配置只允许停用，不能直接删除追溯信息。
- 客户端沿用 `React.createElement`、无 JSX、无 bundler；新增模块维护拼接顺序。
- 当前源码直接使用宿主 `{ id, factory }`，规范描述的 `load(name, factory)` 适配器尚未在拼接脚本中实现。新增模块前先确定符合规范的最小适配方式，不扩展为全量客户端重构。

**验证**：界面测试覆盖目标列表、失败保留原选择、切换回执及禁用状态；认证测试覆盖所有新端点；模块拼接和构建通过。

## 7. 后续平台接入规则

实际决定接入某个平台时，才创建其预留模块，并读取该平台当时的官方接口文档。适配器只将已授权的实例信息转为统一连接描述；平台 API 的错误和未支持能力必须如实返回。

每接入一个平台，单独增加脱敏响应样本测试和实例验收记录。没有实测账号和实例时标记“未验证”，不以模拟测试替代平台接入成功。

不将用户提供的 GPU 报价写死在核心配置校验中，也不根据价格自动租用或切换实例。

## 8. 逐步验证与最终验收

后续每一步完成后运行：

```sh
cd dsh-elysium && npm test
```

涉及本机启动、隧道、安装或 settings 时，在仓库根运行：

```sh
node --test harness/tests/harness-scripts.test.mjs harness/tests/harness-settings.test.mjs
```

新增 `harness/tests/` 测试也加入执行范围。涉及客户端或入口构建时运行 `cd dsh-elysium && npm run build`。实施中的逐步测试与最终结果见实施记录；没有启动或租用真实实例。

最终验收以两台模拟服务器为基础：切换前任务归属A，切换后新任务归属B，恢复与素材无串用，批量生产不被全局默认值中途改变。实际跨平台验收留到对应平台确实接入后进行。

## 9. 本轮交付

已完成统一配置、任务和批次归属、手工连接与切换、工作台服务器设置。未接入平台仍只约定包名；没有新增 provider 源文件、目录、依赖或真实服务器配置。
