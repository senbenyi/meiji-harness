# 重启取消排队任务

- 类型：完整流程
- 目标：服务重启时，尚未开始的排队任务结算为已取消；任务管理文件改名为 `task-manager.js`。
- 非目标：不改进行中任务的已作废结算，不改面板重新加载只取消运行任务的规则，不改组内前序停止后的作废规则。

## 验收标准与调研结论
| AC | 输入/状态 → 可观测结果 | 已确认/未确认/未验收 | 依据或缺口 |
|---|---|---|---|
| AC-1 | 重启时存在排队任务 → 任务状态为 cancelled（已取消），未开始步骤为已取消，节点按入队快照恢复 | 已确认 | `recover` 目前把排队和运行都写成 superseded |
| AC-2 | 重启时存在运行任务 → 任务仍是 superseded（已作废），节点为已取消并保留内容 | 已确认 | `#finish` 对已开始任务把 superseded 写成节点 cancelled |
| AC-3 | 任务服务文件名为 `task-manager.js`，原导入指向新文件 | 已确认 | 现文件是 `server/flow/tasks/task-service.js` |

## 改动
1. `meiji/server/flow/tasks/task-service.js` 改名为 `task-manager.js`；`recover` 对 `queued` 使用 `cancelled` 和原因「服务重启，排队任务已取消」 → AC-1、AC-2、AC-3
2. 导入与开发说明中的文件路径 → AC-3
3. `meiji/tests/stage08-lifecycle.test.js`、`meiji/tests/stage11-workflow-states.test.js` → AC-1、AC-2

验证：`cd meiji && node --test tests/stage08-lifecycle.test.js tests/stage11-workflow-states.test.js` — 通过。

`cd meiji && node --test tests/stage08-lifecycle.test.js tests/stage11-workflow-states.test.js`：31 通过，0 失败。排队任务重启后为 cancelled，原因「服务重启，排队任务已取消」；运行任务仍为 superseded。
