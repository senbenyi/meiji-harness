# 大纲承担最终剧情改编

- 类型：完整流程，修改节点职责和三动作规则，并同步字段说明、测试及开发文档。
- 目标：故事大纲承担最终剧情改编及人物塑造，以连贯饱满和可观看性为目标，时长仅为最终输出粗估。
- 非目标：不改JSON结构或接口，不改已有项目规则快照，不重启、不发起真实模型任务。

## 验收标准与依据

- AC-1：允许基于工作剧本补足因果、人物动机、行动、对白和必要过渡；保护用户明确锁定的主题、人物身份关系、关键事实、结局及逐字要求。没有锁定的原话可以修饰，不能同时要求逐字保留全部原稿。
- AC-2：大纲是最终叙事稿，正文承载完整改编，锚点及相关字段基于最终正文；下游只做资产与视听实现，叙事问题返回大纲，不让下游改剧情。
- AC-3：输入中的时间码、总时长、每场时长和估时均不构成剧情/分段/审核预算；完成内容后仅输出duration_seconds参考值，不能凑时长或仅因秒数拒绝。
- AC-4：审核允许有据且符合授权的改编；一般上游叙事缺口在本节点修复，只有无法兼容的明确锁定要求或必须由用户决定的核心歧义停住。既有连续性和状态核对保留。
- AC-5：项目初始化、三动作提示词、输出契约和大纲执行测试通过；不声称模拟测试能证明创作质量。

源码证据：默认规则skills/story_segments.json在createNode时写入项目node_state；Executor调用composeNodePrompt使用保存规则。当前禁止新增事件与修改原话，与新职责冲突；输入剧本自身含预算与时间码，不能把它们当创作约束。下游shot_design规则已禁止新增上游关系/独立事件/台词，保持其现有边界。

## 改动

1. skills/story_segments.json：重写三动作的职责、改编权限、连续性、定稿和时间边界。
2. story_segments/definition.js及docs/project_detail.json：仅同步body与duration_seconds含义，不改字段/类型。
3. tests/output-definition.test.js：扩展规则接入测试，确认含固定时长的输入不会变成系统任务预算，三动作均携带改编授权和定稿边界；不伪造模型语义验证。
4. docs/开发方向.md：替换上一版“只忠实提取”的大纲规则边界，同步估时和下游责任。
5. 用户追加要求同步镜头表规则：skills/shot_design.json三动作明确只做视听实现、不重复改编；叙事问题返回大纲，技术问题由镜头修订。测试覆盖两节点提示词和输出契约。
6. tests/create-project-http.test.js：规则展示接口的旧字段说明断言同步到最终改编定稿表述，仍验证真实契约、鉴权及规则不被改写。

补充AC-6：镜头生成/审核/修订以已确认大纲为唯一叙事依据，不回原稿推翻改编，不新增或润色剧情/动机/对白，不为视频时长容量改戏；允许摄影、表演、声音设计以及已有连续动作的具体化。审核只核对叙事覆盖和视听执行问题，不重复剧情创作审核。
