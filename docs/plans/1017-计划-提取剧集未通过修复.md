# 提取剧集未通过修复

- 类型：小改动
- 目标：剧本模式提取剧集最新任务未通过时，在原因下方提供修复，直接按该原因修订上一版切点。
- 非目标：不改任务协议、不把失败改成未通过、不在已有正式剧集时弹出原结果修订框。

## 验收标准
| AC | 输入/状态 → 可观测结果 |
|---|---|
| AC-1 | 最新拆分任务未通过且有原因、当前无排队或运行 → 原因下方独立一排「修复」；顶部仍是重新生成或 AI生成、任务历史、查看规则 |
| AC-2 | 点击修复不弹框，提交 `script-split` / `revise`，意见为未通过原因，并接上本次执行意见 |
| AC-3 | 失败、已完成、排队、运行中不出现该按钮 |

## 改动
1. `meiji/client/project-ui.js` 的 `renderOverview`：未通过原因后追加修复行。提取剧集没有项目节点，候选在任务历史，因此无论是否已有正式剧集都提交 `revise`。
2. `meiji/tests/stage07-split-feedback.test.js`：覆盖未通过按钮位置与提交命令；既有状态断言保持。
3. `meiji/dev_docs/制作工作流.md`：补一句提取剧集未通过时的修复按钮。

图谱：`renderOverview` 上游影响为 CRITICAL，直接调用方只有 `renderTaskPanel`。改动限制在剧本模式拆分分支，不改其他节点按钮。

验证：`node --test meiji/tests/stage07-split-feedback.test.js`；刷新项目页确认未通过剧集卡出现修复。

## 验证结果
- AC-1/2/3：`node --test tests/stage07-split-feedback.test.js tests/stage07-panel.test.js`，15 项全部通过。未通过时原因下为「修复」，顶部保持 AI生成、任务历史、查看规则；点击提交 `script-split` / `revise`，意见为未通过原因加本次执行意见，无弹框。失败、完成、排队、运行中没有该按钮。
- 页面：服务已返回新的 `project-ui.js`。当前项目最新拆分任务已是完成，剧集卡不显示修复，与 AC-3 一致。未在生产项目上点击修复，避免另起一次真实切分。
