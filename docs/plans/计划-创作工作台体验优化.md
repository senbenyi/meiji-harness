# 创作工作台体验优化实施计划

日期：2026-09-12　状态：阶段 A–E 已实施；阶段 F 自动化与本地浏览器复核已执行，发布前人工验收尚有待办。

设计依据：[创作工作台体验优化设计](../design/设计-创作工作台体验优化.md)。问题依据：[浏览器调查](../research/调研-Harness展示布局与操作效率.md)。

本计划是现有产品闭环功能完成后的体验改造，不覆盖或重做旧计划阶段 1–2，不恢复已删除插件。复用现有项目、锚点、镜头和交付数据；不自动修改真实项目、不执行部署。

## 一、执行约束

- 按阶段顺序实施，每阶段形成可运行版本，结束后运行 `cd dsh-elysium-tools && pnpm build && pnpm test`，全部通过后才进入下一阶段。
- 现有未提交修改原样保留。每阶段记录实际改动文件、测试结果、浏览器验收和未解决项。
- 写操作验收使用独立测试数据或项目副本；《第三杯咖啡》原项目用于只读浏览与性能对照。
- 不引入新的 UI 框架、状态库、虚拟列表依赖；只有遇到本计划无法覆盖的具体问题再评估。
- 不在第一阶段提前删除旧组件；新视图接入并验收后，随对应阶段移除被替代的渲染路径，最终不保留两套制作 UI。
- 方案中的性能值是验收目标，禁止作为已测结果写入实施记录。

## 二、入口与依赖关系

```text
scripts/client-source.mjs（模块注册）
  → client/panel/asset-panel.js（工作台入口、导航状态）
      → asset-list.js（素材查询、网格、选择）
      → project.js（项目数据、写入协调、子页）
      → dialog.js（新增：公共选择对话框）
      → storyboard-view.js（新增：分镜列表、单镜详情）
      → panel-styles.js（工作台布局和视觉变量）
  → http/media-jobs.js（素材摘要、分页前搜索）
  → http/project.js（现有 CRUD；必要的摘要封面字段）
```

只抽取有明确职责或跨视图复用的模块；无需将每个按钮拆成文件。新增客户端模块必须同步注册，并验证构建后模块可加载。项目存储结构保持兼容。

## 三、实施阶段

### 阶段 A：基线与数据能力核对

**工作：**

1. 阅读当前入口、媒体 API、项目 API、任务元数据与客户端测试，核对部署代码和工作区差异。
2. 在 1440×900、100% 缩放重测真实 120 镜项目：可视行数、DOM/播放器数量、请求数、首屏时间与滚动表现。
3. 确认可用标题/提示词字段、图片 URL、是否存在视频封面；确认宿主公开挂载点。记录事实，不先添加字段或新服务。
4. 创建 `docs/implement/实施-创作工作台体验优化.md`，记录基线和后续阶段结果。

**门槛：** 构建和测试通过；明确摘要数据来源和工作台挂载方式。不能用虚构素材替代缺失字段。

### 阶段 B：工作台框架与连续导航

**主要文件：** `asset-panel.js`、`panel-styles.js`、新增 `dialog.js`、`scripts/client-source.mjs`。

**工作：**

1. 创建自有全屏工作区、“项目/素材/返回聊天”导航；移除旧 body paddingRight 布局机制，按生命周期清理样式与事件。
2. 建立顶层界面状态，保留项目、子页、选中镜头、筛选、页码和滚动位置。旧面板偏好仅迁移有意义的导航值，丢弃旧窄宽度。
3. 固定项目标题及子导航，增加响应式两列/单列降级规则。
4. 公共对话框具备视口定位、焦点约束、Escape、取消和返回焦点。将项目选择与锚点素材选择接入，避免尾部插入。
5. 暂时将现有业务视图接入新容器，确保功能仍可达。

**验证：** `panel.test.js`、`project-panel.test.js`、`client-source.test.js` 覆盖关闭清理、切换状态、弹层取消。浏览器检查两个选择器首屏可见，返回聊天后能恢复位置；不修改真实项目。

**完成门槛：** 阶段构建/测试通过；工作区可进可退，宿主聊天正常，选择器不再出现在列表末尾。

### 阶段 C：高效分镜浏览与安全编辑

**主要文件：** `project.js`、新增 `storyboard-view.js`、`panel-styles.js`、模块注册。

**工作：**

1. 替换全部展开的表单为幕导航 + 每页 30 镜紧凑列表 + 当前镜头详情。
2. 增加镜号/动作/字幕搜索、角色/状态筛选、结果数、分页与上一镜/下一镜。
3. 仅选中镜头读取媒体状态并挂载播放器；列表无逐镜状态请求。
4. 将默认表单改为只读详情，编辑时显式保存/取消；建立草稿离开处理、失败保留、重复提交防护。
5. 保留幕/镜增删改与排序；校准“标记待重拍”“解除素材关联”文案；排序和删除后校正选中位置。
6. 技术字段移入展开区；每个可编辑字段有持续可见标签。

**验证：** 在测试项目中覆盖保存成功/失败、放弃草稿、排序后选择、删除后选择、筛选分页边界；确认原始项目数据未被访问行为修改。

**完成门槛：** 构建/测试通过；真实项目最多渲染 30 行、工作台最多 1 个播放器，1440×900 至少看到 10 镜；镜号定位与上下文恢复通过。

### 阶段 D：素材网格、搜索和锚点选择

**主要文件：** `asset-list.js`、`http/media-jobs.js`、`project.js`、`dialog.js`、`panel-styles.js`。

**工作：**

1. 服务端白名单输出有依据的展示标题/提示词摘要；增加 `q` 校验及分页前过滤，保持原查询参数兼容。
2. 使用已有 total 显示结果数，默认每页 30 项；搜索防抖、取消旧请求、阻止过期结果覆盖。
3. 素材卡采用图片懒加载与视频无封面占位；点击创建单预览，不后台提取视频首帧。
4. 实现固定筛选区、清空条件、空结果与错误重试；原下载链接和档次/类型筛选保留。
5. 锚点改为图片卡与详情，合并重复入口；选择器使用明确选中 + 提交流程，失败可重试，取消零写入。

**验证：** `asset-list.test.js` 与媒体 HTTP 测试覆盖跨页搜索、旧数据无标题回退、total、参数校验、旧响应晚到；项目测试覆盖选择不提交/提交失败/成功替换。

**完成门槛：** 构建/测试通过；素材网格 video 元素为 0，查询范围不局限于当前页；筛选后仍能识别内容或明确看到短 ID 回退。

### 阶段 E：项目总览、交付审看与视觉收敛

**主要文件：** `project.js`、`http/project.js`（仅必要摘要扩展）、`panel-styles.js`。

**工作：**

1. 项目卡展示封面/占位、统计、更新时间和继续制作，新建通过对话框进入；项目摘要避免每张卡再取完整项目。
2. 交付页单成片预览、附件列表、下载入口和自适应文件大小；无版本关联时不自动配对字幕。
3. 统一字阶、间距、按钮、状态、焦点、骨架与错误样式，移除被替代的旧渲染代码和样式。
4. 检查窄屏详情返回、触屏点击区、键盘、200% 缩放及减少动态效果。

**验证：** 项目新建/继续/删除确认、空交付、失效 URL、B/KB/MB、预览切换释放旧播放器；人工审看与用户触发的真实下载。

**完成门槛：** 构建/测试通过；1440×900、1366×768、390×844 无遮挡、无页面横向滚动，主要任务不依赖悬停。

### 阶段 F：性能对照与整体验收

**工作：**

1. 同设备、同网络、相同数据对照阶段 A；分别记录冷/热加载各 5 次，交互延迟、请求数、DOM、主线程长任务和内存释放。
2. 检查隐藏页面暂停媒体与轮询、缓存失效、在途请求去重、连续开关 10 次不累积监听器/播放器。
3. 只有确认服务端素材扫描形成瓶颈时，才增加有界摘要缓存和可靠失效；独立补充测试并重测。
4. 依设计文档的 7 条场景完成浏览器验收，列出通过证据及未达目标项。
5. 更新 README 的工作台入口说明，并完成实施记录。调查中的聊天卡片失败记录复测结果；若仍存在，单独记录任务和错误证据，不宣称整条媒体链路全部通过。

**完成门槛：** 阶段构建/测试通过，设计的结构性能预算及操作场景通过，文档描述与实际一致。任何未通过项明确保留，不能只凭构建成功完成验收。

## 四、交付与发布边界

本计划完成实施后应交付代码、构建测试结果、浏览器验收记录、性能前后对照和使用说明。实际执行记录、已验证项目及剩余验收见 [实施记录](../implement/实施-创作工作台体验优化.md)。

发布时使用现有部署流程，记录当前构建版本与可回退包；不连带调整登录、模型配置和旧插件清理范围。部署与重启根据届时用户指令执行，不用本计划编写动作替代发布授权。
