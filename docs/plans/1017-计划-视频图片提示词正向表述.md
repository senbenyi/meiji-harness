# 视频图片提示词正向表述

- 类型：小改动以外的提示词修改（涉及 4 个源文件 + 2 个测试，按完整流程）
- 目标：直接发给 MiniMax-H3 与图片模型（gpt-image / krea）的固定文字改为正向描述；文生视频提示词节点要求模型在三段正文中使用正向描述。
- 非目标：只发给文本模型的节点规则（outline、shots、seconds、审核等）中的否定句不改；不改输出契约、字段、任务流程。

## 背景

MiniMax-H3、gpt-image、Sora 均没有 negative_prompt 参数，且 H3 有提示词扩写。写在正向提示词里的“不要/不/无 X”会把 X 带入语义，可能反而生成 X。

## 验收标准与调研结论
| AC | 输入/状态 → 可观测结果 | 状态 | 依据或缺口 |
|---|---|---|---|
| AC-1 | 首尾帧、多模态视频请求 → prompt 中程序拼接的固定文字不含否定句 | 已确认 | `server/http/video-request.js` 直接拼接 prompt 发送 H3 |
| AC-2 | 场景参考图、定妆照请求 → 规则文字不含否定句与项目特例 | 已确认 | `render.js` 将 system+user 拼成 body 作为图片 prompt；scene-image 规则含“井式发射”“石丘”特例 |

| AC-4 | 全量测试 → 失败项与基线相同 | 未验收 | 基线 613 项 609/4/0（stage05 角色类型 2 项、镜头表嵌套 1 项、角色性别 1 项） |

## 调用链与证据
- 视频：video 节点 `render` → `videoRequest` 拼接固定说明 + 已审核三段 → `videoPayload` → `/videos/generations`。
- 图片：scene-image / costume-image `renderPrompt` → `body`（system 规则 + user）→ `imageParameters` prompt。
- 文生提示词：storyboard（文本模型）输出三段 → 视频 prompt。
