# 大纲重新生成与修改入口

- 类型：完整流程，面板/HTTP/Service动作参数。
- 目标：已有大纲或未通过原因时提供重新生成与修改两个入口，并实际创建不同动作的新任务。
- 非目标：不改变审核规则、旧任务结论及盒子hash职责；不自动触发模型任务。

## 验收标准与调研
| AC | 输入/状态 → 可观测结果 | 证据 |
|---|---|---|
| AC-1 | 有大纲且审核未通过 → 展示重新生成、按意见修改 | 当前panel只渲染一个run按钮 |
| AC-2 | 重新生成 → 新Task首步generate；修改 → 新Task首步revise并携带当前原因/用户意见 | 当前Service仅按是否存在segments选择动作，需显式regenerate |
| AC-3 | 提交/执行中 → 两按钮禁用；连点合并，失败可按原请求重试 | 沿用local.submitting与稳定ID并区分regenerate动作 |
| AC-4 | 无有效候选但有失败原因 → 可重新生成，修改禁用；无稿时仍只有初次生成 | 不伪造可修改内容 |
