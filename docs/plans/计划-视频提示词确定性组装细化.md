# 视频提示词确定性组装细化方案

范围：细化主计划阶段2；仅出方案，不实施。每秒分镜仍一次请求返回整集。当前代码仍由 TextStoryboardModel 生成整段正文，本方案尚未落地。

## 1. 唯一内容来源

每秒分镜生成后保存可审核的结构化正文，界面文本由同一结构渲染，不维护两份可独立编辑的数据。镜头表决定ID、目标时长、上游事件；每秒分镜决定动作、机位、空间、声音和段末状态；素材快照决定图片；项目配置决定语言、画幅等。下游编排不补写剧情。来源冲突回到对应上游解决，不静默择一。

最低内容结构：shotId、beats、dialogues、ambientSounds、music。每个beat含稳定id、durationMs、action、camera、space、soundEventIds、endState。实体通过角色/场景/道具ID引用；正文需要插入实体名称处使用文本片段与entityId片段，避免全篇姓名替换破坏台词。对白独立记录id、speakerId、原文、语言、时间区间、画内/画外及已给表演状态。明确未知与无，不凭空补满字段。持续声明确起止范围，不因只出现一次就推断全镜持续。

模型选择节拍长度，程序用整数毫秒累加时间；总和不符退回修订，不自动拉伸。beat表示内容节拍，不等于剪辑镜头；camera.transition明确连续、切镜或上游指定转场。程序只在明确剪辑点增加[Shot N]。

## 2. 字段映射

| 输出 | 来源 | 程序规则 | 禁止 |
|---|---|---|---|
| subject_definitions | 实际实体ID、素材映射 | 稳定分配Subject；按冻结快照分配Picture；一主体可多图，一图多主体须明确关联 | 每张图机械生成一个人物；让模型猜图片中的身份 |
| summary | 已批准的本镜核心事件和起止状态 | 模板组合明确事件；没有独立概要时采用已批准事件短句，不另发创作请求 | 新增心理、悬念、下一镜事件 |
| retention_analysis | 素材用途及已批准状态变化 | 人物保留身份外形，服装/道具按所属实体绑定，场景保留已确定布局，尾帧继承适用末态 | 默认保留参考姿势、背景；凭类型模板覆盖剧情明确变化 |
| detailed_description | 每段动作/机位/空间/同步声音 | 按时间码逐段渲染，实体引用由程序插入；对白只写在对应事件 | 把每个节拍误当切镜；重写已审核动作；插入流程备注 |
| overall_soundscape | 持续环境声、声场及对白事件索引 | 持续声写明确范围，动作同步声留对应段，对白汇总仅指向说话人与时间 | 再输出完整对白；把无声视觉现象猜成声音 |
| non_diegetic_music | 已批准配乐设置 | 有明确音乐则按范围渲染；明确无配乐或未要求则N/A | 自动添加紧张配乐；把人物演奏误作后期配乐 |

固定栏目即使无内容也用约定无内容标记，不让模型为填非空正文臆造事件。模板是否符合当前网关模型实际输入规范，在实施时对照仓库原始接口文档与真实已通过请求验证，不仅以现有正则为依据。

## 3. 素材绑定

冻结一次引用清单：assetId、文件版本/内容摘要、purpose、entityIds、pictureIndex。主体表与素材表独立；道具可以属于人物但保留自己的实体身份。场景与尾帧不能被当作发声人物。人物图缺失不删除该人物，明确以文字描述；需要参考图的流程按既有门禁处理。

尾帧只有连续性用途：明确sourceShotId、sourceVideoFile及适用状态；跨场景不继承旧背景和机位，同场连续则核对位置/持物等。多人同图须有已确认区域或外观区分，没有信息则报映射不明确，不能猜。

提交时按同一快照顺序读取图片，转换Base64并写reference_images。预览显示Picture编号、用途、所属实体及缩略图，实际请求日志只保存图片类型/字节数/摘要。替换素材或重新生成前镜视频后，相关提示词失效，不重新排序后沿用旧prompt。

## 4. 追溯与审核

渲染时保留sourceMap：输出字段/段落到shotId、beatId、dialogueId、assetId和内容版本。sourceMap放内部记录，不发送给视频接口。

程序自审验证：全量覆盖、时间总和、实体存在、Subject定义与实际引用、Picture映射、对白事件恰好渲染一次、所有必要动作及声音块有对应输出、版本一致。对白按事件ID去重，剧情有意重复同一句仍保留多个不同事件。覆盖检查证明没漏块，不能证明语义和画面物理关系正确。

每秒分镜模型审核负责剧情、空间、朝向、道具和声音可行性。纯程序渲染默认只执行程序审核；如果保留模型补充内容，则对新增部分及关联上下文做语义审核。首次上线用已知样本人工/模型对照原文与成稿，证实模板没有遗漏或失真；不能因无额外模型调用就宣称语义必然正确。

缺必需内容：回到对应分镜修订。引用/模板错误：修程序。上游矛盾：定位原字段，不在渲染时修剧情。沿用最多一次自动内容修订，修改镜头末态需重审受影响邻镜。原内容和失败稿分别保存，不伪装通过。

## 5. 实施文件与验收

- shared/seconds-content.js：内容契约、时间计算、引用完整性；shared/drama-model.js及所有编辑/读取路径同步。
- server/prompts/video-prompt-renderer.js：固定字段渲染与sourceMap。
- server/generate/shot-text.js、models/text-storyboard-model.js：删除被替代的整段转写请求；保留确有必要的语义步骤，更新步骤计划及提示词预览。
- shared/reference-images.js、server/flow/operations/films.js、server/data/pictures.js：同一快照绑定和提交校验。
- generate/film.js：从字符串猜测升级为结构与引用表验证；网关边界仍验证实际最终请求，不以“由程序生成”跳过检查。
- skill和文档：分开创作规则、程序协议、语义审核范围；不让模型重复承担程序格式工作。
- 新结构上线提供备份后离线迁移；无法可靠解析的旧文保留备份并标待重新生成，不运行时兼容、不删除用户数据。

验收样本：两镜漏镜、未定义Subject、尾帧误作主体、同人多图/多人同图、道具图、无图、重复台词事件、跨段对白、画外音、切镜与连续运镜、环境声延续、无配乐、素材替换。

衡量：已知结构失败样本全部通过正确组装或明确阻止发布；原文内容块与输出映射齐全、台词原文无改动；语义错误仍能检出。记录初次审核通过率、最终通过率、人工发现漏项、请求数/token/耗时，不以通过率单独衡量质量。

验证状态：仅文档方案，未修改业务代码，未请求生成模型，未测试或重启服务。
