# 节点按钮收口

- 类型：小改动上的界面规则调整，涉及面板多处按钮，按完整流程记录
- 目标：尾帧改为视频内的步骤；程序节点只留生成和任务历史；两个组使用同一套按钮，取消停掉组内全部未结束任务。
- 非目标：不把尾帧恢复成独立任务；不改成片、定妆照的生成流程；不改任务历史页。

## 验收标准与调研结论
| AC | 输入/状态 → 可观测结果 | 已确认/未确认/未验收 | 依据或缺口 |
|---|---|---|---|
| AC-1 | 镜头详情里的尾帧不是公共节点栏。失败时出现「重新提取」和失败说明；其他状态没有这颗按钮 | 已验收 | 尾帧步骤没有 `.node-ui`。失败时按钮是重新提取，并提交已有视频的人工保存 |
| AC-2 | 合片、首尾帧、多模态只有对应生成按钮和任务历史，没有意见框，也没有人工编辑、人工放行、按意见修改、取消 | 已验收 | 首尾帧按钮是执行编排、任务历史；合片是生成合片、任务历史。两处都没有意见框 |
| AC-3 | 其余节点和两个组都有任务历史 | 已验收 | 节点公共按钮仍含任务历史；两组按钮也含任务历史 |
| AC-4 | 生成定妆照和逐镜头成片都是「一键生成 / 重新生成」「继续」「任务历史」「取消」。取消会逐个取消该组排队或生成中的任务 | 已验收 | 成片组取消一次发出组内运行中和排队中两个取消命令 |

## 改动
1. `meiji/client/project-ui.js` — 尾帧改成步骤；两组按钮收成同一套。失败尾帧的「重新提取」对已有视频做一次人工保存，从而重跑截帧，不重新向模型要视频。
2. `meiji/client/task-panel.js` — 合片、首尾帧、多模态只保留主按钮和任务历史，不画意见框。
3. `meiji/client/panel-styles.css` — 尾帧步骤样式。
4. `meiji/dev_docs/制作工作流.md` — 对齐按钮。
5. 相关面板测试改为新文案和新结构。
