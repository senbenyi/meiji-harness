# skill 页面布局

类型：UI 优化。调研：docs/research/调研-skill页面布局.md。
待用户决定：无。

1. client/node-skill.js：标题区展示项目/剧集/节点；基础规则按小节直接显示，协议分开展示；补充列表、编辑器、提示词预览独立分区，增加加载/空状态/错误重试和保存状态。删除无关条目不丢正在编辑的草稿。
2. client/skill-detail.js：基础字段全部直接显示，取消隐藏字段的页签；固定约束、基础、已有项目补充、指导及预览按职责分区，保留现有权限及功能。
3. styles.css：统一页面标题、导航、分区与操作行，基础正文不用内部限高滚动，窄面板不溢出。
4. .agents/meiji-dev.md：写入基础默认展开、范围清晰、补充与预览分区要求。
5. 只运行相关 skill/UI 测试，真实页面核对；修改后检查差异，集中更新图谱。

验收：基础不用点击展开即可阅读全部规则；作用范围明确；CRUD/失败保留/重试/完整提示词预览正常。
验证结果：相关测试两批 55/55、42/42 通过，无失败或取消；30 组提示词前后完全一致。浏览器隔离预览确认默认展示与分区，Harness 实际节点页验收仍待完成。

追加范围：constraints 不设分类子目录。阶段文件命名为 `<功能>-<字段>.md`，指导文件为 `guidance-<类型>-<字段或阶段>.md`，共享正文保留功能名，人物/场景图为 `generate-character-image.md` / `generate-scene-image.md`；元数据为 `<技能ID>.skill.json`。同步加载器、测试、引用与目录规范，迁移前后对照提示词确认正文和请求不变。

确认后的清理方案：一个功能只维护一份基础生产规则，生成与审核共用，修订增加基稿和意见。删除独立 common/review/revise/shared/guidance 正文与注册文件；有价值的领域规则并入对应功能基础正文，身份、审核协议、修订边界、语言与输出协议交给代码。大纲、人物提取、场景提取分别一份正文。约束只读，旧覆盖不再改变基础规则，运行数据不删除。后续每个 AI 步骤由独立 Model 提供生成/审核/修订编排方法。

编排落地：将仍在接口函数中编排的镜头表、单镜修订、整集/单镜每秒指令、文本分镜、图片提示词改写迁入各自 Model，接口只赋值并调用生成/审核/修订方法；不改变任务次数与数据保存流程。图片和视频接口按其现有能力迁入对应 Model，不新增外部审核调用。

最终验证：单一基础规则与 Model 改造后相关测试 86/86 通过；随后 Model 赋值专项及关联测试 23/23 通过，无失败或取消。未执行全套测试。30 组提示词差集及逐句删除理由见 docs/implement/提示词差集-skill页面与基础规则.md。Harness 重启并响应鉴权入口；浏览器隔离预览已核对基础直接展示，真实 Harness 节点页端到端验收受当前 Chrome 页面请求停滞影响，未宣称完成。

收尾：Harness 已重启；GitNexus 索引更新成功。真实节点页的浏览器端到端验收仍待恢复页面响应后完成，其余代码、相关测试和文档工作已完成。
