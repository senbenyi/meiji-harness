# 剧本素材导入与摘要提取

- 类型：新功能，完整流程。
- 目标：素材库支持文本剧本；创建项目可导入或选择剧本，自动提取最多 500 字的项目摘要；剧集摘要按剧本进度和时长提取，无剧本时按项目摘要生成。
- 非目标：不改变剧情、图片、镜头或视频流程，不新增剧集摘要字数限制，不改动现有用户数据。

## 验收标准与调研

| AC | 输入/状态 → 结果 | 调研依据 |
|---|---|---|
| AC-1 | 素材库导入 TXT/TEXT → 独立剧本素材，可预览、下载、重复使用 | asset-library-store、asset-library-view；原来仅支持媒体和指导提示词 |
| AC-2 | 空文件、非法编码、二进制、格式不符或超限 → 拒绝且不留下半成品 | 沿用 UTF-8、暂存和原子发布；剧本最多 1 MB、200000 字符 |
| AC-3 | 创建页选择已有剧本或导入文件 → 保存完整正文与来源，自动启动项目摘要任务 | 项目已有 script 字段，创建页仅接收手填 summary |
| AC-4 | 项目摘要任务 → JSON summary，非空且最多 500 个非空白 Unicode 字符；生成、自审、修订各有编排 | 新增 ProjectSummaryModel、task 与基础/审核 skill，复用文本队列和历史 |
| AC-5 | 提取失败 → 剧本和项目保留，可看任务、提示词与失败原因，重新提取；创建弹窗不会因长请求一直遮挡 | 创建后立即进入项目，后台任务由 manager.start 发起 |
| AC-6 | 有剧本生成/修订/审核剧集摘要 → 剧本是剧情来源，前集定位已演进度，按本集时长选连续事件；不提前后集、不重演 | EpisodeSummaryModel 和对应 skill 目前将项目摘要与剧本并列 |
| AC-7 | 无剧本 → 根据项目摘要和前后集生成；既有人工创建、草稿、自审与修订保持有效 | 复用现有 summary 操作，不变更返回字段及用户指定时长 |
| AC-8 | 自动提取拥有独立任务、完整请求与输出快照；页面有历史、skill 及重试入口 | 沿用三层模型，项目级摘要与剧集摘要使用不同 target |

调研与实施均已完成；验收结果如下，详细证据见对应实施记录。

## 调用链与改动

1. `asset-library-store.js`、`asset-library-view.js`、上传接口：新增 scripts 分类，保存原文件，列表仅返回元数据，按需读取正文。→ AC-1、2
2. `project-session-view.js` 创建弹窗：本地导入与已有剧本选择；选择后无需手填摘要，清除选择恢复手填。`operation-project-create.js` 按素材 ID读取和冻结剧本正文。→ AC-3
3. 创建项目完成并绑定工作区后，HTTP 与会话入口启动同一个 project-summary 操作。`task-project-summary.js` 经文本队列、自审与至多两轮修订写项目摘要；生成失败不删除已创建项目。→ AC-4、5、8
4. 新 Model、interface、task/review skill 和输出协议，统一 system 规则、user 任务/参数/剧本，严格检查 500 字；项目级快照 target 为 project-summary。→ AC-4、8
5. `EpisodeSummaryModel` 的任务和资料用途按有无剧本分支；生成、自审、人工修改与自动修订使用同一来源规则。→ AC-6、7
6. 项目概要展示提取状态、历史、skill 与重新提取；更新开发指引和实施记录。→ AC-5、8
7. `task-interrupt.js` 同时处理项目摘要节点，服务重启取消遗留占用，保留剧本和已保存的摘要，允许重新提取。补任务取消与重启测试。→ AC-5
