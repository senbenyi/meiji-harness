# 操作与任务文件拆分（补充方案）

- 类型：重构（完整流程：涉及目录结构、任务记录结构、任务状态、前端任务视图，远超 3 个文件）
- 目标：在 `server/flow/operations/` 中，每个生成任务、每个小任务、每个操作各是一个独立文件；小任务有独立任务记录与状态；取消是操作按钮，调用取消接口，不作为任务。
- 非目标：不改提示词 Model、skill、网关、内容节点（summary/outline/…）的数据结构与审核规则；不改 text/image/video 限流策略。

## 1. 现状（调研结论）

| 概念 | 现在的实现 | 依据 |
|---|---|---|
| 操作 | `operation-registry.js` 的 `definitions` 共 52 个 action，按钮与会话工具共用 | operation-registry.js |
| 任务 | 一次 action 执行 = 一条任务记录 `history/tasks/<id>.json`，状态由步骤推导 | task-manager.js、task-execution.js、shared/task-steps.js |
| 小任务 | **不存在**。剧情 `outline` 把大纲、角色、场景、道具作为同一任务里的 16 个步骤；每秒指令 `seconds` 把各镜作为同一任务的步骤；成片 `produce`/`produce-all` 把分镜与视频作为同一任务的步骤 | operation-registry.js plan |
| 实现文件 | 按领域混放：project / story-text / shot / image / video 五个 `*-operations.js`（共 1600+ 行），每个文件里既有生成任务又有人工操作 | flow/operations/ |
| 取消 | 已经不是任务：`POST /tasks` → `tasks.cancel(id)` → AbortController；但按钮只能取消整条任务 | panel-routes.js:268、task-manager.js cancel |

## 2. 目标结构

```
server/flow/operations/
  registry.js                 汇总下面所有文件的定义（替代 operation-registry.js 的 definitions 大表）
  run-operation.js            执行上下文、分派、释放（保留）
  tasks/                      生成任务：经任务管理器排队，写任务记录
    episode-summary.js        1 剧集摘要
    episode-story.js          2 剧集剧情（父任务，只编排小任务）
      story-outline.js          小任务：大纲
      story-characters.js       小任务：角色文字资料
      story-scenes.js           小任务：场景文字资料
      story-props.js            小任务：道具文字资料
    character-image.js        3 角色图
    scene-image.js            4 场景图
    prop-image.js             5 道具图
    shot-table.js             6 镜头表
    seconds.js                7 每秒指令（父任务）
      shot-seconds.js           小任务：单镜每秒指令（按镜头表数量生成 N 个）
    film.js                   8 成片（父任务）
      film-storyboard.js        小任务：分镜文本提示词
      film-video.js             小任务：生成视频（提交、生成、尾帧）
  actions/                    操作：人工或即时动作，不排队、不建父子任务
    project/   create、open、overview、project-delete、library-import
    episode/   episode-add、episode-edit、episode-delete、source
    story/     outline-text、character-text、scene-text、prop-delete
    image/     import-image、part-import、part-text、set-reference、clear-reference、use-asset、clear-image、confirm-image、discard-image
    shot/      shot-assets、storyboard-text
    review-override.js
    task-cancel.js            取消：调用 tasks.cancel，不写任务记录
```

每个任务/小任务文件导出同一形状：`{ action, label, scope, queue, agent, plan(project, op), run(context) }`；父任务额外导出 `children(project, op)` 返回小任务列表。共享的生成函数（generateStoryPackage、generateShots、submitAssetImage 等）移到各自任务文件或 `tasks/shared/`，不再按领域堆在一个文件里。

## 3. 小任务的记录与状态

- 小任务是独立任务记录：`history/tasks/<childId>.json`，新增 `parentId`；父任务记录新增 `children: [childId…]`，自身不再有生成步骤。
- 小任务状态仍由自己的步骤经 `deriveTaskStatus` 推导（generate → review → revise → re_review 等不变）。
- 父任务状态由小任务状态推导（新增 `deriveParentStatus`）：有执行中 → running；全部排队 → queued；有取消 → cancelled；有失败 → failed；有审核未通过 → review_failed；全部完成 → completed。
- 当前任务页与历史按父任务分组，展开显示每个小任务及其状态；每个小任务行有自己的停止按钮。
- 内容节点状态（未生成/生成中/未通过/已通过）与任务状态继续分开记录，不受本次改动影响。

## 4. 取消

- 取消是 `actions/task-cancel.js` 操作：校验归属后调用 `tasks.cancel(taskId)`，不建任务记录、不进队列。
- 取消父任务或任一小任务 = 取消该父任务下所有未结束小任务；小任务失败同样停止其余小任务。
- 已提交到网关的视频无法远端取消，沿用现有「远端可能仍在运行」的记录方式。

## 7. 用户决定（2026-10-03）

1. 道具文字资料作为剧集剧情的第 4 个小任务：`story-props.js`。剧情 = 大纲、角色、场景、道具四个小任务。
2. 任一小任务失败或被停止，同一父任务下其余未结束的小任务全部停止（取消）。
3. 合成（assemble）归为操作：`actions/shot/assemble.js`（不建父子任务）。铅笔分镜图（pencil）功能取消，在阶段 2 删除其操作、前端入口与测试。
