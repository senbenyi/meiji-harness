## 目标流程

大纲 → 镜头表 → 每秒指令与参与角色清单 → 汇总本集角色并匹配项目库 → 补齐角色外貌/声音资料并审核 → 仅为实际出镜且缺图的角色准备图片 → 分镜程序绑定视觉身份及发声身份 → 格式与绑定校验 → 提交视频 → 尾帧衔接。

每个阶段只承担自己的内容：

| 阶段 | 产物与职责 | 下游使用方式 |
|---|---|---|
| 镜头表 | 分段叙事、人物自然称谓、原台词与必要画内/画外说明 | 每秒指令设计时间与画面 |
| 每秒指令 | beats、dialogues、ambient、music 与 participants | 时间线和参与清单均作为下游事实 |
| 人物资料 | 身体身份、外貌、voiceDescription、库关联 | 给出稳定视觉与声音设定 |
| 图片准备 | 只覆盖 visible 身体的缺失外观图 | 固定 Picture 清单 |
| 分镜编排 | 先使用参与清单，再引入角色，最后编排完整时间线和声音 | 唯一最终视频提示词 |

## 数据约定

### 1. 每秒指令只列参与者，不提前生成人物资料

```json
{
  "participants": [
    {"name": "餐馆老板", "presence": "visible"},
    {"name": "电话中的顾客", "presence": "voice"}
  ]
}
```

- 同一人物在本镜只列一次；有任何可见身体时用 visible，全镜只发声用 voice。
- 画内说话人必须列为 visible；画外/内心声可能来自本镜可见人物，不能仅凭 delivery=off/inner 推定 voice。
- 仅被提及的人物与独立旁白 NARRATOR 不加入角色清单；独立旁白继续使用独立发声身份。
- 生成完成后 AI 从最终分镜提取清单；生成、审核和修订均检查它与动作及发声事件一致。
- 程序校验结构、重复和对白身份；语义审核检查漏人物、误列人物与出镜范围。程序不能从简单姓名匹配证明语义正确。

### 2. 人物增加独立声音字段

建议字段名为 `voiceDescription`，界面显示“声音特征”，保存为一段自然语言，避免强制所有角色填同样的标签或长列表。

示例：“成年男声，中低音，音色略沙哑，普通话带轻微北方口音，吐字清楚，平时语速适中。”

- 描述音色、音高、口音、吐字、惯常语速等稳定特征；不混入当句情绪、临时音量或嘴部动作。
- 已有库设定优先复用；剧本明确设定用于核对冲突。缺失时 AI 可提出与人物相容的声音设定，写入资料后持续复用，不在每镜重新随机设计。
- 与 appearance、look 分开；不加入人物生图提示词。
- 旧记录允许空值。新角色资料生成需包含该字段；静默角色可以明确写“本集无发声，声音特征未设定”，不能强迫增加对白。
- 穿越或变身等特殊情况不得自动按意识或身体推断声线变化，服从已明确的声音设定。

### 3. 仅声音角色也需要声音身份

建议人物资料准备同时覆盖 visible 与 voice；保存本集角色的参与类型，复用每秒清单的 visible/voice 语义。角色跨镜有出镜时，本集按 visible 准备外貌；全程仅声音时，只要求身份与声音资料。

仅声音资料不强制 look/服装/体型等视觉字段，不生成图片，不列入缺图门禁，不建立视觉 Subject。资料展示与编辑应允许这种角色，避免为通过现有卡片校验补造外貌。

1. `shared/run-planner.js`、`server/flow/runs/run-service.js` 及实际图片准备入口：visible 才要求外貌图片，voice 只准备身份和声音；失败或取消阻止依赖它的分镜/视频 → AC-5/10。

4. 正常对白、角色画外声、内心声复用同一角色声音特征；内心声和画外声不要求对口型。NARRATOR 保持独立 → AC-6/7。
5. 全程仍由程序编排，预览与提交复用入口；保持现有三字段/六字段输出形式 → AC-10。

### 阶段 4：补齐失效规则、审核与兼容

1. `shared/pipeline-cascade.js`、`server/flow/steps/shared/film-freshness.js`、视频提交检查：声音变化使依赖的分镜过期；不因声音修改重生图或改写每秒指令 → AC-8。
2. 将角色声音资料版本/有效内容纳入编排依赖检查，避免只比较图片快照 → AC-8。
3. 旧卡无 voiceDescription、旧指令无 participants 可继续使用；显式重新生成时补齐新结构 → AC-9。
4. 审核只检查有依据的参与范围、身份、声线及转换错误，不借机重新设计已通过动作、机位或台词 → AC-10。
