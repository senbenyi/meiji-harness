# 场景补全与文字资料贯通

- 类型：完整流程，提示词、上下文、场景显式修订及依赖投影调整。
- 目标：原文不完整时合理补全可拍场景，既有角色/场景文字资料持续用于镜头和提示词；图片同时核对原始来源。
- 非目标：把完整角色档案抄入剧情、改项目或task/step/group固定JSON结构、自动覆盖现有项目规则/资料、调用收费模型批量重做。
- 用户已授权完善前述源头和场景修正流程，并要求改编阶段补全环境；沿用已有原结果修订action。新增的AI接口输入选项属于请求编排，项目模型字段定义不变。

## 调用链与证据
原文→outline.segments→episode-scenes→scene_library→shots→seconds→storyboard→video；角色库独立注入shots/seconds/storyboard，无需把整份档案回填body。
sceneImageContext由createMediaHandler及dependencyMaterial共同读取。characterTextCatalog用于seconds/storyboard；shotCharacterContext用于shots和hash。普通提取复用场景，显式revise才开放维护范围。
GitNexus源码索引当前；MCP不可用，以同版本LocalBackend query/impact取证。sceneImageContext、characterTextCatalog、shotCharacterContext、prepareContent、taskNodeInput均CRITICAL；已核对媒体handler、节点输入、依赖材料及测试直接调用方。规则模块MEDIUM，路由LOW；测试UNKNOWN已源码确认正式入口。

## 改动
1. 公共规则定义场景补全边界，仅outline与episode-scenes引用；outline在既有body落实际动作所需空间，不另建字段。
2. episode-scenes节点增加可选请求参数updateExisting，taskNodeInput仅task.action=revise时为true；模板和输出说明按维护范围一致，prepareContent仅显式revise/manual_edit允许更新已有场景。
3. scene-inputs.js提供原始script与相关plot/story；出图模板明确来源优先级与参考图纠错。结构变化仅为现有context任意对象内的业务输入，不增项目字段。
4. shot-text-inputs.js及node-dependencies.js补齐人物外观投影，最终人物参与子集复用同一目录，保留无图/画外/局部可见规则。
5. 场景、改编、角色文字链回归与业务文档同步。

## 验证
记录相关基线、规则固定文本长度；测试原文/改编输入及hash、普通复用与显式修正、只使变化场景过期、人物三字段贯通及媒体隔离；运行全量测试、差异检查和图谱刷新。实际模型对补全语义的遵循性与图片质量仍需生产验证，不用字符串断言代替。
