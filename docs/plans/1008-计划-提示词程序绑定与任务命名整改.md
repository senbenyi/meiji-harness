# 提示词程序绑定与任务命名整改

- 类型：完整流程整改计划。用户已授权实施。
- 目标：点击生成分镜提示词时，程序直接消费每秒指令的参与人物清单、匹配现有资料和图片、编排并校验；不再触发角色大模型、自审模型或生图。确认参考图真实Base64提交，并统一全项目任务/步骤的业务名称。

## 目标流程与边界

点击“生成/重新编排提示词”：

已通过每秒指令 → 程序读取participants → 匹配本镜现有角色资料及项目库 → 固定角色声音与图片引用清单 → 程序编排最终提示词 → 程序校验 → 保存结果。

1. 只读当前任务镜头的participants，不为了单镜编排提取整集未参与角色，不重新向模型询问人物范围。
2. 匹配顺序建议为：明确已有身份关联 → 本集name/sourceName → 库名称/别名。多个候选时报告歧义；不任意取第一个、不新增同名卡。
3. 可见角色使用既有外貌/图片，声音角色使用既有voiceDescription；声音角色不绑定图片或Subject。已有无图片但有文字外貌的角色沿用文字模式，不自动生图。
4. 清单仅含名称与参与类型，无法凭空补齐外貌/声音。缺资料时列出缺失人物与镜头，提供“编辑/准备角色资料”独立入口；该入口是否调用AI由独立动作决定，不混入生成提示词。
5. 新指令清单缺失时提示补齐上游；旧ID指令可用原有确定性标记兼容，不能借兼容规则自动调用模型。旧自然名称指令无清单的补齐另由用户发起。
6. 检查并清除纯提示词目标的隐式角色/图片展开，包括重试、resume及运行中秒级指令更新后的插入分支。
7. 完整成片仍按其实际授权范围安排媒体步骤；角色资料准备应作为独立明确动作/前置，不再用“读取清单”名义自动重新生成角色。手动“生成人物资料/人物图片”的功能保留。

## 整改阶段

### 阶段一：拆开程序读取角色与AI生成人物资料

- `shared/run-planner.js:planRun`：单独识别纯提示词目标；移除角色生成、自审和生图依赖 → AC-1/2。
- `server/flow/runs/run-service.js:checkStep`：使用同一业务边界，纯提示词运行时不得重新插入这些步骤 → AC-1/8。
- 新增/复用shared角色解析辅助：直接消费participants并匹配本集/库资料，返回确定的角色/声音/图片绑定及具体错误；不调用网关、不重新生成资料 → AC-2/3。
- `step-generate-storyboard.js`及`video-prompt-renderer.js`：按解析→编排→校验顺序执行。步骤/内部动作真实记录“匹配参与角色”“编排分镜提示词”“校验分镜提示词” → AC-1/5。
- 单镜缺资料不改写其他镜头；重复编排不能清空人物图片或重新生成角色 → AC-3/8。

验证：通过真实Run与请求计数器覆盖单镜、整集、重新生成、缺角色、缺图、歧义、声音角色、旧数据、运行时插入；所有纯提示词场景文本/图片/视频网关调用数为0，缺资料明确暂停。

### 阶段二：验证Base64实际提交与展示语义

- 沿用当前正确的转换入口，不把Base64提前混入角色卡或最终提示词正文。
- 贯通测试`submitVideo→submitFilm→submitGatewayVideo`，在fetch替身处断言真实body.reference_images；校验内容解码与原文件字节一致，以及角色图/尾帧和Picture编号顺序。
- 覆盖PNG/JPEG/WebP、素材库图/旧剧集图/尾帧、缺文件/读取失败、9张上限、体积超限与非法路径；失败时不得提交视频。
- 预览/历史明确标识“参考素材清单（本地读取来源）”与“实际提交：Base64 data URL”。HTTP记录仍使用现有Base64脱敏方式，可显示MIME、字节数、Picture序号和传输类型，不将完整Base64当普通提示词展示。
- “查看提示词”仅展示真正记录的模型输入；程序编排提供“查看编排结果/角色与素材绑定”，避免让人误解发生了大模型调用。实际有HTTP请求才提供HTTP入口。

验证：网关payload自动化；用户截图任务的实际HTTP记录如能定位则补证据，否则标明未取得，不声称已实测该次请求 → AC-4/5。

### 阶段三：统一全项目任务及步骤命名

集中维护共享命名规则，由目标产物、操作模式、范围、步骤/内部动作共同决定。面板列表、任务详情、进度、预览确认、步骤详情、会话job/goal使用同一规则，不用多个局部映射互相覆盖。

| 大纲及人物资料 | 第1集 · 生成剧情大纲；第1集 · 生成人物资料 |
| 场景资料 | 第1集 · 生成场景资料 |

| 纯分镜提示词 | 第1集 · 编排S03分镜提示词；第1集 · 重新编排全部分镜提示词 |

- 覆盖generate/regenerate/modify/review、scope.only、parts、tracks/itemIds/library、跨阶段from/to及项目级/集级。
- `expand`根据真实展开目标显示“安排角色图片步骤/安排镜头制作步骤”等；`image`显示“生成人物/场景/道具图片 · 对象”；`storyboard`显示“编排分镜提示词 · S03”。
- 审核、自审、复审仅用于真实审核操作；程序格式检查叫“校验”，程序绑定角色不能叫“生成角色”。
- 下载图片并转Base64、保存图片、提交视频、获取视频、提取尾帧、等待确认、人工编辑/放行等内部动作同样有明确中文名称。
- 旧历史通过kind/target/input推导展示名称，不修改其ID、执行状态或原始请求记录；未知类型主标题给出可理解的“未识别步骤”，原始标识只留详情诊断。
- 调整`shared/run-view.js:runGoalLabel`、`client/run-labels.js`、`run-detail/run-progress/run-preview`与Harness任务观察入口；实施时先盘点所有kind/action枚举，避免只修截图3项。

验证：枚举驱动的语义命名用例、按钮→goal→预览→执行→历史一致性、旧Run展示、会话job/goal名称；不以大量快照替代语义断言 → AC-6/7/8。
