# 任务步骤重构

- 类型：重构
- 目标：以「操作 → 任务 → 步骤 → 内容节点」为唯一执行模型，任务状态只从步骤推导；增加人工忽略自审；面板提供「当前任务」与「任务历史」两个页面；统一文件命名。
- 调研：`docs/research/调研-任务步骤重构.md`（设计、证据与已定决策）

## 待用户决定
- 无（阶段 1–7 已按用户要求实施）。
- 人工关卡放行位置（仅在实现人工关卡时需要，本计划不实现）。

## 约束
- 各阶段独立提交，顺序执行；每阶段 `npm test` 全部通过（同时核对失败与取消计数）、ESLint 无未定义标识符、架构测试通过。
- 除「人工忽略」为新增行为外，用户可见行为不变。
- 不实现整集一键、人工关卡、图片自动确认，只预留结构（见调研第 9 节）。

## 改动

### 阶段 1：命名调整
1. 按调研第 11 节「阶段 1」各行重命名文件，并改写全部相关 import → AC-1
2. `shared/project-rules.js`（原 `gates.js`）— 删除对门禁函数的转出；引用门禁函数的模块改为从 `shared/gates.js`（原 `flow-rules.js`）导入 → AC-1
3. `tests/architecture.test.js` — 分层前缀随改名调整 → AC-1
4. `.agents/architecture.md`、`.agents/development.md`、`meiji/README.md`、`meiji/docs/*.md` — 更新文件名 → AC-1

验证：`npm test`；ESLint；`grep` 旧文件名在源码与现行文档中无残留（历史实施记录除外）→ AC-1

### 阶段 2：步骤模型与状态推导
1. `server/data/task-records.js` → `task-store.js`：任务文件 `nodes` 改为 `steps`，步骤字段与状态按调研第 3 节；新增 `deriveTaskStatus(steps)` → AC-2
2. `server/flow/tasks.js`、`task-store.js` — 删除 E1、E2 中对任务状态的直接赋值，统一调用推导函数 → AC-2
3. `scripts/migrate-task-steps.js` — 历史任务文件迁移（`nodes`→`steps`、`succeeded`→`completed`、`interrupted`→`cancelled`），先备份；`configure-harness.sh` 启动前执行 → AC-2
4. `client/execution-history.js` — 改读 `steps` → AC-2
5. 所有操作都写任务记录（删除 `tracked` 白名单）；任务开始时写入完整步骤计划；步骤状态变化通过 `notifyProject` 推送 → AC-2、AC-6

验证：推导函数覆盖调研第 4 节每一行；迁移脚本对真实任务记录副本读回一致 → AC-2

### 阶段 3：执行器与文本步骤
1. `server/flow/tasks/runner.js`（原 `tasks.js`）、`queue.js`、`restart.js`（原 `interrupt.js`）— 执行器按步骤清单顺序执行，只通过开始/结束步骤接口改状态 → AC-3
2. `server/generate/text-steps.js`（原 `text-workflow.js`）— 删除 `runTextWorkflow`，提供 `textSteps(...)` 与单步执行 → AC-3
3. `shot-text.js`（5 处）、`story.js`（3 处）、`operations/images.js`（1 处）— 改为声明 `textSteps` → AC-3
4. `server/data/review-checks.js`、`operations/finish.js`、`operations/execute.js` — 删除 `textDraftSaved`、`deferCheckFailure`、`textNodeSaving`、`reviewHistory` 标志，改为从步骤推导；`checkContext` 移出为 `server/data/operation-context.js`（实施时由 flow 改到 data 层，避免 data/generate 反向依赖 flow）→ AC-3

验证：`api-failure-state`、`reviewed-generation`、`review-checks`、`all-seconds`、`prompt-nodes` 全部通过；每处文本生成的请求次数与顺序不变 → AC-3

### 阶段 4：操作定义与组合
1. `operations/registry.js` — 每个操作补全 `scope`、`queue`、`plan`、`agent` → AC-4
2. `operations/films.js` — `shotSteps(track)`；单镜成片与一键成片复用；一键成片跳过已通过镜头、失败即停 → AC-4
3. `server/workers/shot-film-worker.js` — 删除；`produce`、`produce-all` 改为 `operations/films.js` 中由 `shotSteps` 驱动的处理函数，子操作复用同一任务 → AC-4
4. 分阶段展开的结构（`task-store.js` 的 `expandStage`：`stage` 占位 → 前序通过后展开），供将来整集一键使用；本阶段不新增整集一键操作 → AC-4
5. 会话工具按操作定义的 `agent` 字段拒绝人工专属操作 → AC-4

验证：一键成片的提交顺序、尾帧衔接、跳过与失败停止与现有测试一致 → AC-4

### 阶段 5：人工忽略自审
1. 新增操作 `review-override`（`agent: false`）：一个 `override` 步骤，节点 `check` 记录 `override` 与原 AI 理由，状态为通过 → AC-5
2. 格式错误不可忽略；与 `check.revision` 绑定，内容变化后失效 → AC-5
3. 门禁把人工放行视为通过 → AC-5

验证：放行后下游可生成；agent 调用被拒；内容重新生成或编辑后放行失效 → AC-5

### 阶段 6：面板
1. `client/task-steps.js` — 新增步骤清单组件：按 `target` 分组，显示状态、审核结论与理由、错误、执行者、起止时间；当前步骤高亮并显示已用时间、尝试次数、远端任务编号 → AC-6
2. `client/current-task.js` — 新增「当前任务」页：本集进行中与排队中的任务、排队位置、停止按钮；收到 `/events` 推送即刷新 → AC-6
3. `server/http/routes.js` — 新增 `GET /plugins/meiji/tasks/current`；`/history` 返回 `steps` → AC-6
4. `client/execution-history.js` — 改用步骤清单组件 → AC-6
5. 状态栏增加「查看当前任务」入口 → AC-6
6. 审核未通过的节点显示「忽略并通过」按钮；已放行的节点显示「人工放行」及原 AI 理由 → AC-6

验证：UI 测试（jsdom）覆盖分组、当前步骤高亮、推送刷新；Harness 中人工验收 → AC-6

### 阶段 7：文档
