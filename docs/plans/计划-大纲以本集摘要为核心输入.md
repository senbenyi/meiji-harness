# 计划：大纲以本集摘要为核心输入

## 背景
剧情大纲提示词把整部项目的「项目摘要」放在【上下文：项目背景】，与本集摘要并列；重新生成（regenerate）时更是不给本集摘要，只用项目摘要与剧本展开。结果是大纲的核心依据变成项目摘要，并与本集摘要冲突。

## 决定（用户确认）
大纲的目标任务是依据本集摘要生成剧情；前后集与项目摘要只作参考和衔接。

## 改动（server/prompts/models/story-model.js 大纲 facts / task）
1. 【核心输入：本集摘要】首次生成、重新生成、修改都提供，排在参数之后第一位。
2. 项目摘要、剧本改为【参考：项目背景】【参考：剧本资料】，说明只用于理解人物、世界与风格，本集事件以本集摘要为准。
3. 前集改为【衔接：前集结尾】（开场承接已发生事实），后集改为【衔接：后集摘要】（结尾能接上后集开头，不提前演出）。
4. 任务说明：首次生成「依据本集摘要生成本集剧情大纲」；重新生成「依据本集摘要重新生成，不参考旧大纲与历史意见」。
5. 审核 skill 的审核依据同步写明以本集摘要为核心。

## 验证
全量测试失败集与基线一致；场景快照中 outline 三种模式都含【核心输入：本集摘要】。
