# 镜头时长超限自动修订

- 类型：关键任务流程 Bug 修复
- 目标：生成镜头表违反单镜 15 秒上限时，在原任务内把校验错误和原始镜头表交给模型定向修订，再进入原审核步骤。
- 非目标：不自动修复其他结构错误，不更改审核规则、镜头总时长/小段预算契约或重试为新任务的行为。

## 验收标准与调研结论
| AC | 输入/状态 → 可观测结果 | 已确认/未确认/未验收 | 依据或缺口 |
|---|---|---|---|
| AC-1 | `shots` 模型输出结构合法、但至少一镜 >15 秒 → 当前生成步骤保存原始结果并标记校验失败；同一任务自动追加修订/审核步骤 | 已确认规格 | 当前提示模板有 15 秒约束，但没有可恢复校验路径 |
| AC-2 | 修订输入 → 收到超限错误及上次生成的镜头表；修订后所有镜头 ≤15 秒且通过原有小段总时长/全集时长校验 → 原任务完成并保存结果 | 已确认规格 | 现有 `shots-regenerate.yaml` 接受 `修改意见`，当前没有把无效草稿作为修订资料传入 |
| AC-3 | 两轮定向修订后仍超限 → 任务以原校验错误失败，审核后序步骤作废 | 已确认规格 | `step.round` 上限为 2；文本任务最多两轮修订 |
| AC-4 | 非时长校验错误或模型/网络错误 → 保持现有失败行为；审核语义流程不变 | 已确认规格 | 定向恢复仅针对镜头表时长上限错误 |

## 调用链与证据
面板/会话提交 `shots` → `TaskService.#run` 执行 `generate` → `createTextHandler` 调模型、校验响应结构、调用 `prepareContent` → `commitContent` 探测提交 → `assertOutput` / `validateProject` 在镜头时长超过 15 秒时抛错 → `TaskService` 将生成步骤和任务直接标记失败，自审步骤作废。新路径在文本处理器识别这一种校验错误并返回原始响应；任务循环记录失败生成步骤，跳过原待审步骤，追加 `revise`/`review`，修订提示带错误与无效镜头草稿。

数据库已确认两次失败任务的生成提示都含“每镜不超过15秒”和“每镜时长为1至15秒”，失败原因为“镜头.时长秒：最多 15 秒”。这是模型输出违反提示后的校验结果，不是提示模板漏写。

占位符报错的直接机制也已定位：`loadTemplate` 每次请求都从磁盘读取 YAML，而 `promptValues` 随服务进程加载。只改 YAML 后，运行中的进程可以读到新占位符，却仍用旧版值构建器；`renderTemplate` 在用户点击/任务执行时才报“缺少占位符”。正确做法是 YAML 字段与资料构建器成组修改、由真实资料路径覆盖测试，并按 `.agents/meiji-dev.md` 重启已链接当前仓库的 Harness。用把结构化草稿塞进“修改意见”来绕过字段缺失不是最终设计。

GitNexus 预编辑影响：`createTextHandler` 风险 HIGH，直接使用者含应用运行时及 3 个测试文件，影响 2 个流程、3 个模块；`TaskService.#run` 风险 UNKNOWN，图谱未解析调用方，因此通过源码确认 `#loop` 直接调用 `this.#run(model, task.id, signal)`。本次涉及关键任务结算，修改范围限制为超限校验恢复分支。

## 问题
| AC | 预期 | 实际 | 根因 |
|---|---|---|---|
| AC-1/2 | 可恢复的镜头时长校验错误进入有预算的修订 | `prepareContent` 抛错直接离开文本处理器；任务循环把任务失败结算 | 合法 JSON 的领域校验错误未被建模为修订输入 |
| AC-3 | 修订预算耗尽后失败 | 不存在定向修订预算 | 失败路径没有在已有步骤循环内重试 |

## 改动
### 阶段 1：建模超限修订
1. `meiji/server/handlers/text-handler.js` — 仅把 `shots` 的精确单镜 15 秒校验错误返回为可修订结果，并通过独立的修订草稿与修改意见字段传入最新失败原因和原草稿；项目契约原校验保持不变 → AC-1/2/4。
2. `meiji/server/flow/tasks/task-service.js` — 留存失败生成/修订步骤及草稿，作废当前待审步骤，追加最多两轮修订与审核；预算耗尽后失败 → AC-1/2/3/4。
3. `meiji/dev_docs/in_puts/shots-regenerate.yaml`、`meiji/dev_docs/提示词编排.md`、`meiji/dev_docs/任务步骤.md` — 定义独立的待修订镜头表输入，明确 YAML 占位符与运行时资料构建器须成组更新、真实路径测试并重启 Harness；记录有限修订行为 → AC-2/3。
4. `meiji/tests/stage05-shots-duration-repair.test.js` — 用真实处理器与任务服务验证自动修订、审核、预算和非目标错误路径 → AC-1/2/3/4。
