# Elysium 数据根目录与导演链路修复

- 类型：Bug 修复
- 目标：将全部 Elysium 数据统一到 `$DSH_HOME/storages/elysium`，无损保留现有项目，并修复导演新增/修改入口和保存链路。
- 调研来源：`docs/research/调研-导演库新增修改链路.md`

## 人工决策

无。用户已明确唯一数据根为 `$DSH_HOME/storages/elysium`；本机对应 `/Users/mac/.dsh/storages/elysium`。

## 执行步骤

### 阶段 1：统一默认路径与迁移方向

1. `dsh-elysium/src/utils/config.js:resolveConfig` — 修改：默认 home 从 `~/.elysium` 改为 `$DSH_HOME/storages/elysium`；显式测试/实例配置仍可覆盖 → AC-4、AC-7
2. `dsh-elysium/src/servers/registry/store.js:registryPath` — 修改：无运行上下文 fallback 改为 `$DSH_HOME/storages/elysium/config/servers.json` → AC-4、AC-7
3. `dsh-elysium/src/servers/selection/store.js:selectionPath` — 修改：无运行上下文 fallback 改为 `$DSH_HOME/storages/elysium/config/selection.json` → AC-4、AC-7
4. `dsh-elysium/scripts/migrate-home.mjs` — 修改：迁移方向改为旧 `~/.elysium`/旧 `.dsh` 散落配置 → `$DSH_HOME/storages/elysium`；只合并源中存在的条目，备份冲突文件，不删除目标独有的 projects/runtime/uploads → AC-5～AC-7
5. `.claude/standards.md:部署与配置`、`dsh-elysium/README.md:本机配置边界` — 修改：固定唯一数据根及目录职责，删除 `~/.elysium` 作为默认目录的说明 → AC-4、AC-7

验证：配置单测证明默认 state、servers、selection、providers 全部位于同一根；迁移 fixture 证明目标独有项目不会被删除、冲突可恢复 → AC-4～AC-7

### 阶段 2：修复导演新增与修改入口

1. `dsh-elysium/src/client/workbench/directors.js:DirectorList` — 修改：分别显示新增/编辑取消文案；移除整卡点击编辑，增加独立 edit 按钮；成功使用服务端返回值，失败保留草稿 → AC-1～AC-3
2. `dsh-elysium/src/client/workbench/styles.js:导演卡片` — 修改：动作列容纳编辑和删除按钮，不改变拖动排序 → AC-2

验证：按 aria-label 定位添加/编辑入口；拖动卡片无 `onClick` 编辑；新增、修改各只发送一次请求 → AC-1～AC-3

### 阶段 3：补齐自动测试

1. `dsh-elysium/tests/director-panel.test.js` — 新增：覆盖首次读取、新增、显式编辑、服务端规范化返回、失败保留草稿及编辑/拖动分离 → AC-1～AC-3
2. `dsh-elysium/tests/director.test.js` — 修改：覆盖跨 Store 重载、最终 JSON 和 `0600` 权限 → AC-3、AC-6
3. `dsh-elysium/tests/config.test.js` — 修改：默认根改为 `$DSH_HOME/storages/elysium`，并覆盖显式配置隔离 → AC-4、AC-7
4. `dsh-elysium/tests/home-migration.test.js` — 修改：覆盖反向迁移、目标数据保留、冲突备份和凭据权限 → AC-5～AC-7

验证：`node --test tests/config.test.js tests/home-migration.test.js tests/director.test.js tests/director-panel.test.js` 全部通过 → AC-1～AC-7

### 阶段 4：无损合并本机数据

1. `/Users/mac/.dsh/storages/elysium/` — 修改本机状态：实施前重新盘点用户并发移动；创建带时间戳备份；保留现有项目/任务/素材文件，将导演归入 `pools/`，服务器连接、模型选择和 provider 配置归入 `config/` → AC-5～AC-7
2. 旧散落路径 — 修改本机状态：新根校验通过后移入同一备份目录，不直接删除，避免再次形成两个可写数据源 → AC-4、AC-7

验证：迁移前后 pools/projects/runtime/uploads 的相对路径和 SHA-256 清单一致；目标目录包含 `pools/directors.json`、`config/servers.json`、`config/selection.json`、`config/providers/`；敏感配置权限为 `0600` → AC-5～AC-7

### 阶段 5：构建、打包、重启与运行验收

1. `dsh-elysium/lib/`、`dsh-elysium/registry/` — 生成：执行 `pnpm build`、`pnpm package:registry` → AC-8
2. 本机 Harness — 重启：执行 `DSH_NO_OPEN=1 node harness/scripts/start.mjs`，让新路径和客户端进入运行进程 → AC-8

验证：

- `pnpm test` 与项目级 Harness 测试通过；环境限制导致的既有失败单独标注。
- `lib/client.js`、`registry/lib/client.js` 和本机链接包哈希一致。
- 3080 返回 Harness 身份响应；运行接口的导演列表、项目列表和模型配置来自 `$DSH_HOME/storages/elysium`。
- 操作一次导演修改后，只有目标 `directors.json` 发生变化，`~/.elysium` 不会重新出现 → AC-1～AC-8。

## 验收标准

- AC-1：导演页提供明确的添加入口；成功后显示服务端最终返回值。
- AC-2：每位导演提供独立的“编辑导演 {名称}”按钮，拖动不触发编辑。
- AC-3：编辑回填并只发送一次 update；失败保留草稿和原列表。
- AC-4：未显式覆盖时，所有运行路径均以 `$DSH_HOME/storages/elysium` 为根，不创建或读取 `~/.elysium`。
- AC-5：本机现有 projects、runtime、uploads 全量保留，文件数量和内容校验迁移前后相符。
- AC-6：最新导演数据合并到 `$DSH_HOME/storages/elysium/pools/directors.json`；重启后接口、界面与该文件一致。
- AC-7：`config/servers.json`、`config/selection.json`、`config/providers/` 职责分离，凭据文件权限保持 `0600`。
- AC-8：源码完成 build、registry 打包和 Harness 重启，运行进程实际使用新根目录。
