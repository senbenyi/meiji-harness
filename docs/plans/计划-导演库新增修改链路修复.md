# 导演库新增修改链路修复

- 类型：Bug 修复
- 目标：统一导演库当前数据源，让新增与修改入口明确且互不干扰，并用自动测试锁定“提交 → 服务端最终值 → 当前列表/持久化”的完整链路。
- 调研来源：`docs/research/调研-导演库新增修改链路.md`

## 人工决策

1. **待确认**：推荐保留当前 `/Users/mac/.elysium/directors.json` 为唯一运行数据源，将旧 `/Users/mac/.dsh/storages/elysium/directors.json` 移入带时间戳的备份目录。若改为使用旧路径，必须同时处理当前 `.elysium` 下的项目、任务、上传和模型选择，不属于导演单功能修复。
2. 导演名称继续作为稳定键，不纳入本次修改范围。

## 执行步骤

### 阶段 1：收敛本机实际数据源

1. `/Users/mac/.dsh/storages/elysium/directors.json` — 修改本机状态（可恢复移动）：在再次确认运行接口与 `/Users/mac/.elysium/directors.json` 一致后，将迁移前旧副本移入 `/Users/mac/.dsh/backups/` 的带时间戳目录，不删除当前数据 → AC-6
2. `dsh-elysium/README.md:本机配置边界` — 修改：明确当前默认导演库是 `~/.elysium/directors.json`，旧 `.dsh/storages/elysium` 仅是迁移源且迁移后不会同步 → AC-6

验证：只读调用 `/director/list`，结果与 `/Users/mac/.elysium/directors.json` 完全一致；原旧路径不再保留易误认的 `directors.json`，备份文件可读取恢复 → AC-6

### 阶段 2：修复新增与修改入口

1. `dsh-elysium/src/client/workbench/directors.js:DirectorList` — 修改：保留顶部添加入口；分别显示“取消添加导演”和“取消编辑导演”；移除整张可拖拽卡片的点击编辑，给每张卡片增加独立 `edit` 图标按钮并与删除按钮组成动作区；保存仍以服务端返回对象作为列表最终值，失败时不清空草稿 → AC-1、AC-2、AC-3
2. `dsh-elysium/src/client/workbench/styles.js:导演卡片样式` — 修改：卡片动作列容纳编辑、删除两个独立按钮，不改变列表、拖动和响应式布局 → AC-2

验证：客户端测试中按钮可按 aria-label 定位；点击编辑不会依赖卡片 `onClick`；新增态和编辑态关闭文案分别正确 → AC-1、AC-2

### 阶段 3：补齐客户端与持久化回归测试

1. `dsh-elysium/tests/director-panel.test.js:新增文件` — 新增：构造独立 DirectorList fixture，覆盖首次读取、新增、显式编辑、服务端规范化返回值、请求次数/请求体、失败保留草稿与原列表，以及编辑按钮不影响拖动入口 → AC-1、AC-2、AC-3、AC-5
2. `dsh-elysium/tests/director.test.js:导演库端到端测试` — 修改：在现有新增/修改落盘断言后，以新 Store 实例重新读取，确认最终 JSON 可跨实例读取且文件权限为 `0600` → AC-4、AC-5
3. `dsh-elysium/tests/config.test.js:默认本机目录测试` — 修改：明确默认 state root 指向 `~/.elysium` 语义，防止再次把旧 `.dsh` 路径当作运行目录 → AC-6

验证：`node --test tests/config.test.js tests/director.test.js tests/director-panel.test.js` — 默认目录、新增、修改、失败和重载场景全部通过 → AC-1～AC-6

### 阶段 4：构建、打包并更新本机运行链路

1. `dsh-elysium/lib/`、`dsh-elysium/registry/` — 修改生成产物：执行 `pnpm build` 和 `pnpm package:registry`，确保 Harness 链接包包含修复后的客户端 → AC-5
2. 本机 Harness — 重启：通过 `harness/scripts/start.mjs` 让已链接的 registry 在运行进程中生效，不修改 `directors.json` 业务数据 → AC-5

验证：

- `pnpm test` — 全量插件测试通过；若沙箱继续导致既有 `worker identity` 用例无法读取进程参数，单独标明环境失败，不将其记为本功能通过。
- `pnpm build && pnpm package:registry` 后比较 `lib/client.js`、`registry/lib/client.js` 与本机插件链接目标哈希一致 → AC-5。
- `curl http://127.0.0.1:3080/` 返回 Harness 身份响应；浏览器人工确认新增、编辑、拖动和失败提示 → AC-1～AC-5。

## 验收标准

- AC-1：导演页提供明确的“添加导演”入口；提交后只发送一次 `create`，成功后显示服务端最终返回值。
- AC-2：每位导演提供独立、可聚焦的“编辑导演 {名称}”入口；拖动卡片不会依赖或触发整卡点击编辑。
- AC-3：编辑入口回填名称、风格和作品；提交后只发送一次 `update`，成功后原位更新，失败时保留草稿和原列表。
- AC-4：新增和修改最终写入 `$ELYSIUM_STATE_ROOT/directors.json`，写入保持串行、原子替换及 `0600` 权限，重新创建 Store 后能读到相同数据。
- AC-5：修改后的导演列表能被导演页、重新进入的项目导演下拉框和 `director_list` 读取，无需重启；源代码经构建、打包后进入本机 Harness 链接的 `registry`。
- AC-6：本机只把一个明确路径作为当前导演库；旧迁移副本不再被误认为运行数据，删除后接口与当前文件保持一致。
