# 镜头表超时失败结果写入正式数据

- 类型：Bug 修复 / 关键业务流程
- 目标：镜头表的最终生成结果即使因整集时长超限而失败，也写入正式镜头数组，并在同一事务中保存失败状态和原因。
- 非目标：不增加第二份草稿数据；不保存接口错误、无效结构的输出；不改变时长校验和自动修订规则。

## 验收标准与调研结论
| AC | 输入/状态 → 可观测结果 | 已确认/未确认/未验收 | 依据或缺口 |
|---|---|---|---|
| AC-1 | 最终一次镜头生成结构有效但整集总时长超限 → Model 的正式镜头数组等于该次生成结果，节点状态为 failed 且原因准确 | 已确认 | `prepareContent` 已将 AI 编号规范化；`TaskService` 预算耗尽时只结算状态 |

## 调研与调用链
面板提交镜头表任务 → `createTextHandler` 调用 `prepareContent` → 镜头编号转换和 `replaceShots` 规范化 → `commitContent(probe,...)` 校验整集总时长并抛错 → 文本处理器把原始响应交给 `TaskService` 自动修订最多两轮 → 预算耗尽时当前代码仅调用 `#finish`，将节点设为 failed，正式 `镜头` 数组仍是旧值。任务步骤虽留有 AI 原始结果，却不属于项目 Model，面板也只读节点正式数据。

变更方式：校验异常携带已规范化内容，仅在时长修订预算耗尽的同一次 `model.update` 中，把其 `镜头` 数组赋给正式节点，再由 `#finish` 写入 failed 状态和原因。中间修订稿不写入 Model；非时长错误维持原路径。
