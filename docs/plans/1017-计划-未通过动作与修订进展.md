# 未通过动作与修订进展

## 目标

面板未通过时，主动作放在原因下面；提取剧集可以人工收下被容量审核拒绝的候选；自动修订在审核意见实质重复时停下，并在卡片上显示轮次。

## 行为

- 文本节点和视频未通过：原因下方是「修复（再给 N 轮）」或剧本的「修改（再给 1 轮）」，N 为该节点 `retryRounds`。不弹框。视频修复只提交该镜视频任务并带上原因，不重跑每秒分镜和提示词。顶栏不再用「原结果修订」冒充修复。重新生成仍可整镜重来。
- 排队或生成中，任务已经进入自动修订时，状态行追加「自动修订 当前轮/上限」。剧本审核的纯审核任务不显示。
- 未通过原因超过 80 字时收成两行，可展开。
- 合片、首尾帧、多模态未通过且已有产出时提供人工放行。重新执行时把节点原因写入意见。首尾帧和多模态的 override 契约放开。
- 提取剧集未通过时，顶栏增加人工放行。放行读取最近一次未通过任务里最后一份生成或修订候选，用 `buildSplit` 做覆盖校验（不传参考时长，因此不卡容量），通过后写入剧集。没有候选或覆盖错误则任务未通过，不改剧集。
- `revisionProgress`：候选不同，且本轮审核原因在去掉空白和标点后与上一轮相同，或被上一轮包含且不少于 20 字，则记为重复审核意见并停止，不提交候选。剧本审核除外，仍用满修改轮次并保存最后一稿。候选相同的既有规则不变：只有重复程序错误才停，相同 AI 原因仍继续并把提示写入下一轮。
- 定妆照、成片、分镜组状态为已取消时，展示停下任务的结束原因。

## 验证

相关阶段测试，`git diff --check`，GitNexus `detect-changes` 与 `analyze --index-only`。不提交真实模型任务。
