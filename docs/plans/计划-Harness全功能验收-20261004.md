# Harness 全功能验收

- 类型：功能验收；若发现需修改业务代码的缺陷，再按完整流程补充根因、影响分析及对应测试后实施。
- 目标：按实际注册的 34 类操作、前端入口及任务生命周期核对覆盖，完成真实生成到整集拼接，不以自动化测试通过代替端到端验收。
- 环境：当前 Harness 和真实模型网关；独立项目「全功能测试-20261004」。既有用户项目不用于写入测试。

## 验收标准

| AC | 功能范围 | 验证 |
|---|---|---|
| AC-1 | 项目创建、打开、概要编辑、剧集新增/编辑、摘要生成/修订 | 实际 UI、操作记录、持久化读回 |
| AC-2 | 大纲/人物/场景/道具生成、自审、修订、手动编辑与下游失效 | 实际 UI 和自动化故障分支；记录语义不符合的产物 |
| AC-3 | 人物/场景/道具图片、候选确认/放弃、导入、素材关联、参考图 | 实际 UI 和独立测试存储中的自动化分支 |
| AC-4 | 镜头表、每秒指令、分镜提示词、单镜/批量视频、尾帧、全片拼接 | 真实操作链路、文件存在和 ffprobe 媒体参数 |
| AC-5 | 历史/内容快照/实际提示词、skill、语言、排队占用、停止、刷新恢复、失败门禁 | 实际 UI 与自动化；明确区分模型失败与程序失败 |
| AC-6 | 删除、权限、跨项目归属、失败写回、重启中断 | 隔离临时数据的自动化验证；不删除现有用户项目 |
| AC-7 | 功能覆盖表与缺陷清单 | 每项给出实际结果、证据和限制；未通过项不得标为通过 |
