## 步骤 1：store.js 增加对象级操作

### 1.1 schema.js：单对象校验 + 镜头 ID

**文件**：`dsh-elysium/src/projects/schema.js`

锚点已有 `role` 作为唯一标识（`anchorsValue` 校验 `roles.has(anchor.role)` 防重复），可直接用作锚点 ID。

镜头没有稳定 ID，`index` 是每次保存时重算的序号。需新增 `id` 字段。

改动：
1. 新增 `validShotId`：`/^[a-z0-9-]{1,40}$/`
2. `actsValue` 中镜头返回对象增加 `id` 字段（透传，不自动生成）
3. 提取 `anchorValue(anchor, existingRoles)` 单锚点校验函数
4. 提取 `shotValue(shot)` 单镜头校验函数

### 1.2 store.js：对象级增删改方法

**文件**：`dsh-elysium/src/projects/store.js`

当前 `change` 的 `update` 操作是整体替换数组。新增两个方法，在 `enqueue` 内串行执行：

#### `changeAnchor(projectId, action, data)`

- `add`：校验后追加到 `anchors` 末尾
- `update`：按 `role` 匹配，合并 patch（仅覆盖传入的字段）。如有 `new_role` 则联动更新所有镜头的 role 引用
- `delete`：按 `role` 移除

#### `changeShot(projectId, action, data)`

- `add`：生成 `id = randomBytes(4).toString('hex')`，追加到指定幕末尾
- `update`：遍历所有幕按 `id` 匹配，合并 patch
- `delete`：按 `id` 移除
- `move`：同幕内按 `direction` (+1/-1) 交换位置

#### 已有镜头补 ID

`load` 函数中，加载 acts 后检查每个镜头是否有 `id`，没有则生成并回写。首次加载透明迁移。

#### 返回值

`createProjectStore` 返回对象增加 `changeAnchor`、`changeShot`、`lastModified`。

### 1.3 验证

新建 `dsh-elysium/tests/store-object-ops.test.js`，用 `node --test` 运行：
- add/update/delete 锚点和镜头
- role 改名联动镜头
- 已有项目首次加载后镜头获得稳定 ID
- 回归测试：整体 update 路径不受影响

## 步骤 2：注册聊天项目工具

### 2.1 新建工具定义

**文件**：`dsh-elysium/src/tools/project.js`（新文件）

参照现有工具模式（`model-jobs.js` 的 `createXxxTool()` 结构），定义 5 个工具：

| 工具 | 用途 | 必需参数 |
|------|------|----------|
| `project_read` | 读取项目完整数据 | `project_id` |
| `project_update_anchor` | 增删改单个锚点 | `project_id, action, role` |
| `project_update_shot` | 增删改单个镜头 | `project_id, action` + `id`(改/删) 或 `act_index`(增) |
| `project_update_info` | 修改项目元数据 | `project_id` + patch 字段 |
| `project_create` | 创建新项目 | title, director 等 |

`renderProjectResult`：精简渲染，只返回 id、title、anchor_count、shot_count，避免完整数据淹没上下文。

### 2.2 工具注册

**文件**：`dsh-elysium/src/tools/index.js` — 导出 `createProjectTools(store)`

**文件**：`dsh-elysium/src/index.js` — 在 `ctx.inject(['webServer'], ...)` 回调内注册项目工具（与 `projects` store 同生命周期）

项目工具直接注册，不走 `discovery.js` 的延迟加载。

### 2.3 验证

- 启动 Harness，确认工具出现在可用列表
- 聊天中调用 `project_read` 读取已有项目
- 聊天中调用 `project_update_anchor` 添加锚点

## 步骤 3：前端改为对象级提交

### 3.1 HTTP 路由

**文件**：`dsh-elysium/src/http/project-routes.js`

`actions` 数组增加 `'update-anchor'`、`'update-shot'`，分别调用 `store.changeAnchor` 和 `store.changeShot`。

### 3.2 前端 API

**文件**：`dsh-elysium/src/client/workbench/project-api.js`

新增 `updateAnchor(projectId, action, data)` 和 `updateShot(projectId, action, data)`。

### 3.3 anchors.js

**文件**：`dsh-elysium/src/client/workbench/anchors.js`

- 创建锚点：`save({ anchors: [...] })` → `run(() => updateAnchor(project.id, 'add', anchor))`
- 编辑锚点：`save({ anchors: project.anchors.map(...) })` → `run(() => updateAnchor(project.id, 'update', { role, ...patch }))`
- 保留 `run` 包装处理 busy 状态和错误

### 3.4 storyboard.js

**文件**：`dsh-elysium/src/client/workbench/storyboard.js`

- `patchShot` → `updateShot(project.id, 'update', { id: shot.id, ...patch })`
- `move` → `updateShot(project.id, 'move', { id: shot.id, direction })`
- `remove` → `updateShot(project.id, 'delete', { id: shot.id })`
- 添加镜头 → `updateShot(project.id, 'add', { act_index, ...fields })`
- **幕级操作保留整数组提交**——频率极低，不存在跨入口冲突

### 3.5 验证

- 右侧面板增删改锚点和镜头，确认功能正常
- 浏览器网络面板确认请求路径为 `update-anchor` / `update-shot`
- role 改名后镜头引用自动更新

## 步骤 4：保存后通知前端刷新

### 4.1 方案：轮询 + 变更标记

宿主目前无服务端到客户端的事件推送机制（待核验），采用轮询方案。

### 4.2 服务端

**store.js**：新增 `modifiedAt` Map，写入成功后记录 `updated_at`。暴露 `lastModified(id)` 方法。

**project-routes.js**：新增 `poll` action（GET），客户端传入 `id` 和 `since`，服务端比较后返回 `{ updated: true/false }`。

### 4.3 客户端

**project-api.js**：新增 `pollProject(id, since)`。

**projects.js**：`ProjectDetail` 组件增加 `useEffect`，每 4 秒调用 poll。有更新时重新加载项目。正在保存时跳过。用户有未提交编辑时提示而非静默覆盖。

### 4.4 验证

- 打开右侧面板查看项目
- 聊天中修改该项目
- 4-5 秒后右侧自动刷新
- busy 状态时不触发轮询

## 步骤 5：创作编辑 Skill

### 5.1 文件

**新建**：`harness/.dsh/agents/skills/project-editing/skill.md`

（目录发现规则待核验，基于 `agent.cordis.yml` 的 `agentsHome` 配置）

### 5.2 内容要点

- 列出可用的 5 个项目工具
- 行为规则：先读后改、展示差异、按授权保存、最小修改、结果为准

## 风险

| 风险 | 缓解 |
|------|------|
| 旧的整数组 `update` 端点仍可被调用 | 保留兼容，不删除 |
| 轮询间隔内看到短暂旧数据 | 4 秒延迟可接受 |
| 已有镜头没有 `id` 字段 | `load` 时透明迁移 |
| 幕级操作仍用整数组 | 极低频，后续可优化 |
