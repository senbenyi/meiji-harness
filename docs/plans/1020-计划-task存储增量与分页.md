# task 存储增量与分页

- 类型：完整流程，公共存储与调度热路径重构。
- 目标：执行与HTTP记录不再读取已结束组的历史；SQLite只写变化记录，在数据库筛选分页并按组读取详情。
- 非目标：不改四个公共Model字段、历史UI、业务重试策略、其他包及同期业务文档/drama改动。

## 验收标准与证据
| AC | 输入/状态 → 可观测结果 | 调研/验证 |
|---|---|---|
| AC-1 | 大量已结束历史下提交、执行、记录HTTP → 仅读写当前组及活动队列 | manager各热路径目前调用全scope read/transaction；增加禁止全读的存储回归及SQL写入计数 |
| AC-2 | status/node_type筛选、offset/limit分页 → 与内存结果一致，只解析当前页；详情只取目标组 | 当前history先全读后slice；新增SQL路径与混合状态、空页、跨scope/参数边界对照 |
| AC-3 | 迟到写、取消、异常、恢复、共享事务 → 保持原终态及回滚语义 | 沿用manager回归并补局部事务越界、跨组冲突、增量回滚和重开验证 |

## 调用链与影响
- TaskManager.submit/loop/stepRecord/finish/cancel/recover → TaskStore.transaction/read → SQLiteTaskStore.read/write。
- history/detail/historySource → TaskStore.history/detail → 全量读取/内存分页。
- 图谱绑定agent-harness；impact覆盖TaskStore、MemoryTaskStore、SQLiteTaskStore、TaskManager、validateSnapshot。动态store子类及回调已由源码补查。基线task27项全通过。

## 实施
1. store/index.js：增加受限读集合（目标组/任务所属组、活动组）及追加事务；局部事务禁止新增/换组；Map查找替代逐记录find；内存存储只替换变化记录并检查跨集合冲突。
2. store/sqlite.js：按组与活动状态读取，SQL索引和完整性约束；事务差异INSERT/UPDATE，历史数据库筛选/排序/分页；定位任务所属组/队尾避免全读。
3. manager/index.js：提交仅追加新组，执行记录只用当前组，调度/恢复只读活动组，historySource精确定位任务。保留公共操作接口及结果结构。
4. models-store/manager现有测试补充性能行为断言，新增受控规模基准脚本（临时执行，不把绝对耗时作为易波动测试断言），更新README。
