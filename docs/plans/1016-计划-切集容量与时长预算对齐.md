# 切集容量与时长预算对齐

- 类型：Bug修复，完整流程。
- 目标：150秒参考在切集时约束实际内容容量，并统一大纲与镜头的时间口径，减少无效反复修订。
- 非目标：重新拆分现有项目、改动已完成镜头、生成媒体、增加修复轮次、变更持久化结构。

## 问题
长行无法细切；长对白组禁止拆分使容量失控；大纲精确时长和程序容差不一致；镜头修订强制同时改正文和时间造成重复重写。

## 待用户决定
无。不可拆发言可超参考，保留真实估时；程序无法仅凭声明秒数证明真实表演可执行，内容容量仍需模型判断。

## 改动
1. script-split.js：长行按引号外完整句与完整发言提供切点，保留短行、全部原字符；150参考时180为多单位集上限，同步程序审核和提交 → AC-1/2。
2. prompts/duration-policy.js及三节点compose：派生切集区间、大纲±30、镜头累计取整预算与可行镜数 → AC-2/3。
3. 三PromptModel与输出契约：同一时长口径，允许完整发言后切集，不为凑秒扩写，不强制已解决的时长意见改正文 → AC-3。
4. 独立回归测试、三节点完整提示词文档与实施记录 → AC-1/2/3/4。

## 用户明确的估时约束
2026-10-16：不得按字数换算。对白容量必须按完整发言的正常表达、动作过程、剧情推进、反应、串行与并行关系语义评估。撤销字符门槛方案及其测试，不作为最终验证证据。真实试切显示声明秒数不足以保证容量，需要前置语义审核。

## 前置语义审核
script-split增加独立AI容量审核，在程序覆盖检查通过后、正式替换剧集前执行；共用原有两次修订预算，审核只依据对白表达、剧情动作与并行/串行关系，不使用任何字数换算。BUSINESS_DEFINITIONS图谱impact为UNKNOWN，源码task-plan.reviewTypes动态读取aiReview、步骤调度与createTextHandler调用审核接口已补查。同步节点输出契约、业务文档和相关任务步骤测试。新增验证：程序数值通过但语义容量失败时，拒绝旧切点并带具体P编号进入修订；修订后才正式写入。
