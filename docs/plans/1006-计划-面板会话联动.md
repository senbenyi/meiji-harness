# 面板会话联动

- 类型：新功能 + 重构（完整流程：任务状态模型、任务归属、Harness 接入、HTTP、面板、会话提示词，超过 3 个文件）
- 目标：一个项目同一时间只有一个任务，任务停下即结束，面板与会话不再交叉操作；面板操作和面板任务结果进入当前会话，需要人处理时 AI 主动说明。
- 非目标：不改上游 Harness；不改规划器（拆分另见 [1006-计划-规划器按阶段拆分](1006-计划-规划器按阶段拆分.md)）；不改任务内的步骤调度、依赖与自动修订复审（最多 2 轮）；不让 AI 代替人确认候选图、剧本方案或人工放行；不为面板任务建 Harness goal。

## 背景

1. 面板上的操作和面板发起的任务结果不进入会话，AI 不知道也不回应。Run 重构计划阶段 5 第 2 条当时规定「面板发起的 Run 不建 goal、不通知会话」。
2. 现有规则是「每集一个任务、不同集可并行、同集新目标自动并入、停下的任务可在原任务内继续」，面板与会话可以同时处理同一个停下的任务，或并入对方的任务（会话 `run-plan` 自动并入并自动确认删除，面板看不到预览）；任务停着时项目里同时挂着多个未结束任务。

## 已决定（2026-10-06，用户）

1. **整个项目同一时间只有一个任务**，不再按集并行。
2. **任务停下即结束**。原来的各种「暂停」全部改为结束状态：步骤出错、重启中断为「失败」；自审用尽为「未通过」；生成候选图或剧本方案后等待人确认为「待确认」。不再有暂停状态，也不再有在原任务内继续的操作。
3. **接着做 = 开新任务**。已完成的内容保存在项目内容节点上，以同一目标、generate 模式新开任务时，规划器跳过已完成的对象，只做剩下的部分。
4. **任务执行中面板冻结生成和编辑**，只能查看和取消。面板目前没有主动暂停按钮，本计划不新增。
5. **会话在任务执行中收到新的制作请求，排成下一个任务**；当前任务「已通过」结束后队首自动开始。
6. **当前任务以失败、未通过、待确认或取消结束时，排队的请求不自动开始**，由用户在面板任务条点「开始」或「移除」；会话记录一条通知。
7. **面板任务结果由 meiji 直接投递通知进会话**：需要人决定时会话空闲则 `followup` 唤醒、忙时 `inject`；只需记录时一律 `inject`；消息直接带结果。不给面板任务绑定 Harness job。

## 与工作区进行中改动的关系

调研时（2026-10-06 19:20）工作区已有未提交、无对应计划文档的改动，方向与决定 2 一致，本计划在其基础上实施，不覆盖：

- `shared/run-model.js` 新增 `failRun` 与 `RunStatus.FAILED`：步骤出错、自审用尽、重启中断直接结束任务，失败步骤记 `failed`，其余未完成步骤取消。
- `server/flow/runs/run-engine.js:finish` 改用 `failRun`，并 `abortFailed` 中止同任务仍在执行的其他分支；`server/data/run-store.js` 重启恢复改用 `failRun`。
- `shared/run-view.js` `failed` 显示「未通过」；`harness-run-goals.js`、`harness-run-jobs.js` 在 failed 时结算。
- 由此，**一条分支失败时整个任务结束、其他执行中的分支一并停止**（原 Run 重构「失败只暂停该分支、其他分支继续」不再成立）。本计划沿用此行为。

前提：上述改动提交并通过其测试后再开始本计划；规划器拆分先于本计划完成（「接着做」依赖规划器正确跳过已完成对象，见决定 3）。
