# 重启作废未完成任务

- 类型：完整流程，任务恢复与队列业务修改。
- 目标：重启后旧排队/进行中任务统一已作废，新任务可正常执行与刷新。
- 非目标：不删除历史、不重放旧任务、不修改远端任务取消协议。

## 验收标准与调研结论
| AC | 输入/状态 → 可观测结果 | 判定 | 证据 |
|---|---|---|---|
| AC-1 | 重启存在 queued/running 任务（含组合）→ 全部 superseded，未完步骤作废，已完成步骤保留 | 已确认问题 | recover 只筛 running，结算 cancelled |
| AC-2 | 作废后 → 运行节点 cancelled，排队节点恢复更新后的快照，正文/媒体保留，任务终态落盘 | 未验收 | #finish 只支持未开始 superseded 的节点恢复 |
| AC-3 | 重启队列暂停，无论是否有未完成任务 → queue_stopped=false；新任务自动执行且不会去重到旧任务 | 已确认问题 | 当前恢复后 queue_stopped=true |
| AC-4 | 旧 completed/failed/rejected/cancelled/superseded → 历史及步骤不变；重复恢复不修改终态，新服务晚到结果不能覆盖作废任务 | 未验收 | 终态校验与 #run 已有 running 守卫 |
| AC-5 | 任务管理/详情/概要 → 显示已作废，无旧任务开始/取消操作，新任务刷新仍可用 | 未验收 | history 与概要当前 superseded 显示已替代；SSE 建连发送当前 revision |

## 调用链与证据

- `createAppRuntime → repository.list/open → tasks.recover → Model.update → #finish → repository`；`dispose → recover` 同样走恢复入口。
- `#finish` 的图谱 UNKNOWN；源码确认调用方为 command 取消、组合后续作废、执行错误、#run 结算、recover，并非未使用函数。
- UI `renderTaskPanel → renderHistory/renderOverview`；SSE events 建连发送项目当前 revision，workbench 依据 revision 刷新。
- force 重建后 recover HIGH：3 直接调用方、2 流程、3 模块，2 个 receiver 未解析缺口以启动/关闭源码补查。renderHistory CRITICAL（2 直接调用、14 流程、2 模块）；renderOverview CRITICAL（1 直接调用、12 流程、2 模块）。已告知风险。
