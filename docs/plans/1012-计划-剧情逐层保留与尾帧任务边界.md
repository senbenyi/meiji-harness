# 剧情逐层保留与尾帧任务边界

- 类型：提示词与制作文档调整
- 目标：明确拆分剧集、故事大纲、镜头表不能逐级丢失剧情事实和描写细节，并把尾帧截取定义为视频任务的生成后步骤。
- 非目标：按用户要求，不修改任何运行时代码；不更改剧情数据字段。

## 验收标准与调研结论

| AC | 输入/状态 → 可观测结果 | 已确认/未确认/未验收 | 依据或缺口 |
|---|---|---|---|
| AC-1 | 剧本拆分 → 每个段落只分配一次，程序按原文写回；提示词明确动作、场景、情绪及修饰细节不能省略 | 已确认 | `script-split` 模板声明切点输出，`script-split.js` 校验连续覆盖并按原文逐字拼接 |
| AC-2 | 大纲生成/修改/自审 → 明确保留剧情依据中的所有具体事件及描写含义 | 已确认 | 更新 `outline-generate/regenerate/review.yaml` |
| AC-3 | 镜头表生成/修改/自审 → 每个故事小段对应的镜头序列保留所有具体信息，不因拆分而概括或弱化 | 已确认 | 更新 `shots-generate/regenerate/review.yaml` |

## 调研与影响

`script-split.js` 已逐字拼回源剧本并拒绝漏段、重叠和不完整结尾。当前运行时代码仍将 `tail` 建模为独立 business，并由视频任务组另行安排；用户明确限定只改文档，因此本次仅将目标流程规格改为同一视频任务内的尾帧后处理，实际执行路径留待后续代码任务处理。

## 改动

1. `meiji/dev_docs/in_puts/script-split-{generate,regenerate}.yaml` — 强化完整段落分配及不得弱化描述。
2. `meiji/dev_docs/in_puts/outline-{generate,regenerate,review}.yaml` — 逐项保留人物、动作、场景、情绪、修饰词等内容并纳入回查。
3. `meiji/dev_docs/in_puts/shots-{generate,regenerate,review}.yaml` — 每个故事小段按锚点拆分并核对事实和描写完整性。
4. `meiji/dev_docs/制作工作流.md`、`制作节点规则.md`、`step_model.json` — 说明尾帧是视频任务的程序后处理步骤，不再是独立任务。
