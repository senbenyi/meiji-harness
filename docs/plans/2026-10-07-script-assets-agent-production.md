# 从正式剧本到完整提示词：六类子 Agent 生产链补齐方案

> 状态：已实施并部署，两集返工链路实机闭环通过；首次入口通过集成测试。内容质量不在本轮验收范围。
> 基线：2026-10-07，`141f802e` 加当前未提交工作区；保留已有改动。
> 范围：剧本提取资产、道具与衍生资产、图片和视频提示词、主 Agent 调度、页面编辑及返工闭环。

## 0. 结论

最大问题是创作阶段与数据契约缺失。现有实现把原文分析中的人物简介直接当作可生产资产，把剧本写作、镜头规划和视频提示词合成一次输出，再临时拼接图片提示词。下游主要检查字段非空和媒体是否存在，无法判断每个产物是否经过完整提示词编写。

增加子 Agent 名称不足以解决。必须补齐“正式剧本 → 资产清单与视觉状态 → 分类提示词 → 参考图 → 分镜图 → 视频 → 交付”的持久化成果、依赖和门禁，再让主 Agent 调度六种职责。

已有的 Proposal、领域命令、版本、任务租约、重试、依赖失效和 PromptSnapshot 继续使用。无需新建 Agent runtime 或另一套项目状态。

前次媒体返工验收证明了部分任务可以执行到成片，不能证明本方案涉及的资产提取、衍生资产和全类别提示词编写已经具备。以本次调查补充原验收边界。

## 3. 主 Agent 与六类 subagent 的边界

主 Agent 是项目协调者：识别操作目标、读取当前项目状态、发起允许的阶段任务、汇报阻塞和成果。调度依据持久化依赖，不能通过自然语言声称“完成”推进阶段。领域服务是唯一正式写入口，执行 revision、幂等、输入版本与权限检查；媒体 Worker 负责真实生成和文件落盘。

| 业务角色 | 输入 | 必须交回的正式成果 | 不负责 |
| --- | --- | --- | --- |
| 剧情 subagent | 原文、原文版本与分段引用 | 故事分析、事件链、人物关系、全书分集规划；分析中的人物场景为候选信息 | 将候选简介直接当可生产资产 |
| 剧本 subagent | 已批准故事分析、分集规划、对应原文 | 分集正式剧本、场次、动作、对白、事件和原文依据 | 同时完成最终镜头规划和模型提示词 |
| 角色 subagent | 当前正式剧本、已有资产和统一视觉风格 | 角色/场景/道具清单、使用位置、视觉状态及衍生关系、每项完整图片提示词 | 自行捏造图片路径、改写剧情；名称保留“角色”，职责包含三类资产 |
| 镜头 subagent | 正式剧本、资产清单、状态与前后场连续性 | 逐镜顺序、景别、机位、运动、时长、动作时间线、对白、精确资产/衍生引用及视频提示词 | 改写原剧情或替代资产设计；参考图/分镜就绪后可补全视频条件绑定 |
| 分镜 subagent | 已批准镜头计划、已就绪参考图及视觉风格 | 每镜独立静态图片提示词、构图与连续性约束、分镜预览生成请求 | 拿视频提示词直接冒充图片提示词；重新拆镜 |
| 成片 subagent | 已批准镜头视频与剪辑要求 | 时间线、排序、声音与字幕配置（按现有能力）、完整性交付检查和交付请求 | 跳过缺镜、临时补写剧情或自行宣告文件已生成 |

用户列出的角色不是强制执行顺序。实际依赖为：剧情 → 剧本 → 资产提取/视觉设计 → 镜头规划；基础图 → 衍生图 → 分镜预览 → 视频 → 成片。资产参考图生成与不依赖其像素结果的镜头规划可以并行，分镜预览必须等两者就绪。镜头视频任务由主协调调度 Worker，镜头 subagent 对其创作输入负责。

角色是持久职责标识，不要求六个永不退出的聊天进程。复用 Harness 原生 workflow/agent；子任务读取限定范围的项目快照并交回结构化成果。主协调/领域服务串行合入结果，禁止子代理直接写 Project 或直接越级调用生成服务。

## 4. 每个可生成目标必须具有的提示词契约

在现有实体/Shot 上增加同构的生成说明，复用 PromptSnapshot 记录实际执行输入，不再把说明隐藏在 renderPreparation 中。每份说明关联目标 ID、用途、编写状态、版本、上游依据和编写角色。

| 目标 | 必须表达的内容 |
| --- | --- |
| 角色基础图 | 剧本身份、年龄段、稳定外观特征、发型服装、姿态/视角、背景构图、风格光照、应保持一致的特征 |
| 场景基础图 | 地点、时代、空间布局、关键陈设、时段天气、视角景别、光照色彩、风格及不得变化的布局 |
| 道具基础图 | 形状、材质、颜色、尺度、关键细节、状态、展示视角、风格与一致性要求 |
| 衍生资产 | 父资产 ID/版本、真实参考图、保持项、变化项、适用场次/镜头；独立完整正向提示词 |
| 分镜图片 | 明确角色与资产状态、单帧动作瞬间、空间关系、构图/景别/机位、光照风格、准确参考图映射 |
| 镜头视频 | 起始状态、动作发生顺序、机位运动、时长、结束状态、衔接要求、说话人及对白、声音/音乐策略、真实参考图或首帧映射 |

共同保存正向提示词、适用时的负向提示词、引用资产/版本、参数、能力选择。模型不支持的负向提示词不伪造必填；参数与自然语言创作内容分开。原文未描述的视觉细节允许设计补充，但标记为视觉设计，不能伪称原文事实。

图片与视频具有不同字段，禁止一个 shot.prompt 同时承担两种用途。编写结果必须按目标 ID 一一对应；缺项、重复、越界、引用错误均失败。完成标准看信息字段及引用是否齐全，不用固定字数冒充完整性，也不承诺仅靠 schema 能判断全部语义质量。

状态至少区分：待编写、编写中、可生成、需更新、失败。渲染前必须校验当前说明可用，落下不可变执行快照；实际请求使用该快照。快照保留最终编译文本、模型/工作流依据、参数和按实际上传顺序排列的参考图片 ID/哈希。图片也必须记录，不能被可选开关关闭。

## 5. 从首次生成到返工使用同一条链

1. 正式剧本批准后，逐集提取并归并资产；同一资产保留稳定 ID。每个条目保存 scriptVersion、场次/文本定位及后续镜头引用。
2. 角色 subagent 设计基础与衍生提示词；生成基础图后才能生成依赖它的衍生图。只生成剧本需要的变体。
3. 镜头 subagent 规划并绑定精确资产状态；分镜 subagent 编写独立图片提示词并请求预览；视频条件随最终预览和引用更新。
4. 所有生成入口，包括批量、页面重生成、单镜 API 和工具调用，都使用相同领域检查与快照；兼容画布不得成为正式短剧的绕行通道。
5. 任务保存 role、scope、输入版本/哈希、依赖、输出 Proposal、错误和检查点；子 Agent 超时或结果不合法就失败，不补通用模板推进下游。
6. 结果提交时重新核对输入版本。过期结果不写成当前内容；重复提交保持幂等；恢复复用版本仍有效的结果。并发任务的结果通过领域入口逐个提交。
7. 编辑正式剧本后使受影响的提取/镜头/提示词需更新；编辑基础资产传播到相关衍生、分镜、视频和成片；视频提示词单改不使无关参考图重做。历史产物保留但不能充当当前完成量。
8. “修改提示词”“重新编写提示词”“按当前提示词重新生成媒体”分别执行明确动作。当前缺提示词时引导补齐；不在用户点击重新生成图片时悄悄改写已确认提示词。
9. 页面显示各项生产状态，详情可看完整提示词、版本和引用；保留紧凑卡片和整卡查看的项目总览，不堆入口。进度由正式任务和当前有效成果计算，新增待编写阶段不能被旧图片数量掩盖。

## 7. 完成验收

使用独立、普通剧情测试项目，至少包含两集、角色换装、场景昼夜变化、一个状态变化道具和一个无人物空镜。

- 角色/场景/道具及实际需要的衍生条目能反查正式剧本使用位置；没有使用依据的新增资产不静默进入生产。

- 基础图 → 衍生图 → 分镜预览 → 视频 → 整集/整剧交付真实执行，核对媒体可解码、引用准确、镜头完整且按序播放。
- 人为删除一个必要提示词、资产引用或前置成果，下游任务被明确阻止；不能以名称/描述/默认模板代替。
- 修改剧本、基础资产、衍生提示词、分镜图提示词和视频提示词，逐项验证关联失效范围及重新生成闭环，未关联内容保留。
- 注入子任务失败、过期结果与进程恢复，验证无旧结果覆盖、无跳步、无重复生成；重生成不擅自覆盖人工修改的提示词。
- 页面全阶段在桌面和窄屏下可用；总览保持简洁，显示真实当前阶段及阻塞原因。

本轮验收先证明流程完整、数据一致和请求依据可追溯；不把字段齐全或媒体可播放等同于剧情连贯性和审美质量。提示词语义充分性仍需后续内容评测。
