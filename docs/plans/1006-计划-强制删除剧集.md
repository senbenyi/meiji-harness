# 强制删除剧集

- 类型：Bug 修复 / 行为调整
- 目标：删除剧集时先停止相关任务和即时编辑，再清理该剧集的全部数据，不因忙碌状态拒绝。
- 非目标：不改变项目删除后的工作区清理语义。

## 验收标准

| AC | 输入/状态 → 可观测结果 | 状态 | 依据 |
|---|---|---|---|
| AC-1 | 剧集存在运行中、暂停或草稿任务 → 删除剧集 → 相关任务先被取消 | 已确认 | 删除入口现在先调用 Run 服务的 `cancel` |
| AC-2 | 剧集存在即时编辑 → 删除剧集 → 相关即时编辑被 abort 后再删除 | 已确认 | 即时服务增加按项目/剧集取消接口并有回归测试 |
| AC-3 | 停止完成 → 删除剧集 → 剧情、视频、图片、Run 和待处理方案被清理 | 已确认 | 原 episode-delete 清理逻辑保留，删除测试通过 |
| AC-4 | 删除项目 → 相关活动也先停止，再清理项目及工作区 | 已确认 | 项目删除共用停止流程，避免后台任务继续写入已删除项目 |

## 改动

### 阶段 1：删除前停止活动

1. `meiji/server/flow/immediate-service.js` — 增加按项目/剧集 abort 并等待完成的接口 → AC-2。
2. `meiji/server/http/panel-routes.js` — 删除项目或剧集前取消匹配的 Run 和即时编辑；移除剧集删除的忙碌拒绝 → AC-1、AC-4。
3. `meiji/tests/run-immediate.test.js`、删除相关测试 — 覆盖停止与删除顺序 → AC-1、AC-2。

验证：`node --test tests/delete-content.test.js tests/project-delete-navigation.test.js tests/run-immediate.test.js`、`git diff --check`。
