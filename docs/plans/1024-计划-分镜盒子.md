# 分镜盒子

- 类型：完整流程，新Service/Executor/Tool/接口和专属UI。
- 目标：按照现有A2规则及shot_design字段完成分镜生成、审核、修订、保存与展示。
- 非目标：重写剧情规则、真实模型试跑用户项目、自动运行其他盒子、自动生图或分片编排、修改宿主/公共包。

## 验收标准
| AC | 输入/状态 → 可观测结果 | 调研 |
|---|---|---|
| AC-1 | 面板/会话点名分镜 → 共用Service独立生成、审核，内容问题最多修订3轮 | 已确认：scene_extraction可复用项目内模式，shot_design目前只有契约与占位 |
| AC-2 | 大纲与资产 → 完整shots；拒绝重复ID、错误段/锚点/资产/服装引用、非法开场与节拍 | 已确认：definition字段与A2规则，不增加字段 |
| AC-3 | 有意见的生成/修改/重新生成 → 模型收到意见；保留稳定ID，生成/修改动作独立 | 已确认：参考团队/场景面板，重新生成保留意见 |
| AC-4 | 排队/执行/失败/拒绝 → 展示进度、原因、会话输入/步骤/结果；有效候选即时保存，失败保留候选 | 已确认：任务Runtime和通用报告投影需登记 |
| AC-5 | 连点/跨会话/上游变化/旧结果覆盖 → 幂等、互斥、拒绝迟到结果；下游过期 | 已确认：ProjectManager、writes、指纹与output_hash模式 |
| AC-6 | 上游问题/规则冲突 → 停住；上下文可诊断，规则修改沿用授权与旧值检查 | 已确认：planning工具与规则执行器模式 |

## 设计与改动
1. shot_design/{state,service,executor,review_context,rule_change_executor}.js：输入story_outline/scene_extraction/group_setting/character_extraction/current_shots/instruction/output_language；仅大纲必须已确认；非空资产须已确认，无资产允许空ID，不回读原稿及图片。
2. state校验：完整非空shots、唯一ID、有序故事段、首镜opening及后镜continuous/cut、锚点归属且覆盖、资产/服装归属及服装故事段适用；已有资料校验只做结构，不以新上游拒绝修订旧候选。旧输出哈希防止覆盖。
3. 独立Tool、插件/路由/会话注册；POST /api/drama/shots，shot_execution与失败决策；规划上下文和授权规则修改。
4. 专属panel/conversation/history：意见、首次生成、修改、重新生成、loading、镜头数/估时/开场及逐拍展示；正常会话记录完整输入/结果，无嵌套滚动。
5. ProjectService编辑分镜规则过期、运行终态恢复与下游clip_arrangement/video_prompt/videos/episodes过期，保留旧数据。
6. 集成测试用模拟模型及harness-http/JSDOM，不修改真实项目数据。
