# 角色服装单一ID

- 类型：完整流程，身份契约重构。
- 目标：提取建档后角色和服装各有唯一ID，识别、编辑、逐镜和成片直接引用同一ID。
- 非目标：不改变镜头S编号、不让AI生成新角色ID、不删除历史任务或用户图片。

## 验收标准与证据
- AC-1：角色/服装Model无number字段，提取合并只创建一次ID，重提取保留现有ID。
- AC-2：角色服装目录、识别输出、正式绑定、每秒分镜与成片均直接使用ID，无编号转换。
- AC-3：ID仍检查存在、唯一及服装归属；角色无服装目录允许空服装ID。
- AC-4：v18→v19事务迁移移除正式资料编号，保留ID、媒体、绑定与历史；依赖指纹按新输入重新校准，避免无意义过期。
- AC-5：界面显示ID；历史提示词原样保留。

## 调用链与影响
mergeCharacters分配number → characterTextCatalog/shotCharacterContext传number → shot-characters验证number → prepareContent按number反查ID → bindingNumbers再次把ID转number。去掉整条往返转换；正式绑定已有ID，无需改已有绑定。
图谱：mergeCharacters、shotTextInputs上游风险CRITICAL，涉及提取、逐镜与依赖；SQLiteStore影响LOW。

## 改动
- shared/models、collection-identity、project_contract：移除角色服装编号。
- shot-text-inputs、node-dependencies、node-inputs、content、shot-characters：直接传递/验证ID，移除旧转换。
- task_contract：删除被替代的通用编号转换。
- client与提示词：ID展示及契约统一。
- sqlite-store/schema及迁移：v19显式迁移，保留历史。
- 对应测试及业务文档同步。

## 验证
先记录完整测试基线，再执行改后测试、迁移与成片链定向检查；差异检查和图谱更新。运行实例无活动任务时备份数据库并重启验证迁移。

## 验证结果
AC-1至AC-5通过。全量基线479项467通过12失败0取消；修改后481项469通过12失败0取消，无新增失败。最后ID投影调整的相关25项全通过。v18副本迁移及正式重启迁移v19成功；ID、角色资料、图片、视频、绑定及任务历史与备份逐项核对，完整性和JSON镜像检查通过。差异检查通过，详情见实施记录。
