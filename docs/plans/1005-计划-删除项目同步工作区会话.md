# 删除项目同步工作区会话

- 类型：Bug 修复，完整流程
- 目标：删除项目时删除其 Harness 工作区，仅当删除当前会话关联项目时打开新的无工作区、无项目关联会话。
- 非目标：不删除旧会话记录，不删除其他工作区，不改删除剧集行为。

## 验收标准与调研结论
| AC | 输入/状态 → 可观测结果 | 状态 | 依据 |
|---|---|---|---|
| AC-1 | 删除项目 → 对应 workspaceId 注册同步删除，其他工作区保留 | 未验收 | opProjectDelete 目前仅 storedProjects.remove |
| AC-2 | 删除当前会话关联项目成功 → 新 sessionId，无 workspaceId/项目关联，面板进入新会话 | 未验收 | panel-routes 仅返回 deleted；bridge 仅 follow 原会话 |
| AC-3 | 工作区删除失败 → 不删除项目、不新建会话；工作区已不存在可继续删除 | 未验收 | Harness workspaceController.delete 提供 workspace/not-found 错误 |
| AC-4 | 删除剧集或取消删除 → 不删除工作区、不切会话；旧会话记录保留 | 未验收 | 公共删除入口需区分 action |

## 调用链与证据
项目概要/片库删除按钮 → bridge.perform → POST /turn → opProjectDelete → projectStore.remove。
Harness workspace-controller.commands.delete 仅注销工作区，保留会话。session-controller.commands.create({}) 不 attach 工作区；省略 workspaceId 使用默认 cwd，但不选择工作区。
面板 enterWorkspace 通过 dsh.sessions.current 设置新 sessionId 后 reload，复用该路径。
GitNexus status/query/context/impact 已执行，动态 HTTP 和前端回调以源码补查。

## 改动
1. operation-project-delete + workspace-links：清理项目对应工作区和会话项目选择文件，保留会话本身 → AC-1/3/4。
2. panel-routes：仅删除当前会话关联项目成功后 create({})，响应带 sessionId、workspace:null → AC-2/4。
3. chat-bridge、panel-app：传递删除响应，复用 enterWorkspace 切换新会话 → AC-2。
4. delete-content/workspace-links/面板测试覆盖成功、失败与原会话保留，更新开发指引 → 全部 AC。

## 用户补充
删除非当前会话关联项目不创建或切换会话。HTTP、planTasks、executeTask 的绑定校验允许人在面板删除其他项目，其他修改仍须绑定；前端请求返回时若用户已切会话，不抢回新会话。补测关联/其他/未关联三种会话状态。
