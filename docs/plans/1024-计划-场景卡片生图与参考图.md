# 场景卡片生图与参考图

- 类型：完整流程；新增独立scene_image服务/执行器、面板与接口。
- 目标：每张场景卡片展示生图要求、可上传/移除参考图、结果图及生成按钮；参考图和结果图同排，参考图明显更小。
- 非目标：自动对用户项目调用真实模型、改场景提取内容、修改宿主或公共包、无检查地重启。

## 验收标准
| AC | 输入/状态 → 结果 |
|---|---|
| AC-1 | 有场景 → 卡片内要求、参考图和结果图同排（参考图72px、结果图220px）、生成/重新生成；无图有小占位 |
| AC-2 | 要求或PNG/JPEG/WebP参考图 → 保存到对应scene资产；刷新可恢复，生成实际请求含要求和该参考图；无参考正常生成 |
| AC-3 | 排队/执行/失败 → 可见状态与停止原因；同项目互斥、连点去重；失败保留旧图及资料 |
| AC-4 | 场景/要求/参考图在执行中变化、项目删除或切会话 → 拒绝迟到覆盖；只写本场景图，不影响人物/其他场景 |
| AC-5 | 历史/会话/轮询 → 记录独立scene_image任务、当次输入/结果和终态；图片鉴权且限定项目目录 |
| AC-6 | 非法参考、过大输入、错误会话归属 → 提交前拒绝，不任意读取路径或外部地址 |

## 证据与影响
scene_image已有规则和image_generation资产字段，但缺Service/Executor/面板，scene_extraction.state负责按scene_id初始化资产。costume_image已有modelClient.generateImage、任务记录、PNG保存及会话投影可参照。参考字段目前为字符串，可使用受限data URL保存，生成要求使用该资产node_state.opinion，不增加顶层项目字段。场景图画幅采用项目basic_info.aspect_ratio。
GitNexus已status、更新索引、query、image服务impact：CRITICAL（79影响节点、157流程），已向用户提示。动态UI回调/资产状态需源码补查；UNKNOWN不视作无影响。保持独立场景执行器，不改定妆照行为。

## 改动
1. scene_image/state.js、service.js、executor.js：选择scene资产、指纹/输入校验、保存要求与参考、独立生成及图片安全读取。
2. scene_image/ui/panel/index.js：每场景要求、上传/移除参考、双图同行、生成、状态/错误及草稿与请求ID隔离。
3. scene_extraction/ui/panel/index.js：挂载场景图面板，文本操作与图像任务互斥。
4. index.js、harness_server/project_routes.js、client_assets.js：组装服务、生成/输入/图片接口、显式静态资源登记。
5. workbench/project-overview/project-production：请求、执行状态和场景图回调透传；项目Service/执行状态同步支持scene_image终态。
6. scene_image/ui/conversation、注册/历史/报告：当次输入及图片结果，失败重生成入口和图片资产结果引用。
7. CSS、开发方向、测试：参考72px、结果220px，同排自然尺寸；Mock模型和harness-http覆盖全流程；不进行真实模型调用。
