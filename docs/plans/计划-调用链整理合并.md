# 调用链整理合并

- 类型：重构
- 目标：按实际函数调用链集中同一职责，消除纯透传封装和中转导出，让入口到业务实现的路径直接可读。
- 非目标：不修改业务行为、接口/存储格式、权限、门禁、任务状态、提示词正文或模型请求协议。
- 整理原则：按用户要求整体整理，不以最小改动或最少文件为约束；保留确有职责的队列、执行上下文、任务步骤、模型和领域操作边界。

## 调用链与证据

- 面板 panel-routes / 会话工具 → task-manager 或 runOperation → executeOperation → services → 各 store；结束经 releaseOperation → endExecution。
- runTextSteps → runTextRequest → askModel → completeChat；askModel 只解构 route 并转发，日志/快照/错误均在两端承担。
- 图片 prompt-interfaces → part/pencil interface → Model；视频调用方 → video interface → FilmModel；三个 interface 无独立赋值/校验。
- GitNexus 索引有效。context 与源码确认 services 和 askModel 各只有一个直接调用方；impact：askModel 13 个上游，services 4 个上游，均 high；其余入口按 impact 日志及 rg 补查动态注册/测试。
- 失败分支须保留：接口失败回退、剧情重新生成不恢复、权限/归属拒绝、任务/步骤收尾、异步图片视频释放、嵌套任务共用锁和记录。
