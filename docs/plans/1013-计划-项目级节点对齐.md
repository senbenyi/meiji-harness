# 项目级节点对齐开发计划

- 类型：跨模块重构与流程修复，执行时采用完整开发流程。
- 目标：以《制作工作流.md》为入口，使五个项目级节点的 Model、前置检查、生成、审核、保存、派生任务及面板/会话入口遵循同一份文档契约。
- 当前阶段：代码、迁移与自动化验证已实施；真实文本接口返回 HTTP 502，完整真实链路尚未通过。
- 调研基线：2026-10-13，分支 `meiji4`，提交 `e733fe8ea932a7a3af41e2b49cf39b628d772699`。实施前重查工作区差异，本文行号为此基线的取证位置。
- 非目标：不开发 ComfyUI；不恢复剧本生成、自由创作或本集资产；不重写故事大纲、镜头表、逐镜提示词、视频和合片规则；不修改上游 Harness；不删除用户项目和历史任务。

模型返回结构和持久化字段分开处理。比如拆分的 AI 返回仍使用 dots 规定的中文切点字段，程序映射到英文 `episodes[]`；不能因为 Model 使用英文而擅自改 AI 返回结构。镜头表返回以对应 dots 为准，本计划不改其规格。

### 1.2 本次节点

| 节点 | business_type | 目标和保存位置 | 编组 |
|---|---|---|---|
| 项目摘要 | `project-summary` | 项目 → `project_summary` | 独立提交，持久化为 `single` 组；不加入主路径多任务组 |
| 提取剧集 | `script-split` | 项目 → 审核通过后替换 `episodes[]`；没有自身持久化节点 | 拆分和派生的各集摘要放在同一 `workflow` 组 |
| 剧本重要角色 | `project-characters` | 项目 → `character_library` | 人物提取及派生图片组成 `workflow` 组 |
| 角色图 | `character-image` | 角色 → `character_image` | 可独立操作；提取人物时派生到原组 |
| 角色定妆照 | `costume-image` | 角色下对应的 `costume_images[]` 条目 | 每套明确服装一任务；空服装一任务；排在该角色图之后 |

保留任务组—任务—步骤三级结构。一个节点的一次执行对应一个任务，修订和复审属于该任务的多个步骤；重新生成或手动重试创建新任务，旧终态不改写。工作流所说项目摘要“不组成任务组”，按其独立业务按钮理解；持久化仍遵循 step_model 的“独立操作默认 single 组”，不创建无父组任务。

本次对剧集摘要只做拆分后的派生、定位、同组排序和必要字段接入，不重写其业务规则。共享项目结构涉及剧集/镜头的调用方必须同步字段访问与状态访问，属于契约贯通；不借此改变这些节点的生成规则。

## 四、逐节点对齐方案

### 4.1 项目摘要

- **前置**：完整 `script.body` 可用。项目摘要不作为拆分、人物或后续制作的前置。
- **生成**：返回纯文本，按对应 dots/YAML 生成摘要；不强行套 JSON 外壳。
- **审核**：无程序业务审核；执行 AI 审核，返回结构严格使用本节点 dots。基础返回类型/解析错误仍按 failed 处理。
- **修订**：最多修订 2 次。修订模板必须收到本轮摘要、审核原因及用户补充意见；完全重新生成与带意见修改使用各自正确的材料。
- **保存**：正文写 `project_summary.body`，记录 `script_version`。审核耗尽保留正文及 rejected 原因；只有通过才记录新的依赖 hash。无下游传播。
- **改动位置**：`text-handler.js`、`content.js`、`handler-registry.js`、`project-summary-*.yaml`、摘要面板字段读取。

### 4.2 提取剧集

- **前置**：完整剧本、有效参考单集时长；替换剧集前按现有保护检查未结束的剧集任务。
- **生成**：复用编号原文算法，AI 只返回 dots 定义的 `序号/起始段落/结束段落/预估时长秒`；不生成剧情正文。
- **程序审核**：单独记录 review 步骤，检查连续覆盖、无遗漏、无重叠、顺序和拼接原文一致。复用 `buildSplit` 核心算法，不重写已有无损拼接。
- **AI 审核**：没有，不发审核模型请求。该节点误差时长为“无”；不增加参考时长 ±30 秒或 ±20% 的程序拒绝门槛，生成提示中的约两成估算沿用该节点 dots。
- **修订**：程序不通过时使用刚返回的切点候选和原因，最多修订 2 次；再次提交未通过拆分时，从任务历史取最后候选和原因，不能拿旧正式剧集冒充失败候选。
- **保存**：通过后映射为 `episodes[].sequence/duration_seconds/plot`，整体替换剧集；同事务追加每集一个 `episode-summary` 任务到原 workflow 组。未通过不替换剧集，不虚构项目 `node_state`，候选及原因仅保存在步骤/任务历史。
- **旁路约束**：剧集摘要的成功状态不成为人物、大纲等主路径前置。保持项目内串行，不为“不挡主路径”引入并行执行器；失败组停止与显式队列暂停分别验证。
- **改动位置**：`script-split.js`、`text-handler.js`、`content.js`、`task-plan.js`、`task-service.js`、`script-split-*.yaml`、拆分卡片和摘要派生接入。

### 4.3 剧本重要角色

- **前置**：本节点唯一业务前置为 `script.body` 非空，目标归属和任务互斥仍由公共检查处理。已分集只决定主流程呈现顺序，不另加“拆分成功”或“摘要通过”的执行门槛。
- **生成**：接收英文 `characters` 增量，只含新增/变更；空数组是合法无变更。按姓名关联已有角色，同人保留 ID/编号和未参与本次变更的资料。
- **字段**：落实 `name/position/age_range/body_type/hairstyle/signature_props/immutable_traits`；服装为 `name/color/material/props`。没有剧本服装描述则 `costumes: []`，不臆造衣服，不重复保存角色级服装颜色。
- **审核**：无程序业务审核；AI 只审核本次变更，删除 YAML 中对声线、编号、默认着装等越权要求；不能因旧库已有角色未再次返回就判漏人。
- **修订**：最多 2 次，传入本轮增量候选与原因；目录用于上下文，不能替代待修改内容。
- **保存**：最终通过或 rejected 的本轮增量均写正式角色库；未通过只保存内容/状态/原因，不更新 hash、不标下游过期、不派生图片。通过后再统一处理依赖及派生。
- **派生**：覆盖流程中的角色及其图片任务，不再只依赖 `new_ids`。每个角色一个角色图任务，定妆照数量为 `max(1, costumes.length)`；一键重新生成按整组含义重建任务，继续按原组停点处理，不能混用“新角色才生成”的旧策略。
- **身份边界**：AI 增量未提供改名/删除语义；不按未返回推断删除，不猜测不同姓名是同人。保留独立人工编辑/删除入口及引用校验。
- **改动位置**：`collection-identity.js`、`content.js`、`text-handler.js`、`project-characters-*.yaml`、角色及服装 Model/校验、派生和人物界面。

### 4.4 角色图

- **前置**：目标角色存在，人物资料满足 dots；用户参考图可选，无参考图可以执行。
- **生成**：一次一张，生成规则保持该节点 dots；有参考图时用于人物面相，体型等按人物资料。重生成/带意见修改不能隐式把旧产出替换成用户参考图。
- **审核与修订**：无程序业务审核、无 AI 审核，重试轮次 0；文件可读性、响应协议检查仍须执行，失败保留旧图。
- **保存**：写 `character_image.address` 与 `node_state`，成功后记录依赖 hash。依赖包括实际使用的人物字段和可选参考图；过期传播指向本角色定妆照及实际依赖的多模态节点。
- **改动位置**：`media-handler.js`、`precheck.js`、`node-dependencies.js`、`character-image-*.yaml`、参考图及角色图 UI。

### 4.5 角色定妆照

- **前置**：角色存在，角色图已有效生成。有明确服装则验证属于该角色；无明确服装且 `costumes: []` 时允许未绑定定妆照。
- **任务定位建议**：有服装沿用 `target_id=co_id`；空服装使用 `target_id=c_id`，由 `business_type=costume-image` 区分角色图。解析到所属角色的 `costume_images`，用 `costume_id=co_id` 或 `""` 唯一命中。新提交和执行前置仅在空服装时允许角色 ID 目标，校验归属和唯一性；不造假服装、不引入图片实体 ID、不用列表下标定位。此方案沿用现有字段，是本次实施设计，需同步写入节点定位文档。
- **生成**：无论首次、重生成还是带意见修改，固定且唯一的图片参考都是该角色的角色图。明确服装遵循其资料；空服装按人物其他资料和角色图生成，不编造服装字段、不将图中衣服反写角色资料。
- **审核与修订**：无程序业务审核、无 AI 审核，重试轮次 0；一次请求一张，拒绝 `n > 1`，不拆成多次隐式请求。
- **保存**：只写本任务对应 `costume_images[]` 一条；空 `costume_id` 条目唯一。成功 hash 包含实际人物资料、明确服装资料（若有）、角色图地址及依赖 hash；变化传播到实际使用该图的下游。
- **已有图片保留**：角色以后新增明确服装时，原未绑定图仍留在 `costume_images[]` 只读展示，不进入新的生成组或默认图片选择。`max(1, costumes.length)` 约束当前流程的任务数，不用它裁剪历史图片数组。历史终态仍可读取原空条目或直接展示执行记录；不得因当前服装不再为空而让旧任务校验失败，不改旧 target、终态、prompt/result。
- **改动位置**：`node-definitions.js`、`task_contract.js`、`precheck.js`、`media-handler.js`、`content.js`、`node-dependencies.js`、`costume-image-*.yaml`、角色/服装卡片与会话命令翻译。

## 五、公共契约方案

### 5.1 状态、审核及保存

在代码节点定义中写定本节点是否有程序审核、是否有 AI 审核及最多修订次数；不把 dev_docs 当运行时规则数据库，不另建通用工作流平台。保留 `review` 步骤种类，程序审核和 AI 审核分别建步骤、用名称区分，并确保执行时可确定调用哪个审核器。

程序与 AI 审核共用同一个修订计数，轮次为初次 0、修订 1/2。未通过审核步骤标为 `rejected` 并保存原因；有余量才追加 revise 和本节点适用的 review。接口、解析和不可用结构错误为 failed，不混作业务审核拒绝。

将“保存候选内容”和“通过后的 hash/依赖传播/派生任务”明确分开。节点、任务、步骤及派生的持久化变化使用现有事务入口一次提交。不得再由 `commitContent` 无条件写 hash 或提前标下游过期。重新提交 rejected 节点时，服务端把原因写入新任务 opinion 并提供给模型，用户附加意见合并保留；不能只靠面板默认填入。

### 5.2 任务组、继续与互斥

- 组字段按 step_model 收敛：移除持久化的 `opinion`、`continued_from_group_id`，状态和原因只按组内任务计算；组创建时保存名称，后续改名不重写历史。
- 派生和组内排序在同事务完成。上游未通过/失败不派生；失败、未通过或取消使本组尚未执行项作废，恢复其入队前 `previous_node_state`。
- 继续从原组停下的任务起新建组，`group_seq` 从 1 开始；已完成项不重做；不存来源组字段。停点未通过则把对应节点原因写入该新任务；拆分例外从原任务历史取原因。后续任务不能继承不属于自己的意见。
- 同 request_id 重复提交返回原结果；其他组请求如目标重叠则整组拒绝，不先建半个组，也不借用其他请求的旧任务。人物派生的目标数量在生成前未知，计划展开和目标冲突检查必须与写回原子执行，冲突原因可追踪。
- 保留项目串行、取消信号、晚到结果保护、重启旧任务 superseded 和队列恢复机制；业务依赖不等于“当前队列是否暂停”。摘要不作为其他节点成功前置。

### 5.3 字段与持久化

统一使用 `node_state.status/reason/dependency_hash` 和英文内容字段，`previous_node_state` 使用 `{ status, reason }`。已被新设计替代的中文运行时分支与兜底在实际调用方同步替换，不增加中英双轨适配器。

当前实际存储为 SQLite `projects.data_json` 加任务组/任务/步骤表；文档的“项目 JSON”指该结构。本次不切换存储介质。新增明确 schema 版本迁移，接入并审查已有项目转换函数，同步组列、步骤 rejected 枚举及节点快照结构。迁移仅处理支持的 SQLite 版本；保留项目、角色、服装和任务 ID、媒体地址、终态及执行时 prompt/result，不重新生成历史。

迁移前备份，单事务校验后升级；任何失败回滚，第二次启动不重复迁移。不支持的旧目录遵循现有拒绝读取规则，不能在启动时清理用户数据。一次性迁移代码可以识别旧字段，正常读写路径只支持完成迁移后的结构。

### 5.4 面板与会话

两个入口继续进入同一 TaskService。面板从项目节点读取内容/状态，历史从任务读取；拆分无持久化节点，按拆分任务历史展示候选和原因。无内容显示 AI生成、有内容显示重新生成、rejected 另有按意见修订；queued/running 隐藏生成类按钮。人工编辑/媒体导入、人工放行、取消、排队开始/移除保留其规定权限和结构校验。

项目卡片标题下同一操作行呈现生成类按钮和任务历史；图片按新位置显示，空服装也有一张定妆照卡片。提交被前置或冲突阻断时显示具体原因，不能静默失败。程序/AI 审核历史分步展示，未通过或失败默认展开，并可查看本次提示词与 HTTP 记录。
