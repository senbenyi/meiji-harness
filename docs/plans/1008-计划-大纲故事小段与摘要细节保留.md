# 故事小段直接生成与展示摘要

- 类型：完整流程重构，涉及数据协议、存储、生成审核、任务依赖和 UI。
- 目标：剧本模式直接提取本集故事小段，自由模式直接按创作方向创作；摘要由大纲提取，仅用于展示。
- 非目标：改动成片模型、自动重做已完成视频、重写人物图片规则。
- 用户决定：人工编辑后的故事小段为准，可覆盖原来源；最新要求替代此前摘要作为上游的方案。

## 调用链与证据

新增剧集/剧情生成 → run-service/planRun → generate outline → review outline → 可选摘要旁支；镜头主线只依赖通过的大纲 → 镜头表 → 每秒指令。
人工编辑 → operation-outline-edit → 保存 manual 来源 → 审核 → 提取最新展示摘要。
摘要 → EpisodeSummaryModel（唯一来源为大纲）→ 单次 generateStep → 保存 outlineRevision；不触发创作级联。

核心文件：`meiji/shared/story-outline.js`、`generation-gates.js`、`run-planner.js`、`pipeline-cascade.js`、`server/prompts/models/story-model.js`、`episode-summary-model.js`、`server/flow/tasks/text/task-summary.js`、`client/flow-view.js`。
图谱 impact：门禁、任务规划、跨集提示与共享存储多为 HIGH/CRITICAL，编辑前已提示风险；动态 taskRegistry 和技能载入以源码补查 UNKNOWN。摘要旁支造成主线末端判定变化，修正 tailSteps 仅计算主线后继，回归确认暂停任务可追加修改。

## 改动

1. 大纲协议和生成/审核 skill：七栏目改为编号小段，保留本集所选剧本全部细节；人工内容优先 → AC-1/2/3/4。
2. 大纲与镜头提示词：移除所有展示摘要，使用方向/剧本、完整前集故事和最新大纲 → AC-1/2/3/7。
3. 门禁与 Run：从故事生成开始，取消摘要和项目摘要前置；摘要为 optional/branch 旁支 → AC-5。
4. 摘要 Model/task：只提取大纲；独立重试；版本核对；不审核、不回写、不清理制作内容 → AC-5。
5. UI 和剧集存储：仅时长及要求，去除摘要 Tab/编辑，新增只读摘要区 → AC-6。
6. 跨集版本、显式回写和旧数据迁移 → AC-7/8。
7. 同步业务文档及有意义的协议、来源隔离、失败路径和集成测试 → 全部 AC。
