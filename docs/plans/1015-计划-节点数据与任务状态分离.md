# 节点数据与任务状态分离
- 类型：完整流程，状态契约、结算、UI和持久化迁移。
- 目标：节点数据四态；最新关联任务独立第二排；失败不清除未通过reason。
- 非目标：不重启、不刷新、不修改生产项目；任务历史和已有正文保留。
## 验收标准
AC-1：开始/失败/取消不覆盖节点数据状态和reason，成功/审核未通过保存新数据后更新。
AC-2：第一排数据状态+按钮，第二排最新任务状态（失败拼接原因），第三排意见，第四排非空未通过原因；从未执行隐藏第二排。
AC-3：当前任务优先，否则数据库快照中该节点最新历史任务；不同节点不串状态。
AC-4：v15显式迁移旧运行/失败/取消数据态，依据原状态快照、内容、历史审核和依赖指纹恢复四态；保留任务历史。
## 影响
TaskService/SQLiteStore LOW；setNodeState HIGH；validateProject/renderTaskPanel/renderOverview CRITICAL，属于共享契约与公共渲染，执行全量基线与回归及迁移/DOM验证。
## 改动

server/data：v15数据态迁移，旧版本升级验证同步。
client/task-panel.js/project-ui.js：统一最新任务状态展示，冻结依据当前任务，原未通过原因独立保留。
相关测试与工作流文档同步；历史快照仍保留历史状态语义，fail_message仅为既有格式字段，新数据态保持空，失败原因只在任务end_reason。
