# 主 Agent 与六类制作 subagent

> 状态：实施中；用户已确认职责方案并要求执行。基线：2026-10-07 当前工作区。

主 Agent 是项目调度入口；专业 subagent 只处理分派范围，提交结构化结果。领域命令负责校验、落库和版本关联，ProductionWorker 负责媒体任务的租约、执行、检查与恢复。

| subagent | 输入与产物 | 边界 |
| --- | --- | --- |
| 剧情 story | 原文 → 事件、人物事实、场景事实、故事分析 | 不生成视觉资产或正式镜头 |
| 角色 assets | 故事设定 → 角色与场景视觉设定、参考图制作方案 | 不改人物身份、故事或分集 |
| 剧本 script | 故事、分集 → 正式剧本 | 不生成镜头表 |
| 分镜 storyboard | 正式剧本、视觉设定 → 镜头表与预览制作方案 | 不改正式剧本 |
| 镜头 shot | 已批准镜头、参考图 → 视频制作方案 | 不改剧情、对白、时长或资产绑定 |
| 成片 delivery | 已批准视频与顺序 → 合成与交付方案 | 不漏镜、不自行改变剧本顺序 |

## 实施文件与验证

- `lib/agents/`：角色定义、固定 workflow、媒体方案校验；所有实际子代理通过官方 workflow 创建并受现有工具隔离限制。
- `lib/script/novel-production.js`、`rework.js`、`contracts.js`、`tools.js`：拆分视觉设定、剧本草稿、分镜任务，沿用持久化任务与 Proposal 提交路径。
- `lib/domain/commands/index.js`：新增视觉设定与正式剧本 Proposal 的应用；分镜应用核对剧本版本，不允许跨阶段改写。
- `lib/domain/production.js`、`lib/domain/read-models.js`：记录和展示任务责任角色；保留领域状态为事实来源。
- `lib/production/worker.js`、`lib/index.js`：接入后台专业代理方案、检查点和实际媒体执行；不让子代理直接调用项目写工具或递归创建代理。
- `lib/guidance.js`、当前使用说明：主 Agent 的统一调度与返工规则。
- 测试覆盖角色路由、越权/缺失结果、剧本与镜头分离、版本失效、失败恢复、媒体检查点复用、旧版 Proposal 兼容；运行聚焦测试、项目测试、smoke 和 diff 检查。

## 兼容与验收边界

旧 `episode_script` Proposal 和媒体任务继续可读；新整书文本任务采用独立版本命名，避免复用旧“剧本与镜头混合”检查点。已有工作区改动保持原样。代理方案与媒体执行分别记录检查点，恢复时校验输入签名。

本轮不自动重跑用户现有项目，不发起计费模型调用或真实 GPU 生成。静态、单元、模拟集成结果与真实模型/媒体验证分别报告；功能完成不等同于已完成视觉质量验收。
