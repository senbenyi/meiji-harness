# 分镜沿用人物定妆服装

- 类型：完整流程，规则、校验与模型输入调整。
- 目标：未描述换装时沿用人物已有定妆服装，不因服装story_segment_ids而缺失。
- 非目标：新增服装、生成照片、修改剧情或自动重跑失败任务。

## 验收标准与改动
| AC | 输入 → 结果 | 改动/验证 |
|---|---|---|
| AC-1 | 人物服装限定其他段，但当前无换装描述 → 可沿用 | state.js取消个人服装段硬限制，保留ID归属校验，团队不变 |
| AC-2 | 空服装ID → 继承前镜/唯一有效定妆照关联/唯一服装，不盲选多套 | state.js归一化；多套仍需模型明确选择，错误含镜头人物 |
| AC-3 | 模型读取已有定妆对应关系 → 明确引用服装 | Service输入character_extraction含characters及costume_references（已生成照片对应ID，不传图片像素）；指纹覆盖引用事实，历史展示保留 |
| AC-4 | 未描述服装 → 生成/审核/修订规则一致 | 默认人物/分镜规则与字段说明同步，实际项目私有规则经ProjectManager同步，保留历史任务和结果 |
| AC-5 | 错误人物或服装ID → 仍拒绝；全部流程回归通过 | 更新语义断言与补充分镜继承/多套/已有失败候选回放测试 |

## 证据与边界
实际失败任务有15镜、10处空服装；三人物只有segment_003礼服但在001/002出镜。旧程序有目录就强制ID且限制适用段，在AI审核前失败。当前人物私有规则同时含“需合理补全”与“无依据不添加、有一套不加日常服”，需同步移除冲突。GitNexus校验函数影响HIGH（6节点、3流程）；实际调用由Executor/Service补查。基线278通过、0失败、0取消。

## 验证结果
新增2组测试，分镜聚焦13通过；全量280通过、0失败、0取消（/tmp/costume-inherit-full.log）。实际失败响应只读回放：15镜通过校验，10处空服装正确落实既有ID，未写回旧候选。当前项目规则经ProjectManager同步并先备份，人物/服装/定妆照/历史未改；无真实模型调用。diff检查与最终图谱/重启结果见实施记录。
