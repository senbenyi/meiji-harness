# 架构重构

- 类型：重构
- 目标：收敛 Harness 依赖、理清分层、拆分 `actions.js`、拆分项目数据、引入全局任务队列，用户可见行为不变。
- 调研：`docs/research/调研-架构重构.md`

## 已定决策
1. 服务关闭与重启：所有进行中任务一律取消（本地标记取消，已提交远端任务尽力发送取消请求，失败如实记录），重启后不续查、不自动恢复。（用户决定）
2. 数据拆分：做。领域模型 `schemaVersion` 保持 2；新增存储布局版本 `layout: 2`，拆分封装在 `projectStore` 内部，对外 `read/save` 不变。剧集文件写新版本、最后原子替换索引，保证多文件保存原子性。旧布局由迁移脚本转换（先完整备份），运行时拒绝旧布局并提示执行脚本。
3. 失败测试：以当前代码为准（近期提交代表最新预期），测试过期则更新测试；代码明显缺陷才修代码；逐项记录在实施记录。
4. Harness 接口：`ctx.workspaceRegistry` 公开提供 `list()`（含 `sessionIds`）、`get(id)`、`archivedSessionIds`，替换直接读取 `storages/workspace.json`。会话日志仍使用已登记的 `command/run`、`command/done` 事件（不进入模型上下文）；为使仅含日志的会话不被视为空白而写入的 `turn/start`/`turn/end` 保留，但收进适配层。

## 约束
- 各阶段独立提交，按顺序执行：0 → 1 → 2 → 3 → 4 → 5 → 6；阶段 7 可随时插入。
- 每阶段结束 `npm test` 全部通过（阶段 0 之后基线为全绿），并在 Harness 中人工打开面板、生成一次文本确认无回归。
- 不改制作流程、门禁顺序、前端轮询与 skill 内容。
