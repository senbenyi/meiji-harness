# 视频类型与尾帧任务接入

- 类型：完整流程，跨任务、媒体、依赖和界面。
- 目标：执行时按已确认绑定选择文生/首尾帧/多模态，程序编排后生成视频，并在同一任务保存视频与尾帧。
- 已确认：有角色缺定妆照时等待补图，不降级；本轮不迁移、不自动清空新产生的数据。
- 非目标：角色子代理调度、模型/协议扩展。

## 改动与验收

| AC | 改动位置 | 输入→结果 |
|---|---|---|
| V1 | shared/video-inputs.js、TaskService、precheck | 有角色→多模态；无人首镜→文生；无人后镜→首尾帧。等待上游实际完成再决定，继续不复制旧类型分支 |
| V2 | node-definitions、video-prompt-handler、HTTP videoRequest | 两个程序编排节点复用已有 Model；不调用文本模型，输出保存；文生不创建编排任务 |
| V3 | node-dependencies、UI | 仅首尾帧依赖前尾帧，仅多模态依赖实际图片；镜头重排、图片和类型变更传播正确，界面显示类型/编排 |
| V4 | task-plan、media-handler、handler-registry、content | 每轮视频生成后文件/时长/截帧校验，同任务可见后处理步骤；视频尾帧原子提交。失败取消保留旧配对 |
| V5 | node-state、TaskService | 视频实测4–15秒且计划±5秒，最多两次修订，使用本轮意见；耗尽保存最后配对为rejected，保留成功hash。文件错误不重试付费生成 |
| V6 | 节点目录/命令/编组/UI | 移除独立tail任务，保留last_frame产物；导入视频同样截帧且无需AI文本；单镜/整集/继续唯一合片 |

## 证据与风险

现有 HTTP 三模式参数已有白名单；任务层仍统一读取尾帧并独立执行tail。已读实际 TaskService→precheck→handler→commit 链路。共享保存、校验、依赖、面板为 HIGH/CRITICAL，已说明。模型已有两种程序编排字段，无需存储结构迁移。动态节点目录及SQL调用另以源码核对。
