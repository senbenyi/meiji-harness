# 统一 60 分钟超时

- 类型：完整流程，跨 App、llm-server、Ollama 的配置与请求路径调整。
- 目标：将上轮列出的推理、HTTP 响应等待、GPU 查询、模型加载和驻留限制统一为 60 分钟。
- 非目标：修改并发、重试次数、断连取消行为、5 秒 GPU 轮询间隔。

## 验收标准与调研结论
| AC | 输入/状态 → 可观测结果 | 依据 |
|---|---|---|
| AC-1 | 推理请求 → 显式总超时及底层响应头/响应体超时均 3600000ms | sendChat 为15分钟，llm-server env为900000，Node Undici默认300000 |
| AC-2 | GPU请求 → 浏览器、代理、SSH采样均60分钟 | 现为4800/4500/4000ms；轮询5秒不变且不重叠 |
| AC-3 | Ollama重启后 → LOAD_TIMEOUT与KEEP_ALIVE均60m | 当前0.40.3，systemd服务；LOAD_TIMEOUT未设，KEEP_ALIVE=30m |
| AC-4 | 客户端取消/超时 → 上游中止、队列释放 | 保持现有AbortSignal链与服务端取消测试 |

## 调用链与证据
App sendChat → llm-server队列 → fetch → Ollama。队列内不计llm-server上游超时，但App总时限包含排队。
GitNexus impact sendChat LOW（elysium/llm-server complete调用），mountGpuStatus LOW（workbench.mount调用）。HTTP客户端配置仅覆盖响应等待，不替换宿主代理策略。
