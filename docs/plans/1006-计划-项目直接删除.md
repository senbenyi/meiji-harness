# 项目直接删除

- 类型：Bug 修复 / 行为调整
- 目标：删除项目时不受任务或项目占用状态影响，确认后直接删除项目数据并清理对应工作区。
- 非目标：不改变删除剧集时的任务占用保护。

## 验收标准

| AC | 输入/状态 → 可观测结果 | 状态 | 依据 |
|---|---|---|---|
| AC-1 | 项目存在运行中/暂停任务 → 点击删除项目可操作，不因项目忙碌而禁用 | 已确认 | 项目删除按钮不再按项目忙碌状态禁用 |
| AC-2 | 项目存在运行中/暂停任务 → 确认删除项目 → 不被 HTTP 忙碌检查拒绝 | 已确认 | HTTP 忙碌检查仅保留 episode-delete |
| AC-3 | 项目存在即时占用 → 确认删除项目 → 删除操作可取得执行机会并清理项目及对应工作区 | 已确认 | project-delete 跳过即时占用锁；删除工作区的既有操作测试通过 |
| AC-4 | 删除剧集且存在运行中/暂停任务 → 仍拒绝删除 | 已确认 | 本次仅对 project-delete 放宽，保留 episode-delete 原检查 |

## 改动

### 阶段 1：项目删除绕过状态保护

1. `meiji/client/project-overview-view.js` — 项目删除按钮不再按项目忙碌状态禁用，并更新确认文案说明会清理对应工作区 → AC-1。
2. `meiji/server/http/panel-routes.js` — project-delete 跳过任务/即时编辑状态检查，episode-delete 保持原检查 → AC-2、AC-4。
3. `meiji/server/flow/immediate-service.js` — project-delete 不参与项目占用锁，允许直接进入删除操作 → AC-3。
4. `meiji/tests/delete-content.test.js`、相关 UI/HTTP 测试 — 覆盖项目直接删除与剧集删除保护 → AC-1 至 AC-4。

验证：`node --test tests/delete-content.test.js tests/project-delete-navigation.test.js`、`git diff --check`。
