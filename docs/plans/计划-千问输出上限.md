# 千问输出上限

- 类型：Bug 修复
- 目标：提高千问单次输出和资料容量，避免 Segment JSON 被截断。
- 调研来源：`docs/research/调研-千问输出上限.md`

## 人工决策
无。服务端当前 `n_ctx=65536`，客户端先放开到训练上下文；超限时再改远端。

## 执行步骤

### 阶段 1：提高客户端上限
1. `harness/.dsh/settings.yaml` — 修改：`maxTokens` 4096 → 65536；`contextWindow` 65536 → 262144 → AC-1 AC-2
2. `harness/.dsh/.agent-presets/_base/agent.cordis.yml` — 修改：`maxBytes` 65536 → 1048576 → AC-3
3. `harness/.dsh/.agent-presets/elysium-standard/agent.cordis.yml` — 修改：同步 `maxBytes` → AC-3
4. `harness/tests/harness-settings.test.mjs` — 修改：锁定新的 maxTokens / contextWindow → AC-1 AC-2

验证：`node --test harness/tests/harness-settings.test.mjs` → AC-1 AC-2

### 阶段 2：同步运行配置
1. `~/.dsh/settings.yaml` 与 `~/.dsh/.agent-presets/` — 修改：安装脚本覆盖运行副本 → AC-4
2. 重启 Harness → AC-4

验证：读取 `~/.dsh/settings.yaml` 含 `maxTokens: 65536`；`/v1/models` 仍可达 → AC-4

## 验收标准
- AC-1：qwen3.8 `maxTokens` ≥ 65536。
- AC-2：`contextWindow` 为 262144。
- AC-3：创作预设 `maxBytes` > 65536。
- AC-4：本机运行配置已同步并重启。
