# 手动保存剧集摘要状态

- 类型：Bug 修复（实施中发现第二处根因，涉及 3 个文件，升为完整流程）
- 目标：手动新增或编辑剧集后，摘要状态显示「已通过」，并清除旧的未通过原因。
- 非目标：不新增状态枚举；不改 AI 生成摘要（episode-generate / episode-summary-draft）的自审逻辑；不改下游重置规则。

## 根因
`meiji/server/flow/operations/project-operations.js` `opEpisodeAdd`：新增或摘要/时长变化时强制写入 `summary.check.passed = null`、`summary.status = NOT_GENERATED`，前端 `stepRunLabel` 按状态显示「未生成」。
2. `meiji/server/data/content-records.js` `prepareContentRecords`：对所有 manualActions（含 episode-add/edit/source）在内容变化时把节点 check 重置为 passed:null、status 置为 not-generated。仅修第 1 处时测试仍得到 not-generated，由此发现。

## 验收标准
| AC | 输入/状态 → 可观测结果 |
|---|---|
| AC-1 | episode-add 保存摘要 → `summary.status === 'passed'`，`check.passed === true`，`check.failures` 为空 |
| AC-2 | episode-edit 修改摘要 → 同 AC-1 |
| AC-3 | 摘要原有未通过原因（check.passed=false、failures 非空）后手动保存（含内容未变）→ failures 清空，状态「已通过」 |
| AC-4 | `npm test` 不新增失败 |

## 待用户决定
无（用户选定：手动保存直接算通过，未通过原因直接删除）。

## 改动
1. `meiji/server/flow/operations/project-operations.js` `opEpisodeAdd` — 条件性写 NOT_GENERATED/passed:null → 每次手动保存都写 PASSED、`check = { passed: true, failures: [] }`、清 error；提示文案「之后会重新待审」改为下游已重置 → AC-1/2/3
2. `meiji/server/data/content-records.js` `prepareContentRecords` — manualActions 重置待审 → 对 key 为 `summary` 的目标豁免（摘要由 episode-add/edit 或 sourcePatch 以 passed:true 写入）；大纲、人物、场景、分镜等手动编辑仍重置待审 → AC-1/2
3. `meiji/tests/task-store.test.js` — 「manual summary saves a pending version」断言 passed null → true，并补充未通过原因被清除的断言 → AC-2/3；episode-add 断言 → AC-1

验证：`cd meiji && npm test` — 全部通过（基线 602 通过 0 失败）。
