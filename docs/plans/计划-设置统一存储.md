# 设置统一存储

- 类型：新功能
- 目标：将工作台设置页涉及的全部运行设置统一保存到 `$DSH_HOME/storages/elysium/config/settings.json`。
- 调研来源：`docs/research/调研-设置统一存储.md`

## 人工决策

无。按用户指定路径统一存储；项目、任务、素材、导演和日志不属于设置，不迁入。

## 执行步骤

### 阶段 1：建立统一设置 Store 与结构

1. `dsh-elysium/config/settings.json` → `config/defaults.json`、`src/utils/config.js:readSettings/resolveConfig` — 修改：将包内同名文件改名为只读初始化模板，运行配置路径固定解析到 `$ELYSIUM_HOME/config/settings.json` → AC-1、AC-4。
2. `dsh-elysium/src/servers/settings/store.js`（新增）— 新增：校验 version 1 统一结构，集中读取、分区 patch、独占锁、临时文件 rename、`0600` 权限与连接/选择分区 revision → AC-1～AC-5。
3. `dsh-elysium/src/servers/registry/store.js`、`src/servers/selection/store.js` — 修改：保留现有公开函数和 CAS 语义，底层改为读写统一 Store 的 `connections` 与 `selection` 分区 → AC-2～AC-4。
4. `dsh-elysium/src/servers/runtime/definitions.js`、`providers/bailian/config.js`、`providers/byteplus/config.js` — 修改：provider 能力仍由代码声明，用户配置和凭据改从统一 Store 的 `providers` 分区读取 → AC-2、AC-4、AC-5。

验证：新增统一 Store 单元测试，覆盖空文件初始化、严格 schema、`0600`、原子写、锁冲突、两个分区连续/并发 patch 不丢字段、revision 冲突 → AC-1～AC-5。

### 阶段 2：接通设置页完整读取与业务路由

1. `dsh-elysium/src/http/server-routes.js` — 修改：`models`、连接、模型选择、服务器登记/启停全部经统一 Store；响应继续只返回设置页所需摘要 → AC-2、AC-4、AC-5。
2. `dsh-elysium/src/servers/runtime/index.js`、`registry/resolve.js` — 修改：聊天模型/隧道、私有模型、服务器和三方模型均读取统一设置，保持私有优先、三方回退及历史任务快照规则 → AC-4。
3. `dsh-elysium/src/client/workbench/servers.js` — 核对并仅在接口字段必须调整时修改：界面仍为现有“设置”页，不新增未要求的控件 → AC-2、AC-5。

验证：更新 `server-panel.test.js`、`server-routes.test.js`、`server-switch.test.js`、`servers-config.test.js`、Bailian/BytePlus 集成测试，验证所有设置操作只改变统一文件且前端响应不含私密字段 → AC-2、AC-4、AC-5。

### 阶段 3：无损迁移与单写入源

1. `dsh-elysium/scripts/migrate-home.mjs` — 修改：从 `servers.json`、`selection.json`、`providers/*.json` 和默认模板合并生成统一设置；空目标文件视为未初始化；写入成功并复读校验后，将旧文件归档到 `runtime/migrations/<timestamp>/settings-sources/` → AC-1、AC-6。
2. `dsh-elysium/tests/home-migration.test.js`、`storage-layout.test.js`、`config.test.js`、`package.test.js` — 修改：验证字段无损、重复执行幂等、旧文件不再参与读取、目标权限、默认模板发布与新路径契约 → AC-1、AC-3、AC-6。
3. `dsh-elysium/README.md` — 修改：声明运行设置唯一文件、敏感权限、迁移方式与非设置数据边界 → AC-2、AC-6。

验证：在临时 DSH_HOME 运行迁移两次，比较迁移前来源字段与迁移后各分区；确认归档可恢复且运行期只写 `config/settings.json` → AC-1、AC-2、AC-6。

### 阶段 4：本机迁移与发布验证

1. 本机 `~/.dsh/storages/elysium/config/` — 执行迁移脚本；迁移前后只比较字段结构、非敏感值和文件哈希，不输出凭据；确认 `settings.json` 为 `0600`，旧源已归档 → AC-1、AC-3、AC-6。
2. 构建与打包 — 执行设置相关测试、`pnpm test`、`pnpm build`、`pnpm package:registry`、`git diff --check`；核对 registry 产物使用新默认模板与统一 Store → AC-7。

验证：重启本地 Harness 后读取设置页，依次验证聊天连接、私有视频选择、三方视频选择；确认接口结果、`settings.json` 分区变化和新任务路由一致，旧文件无新增写入 → AC-2、AC-4、AC-5、AC-7。

## 验收标准

- AC-1：首次加载时，空目标文件或无目标文件可从现有配置及包内默认值生成完整 version 1 设置。
- AC-2：所有设置页操作只更新 `config/settings.json`，不再写旧设置文件。
- AC-3：统一文件为 `0600` 且原子、加锁写入，分区 revision 与冲突语义不回退。
- AC-4：所有模型与连接路由从统一文件解析，业务优先级和历史任务行为不变。
- AC-5：浏览器与错误响应不暴露任何凭据和私密连接字段。
- AC-6：现有设置无损迁移，旧源可恢复归档且不再参与读取。
- AC-7：相关测试、完整测试、构建、打包及差异检查通过。

## 验证结果

- 阶段 1：通过。统一 Store、默认模板、`0600`、锁、原子写与分区 revision 测试通过。
- 阶段 2：代码验证通过。设置接口、provider、选择、路由及敏感字段边界测试通过；运行进程因未重启而未验收。
- 阶段 3：临时副本验证通过。本机旧源字段已完整进入 `settings.json`；真实旧文件归档被沙箱权限阻止。
- 阶段 4：170 项测试中 169 项通过，唯一失败为既有 worker 身份环境用例；构建、registry 打包、产物核对及 `git diff --check` 通过。Harness 重启因沙箱禁止写日志而跳过。
