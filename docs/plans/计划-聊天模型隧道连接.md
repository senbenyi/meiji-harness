# 聊天模型隧道连接

- 类型：新功能
- 目标：Harness 启动不建立 Qwen 隧道，改为在私有模型面板点击“连接/重新连接”时按需建立并验证。
- 调研来源：`docs/research/调研-聊天模型隧道连接.md`

## 人工决策

无。按钮中的“重新连接”定义为再次执行同一连接与模型检查：已健康的本功能 SSH 控制连接可复用，断开后则重建；不为“重新连接”强制中断健康隧道。

## 执行步骤

### 阶段 1：暴露聊天隧道连接接口

1. `dsh-elysium/src/servers/runtime/index.js:defaultTunnelAlias` — 修改：只返回默认隧道别名 → 同时提供不含 SSH 凭据/地址的默认聊天模型公开元数据，元数据从 provider definition 派生，不在核心路由硬编码 Qwen 连接参数 → AC-1、AC-2。
2. `dsh-elysium/src/http/server-routes.js:createServerHandler` — 修改：当前只有图片/视频模型选择接口 → `models` 返回聊天模型展示元数据，新增已认证的按需隧道连接动作；动作调用 `legacyTunnelBackend → checkBackend`，只在 SSH 隧道和 `/v1/models` 目标模型检查都成功后返回 `connected: true`，不写图片/视频选择 → AC-2、AC-3、AC-5。
3. `dsh-elysium/tests/server-routes.test.js` — 修改：无聊天隧道路由覆盖 → 验证未认证请求不触发连接、模型元数据不泄露连接参数、成功/失败返回及连接后端确为 SSH LLM 目标 → AC-1、AC-2、AC-5。

验证：`node --test dsh-elysium/tests/server-routes.test.js dsh-elysium/tests/media-http.test.js` — 连接路由、认证、脱敏及路由注册断言通过 → AC-1、AC-2、AC-5。

### 阶段 2：接入私有模型面板

1. `dsh-elysium/src/client/workbench/servers.js:ServerList` — 修改：私有模型只有图片/视频下拉框 → 在私有模型内增加“聊天模型”行，显示 qwen3.8 提供者元数据和“连接”按钮；请求中禁用按钮，成功后改为“重新连接”，失败时恢复可点击并显示脱敏错误 → AC-1、AC-2、AC-3、AC-5。
2. `dsh-elysium/tests/server-panel.test.js` — 修改：当前断言模型面板无按钮 → 验证聊天模型标签/qwen3.8 文案、连接时禁用、失败可重试、成功后“重新连接”且再次点击会再发请求；保留图片/视频和三方选择断言 → AC-1、AC-3、AC-5。

验证：`node --test dsh-elysium/tests/server-panel.test.js` — 面板交互与原模型选择回归通过 → AC-1、AC-3、AC-5。

### 阶段 3：回归、构建与运行验收

1. `harness/scripts/start.mjs` — 不修改：保持只管理 Harness 进程的边界 → AC-4。
2. `dsh-elysium/lib/` 、`dsh-elysium/registry/` — 构建/打包生成（Git 忽略产物）：将服务端路由和客户端面板同步到 Harness 已链接的发布包 → AC-1～AC-5。
3. 本机 Harness — 重启：使打包产物加载生效，重启过程不建立 Qwen 隧道 → AC-4。

验证：

- `node --test harness/tests/harness-scripts.test.mjs` — Harness 启动边界仍通过 → AC-4。
- `pnpm --dir dsh-elysium test` — 插件全量回归通过 → AC-1～AC-5。
- `pnpm --dir dsh-elysium build && pnpm --dir dsh-elysium package:registry` — 源码可构建且发布包已更新 → AC-1～AC-5。
- `git diff --check` — 本次差异无空白错误 → AC-1～AC-5。
- 启动 Harness 后检查 `127.0.0.1:18000/v1/models` 在点击前不因 Harness 启动被创建；在面板点击“连接”后返回 qwen3.8 目标模型，按钮变为“重新连接”并可再次点击 — 本机运行验收 → AC-1～AC-4。

## 验收标准

- AC-1：打开模型面板 → “私有模型”下显示“聊天模型：qwen3.8”及“连接”按钮。
- AC-2：隧道未建立时点击“连接” → 仅此用户操作触发 `veo-qwen38` 的本机 SSH 端口转发，并在返回成功前核对目标 Qwen 模型。
- AC-3：连接成功 → 按钮文案变为“重新连接”；再次点击会重新执行连接与模型检查，可用隧道由现有 SSH 控制连接安全复用。
- AC-4：启动 Harness → 启动脚本仍不读取模型配置、不建立隧道。
- AC-5：连接失败 → 面板显示脱敏错误，按钮恢复可点击，不改动图片/视频选择。
