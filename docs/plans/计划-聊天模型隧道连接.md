# 聊天模型隧道连接

- 类型：新功能
- 目标：Harness 启动不建立 Qwen 隧道，改为在私有模型面板点击“连接/重新连接”时按需建立并验证。
- 调研来源：`docs/research/调研-聊天模型隧道连接.md`

## 人工决策

用户已决定命名边界：

**仅缩短显示名**：本地界面、Harness `displayName/name` 和设置项显示 `qwen3.8`；真实 API ID 仍为远端已发布的 `qwen3.8-27b-elysium`，不修改、不重启远端模型。

按钮中的“重新连接”定义为再次执行同一连接与模型检查：已健康的本功能 SSH 控制连接可复用，断开后则重建；不为“重新连接”强制中断健康隧道。

## 2026-09-18 修订步骤

1. `dsh-elysium/config/defaults.json` 及统一设置 schema — 修改：聊天模型显示名缩短为 `qwen3.8`；删除远端实际不需要的 `QWEN38_LOCAL_API_KEY` 强制检查，保留真实上游模型 ID 的校验 → AC-1、AC-2、AC-5。
2. `dsh-elysium/src/client/workbench/servers.js:ServerList` — 修改：聊天模型纯文本 → 与图片/视频一致的下拉框，同行保留“连接/重新连接”按钮 → AC-1、AC-3。
3. `dsh-elysium/src/servers/registry/resolve.js:legacyTunnelBackend` 及路由测试 — 修改/验证：统一设置中的空连接清单仍组装 SSH 隧道，不退回无 transport 的 LLM 后端 → AC-2、AC-5。
4. `harness/.dsh/settings.yaml` 及模型相关测试 — 按用户选定的命名边界同步显示名或全局 API ID → AC-1～AC-3。
5. 若选择全局 API ID 改名：远端 `/root/autodl-tmp/project/scripts/qwen38/run_server.sh` 中 `--alias` 改为 `qwen3.8`，安全重启后以 `/v1/models` 和一次聊天请求验收；否则不修改远端。

验证：设置 schema/store、server route、server panel、Harness settings 定向测试；插件全量测试；构建、registry 打包、Harness 重启；点击前 18000 不可达，点击后隧道可达且目标模型检查通过。

## 验收标准

- AC-1：打开模型面板 → “私有模型”下显示“聊天模型：qwen3.8”及“连接”按钮。
- AC-2：隧道未建立时点击“连接” → 仅此用户操作触发 `veo-qwen38` 的本机 SSH 端口转发，并在返回成功前核对目标 Qwen 模型。
- AC-3：连接成功 → 按钮文案变为“重新连接”；再次点击会重新执行连接与模型检查，可用隧道由现有 SSH 控制连接安全复用。
- AC-4：启动 Harness → 启动脚本仍不读取模型配置、不建立隧道。
- AC-5：连接失败 → 面板显示脱敏错误，按钮恢复可点击，不改动图片/视频选择。
