# 请求中查看 HTTP

- 类型：完整流程
- 目标：任务步骤的查看 HTTP 在请求发出后就能看到请求，返回后再看到响应。
- 非目标：不重启 Harness，不改变最终保存的请求和响应内容。

## 验收标准与调研结论
| AC | 输入/状态 → 可观测结果 | 已确认/未确认/未验收 | 依据或缺口 |
|---|---|---|---|
| AC-1 | 请求已发出、响应未到 → 查看 HTTP 能看到本次请求，返回页说明尚未返回 | 已确认 | `sendChat` 和 `requestGatewayRaw` 都在请求结束后才 `recordTransfer` |
| AC-2 | 响应已返回 → 同一次调用的返回页看到响应，不另计成一次请求 | 已确认 | 每次 `recordTransfer` 都会往 `prompt.transfers` 追加一条 |

## 调用链与证据
任务执行 → `createAiRoutes` 把网关记录写入步骤 `prompt` → 面板事件刷新 → 任务历史「查看 HTTP」。

| 来源（文件:行） | 支持的结论 |
|---|---|
| `meiji/server/http/chat-transport.js:12` | 文本请求在 `fetch` 完成或失败后才记录 |
| `meiji/server/gateway/model-gateway.js:149` | 图片和视频请求同样在结束后才记录 |
| `meiji/server/http/ai-routes.js:71` | 记录回调把每条传输追加进 `prompt.transfers` 并立刻写入步骤 |
| `meiji/client/history-ui.js:108` | 没有 `transfers` 时显示没有 HTTP 记录 |

图谱：`requestGateway` 影响为 HIGH，直接调用方是 `downloadImageBytes`、`generateGatewayImage`、`submitGatewayVideo`、`retrieveGatewayVideo`。`renderStepRecord` 影响为 HIGH，直接调用方是 `renderHistory`。`sendChat` 影响为 LOW。
