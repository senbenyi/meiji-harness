# 换机中转初始化

- 类型：新功能
- 目标：新电脑拷贝私钥与 Elysium 数据后，执行一条命令即可生成与原机一致的中转 SSH 配置，直接启动使用。
- 调研来源：`docs/research/调研-香港中转网络.md`、`docs/implement/实施-香港中转网络.md`

## 人工决策
已定（2026-09-21）：
- 私钥：从原机复制 `id_ed25519_veo_hk`、`id_ed25519_veo_comfyui`、`id_ed25519_veo_qwen38` 到新机 `~/.ssh/`。
- 数据：手动整体拷贝 `~/.dsh/storages/elysium`（含 `autodl-comfyui` 登记），脚本不做服务器登记。
- 香港与 GPU 端无需任何改动。

## 验收标准
- AC-1：新机缺少 `veo-*` 配置时执行 `node init/relay.mjs` → `~/.ssh/config` 生成 `veo-hk`、`veo-comfyui`、`veo-qwen38`、`veo-comfyui-direct`、`veo-qwen38-direct`，原配置先备份；已存在的同名块被整块替换，其他 Host 不变；重复执行结果不变。
- AC-2：主机公钥按仓库固定值写入 `known_hosts`；已有条目与固定值不一致时报错退出，不覆盖、不 `accept-new`。
- AC-3：生成的配置使 `sshIdentity(veo-comfyui)` 与原机登记值一致，拷贝来的 `settings.json` 无需修改；脚本回读登记值并报告一致与否。
- AC-4：脚本以 `StrictHostKeyChecking=yes` 逐个登录五个别名并报告结果；缺私钥时给出明确提示后退出。
- AC-5：在原机执行不改变任何身份哈希，登录与项目连接不受影响。

## 执行步骤

### 阶段 1：固定参数与脚本
1. `init/relay.json` — 新增：香港（地址、用户、密钥、主机公钥）与两台 GPU（中转端口、直连地址端口、密钥、主机公钥）→ AC-1、AC-2
2. `init/relay.mjs` — 新增：`renderBlocks`（按 relay.json 生成五个 Host 块，字段与原机一致）、`upsertHostBlock`（整块替换或追加）、`knownHostLines`；`main` 依次：检查私钥（权限收紧为 600）→ 备份并写 `~/.ssh/config` → 写/核对 `known_hosts` → 严格登录 → 回读 Elysium 登记并比对 `sshIdentity` → AC-1～AC-4
3. `harness/tests/relay-init.test.mjs` — 新增：块渲染字段、整块替换与幂等、其他 Host 保留、known_hosts 冲突检测 → AC-1、AC-2

验证：`node --test harness/tests/relay-init.test.mjs harness/tests/switch-ssh.test.mjs` 通过 → AC-1、AC-2

### 阶段 2：原机回归与文档
1. 原机执行 `node init/relay.mjs` → 配置块等价替换；前后 `sshIdentity` 不变、登记一致、五个别名严格登录通过 → AC-3～AC-5
2. `init/README.md` — 新增"换电脑"一节；`AGENTS.md` 指向该节 → AC-1

验证：执行前后 `ssh -G` 身份字段 diff 为空；脚本输出"登记一致" → AC-3、AC-5
