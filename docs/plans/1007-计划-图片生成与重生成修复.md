## 改动
### 阶段 1：入口与并发
1. meiji/shared/run-templates.js:normalizeRunGoal — 仅像素 → 像素或已有五种比例白名单 → AC-1。
2. meiji/server/data/project-store.js:revisionStore/fingerprint — image/revise-image 按 episodeId/itemId 比较本卡及其候选，保留输出语言/画幅依赖；图片提示词不使用剧本/项目时长，不把这些无关更新作为依赖，其他任务的公共依赖保持 → AC-2。
3. meiji/client/project-library-view.js:renderProjectLibrary — 库重生成按钮显式 generationMode regenerate → AC-4。

验证：真实页面按钮参数经过 goalRequest/planRun；Run 并发生成两图；修改本卡资料仍返回 409。相关 run-planner、image-detail-ui、library-ui、data-consistency 测试。

### 阶段 2：候选替换与面板恢复
1. meiji/server/runtime/review-checks.js:prepareChecks — 图片保留 matchingCandidate，仍冻结基图和开始节点；已处理或错误归属的显式 draftId 返回 409。失败优先落定错误，不能因旧候选仍在就误记为等待确认；其他任务不变 → AC-2、AC-3。
2. meiji/server/flow/steps/shared/image-files.js:stageImageDraft 与 shared/image-generation.js:startImage — 新候选就绪后在同次保存替换对应旧候选，成功后删除旧文件；其他卡候选和已确认图保持 → AC-3。
3. meiji/client/panel-app.js:beginImage/regenerateImage — 不提前 discard，处理 cancelled、恢复异常状态；重生成保留旧 gate 供取消/失败回退 → AC-3、AC-5。
4. meiji/client/image-review.js:syncImageGate/generatingOf — 保留旧候选期间按实际执行锁判断忙碌，任务停止后恢复可用旧候选；meiji/client/asset-cards.js:cardImageGate 限定本卡执行锁，不能把其他卡生图当成本卡 gate → AC-2、AC-3、AC-5。generatingOf 为 CRITICAL（1 直接调用方，经 syncImageGate 影响图片 UI），已在同步入口风险说明中覆盖；cardImageGate LOW。
5. .agents/meiji-dev.md、meiji/README.md — 更新候选保留/成功替换与并发说明 → AC-2、AC-3、AC-5。

验证：候选再生/修改的成功、接口失败、Abort、非法输入；mounted panel 的预览取消和重生成错误恢复；不得发 discard 请求。回归先运行旧实现，确认失败，再实施。
