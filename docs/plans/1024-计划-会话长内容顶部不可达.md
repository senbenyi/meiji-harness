# 会话长内容顶部不可达

- 类型：Bug修复，完整流程（初始原因未知）。
- 目标：展开大纲后仍能滚回最早的操作消息，保留自然展开和底部输入框。
- 非目标：修改宿主源码、恢复故事段内滚动、调整虚拟列表或启动模型任务。

## 验收标准
| AC | 状态/预期 | 调研 |
|---|---|---|
| AC-1 | 空会话任务消息展开长输入后，可滚到最早消息 | 当前Chrome已复现向上20页仍卡在第三故事段 |
| AC-2 | 收起再展开后仍能正常上下滚动，输入框可用 | 待实际浏览器验收 |
| AC-3 | 正常聊天的原生消息座位、其他会话布局不变 | 仅限定hero且存在直属drama-task-messages |

## 调用链及证据
mountTaskMessages.seat在hero会话滚动容器prepend任务消息；原覆盖选择器特异性(0,1,1)，宿主ConversationRoot.module.css的.embeddedBody[data-content-phase=hero] .scrollBody为(0,3,0)，导致justify-content:center实际胜出。长内容负向居中，上方溢出不能通过scrollTop=0找回。宿主只读检查，源码不修改。当前为hero独立任务座位，不是原生虚拟消息高度问题。
GitNexus MCP list_repos连接关闭，转CLI使用仓库绝对路径。已status、更新索引、query/context/impact，mountTaskMessages为UNKNOWN；实际动态挂载和CSS选择器经源码、Chrome复现补查，不将UNKNOWN视为安全结论。

## 改动
1. projects/drama/src/client/task-messages.js：顶部对齐选择器增加公开hero容器限定，特异性高于宿主居中样式，只有存在插件任务消息时生效 → AC-1/2/3。
2. 验证原task-messages测试及真实Chrome刷新后重复展开、滚至顶部和底部，不触发业务操作。
