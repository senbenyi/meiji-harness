# 剧本到视频与共享图片库完整方案

本文整合用户最新确认：共享图片数据库只有id和url；人物、衣服、道具、场景及组合定妆照支持导入/AI生成并直接入库；按镜头需求准备稳定形象；先联合改编规划再连续故事定稿；前期不分集；声音分为稳定音色与镜头表演。本文取代此前大剧本方案中资产、声音及阶段顺序的目标设计，未实施业务代码或创建数据库。

## 1. 核心边界

- 全局图片库保存可跨项目复用的实际图片，仅两个字段id、url，不承载人物身份、类别、服装归属、审核状态、项目ID或声音。
- 项目JSON保存本项目采用的人物/服装/道具/场景/人物造型定义、语义关系、所选图片ID及阶段状态。两个项目可引用同一图片ID，但人物身份与剧情关系各自独立。
- 分镜保存故事段、人物造型、场景、道具ID和本次选用图片ID；图片地址在执行时从全局库解析，不在各镜头重复存放权威地址。
- 稳定形象由“素材准备”阶段建立；文字镜头先登记实际需求，已有素材优先复用，缺项才导入或生成。组合定妆图也登记到同一图片库。
- 原著解析、联合规划、故事定稿、分镜表达、项目资产定义及图片文件各有唯一归属。计划不是正文；人物定妆图不是分镜首帧；参考道具不意味着每镜必须持有。
- 不提前分集，连续维护人物/物体/空间状态，最终分集只作用于剪辑时间线。

## 2. 完整流程与交付

| 阶段 | 工作与边界 | 产物及项目字段 |
|---|---|---|
| 1 项目创建/原稿入库 | 纯程序保存项目、原稿文件、来源版本及会话；不自动摘要 | basic_info、source；创建已改为纯程序，后续长稿导入能力待建设 |
| 2 原著解析 | 按预算读取全文，识别章节/场次并忠实记录人物、地点、事件、伏笔与未知项 | source_analysis：章索引/摘要、原文区间、事实及阅读覆盖记录 |
| 3 联合改编规划 | 确定用户约束、人物动机/关系/成长、场景功能、主线冲突、爽点与铺垫兑现、各段改编目标 | adaptation_plan：人物规划、场景规划、剧情及连续故事段计划，不生图 |
| 4 连续故事分段定稿 | 按计划逐段写完整动作和对白，局部审核加全篇因果/连续性复核 | story_segments：定稿、来源、计划关联、锚点、开场/结尾状态；无episode_id |
| 5 文字分镜与需求识别 | 编排连续镜头、表演和声画，查项目已有资产；识别确实用到的服装、道具、场景与组合造型 | shot_design的同一组shot草案、asset_requirements；不因缺图否决内容正确的镜头 |
| 6 稳定素材准备 | 复用全局图片；支持导入/AI生成人物基础形象、服装、道具、场景总览；按需组合人物定妆图 | 图片直接写全局images；项目asset_library绑定image_id、组合关系、候选和选用状态 |
| 7 分镜参考绑定与确认 | 把实际采用的定妆、场景、道具图绑定回原镜头；检查构图、身份/空间和状态要求 | 相同shot ID的已确认版本及明确image_id，不生成第二份独立镜头表 |
| 8 技术分片与H3提示词 | 程序按实际模型容量安排镜头/节拍覆盖；模型写声画指令并明确每张图片、音频的用途 | clip_arrangement、video_prompt；请求级图片/主体/说话人映射及实际引用快照 |
| 9 视频及声音生成/审核 | 默认参考模式使用定妆、场景、道具及可选音色样本，H3同步生成对白声音；检查画面、对白、音色及镜头衔接 | videos：候选、已选take、素材版本、真实时长、调用/重试事实；视频/音频不塞进图片表 |
| 10 连续剪辑与后期 | 裁切转场、声画同步、对白响度/环境衔接、必要音效音乐、字幕及技术处理 | editing：时间线、已选视频、音轨、字幕及预览 |
| 11 最终分集/验收导出 | 依据成片节奏选择集界，检查内容连续及目标规格 | episodes、delivery：时间线范围及导出文件 |

这些是业务阶段，不要求每阶段只能有一个Task或一次模型请求。主Agent在盒子之间调度；素材执行器不藏在分镜模型中任意执行，模型不能直接写共享数据库或项目JSON。阶段5/7使用同一镜头对象，通过状态和修订记录推进，允许只补缺项和局部返工。

## 3. 共享图片库：严格只有两列

```sql
CREATE TABLE images (
  id TEXT PRIMARY KEY,
  url TEXT NOT NULL
);
```

数据库属于drama全局存储层，与projects目录分开。图片文件也放共享持久化位置，地址不绑定某个项目/会话，不仅保存供应商短期下载链接。外部导入和AI生成共用同一入库入口：取得实际图片→检查可用性→保存持久文件→登记id/url→返回image_id→绑定项目实体。生成或导入成功的图片立即入库，审核/选用状态留在项目及执行记录，入库不代表已选定使用。

全局图片ID由程序分配且对应不可变图片；重新生成新图就生成新ID。重试用任务记录关联入库结果，避免重复绑定；共享图片已落库而项目写入失败可重试绑定，不误报项目已完成。删除项目只解除本项目引用，不删除共享图片。全局删除需另行检查引用，不能沿用项目文件删除逻辑。

只有id/url意味着图库支持按ID获取、分页缩略图浏览及用户选择，不能宣称数据库能按“张飞/蛇矛”自动语义检索。项目内AI可依据本项目文字定义与image_id索引复用；其他项目素材通过选图后绑定为本项目定义。以后要做全局语义检索，应另建独立检索索引，不改变此两列表。

现有library_store已是全局入口，但目前仅实现剧本入库，且元数据结构不是本图片表；保留剧本库，新建图片存储能力。现有定妆照/场景图写项目目录并返回带session_id地址，需迁移到共享图片入口；旧项目图片先复制到共享存储再绑定，不让旧会话删除影响复用。

## 4. 项目资产类型与组合定妆

| 类型 | 项目字段 | 保存内容 |
|---|---|---|
| 人物基础形象 | asset_library.characters | 人物身份与稳定外貌、基础参考图片ID、稳定声音设定 |
| 服装 | asset_library.clothing | 独立服装定义及图片ID，可被多人物采用；团队制服共享定义，人物脸部不共享 |
| 道具 | asset_library.props | 稳定外形及图片ID；关键尺寸、结构、标识等约束 |
| 场景 | asset_library.scenes | 固定布局/出入口/参照物及总览图ID，必要区域图按需补齐 |
| 人物造型 | asset_library.character_looks | 人物ID＋服装ID＋可选道具绑定＋发妆及穿着说明＋组合定妆图ID |

“人物”和“人物造型”分开：人物保留脸/体型等稳定身份；造型表达实际穿着及必要持物效果。只有本次分镜需要的造型才准备，不为全部可能服装预生成图片。一个造型可有多个候选/视角，但通过项目选用状态确定实际参考。

所有类型支持两条入口：导入图片绑定定义，或按定义AI生成。若用户直接导入完整定妆图，可直接建立人物造型，不强制拆出或生成基础人像/衣服/道具单图。只有独立复用、细节约束或后续镜头实际需要时再补单图。

### 张飞与丈八蛇矛

可先分别准备张飞基础形象、服装、丈八蛇矛，再生成“张飞穿该服装、手持该蛇矛”的组合定妆图；也可直接导入或生成整张组合图。无论哪条路线，人物、衣服、道具的逻辑身份及引用关系独立保存。

H3官方参考指南明确：人、服装、道具可作为Subject；一个主体可由多份参考定义，一份参考也可以提供多个主体。因此，一张组合图可同时提供张飞和蛇矛的参考。它支持这种参考表达，但不保证每次生成都完美保留全部细节，需实际验证。

建议用法：稳定标志性持物可组合定妆；道具有特写、交接、放下等独立动作时，可额外给独立道具图。在H3主体定义中说明人物取哪张图、蛇矛取哪张图或同图哪个部分，且不同参考对同一对象的关键外观不能冲突。组合图中持有武器不等于武器永久粘在手上，实际持有者、左右手、拾取/放下/递交写在镜头/节拍状态中。镜头不持矛时明确动作与可见范围，必要时选择无持物造型；不为每种动作建立新稳定资产。

场景总览用于布局参考，不要求每镜复制总览机位。定妆照用于身份/穿着，不自动当成视频首帧；首帧如有需要，按镜头构图单独准备。

## 5. 声音：稳定身份＋逐镜表演＋场景声学

### 稳定层

人物voice_profile保存：基准音色/年龄感/共鸣、常态口音和习惯语速，以及可选reference_audio_ref及其修订号。参考音频保存在项目音频资源中，不写入只有图片的images表。主角/频繁发言角色建议使用选定的干净音色样本，以文字说明它仅提供音色，不复制样本台词或把平静语气固定到所有镜头。配角可先用文字音色描述。

可先生成试听或从已认可视频提取干净语音片段，用户选定后作为音色锚点；提取需检查是否含其他人声、配乐或环境声，不能任意截取后即标合格。参考样本增强约束，不保证跨请求音色完全一致。

### 镜头层

每条对白单独保存speaker_id、text及delivery（情绪、音量、语速、强度、气息/停顿）。平静、愤怒、耳语、奔跑喘息等是同一声线的表演，不为每镜创建一个新voice_id或单独预录整句对白。旁白明确独立说话人。

### 场景层

室内/室外、距离、遮挡、混响和底噪属于镜头soundscape/acoustics，不能用人物永久声线字段表示。后期可处理轻微响度和背景衔接；明显换人、串音、错台词不能靠调音当作通过，应定向返工。

### H3执行

优先采用参考生视频：定妆图/场景图/独立道具图＋可选角色音色样本＋本镜对白与表演指令。按每个请求明确角色ID到Subject/Speaker/Audio标签映射，不能假设模型跨调用记住同名角色。

官方API规定参考图最多9张，参考音频最多3段、每段2～15秒、总计不超过15秒；官方模型说明还要求音频与图或视频同行。输入只选本分片真正需要的角色/道具/场景，人数或参考数量超限时重新安排分片/参考组合，不能静默丢掉关键声音或图片。

显式first_frame/last_frame模式与reference_image/reference_video/reference_audio不能混用。因此，强首尾帧与音色样本无法在该接口同请求同时启用；由生成计划明确模式及取舍，必要时采取单独配音/口型后处理，不承诺参考模式的构图指令等同强首帧约束。

音色审核至少检查人物声音身份、说话人对应、对白原文及当镜表演是否成立。相邻镜头允许情绪/音量变化，判定“声音变了”不能仅比较音高或响度数值；稳定身份与表演变化分开评估。

## 7. 执行、审核与迁移

- 每阶段保留独立状态/动作规则和真实Task/Step记录；长稿用预算化范围读取与检查点推进，不能把完整全文或全库图片一次注入模型。原著所有区间覆盖完成后才标解析完成。
- 内容生成、结构校验、独立审核及候选保存分开；图已入库不等于项目已审核选用，分镜已通过不等于图片已齐备，视频已生成不等于成片验收通过。
- 当前character_extraction/scene_extraction/group_setting及图像生成能力可逐步迁移为项目资产对象的生产/完善服务；删除旧生产字段前适配所有读写入口，不能双写两份权威定义。
- 服装由人物内嵌costumes逐步迁为独立clothing；人物穿着关系迁到character_looks，镜头costume_id迁为look_id。旧ID建立映射，已有图复制到共享库后保存新image_id，旧任务历史不重写。
- 现有图片执行器仅接收一个reference_image，且图片模型支持受限；组合人物＋服装＋道具多参考需明确扩展图片适配器，H3参考能力不能当作当前图片执行器已支持组合生图的证明。
- 项目只存图片ID，实际生成调用保存当次ID及地址解析/上传事实。更换项目默认图不改变旧视频引用快照。任务、图片DB和文件之间采用可重试绑定流程，不夸大为跨存储一次原子事务。
- 原著解析、联合规划、范围化定稿、共享图片表、独立服装/道具/人物造型、声音参考与完整视频后期流程均为后续实施项；当前已完成的只是纯程序创建/导入及原有生产能力。

建议实施次序：先共享图片库与统一导入/生成落库入口；再项目资产定义和组合定妆；再镜头需求/绑定闭环；原著解析及联合规划/范围化定稿独立分阶段建设；最后接通H3参考模式、声音审核和后期交付。实施前分别明确接口、迁移与验收，避免一次改所有盒子。

## 8. H3依据与适用范围

- [官方参考模式提示词指南](https://huggingface.co/MiniMaxAI/MiniMax-H3/blob/main/docs/VIDEO_PROMPT_WRITING_GUIDE_ref_en.md)：支持人、服装、道具等Subject，一图多主体/一主体多参考；音色参考与音频复制分开，人物声线与当镜表达可组合。
- [官方视频生成V2接口](https://platform.minimax.io/docs/api-reference/video-generation-v2-create)：参考图片/音频输入数量与时长限制，首尾帧与参考模式互斥。
- [官方H3模型说明](https://www.minimax.io/news/minimax-h3-open-source)：原生音视频输出、参考音频需与图/视频配合。
