# 逐镜文本任务接入

- 类型：完整流程，节点/存储/任务重构。
- 目标：接通镜头识别→每秒分镜→文生提示词，按统一任务服务审核、修订、保存。
- 非目标：视频类型新策略、视频尾帧原子结果、角色子代理自动调度。

## 顺序与改动
1. `shared/models/character_binding_model.js`、shot Model、project_contract、node-definitions、handlers：正式识别节点，唯一嵌套绑定数据，编号映射 ID；has_result 区分无结果与合法空结果。HTTP 候选接口沿用。
2. `precheck.js`、`task-service.js`：逐镜须有效角色库和镜头表，识别先于 seconds，文本不要求图片。独立任务不自动补上游。
3. `node-state.js`、节点 seconds 及 PromptModel：时间范围语法仍为协议校验，连续性/正向/容差±5交程序审核，与 AI 共用两次修订。亚秒格替换所属秒的细分，禁止重叠追加。
4. 共享文本输入投影、node-dependencies、所有绑定读取方和 client：输入与 hash 共用投影；镜头/角色/前镜穿着变化传播，图片变化不影响文本；显示识别状态、编号和人工编辑。
5. 按用户最新要求清空已有项目、任务及关联文件，不迁移。移除旧版本迁移实现及测试；新数据库使用 v9，保留模型配置与独立素材库，旧版本入口明确拒绝且不自动删除数据。

## AC
| AC | 输入 → 可观测结果 |
|---|---|
| T1 | 新镜头/识别空结果 → 未识别与确认无人状态不同；合法编号映射，错误绑定拒绝 |
| T2 | 成片/逐镜提交 → 识别先于每秒分镜；无角色库阻断，有角色库缺图可完成文本 |
| T3 | seconds 时间线错误/±5边界 → 程序审核决定通过或修订，最多两次；协议损坏失败 |
| T4 | 角色/绑定/声音/前镜/图片变化 → 与实际输入匹配的过期传播 |
| T5 | 取消、晚到、继续、人工编辑与界面 → 保留统一执行链和合法空绑定 |
| T6 | 清空旧项目/任务 → v9 空数据库；模型配置和独立素材库不变；旧版本打开失败且不迁移 |
