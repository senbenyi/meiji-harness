# 重新生成与按意见修改分离

- 类型：完整流程，行为修复。
- 目标：文本重新生成不注入上次结果；按意见修改明确使用多轮基稿。
- 非目标：不改变媒体协议，不改已保存任务历史，不取消自动审核修订。

## 验收标准
- AC-1：regenerate 首轮使用 generate 提示，只发 system/user，不含基稿或上次结果；本次输入要求保留。
- AC-2：按意见修改提交 revise，使用 system/user/assistant/user，上次结果仅在 assistant；要求非空意见，且只支持文本。
- AC-3：自动 revise 步骤继续引用本任务最近候选，review 审核当前候选。
- AC-4：面板与会话工具入口、任务名称和文档同步；既有终态历史不改写。

## 调用链与证据
面板两按钮原来均提交 regenerate；text-handler 以 task.opinion 是否非空判断是否调用多轮。TaskService 还会给未通过节点自动带入原因，因此点击重新生成仍可能进入修订。
当前 renderPrompt 的 regenerate 已正确发四条消息，无需修改渲染器。
GitNexus：handler LOW；taskNodeInput/precheck HIGH；面板与任务名称 CRITICAL。validateCommand 已补充具体符号影响分析。
