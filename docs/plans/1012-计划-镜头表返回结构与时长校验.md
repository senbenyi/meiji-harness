# 镜头表返回结构与时长校验

- 类型：Bug 修复 / 提示词契约调整
- 目标：让镜头表生成只返回“标题、编号、参考时长、正文”，并消除当前提示词与时长硬校验之间的冲突。
- 非目标：不调整角色/服装关联、视频生成、分镜、文本提示词或其他后续成片步骤；不更改数据库中的镜头结构、15 秒单镜上限或本集参考时长 ±30 秒范围。

## 验收标准与调研结论
| AC | 输入/状态 → 可观测结果 | 已确认/未确认/未验收 | 依据或缺口 |
|---|---|---|---|
| AC-1 | 模型生成/重生成镜头表 → 每行严格只有标题、编号、参考时长、正文 | 已确认 | `shots-generate.yaml` / `shots-regenerate.yaml` 的输出结构及严格 `validateShape`。 |
| AC-2 | 四字段镜头返回 → 转成现有项目镜头表字段 | 已确认 | 程序按数组顺序生成序号、将参考时长映射到存储字段时长秒；角色关联及后续成片流程不在本次范围。 |
| AC-3 | 镜头生成/重生成 → 按故事大纲小段顺序拆成最长15秒镜头，分镜规则只作为切点参考 | 已确认 | 故事大纲每个小段已带有时长和剧情锚点；当前模板额外要求整集预算和镜头数下限，增加复杂度。 |
| AC-4 | 自动时长修订 → 反馈当前镜头数、总秒数及允许范围，并继续按小段切分 | 已确认 | 当前程序错误只报告范围；实际生成曾偏离总时长，修订缺少当前合计时长。 |

## 调用链与证据
面板提交 `shots` → `TaskService` 调用文本处理器 → `promptValues` 组装 YAML 输入 → 模型 JSON 经 `validateShape` → `prepareContent` / `translateNumbers` / `replaceShots` → `assertOutput` 校验单镜不超过 15 秒及整集总时长范围。时长校验失败后，同一任务最多自动修订两轮。

## 问题
| AC | 预期 | 实际 | 根因 |
|---|---|---|---|
| AC-1 | 仅四个输出字段 | 当前还要求序号、时长秒、出镜角色和服装编号 | 模型同时执行内容拆分、编号引用和角色/服装绑定。 |
| AC-2 | 简化输出映射到项目镜头表 | 程序目前需要序号、时长秒；角色关联字段由本次适配留空 | 数组顺序和参考时长可在程序侧派生/映射；角色关联不属于本次流程范围。 |
| AC-3 | 有效结果可以满足时长范围 | 12 镜最高只能有 180 秒，达不到 270 秒下限 | 取消固定镜头数时未将时长范围与单镜上限的数学下限反馈给模型。 |
| AC-4 | 生成规则单一清楚，修订能针对差额 | 模板要求段内小计、邻段转移、整集复核，且程序错误未包含实际总秒数 | 重复预算规则增加了模型负担，并使修订缺少可执行的当前差额。 |
