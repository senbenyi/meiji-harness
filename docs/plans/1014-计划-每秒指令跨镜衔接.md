# 每秒指令跨镜衔接

- 类型：完整流程；代码已实施并验证；真实服务待运行任务结束后重启加载。
- 目标：上一镜生成每秒指令时产出交接资料，下一镜直接读取已审核资料，保持动作与状态连续。
- 非目标：在镜头表阶段生成详细结束状态；让上一镜提前编写下一镜剧情；将前镜资料伪装成当前镜头的 assistant 历史回答。

## 已确定设计

1. 镜头表仅提供本镜剧情、参考时长和总体衔接意图。详细结束状态、待衔接事项由每秒指令生成阶段产出，并随每秒指令一起审核、修订和保存。
2. 固定连续性规则放在 system：不重复已完成动作，不无故改变人物位置、朝向、持物、服装和关键物件状态；连续动作、对白与声音按实际需要接续。
3. 每秒指令输出包含完整时间轴、结束状态、待衔接事项。结束状态描述最后一刻的事实；待衔接事项描述尚未完成的动作、对白和持续声音，不指挥下一镜新增剧情。
4. 最后动作段由程序直接从上一镜时间轴末尾提取，保留完整末尾节拍及必要相邻段，不让模型重复生成一份摘要。约1～3秒仅作为选段参考，不截断完整动作或对白。
5. 下一镜的 user 输入包含本镜剧情/时长/人物资料、上一镜结束状态、最后动作段、待衔接事项及镜头表已有衔接意图。下一镜据此决定自己的开头。
6. 按意见修改沿用 system → user（本镜与前镜输入资料）→ assistant（本镜上一轮完整结果）→ user（本轮意见）。前镜资料始终属于 user 输入。
7. 首镜无需前镜资料。明确换场或时间跳跃时按镜头表说明选择继承的信息，不强行保持空间、动作和声音连续。
8. 前镜交接资料必须来自有效、已审核的每秒指令。按镜头顺序执行；前镜缺失、未通过或过期时，后镜明确提示前置不足，不默认为空资料继续生成。
9. 将实际读取的前镜交接资料登记为依赖。前镜相关资料变化时，后镜每秒指令及其下游按依赖传播标记过期；不删除已有内容，不触发无关任务自动重生成。实施时核对连续多个后镜的传播。

3. 在共享输入提取中读取前镜有效资料，并同步依赖指纹、前置校验、顺序执行与过期传播。下一镜只引用所需末尾资料，不携带前镜全部无关时间轴。
