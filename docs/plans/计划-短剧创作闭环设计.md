# 短剧创作闭环设计

- 类型：新功能（流程重新设计）
- 目标：从项目创建到成片，形成一条由人主导、每步可编辑、每步有自动生成入口、事实只存一处的直线流程；概念、设计、代码都保持最少。
- 调研来源：`docs/research/调研-短剧创作方案闭环.md`
- 状态：**设计待审核**（第二版：按 6 条简化机制修订）。审核通过前不改代码和 Skill。

## 0. 设计机制：用 6 条规则约束复杂度

先定设计再改代码，而且设计本身要用规则约束，否则复杂度只会换个地方出现。以下 6 条是本设计唯一的顶层规则，后面各节都从这里推出。实施和评审时逐条检查。

| # | 规则 | 含义 | 如何检查 |
|---|---|---|---|
| M1 | **同名约定** | 一个步骤对应一组同名文件：流程 Skill `drama/steps/<步骤>.md`、导演 `references/<步骤>.md`、数据文件 `<步骤>.md`。拼接提示词只有一条规则，不维护映射表 | 测试：步骤清单与三处文件名一致 |
| M2 | **人写 Markdown，系统写 JSON** | 创作内容由人拥有，存 Markdown，文本本身就是数据；任务、状态、成片由系统拥有，存 `state.json`。两边互不写入对方的文件 | 测试：生产代码不写 `.md`；保存文本不改 `state.json` |
| M3 | **引用而不复制** | 下游只写上游的名称或编号，使用时再读取原文 | 评审：同一事实只能在一个文件里出现 |
| M4 | **状态只从事实推出** | 进度和完成与否只看任务状态和成片是否存在；不存版本、定稿、复核、确认这类标记 | 测试：`src` 中不出现 `needs_review / finalized / versions / cascade` |
| M5 | **两个拼装点** | 给模型的输入只在两处拼装：`assemble(步骤)`（写文本）和 `compileShot(镜头)`（出画面） | 评审：其他地方不拼接提示词 |
| M6 | **概念预算** | 新增一个概念，必须删掉一个；设计文档维护概念清单 | 评审：对照 0.1 节的清单 |

**已确认的口径**：

- 剧本与分镜分开，但不重复维护。
- 前期全部人工审核，系统不做内容审核。
- 不区分版本，保存即生效。
- 闭环由人工验证，系统少干预。
- 集数由 Skill 维护。
- 第一版计划中的 D1～D7 已同意。

### 0.1 概念清单（M6）

| 类别 | 删除（现状） | 保留 / 新增（目标） |
|---|---|---|
| 流程状态 | 版本、定稿、依据版本、需复核、级联暂停、级联确认、提示词定稿、锚点确认、锚点“需复核”、剧集停用 | 无 |
| 创作数据 | 时间线、`episode_count`、`series.genre`、`episode_seconds`、角色和场景的技术 ID、分镜中的台词副本、字幕副本、锚点中的角色描述副本 | 项目、总览、剧本、锚点提示词、分镜、镜头提示词（6 份 Markdown）；行号 `[L..]`；镜头号 `[S..]` |
| 系统数据 | `planning.json`、`auto.json`、`anchors.json`、每集的 `storyboard.json / deliverables.json / film-task.json` | 一个 `state.json`（`materials.json` 与 `media/` 不变） |
| Skill | `drama-planning`、`shot-planning`、两份检查清单、导演 `shot-prompt-example.md` | 1 个 `drama` 包（6 个步骤文件）；导演包（总纲 + 6 个同名可选文件） |
| 代码 | 结构化 JSON schema × 5、内容规则校验、前端“JSON ⇄ 文本”双向转换、流水线中的规划推进 | 1 个 Markdown 解析器、2 个拼装点、机械生产 |
| 锚点 | — | 角色（定妆图）、场景（文字）。物件锚点和风格锚点**暂缓** |

**概念总数明显下降**：共删除 18 个旧概念，新增的只有 `[L..]`、`[S..]`、`state.json`、`drama` 包 4 个。

## 1. 流程

**页面顺序（项目 → 剧本 → 锚点 → 分镜 → 成片）保持不变，各步骤内部的做法全部按 M1～M6 重做。**

```text
 ┌──────┐  ┌──────────────────┐  ┌──────┐  ┌─────────────────┐  ┌──────────────────┐
 │ 项目  │─▶│ 剧本               │─▶│ 锚点  │─▶│ 分镜              │─▶│ 成片               │
 │project│  │ series → script   │  │anchor │  │ storyboard→prompt │  │ 生产 → 合成 → 人看  │
 └──────┘  └──────────────────┘  └──────┘  └─────────────────┘  └──────────────────┘
     ▲             ▲                  ▲              ▲                     │
     └─────────────┴──────────────────┴──────────────┴── 不满意：回任一步改文本 / 自动生成 → 重拍
```

每一步的交互都一样：

```text
 这一步的文件为空？─是─▶ [🤖 自动生成] ─▶ assemble(步骤) ─▶ LLM 输出 Markdown ─▶ 写入文件
        │                                                                    │
        否 ◀─────────────────────────────────────────────────────────────────┘
        ▼
  查看（渲染）─▶ [编辑] 同一份文本 ─▶ [保存] ─▶ 生效（不动下游、不动 state.json）
  已有内容时点 🤖：先确认覆盖
```

三个与现状不同的地方：

1. **锚点只卡住镜头生产，不卡住写分镜。**
2. **分镜页只负责“写”，成片页负责“拍和看”。**
3. **系统只做机械工作**：补出缺失的角色定妆图、提交镜头、失败重试一次、合成成片。不再设“确认锚点”：人点“一键生产”就相当于确认。

## 2. Skill 体系

### 2.1 两个包，文件同名（M1）

```text
drama/                          流程 Skill（全局一份）：这一步写什么、按什么格式写
  SKILL.md                      总则：人工内容优先、只用已有名称、输出纯 Markdown
  steps/project.md              立项
  steps/series.md               剧情总览
  steps/script.md               单集剧本
  steps/anchor.md               定妆提示词
  steps/storyboard.md           镜头表
  steps/prompt.md               镜头提示词（模型适配：H3 语法 + 范例；换模型只换这一个文件）

director-xxx/                   导演 Skill（每位导演一份）：这部戏是什么味道、多大规模
  SKILL.md                      总纲：题材、人物、声音、禁忌（每一步都读）
  references/project.md         题材范围
  references/series.md          集数（一条确定规则）、单集秒数、分集结构      ← 集数的唯一来源
  references/script.md          节奏、单集结构、钩子、对白风格
  references/anchor.md          角色服装色系、标志物、定妆画风
  references/storyboard.md      镜头语言、单镜时长范围
  references/prompt.md          提示词风格要求（与模型无关，如“写清两人距离变化”）
                                （以上文件都可以不写，缺失时按空处理）
```

拼接规则只有一条：

```text
system = drama/SKILL.md + drama/steps/<步骤>.md + director/SKILL.md + director/references/<步骤>.md
user   = 该步骤的输入文本（见 3.2 节）
output = { markdown: string }   ← 只要一段 Markdown，不再用结构化 JSON schema
```

### 2.2 职责边界

| 文件 | 只写 | 不得写 |
|---|---|---|
| `drama/steps/*` | 这一步输出什么、Markdown 模板、结构规则 | 集数、时长这类由导演决定的数值；风格偏好 |
| `drama/steps/prompt.md` | H3 语法：分秒段落、首帧用英文静态描述、画面不出字幕、不写台词原文（由编译附加） | 剧情、风格 |
| 导演 `SKILL.md` | 题材、人物、声音、禁忌 | 格式、模型语法 |
| 导演 `references/<步骤>.md` | 该步骤的风格和数量规则 | 其他步骤的内容；互相矛盾的规则 |

优先级：人工编辑的内容 > 导演 > `drama` 的默认建议。

## 3. 数据

### 3.1 文件（M2）

```text
projects/<id>/
  project.md                 人  frontmatter{title, director, genre, cover} + 梗概
  series.md                  人  一句话故事 · 世界观 · 角色 · 场景 · 分集
  anchor.md                  人  每个角色的定妆提示词（英文）
  episodes/N/script.md       人  场 → [L..] 行
  episodes/N/storyboard.md   人  [S..] 镜头块
  episodes/N/prompt.md       人  每个 [S..] 的视频提示词 + 首帧提示词
  state.json                 系统  创建/更新时间 · 自动任务 · 角色定妆图 · 各集镜头任务 · 合成任务 · 成片
  materials.json · media/    系统  不变
```

`state.json` 的结构：

```json
{ "created_at": 0, "updated_at": 0,
  "auto": { "task": null, "until_episode": null, "paused": null, "attempts": {} },
  "anchors": { "林晚": { "image_job_id": "…", "source_job_id": "…" } },
  "episodes": { "3": {
    "shots": { "S01": { "take": 1, "keyframe_job_id": "…", "job_id": "…", "status": "succeeded" } },
    "film_task": null, "deliverables": [] } } }
```

其中 `auto.task` 的取值为 `"fill"`、`"produce"` 或 `null`，分别表示一键补全、一键生产和空闲。

**名称就是 ID**：角色和场景用名称引用，不再单独存 `char_xxx` 这类技术 ID。代价是改名后需要全文替换，而且定妆图按名称挂接（见人工决策 N1）。

### 3.2 数据从哪里来、传给谁（M3、M5）

```text
导演 references/<步骤>.md ────────────── 每一步 assemble 时读取同名文件
                                                                      
project.md ──(梗概/题材)──▶ assemble(series) ──▶ series.md
                                                   │ 角色/场景/分集
            ┌──────────────────────────────────────┼─────────────────────────┐
            ▼                                      ▼                         ▼
 assemble(anchor)                       assemble(script)              项目列表：N=分集数、主演
   输入：series 角色                       输入：series + 分集条目 N
     ▼                                         + 第 N-1 集 script 最后一场
 anchor.md ──▶ 出图 ──▶ state.anchors             ▼
     │                                     episodes/N/script.md
     │                                         │ [L..] 行
     │                                         ▼
     │                                 assemble(storyboard)  输入：script + series 角色
     │                                         ▼
     │                                 episodes/N/storyboard.md
     │                                         │ [S..] 引用 L..
     │                                         ▼
     │                                 assemble(prompt)  输入：本镜块 + 所引行 + series 角色
     │                                         ▼
     │                                 episodes/N/prompt.md
     ▼                                         ▼
 ┌──────────────────────── compileShot(S) ───────────────────────────┐
 │ 首帧 = keyframe_prompt + 出镜角色的定妆提示词(anchor.md) + 主角定妆图  │
 │ 视频 = 场景描述(series) + 出镜角色外观/音色(series) + prompt(prompt.md) │
 │       + 台词段：所引 [L..] 行，按顺序写成“角色（语气；音色）：原文”     │
 └───────────────────────────────────────────────────────────────────┘
                                         ▼
                           state.episodes[N].shots[S] ─▶ 合成 ─▶ 成片 + 字幕（取自所引行）
```

| 事实 | 唯一所在 | 被谁读取 |
|---|---|---|
| 集数、单集秒数 | 导演 `series.md` → 落实为 `series.md` 的分集条目 | 列表分母 = 分集条目数 |
| 题材、梗概 | `project.md` | assemble(series)、列表 |
| 角色外观、服装、音色、性格、主角标记 | `series.md` | 剧本、分镜、编译、列表主演 |
| 场景描述 | `series.md` | 剧本的场次、编译 |
| 分集标题、梗概、钩子 | `series.md` | assemble(script)、成片标题 |
| 台词、动作、音效 | `script.md` 的行 | 分镜页只读显示、编译台词段、字幕 |
| 定妆提示词 | `anchor.md` | 出图、首帧编译 |
| 镜头语言、时长 | `storyboard.md` | 编译、时间码（累加得出，不存储） |
| 画面与节奏 | `prompt.md` | 编译 |
| 任务、状态、成片 | `state.json` | 列表、成片页、流水线 |

### 3.3 Markdown 格式（服务端只有一个解析器）

`series.md`：

```text
一句话故事：婚礼前夜，一封匿名信让林晚开始怀疑闪婚丈夫。
## 世界观
……
## 角色
### 林晚（主角）
外观：28 岁，黑色长直发……
服装与标志物：米白针织开衫；旧黄铜钥匙
音色：清亮偏轻，激动时哽咽
性格：外柔内刚
## 场景
### 咖啡馆
街角咖啡馆，靠窗座位，雨天冷光……
## 分集
### 第 1 集 · 未署名的信
梗概：……
钩子：林晚拆开信，眼神骤变。
```

`episodes/3/script.md`：

```text
## 场 1｜咖啡馆｜林晚、苏晴
[L1] 动作：苏晴把旧照片放在桌上，林晚没有伸手。
[L2] 苏晴（低声）：她已经不在了。
[L3] 音效：雨声压住尾音。
```

`episodes/3/storyboard.md`：

```text
[S01] L1-L2｜林晚、苏晴｜双人近景｜缓推｜6 秒
画面：前景雨痕玻璃，两人相隔一臂。
```

`episodes/3/prompt.md`：

```text
## S01
视频：【0–2 秒】苏晴把照片推过桌面……【2–6 秒】缓推至林晚近景，苏晴开口，林晚垂眼。
首帧：Two women face each other across a cafe table by a rain-streaked window…
```

保存时，解析器为没有编号的行或镜头补上 `[L..]` / `[S..]`，其余原文不动。解析失败时，报错并指出行号，文件不写入，由人修改。这不算内容审核。

## 4. 各步骤设计

### 4.1 项目列表

| 字段 | 核心作用 | 来源 |
|---|---|---|
| 封面 | 识别项目 | `project.md` 中的 cover，缺省用主角定妆图 |
| 名称 · 导演 · 题材 | 识别项目、区分类型 | `project.md` |
| 主演 | 一眼看出谁演 | `series.md` 中标“（主角）”的角色 |
| 成片 M / N 集 | 核心进度 | M 来自 `state.json` 各集成片；N 为 `series.md` 分集数 |
| 镜头 完成 / 总数 | 生产细节 | `state.json` / 各集 `storyboard.md` |
| 状态 | 分类筛选 | 见下方状态规则 |
| 暂停原因（一行） | 卡在哪里，点击直达 | `auto.paused.reason` |
| 更新时间 | 排序 | `state.json` |

状态只根据生产事实计算：

| 状态 | 条件 |
|---|---|
| 未开始 | 没有任何镜头任务 |
| 进行中 | `auto.task` 不为空，或有运行中的任务 |
| 已暂停 | `auto.paused` 不为空 |
| 已完成 | M = N |

一键入口：

| 入口 | 行为 |
|---|---|
| ＋ 新建项目 | 立项表单，可以 🤖 自动生成 |
| 🤖 一键补全 | `auto.task = fill`：按顺序只补空白文件（总览 → 各集剧本 → 定妆提示词 → 各集分镜 → 各集提示词），**不覆盖已有内容**，也不出片 |
| ▶ 一键生产 / ⏸ 暂停 / 继续 | `auto.task = produce`：补出缺失的角色定妆图 → 逐集提交镜头 → 合成；不改任何文字 |
| ⬇ 下载全部成片 | 打包各集最新成片和字幕 |
| 删除 | 确认后删除 |

```text
列表 ─┬─ 新建 ─▶ 立项表单 ─▶ 保存 ─▶ 项目详情
      ├─ 🤖 一键补全 ─▶ 按顺序找第一个空白文件 ─▶ assemble ─▶ 写入 ─▶ 下一个空白 … ─▶ 完成
      │                     └ 生成失败 ─▶ 暂停：“第 N 集剧本生成失败：原因” ─▶ 人处理后点继续
      ├─ ▶ 一键生产 ─▶ 出镜角色缺定妆图？─是─▶ 出图（失败重试 1 次，仍失败则暂停：去锚点）
      │                  └否─▶ 本集还有文件为空？─是─▶ 暂停：“第 N 集分镜/提示词为空”
      │                          └否─▶ 提交无任务的镜头 ─▶ 本集全部完成 ─▶ 合成 ─▶ 下一集
      │                                   └ 失败重试 1 次仍失败 ─▶ 暂停：第 N 集 S0x + 错误
      └─ ⬇ 下载全部成片
```

### 4.2 项目

| 字段 | 核心作用 | 约束 |
|---|---|---|
| 导演 | 决定风格和规模 | 必选；中途更换只影响之后的生成 |
| 名称 | 标识 | 必填，≤ 500 字 |
| 题材 | 列表展示；总览的输入 | 单行，≤ 200 字 |
| 梗概 | 故事梗概、主角与冲突 | **不写逐集走向、不写集数** |
| 封面 | 可选 | 已完成的图片素材 |

交互：表单字段就是 `project.md` 的 frontmatter，梗概就是正文。🤖 自动生成会填入名称、题材和梗概，然后保存。

- **Skill**：`drama/steps/project.md` + 导演 `SKILL.md` + `references/project.md`。
- **必须约束**：
  - 只输出 frontmatter（title、genre）加梗概正文。

### 4.3 剧本（总览 `series.md` + 分集 `script.md`）

**总览的核心内容**：

- 一句话故事、世界观。
- 角色：外观、服装与标志物、音色、性格，以及“（主角）”标记。
- 场景：空间与光线。
- 分集：标题、梗概、钩子；分集条数就是集数。

**分集剧本的核心内容**：场（场景名、出场角色）→ 行。行分为动作、对白（角色、语气、台词）、音效三类，每行带 `[L..]`，不写时间码。

增、删、合并、优化都在文本里直接完成：

| 操作 | 做法 | 下游 |
|---|---|---|
| 增行 | 写一行，不带编号 | 保存时补编号 |
| 删行 / 合并行 | 删除，或保留其中一个编号 | 引用了消失编号的镜头显示“引用已删除” |
| 改台词 | 直接改，编号不变 | 分镜显示、编译、字幕自动用新台词 |
| 增删集 | 在总览里增删分集条目 | 超出范围的集保留文件，列表只统计范围内的集 |
| 改角色名 | 全文替换（见人工决策 N1） | 定妆图按新名称重新挂接 |

按钮：🤖 生成总览、🤖 生成本集、编辑、保存。批量生成走列表页的“一键补全”。

- **Skill**：
  - 总览：`drama/steps/series.md` + 导演 `SKILL.md` + `references/series.md`；输入为 `project.md`。
  - 分集：`drama/steps/script.md` + 导演 `SKILL.md` + `references/script.md`；输入为 `series.md` + 分集条目 N + 第 N−1 集最后一场。
- **必须约束**：
  - 分集条数严格等于导演 `series.md` 的规定。
  - 至少一名主角。
  - 角色的外观、服装、音色写全，跨集不变。
  - 剧本承接上一集钩子，并落在本集钩子上。
  - 只使用总览中的角色名和场景名。
  - 对白标明角色和语气。
  - 不写时间码，不写镜头语言。
  - 篇幅与单集秒数相称。
- **Skill 修改**：`drama-planning` → `drama/steps/series.md`、`script.md`；导演 `script.md` 拆出 `series.md`。

```text
series.md 为空？─是─▶ 🤖 assemble(series) ─▶ 写入 ─┐
   │否                                              │
   ▼ ◀──────────────────────────────────────────────┘
查看总览 ─▶ 编辑 ─▶ 保存（生效）
   │
选第 N 集 ─▶ script.md 为空？─是─▶ 🤖 assemble(script)：总览 + 条目 N + 第 N−1 集最后一场 ─▶ 写入 ─┐

查看剧本 ─▶ 编辑（整集一个文本框，行带 [L..]）─▶ 保存 ─▶ 补编号 ─▶ 生效（不动分镜、不动任务）
```

### 4.4 锚点

锚点负责画面上的一致性，剧情的连贯由剧本里的钩子和“上一集最后一场”输入保证（4.3 节）。

| 锚点 | 内容 | 生成方式 | 在哪里使用 | 保证什么 |
|---|---|---|---|---|
| 角色 | 定妆提示词（`anchor.md`）+ 定妆图（`state.anchors`）；外观和音色文字仍在 `series.md` | 🤖 `assemble(anchor)` 写提示词 → 出图；可从素材库替换 | ① 主角定妆图作为首帧参考图 ② 所有出镜角色的定妆提示词进入首帧编译 ③ 所有出镜角色的外观和音色进入视频编译 | 人物长相、服装、声音跨镜跨集一致 |
| 场景 | 描述文字（`series.md`） | 来自总览，无需生成 | 视频编译时注入 | 同一地点的空间和光线一致 |
| 物件、风格、场景参考图 | **暂缓**（M6） | — | 风格由导演 Skill 在写提示词时体现 | — |

交互：

- 角色卡片显示：名称和外观（只读，来自总览，点击去总览修改）、定妆提示词（编辑，🤖 生成）、定妆图（🤖 出图 / 替换 / 查看）。
- 场景卡片只读。
- 页头：🤖 补齐空白提示词，以及“全部出图”（只为缺图的角色出图）。

- **Skill**：`drama/steps/anchor.md` + 导演 `SKILL.md` + `references/anchor.md`；输入为 `series.md` 的角色。
- **必须约束**：
  - 定妆提示词用英文，只写单人、成年、正面全身。
  - 不写背景、音色、性格。
  - 服装色系和标志物遵循导演 `anchor.md`。
- **Skill 修改**：定妆提示词规则从 `drama-planning/steps/series.md` 移到 `drama/steps/anchor.md`；导演新增 `anchor.md`。

```text
   ├─ 缺定妆图？─▶ 出图 / 从素材库替换 ─▶ state.anchors[名称]
```

### 4.5 分镜（`storyboard.md` + `prompt.md`）

**镜头表的核心内容**：`[S..]`、引用行、出镜角色（第一位是主角）、景别、运镜、时长、画面补充（只写视觉，不复述剧情）。场景由引用行所在的“场”决定。

页面的派生显示（不存储）：

- 每镜所引台词：只读，点击跳到剧本对应行。
- 时间码、本集总时长。
- “引用已删除”提示。

**镜头提示词的核心内容**：每个 `[S..]` 一组，包括视频提示词（画面和分秒节奏，**不写台词原文**，不写外观和场景）和首帧提示词（英文静态构图）。页面上的“编译预览”只读显示 `compileShot` 的结果，也就是模型实际收到的内容。

增、删、合并、拆分在 `storyboard.md` 中直接编辑：

| 操作 | 做法 | 生产 |
|---|---|---|
| 增镜 / 拆镜 | 写一个不带编号的块 | 新编号，待生成 |
| 删镜 | 删除整块 | 不再进入成片；视频留在素材库 |
| 合镜 | 保留一个编号，合并引用行 | 保留原视频，由人决定是否重拍 |
| 改已拍镜头 | 直接改 | 不清任务；由人决定是否重拍 |

`prompt.md` 按 `[S..]` 对应；分镜中已删除的镜头，其提示词段落不再使用。

按钮：🤖 生成本集镜头表、🤖 生成本集提示词（只补空白段落）、🤖 重写本镜提示词、编辑、保存。

- **Skill**：
  - 镜头表：`drama/steps/storyboard.md` + 导演 `SKILL.md` + `references/storyboard.md`；输入为本集 `script.md` + 总览角色。

- **必须约束**：
  - 镜头表：
    - 每句台词都被某个镜头引用。
    - 台词量与时长相称（≤ 时长 × 5 字）。
    - 单镜时长在导演规定的范围内。
    - 主角放在第一位。
    - 画面补充不复述剧情。
    - 总时长接近导演规定的单集秒数。
  - 提示词：
    - 不写台词原文，只写谁在第几秒开口。
    - 不写外观和场景描述。
    - 按分秒写动作和运镜。
    - 画面不出现文字。
    - 首帧只写静止画面。
- **Skill 修改**：`shot-planning` → `drama/steps/storyboard.md`、`prompt.md`；导演 `storyboard.md` 拆出 `prompt.md`；删除导演 `shot-prompt-example.md`。

```text
   │否                                                     │
```

### 4.6 成片

| 字段 | 核心作用 | 来源 |
|---|---|---|
| 分集目录 | 选集；显示“镜头 x/y · 是否已有成片” | `state.json` |
| 镜头网格 | 缩略图、状态、第几条 | `storyboard.md` 的镜头 + `state.json` |
| 镜头详情 | 视频、首帧、编译后的提示词、错误信息 | `state.json` + `compileShot` |
| 成片 | 视频、字幕、时长、生成时间；历史成片可播放、可下载 | `state.json` |

交互：

- 镜头：
  - 重拍此镜：换新种子，旧视频留在素材库。
  - 恢复原任务：只适用于基础设施故障。
  - 去改分镜 / 去改剧本：跳到对应的镜头或行。
- 成片：
  - 本集镜头全部完成后自动合成，也可以手动点“合成本集”。
  - 播放、下载视频和字幕。

成片本身不需要编辑，调整都回到分镜去做。每集有成片即算完成，满意与否由人判断，不设验收状态。

- **Skill**：不需要。
- **必须约束**：
  - 按 `storyboard.md` 的镜头顺序合成。
  - 字幕取自所引剧本行，时间按实际视频时长分配（沿用 `film.js` 现有算法）。
  - 所有镜头都完成才能合成。
  - 已有成片不会因为改稿而被删除。

```text
一键生产 / 逐镜提交 ─▶ compileShot(S) ─▶ 首帧图（主角定妆图作参考）─▶ 图生视频
   │                                                   └ 失败 ─▶ 重试 1 次 ─▶ 仍失败则暂停
   ▼
本集全部完成 ─▶ 合成（按镜头顺序；字幕取自所引行）─▶ 成片
   │
人看成片 ─┬─ 满意 ─▶ 下一集 / 下载
          └─ 不满意 ─▶ 点击镜头 ─┬─ 画面偶然不好 ─▶ 重拍 ──────────────┐
                                ├─ 画面描述不对 ─▶ 去改分镜/提示词 ─▶ 重拍 ─┤
                                └─ 台词/情节不对 ─▶ 去改剧本 ─▶ 重拍 ───────┴─▶ 自动重新合成
```
