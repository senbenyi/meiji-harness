# 规划器按阶段拆分

- 类型：重构（完整流程：涉及 3 个以上文件，改动关键业务流程的规划入口）
- 目标：把 `shared/run-planner.js` 的 `planRun` 从一个按阶段分支的大函数，拆成「阶段信息表 + 每阶段一个展开函数」，规划结果保持不变。
- 非目标：不改变任何目标规划出的步骤、依赖、前置、删除清单和阻断；不改 Run 引擎、run-service 的调用方式和 `planRun` 的签名与返回结构；不把步骤规划交给 AI；不改 `normalizeRunGoal` 的校验规则。
- 实施时机：先于 [1006-计划-面板会话联动](1006-计划-面板会话联动.md) 实施。该计划改为「任务停下即结束、接着做 = 以原目标新开任务」，依赖规划器正确跳过已完成对象，需先用本计划的等价快照锁住规划行为。开始前须等工作区进行中的「被动中断直接结束任务」改动提交（其中 `run-planner.js` 每秒指令续做规则有改动，快照以提交后的行为为准）。

## 背景

`planRun`（`shared/run-planner.js:13-186`）约 175 行，主循环里每个阶段一个 `if/else` 分支，阶段完成判断、前置文案、依赖特例分散在不同位置。今天的 AC-21 缺陷（见 Run 重构计划「会话直接执行与循环报错修复」）就来自共用的 `text()` 位置参数 `regenerateOnly` 被扩大使用，悄悄改变了剧情是否完成的判断，镜头表因此一直停在 `prereq_required`。

规划逻辑本身是业务规则（尾帧衔接、引用图片确认、逐镜修订基稿、剧情先大纲后人物/场景再道具），继续由代码负责；本计划只调整代码组织。
