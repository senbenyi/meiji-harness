# 会话按目标编排节点

- 状态：未实施
- 类型：会话编排
- 档位：分阶段。先让生成结果在步骤结束时落库，并让会话看见真实步骤；再加目标与沿主路径提交；上游修补和重新确认放在后面
- 目标：用户在会话中给出成品目标时，会话模型按现有主路径一次提交一个前置已满足的节点，并等该节点任务的终态再决定下一步。节点内部步骤由节点代码决定。生成或修订一旦交出可写入的结果，就由正在执行的任务写入项目，不交给主 agent，也不因后面的步骤或断网撤回
- 非目标：不让主 agent 重排节点内部步骤。不让会话模型或生成模型改写 `project.json`，也不把中间结果交回主 agent 再写。不把整份项目放进节点生成提示词。不让模型代替依赖指纹判断谁过期。不在导入时预排每一镜。不自动生成项目摘要、剧集摘要和定妆照。不用 Harness `/goal` 或后台任务充当制作编排

## 主 agent 与子任务

会话模型是主 agent。它看不见制作源码，每轮只有 `meiji-workflow` 技能、用户原话和工具摘要。用户给出成品目标后，它提交一个节点任务并结束本轮；该任务的终态送回后，再决定下一项。剧集 id、镜头 id 来自上一步结果，导入时不排死每一镜。

每个节点任务是子任务，不是另一个会聊天的 agent。步骤表在 `shared/task-plan.js` 的 `stepKinds`，有没有程序审核、AI 审核由 `shared/node-definitions.js` 决定。某个节点可以没有前置检查，也可以没有审核：图片节点不审核，合片是前置检查加生成，剧本审核任务只有前置检查和审核，按意见修改才先改写再审核。主 agent 不看中间稿，不代写该节点提示词，也不增删这些内部步骤。项目写入串行，一个子任务完成后再开下一个。

调用模型的只有该任务里执行者是 AI 的步骤：文本或媒体的生成、修订，以及 AI 审核。前置检查、程序审核、影响面、写回和参数编排是同一条子任务里的代码，不算另一个 agent。

送回主 agent 的终态摘要只有：完成、未通过或失败；新产生的剧集 id 或镜头 id；未通过原因；上游问题的来源、位置、依据和建议；这次写入后实际过期的节点。不含生成全文、历史提示词和图片。

## 生成结果何时写入项目

SQLite 是源。`project.json` 只投影 `snapshot.project`，不包含任务步骤。步骤行上的 `result` 因此还不等于项目正文。

生成或修订步骤返回、并且这份结果可以作为节点内容写入时，`TaskService` 在下一步开始之前，经现有仓库事务把它写入对应节点，提交后再投影 `project.json`。程序审核、AI 审核、下一次网络请求都发生在这次写入之后。后面的审核未通过、断网、进程中断或主 agent 不在线，都不参与这次写入，也不把已经落下的内容删掉。

模型不调用 `TaskService`，也不写 JSON。主 agent 只在终态摘要里得知结果，不接收这份正文再去改项目。

生成这一步本身没有可写入的产出时，仍不覆盖节点内容。这包括前置检查失败，以及发生在拿到结果之前的网络、接口、JSON 解析或结构不完整。

依赖过期仍由 `expireDownstream` 按依赖指纹计算，放在任务到达终态时。内容先在项目里，下游不在审核尚未结束时被提前打过期。进程若在落库之后、终态之前退出，恢复时按已写入内容补算过期。

这替换现在的内存 `draft`。现在正式内容要等整段步骤走完，或修订次数用尽且没有结构错误，才 `#commitOutput`；上游问题和无进展不提交。生成已经成功、后续步骤失败时，失败分支不写 `project.json`。

## 未通过归因

三类都由主 agent 判断。子任务只交证据：程序审核原文，AI 审核的是否通过和 `问题`，以及修订前后候选有没有变化。程序核对上游依据是否真的出现在所声明的资料里。生成模型和审核模型不判断「是能力不够」或「是规则冲突」。

- 上游问题：`修复范围` 是上游，且依据能在该来源里对上。停掉本节点自动修订。生成结果已经在项目里，任务仍为未通过。目标收下 `问题` 的来源、位置、依据和建议，只改那一处，再按终态时的过期名单回来。
- 模型结果不正确：程序审核已通过，AI 仍拒绝，但依据在候选里已经存在，或位置超出实际条目数；或修订后候选几乎没变、同一条意见又出现。先换修订方式，例如局部修订对不上就改整表替换。仍然如此就停止，不再空转。已落下的内容保留。
- 程序规则冲突或缺陷：模型已按契约返回，程序仍拒绝，且换修订方式后还是同一条程序错误。主 agent 留下这条程序原因并停止该目标，不把它当成内容问题再改一轮，也不修改规则本身。

## 会话里怎么看见

用户目标卡片下面，按实际发生列出该目标已经跑过的步骤：名称、状态、失败原因。步骤一开始、一结束就更新。这是任务步骤状态的只读投影，主 agent 不转发每一步的正文。

不打印模型思考、完整提示词和生成正文。

弹框并停住后续任务，只在必须由人选择时：这一轮是继续修订还是人工放行；程序规则冲突，目标停止；删除或其它已经阻塞、只能由人决定的选择。模型结果不正确，以及沿过期名单自动修补上游，都不弹框。

节点任务记在项目 SQLite 里。关掉会话不取消这些任务。Harness `/goal` 只武装同一会话的后续轮次，后台任务会随会话销毁被取消，两者都不是这条制作队列。

## 行为

- 面板按钮和会话都创建同一种目标，例如「做完成片」。目标记录原始节点、意见、参考单集时长和当前停住的上游问题。目标不代替任务组。
- 会话每次只提交依赖已经满足的下一个节点或现成任务组。剧集数等切集结果，镜头数等镜头表。
- 「按剧本生成视频，每集大概 3 分钟」把 `reference_episode_duration_seconds` 写成 180。各集正式时长仍以切集结果为准。顺序是：写入剧本并等待自动剧本审核 → 提取剧集 → 提取人物 → 按集做故事大纲、选择性提取场景、镜头表 → 按集提交 `episode-film` 成片组 → 视频齐备后由现有规则追加合片 → 下一集从大纲继续。
- 过期节点先走重新确认：正文仍符合新上游时，只重写依赖指纹并回到已生成，不调用生成模型。对不上的才提交现有生成或修订。然后回到原目标。连续上游修补有次数上限，超过则停住并说明。
- 面板增加一行目标状态。节点卡片仍显示该节点自己的任务组状态。会话目标卡片另列步骤，见上一节。

## 会话每轮输入输出

技能保持主路径、时长字段和「一次一个节点」。查询返回绑定、节点状态、当前任务状态和上游问题，不返回历史提示词、图片和整份步骤。

示例：

1. 用户给出剧本和成片目标。模型调用查询，得到未绑定。
2. 模型调用创建项目，带上剧本和 180 秒。返回项目 id 和剧本审核已排队。模型告知用户后结束本轮。
3. 审核终态作为下一轮输入送回会话。通过则提交 `script-split`。
4. 之后每收到一个终态摘要，再提交主路径上的下一项。全部完成时只回复结果，不再发任务。

当前缺口：`meiji-context-query` 返回整份快照；技能禁止自动提交下一步；任务完成只出提示卡，不唤醒会话；生成结果留在内存，要等任务终态才进入 `project.json`。

## 阶段

1. 会话查询改为状态摘要。`meiji-context-query` 不再返回 `repository.read()` 全量快照。
2. 生成或修订交出可写入结果后，由 `TaskService` 在下一步开始前写入节点并投影 `project.json`。后续失败不回滚。没有产出的错误仍不覆盖。依赖过期留到任务终态。
3. 增加目标记录。面板和会话的明确成品请求都写入目标，尚不自动串联。
4. 目标进行中的任务进入终态时，把终态摘要送回该会话，唤醒主 agent。摘要含任务 id、状态、原因、上游问题和本次过期节点。
5. 会话在用户目标卡片下列出已发生步骤的名称、状态和失败原因。必须人工选择时弹框并停住后续任务。
6. 按主路径懒提交下一节点。更新 `skills/session/panel.md`：明确的成片目标可以提交前置已满足的下一步；前置不足仍报告原因，不发明节点内部步骤。更新 `制作工作流.md`：会话展示目标步骤；人工选择才停住后续任务；生成结果在步骤结束时落库。
7. `upstreamFailure` 把结构化问题挂到目标上。剧本、剧情、大纲补局部修改。新增重新确认。编排器只遍历本次过期名单，并限制上游跳转次数。
8. 面板显示目标行。

## 验收

- 会话查询的结果不含步骤提示词和图片，且能看出节点是否已生成、未通过或已过期。
- 生成或修订步骤成功后，即使后续审核失败或连接断开，该结果已在 SQLite 和 `project.json` 的对应节点里。主 agent 未醒来时也是如此。
- 生成步骤本身没有产出时，原节点内容保持不变。
- 导入剧本并要求按约 3 分钟一集生成视频后，未绑定会话会创建项目、写入 180 秒，并在审核通过后自行提交切集；摘要和定妆照不会被提交。
- 任务终态会进入原会话的下一轮，而不是只留在面板提示卡。摘要足以让主 agent 区分上游问题、模型结果不正确、程序规则障碍，且不含节点生成全文。
- 用户目标卡片能看到已经发生的步骤名、状态和失败原因。只有修订或放行、程序规则停住、以及必须人工决定的阻塞会弹框。
- 镜头审核标明上游某一句时，只修改该句；指纹未变的节点保持已生成；过期但正文仍符合的节点经重新确认恢复，不重新生成。已落下的本节点内容不被这次上游修补删掉。
- 节点生成提示词的输入范围与改动前一致。节点有哪些步骤仍由 `stepKinds` 和节点定义决定。
