# 结构设计与面板流程

当前结构设计入口为 `../data/a_drama_detail.json`，采用字段名对应用途说明的普通JSON；设计文档不作为运行配置读取。新模型定义已实现；改编规划节点已接入运行，其余节点按各自现行契约运行。

前四步依次为改编规划、故事分段、核心资产准备、分镜。

- 核心资产准备只整理核心人物、核心服装、核心道具和核心场景。服装使用clothes数组，说明款式、颜色、材质、穿着层次与配饰。各资产image_id引用真实共享图片，也允许为空；缺图可生成、导入或不生成，不要求所有核心资产提前有图。
- 分镜的人物、服装、道具和场景是该镜头需要出镜或在动作中使用的内容，四类结构统一只保留id、name、description、image_id。id为可空的核心资产引用；已有核心资产直接复用，没有时用名称和完整固定特征描述表达，不要求先建核心资产或生成图片。
- characters、clothes、props为镜头级数组，scene为镜头级对象；clothes不嵌套在人物内，不固定绑定穿着者。description只描述人物固定外貌、服装款式材质、道具形态和场景固定布局，不包含动作、状态变化、衣物穿脱或道具持有传递。
- 穿着、换装、道具持有和传递、人物表情姿态以及天气光线等变化统一放入beats；通过名称明确涉及的人物、服装和道具。首个节拍交代开场状态，最后一个节拍交代结束状态供下一镜衔接，删除镜头级ending_state避免重复。visual_description只说明静态构图和叙事重点。
- 对白中的speaker_name支持非核心说话人物；画外音和旁白不自动成为出镜人物。image_id始终只引用真实图片且可为空。
- 图片素材引用并入分片编排。编排汇总实际采用的reference_images及首尾帧，标明用途和对应镜头；未采用的缺图项目不写入参考图数组。实际需要图片的生成模式仍需具备相应输入；可不生成的图片，不作为流程统一阻断条件。
- 图片生成是盒子内按需调用的步骤，可与复用、导入、选图共同使用，不设置独立图片生成或图片素材引用盒子。生成执行、失败与取消事实应由真实Task/Step记录；项目产物只引用实际图片，不预填或伪造图片id。

面板显示九个主流程节点：改编规划 → 故事分段 → 核心资产准备 → 分镜 → 分片编排 → 视频提示词 → 视频生成 → 视频剪辑 → 分集导出。剧本资料位于制作流程上方，仅保留短剧与原稿。原著解析与图片素材引用不提供独立面板入口，旧选择回到改编规划。

新模型模块为 `src/drama_runtime/drama_model.js`，由 `src/index.js` 公开 `dramaModelSchema`、`createDramaModel({id,title,aspect_ratio,origin_script})`、`assertDramaModel(model)`。初始化生成九个节点及空产物；节点统一为 id/type/data/state，数组按保存顺序表达故事段顺序。校验严格拒绝额外字段并核对内部引用、重复ID、生成模式与媒体时间范围，返回独立副本。临时资产id与图片引用使用null表示空值；对白speaker_id可为空，speaker_name必填，现场对白说话人需出镜。

草案引用的 `delivery.json`、`drama_detail_shared.json` 尚未提供：交付节点暂采用现有episodes/delivery产物，状态与图片/声线引用暂沿用现有明确字段；不将这些补充视作草案已确认的新增规格。video_editing节点内id遵循editing.json为editing；video_delivery暂用delivery。结构校验不证明图片、音频或引用文件实际存在，接入时仍需存储层核实。

改编规划右侧面板由 `src/node_box/adaptation_plan/ui/plan-panel.js` 维护：改编定位的受众与风格使用简单的键值行展示，各自提供编辑入口；故事方向包含主线方向、必须保留的情节与创作约束，人物/团队/场景规划按原著内容和改编方案成对展示。内容采用无独立卡片边框的排版，以标题和留白分区；不提供添加人物、团队、场景规划的入口。已有规划项不要求名称字段或ID，编辑按列表位置处理；支持编辑、删除、空态和段内换行，保存失败保留表单内容。

本轮接通改编规划的展示、人工保存、生成、独立审核及修订。运行文档暂保留现有顶层外壳，adaptation_plan字段完整保存id/type/data/state；业务data直接引用新模型Schema，状态只在该节点内保存。此节点不保存或校验revision、source_revision_id、product_revision；不要求expected_revision。共享入口通过projectNodeStates读取状态，其他节点的既有状态机制保持各自契约。人工编辑清理该节点检查点，任务归属、活动任务互斥、请求幂等及不可变执行记录继续生效。

故事定稿读取冻结的新规划data，不再记录或比较adaptation_revision。改编规划不自动创建资产：规划每项仅有original_content/adaptation_plan，后续资产使用自身ID，当前资产结构的character_plan_id/scene_plan_id为空。其他节点的完整新结构改造不属于本轮，不将当前节点接通宣称为九节点运行流程全部切换。

改编规划的输入直接采用导入的剧本原件：单元范围来自当前原稿的完整字符数，source_ref指向实际不可变原稿文件。无需先执行原著解析；read_source在此节点直接分页读文件，read_file也可按source_ref读取。生成、独立审核和修订均需完整阅读原件；仅读取解析正文、摘要、快照或检索片段不能满足覆盖要求。分页上限、单轮预算、冻结输入与真实读取记录继续生效，其他节点的读取策略保持现行契约。

“查看规则”进入面板内详情页，使用生成规则、审核规则、修订规则、输出格式四个tab展示production-rules返回的完整内容；不打开dialog，不以补充规则代替完整规则。详情页支持键盘切换、加载失败重试和返回原制作步骤，异步响应在返回或销毁后不得覆盖页面。编辑补充规则继续使用现有编辑入口。
