# 结构设计与面板流程

当前结构设计入口为 `../data/a_drama_detail.json`，采用字段名对应用途说明的普通JSON；设计文档不作为运行配置读取，尚未替换现有V4运行契约。

前四步依次为改编规划、故事分段、核心资产准备、分镜。

- 核心资产准备只整理核心人物、核心服装、核心道具和核心场景。服装使用clothes数组，说明款式、颜色、材质、穿着层次与配饰。各资产image_id引用真实共享图片，也允许为空；缺图可生成、导入或不生成，不要求所有核心资产提前有图。
- 分镜的人物、服装、道具和场景是该镜头需要出镜或在动作中使用的内容，四类结构统一只保留id、name、description、image_id。id为可空的核心资产引用；已有核心资产直接复用，没有时用名称和完整固定特征描述表达，不要求先建核心资产或生成图片。
- characters、clothes、props为镜头级数组，scene为镜头级对象；clothes不嵌套在人物内，不固定绑定穿着者。description只描述人物固定外貌、服装款式材质、道具形态和场景固定布局，不包含动作、状态变化、衣物穿脱或道具持有传递。
- 穿着、换装、道具持有和传递、人物表情姿态以及天气光线等变化统一放入beats；通过名称明确涉及的人物、服装和道具。首个节拍交代开场状态，最后一个节拍交代结束状态供下一镜衔接，删除镜头级ending_state避免重复。visual_description只说明静态构图和叙事重点。
- 对白中的speaker_name支持非核心说话人物；画外音和旁白不自动成为出镜人物。image_id始终只引用真实图片且可为空。
- 图片素材引用并入分片编排。编排汇总实际采用的reference_images及首尾帧，标明用途和对应镜头；未采用的缺图项目不写入参考图数组。实际需要图片的生成模式仍需具备相应输入；可不生成的图片，不作为流程统一阻断条件。
- 图片生成是盒子内按需调用的步骤，可与复用、导入、选图共同使用，不设置独立图片生成或图片素材引用盒子。生成执行、失败与取消事实应由真实Task/Step记录；项目产物只引用实际图片，不预填或伪造图片id。

面板显示九个主流程节点：改编规划 → 故事分段 → 核心资产准备 → 分镜 → 分片编排 → 视频提示词 → 视频生成 → 视频剪辑 → 分集导出。剧本资料位于制作流程上方，仅保留短剧与原稿。原著解析与图片素材引用不提供独立面板入口，旧选择回到改编规划。

本轮仅调整设计JSON和面板导航。现有核心资产/分片执行器、运行Schema、保存校验与主Agent工具仍按现有V4工作，不将导航调整宣称为新运行流程已经实现。
