# 开发方向

- 状态：方向已定。开发阶段另定，当前先做基础代码。
- 目标：按固定节点图制作。会话模型担任主 agent，负责编排和项目审核；AI 盒子由对应子 agent 执行并直接保存，程序盒子由主 agent 调用代码。
- 非目标：不改 meiji 的运行链和项目数据。不把节点目录、审核结论、授权放进公共包。不让用户在面板上改连线。不把整份项目、图片文件或视频文件交给主 agent。不设修订回合上限。不自动生成定妆照和场景图。程序契约不能被规则文本改写。

运行时AI字段以 [node_definitions.js](../src/project/node_definitions.js) 为准，[project_detail.json](project_detail.json) 仅作开发结构说明。[会话按目标编排节点.md](会话按目标编排节点.md) 不作为当前方向。

## 盒子

面板只显示节点状态和当前目标。面板点击和会话都创建目标。点击是短目标，已经点名一只盒子和动作，前置不满足就停下。会话里的成片请求是长目标，主 agent 沿主路径一次提交一只前置已满足的盒子，等终态后再决定下一只。

主路径：

```text
剧本优化（仅用户要求改编时）
  → 故事分段
  → 人物提取
  → 场景提取
  → 镜头设计
  → 分片编排
  → 视频提示词
  → 分片视频
  → 合片
```

人物提取和场景提取按顺序各跑一只盒子。定妆照、场景图只有用户点名才执行。分片视频里，首尾帧模式等前片尾帧可用后再提交。项目写入串行，同一时刻只跑一只盒子。

| 盒子 | 执行者 | 模型 |
|---|---|---|
| 剧本优化、故事分段、人物提取、场景提取、镜头设计、视频提示词 | 子 agent | 文本模型 |
| 定妆照、场景图 | 子 agent | 图片模型 |
| 分片视频 | 视频接口 | 视频模型 |
| 分片编排、合片 | 程序代码 | 无 |

子 agent 只看到代码装好的本盒子输入和本节点规则。内部完成生成、程序校验、审核和修订。得到可写入结果就保存自己的字段。本地审核通过后才把终态交给主 agent。内容和规则没有变化而同一失败再次出现时，停止修订，保留最后一次已保存内容，节点标为未通过。

## 项目审核

主 agent 在保存之后做项目审核。审核包只有：这次新结果、这次实际引用的上游节点、当前目标、这只盒子的规则。结论只取一种：

- 通过：长目标继续下一只盒子；短目标结束。
- 上游问题：只提交那一个上游盒子，意见只含这一处。上游写入后按过期名单回到原目标；正文仍符合的只重新确认。
- 规则冲突：输出规则差异并停住。人授权后才写入该动作的规则并重试这只盒子；拒绝则规则不变，目标停住。
- 本节点内容不对：把意见交回这只盒子修订。

没有被这次引用的节点不进入审核包。下游只提供过期名单，不提供旧正文。图片和视频文件不进入审核包，只核对是否对应到该人物、服装、场景或分片。程序盒子不做项目审核，主 agent 只看终态。

项目审核未通过时，已保存内容保留，节点标为未通过。过期由依赖指纹计算。

| 刚保存的盒子 | 审核包中的其他节点 |
|---|---|
| 故事分段 | 原始剧本、剧本优化稿 |
| 人物提取 | 故事分段 |
| 场景提取 | 故事分段 |
| 定妆照 | 对应人物和对应服装 |
| 场景图 | 对应场景 |
| 镜头设计 | 引用到的故事分段、人物、场景 |
| 视频提示词 | 对应分片、来源镜头、用到的人物图和场景图；首尾帧另加前片尾帧 |
| 分片视频 | 只核对对应的视频提示词和选定参考，不读取视频文件 |

## 规则与授权

规则以项目内保存的文本为准。代码规则只在盒子第一次建立时写入生成、审核、修订各一份；之后代码更新不覆盖项目。三份规则互不引用。输出字段、分片时长 4–15 秒、节拍完整覆盖一次、依赖指纹和落库时机是程序契约，冲突时作为程序障碍停住。

授权只有两处，都在会话里停下，面板只显示已停住：

- 改规则。
- 重做已有视频。上游或规则变化使已有视频过期时，列出分片后等待授权。文本、图片和程序盒子过期后直接重做。目标要求的第一次出视频不另要授权。

基本信息、原文和参考图的编辑是改项目数据，不创建目标。

设置里的会话模型只用于主 agent。文本、图片、视频模型分别用于对应盒子，同一类盒子共用一个模型。

## 完成时要满足

- 新建 AI 盒子时写入三份规则；之后执行读取项目规则，代码默认不再覆盖。
- 子 agent 的提示词只含本盒子输入和本节点规则；可写入结果先落库，本地审核通过后才进入项目审核。
- 同一失败再次出现，且内容和规则都未变时，停止修订并保留最后内容。
- 项目审核只看规定的审核包，并只返回通过、上游、规则、本节点内容四种结论之一。
- 面板点击只创建该短目标；前置不满足时停住，不执行上游。
- 会话要求按约 3 分钟一集做成片时，参考时长写为 180 秒，并沿主路径推进，不自动定妆、不自动生成场景图。
- 分片编排和合片只执行程序代码；契约失败作为程序障碍停住。
- 已有视频过期后列出分片并等待授权；空视频的第一次生成直接调用。
- 会话模型只用于主 agent，三类制作模型分别用于对应盒子。

## AI输出定义与规则引用

文本节点的AI结果统一保存于 `output`：剧本优化为 `script_revision.output`，故事分段为 `story_segments.output.segments`，人物为 `character_extraction.output.characters`，场景为 `scene_extraction.output.scenes`，镜头为 `shot_design.output.shots`，视频提示词为 `video_prompt.output.items`。人工意见、参考图、规则和状态留在外层。

人物的原始参考图与照片槽位保存在 `character_extraction.assets[]`，通过 `character_id` 关联人物；照片节点位于各资产记录的 `costume_images[]`。场景图片节点保存在 `scene_extraction.assets[].image_generation`，通过 `scene_id` 关联场景。提取结果更新后，由程序按稳定ID维护资产对应关系，不让AI返回或覆盖图片地址、照片规则和节点状态。

`video_prompt.output.items` 只含分片关联与已选模式的 `prompt`，三个示例代表互斥模式，每个分片只返回一种。AI输出定义只引用既有 `$defs` 中对应模式的 `prompt` 部分；视频接口的完整请求定义、参数处理及程序执行保持原状，不新增bindings或改变视频生成节点。

`project_detail.json` 只用于开发阅读，不被src运行时代码读取。运行时唯一字段来源是 [node_definitions.js](../src/project/node_definitions.js)：字段结构、类型、必填、枚举和基本含义。`skills/*.json` 负责生成依据、审核判断和修订联动，不复制输出Schema。修改运行时字段后同步更新开发文档；文档变化本身不改变运行行为。

规则仍以 `{{output:#/script_revision/output}}` 一类JSON Pointer引用运行时定义。生成/修订引用本节点output；审核引用 `#/$defs/review_output`；图片生成/修订引用 `#/$defs/image_output`。`renderNodeRules(model, action)` 可展开引用供查看；它默认引用运行时定义，不再提供definitionFile或读取文档。需要隔离的配置测试可通过definition参数传入同结构定义对象。

基础链路入口均由 `src/index.js` 导出：

- `createNode(nodeType, { rules?, definition? })`：创建空AI节点，默认从该节点skill复制规则，也可显式保留传入的项目规则。状态使用公共NodeStateModel；人工字段和assets与output分开。空节点的零时长只是初值，不代表生成结果已通过验证。
- `composeNodePrompt({ nodeType, action, rules, input, goal?, definition? })`：按当前动作注入本节点有效业务规则、本次已筛选资料和程序输出契约，返回公共prompt-composer生成的messages/system/user/body。规则与资料不会被再次当作模板解释，输出契约只注入一次；跨节点或动作的输出引用明确拒绝。修改意见、语言、基稿和真实引用上游由调用方放进input；不自动读取整个项目。
- `parseNodeOutput(nodeType, action, response, { definition? })`：解析JSON并调用同源结构校验；已解析对象可直接交 `validateNodeOutput`。返回数据副本，不自动落库，不覆盖人工意见或资产。生成/修订的合法文本结果写入该节点output；审核结果用于判断，不写入业务output。

校验支持本项目使用的类型、必填、额外字段禁止、数字范围、非空文本、枚举、数组容量及oneOf互斥结构；新增不支持的Schema关键字会明确失败。审核通过必须没有问题，其他结论须有具体问题。这里只负责结构，剧情依据、素材对应、跨节点ID关系和分片mode是否匹配等业务条件由后续执行器核验。图片返回仍由实际媒体接口适配器处理，JSON校验拒绝虚构图片地址；视频接口及程序节点不参与这次改动。

示例：

```js
const node = await createNode('script_revision');
const request = composeNodePrompt({
  nodeType: 'script_revision', action: 'generate', rules: node.rules,
  input: { script: originalScript, requirements: userRequirements },
});
// 调用模型后，先校验，再通过ProjectManager保存本节点内容。
const output = parseNodeOutput('script_revision', 'generate', responseText);
manager.change(project => { project.script_revision.output = output; });
await manager.model.update();
```

基础链路已实现，真实模型调用、节点执行器、完整项目创建流程和旧数据迁移尚未接入。已保存业务规则仍以项目为准，初始化默认不覆盖既有项目。

## 会话与项目工作区

没有工作区时，面板通过认证的 `/api/drama/sessions` 接口准备未绑定会话，用户可以直接输入。会话拥有独立工作目录，尚未登记工作区或创建项目。创建请求ID持久保存在 `bindings.json`，重试沿用同一会话。

面板与 `drama-create-project` 共用项目创建入口。创建项目时保存 JSON、登记以项目名称命名的工作区，并为该工作区新建标准模式会话；成功后面板切换到新会话。只有新会话关联新项目，源会话的项目归属与消息保留，允许从已有项目会话创建其他项目。重复创建请求沿用原项目、工作区和预先保存的新会话ID。


项目插件不提供独立的短剧模式。默认使用 Harness 标准模式；标准、PTC、极简、创造等模式保留自己的原有配置，共享 `drama-create-project` 工具和项目创建指导。业务指导以独立提示词段落注册，不覆盖模式的身份或通用工具；极简模式遵循宿主的完整身份提示，仍通过工具说明了解业务调用要求。无工作区准备的会话与项目创建后的新会话均使用标准模式。卸载项目工具插件时，共享工具与业务指导一起移除。
