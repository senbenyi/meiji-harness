# 开发方向

- 状态：方向已定。开发阶段另定，当前先做基础代码。
- 目标：按固定节点图制作。会话模型担任主 agent，负责编排和项目审核；AI 盒子由对应子 agent 执行并直接保存，程序盒子由主 agent 调用代码。
- 非目标：不改 meiji 的运行链和项目数据。不把节点目录、审核结论、授权放进公共包。不让用户在面板上改连线。不把整份项目、图片文件或视频文件交给主 agent。不设修订回合上限。不自动生成定妆照和场景图。程序契约不能被规则文本改写。

运行时AI字段由各 `src/node_box/<节点名>/definition.js` 维护，经 [node_definition_registry.js](../src/node_runtime/node_definition_registry.js) 汇总，[project_detail.json](project_detail.json) 仅作开发结构说明。“会话按目标编排节点”旧方案 不作为当前方向。

## 盒子

面板只显示节点状态和当前目标。面板点击和会话都创建目标。点击是短目标，已经点名一只盒子和动作，前置不满足就停下。会话里的成片请求是长目标，主 agent 沿主路径一次提交一只前置已满足的盒子，等终态后再决定下一只。

主路径：

```text
剧本优化（仅用户要求改编时）
  → 故事分段
  → 场景提取
  → 团队设定（基本形象与共同服装）
  → 人物提取（含个人服装与团队引用）
  → 镜头设计
  → 分片编排
  → 视频提示词
  → 分片视频
  → 合片
```

场景提取放在人物提取之前；场景提取已接独立执行器，要求故事大纲存在；团队设定同样要求大纲存在，有场景资料时一并参考，不以场景生成作为硬前置。团队设定和人物提取各自独立生成、审核及修订；团队通过后执行人物，无团队时也先由团队盒子返回空集合并审核通过。定妆照、场景图只有用户点名才执行。分片视频里，首尾帧模式等前片尾帧可用后再提交。项目写入串行，同一时刻只跑一只盒子。

| 盒子 | 执行者 | 模型 |
|---|---|---|
| 剧本优化、故事分段、团队设定、人物提取、场景提取、镜头设计、视频提示词 | 子 agent | 文本模型 |
| 定妆照、场景图 | 子 agent | 图片模型 |
| 分片视频 | 视频接口 | 视频模型 |
| 分片编排、合片 | 程序代码 | 无 |

子 agent 只看到代码装好的本盒子输入和本节点规则。内部完成生成、程序校验、审核和修订。得到可写入结果就保存自己的字段。审核终态单独记录；内容审核未通过时等待用户操作。内容和规则没有变化而同一失败再次出现时，停止修订，保留最后一次已保存内容，节点标为未通过。

## 项目审核

主 agent 在保存之后做项目审核。审核包只有：这次新结果、这次实际引用的上游节点、当前目标、这只盒子的规则。结论只取一种：

- 通过：长目标继续下一只盒子；短目标结束。
- 上游问题：只提交那一个上游盒子，意见只含这一处。上游写入后按过期名单回到原目标；正文仍符合的只重新确认。
- 规则冲突：输出规则差异并停住。人授权后才写入该动作的规则并重试这只盒子；拒绝则规则不变，目标停住。
- 本节点内容不对：把意见交回这只盒子修订。

没有被这次引用的节点不进入审核包。下游只提供过期名单，不提供旧正文。图片和视频文件不进入审核包，只核对是否对应到该人物、服装、场景或分片。程序盒子不做项目审核，主 agent 只看终态。

项目审核未通过时，已保存内容保留，节点标为未通过。过期由依赖指纹计算。

| 刚保存的盒子 | 审核包中的其他节点 |
|---|---|
| 故事分段 | basic_info.actual_script当前工作稿 |
| 团队设定 | 故事分段、已有场景资料（可为空） |
| 人物提取（含个人服装） | 故事分段、已确认团队、已有场景资料（可为空） |
| 场景提取 | 故事分段 |
| 定妆照 | 对应人物、关联团队基本形象与选定制服、个人服装差异 |
| 场景图 | 对应场景 |
| 镜头设计 | 引用到的故事分段、团队、人物、服装和场景 |
| 视频提示词 | 对应分片、来源镜头、用到的人物图和场景图；首尾帧另加前片尾帧 |
| 分片视频 | 只核对对应的视频提示词和选定参考，不读取视频文件 |

## 规则与授权

规则以项目内保存的文本为准。代码规则只在盒子第一次建立时写入生成、审核、修订各一份；之后代码更新不覆盖项目。三份规则互不引用。输出字段、分片时长 4–15 秒、节拍完整覆盖一次、依赖指纹和落库时机是程序契约，冲突时作为程序障碍停住。

授权只有两处，都在会话里停下，面板只显示已停住：

- 改规则。
- 重做已有视频。上游或规则变化使已有视频过期时，列出分片后等待授权。文本、图片和程序盒子过期后直接重做。目标要求的第一次出视频不另要授权。

基本信息、原文和参考图的编辑是改项目数据，不创建目标。

设置里的会话模型只用于主 agent。文本、图片、视频模型分别用于对应盒子，同一类盒子共用一个模型。

## 完成时要满足

- 新建 AI 盒子时写入三份规则；之后执行读取项目规则，代码默认不再覆盖。
- 子 agent 的提示词只含本盒子输入和本节点规则；可写入结果先落库，本地审核通过后才进入项目审核。
- 同一失败再次出现，且内容和规则都未变时，停止修订并保留最后内容。
- 项目审核只看规定的审核包，并只返回通过、上游、规则、本节点内容四种结论之一。
- 面板点击只创建该短目标；前置不满足时停住，不执行上游。
- 会话要求按约 3 分钟一集做成片时，参考时长写为 180 秒，并沿主路径推进，不自动定妆、不自动生成场景图。
- 分片编排和合片只执行程序代码；契约失败作为程序障碍停住。
- 已有视频过期后列出分片并等待授权；空视频的第一次生成直接调用。
- 会话模型只用于主 agent，三类制作模型分别用于对应盒子。

## AI输出定义与规则引用

文本节点的AI结果直接保存在项目业务字段：剧本优化为 `basic_info`，故事分段为 `story_segments.segments`，团队为 `group_setting.groups`、人物为 `character_extraction.characters`，场景为 `scene_extraction.scenes`，镜头为 `shot_design.shots`，视频提示词为 `video_prompt.items`。意见、规则和状态集中于node_state，参考图与assets留在业务节点。

人物的原始参考图与照片槽位保存在 `character_extraction.assets[]`，通过 `character_id` 关联人物；照片节点位于各资产记录的 `costume_images[]`。场景图片节点保存在 `scene_extraction.assets[].image_generation`，通过 `scene_id` 关联场景。提取结果更新后，由程序按稳定ID维护资产对应关系，不让AI返回或覆盖图片地址、照片规则和节点状态。

`video_prompt.items` 只含分片关联与已选模式的 `prompt`，三个示例代表互斥模式，每个分片只返回一种。AI输出定义只引用既有 `$defs` 中对应模式的 `prompt` 部分；视频接口的完整请求定义、参数处理及程序执行保持原状，不新增bindings或改变视频生成节点。

`project_detail.json` 只用于开发阅读，不被src运行时代码读取。运行时字段来源是各盒子的 `src/node_box/<节点名>/definition.js`：字段结构、类型、必填、枚举和基本含义。[node_definition_registry.js](../src/node_runtime/node_definition_registry.js) 仅汇总，不再重复定义具体节点Schema。`src/node_runtime/schema_builders.js` 提供结构构建工具，`shared_output_contracts.js` 保存通用审核和图片返回契约。`skills/*.json` 负责生成依据、审核判断和修订联动，不复制输出Schema。修改运行时字段后同步更新开发文档；文档变化本身不改变运行行为。

规则仍以 `{{output:#/script_revision/output}}` 一类JSON Pointer引用运行时定义。生成/修订引用本节点output；审核引用 `#/$defs/review_output`；图片生成/修订引用 `#/$defs/image_output`。`renderNodeRules(model, action)` 可展开引用供查看；它默认引用运行时定义，不再提供definitionFile或读取文档。需要隔离的配置测试可通过definition参数传入同结构定义对象。

基础链路入口均由 `src/index.js` 导出：

- `createNode(nodeType, { rules?, definition? })`：创建空AI节点，默认从该节点skill复制规则，也可显式保留传入的项目规则。状态使用公共NodeStateModel；规则、意见位于node_state，业务结果直接展开，assets保持独立。空节点的零时长只是初值，不代表生成结果已通过验证。
- `composeNodePrompt({ nodeType, action, rules, input, goal?, definition? })`：按当前动作注入本节点有效业务规则、本次已筛选资料和程序输出契约，返回公共prompt-composer生成的messages/system/user/body。规则与资料不会被再次当作模板解释，输出契约只注入一次；跨节点或动作的输出引用明确拒绝。修改意见、语言、基稿和真实引用上游由调用方放进input；不自动读取整个项目。
- `parseNodeOutput(nodeType, action, response, { definition? })`：解析JSON并调用同源结构校验；已解析对象可直接交 `validateNodeOutput`。返回数据副本，不自动落库，不覆盖人工意见或资产。生成/修订的合法结果立即提交本节点业务字段并记录Task步骤；保存与审核结论独立，审核意见不写入正文。定义中的output是Schema容器，不是项目实例的包装。

校验支持本项目使用的类型、必填、额外字段禁止、数字范围、非空文本、枚举、数组容量及oneOf互斥结构；新增不支持的Schema关键字会明确失败。审核通过必须没有问题，其他结论须有具体问题。这里只负责结构，剧情依据、素材对应、跨节点ID关系和分片mode是否匹配等业务条件由后续执行器核验。图片返回仍由实际媒体接口适配器处理，JSON校验拒绝虚构图片地址；视频接口及程序节点不参与这次改动。

示例：

```js
const node = await createNode('script_revision');
const request = composeNodePrompt({
  nodeType: 'script_revision', action: 'generate', rules: nodeRules(node.node_state),
  input: { script: originalScript, requirements: userRequirements },
});
// 调用模型后先校验，候选保存在Task步骤，再执行审核。
const output = parseNodeOutput('script_revision', 'generate', responseText);
// 结构校验通过并检查Task身份、输入快照后立即保存，再审核。
manager.change(project => { Object.assign(project.basic_info, output); });
await manager.model.update();
```

基础链路和项目创建已实现；剧本优化执行器已接入独立模型worker、本地审核/修订、主Agent模型的有界项目审核及任务记录。其他节点执行器与旧数据迁移尚未接入。已保存业务规则仍以项目为准，初始化默认不覆盖既有项目。

## 会话与项目工作区

没有工作区时，面板通过认证的 `/api/drama/sessions` 接口准备未绑定会话，用户可以直接输入。会话拥有独立工作目录，尚未登记工作区或创建项目。创建请求ID持久保存在 `bindings.json`，重试沿用同一会话。

面板与 `drama-create-project` 共用项目创建入口。创建项目时保存 JSON、登记以项目名称命名的工作区，并为该工作区新建标准模式会话；成功后面板切换到新会话。显式绑定新会话到新项目；宿主刷新恢复到同一项目工作区的另一会话时，以宿主workspaceRegistry公开成员关系与已完成项目的工作区ID/path解析同一项目，不按名称匹配或改写历史绑定。源会话的项目归属与消息保留，允许从已有项目会话创建其他项目。重复创建请求沿用原项目、工作区和预先保存的新会话ID。


项目插件不提供独立的短剧模式。默认使用 Harness 标准模式；标准、PTC、极简、创造等模式保留自己的原有配置，共享 `drama-create-project` 工具和项目创建指导。业务指导以独立提示词段落注册，不覆盖模式的身份或通用工具；极简模式遵循宿主的完整身份提示，仍通过工具说明了解业务调用要求。无工作区准备的会话与项目创建后的新会话均使用标准模式。卸载项目工具插件时，共享工具与业务指导一起移除。


当前剧本优化入口为`src/tools/optimize_script_tool.js`，执行器为`src/node_box/script_revision/executor.js`，由`src/node_box/script_revision/service.js`的ScriptRevisionService校验绑定、提交任务并提交通过结果，与项目管理共用写入队列。会话与UI共用同一目标入口，UI点击只执行剧本优化，不执行后续节点。这里的worker通过独立模型请求运行，只接收当前盒子有界输入，不创建继承完整会话历史的Harness子会话。项目审核同样使用主Agent所选模型和规定审核包，不继承其他节点内容。


## 盒子Service与harness-http入口

- `src/harness_server/`：向Harness已有HTTP服务注册项目路由、静态资源与SSE，属于harness-http，不单独启动服务器。
- `src/tools/`：主Agent调用协议，将可信会话ID、Tool调用ID和取消信号传入盒子Service。
- `src/node_box/project/service.js`：项目管理统一入口；当前承接创建、编辑、删除和原始剧本导入。`executor.js`保留创建落盘、工作区、新会话和恢复逻辑。
- `src/node_box/script_revision/service.js`：优化任务校验、幂等提交、等待终态和有效结果自动保存；`executor.js`负责生成、本地审核、修订及有界项目审核。
- `src/node_box/project/create_project.js`、`edit_project.js`：项目管理专属的字段/创建校验和编辑、原始剧本导入命令。它们是服务端业务，不是UI。
- `src/client/`：面板UI组件；`src/project_runtime/`当前没有需要迁入client的UI代码。
- `src/project_runtime/`：共享项目Model、Manager、持久化及写入队列；project_manager.js与project_model.js保留原位。两个盒子共用项目管理服务持有的队列实例，不在模型请求期间占住队列。
- 根`index.js`组装服务和共享记录，面板路由与Tool直接注入所需盒子Service；不增加顶层service转发层。项目服务不持有或转发优化流程，面板执行状态由harness-http路由组合。

项目摘要与原稿预估时长提取，职责规划归项目管理盒子；当前尚未新增相应子Agent流程。优化稿已有的摘要、预估时长仍归优化盒子保存，不等同于原稿提取。当前优化任务的提示词和llm-http记录继续关联步骤；本次目录调整不代表已为创建、编辑、删除、导入新增全套任务记录，也未新增HTTP分类字段。后续实现遵守根开发指引的HTTP术语及记录归属约定。


## 节点运行层

`src/node_runtime/` 承担drama各AI盒子共享的节点运行机制：定义汇总、Schema构建、通用契约、契约渲染、响应解析校验和空节点初始化。文件与职责见下表。各盒子 `definition.js` 继续独立维护字段；`src/node_runtime/node_prompt_composer.js` 只负责按本次动作编排提示词；`src/project_runtime/` 只保留项目Manager、Model和共享写入队列。


| 文件 | 职责 |
|---|---|
| node_definition_registry.js | 汇总各盒子定义，保留节点名称和JSON Pointer |
| schema_builders.js | 构建Schema片段 |
| shared_output_contracts.js | 通用审核与图片返回契约 |
| output_contract_renderer.js | 选择/展开输出结构，渲染格式要求和规则引用 |
| output_response_parser.js | 解析并校验AI实际返回，不保存数据 |
| node_initializer.js | 按定义加载规则并初始化空节点 |
| node_prompt_composer.js | 组装当前节点动作的规则、资料、目标与输出契约，不决定执行顺序 |

共用输出契约的代码导出名与引用键名统一为 `review_output`、`image_output`；汇总的 `$defs` 保留显式 `review_output: review_output`、`image_output: image_output` 写法，不使用同名简写。审核动作仍叫 `review`，不是契约变量名。

## 面板任务与会话交接

打开项目即使用项目关联会话。面板任务不要求先有聊天消息，不为任务或问题报告另建会话。

面板经harness-http提交任务后，Service在盒子启动前向已有会话展示“面板操作”；面板和会话发起的盒子每个步骤结束后独立展示步骤结果，面板盒子终态再展示最终结果。步骤包含名称、顺序、修订轮次、状态、原因和完整result，审核结论为content_issue/upstream_issue/rule_conflict时即使步骤执行为done也显示红色“未通过”。自动修改及复审各轮保留；运行中不随轮询追加消息。盒子最终结果包含最后执行步骤及停止原因。

展示适配在src/session/panel_task_messages.js，通过宿主公开session.append写入log-only的command/run、command/done，不进入模型上下文、不伪造AI回复、不调用llm-http。每个独立展示以任务组、任务、阶段、步骤ID和轮次计算稳定ID，单张卡的事件配对只满足宿主协议；逐事件去重，崩溃时仅补齐缺失事件。同一会话内并发投递串行化。

面板操作在会话中以“请求 → 执行过程 → 最终结果”组织。请求明确标识面板来源，只出现一次修改要求；输入描述包括当次工作稿、项目名及字数，展开后按需读取正文、摘要、估时、输出语言及规则。AI步骤输入取step.prompt.input，包含实际候选稿及本轮review_issues；盒子输入取metadata.input_snapshot，创建/程序任务使用当次info/command，不读取最新项目补造历史。新的优化任务保存project_name；缺失旧字段时不按当前项目猜测。

同一任务的步骤独立记录，界面按group_id聚合。执行中展开过程并显示当前步骤；终态默认收起，保留用户手动展开状态。中间审核未通过仍显示红色，后续审核通过时标“已解决”。列表不混入长JSON、重复要求或剧本摘要。最终结果优先说明是否完成、是否保存；失败说明原因、结束步骤与最新结果是否已保存。保存成功提供查看本次剧本、对比本次修改前后及任务详情；对比使用当次输入及本次已保存结果，高亮变化范围，不读取当前工作稿冒充旧结果。

空会话和正常聊天共用client/ui/task-operation.js。正常聊天通过宿主公开data-chat-node-key定位相应command座位，组件放在同组首个已挂载座位，仅隐藏本组原生程序展示及其余成员；保留原始事件、其他消息和原生虚拟列表归属。座位卸载或复用时自动重新匹配，还原过期标记。空会话在公开data-conversation-scroll滚动区展示同一组件，以公开slot锚点隐藏欢迎标题、保持输入框底部停靠，保留输入实例和草稿。不修改宿主源码。

harness-http的GET /api/drama/task-messages?session_id=沿用宿主鉴权。compact=1轮询仅返回状态、描述及引用，不携带完整输入正文、规则、输出或长摘要；id=<消息ID>仅返回该会话对应消息详情，eager=1首次响应直接预载完整输入/输出，after以event_seq作增量游标，仅新增详情随响应带入；pending组在终态时补齐旧详情，防止缓存沿用未完成输出。展开优先同步使用已准备内容，不等待独立详情请求；id读取仍保留作兼容和失败恢复。规则及原始JSON另行折叠。会话event_seq与步骤seq分开保存，步骤编号不得被日志事件序号覆盖。读取旧事件时用当次Task/Step记录补齐投影，不重写旧消息，也不重新执行任务。切换会话清空旧组件及缓存，迟到响应不得写回新会话。

盒子本节点内容问题内部修订，中间未通过仅展示。面板completed/cancelled不唤醒主Agent；最终rejected/failed才由ReportDispatcher交接原目标、依据和报告，但终态content_issue或执行failed不唤醒主Agent，由会话卡片提示用户选择“继续修改、停止、重新生成”。继续修改使用原任务最后候选和审核意见创建新任务，资料或规则变化时要求重新生成；重新生成使用当前正式稿创建新任务；停止不调用模型。两种重试均通过harness-http既有生成入口提交retry_of/retry_action，来源固定ui，保留原目标、旧任务及正式结果，每轮有效结果自动落盘。原会话通过Tool创建新项目后的目标交接继续保留，普通Tool任务完成不额外发送规划通知。规划来源固定drama-box-report，不代表用户授权；规则修改仍须授权，修复后以retry_of派发新任务，旧记录保留。

main-agent-deliveries.json分别记录开始、每个步骤、最终展示及规划通知的成功回执。展示失败不撤回业务，也不阻断规划通知；已成功通道不重复投递，失败通道5秒后重试并支持重启恢复。主Agent报告沿用稳定ID及宿主历史/收件箱去重。首次升级仅纳入运行中及此后新任务，不把全部旧步骤补灌会话；旧投递成功记录继续生效，旧展示卡仍可在空会话读取。

普通任务的目标会话取受理时绑定，不随网页当前会话切换。项目删除或归属变化拒绝投递，不创建替代会话、不转投其他项目。创建项目尚未产生新会话时，开始、失败步骤及最终失败归来源会话；创建成功后步骤及最终结果归已创建项目会话。保留创建项目、无工作区开始会话以及删除项目后的必要会话创建入口。

删除项目完成后，Service在项目创建请求行保存deleted_session_request_id；释放删除写队列后，使用相同ID调用startSession，避免嵌套队列死锁。新会话使用独立sessions目录的cwd，不传workspaceId、不创建项目工作区、不写项目session绑定。重复/并发删除及重启后的重试复用同一后继会话。删除事实先落盘；空会话创建失败返回deleted及session_error/session_request_id，面板明确提示已删除并提供重试创建入口，不恢复旧项目。删除请求期间关闭本页SSE以免迟到刷新覆盖交接状态；删除失败恢复SSE；切换会话后清理交接状态并拒绝迟到响应抢切。删除不清除旧会话、磁盘文件或任务记录。此新空会话属于用户明确的删除后动作，不是盒子失败报告的兜底会话。

## 原始剧本展示摘要

原稿摘要属于项目盒子，不新建盒子、主Agent工具或审核循环。根插件通过configureOriginalSummary显式注入所选文本模型；纯存储ProjectService实例不隐式调用外部模型。summary_extractor.js使用公共提示词编排和llm-http客户端，只发送原稿与输出语言，一次请求按project/definition.js中basic_info输出契约返回非空summary与正数estimated_duration_seconds，不额外发起估时请求。

创建项目有原稿时，创建程序步骤后追加extract_summary AI步骤；没有或仅空白原稿则跳过。面板导入、素材导入或上游修复中的import_script，均先保存原稿并清空basic_info的summary和estimated_duration_seconds及节点状态，再在同一project盒子追加摘要步骤。导入使用请求ID幂等；任务、步骤、提示词和实际llm-http记录统一归project。摘要和估时保存前校验会话归属、原稿及output快照未变，不持有项目写入队列等待模型。

结果保存在basic_info的summary和estimated_duration_seconds（summary、estimated_duration_seconds），创建状态位于basic_info.create_project_node，创建成功即generated；初始摘要为空、估时为0，摘要失败只记warning，不改变创建成功事实。两字段只读、仅供展示；不能由创建工具或人工基本信息编辑覆盖，人工编辑其他字段须保留它。摘要无效或请求失败只在步骤结果记录summary_error，等待完整任务的API/Tool返回warning；面板创建已提前返回时通过任务历史查看该警告，已创建项目与已保存原稿仍成功，不自动重试、不唤醒主Agent修复摘要；用户取消仍按取消处理。历史项目不自动补算。

优化剧本继续随完整正文返回basic_info.summary和预估时长，按既有节点流程处理；不增加独立摘要调用；仅在审核通过后，在同一项目写入事务中将摘要和估时同步到basic_info的summary和estimated_duration_seconds，并更新basic_info.script_revision_node。后台原稿提取需同时核对原稿和output快照，避免晚返回覆盖较新优化结果。

## 盒子任务与步骤记录边界

一次业务盒子执行对应一个Task。Service负责校验、幂等受理、提交任务、启动执行与返回结果；Executor负责节点注册、步骤计划、动作执行、条件追加步骤以及提示词/llm-http关联。公共packages/task的TaskManager统一持久化任务和步骤的状态、时间及结果，Service和Executor不分别维护另一套任务数据库。

项目盒子的ProjectExecutor位于src/node_box/project/executor.js，CreateProjectExecutor是其中的创建程序子执行器。创建有稿时同一个Task包含create与extract_summary两个Step，无稿只有create；单独导入原稿是另一个Task，包含import_script和extract_summary。Service提供snapshot、saveOriginalSummary等数据能力，模型调用和摘要异常处理在执行层。优化盒子原本已采用该边界；生成、审核与多轮修订都在同一Task追加Step，重新派发才建立新Task，旧记录保留。

存储层要求Task归属TaskGroup，独立执行可以由单任务组承载；TaskGroup用于组织任务，不当作盒子身份。当前公共任务历史保留原卡片结构，可由任务组详情看到组内Task及其各Step。纯资料维护接口的记录范围不在本次重构扩大，历史数据与公共Model结构不改。

## 项目制作阶段页面

项目详情标题区的“下一步”（位于删除右侧）进入制作页，可返回详情。界面在client/project-production.js，从meiji复制stageTabs与字段展示布局、在drama独立维护；标签样式在client/ui/project-ui.css，不依赖meiji运行时代码。
七个标签依次为故事大纲、场景、角色、分镜、提示词、成片、分集，分别展示story_segments、scene_extraction、角色页（group_setting、character_extraction与costume_image三卡片）、shot_design（含clip_arrangement）、video_prompt、videos、episodes。当前只展示实际保存的模型数据，不代表未实现的盒子已有生成能力。选中阶段保存在每个项目的视图state中，数据更新仍停留当前阶段。

制作页节点操作区沿用剧本节点布局：任务历史/查看规则在左，AI生成和修改两个按钮在右，下方为本次执行意见。历史用公共task UI按项目和真实任务类型过滤；规则用公共prompt-composer UI展示该节点Model，故事大纲可保存各动作补充规则，其他生产节点目前只读。意见经项目编辑入口指定node_type保存到node_state.opinion，缺省为空，草稿按项目和节点隔离。故事大纲已接入生成与按意见修改；其他尚未实现的执行器明确禁用生成按钮；分片编排、视频生成、合片按程序节点展示任务记录和程序操作，不增加AI规则或意见。

剧本节点标题旁只展示节点数据状态，执行期间保持Task创建时的node_state_before，刷新也从任务元数据恢复；任务结束再展示最终状态。按意见修改按钮始终保留该文案，提交及执行期间置灰且不可点击。当前步骤区域单独展示前置（准备/等待）、生成、审核、修订；主动基于旧稿改编归为生成，只有当前Task审核未通过后的返修用红字显示修订和具体原因，正常步骤用黄色，不使用旧任务的拒绝原因推断本次返修。

项目快照script_execution提供当前步骤简要字段、本Task最近审核问题、执行前节点状态，不暴露提示词/请求内容；公共NodeState枚举和历史终态不改变。候选待审核只保存在Task步骤，不覆盖工作正文；无活动任务时等待审核说明不伪报执行中。优化稿存在时，“复制原文”位于“查看规则”右侧，复制完整正文，正文区域不再重复展示复制按钮。

剧本优化卡片标题右侧使用“查看剧本”文字按钮（无箭头），进入优化稿详情；原始剧本的同名按钮仍进入原稿详情，两个入口通过独立可访问名称区分。

剧本优化审核通过后，若node_state.opinion仍为本Task已使用的instruction，则与结果一起清空并落盘；失败保留意见。面板收到成功清空快照时，只清除与旧已保存意见完全相同的草稿；执行期间新增的已保存意见或未保存草稿均保留。历史任务的instruction及提示词不变。

任务历史中每个任务卡片按“输入依赖 → 内部步骤 → 任务输出”展示；界面不展示任务组标题、ID及1/1进度；任务组仅保留为底层组织与调度实体。列表按Task显示和分页，详情只显示选中Task，顶部为任务标题及原状态标签，次级信息为可复制任务ID、业务节点类型、发起时间和来源，不重复显示任务标题或组内序号。“输入依赖”由公共task UI以JSON展示，drama在client/ui/task-presentation.js提供只读适配，全局/节点入口一致。依赖来自当次记录的input_snapshot和首个实际prompt.input，新剧本任务排队时已保存当前稿、原稿、语言、指令；输入展示按外部资料字段投影，内部规则不并入输入；不读取现在项目来替代历史。多Task逐任务区分，未记录输入时显示null。任务卡片底部“任务输出”由presentation.taskOutput按本任务已保存步骤投影盒子交付结果，以JSON显示任务状态、结束原因及业务结果。成功显示最终结果；未通过/失败/取消显示原因和已有候选或部分操作，并明确标为partial_result，不当成通过结果；执行中result为null。剧本审核依据与建议在issues中展示。项目创建合并创建结果、原稿摘要及摘要失败warning。内部Task.metadata仍保留用于追溯，不再直接渲染为对外输出。输入依赖与任务输出均提供完整JSON复制按钮；多任务输出分别展示，不以任意最后步骤代替业务结果。步骤使用内联展开，保留提示词/HTTP入口，删除重复的查看步骤按钮。

## 节点盒子的资料边界

每个节点视为一个盒子，区分三部分：输入资料是上游结果、用户本次要求等外部参数；输出资料是盒子交付的最终业务结果；内部资料包括节点自身规则、生成/审核/修订步骤、审核问题、提示词、调用记录及运行信息。盒子内部使用的资料不等于盒子的外部入参。剧本输入展示只允许原稿、旧优化稿、输出语言和本次意见，不能把input_snapshot中的rules整体合并进去。规则快照仍保留在任务内部用于追溯，不删除或改写历史。步骤结果不等同盒子最终输出，当前任务详情的步骤结果仍属于内部过程展示。

项目盒子的输入展示使用创建资料、导入原稿或本次目标修改值；command/previousValue等并发执行命令和摘要子步骤包装也属于内部，不作为盒子输入展示。未声明输入契约的盒子不得把任意input_snapshot整体并入输入资料。

公共操作提示由`@agent-modules/ui`的`showToast(message)`提供，只传提示文字，固定2.5秒自动关闭，连续调用替换旧提示。面板壳初始化时用setToastContainer(sidebar)登记定位容器，销毁时解除；toast挂在sidebar直接子级，在内容滚动区之外，以50%/50%和最高局部z-index居中，不拦截点击。未登记或容器移除时回退到页面中央。无需新建空白页面，后续如抽取通用面板，保持内容区与提示浮层分离即可。drama全局和节点任务历史的`onNotify`回调调用此公共UI；复制成功/失败不再写入任务页顶部固定notice。公共task/http-client/prompt-composer组件通过onNotify回调反馈复制结果，不依赖业务项目或toast实现；task将回调透传给内嵌HTTP详情。复制按钮始终保留原文案，不因复制成功、失败或请求未结束而禁用，可连续重复点击。会话输入输出和工作稿卡片同样通过toast反馈，失败不改按钮文案。

任务历史数据源的列表查询以`unit=task`按任务本身状态/类型筛选和分页，返回`tasks/total/offset/limit`；TaskManager原默认组查询保留供调度及已有程序使用。SQLite按任务表直接分页，不读取历史步骤正文；harness-http节点入口同时保持项目与节点隔离。详情内部仍经group_id读取记录，再按task_id选出唯一任务，任务、提示词与HTTP页面往返保留所选任务。

剧本优化的外部输入契约集中在`ScriptRevisionService.executionInput({ current_script, instruction, output_language })`：三项必选。current_script必须包含非空actual_script、字符串summary和非负estimated_duration_seconds（导入后尚未提取时摘要为空/估时0）；instruction最长10000字；不再接受original_script或读取来源文件作为优化正文。入口`optimizeScript({ instruction, retry_of }, { sessionId, requestId, projectId, source = 'api' })`要求instruction、sessionId、requestId，retry_of/projectId/source可选（提供时必须有效）；Service从绑定项目的basic_info和设置解析资料，不允许调用者传入完整项目、规则或任意覆盖原稿。提交后Executor使用已验证的外部输入快照，仅在内部替换最新候选及追加review_issues。

`ScriptRevisionService.maxRevisionRounds = 3`是Service类属性，由Executor通过回调读取，不作为项目字段、Tool/面板参数或规则资料。首次生成或用户发起的按意见修改为round0；审核不通过后自动修订round1、2、3，每轮再审核，第三轮通过则成功，仍有内容问题则保留最后候选并以未通过报告；上游、规则冲突和重复问题仍可提前停止。

项目basic_info不再定义creative_requirements，创建/编辑Tool与UI均不收集此字段。reference_episode_duration_seconds仍是项目资料，已从本节点输入及依赖指纹移除；需要特定优化时长时写入本次instruction。新建自由模式项目不再收集无存储位置的创作方向。历史任务/提示词快照保持原样；输入依赖展示按当前外部契约过滤旧字段。

面板创建（source=ui）在同一Task的create程序步骤完成、项目JSON/工作区/新会话均已建立后返回`project_id/session_id/workspace/group_id/status`，随后立即切换目标会话详情，不等待extract_summary模型请求；status是当时Task真实状态，不提前标记摘要完成。会话Tool及其他API调用仍等待整个盒子终态。幂等重试复用相同项目、会话和任务。

修订轮次是停止条件，不是审核原因类型。Executor终态及节点last_execution.stop_code采用最后一轮review.status（content_issue、upstream_issue、rule_conflict）；原因正文采用该轮完整issues。达到轮次上限不生成独立原因类型，轮次仍保留在步骤round和执行过程。历史Task保持原事实，读取节点摘要/会话展示时由最后审核事实重新投影，不以历史revision_limit_reached盖过结论。独立失败卡片去掉黄色装饰边线，单独显示“原因类型”和最后一轮问题。

## 场景提取

场景提取为独立 `scene_extraction` 文本盒子，面板 harness-http `/api/drama/scenes` 和会话 `drama-extract-scenes` 共用 SceneExtractionService。只要求完整故事大纲存在；输入为 `story_outline.segments`、`current_scenes.scenes`、`instruction`、`output_language`，不依赖团队或人物，不传整项目和原稿。沿用既有场景定义：id/name、description、layout、materials、lighting、entrances_and_routes、fixed_landmarks；输出只含scenes，不接受assets、图片地址或node_state。

已有场景时，面板同时提供“重新生成”和“按意见修改”：前者通过可选布尔参数regenerate=true从generate开始，按当前大纲和项目规则重新组织完整场景，已有资料供稳定ID与名称复用；后者默认从revise开始。执行期间两按钮禁用，请求ID区分执行模式。新结果有效前保留原场景和资产，沿用有效候选即时保存与独立审核流程。regenerate不能与失败任务retry_of/retry_action混用。

按现有规则收录反复出现、对剧情/空间连续重要或用户要求固定的地点。同一总体布局按稳定ID复用，机位、天气和昼夜不另建资产；固定空间可合理补足以支撑定稿行动，但不改剧情、设施用途或出入关系。无符合条件场景允许空集合并审核通过，程序拒绝重复ID及不合契约字段。

一次任务包含生成/本地审核/按意见修订；结构有效候选立即保存，审核失败或取消不撤销候选，只有审核通过才清除同次意见。内容问题最多自动修订三轮并检测重复问题；终态内容问题或执行失败等待用户继续/停止/重新生成，不自动重跑。规则冲突通过drama-change-rules一次授权修复，补充规则支持在场景规则页独立保存；共用请求幂等、会话归属和项目执行互斥。

场景tab提供独立操作、意见、规则、任务历史、复制、运行loading及真实停止原因；会话和历史显示本次大纲、当前场景快照、各轮输出与审核，输入白名单不透内部规则。项目快照提供scene_execution，轻量node-states轮询包含独立状态及last_execution；重试通过场景专属端点。

场景三动作采用同一事实与设计边界：来源明确的因果、出入及装载关系保持原有确定强度；与年代、用途和已有行动相容的普通材质、门窗、基础光照和必要空间可以成为本项目固定设计，不能仅以“原文未写”拒绝，也不要求逐字段重复来源标签。不得以补全新增无据的唯一/必须/禁止关系、强制内外归属、改运输路径或扩大关键设备覆盖。资产字段只保存可执行的正向环境资料，不写“未交代/无法确认”等审核旁白。

修订与复审记录内部辅助review_history：仅当前Task已有审核（最多当前修订预算）及显式用户继续任务的原问题，每轮包含round/status/issues及revision.applied、changed_fields。变化由程序按scene_id及字段比较，只保留字段名和新增/修改/移除类型，不重复旧场景全文；applied不代表问题已解决。前轮未提及不表示已通过，历史意见也不是事实或不可撤销指令；若需推翻先前建议，审核reason须指出违反共同边界的原因和有效依据。同条件无新依据不应给相反建议，已解决问题不重复提出。该上下文只在真实步骤提示词中记录，不冒充盒子外部入参，历史展示白名单仍不透内部审阅上下文；输出Schema与修订上限保持不变。

每个场景按scene_id维护assets[].image_generation空槽，继承新槽位的项目画幅；不请求生图、不新增场景图按钮。重复输出保留图片、原参考及规则；实际场景资料变化或从历史恢复时，将对应已有图片标记过期并保留地址，其他图片和被移除场景的历史资产保留。场景内容或规则变化使团队、人物、镜头、分片、提示词及已有视频/分集状态过期；人物照片等造型资产继续保留，待造型实际变化后由对应盒子处理过期。执行中大纲、规则或场景输出变化拒绝迟到覆盖。

团队和人物仍可使用已有场景而不新增场景硬前置；主路径按大纲→场景→团队→人物推进。旧项目私有规则不覆盖，新默认规则补齐本次输入字段说明；不新增场景字段，不迁移或重写现有场景内容。

## 场景图

scene_image为独立图片执行盒子，scene_image/维护Service、Executor、state与ui/panel/conversation。场景提取文本不自动启动生图；用户在每张场景卡片明确点击生成/重新生成，harness-http POST /api/drama/scene-images经SceneImageService创建一项场景图任务。前置为场景节点已生成；输入仅当前scene、该图的要求/参考图、项目画幅和输出语言，采用图片模型，不携带人物或整项目，不另行调用文字模型或自动视觉审核。

每个scene_extraction.assets[scene_id].image_generation保存reference_image、address、aspect_ratio和node_state；生图要求使用该图node_state.opinion。POST /api/drama/scene-image-inputs通过当前会话/项目校验、项目写队列与旧值检查保存要求和参考图，原有结果保留并标记过期。参考图为不超过8MB的PNG/JPEG/WebP data URL，支持上传、更换、移除；当前有参考图时需使用支持参考的GPT Image。拒绝任意文件路径、外部地址、伪造MIME及过大请求，不增加新的项目顶层字段。

参考缩略图72px、结果图220px在同一排，结果按项目比例contain显示，要求框、生成按钮、进度和失败原因位于本场景卡片；参考始终比正常结果图小。刷新恢复已保存输入，切换会话或项目后迟到回调不回写当前UI；连点复用请求ID，同项目任务互斥。结果保存在项目scene-images/目录，GET /api/drama/scene-image沿用宿主鉴权和项目归属，仅接受安全PNG文件名。生成前及保存时核对场景/画幅/要求/参考/规则指纹，变化时拒绝覆盖。失败保留旧图，终态按scene_id独立投影到图片node_state.last_execution；node-states和project响应提供对应活动任务。

任务与会话按当次输入快照展示参考图、要求和生成结果，不用当前项目补历史。失败可在场景卡片或会话选择重新生成，不擅自修改场景资料或启动其他盒子。图片保存不冒充视觉审核通过。

## 团队设定、人物提取与定妆照

团队设定为独立 `group_setting` 盒子，通过会话 `drama-generate-groups` 或 harness-http `/api/drama/groups` 共用 GroupSettingService。输入为完整 `story_outline.segments`、已有 `scene_extraction.scenes`（允许为空）、`current_groups.groups`、意见和输出语言；只输出并保存 `group_setting.groups`，不生成人物或图片。只收录实际出场、有组织归属且需要统一着装的团队，例如军队、宗门、有统一工装的探月基地工作人员；群众、观众、临时聚集者和不需统一着装的人群不纳入。同职业或同场不足以合并成团队，不给普通人群强加制服。简短描述基本团队形象、整体状态和统一着装；其他字段按必要信息简写或留空，不逐项扩写年龄体型、岗位外观或等级标识。服装默认一套，只在剧情确需时区分；吸烟、受伤、倒地和临时沾灰破损留给镜头状态，不据此新建团队、拆服装版本或缩窄适用段。生成、修订和审核共用此边界，不合格旧群体从下一次完整输出中剔除。无合格团队时允许空groups，生成并审核后仍标为已生成。

人物提取通过 `drama-extract-characters` / harness-http `/api/drama/characters` 共用 CharacterExtractionService。输入为 `story_outline.segments`、已有 `scene_extraction.scenes`、已确认的 `group_setting.groups`、`current_characters.characters`、意见及输出语言；只输出和保存 `characters`，不能返回或改写groups。人物提取和定妆照要求团队节点处于已生成状态，团队缺口返回上游盒子。人物 `group_ids` 引用实际所属团队，个人服装以 `group_id/group_costume_id` 引用共同制服并补充个人差异；独立服装两项引用同时为空。`story_segment_ids` 指定真实适用段，空数组为通用，个人制服范围不能超出团队版本。严格校验稳定ID、成员与制服引用、适用段；当前旧候选允许交模型修复旧引用，新输出必须有效。

人物costumes保持JSON数组及id、团队制服/故事段等内部关联。每个需要服装的出镜人物，即使剧本没有服装介绍，也要结合职业身份、年代、地域气候与实际场景补齐至少一套具体设计；不得以“未交代”或“普通衣服”代替。合理相容的服装设计不因缺少原文逐件依据被审核拒绝，已明确的穿着事实优先，不新增换装剧情。人物卡片将服装与其他人物字段按同一结构展示：服装：1. 名称，描述；2. 名称，描述。多套合并在同一字段值，长文本自然换行，不拆成名称/描述子字段或独立子卡片；引用制服时基础制服描述加个人差异合成展示，保存值不改变。会话和复制的可读文本共用相同序号拼接格式，原始JSON及下游引用保持。

两个文本盒子各自拥有node_state、三动作规则、意见、独立Task/Steps、生成/本地审核/修订、输入快照、提示词/llm-http记录、失败决策和规则修复能力。结构有效输出立即保存，审核失败不撤回；内容问题最多自动修订三轮。面板点击只执行本卡盒子，主Agent按目标调用对应Tool，不自动串行启动下一盒子。请求幂等、会话归属、项目执行互斥及用户继续/重新生成共用既有Task机制。

团队内容或规则改变使人物及镜头/提示词下游过期；照片按实际人物所属团队及选定制服比较，相关变化过期但保留地址，未选制服或无关团队变化不让旧照片过期。人物和定妆照指纹包含团队资料，执行中上游变化拒绝迟到覆盖。轮询 `/api/drama/node-states` 包含团队状态、终态停止原因和活动任务，项目快照提供 `group_execution`；会话及历史使用当次团队输入/输出快照，不用当前项目补历史。

旧项目在ProjectManager读取时补独立团队节点到内存；合并版本的characters节点groups资料保留为团队候选，标为过期并要求独立执行审核。无旧团队资料则初始化空节点。ProjectManager只读不落盘，后续业务保存或任务状态同步时才落盘；独立团队保存后删除旧重复groups字段。已有私有规则保持不变，新团队节点使用新默认规则。

资产按稳定人物ID关联；每套明确服装对应一个照片槽位，服装目录为空时使用 costume_id=null 的人物照槽位，不补造服装。首次提取创建空槽位；重复提取保留照片及规则；人物资料或其关联团队形象、选定制服变化使对应照片过期，删除人物或服装时历史资产仍保留。定妆照不会随提取自动执行。

`costume_image/` 负责子盒子的 Service、Executor 和 UI。用户可在定妆照卡逐套生成，也可点击“一键生成所有角色定妆照”。批次为一个 TaskGroup，每个角色/服装照片为独立 Task，逐张串行生成和保存，保存后即完成，不调用文本模型审核、不自动修订。任一照片失败或取消即停止该批次剩余任务，已保存结果保留。重新生成沿用用户原先选择的人物/服装范围；每张终态摘要写入自己的 node_state，批次全程推送更新。

会话使用 `drama-generate-costume-images`，面板使用 harness-http `/api/drama/costume-images`；接口校验会话归属、请求ID及项目执行互斥。槽位显式 reference_image 传给支持参考图的 GPT Image；不默用人物原始参考，不支持参考图的模型明确报错。图片模型返回真实字节后保存至项目 `costume-images/`，生成唯一文件名并写入 address，经鉴权 `/api/drama/costume-image` 提供预览和放大；原图文件名不能包含路径。定妆照不执行审核，生成并保存成功即可报告完成。任务、步骤、llm-http 和历史展示均关联本次快照；上游资料变化拒绝迟到结果覆盖。

角色标签内依次为“团队设定”“人物提取”“定妆照”三张卡片；前两张卡片各有独立状态、按钮、意见、规则、历史与loading；照片独立点击执行。团队和人物资料直接展开，服装引用显示对应名称。定妆照输入包含实际所属团队形象与选定制服，不传无关团队或未选制服；历史会话保留同一快照。镜头表以 groups 引用在场团队、制服及占位，视频描述继承团队视觉设定和个人差异，不再次设计。旧人物资料缺失的团队/服装引用字段只在输入投影中补齐，不覆盖已有私有规则；新默认人物规则用于新建节点。定妆照按服装横向滚动排列，图片框固定高162px、3:4，使用contain完整显示已有图片；未生成显示相同尺寸占位。新生成与重新生成请求固定3:4，忽略项目及旧槽位画幅，保存结果同步该照片aspect_ratio。

团队设定与人物提取已有结果时，同时提供“重新生成”和“按意见修改”。重新生成不带输入框意见，保留意见草稿，通过groups/characters面板接口的可选regenerate=true从generate开始，按最新上游资料与项目私有规则组织完整结果；按意见修改带输入框意见，仍从revise开始。请求ID区分模式，执行中两按钮及互斥操作禁用；人物重新生成仍要求团队节点已生成。有效新结果返回前不清空旧资料；原有有效候选即时保存及审核机制不变。普通regenerate入口不能与失败任务retry_of/retry_action混用。


## 分镜盒子

shot_design是独立文本盒子，Service/Executor/规则修改与panel/conversation/history位于src/node_box/shot_design。面板POST /api/drama/shots与会话drama-generate-shots共用generateShots入口；首次生成、按意见修改和重新生成均携带当前意见。regenerate=true使用generate动作重新设计，复用适用的稳定ID；普通有结果时使用revise，两个入口均不重新改编大纲剧情。

输入为已确认story_outline、scene_extraction.scenes、group_setting.groups、character_extraction（characters及costume_references）、current_shots、instruction、output_language，规则读取项目私有快照。大纲须非空且generated；已有非空资产须generated，没有资产时允许明确称谓和空ID，不强制图片，不自动执行上游或后续盒子，不读取原稿。镜头完整集合写入shot_design.shots，结构与project_detail.json一致，不新增字段。程序校验非空、唯一镜头ID、故事顺序、首镜opening、段和锚点归属/覆盖、资产及服装归属、团队制服故事段适用、正节拍时长及首拍摄影；后续节拍空摄影/声音变化允许继承。全文、对白、声画和剧情连续性由本地AI审核。

每次有效候选通过ProjectManager即时保存，保存与审核结论分开记录。内容问题最多自动修订3轮；重复问题或上限停止，用户可继续修改、停止或重新生成；上游问题/规则冲突立即停住。支持报告、规则授权修改、失败决定、任务历史、完整输入及结果会话展示；轮询返回shot_execution，终态恢复至shot_design.node_state.last_execution。输入指纹包括大纲、资产、确认状态及分镜规则；输出哈希、scope、项目互斥和幂等保护拒绝旧结果覆盖。分镜变化仅使分片编排、提示词与视频/分集过期，保留原数据，不自动运行下游。


### 人物定妆服装沿用

大纲和分镜没有明确描述服装、换装或伪装时，沿用已有定妆服装与外貌，不因换故事段补新服装。个人服装story_segment_ids仅是明确穿着段落的选装线索，不作跨段禁用条件；仍检查人物与服装ID归属。明确换装与现有资料不符时由审核定位上游，不在分镜重新设计衣服。

分镜输入character_extraction同时含characters与costume_references，后者由已生成且未过期定妆照投影为character_id/costume_id，仅传关联事实、不传图片像素或重做视觉理解。ID漏填时按前镜已选、唯一已生成定妆关联、唯一服装的顺序归一化；多套且无明确默认时要求模型指定，不盲选首项。归一化结果写入候选、步骤及项目，原模型响应保留在调用记录。无服装目录的特殊角色允许空ID。团队制服现有适用校验保持独立。

分镜模型返回的groups若包含六个已知字段全部空白的完整占位，接收阶段清理为无团队（空数组）；清理后仍按原严格契约检查并保存。有实际描述却缺团队ID、未知字段或缺字段不自动删除，不伪造团队。原始模型响应保留在调用记录。
