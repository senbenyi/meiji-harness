# 短剧数据契约 V4

用户允许清空旧数据、不做迁移。当前新建入口只创建 `schema_version: 4`，旧优化、大纲、人物提取等服务不再由插件入口注册。现有旧模块和对应回归测试尚待后续节点替换时删除，不作为新短剧的写入入口。

权威运行契约位于 `src/drama_runtime/drama_document.js`，浏览器共用阶段目录位于 `src/shared/production/production_stages.js`；[JSON Schema](drama_v4.schema.json)、[字段详解](drama_detail.json) 和 [空短剧示例](drama_v4.example.json) 从运行契约生成，仅用于文档和一致性测试，运行时不读取文档模板。

## 根字段与职责

| 根字段 | 内容与权威来源 |
|---|---|
| schema_version / document_revision | 文档版本与程序递增的保存版本 |
| basic_info | 短剧ID、名称、创作模式、画幅、输出语言；没有预分集时长 |
| source | 当前原稿版本、所有原稿文件引用与字符数；不可变原稿不被改编覆盖 |
| source_analysis | 程序将整份原稿赋值为一条body记录；摘要为空，事实与覆盖报告引用默认空 |
| adaptation_plan | 全篇改编目标、锁定要求、剧情指导正文、人物动机关系成长、场景作用与团队指导 |
| story_segments | 定稿自主分段的段索引、完整改编剧本正文文件、指导版本和连续性记录；不预分集 |
| asset_library | 短剧人物、服装、道具、场景、人物造型及图片ID、所选图；声音描述/音频引用属于人物 |
| asset_requirements | 分镜提出的素材需求、目标资产ID、涉及镜头及复用/导入/生成策略 |
| shot_design | 唯一一组镜头ID；人物造型、持有道具、节拍、对白表演、参考图片ID |
| clip_arrangement | 生成分片与原镜头/节拍对应关系；生成模式、首尾帧ID |
| video_prompt | 分片提示词正文文件、图像与声音引用快照 |
| videos | 实际视频候选、提示词版本、文件、真实时长和人工选择 |
| editing | 连续时间线、裁切位置、字幕与音轨文件引用 |
| episodes / delivery | 后期才确定的集界、导出文件及验证报告 |
| node_states | 各步骤意见、产物版本与核对状态；仅模型步骤带补充规则，仅文本AI步骤带检查点 |

全局图片库表仅 `images(id, url)`；类型、服装组合、短剧引用和选择状态均在 `asset_library`，不在图片表重复保存。声音文件不进图片库。图片生成/导入成功立即入库；短剧保存会检查所有图片ID及实际文件存在，支持跨短剧图库选用。

人物/场景/团队规划只提供全篇改编方向；资产定义是后续分镜与素材阶段落实的稳定视觉和声线。分镜需要新增服装/道具时，应在同次程序提交中先建立短剧资产定义，再校验镜头引用；图片可以尚未生成，不要求为每套衣服提前生图。图片生成与导入成功后才登记真实图片，再回填引用。

## 全篇联合改编指导与自主定稿


人物指导为 `id/name/description/motivation/relationships/arc`，明确人物定位、动机、关键关系和成长方向。场景指导为 `id/name/function/description`，说明关键场景作用与必要调整。团队指导为 `id/name/social_role/description`，仅纳入实际出场、具有组织身份或共同形象需要的团队，描述组织定位、成员归属和必要共同形象；无则[]，不统一成员脸型。

已删除详细故事段计划、虚设的原著人物/场景来源引用、提前声线、团队年代地域/制服版本等旧字段与规则。联合改编不预先规定每段事件、分段边界或段间衔接。服装、定妆和稳定声线由后续分镜/素材阶段按实际情节补齐。

联合改编每次生成一份全篇指导，通过有界工具读取全部原著。故事定稿确认指导属于当前原稿后，建立一个全篇工作单元，完整读取原剧本与冻结规划后自行返回有序 `segments` 数组（至少一项），每段为 `id/title/body/continuity`，决定具体情节、合理边界及前后衔接，不预分集。

程序保存每段 `adaptation_revision`、全局 `sequence` 及不可变正文/衔接文件。正式故事段不保存 `source_chapter_ids` 或 `source_spans`，不按原文章节分组或排序；正文为可独立阅读的完整改编剧本。拒绝重复段ID；原有被分镜引用的段不能静默删除。修订取回改编后全篇候选并保持稳定ID。生成与独立审核都必须读完原著和冻结的全篇指导文件；后续仍独立复核相邻实际定稿段，必要修订只返回指定两段全文。旧契约任务不能在新契约下续接，必须重新生成。

现有短剧按用户明确选择清空后重新创建，不建立旧字段兼容或双写分支。工程偏好、模型配置、共享图库不在清理范围。

## 大文本与执行记录

`projects/<id>/project.json` 保存结构与原著分段正文；不可变导入原稿在 `sources/`，改编剧情与提示词在 `artifacts/`，媒体、音频、导出分别在 `media/`、`audio/`、`exports/`。原著每段为 `{id,sequence,title,body,summary?}`，不保存 `source_spans` 或正文文件引用。分段正文按顺序拼接必须与对应原稿逐字一致，保存时由程序核验，拒绝遗漏、重复、乱序或改写；标题和辅助摘要可人工编辑，也可通过完整分段产物调整边界。引用均为短剧内相对路径，拒绝路径穿越及越界符号链接。文件按UUID新建；其他阶段编辑文件正文产生新文件，历史文件不覆盖。

原稿导入上限24MiB，按JavaScript UTF-16字符下标定位来源区间 `[start,end)`。后续模型读取通过有界工具，基础读取函数每次范围最多16000字符；程序内部可读取完整Buffer。人工正文编辑最多240000字符；更长文件提供16000字符分页查看和完整下载，不把截断正文当成完整内容保存，大稿通过本地文件重新导入。V4本地导入及共用弹框上限24MiB；素材库上传仍遵循既有1MiB限制，本次不修改库容量策略。文件仍保留完整内容。

`bindings.json` 保存创建请求、工作区和会话归属；`records.sqlite` 由公共TaskManager维护任务和步骤。原稿和人工命令正文外置不可变文件，任务保存文件引用，不在每个Step重复写入10MiB正文。人工修改进入Task，保存和失败事实都可查询；历史展示仅依据当次记录，不用当前短剧补造旧结果。

文字分镜在每段开始时冻结完整输入：该定稿段正文与衔接、全篇改编指导、已有资产定义（保留图片引用，不读取图片内容）。生成首轮直接提供这些资料，审核与修订首轮在预算允许时同时附带完整当前候选，资料齐全时不再开放重复读取这些资料的工具。每段开始才冻结资产，后段可复用前段新增内容；同段后续轮次沿用不可变输入。该完整输入模式的资料与候选合计上限为64000字符，超限时明确标记未附带部分，保留原有有界分页读取和完整读取校验；其他盒子保持原有资料阈值和读取方式。已有历史Task/Step不改写。

## 人工编辑矩阵

| 步骤 | 可编辑内容 | 程序负责的事实 |
|---|---|---|
| 短剧与原稿 | 短剧信息、导入原稿新版本 | ID不变、文件与版本生成 |
| 原著解析 | 分段标题、可选摘要、body及完整分段编排 | 顺序连续，正文逐字完整还原原稿；不改写原著 |
| 联合规划 | 目标、锁定要求、全篇剧情指导、人物/场景/团队指导 | 稳定ID与原稿版本合法 |
| 分段定稿 | 实际故事段索引和正文、衔接信息 | 指导版本、不可变文件 |
| 文字分镜 | 镜头、对白、时长与素材需求 | 镜头/节拍/人物/道具引用合法 |
| 素材与定妆 | 稳定定义、组合关系、选图 | 图片实际入库和生成结果 |
| 参考确认 | 同一镜头的造型与参考图绑定 | 不复制出第二组镜头；和分镜共用冲突版本 |
| 分片与提示词 | 分片安排、文字提示词和引用 | H3技术边界及文件存在 |
| 视频与声音 | 候选的人工选用/拒绝 | 真实文件、媒体时长和生成任务事实 |
| 剪辑与后期 | 时间线、裁切、字幕、音轨 | 素材真实存在、裁切不超范围 |
| 分集与导出 | 最终集界、导出参数 | 实际导出文件与技术验证 |

添加和编辑短剧共用projectDialog弹框，字段均为创作模式、剧本的本地/素材库导入、标题和画幅；编辑回填现有资料和当前原稿文件名，不读取旧稿全文。内容语言保持原值，不恢复预分集时长。只改资料不新增原稿；选择替换原稿时，basic_info命令携带可选source{text,original_name}，与资料共用打开时expected_revision，在同一个程序Task内单次原子保存；旧来源文件及引用保留，失败/冲突不半写。撤销替换恢复原稿占位，不删除既有原稿。取消/销毁清理弹框及遮罩。其他阶段继续提供结构编辑器、已有正文编辑、原稿导入、意见与历史。专用控件支持章节/计划/对白表演编辑、素材定义/服装组合/导入生图/图库选用、声线样本导入与截取、视频导入/生成/选用、裁切/淡入淡出、音乐音轨、SRT字幕、输出规格及下载。人工与AI动作共用同一Service和保存契约。

左侧12阶段使用无逐项边框的窄栏菜单，桌面宽164px、400px窄屏宽104px。小色点区分完成绿色、审核未通过或最近执行失败红色、其他未完成灰色；不显示完成勾号和箭头，常规完成/未开始不重复状态文字，异常、执行中、待核对和已停止保留文字。当前项以浅金色背景和细左线提示，键盘焦点仍可见，活动Task优先显示“执行中”。状态来自node_states、按任务记录查询的execution_states与active_execution，不由产物数量推断，图片/视频候选不冒充完成。顶部显示短剧标题、完成数与两层记忆入口，“删除短剧”位于同一工具行最右端，保持原删除回调。“短剧与原稿”以紧凑摘要行展示创作方式/画幅/语言，编辑短剧信息保留于本步骤；原稿以文件列表展示文件名、当前版本、字符数和分页只读查看；原稿页仅提供本地导入、素材库导入和任务历史，不提供直接正文编辑。不再嵌套资料和原稿卡片。步骤操作分为历史/规则、执行意见和执行/人工编辑/确认三组；导出使用目标时长旁的专用导出入口，不再重复展示默认执行按钮。纵向tab保持键盘上下/Home/End切换，窄屏保留流程侧栏并独立滚动。

## 保存与审核

人工编辑携带 `expected_revision`，按短剧串行校验、原子写入，过期版本拒绝覆盖。修改产物标记 `draft`，保存成功不冒充审核通过；意见、规则、已有执行记录不会被产物覆盖。人工不能编辑整个 `node_states`，不能通过JSON声称文件已经生成。

步骤状态按类型区分：六个程序步骤不保存模型补充rules；四个文本AI步骤保存rules和候选checkpoint；图片/视频步骤保存rules但没有文本checkpoint。所有步骤不保存last_execution，harness-http短剧快照在project外返回execution_states（task_id、group_id、status、reason），从同短剧各步骤最新已结束Task查询，活动任务单独返回active_execution。查询只读取Task摘要，不装载全部Step，也不写回或递增项目版本；续接按钮直接使用其中group_id。

退役字段source.revisions[].line_index_ref、source_analysis.facts_ref、shots[].previous_shot_id及delivery.exports[].settings_ref不再属于运行Schema。镜头顺序以sequence为准；导出设置保存在本次不可变input_snapshot_ref.settings中，不再另存同一设置文件。原稿正文、文本检查点、产物版本、coverage_ref和实际媒体validation_report_ref继续保留。

文字分镜模型契约与内部持久化结构分开。generate只提交名称版assets和完整shots数组：场景scene、人物name/造型look、道具name/持有者holder、对白speaker均使用名称；节拍和对白仅含内容，不提交ID、sequence、revision、图片引用或requirements。已有资产按准确名称复用，人物名称含明确斜杠别名时可使用其中之一；造型在人物范围内匹配。同名歧义、未知引用、错误人物造型归属明确拒绝，不模糊猜测。新增资产先给出名称及定义，由程序建档并保留已有图片、选图、声线文件及规划关联。

revise按当前名称版candidate的shot_number定位：shot_updates为{shot_number,shot完整内容}，shot_additions为新增镜头内容，shot_removals为{shot_number,reason}明确删除；shot_order为空保持原顺序并追加新增，非空须完整且唯一列出最终镜头的原候选序号。新增临时序号为原候选镜头数+1、+2；删除和重排均基于修改前序号。程序先精确绑定名称，再按内部稳定ID合并，未提及镜头保留。镜头/节拍/对白ID由程序分配，重做及局部修订优先复用对应位置的已有标识，全局sequence统一分配，素材需求由实际镜头引用派生。

程序基于本次不可变candidate_ref编译/合并，完整文档验证通过后才保存。原始trace保留名称版模型提交；candidate_ref保存完整内部产物，审核/修订通过另存的不可变名称版视图读取，不将内部ID交回模型维护。素材准备、参考绑定、视频提示词仍使用程序建立的真实资产及图片引用，既有任务历史不改写。

旧镜头明确移除后清除其素材需求引用，其他下游引用仍须通过完整文档校验，不能静默删除。首轮冻结资料包含shot_index和current_shots，供复用ID；current_shots为单元开始时历史，审核和修订以最新candidate为准。独立审核先核对定稿开场、推进、转折、结尾和直接引语的全段覆盖，再检查局部可执行问题；结构校验通过不等于语义覆盖充分。文本模型同一动作连续三轮没有工具调用时失败停止，正常工具读取打断该连续计数。

引用校验同时检查整个文档；删除上游被引用对象会被拒绝，需先调整关联引用。此机制不按内容hash使下游自动过期，是否重做由真实变化和用户目标决定。旧版本引用仍可保留，不自动改写成最新版本。

## 各阶段执行与记录

1. 创建/导入：纯程序建短剧、工作区/会话及不可变原稿；不摘要、不估时。
2. 原著解析：纯程序执行，默认不拆分。将当前原稿完整保存为一条`chapters`记录：`id`复用同正文的既有单条记录ID，否则生成；`sequence=1`；标题沿用既有标题或原稿文件名；`body`逐字等于整份原稿；`summary=''`，`coverage_ref=null`。程序校验正文完整性，不调用文本生成、审核、修订或记忆整理模型，任务仅prepare→execute→finish。自由创作且没有原稿时保留空章节，剧本模式无原稿则失败。其他阶段仍可按工具上限分页读取body。旧AI解析检查点不可套用新程序步骤，应重新执行；既有短剧和历史记录不自动删除或迁移。
3. 联合规划：按分段body读取原文，摘要仅辅助定位；每个动作提交前须实际读完本单元正文，定稿同样检查。`character_plans.voice_description`描述稳定声线；其他阶段既有`source_spans`仅用于程序派生的读取边界，章节本身不再持有。故事计划不提前分集，当前阶段的“不写正文”等操作要求不得作为永久锁定要求传给下游。
4. 分段定稿：完整读取原剧本，依据全篇联合改编规划创作完整改编剧本，自主分段；正文展开具体动作、对白、角色反应和场景细节。独立审核全篇候选，并复核相邻完整段落的连贯性。全篇修订返回完整段落数组，相邻复核修订只更新指定两段。
5. 文字分镜：引用故事段与短剧人物/场景/服装/道具/造型，节拍包含对白原文与表演、声画、时长；保存同组镜头及真实素材需求。
6. 素材：默认只生成实际缺少的需求素材；任何已定义服装/道具也可单独生成。组合定妆最多5张输入参考，成功立即入图库并保留候选；实际所需素材均有图片后直接confirmed，面板显示“已通过”，不要求审核或先选图。只生成部分素材时保持partial，失败如实标记；图片选用可独立操作；分镜参考确认优先使用已选图片，未选时自动选用唯一候选，只有多候选未选或确实无图时提示处理。
7. 参考确认：复用原镜头ID并绑定所选图，合并造型中已包含的道具，最多9张。
8. 分片：程序完整有序覆盖每个节拍且不重复，组合成4～15秒；支持参考、文生、首尾帧模式。
9. 提示词：逐分片生成/审核，`mode`、参考图、对白及声线版本明确保存。H3 reference按官方Ref2VA格式返回六个字符串字段：subject_definitions、summary、retention_analysis、detailed_description、overall_soundscape、non_diegetic_music；text/first_frame返回base三字段integrated_multimodal_description、overall_soundscape、non_diegetic_music。程序按顺序编译为prompt_ref纯文本，首尾帧对齐指令由程序添加；总长≤7000字符。英文描述，原语对白逐字放在`<d>[Chinese] …</d>`，原语可见文字加引号。同一句对白可跨镜分为多个d标签，程序按原文顺序和说话人连续核对，仍拒绝缺词、重复或换人；主体标签后的冒号、缩进、列表及同段排列不影响映射；程序按Subject/Audio标签边界核验各自来源与保留说明，而非按换行切分；参考映射问题集中返回。候选中的`At 时间, [Shot N]`由编译器统一成`[Shot N] At 时间,`，不修改对白、时间值或镜头编号。固定`<Picture N>`、`<Audio N>`与实际发送数组同序，`<Subject N>`按视觉来源合并，`(Sx)`按当前分片首次发声顺序编号；模型只返回prompt对象，引用由程序保存。保存/发送前核验字段、引用、对白与说话人、切镜递增及时间边界；旧格式需重新生成，视频提示词任务契约版本3，旧检查点不能续接。单镜不强制拆镜，不按字数或推测口播速度反复否决。
   官方依据：[Ref2VA](https://github.com/MiniMax-AI/MiniMax-H3/blob/main/skills/h3-prompt-writing/references/ref-en.txt)、[base](https://github.com/MiniMax-AI/MiniMax-H3/blob/main/skills/h3-prompt-writing/references/base-en.txt)。
10. 视频/声音：实际生成/下载/探测，`videos[].input_snapshot_ref`记录当次镜头/分片/提示词，候选需人工检查选用；一分片只选一个。稳定声线文字可配可选2～15秒干净样本，每句对白的情绪/音量/语速/气息留分镜。H3参考最多9图、3音频，音频合计最多15秒，首尾帧不混用参考音频。
11. 连续剪辑：`preview_ref`真实预览；时间线裁切不越实际文件、不重叠，允许黑场间隔；`transitions`是逐片段淡入淡出，非交叉叠化；音轨JSON含文件/入出点/位置/增益，支持响度归一。字幕从已选视频输入快照生成时间估计，可人工改SRT；裁切后显式重新生成字幕会替换人工字幕。
12. 分集/导出：最后才定集界，可按目标秒数选择片段边界或人工精确设置，需无缝覆盖连续成片；`delivery.settings`含宽高/帧率/SRT或烧录/响度，输出实际MP4、各集重置时间码的SRT和验证报告。`exports[].input_snapshot_ref`记录当次集界/时间线/输出参数，历史导出不依赖当前集界。缩短时间线前应先在交付产物中移除或调整不再有效的当前集界，历史导出文件保留。

`node_states.<文本AI步骤>.checkpoint`保存最近单元的candidate/unit文件、Task、保存或审核事实和产物版本；中断后续接复用已通过单元。原稿/意见/规则或人工产物变化时拒绝沿旧检查点执行。每个模型动作最多40轮读取、单轮32000字符工具输出、约100000字符活动消息预算，较早消息外置可重读；`remember`可保留带来源的阶段记忆。生成→独立审核→最多3轮修订，不变候选重复同问题会停止，保留最新候选与真实终态。程序校验失败最多2次输出修复。实际消息/工具读取/候选与媒体输入快照均不可变保存，历史查看不拿当前短剧补造。

## 当前验证边界

所有阶段已经接入真实可执行入口。自动集成测试使用本地模拟llm-http网关，真实保存图片、视频、音频，执行ffprobe/ffmpeg/Canvas字幕烧录与导出；它不代表真实供应商生成质量、音色匹配或口型准确率。实际部署需ffmpeg/ffprobe、libx264/AAC、可用中文字体（可通过`DRAMA_SUBTITLE_FONT`指定字体文件；缺字体会明确失败，不生成缺字字幕）；Canvas作为短剧依赖随独立复制安装。画面/对白/声线与连续性由用户对实际候选检查选用。


## 执行器边界

制作执行入口按类型注册：`TextProductionExecutor`执行五个文本节点的生成/审核/修订，`ImageProductionExecutor`执行素材生图，`VideoProductionExecutor`执行视频生成/下载/技术校验，`ProgramProductionExecutor`执行参考绑定/分片/剪辑/导出。`UnitProductionExecutor`只共用单元清单、已完成单元跳过、检查点与Task终态等设施；不包含文本审核或模型类别分支。各类型拥有自己的单元准备、步骤选择、实际执行和人工确认条件。创建/导入/人工保存仍用`ProjectDocumentExecutor`。此次拆分不改变短剧JSON、Task/Step格式或原生工具上下文语义。


## 两层视频制作长期用户记忆

这两层都只服务视频制作：剧本改编、人物剧情、镜头、画面、声音、字幕、剪辑等；不记录代码风格、技术选型、开发流程。存储与任务快照显式标记`domain: video_production`。长期记忆独立于短剧产物Schema：

| 范围 | 文件（相对Drama存储根） | 内容 |
|---|---|---|
| 当前短剧 | `projects/<id>/memory.json` | 用户决定、短剧约束、偏好、未决问题 |
| Drama工程 | `memory/user-preferences.json` | 用户明确要求跨Drama短剧复用的偏好；不影响其他业务插件或Codex全局 |

每份文档包含schema_version、revision、entries和修改history。条目包含稳定主题key、id、title、content、kind、stages、active/archived、版本/时间和source（会话、操作来源、用户原话或人工输入）。按主题key更新，不把同一决定不断追加成冲突副本；归档后不参与执行，可以恢复。版本冲突拒绝覆盖，文件原子保存；单条正文/用户原话各最多2000字符，最多500条，历史最多10000项/文档最多40MiB，超过时要求整理，不静默清理历史。

作用顺序是本次明确用户目标 > 短剧记忆 > Drama工程偏好；短剧同key仅在适用步骤内覆盖工程偏好，未覆盖步骤继续用工程偏好。正式剧本/分镜/资产和程序校验仍是实际内容权威，记忆不会自动改产物、选视频、改变输出参数或绕过审核。旧审核意见、模型推断、候选和失败原因不自动写成用户要求。

短剧面板顶部有“短剧记忆”和“Drama通用偏好”，支持搜索、查看/编辑、新增、限定步骤、归档/恢复、删除和修改历史。删除清除当前条目及其记忆修改历史正文，旧Task的不可变输入/提示词/媒体生成快照仍保留当时事实；不是全盘历史擦除。

主Agent使用`drama-read-memory`按主题读索引/正文/历史，`drama-write-memory`仅按用户明确表达维护；工程范围只接受preference。跨会话依据已存记忆继续，不将全部对话自动拷贝给模型。盒子的phase `remember`仍只压缩本次动作，独立于长期记忆。

制作入口提交Task前冻结适用记忆为`artifacts/*.json`，metadata.memory_snapshot_ref关联这份输入，包含工程/短剧版本、优先级及有效条目。生成、独立审核、修订与失败续接读取同一快照；运行中改记忆只影响新Task，想立即应用新决定应以新任务执行而非续接旧目标。文本首轮仅提供最多20条索引及总数，search_memory分页/检索、read_memory读取单条正文；没有候选时不注册read_candidate，审核/修订在有候选时仍须完整读取；读过的记忆可作为审核要求的实际引文，不继承作者推理。图片执行器将适用正文或压缩视图纳入本次真实模型输入并保存引用。有压缩视图时偏好用摘要，决定/约束/未决问题仍带原文；硬性要求仍超过12000字符时明确要求收窄适用范围或归档旧项，不静默遗漏。

harness-http入口为`/api/drama/production-memory?session_id=...&scope=project|engineering`，GET索引/单条/历史、POST维护；沿既有会话归属、请求标识和冲突校验。短剧记忆严格检查会话绑定；Drama工程偏好由已有鉴权保护，可在尚未创建短剧的新Drama会话读取，便于创建前复用视频创作偏好。面板管理入口位于短剧页。所有测试使用临时目录，未预填未经用户明确要求的跨短剧偏好。


### 对话整理与压缩

`src/memory/conversations.js`在宿主`llm/stream`进入主Agent请求前，记录已绑定Drama短剧的可见user/assistant文字（不记录system/tool/reasoning）。记录位于`projects/<id>/memory-conversations/<会话标识>.json`，按消息ID或窗口重叠去重、保存已处理游标；单会话原文最多24MiB，超限报错，不截断。原始会话可能包含其他话题，但提炼的长期记忆只允许视频制作内容，助手文字仅作背景。未绑定会话不自动记录；原文保留不等于整段注入模型。

待处理用户发言达到3条、合计1500字符，或有“记住/改为/不再/以后Drama”等明确表达时自动整理。短剧有活动Task时先保留原文，稍后的请求或显式工具再处理。含跨短剧明确要求时先整理工程偏好，再整理短剧记忆；短剧提炼成功后才推进对话游标。自动整理失败保留原文及失败任务，不拦截主Agent回复。

面板提供从对话提炼（可输入用户原话）、核对重复与冲突、压缩记忆、查看压缩摘要、整理历史；`drama-maintain-memory`共用同一Service。整理是独立`memory_maintenance` Task，内部准备→提炼/压缩→独立审核→最多2轮修订→原子保存；每次真实模型请求对应Step，每动作一份完整skill，任务冻结规则正文，首轮仅动作目标与规则索引，read_skill后执行。提示词、读取、候选、审核和原始输入保留于`memory/jobs/<任务组>/<文件>.json`，可停止。核对不能凭时间自行归档，明确失效/替代必须引用用户取消或修改原话；新增不得同key覆盖，修改前必须读取旧项。

每条提炼操作须有实际user原文turn_id/quote，程序校验引用、目标读取和数量；工程新增/修改/取消还须引用明确跨Drama适用原话。相同条件的重复可合并；决定/约束的原文必须保留，旧项与修改历史不删。短剧含糊冲突保留旧项并生成open_question；工程含糊冲突不改全局偏好，作为unresolved候选留在任务结果等待用户确认。一次提炼批量检查文档revision后原子写入，坏引文、版本冲突和提交前取消不会部分应用。提炼已完整提交、随后压缩失败时保留已提交记忆，Task明确记录保存步骤及压缩失败，可独立重跑压缩。

对话按每页≤6000字符切分，保留原turn引用和UTF16边界；已有记忆仅给20项索引，模型按需搜索/读取单条。压缩每组输入约12000字符，独立审核每组摘要后逐层归并成≤1800字符摘要；每层须完整列出输入row id，程序检查无缺失或重复。每个模型动作最多30轮、约80000字符活动上下文、单轮28000字符读取预算；更早执行记录外置保留。来源ID覆盖是结构检查，语义准确性依靠独立审核和原文回读，并不代表摘要绝无损失。

派生视图位于`memory/views.json`（最多64份），保存摘要、全部来源ID、条目版本签名和任务引用；不替换memory.json。模型单条读取保留完整记忆正文和用户原话，仅展示前2条来源引文及引文总数，完整来源仍在原始记录，避免来源增长堵塞读取。新制作Task适用记忆超过24项或正文合计约6000字符且无匹配摘要时，先自动压缩；同一来源ID/版本集合才可复用，人工变更后旧摘要不再适用，压缩期间记忆变化则拒绝发布。文本首轮提供memory_brief摘要和索引，具体决定/约束应按需读取原文；生成/独立审核/修订仍共享冻结快照，续接旧任务不因新摘要而改变输入，也不会为新版本记忆额外触发压缩。

整理harness-http：`/api/drama/production-memory-maintenance?session_id=...&scope=...`，POST action/turns/request_id发起、cancel停止，GET无id读最近40项历史，带id读任务，带id/file/start读不可变记录（每页16000字符）。短剧归属、工程会话、请求标识、同request_id相同输入检查一致；`production-memory`的GET summary=1读当前适用摘要。删除记忆也移除引用该ID的派生缓存；原始对话、整理任务与既有制作Task仍保留真实历史，不是全盘擦除。

## 执行操作时间线

规则文件放在对应 `src/node_box/<节点>/skills/` 下，分别为 `<节点>-generate.md`、`<节点>-review.md`、`<节点>-revise.md` 和 `<节点>-output-format.json`。六个AI制作节点使用四文件布局，skills内不嵌套动作目录，节点名与左侧十二阶段一致，不再有production_前缀或退役盒子。纯程序节点不创建空规则。记忆整理是独立辅助功能，四文件放在`src/memory/skills/`，文件名前缀为memory_maintenance。文本返回格式使用project:/指针引用运行Project Schema、shared:review引用共用审核结构，读取时展开为完整模型契约，覆盖项如minLength在本节点生效；不复制短剧字段定义。记忆整理返回格式按mode单列，随动作规则冻结入Task。现有Task快照及私有规则不批量覆盖，面板“查看规则”包含output_format。

文本模型每次工具轮次的 result.trace.activities 是可见操作摘要，只由当轮实际工具调用和对应工具返回生成，包含中文动作、范围或字段定位、返回状态。正文、完整规则和模型自由文本不进入摘要；原始trace继续保存为不可变文件。提交候选只显示校验通过，不提前声称已保存；没有返回记录或未接受的提交标为未确认，工具错误显示失败，审核结论以已接受的实际提交为准。

会话执行过程对V4默认展开操作列表，原始步骤输入输出仍可折叠查看。运行中显示中文阶段及等待本轮调用结果，用户手动展开状态在更新时保留。已有步骤没有摘要时，只读其Task所属短剧的trace文件恢复，不能读取当前短剧补造历史；文件不可用时明确提示。摘要有数量及文本上限，并使用有界缓存；compact轮询保留摘要，不携带完整正文。公共任务历史采用中文阶段名，公共Task包及生成审核逻辑不变。

V4文本模型步骤收起时显示“发送、模型返回、工具执行”三段摘要：发送显示当次Task要求或任务名的有界短文本；模型返回显示真实工具名及中文作用，工具执行显示对应状态、范围或错误，不重复渲染额外操作列表。展开步骤时才读取当次prompt.input.messages_ref和result.trace.file_ref，按原顺序展示实际请求消息、assistant可见返回及工具执行。工具调用按tool_call_id关联真实参数和结果，缺失、失败、无工具回复分开展示；程序补充反馈单列，是否进入后续请求以后续messages_ref为准。不展示内部推理字段，不以当前短剧恢复历史。model_call仅含模型、任务目标短文本及文件索引，model_exchange完整内容从compact和eager预载中排除，浏览器不能将预载摘要缓存为完整模型详情。关联文件与步骤保存结果保留于技术详情，任务整体输入仍只在顶部一处展示。请求详情仅代表已保存的真实消息，不冒充未记录的供应商原始响应或完整llm-http传输参数；其他程序/图片/视频及旧任务保持原展示。

## 联合改编规划覆盖验收

有原稿的联合改编，character_plans与scene_plans必须非空，分别覆盖主要人物与关键场景，不能用总纲代替或推迟到后续阶段；程序在候选保存前拒绝空表，具体对象是否遗漏由独立审核对照原著判断。单字段缺少依据可为空，不代表整个规划列表可省略。group_plans按实际出场且有组织身份/共同形象需要的团队提取，无相关团队允许为空，不能编造组织。审核必须指出有据可核的遗漏并要求修订，不能只因总纲完整就通过。无原稿自由创作不强制补造原著人物或场景。

## V4联合改编与故事定稿交接

运行版本schema_version=4，不支持V3及更早旧短剧。文档快照为drama_v4.schema.json、drama_v4.example.json和drama_detail.json。

adaptation_plan保存revision、source_revision_id及五项内容：
- creative_constraints：style风格、audience受众、adaptation_scope改编尺度、preserve保留内容、allowed_changes允许调整内容、locked_requirements用户明确锁定要求。
- plot_development：一份全篇连贯文本，写清主线目标、核心冲突、因果推进、关键转折、高潮和结局方向，结合人物动机、团队关系及场景作用说明剧情发展。
- character_plans：id/name/description/motivation/relationships/arc，说明定位、动机、关键关系、剧情作用及成长变化。
- group_plans：id/name/social_role/description，说明实际组织目标、成员归属、内部关系、对外冲突和剧情作用；无适用团队时为空列表。
- scene_plans：id/name/function/description，说明关键场景作用、空间关系和保留/合并/调整方案。

剧情发展是全篇规划，不使用逐事件条目或事件ID关联。故事定稿完整读取原剧本与冻结全篇规划，自主形成一个或多个叙事段，展开完整动作、对白和continuity。输入原文范围仅供分页阅读，正式产物保留指导版本及稳定段ID；独立审核核对全篇主线与因果转折的落实以及相邻段衔接。

面板剧情卡以纯文本显示并编辑，不展示内部字段名、顺序号或ID。团队规划分组始终显示，空时用“暂无团队规划。”占位。人工编辑沿用版本冲突和完整Schema校验；人物/场景覆盖与原著事实边界规则保留。

## 故事分段定稿的内容依据

人物、团队、场景规划已分别保存在adaptation_plan.character_plans、group_plans、scene_plans，和全篇创作约束、剧情发展一起写入正式drama JSON。定稿任务冻结完整adaptation_plan，在一个全篇单元内完整读取原剧本并按规划自主分段改编。正文要求详细、完整、有观赏性，包含具体动作、角色反应、自然对白和必要场景细节，体现冲突、情感和节奏变化；continuity维护段间衔接。后续分镜输入优化不属于本次修改范围。

现行文档可显式运行 `node projects/drama/scripts/migrate-story-segments.js <drama存储目录> --apply` 去除旧定稿来源字段。默认只预览；应用前备份原JSON，保留原稿、改编正文及所有历史文件，清除旧定稿检查点；新定稿任务契约为3，旧任务须重新生成或以当前正文发起新修订。

参考绑定在单次文档事务中保存镜头引用、默认选图和需求状态；已有选图不覆盖，单图自动选用后需求回填ready及image_id，并更新素材版本。遇到歧义、缺图或超过9张参考时整体拒绝，不半写入。

视频生成直接发送已保存的官方结构提示词，保留当次冻结记忆引用用于审计；不在结构外追加记忆或补充意见。需要落实的创作要求应先在视频提示词阶段应用并审核，再生成视频。
