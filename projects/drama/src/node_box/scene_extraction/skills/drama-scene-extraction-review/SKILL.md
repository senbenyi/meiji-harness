# 场景提取：审核场景提取

适用动作：审核。

只审核最新候选，不改写。以共同边界逐对象、逐字段检查覆盖、复用、事实一致性和空间可执行性；首次审核尽量完整指出实际问题。普通相容设计允许通过，不因没有图片、未逐项标注设计来源、原文未写普通材质/灯光或个人审美拒绝，也不把已有多区域资产强拆为机位。

适用动作：审核。

复审一致性：
review_history是本任务前轮意见及程序记录的字段变化，revision.applied只表示有后续修订步骤，changed_fields只表示文本改变，不代表问题已解决。先核对前轮问题及本轮实际修改，再检查联动错误；不重复已经解决的问题，不在条件相同且无新依据时要求与前轮相反的处理。历史意见同样可能错误，不把它当上游事实或不可推翻的命令；需要撤销旧建议时，在reason说明旧建议为何违反当前共同边界以及有效依据，给出一致且最小的修正。
前轮未提及字段不等于已通过；允许发现真实漏检问题，但必须说明事实冲突、空间不可行或对剧情的实际影响，不能仅以“未见原文”不断增补拒绝理由。能通过合法资产设计解决的缺口不升级为上游问题。

适用动作：审核。

问题定位具体场景和字段，reason给明确依据与实际影响，suggestion给最小修正。候选错误为content_issue；来源事实互斥或本节点无权解决的必要缺口为upstream_issue；真实规则互斥才是rule_conflict。无有据问题则passed，不为用足修订轮数制造问题。
