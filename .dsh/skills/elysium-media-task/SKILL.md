# 视频生产任务

- 创作分镜沿用 `elysium-shot-design`；本 Skill 只准备生产输入、选择入口和解释结果。步骤顺序、素材复用、合片与验收由工作流代码保证。
- 仅调用本轮实际提供的工具。生产统一使用 `workflow_generate_video`，不拆成原子模型调用，不通过 Bash 绕过缺失或失败的工作流。

## 准备输入

- 沿用已确认角色、分镜和总时长。`duration` 为目标总秒数，不能用段数代替。
- 新生成：`prompts` 按镜头顺序排列；1..15 秒用一条，长视频至少两条且每段 1..15 秒。长视频提供已有首帧 `image_path` 或首帧提示词 `image_prompt`，二者互斥。
- 已有素材：将已完成任务返回的 MP4 路径按镜头顺序放入 `video_paths`，另填目标总时长；不能同时传生成输入。12 个15秒片段可直接提交 `duration: 180`，不重新生成。
- 素材路径必须来自真实返回值并位于服务器共享 artifacts 中；不编造、不扫描旧目录冒充本次素材。
- 第一版默认保留原片规格与音轨。需要额外补帧、超分、配音或多参考视频编辑时明确工作流能力缺口，不改用原子工具。

## 提交、查询与恢复

- `workflow_generate_video` 返回 `job_id` 和 `queued`，表示后台任务已创建，不表示成片完成。
- 用 `model_job_status` 查询；成功后用 `model_job_result` 获取成片。查询间隔合理退避，不紧密循环。
- 失败先读取具体阶段和日志；原因解决后使用 `workflow_resume_video(job_id)`。保留原输入，复用已完成步骤，不重新创建同一任务。输入确实变化时才创建新任务。
- 进程状态不明或残留任务锁时报告需运维核对，不自动清锁、安装、部署或重提 GPU 任务。

## 交付

- 成片 `path` 和验证结果必须来自工作流；仅片段生成完成时不标记整个任务完成。
- 检查实际总时长以及 `validation.full_decode`、`validation.specification_match`；未通过不宣称制作成功。
- 画面、角色一致性、动作和声音衔接需另行查看；无法查看则标记人工验收未执行。
