# 工程文档通用规范

## 1. 目标

工程文档用于回答四个问题：

1. 当前事实是什么。
2. 为什么得出这个结论。
3. 决定做什么以及明确不做什么。
4. 如何复现、验证和推翻该结论。

文档不是工作日志的堆积，也不是对代码的逐行转述。

## 2. 证据等级

按以下优先级使用证据：

| 等级 | 证据 | 可支持的表述 |
| --- | --- | --- |
| E1 | 当前环境的实测结果、原始输出、产物检查 | “已实测”“当前为” |
| E2 | 当前仓库实际执行路径、测试、配置和数据 | “代码当前会”“契约要求” |
| E3 | 官方文档、官方源码、官方模型卡 | “官方声明”“接口定义” |
| E4 | 上游 issue、维护者讨论、可信第三方复现 | “有外部证据表明” |
| E5 | 理论分析、经验判断、类比 | “推断”“预计”“需要验证” |

规则：

- 低等级证据不得伪装成高等级结论。
- 搜索摘要、转载和模型回答不能替代原始来源。
- 历史错误不能证明当前仍然失败；必须核对当前版本和当前请求。
- 本地存在文件不能证明运行时使用了它；必须定位加载与选择路径。

## 3. 文档开头

除极短记录外，文档开头应包含：

```markdown
# 标题：直接说明对象和问题

> 状态：草案 / 已定稿 / 已实测 / 已废弃
> 基线：版本、提交、日期或运行环境
> 范围：本文覆盖什么，不覆盖什么

## 0. 结论

- 结论一。
- 结论二。
- 最重要的限制或未确认项。
```

“结论”应让读者在一分钟内知道能不能做、该选什么、最大风险是什么。

## 4. 正文结构

按问题选择章节，不要求所有文档使用同一目录。常用顺序：

1. 问题与边界。
2. 当前实现或基线。
3. 关键证据。
4. 方案或实验对比。
5. 决策与理由。
6. 实施路径或复现方式。
7. 风险、诚实边界与未决项。
8. 参考来源。

结构必须服务于判断过程，不能为了整齐制造空章节。

## 5. 事实表达

### 5.1 区分状态

使用明确措辞：

- 已确认：`代码当前调用……`、`本次实测为……`
- 推断：`由此推断……，尚未实测`
- 未确认：`未确认：当前没有……证据`
- 计划：`计划修改……`
- 完成：`已修改……，并通过……验证`

禁止使用“应该没问题”“理论上已经完成”“看起来支持”等模糊完成态。

### 5.2 引用代码

- 写出仓库相对路径，并尽量给出符号名、配置键或测试名。
- 引用实际执行路径，不只引用声明、README 或同名旧实现。
- 代码片段只保留支撑结论所需的最小部分。
- 文件会频繁变化时，优先引用稳定符号而不是易漂移的行号。

### 5.3 使用数字

性能、质量、成本和尺寸数据必须同时说明：

- 测试对象与版本。
- 硬件、软件和关键配置。
- 输入规模、样本数与计时口径。
- 基线和唯一变量。
- 原始值以及派生倍率的计算方式。

不同口径的数据不得放进同一张对比表直接排名。

## 6. 表格、代码块和图

- 表格用于稳定维度的比较、契约字段和决策矩阵。
- 代码块用于命令、配置、接口示例和可复现输入。
- 流程图用于三步以上的数据流、状态流或职责边界。
- 同一信息不同时用长段落和大表格重复表达。
- 表格中的“支持”“通过”“更快”必须能追溯到证据或注释。

## 7. 决策记录

涉及取舍时至少记录：

| 项目 | 必须回答 |
| --- | --- |
| 决策 | 最终选择什么 |
| 原因 | 哪些证据决定了选择 |
| 代价 | 为此接受什么限制 |
| 否决路线 | 为什么不选，而不是只写“不选” |
| 重审条件 | 出现什么新证据时需要重开决策 |

## 8. 勘误与演进

新证据推翻旧结论时：

1. 在旧结论附近添加醒目的勘误。
2. 写明旧结论、错误原因、新证据和当前结论。
3. 更新所有依赖该结论的设计、配置说明和测试口径。
4. 保留必要的失败记录，防止同一路线被无理由重复尝试。

推荐格式：

```markdown
> **勘误（YYYY-MM-DD）**：原结论为……；由于……，该结论已被……实测推翻。
> 当前应使用……；仍未验证的范围是……。
```

## 9. 诚实边界

文档末尾应明确列出适用范围内的重要缺口：

- 没有运行过的测试。
- 没有覆盖的硬件、输入或版本。
- 只能由外部系统验证的假设。
- 已知风险和失败恢复方式。
- 需要用户或维护者决定的未决项。

未确认项应具体说明缺少什么证据，不得只写“待观察”。

## 10. 发布前自检

- [ ] 标题能准确表达问题和对象。
- [ ] 开头有结论、基线和范围。
- [ ] 当前事实、推断、计划和完成态没有混写。
- [ ] 关键结论可以定位到代码、来源或实测。
- [ ] 所有数字都有口径。
- [ ] 被否决路线写明了原因。
- [ ] 未测范围和未决项已明确。
- [ ] 文档与当前实现没有明显漂移。
