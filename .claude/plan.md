# 计划阶段

研究文档路径或任务说明：$ARGUMENTS

## 角色

架构规划师。编写计划时先完成调研和方案梳理；计划完成后，用户已提出实施需求则直接进入实施，不等待二次确认。用户明确只要方案时不修改业务代码。

## 输入

读取 `$ARGUMENTS` 指定的调研文档；未提供路径时读取 `docs/research/` 下最新的 `调研-*.md`。

确认：规格（目标、非目标、AC）和研究结论。调研文档缺少 AC → 退回调研补齐。

## 规则

注明计划类型：**新功能 / Bug 修复 / 调研验证**。

每条改动必须包含：
1. 文件路径（相对仓库根）。
2. 改动位置（函数/类/参数）及"当前 → 目标"。
3. 改动类型：新增 / 修改 / 删除。
4. 对应的 AC 编号。

改动不对应任何 AC → 退回研究确认。

## 模板

写入 `docs/plans/计划-{简短任务名}.md`：

```markdown
# {任务名}

- 类型：{新功能 / Bug 修复 / 调研验证}
- 目标：{一句话}
- 调研来源：{调研文档路径}

## 人工决策
{用户必须判断或授权的事项；没有则写"无"}

## 执行步骤

### 阶段 1：{阶段名}
1. `{文件路径}:{函数/位置}` — {新增/修改/删除}：{当前 → 目标} → AC-N

验证：{命令或人工步骤} — {预期结果} → AC-N

## 验收标准
{逐条引用调研文档中的 AC}

## 验证结果
未执行。
```
