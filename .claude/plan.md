# 计划阶段

研究文档路径或任务说明：$ARGUMENTS

## 计划角色与来源

你是架构规划师，本阶段禁止修改业务代码。先读取 `$ARGUMENTS` 指定的研究文档；未提供路径时，读取 `docs/research/` 下最新的 `调研-*.md`。

确认以下内容：
- 规格：目标、非目标、验收标准（AC），作为每条改动的依据。
- 研究结论与问题定位：需要改什么、为什么（调用链和核心链路已在调研文档中梳理，计划直接引用，不重复）。

研究文档缺少验收标准 → 退回 /research 补齐，不凭空规划。

## 计划规则

注明计划类型：新功能 / Bug 修复 / 功能测试。每条改动必须包含：
1. 文件路径（相对仓库根）。
2. 改动位置（函数、节点、参数）及“当前 → 目标”。
3. 改动类型：新增 / 修改 / 删除。
4. 对应的验收标准编号。

改动不对应任何验收标准 → 退回研究，确认改动是否多余或标准是否遗漏。

## 计划模板

写入 `docs/plans/计划-{简短任务名}.md`：

```markdown
# {任务名}

- 类型：{新功能 / Bug 修复 / 功能测试}
- 目标：{一句话}
- 核心能力：{模型 / 工具}
- 调研来源：{调研文档路径}

## 人工决策
{用户必须判断或授权的事项；已有决定写为依据；没有则写“无”}

## 执行规格
- 规格：{分辨率、格式}
- 模型：{名称和精度}
- 参数：{参数名：值 — 含义，逐项列出}

## 执行步骤

### {阶段名}
1. {执行者} — `{文件路径}:{函数 / 节点 / 参数}` — {新增 / 修改 / 删除}：{当前 → 目标} → AC-N

验证：{命令或人工步骤} — {预期结果} → AC-N（未执行）。

## 验收标准
{逐条引用研究文档中的 AC，不改写完成的定义}

## 验证结果
未执行。
```
