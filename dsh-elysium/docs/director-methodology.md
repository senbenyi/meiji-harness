# 导演方法论

`src/application/director-profile.js` 的参数与 `src/application/planning-service.js` 的两阶段
提示词依据的方法论。蒸馏自 Toonflow-app 导演/分镜技能包，按本插件管线能力做了两处明确取舍
（见文末）。改动规划提示词前先读这里，避免把纪律改丢。

原实现是 `llm-ai-model` 仓库里的 `mvp-director` Skill + `workflows/mvp/director.yaml`（面向固定
12 镜的 `vmp-1`）。业务能力归位到插件后，方法论保留，产出结构改为插件的**动态章节 × 6 锚点**模型。

## 两阶段纪律

规划严格分两步，不得跳过：先忠实拆解，再分配画面。

```
故事文本 ──▶ 第一阶段：场景拆解 ──▶ scenes ──▶ 第二阶段：章节与锚点分配 ──▶ plan
```

第二阶段**只依据第一阶段的 scenes**，不重新读故事原文。这是防止模型在分镜时二次创作的关键。

## 第一阶段 · 场景拆解

只做四件事，不做其余任何创作：

1. **拆分场**——按同一时空下的连续戏切分，地点变更/时间跳变/戏剧单元收束为切点；顺序与故事一致，全覆盖不漏不重。
2. **台词统计**——逐场统计条数与字数（对白/独白/旁白各算一条），无台词记 0。只忠实计数，不预算镜头数。
3. **情绪分析**——逐场给 `emotionIntensity`（0-10）与起止情绪词。相邻场落差不超过
   `pacing.maxAdjacentEmotionDelta`；确因剧本转折超出时，在 `notes.pitfall` 写明依据。
4. **过渡设计**——**先判断是否必要**。同一时空连续推进、或直接相接已顺畅就不写（硬切），不为凑数增补。
   确需缓冲时才从 `transitions.preferred` 里选，并具体到"谁做了什么动作""空镜内容是什么"，不能只写类型名。

红线：

- 只拆分、不创作（过渡是唯一例外）。
- **不规划光影/色调/配乐**——那是第二阶段按 `style` 统一注入的，第一阶段提前臆造会污染下游。
- 环境音只写可听见的具体声源，不写配乐。
- 本阶段不产出任何 imagePrompt / motionPrompt / castPrompt。

`notes` 的五类（情感砸点、一致性锚点、空间与距离、环境音、易错提示）按需填写，写了就必须是具体
描述，不能是类别名本身。

## 第二阶段 · 章节与锚点分配

### 内容忠实性原则（最高优先级）

提示词生成是**格式转换**，不是创意写作。scenes 是唯一内容来源：其中的视觉元素必须完整体现，
不得遗漏或替换语义；不添加 scenes 未提及的装饰性元素；不重新诠释情绪基调。`style` 的风格词是
辅助修饰，与场景描述冲突时以场景为准。

### 首帧识别原则（imagePrompt 取值依据）

`imagePrompt` 是该锚点的**首帧静止状态**，不是动作全过程：

| 场景描述类型 | 处理方式 |
|---|---|
| 静态瞬间（站立凝望、独自等待） | 直接按描述生成，不改写 |
| 连续动作过程（推门走出、并肩走向） | 取动作**起始瞬间的凝固态**，不是抽象预备态 |
| 情绪/镜头运动（由远及近、由紧张转柔和） | 取运动**起始端**作为首帧构图 |

`motionPrompt` 描述从首帧出发的运动过程（动作、情绪推进、镜头运动），必须含至少一个运镜词，
且避开 `camera.forbiddenMotions`。

### 位置与朝向连贯性

- 同一角色在同一章内画面左右位置固定，无叙事理由不得跳侧。
- 对话/对峙遵循 180° 视轴线：先出场时确定的朝向全章保持；朝向变化必须在 `motionPrompt` 里有
  转身/转头等动作衔接，不能凭空改向。
- 换章允许重新分配位置与朝向，但新章内部仍需一致。

### 锚点分配

- 按各场景的台词字数与 `emotionIntensity` 的相对权重分配篇幅，权重高的场景多分锚点。
- 每章恰好 6 个锚点：第 1 个 `role=start`（独立文生图起始帧），其余 5 个 `role=continuation`。
  起始帧属于这 6 个，不额外增加模型输入。
- 景别递进参考（按情绪曲线动态调整，非强制顺序）：建立镜头（远景）→ 中景/近景引入角色 →
  交叉特写对话 → 动态跟拍推进 → 情绪峰值特写 → 远景/留白收束。
- 场间有过渡的，衔接处必须体现该过渡。

### 一致性字段

- `castPrompt`：对每个出场角色套用 `consistency.castPromptTemplate`，覆盖全部出现过的角色，
  定妆表口径（分开站立、中性背景、正面全身、固定外貌与服装，不要叙事场景）。
- `negativePrompt`：缺省取 `consistency.negativePromptBase`。
- 合规字段涉及非自愿情节时必须中止并向用户说明，**不得为通过校验而勾 true**。

## 与源方法论的差异（刻意取舍，不是遗漏）

1. **imagePrompt 保留光影/色调描述**，源方法论明确禁止。
   源项目的分镜图依赖场景资产参考图承载光影，模型只需描述内容；本插件每个锚点只以定妆图
   （`cast-main`）作为角色一致性参考，没有场景参考图，光影必须写进 prompt 文本，否则画面无从推导光照。

2. **不做 `@图N` 多资产编号绑定**。
   源项目面向资产库（角色/道具/场景分别建档并按 ID 引用）；本插件当前只有单一角色一致性参考，
   绑定机制没有落地对象，保留会变成没有实现的装饰性格式。
