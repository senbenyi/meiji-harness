# AI 原生短剧工厂：第一性原理审计与落地决策


状态：审计任务书与决策门槛，尚不是已完成的服务器审计或获准执行的重构方案。

## 1. 唯一目标与分析顺序

找到利用现有模型、GPU 和 Harness，稳定交付可验收短剧的最短路径。Elysium 是待评估资产，不是分析起点。

严格按以下顺序推进：

```text
用户购买的结果 → 不可消除的约束 → 真实能力证据
→ 最小生产闭环 → 已证实的缺口 → 最后决定插件取舍
```

不能预设“一句话”“Agent”“分镜流水线”或“文件系统事实源”就是最优实现。输入简洁是体验目标；可靠交付才是产品结果。

本轮先完成调查、产品判断和目标架构设计，仅更新报告文档。不得修改业务代码、构建、部署、重启服务或执行 GPU 生成。实验方案与执行授权分开；设计完成后等待用户确认。

## 2. 从结果推导必要工作

先定义用户的输入、可接受的默认值、交付物和验收标准，再讨论功能。成片至少应能正常播放，叙事可理解，角色与场景符合意图，镜头衔接和声音可接受，并能定位修改范围。

把每项工作归入：必须由人决定、机器内部必须完成、现有实现额外制造。不要把当前模型需要的关键帧、固定锚点数量或章节结构视作视频生产的物理定律。

对每个现有操作及开发建议回答：

1. 删除后，交付结果具体损失什么？
2. 这是客观约束、当前模型限制，还是历史实现负担？
3. 为什么必须让用户做？模型或确定性程序能否承担？
4. 现有模型、工作流、Harness 或 Skill 能否直接解决？
5. 缺的是能力、接入、可靠性还是验证证据？
6. 最小验证是什么？什么结果意味着停止开发？

优先复用现有能力，但不得用提示词替代授权、预算限制、幂等、持久化和恢复保障。减少组件必须同时证明可靠性没有退步。

## 6. 用最小实验选择闭环

至少比较两条路径：模型直接完成较长片段；按必要阶段组合角色、镜头、声音与合成。比较可用成片率、连续性、成本、耗时及局部修改代价，再决定粒度。

先回答：没有 Elysium，仅用现有 Harness、工具和模型能完成多少？缺失环节是否只需组合、Skill、工作流或轻量适配？

## 7. 必须解决的可靠性边界

**路由：** 根据已验证能力、输入类型、质量要求、显存、队列及预算选择。换模型前检查输入输出兼容性；模型多不代表需要复杂路由器。

**质量：** 技术可解码、语义满足和全片连续性分别判断。黑场、静音和静帧可能是创作意图，不能仅凭阈值一律判错。自动评分必须与人工盲评校准，报告误报和漏报。

**恢复：** 区分暂时故障、输入错误、资源不足和质量失败；分别决定重试、调整、降级或人工处理。预算耗尽即停止，不循环换种子碰运气。

**复用：** 锁定合格产物及依赖版本；修改只使受影响的依赖失效。“已通过不重复生成”以输入、约束和依赖仍有效为前提。

**追溯：** 记录意图、决策、输入输出引用、模型版本、任务身份、费用和检查结果。模型提出计划，执行层验证并提交；普通 JSON 文件本身不保证并发一致性或崩溃恢复。

**共享路径：** 验证相关服务实际挂载、路径映射、权限和读取能力。服务器内部大文件流转目标为零 HTTP 上传；首次导入本地素材单独计数，不能隐瞒搬运成本。

**隐私：** 分别检查文本、媒体、日志和遥测的目的地。GPU 自建不等于全链路本地，目录名称也不能证明素材未外发。

## 8. 最后决定 Elysium 的职责

依据前述证据逐项处置：提供不可替代能力则保留；仅供诊断则隐藏到专业模式；重复能力则合并或删除；阻碍闭环则重构；不能改善交付指标则停止投入。

默认目标为一个创作界面：意图、可选参考、进度、成片和修改入口。专业模式按需展开角色、镜头、模型、参数与费用。是否需要独立页面，由最小闭环验证决定。

既有数据和接口的迁移必须列出消费者、兼容期、回退办法与退出条件。报告中的删除建议不构成实际删除授权。

## 9. 产品审判与竞争判断

最终报告必须直接回答七问：

1. 当前有没有已兑现的护城河？没有足够证据就写“尚未证明”。
2. 哪些只是拥有模型，尚未转化为交付优势？
3. 哪三项能力最值得集中资源？
4. 哪些功能即使完成也不能形成竞争力？
5. GPU、模型、Harness 与插件如何组合成难复制的结果？
6. 六个月不改变，最可能被哪类产品替代？写明条件和依据。
7. 必须在哪些指标领先，怎样证明领先？

对比开源工作流、开源短剧工厂、通用视频 SaaS、传统剪辑软件和单模型产品。使用当前公开来源及同任务基准，比较质量、人工时间、交付时间、成本、隐私、恢复、局部重做和运维负担；缺少可比数据不得宣称行业领先。

三项候选方向是：可测量的私有生产链路、持续复用的角色场景资产、低人工干预的可靠交付。它们只是待验证假设。必须说明积累机制、复制成本和客户价值，不能把自建 GPU 或模型清单本身称为护城河。

## 10. 验收指标与投入门槛

| 指标 | 目标与统计口径 |
|---|---|
| 用户输入 | 默认创作意图输入 1 次，可选参考另记 |
| 人工确认 | 正常成功路径不超过 2 次，异常干预另报 |
| 默认界面/技术参数 | 1 个主界面，必须理解的技术参数 0 个 |
| 人工操作 | 想法到提交生产不超过 3 分钟，与生成耗时分开 |
| 服务器内部上传 | 大文件 HTTP 上传 0 次，首次素材导入单列 |
| 自动恢复率 | 无人工干预最终成功的失败任务数 / 失败任务总数；按原因分组 |
| 质量与速度 | 首次验收通过率、最终通过率、到合格成片 P50/P95 时长 |
| 单位成本 | 总 GPU、存储及外部调用成本 / 人工验收通过的成片分钟数，计入失败 |
| 局部重做与复用 | 单镜头可替换；未受影响的已采用产物版本保持不变 |
| 暂停恢复追溯 | 停止新增提交；在途任务策略明确；恢复不重复执行已确认成功的任务 |

质量、速度、成本和恢复率的数值目标由基线与竞品证据确定，当前待确认。无法满足的指标须定位具体模型或基础设施限制，估算最小改造人日和验证成本。

30 天内完成基线与最小闭环验证；60 天内仅针对已证实缺口完善恢复、复用和局部修改；90 天内完成同任务竞争基准，再决定界面与规模化投入。每阶段均以证据门槛退出，未通过则收缩承诺，不按日历强行扩张。

成本按模型接入、编排、界面和验证分别估算人日；GPU 使用时长乘实际单价，并计入失败与闲置。报价、速度和投入人数无依据时列为待确认，不编造总预算。

- **A：当前真实具备。** 有验证范围和证据，可直接使用。
- **B：已有资产但没有产品化。** 标明缺组合、接入还是质量证明。
- **C：必须新增或重构。** 说明现有能力不能解决的理由、最小变更与验收方法。

删除和停止投入建议附在对应项中；证据不足保留“待确认”，不能强行归入 A。

最多提出五个用户决策：首个目标用户与场景、最低成片质量、单片预算、可接受等待时间、隐私及素材边界。能从项目和已授权偏好确认的事项不重复询问。
